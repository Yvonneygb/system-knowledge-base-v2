<KbCard num="1" title="重点逻辑1：经销商发起视角">
<ul><li><strong>业务意义</strong>：本菜单由经销商主动发起设计点将申请，经销商自主选择门店、设计师与设计信息。</li><li><strong>具体逻辑描述</strong>：通过<code>dealer</code>路径接口（dealerPage、dealerSave、dealerSaveAndSubmit）实现经销商发起，后端自动按当前登录经销商过滤数据并写入DEALER_CODE、DEALER_NAME。</li></ul>
</KbCard>

<KbCard num="2" title="重点逻辑2：数据范围隔离">
<ul><li><strong>业务意义</strong>：经销商仅能查看和操作自己发起的设计点将记录，避免跨经销商数据泄露。</li><li><strong>具体逻辑描述</strong>：通过<code>dealer</code>路径接口自动按当前登录经销商过滤，前端无需传经销商参数。</li></ul>
</KbCard>

<KbCard num="3" title="重点逻辑3：applyCode自动生成">
<ul><li><strong>业务意义</strong>：保证设计点将申请编码全局唯一、可追溯，作为主键贯穿全链路。</li><li><strong>具体逻辑描述</strong>：提交申请时系统自动生成唯一编码applyCode，写入APPLY_CODE字段。</li></ul>
</KbCard>

<KbCard num="4" title="重点逻辑4：设计点将独特流程">
<ul><li><strong>业务意义</strong>：设计点将区别于其他点将类型，包含完整的设计服务流程：申请→审批→开始设计→上传图纸→图纸确认→下单→完成。</li><li><strong>具体逻辑描述</strong>：审批通过后由设计师开始设计（startDesign），上传设计图纸（upload），经销商进行图纸确认（startDrawingConfirm），确认后下单（startOrder），区域确认（areaConfirm），最终完成。任一环节可终止（termination）。</li></ul>
</KbCard>

<KbCard num="5" title="重点逻辑5：多级审批关联">
<ul><li><strong>业务意义</strong>：设计点将涉及讲师审批、门店审批等多级审批流程，确保设计服务各方确认。</li><li><strong>具体逻辑描述</strong>：设计点将涉及designApplyApproval（讲师审批designApplyLecturerApproval）、designApplyTerminalApproval（门店审批）、designApplyCancelApproval（取消审批）等多级审批流程。</li></ul>
</KbCard>

<KbCard num="6" title="重点逻辑6：下载图纸与反馈">
<ul><li><strong>业务意义</strong>：经销商可下载设计师上传的图纸并反馈意见，形成设计沟通闭环。</li><li><strong>具体逻辑描述</strong>：行操作"下载图纸"，弹窗展示三类图纸：设计图（designTableDS）、效果图（renderingTableDS）、施工及软装图（constructionTableDS）。通过<code>downloadDrawing</code>接口加载，每类图纸展示文件名称（可点击预览）和反馈按钮。点击反馈按钮弹窗展示反馈意见（feedbackComments，TextArea，必填）和历史反馈记录（feedbackListDS，通过<code>queryFeedback</code>接口加载）。通过：feedbackResult=approved；驳回：feedbackResult=reject。调用<code>POST feedback</code>接口，参数包含applyCode、designDrawingId、feedbackResult。</li></ul>
</KbCard>

<KbCard num="7" title="重点逻辑7：面积确认/图纸确认">
<ul><li><strong>业务意义</strong>：面积确认用于确认设计面积以计算费用，图纸确认用于确认设计图纸满足需求。</li><li><strong>具体逻辑描述</strong>：面积确认校验 approvalState === 'fdd_in_approval'（FDD签署中），调用<code>useFDD</code>签合同；图纸确认校验 settlementConfirmState === 'to_be_confirm'（待确认），调用<code>useFDD</code>签结算合同。</li></ul>
</KbCard>

<KbCard num="8" title="重点逻辑8：效果图补申">
<ul><li><strong>业务意义</strong>：对已完成的申请进行效果图补充申请，关联原申请。</li><li><strong>具体逻辑描述</strong>：行操作"效果图补申"，跳转<code>/detail/&#123;applyCode&#125;/supplement</code>，使用dealerSaveSupplement/dealerSaveAndSubmitSupplement接口保存，写入RELATION_APPLY_CODE关联原申请，APPLY_TYPE='supplement'。</li></ul>
</KbCard>

<KbCard num="9" title="重点逻辑9：设计改派">
<ul><li><strong>业务意义</strong>：对已生效的设计点将可改派设计师，应对设计师档期变更。</li><li><strong>具体逻辑描述</strong>：调用<code>designReassignment</code>接口，更换设计师并重新走审批流程。</li></ul>
</KbCard>

<KbCard num="10" title="重点逻辑10：行操作显隐">
<ul><li><strong>业务意义</strong>：根据申请状态差异化展示行操作，避免误操作。</li><li><strong>具体逻辑描述</strong>：编辑再发起：orderLectureState === 'draft' 或 approvalState 为 reject/oa_reject/fdd_reject；效果图补申：始终显示，跳转<code>/detail/&#123;applyCode&#125;/supplement</code>；下载图纸：始终显示；终止：根据设计流程状态显示。</li></ul>
</KbCard>

<KbCard num="11" title="重点逻辑11：点将设计面积说明">
<ul><li><strong>业务意义</strong>：明确设计面积计算口径，为费用计算提供依据。</li><li><strong>具体逻辑描述</strong>：点将设计面积为店面原始结构净空面积，用于计算设计点将费用。</li></ul>
</KbCard>

<h4>按钮1：新建（列表页头部）</h4>
<ul><li><strong>显隐条件</strong>：始终显示</li><li><strong>业务逻辑</strong>：跳转详情页<code>/detail/null/add</code>，传入新增模式参数。</li></ul>
<h4>按钮2：编辑（列表行）</h4>
<ul><li><strong>显隐条件</strong>：orderLectureState='draft' 或 approvalState 为 reject/oa_reject/fdd_reject</li><li><strong>业务逻辑</strong>：跳转详情页编辑模式，加载已有数据。</li></ul>
<h4>按钮3：删除（列表行）</h4>
<ul><li><strong>显隐条件</strong>：orderLectureState='draft' 或 approvalState 为 reject/fdd_reject/oa_reject</li><li><strong>业务逻辑</strong>：确认后调用<code>POST delete</code>接口删除申请。</li></ul>
<h4>按钮4：保存（详情页）</h4>
<ul><li><strong>显隐条件</strong>：始终显示</li><li><strong>业务逻辑</strong>：校验通过后调用<code>POST dealerSave</code>接口保存为草稿。</li></ul>
<h4>按钮5：保存并提交（详情页）</h4>
<ul><li><strong>显隐条件</strong>：始终显示</li><li><strong>业务逻辑</strong>：校验通过后调用<code>POST dealerSaveAndSubmit</code>接口保存并提交审批，触发designApplyApproval审批流。</li></ul>
<h4>按钮6：取消申请（列表行）</h4>
<ul><li><strong>显隐条件</strong>：始终显示</li><li><strong>业务逻辑</strong>：弹窗填写取消原因，调用<code>POST cancelApply</code>接口。</li><li><strong>校验</strong>：取消原因必填。</li></ul>
<h4>按钮7：下载设计图纸（列表行）</h4>
<ul><li><strong>显隐条件</strong>：始终显示</li><li><strong>业务逻辑</strong>：弹窗展示三类图纸（设计图、效果图、施工及软装图），通过<code>downloadDrawing</code>接口加载，每类图纸展示文件名称（可点击预览）和反馈按钮。</li></ul>
<h4>按钮8：设计改派（列表行）</h4>
<ul><li><strong>显隐条件</strong>：已生效状态</li><li><strong>业务逻辑</strong>：调用<code>designReassignment</code>接口，更换设计师并重新走审批流程。</li></ul>
<h4>按钮9：查看反馈（列表行）</h4>
<ul><li><strong>显隐条件</strong>：始终显示</li><li><strong>业务逻辑</strong>：调用<code>queryFeedback</code>接口查看历史反馈记录。</li></ul>
<h4>按钮10：上传设计图纸（详情页）</h4>
<ul><li><strong>显隐条件</strong>：设计中状态</li><li><strong>业务逻辑</strong>：调用<code>upload</code>接口上传设计图纸，可选类型为设计图/效果图/施工及软装图。</li></ul>
<h4>按钮11：下单（详情页）</h4>
<ul><li><strong>显隐条件</strong>：图纸确认后</li><li><strong>业务逻辑</strong>：调用<code>startOrder</code>接口下发订单。</li></ul>
<h4>按钮12：区域确认（详情页）</h4>
<ul><li><strong>显隐条件</strong>：FDD签署中（approvalState='fdd_in_approval'）</li><li><strong>业务逻辑</strong>：校验通过后调用<code>areaConfirm</code>接口，useFDD签合同。</li></ul>
<h4>按钮13：开始设计（详情页）</h4>
<ul><li><strong>显隐条件</strong>：审批通过后</li><li><strong>业务逻辑</strong>：调用<code>startDesign</code>接口开始设计流程。</li></ul>
<h4>按钮14：图纸确认（详情页）</h4>
<ul><li><strong>显隐条件</strong>：待确认状态（settlementConfirmState='to_be_confirm'）</li><li><strong>业务逻辑</strong>：校验通过后调用<code>startDrawingConfirm</code>接口，useFDD签结算合同。</li></ul>
<h4>按钮15：终止（列表行）</h4>
<ul><li><strong>显隐条件</strong>：设计流程中</li><li><strong>业务逻辑</strong>：调用<code>termination</code>接口终止设计流程。</li></ul>
<h4>按钮16：效果图补申（列表行）</h4>
<ul><li><strong>显隐条件</strong>：始终显示</li><li><strong>业务逻辑</strong>：跳转详情页<code>/detail/&#123;applyCode&#125;/supplement</code>，使用dealerSaveSupplement/dealerSaveAndSubmitSupplement接口保存补充申请，关联原申请。</li></ul>

<KbCard title="保存/提交校验">
<blockquote>数据来源：<code>detail.tsx</code> 的 <code>handleSave</code> + <code>stores/detailConfig.tsx</code> 字段 required 配置。保存与保存并提交共用同一校验逻辑，依次校验 generalFormDS 和 designInfoFormDS。效果图增补模式使用 dealerSaveSupplement/dealerSaveAndSubmitSupplement 接口。</blockquote>
<p><strong>校验1：</strong>效果图数量必填 —— generalFormDS.renderingNumber，precision=0</p>
<p><strong>校验2：</strong>鸟瞰图必填 —— generalFormDS.airscapeNumber，precision=0</p>
<p><strong>校验3：</strong>店面面积必填（非增补模式） —— generalFormDS.storeArea，min=0.0001，step=0.01，precision=2</p>
<p><strong>校验4：</strong>复尺面积必填（isConfirmArea时） —— generalFormDS.scaleArea</p>
<p><strong>校验5：</strong>签订人必填（haveSigner时） —— generalFormDS.signer</p>
<p><strong>校验6：</strong>所属运营中心必填 —— designInfoFormDS.opCenter</p>
<p><strong>校验7：</strong>交易公司必填 —— designInfoFormDS.tradingCompanyName</p>
<p><strong>校验8：</strong>开票账户必填 —— designInfoFormDS.legalEntityName（选交易公司自动带出）</p>
<p><strong>校验9：</strong>门店名称必填 —— designInfoFormDS.storeName</p>
<p><strong>校验10：</strong>门店地址必填 —— designInfoFormDS.storeArea（选门店自动带出）</p>
<p><strong>校验11：</strong>店面类型必填 —— designInfoFormDS.storeType，值集MBO.ORD_LECTURER_STORE_TYPE</p>
<p><strong>校验12：</strong>取消申请时取消原因必填 —— cancelFormDS.cancelReason</p>
<p><strong>校验13：</strong>图纸反馈时反馈意见必填 —— feedbackFormDS.feedbackComments</p>

```sql
draft(新建) → submitted(已提交) → approved(审批通过) → valid(生效)
   → designing(开始设计) → drawing_uploaded(图纸已上传) → drawing_confirmed(图纸确认)

rejected(审批驳回) → 可修改重提
valid → cancel_applied(取消申请中) → cancel_approved(已取消)
任一环节 → terminated(已终止)
```

```sql
-- 查询经销商设计点将申请
SELECT
  da.APPLY_CODE    AS 申请编码,
  da.DESIGN_NAME   AS 设计名称,
  da.LECTURER_NAME AS 设计师,
  da.ORDER_LECTURE_STATE AS 点将状态,
  da.DESIGN_STATE  AS 设计状态,
  da.APPROVAL_STATE AS 审核状态,
  da.FEEDBACK_NUMBER AS 反馈次数,
  da.RELATION_APPLY_CODE AS 关联单据
FROM DESIGN_APPLY da
ORDER BY da.CREATE_DATE DESC;

-- 查询图纸反馈记录
SELECT
  dd.APPLY_CODE    AS 申请编码,
  dd.FILE_NAME     AS 文件名称,
  dd.DRAWING_TYPE  AS 图纸类型,
  dd.FEEDBACK_RESULT AS 反馈结果,
  dd.FEEDBACK_COMMENTS AS 反馈意见,
  TO_CHAR(dd.OPERATION_TIME, 'YYYY-MM-DD HH24:MI:SS') AS 反馈时间
FROM DESIGN_DRAWING dd
WHERE dd.FEEDBACK_RESULT IS NOT NULL
ORDER BY dd.OPERATION_TIME DESC;

-- 查询效果图补申申请
SELECT
  da.APPLY_CODE    AS 申请编码,
  da.RELATION_APPLY_CODE AS 关联原申请,
  da.DESIGN_NAME   AS 设计名称,
  da.LECTURER_NAME AS 设计师,
  da.APPROVAL_STATE AS 审核状态
FROM DESIGN_APPLY da
WHERE da.APPLY_TYPE = 'supplement';

-- 查询待图纸确认的申请
SELECT
  da.APPLY_CODE    AS 申请编码,
  da.DESIGN_NAME   AS 设计名称,
  da.SETTLEMENT_CONFIRM_STATE AS 结算确认状态
FROM DESIGN_APPLY da
WHERE da.SETTLEMENT_CONFIRM_STATE = 'to_be_confirm';

-- 查询设计师饱和度
SELECT
  da.LECTURER_NAME AS 设计师,
  COUNT(*)         AS 服务中单据数
FROM DESIGN_APPLY da
WHERE da.ORDER_LECTURE_STATE IN ('valid', 'designing', 'drawing_uploaded')
GROUP BY da.LECTURER_NAME;
```

<KbCard title="常见问题">
<p><strong>Q1：经销商看不到自己发起的设计点将记录？</strong></p>
<p>A：检查该经销商是否正确关联当前登录用户，确认DEALER_CODE与当前登录用户关联的经销商一致。</p>
<p><strong>Q2：设计师点将的审批状态如何查看？</strong></p>
<p>A：在详情页中可查看完整审批链路，包括讲师审批、门店审批等各环节状态。</p>
<p><strong>Q3：详情页type参数有什么作用？</strong></p>
<p>A：<code>type</code>参数用于区分详情页的展示模式，不同模式可能展示不同的操作按钮和字段。</p>
<p><strong>Q4：申请点将弹窗无设计师数据？</strong></p>
<p>A：检查campApi.lecturerList接口，pageType=design参数是否正确传递。</p>
<p><strong>Q5：下载图纸弹窗无图纸数据？</strong></p>
<p>A：检查downloadDrawing接口返回，确认设计图已上传。</p>
<p><strong>Q6：图纸反馈失败？</strong></p>
<p>A：检查feedback接口，确认feedbackComments填写。</p>
<p><strong>Q7：面积确认无法签合同？</strong></p>
<p>A：检查approvalState是否为fdd_in_approval。</p>
<p><strong>Q8：效果图补申跳转失败？</strong></p>
<p>A：检查applyCode是否存在，详情页supplement路由配置。</p>
