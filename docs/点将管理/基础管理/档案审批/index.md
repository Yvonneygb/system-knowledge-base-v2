<KbCard num="1" title="重点逻辑1：审批中锁定">
<ul><li><strong>业务意义</strong>：避免审核对象与实际内容不一致，保证审批依据的稳定性</li><li><strong>具体逻辑描述</strong>：</li><li>档案提交后进入"审批中"状态</li><li>提交人不能再修改档案内容</li><li>审批人看到的内容与提交时一致</li></ul>
</KbCard>

<KbCard num="2" title="重点逻辑2：通过即生效">
<ul><li><strong>业务意义</strong>：审批通过是档案/价格可被点将业务选用的前置条件</li><li><strong>具体逻辑描述</strong>：</li><li>档案审批通过 → 档案状态转为"生效"</li><li>价格审批通过 → 价格同步生效</li><li>价格变更审批通过 → 价格更新为新价格</li><li>生效后方可被点将业务选用</li></ul>
</KbCard>

<KbCard num="3" title="重点逻辑3：拒绝可重提">
<ul><li><strong>业务意义</strong>：保证审批不通过时业务可闭环修正</li><li><strong>具体逻辑描述</strong>：</li><li>审批拒绝必须填写审批意见</li><li>档案状态退回可编辑</li><li>提交人按意见修改后可再次提交审批</li></ul>
</KbCard>

<KbCard num="4" title="重点逻辑4：初始化讲师类型加载">
<ul><li><strong>业务意义</strong>：仅展示有审批数据的讲师类型，避免空查询</li><li><strong>具体逻辑描述</strong>：</li></ul>

<h4>档案审批（archivesAudit）</h4>
<ol><li>查看待审批讲师档案的详细信息（个人档案 + 讲师档案）</li><li>审批人审核档案信息的完整性和合理性</li></ol>

<ul><li>通过 → 调用 <code>POST mlt/maLecturerApproval/archivesAudit</code>，传入审批结果=通过</li><li>拒绝 → 调用 <code>POST mlt/maLecturerApproval/archivesAudit</code>，传入审批结果=拒绝 + 审批意见</li></ul>

<ol><li>查看待审批讲师的价格信息（通过 <code>GET mlt/maLecturerApproval/queryCrmLecturerPriceList</code> 获取价格列表）</li><li>审批人审核价格的合理性</li></ol>

<p><strong>4. 审批结果回写：</strong></p>
<ul><li>通过 → 讲师价格生效</li><li>拒绝 → 价格维持原值</li></ul>
<h4>价格变更审批（priceChangeApproval）</h4>
<ol><li>查看待审批讲师的价格变更信息（原价格、新价格、变更原因）</li><li>审批人审核价格变更的合理性</li></ol>

<ul><li>通过 → 调用 <code>POST mlt/maLecturerApproval/priceChangeApproval</code>，传入审批结果=通过</li><li>拒绝 → 调用 <code>POST mlt/maLecturerApproval/priceChangeApproval</code>，传入审批结果=拒绝 + 审批意见</li></ul>
<p><strong>4. 审批结果回写：</strong></p>

<p><strong>校验1：</strong>审批意见 approvalComments 必填 —— 保证审批拒绝时有可追溯的拒绝理由</p>

```sql
SELECT LECTURER_APPROVAL_ID, LECTURER_APPROVAL_CODE, APPROVAL_RESULT, APPROVAL_REMARK
    FROM MA_LECTURER_APPROVAL
    WHERE APPROVAL_RESULT = 'reject' AND (APPROVAL_REMARK IS NULL OR APPROVAL_REMARK = '');

SELECT la.LECTURER_APPROVAL_CODE, la.LECTURER_ARCHIVES_CODE
    FROM MA_LECTURER_APPROVAL la
    LEFT JOIN MA_LECTURER_ARCHIVE ar ON la.LECTURER_ARCHIVES_CODE = ar.LECTURER_ARCHIVES_CODE
    WHERE la.APPROVAL_TYPE = 'archives' AND la.APPROVAL_RESULT = 'pass'
      AND (ar.LECTURER_LEVEL IS NULL OR ar.LECTURER_LEVEL = '');
```
<p><strong>校验3：</strong>档案审批通过时牌价 priceInfo 必填 —— 保证生效档案可参与点将计价</p>
<ul><li><strong>详细逻辑</strong>：approvalType=archives 且结果=通过时，校验关联档案的 priceInfo 非空</li><li><strong>系统体现</strong>：后端 archivesAudit 接口校验</li><li><strong>排查SQL</strong>：</li></ul>

<KbCard title="常见问题">
<ul><li><strong>Q1：档案审批、价格审批、价格变更审批有什么区别？</strong></li></ul>
<p>A：档案审批是对讲师档案基本信息的审批；价格审批是对讲师首次设定价格的审批；价格变更审批是对讲师价格变更的审批。三者审批接口不同（archivesAudit/priceAudit/priceChangeApproval），回写逻辑也不同。</p>
<ul><li><strong>Q2：审批拒绝后能否重新提交？</strong></li></ul>
<p>A：可以。审批拒绝后，讲师档案状态回退，用户可在讲师档案菜单修改后重新提交审批。</p>
<ul><li><strong>Q3：审批通过后能否撤销？</strong></li></ul>
<p>A：审批通过后不支持撤销，如需变更需走变更审批流程。</p>
<ul><li><strong>Q4：价格变更审批中原价格和新价格如何记录？</strong></li></ul>
<p>A：提交价格变更时，系统自动记录原价格（ORIGINAL_PRICE）和新价格（NEW_PRICE），审批人可对比查看。</p>
<ul><li><strong>Q5：一个审批单能否多次审批？</strong></li></ul>
<p>A：不可以。每个审批单仅可审批一次，审批后状态终态化。</p>
<ul><li><strong>Q6：讲师类型下拉为空？</strong></li></ul>
<p>A：检查 getLecturerTypeList 接口返回，确认有审批数据的类型，并确认值集 MBO.LECTURER_TYPE 已配置。</p>
<ul><li><strong>Q7：审批跳转页面错误？</strong></li></ul>
<p>A：检查 approvalType 字段值（archives/price），路由配置是否正确。</p>
<ul><li><strong>Q8：审批状态无待提交选项？</strong></li></ul>
<p>A：值集已过滤 to_be_submit，仅展示已提交状态，属正常设计。</p>
<ul><li><strong>Q9：列表无数据？</strong></li></ul>
<p>A：确认讲师类型选择正确，该类型下是否有审批数据。</p>
