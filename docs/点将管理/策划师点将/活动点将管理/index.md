<ul><li><strong>业务意义</strong>：同一菜单页面通过pageType参数切换三种视图模式，复用列表与查询能力，差异化展示按钮和操作。</li><li><strong>具体逻辑描述</strong>：通过<code>useAuthPageOption</code>实现三种模式切换。manage（点将活动管理）显示按计划结算、同步CRM、特殊取消按钮；approval（活动点将审批）显示审批、同步OA、同步FDD按钮；cancelApproval（活动点将取消审批）显示审批、同步OA按钮。查询接口<code>pageType</code>参数默认为<code>manage</code>。</li></ul>
</KbCard>

<KbCard num="2" title="重点逻辑2：双审批流独立运行">
<ul><li><strong>业务意义</strong>：活动点将申请提交与取消分别走独立审批流，互不影响，确保申请与取消审批权责清晰。</li><li><strong>具体逻辑描述</strong>：申请提交触发activityApplyApproval审批流（applyTypeTwo=apply）；取消申请触发activityCancelApplyOrgApproval审批流（applyTypeTwo=cancel_apply，组织级审批）。审批参数 applyTypeOne=activity，approvalResult=approved/reject。</li></ul>
</KbCard>

<KbCard num="3" title="重点逻辑3：按计划结算">
<ul><li><strong>业务意义</strong>：对已生效的活动点将按计划进行结算，下发结算金额与目标数据，驱动费用结算与对账。</li><li><strong>具体逻辑描述</strong>：通过Modal弹窗实现，包含结算信息（PlanSettlementInfo）展示目标数据和完成数据，申请详情（ActivityApplyDetail）通过<code>onDetail</code>回调同步数据到结算信息。保存并下发时收集目标数据、完成数据、签订人、讲师牌价、结算金额、实际时间，调用<code>POST settleForPlan</code>接口（管理页面用settleForPlan，执行页面用startSettle）。</li></ul>
</KbCard>

<KbCard num="4" title="重点逻辑4：特殊取消校验">
<ul><li><strong>业务意义</strong>：对已生效且活动开始时间临近的申请提供特殊取消通道，约束时间窗口与状态，避免随意取消影响活动执行。</li><li><strong>具体逻辑描述</strong>：校验规则与特训营点将管理一致。时间差值<code>timeDiff</code>需在1-7天内；审批状态需为<code>fdd_sign</code>（已法大大签约）；未发起过取消申请（或已驳回）。校验通过后提交调用<code>POST specialCancel</code>接口。</li></ul>
</KbCard>

<KbCard num="5" title="重点逻辑5：applyCode自动生成">
<ul><li><strong>业务意义</strong>：保证活动点将申请编码全局唯一、可追溯，作为主键贯穿全链路。</li><li><strong>具体逻辑描述</strong>：提交申请时系统自动生成唯一编码applyCode，写入APPLY_CODE字段。</li></ul>
</KbCard>

<KbCard num="6" title="重点逻辑6：状态联动">
<ul><li><strong>业务意义</strong>：点将状态是策划师档期占用与费用发生的唯一依据，任何调整都必须通过审批或取消审批完成，不得绕过流程改单。</li><li><strong>具体逻辑描述</strong>：活动点将申请状态与审批状态联动，审批通过后申请状态自动变更为已通过；取消审批通过后状态变更为已取消；取消则同步回退下游状态。</li></ul>
</KbCard>

<KbCard num="7" title="重点逻辑7：同步外部系统差异化">
<ul><li><strong>业务意义</strong>：根据pageType差异化推送外部系统，避免误推送与重复推送。</li><li><strong>具体逻辑描述</strong>：同步CRM仅pageType=manage显示；同步OA在pageType≠manage时显示；同步FDD仅pageType=approval显示。</li></ul>
</KbCard>

  aa.DISTRIBUTOR_NAME AS 申请人,
  aa.ACTIVITY_NAME AS 活动名称,
  aa.LECTURER_NAME AS 培训师,

  aa.LECTURER_PRICE AS 讲师牌价,
  aa.SETTLEMENT_AMOUNT AS 结算金额
FROM TRAIN_APPLY aa
WHERE aa.APPLY_TYPE_ONE = 'activity'
ORDER BY aa.CREATE_DATE DESC;

-- 查询可按计划结算的申请
SELECT
  aa.APPLY_CODE    AS 申请编码,
  aa.ACTIVITY_NAME AS 活动名称,
  aa.LECTURER_PRICE AS 讲师牌价,
  aa.PRE_ORD_LECTURER_DAYS AS 拟点将天数
FROM TRAIN_APPLY aa
WHERE aa.APPLY_TYPE_ONE = 'activity'
  AND aa.APPROVAL_STATE = 'approved'
  AND aa.SETTLEMENT_CONFIRM_STATE = 'pending';

-- 查询可发起特殊取消的申请

  aa.APPLY_CODE    AS 申请编码,
  TO_CHAR(aa.ACTIVITY_START_DATE, 'YYYY-MM-DD') AS 活动开始时间,
  aa.APPROVAL_STATE AS 审核状态,
  ROUND((aa.ACTIVITY_START_DATE - SYSDATE)) AS 距开始天数
FROM TRAIN_APPLY aa
WHERE aa.APPLY_TYPE_ONE = 'activity'
  AND aa.APPROVAL_STATE = 'fdd_sign'
  AND aa.ACTIVITY_START_DATE > SYSDATE
  AND aa.ACTIVITY_START_DATE <= SYSDATE + 7
  AND (aa.CANCEL_APPROVAL_STATE IS NULL
       OR aa.CANCEL_APPROVAL_STATE IN ('reject', 'oa_reject'));

<KbCard title="常见问题">
<p><strong>Q1：活动点将与特训营点将有什么区别？</strong></p>
<p>A：活动点将由策划师发起，审批流为activityApplyApproval；特训营点将由经销商/业务员发起，审批流为campApplyApproval。</p>
<p><strong>Q2：取消审批为什么是组织级审批？</strong></p>
<p>A：活动取消影响范围较大，需组织级管理层审批确认，因此取消审批流为activityCancelApplyOrgApproval。</p>
<p><strong>Q3：活动点将申请被拒绝后能否重新提交？</strong></p>
<p>A：可以，拒绝后可修改申请内容重新提交审批。</p>
<p><strong>Q4：按计划结算按钮不显示？</strong></p>
<p>A：确认pageType为manage，按计划结算仅在管理视图显示。</p>
<p><strong>Q5：同步FDD按钮不显示？</strong></p>
<p>A：确认pageType为approval，同步FDD仅在审批视图显示。</p>
