<KbCard num="1" title="重点逻辑1：基于报销申请单发起兑现">
<ul><li><strong>业务意义</strong>：门头展板兑现不能独立创建，必须关联已审批通过(APPROVED)的门头展板报销申请单，确保兑现有据可依</li><li><strong>具体逻辑描述</strong>：</li><li>新增页面通过LOV(AE.CUSTDHCASHOUTHEADLIST.VIEW)选择报销申请单，接口GET <code>/cust-dh-reimburse-heads/get-cashout-lov</code></li><li>选择后调用GET <code>/cust-dh-reimburse-heads/do-select</code>查询报销单详情，联动带出经销商、交易公司、法人客户、预算年度、报销类型、支付方式、额度内外金额等全部信息</li><li>后端checkParams校验：报销单必须存在且hzApproveStatus=APPROVED，否则报"报销单号不存在或未完成审核"</li><li>后端checkParams校验：同一报销单下不能存在未审批完成的兑现单(状态非APPROVED)，否则报"该报销单存在未审批结束的兑现单X，请勿重复创建"</li></ul>

<h4>报错8：申请金额需≤剩余未申请金额</h4>
<ul><li><strong>触发条件</strong>：点击"提交"按钮，firstSubmitVerify校验同一报销单下，本次额度外申请金额&gt;报销单实际额度外报销金额-已提交或已审批的sum(各兑现单本次额度外申请金额)</li><li><strong>逻辑分析</strong>：同一报销单下可分多次兑现，但累计额度外申请金额不得超过报销单实际额度外报销金额。校验逻辑计算：报销单实际额度外报销金额-已有兑现单(状态RUN/APPROVED/RETURN/INTERRUPT)的outCashoutApplyAmt之和，若本次申请金额超过该余额即抛异常。常见根因：已有兑现单占用大部分金额、本次申请金额过大、或报销单金额被错误调整。</li><li><strong>排查SQL</strong>：</li></ul>

```sql
SELECT r.id                       AS 报销单ID,
         r.reimburse_code           AS 报销单号,
         r.out_fin_amt              AS 额度外实际报销金额,
         NVL((SELECT SUM(c.out_cashout_apply_amt)
              FROM   cust_dh_cashout_head c
              WHERE  c.reimburse_head_id = r.id
              AND    c.hz_approve_status IN ('RUN','APPROVED','RETURN','INTERRUPT')), 0) AS 已申请金额,
         r.out_fin_amt - NVL((SELECT SUM(c.out_cashout_apply_amt)
              FROM   cust_dh_cashout_head c
              WHERE  c.reimburse_head_id = r.id
              AND    c.hz_approve_status IN ('RUN','APPROVED','RETURN','INTERRUPT')), 0) AS 剩余未申请金额
  FROM   cust_dh_reimburse_head r
  WHERE  r.hz_approve_status = 'APPROVED'
  ORDER  BY r.last_update_date DESC;
```

<h4>报错18：申请兑现比例需≤X</h4>
<ul><li><strong>触发条件</strong>：点击"保存"按钮，checkParams校验outCashoutRatio&gt;1-sumOutCashoutRatio（已提报的申请兑现比例合计）</li><li><strong>逻辑分析</strong>：同一报销单下可分多次兑现，各兑现单的额度外兑现比例之和不得超过1(100%)。校验逻辑汇总同一REIMBURSE_HEAD_ID下已提报兑现单的outCashoutRatio之和(sumOutCashoutRatio)，若本次比例&gt;1-sumOutCashoutRatio即抛异常。常见根因：已有兑现单占用大部分比例、本次比例输入过大。需修改比例至≤剩余可申请比例。</li><li><strong>排查SQL</strong>：</li></ul>

```sql
SELECT c.id                 AS 兑现单ID,
         c.cashout_no         AS 兑现单号,
         c.reimburse_head_id  AS 报销单ID,
         c.out_cashout_ratio  AS 额度外兑现比例,
         NVL((SELECT SUM(t.out_cashout_ratio)
              FROM   cust_dh_cashout_head t
              WHERE  t.reimburse_head_id = c.reimburse_head_id
              AND    t.hz_approve_status IN ('RUN','APPROVED','RETURN','INTERRUPT')
              AND    t.id <> c.id), 0) AS 已提报比例,
         1 - NVL((SELECT SUM(t.out_cashout_ratio)
              FROM   cust_dh_cashout_head t
              WHERE  t.reimburse_head_id = c.reimburse_head_id
              AND    t.hz_approve_status IN ('RUN','APPROVED','RETURN','INTERRUPT')
              AND    t.id <> c.id), 0) AS 剩余可申请比例
  FROM   cust_dh_cashout_head c
  WHERE  c.hz_approve_status = 'NEW'
  ORDER  BY c.creation_date DESC;
```

<KbCard title="常见问题">
<p><strong>Q1：报销申请单LOV无数据？</strong></p>
<p>A：检查CUST_DH_REIMBURSE_HEAD表中是否存在HZ_APPROVE_STATUS='APPROVED'的记录，且该报销单下不存在未审批完成的兑现单。排查SQL：<code>SELECT * FROM CUST_DH_REIMBURSE_HEAD WHERE HZ_APPROVE_STATUS = 'APPROVED' AND ENTID = #&#123;当前用户组织ID&#125;</code></p>
<p><strong>Q2：兑现金额计算不正确？</strong></p>
<p>A：额度内申请兑现金额 = 额度内业务批准金额 - 已兑现的申请兑现金额(同一报销单下APPROVED状态的兑现单IN_CASHOUT_APPLY_AMT之和)。额度外申请兑现金额 = min(兑现比例 × 额度外实际报销金额, 额度外实际报销金额 - 已提报金额)。排查SQL：<code>SELECT SUM(IN_CASHOUT_APPLY_AMT), SUM(OUT_CASHOUT_APPLY_AMT), SUM(OUT_CASHOUT_RATIO) FROM CUST_DH_CASHOUT_HEAD WHERE REIMBURSE_HEAD_ID = #&#123;reimburseHeadId&#125; AND HZ_APPROVE_STATUS = 'APPROVED'</code></p>
<p><strong>Q3：审批流程未启动？</strong></p>
<p>A：检查workflow/proc-submit接口调用参数是否完整(objId, subject='SUB_STORE_MTZBBXDX', flowCode)。确认工作流配置中SUB_STORE_MTZBBXDX流程已部署。排查SQL：<code>SELECT HZ_INSTANCE_ID, HZ_APPROVE_STATUS FROM CUST_DH_CASHOUT_HEAD WHERE ID = #&#123;id&#125;</code></p>
<p><strong>Q4：额度外预算不足？</strong></p>
<p>A：检查当前年份额度外总预算是否充足。排查SQL：<code>SELECT * FROM FIN_FEE_CHECK_BX_HEADER WHERE BUD_YEAR = #&#123;year&#125; AND FEE_TYPE_ID = 66014602 AND DIVISION_ID = #&#123;divisionId&#125;</code>。同时检查已使用金额：<code>SELECT SUM(OUT_CASHOUT_APPLY_AMT) FROM CUST_DH_CASHOUT_HEAD WHERE REIMBURSE_HEAD_ID = #&#123;reimburseHeadId&#125; AND HZ_APPROVE_STATUS IN ('RUN','RETURN','APPROVED','INTERRUPT')</code></p>
<p><strong>Q5：保证书无法填写？</strong></p>
<p>A：确认当前审批节点taskName为"区域经理审批"或"设计师审批"。保证书中的CheckBox和TextField仅在对应对审批节点可编辑。前端通过taskName匹配控制disabled属性。</p>
<p><strong>Q6：门店装修信息为空？</strong></p>
<p>A：门店装修信息从报销申请单行表联动带入，选择报销申请单时自动加载。若为空，检查报销单行表CUST_DH_REIMBURSE_LINE是否有数据。排查SQL：<code>SELECT * FROM CUST_DH_REIMBURSE_LINE WHERE HEAD_ID = #&#123;reimburseHeadId&#125;</code></p>
