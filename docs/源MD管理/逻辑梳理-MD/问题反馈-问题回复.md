# 问题反馈-问题回复

> **说明**：本菜单后端代码位于 `mbo-business` 微服务，API 路径前缀为 `feedback/*`。前端源码位于 `arrow-mbo/src/pages/afterSales/feedback/brand/list.tsx`。事业部/品牌方回复经销商提交的问题反馈。

## 业务流程

### 业务流程图

```
事业部/品牌方用户进入问题回复页面
        |
        ├── 查询反馈单列表（事业部视角）
        |       └── 按问题编号/问题类型/问题状态/提交人/提交时间筛选
        |
        ├── 查看详情 ──→ 跳转反馈单详情页
        |       └── 查看经销商反馈内容、进行回复、查看回复历史
        |
        ├── 回答 ──→ 填写回答内容，提交 answer 接口
        |
        ├── 追评 ──→ 对已回答的问题进行追加反馈
        |
        ├── 完成 ──→ 确认后调用完成接口
        |
        ├── 评价 ──→ 对问题处理结果进行评价
        |
        └── 导出 ──→ 导出反馈单列表到 Excel
```

### 上游依赖

| 上游模块 | 依赖类型 | 依赖说明 | 依赖成立条件 |
|---------|---------|---------|-------------|
| mbo-business 微服务 | 后端服务 | 提供反馈单查询、回答、追评、完成、评价等接口（`feedback/*`） | 微服务已部署且可用 |
| HZERO 值集平台 | 平台服务 | 提供问题类型、问题状态值集 | 值集已配置 |
| HZERO 用户服务 | 平台服务 | 获取当前登录用户、事业部信息 | 用户已登录 |
| 经销商问题反馈 | 业务上游 | 经销商提交的反馈单数据 | 经销商已提交反馈单 |

### 下游影响

- **经销商问题反馈**：事业部回复后，经销商可在问题反馈页面查看回复内容并进行评价。
- **反馈单完结**：完结后反馈单不可再操作，状态变为已完成。

## 重点逻辑

### 重点逻辑1：事业部与经销商视角差异

- **业务意义**：事业部和经销商查看同一批反馈单，但操作权限和 API 接口不同，确保职责分离。
- **具体逻辑描述**：事业部使用 `POST feedback/division/page` 接口查询（经销商使用 `POST feedback/distributor/page`），事业部可执行：查看详情、回答、追评、完成、评价、导出；无新增、编辑、删除按钮。

### 重点逻辑2：回答逻辑

- **业务意义**：事业部对经销商提交的问题进行回复，推动问题处理流程。
- **具体逻辑描述**：选择一条已提交/处理中状态的问题，填写回答内容（必填），提交 `POST feedback/answer` 接口，回答后状态变为已回答，记录处理人和处理时间。

### 重点逻辑3：追评逻辑

- **业务意义**：对已回答的问题进行追加反馈，支持多轮沟通。
- **具体逻辑描述**：对已回答状态的问题，事业部或经销商可进行追加反馈，调用 `POST feedback/comment` 接口，追评后状态变为处理中，等待对方再次回复。

### 重点逻辑4：完成逻辑

- **业务意义**：问题处理完毕后标记为已完成，关闭问题处理流程。
- **具体逻辑描述**：选择已回答状态的问题，确认后调用 `POST feedback/end/${id}` 接口，完成后状态变为已完成，反馈单不可再操作。

### 重点逻辑5：评价逻辑

- **业务意义**：经销商对问题处理结果进行评价，帮助改进服务质量。
- **具体逻辑描述**：问题完成后，经销商可对处理结果进行评价，调用 `POST feedback/evaluate` 接口，写入评价星级和评价内容。

#### 按钮1：导出（列表工具栏）

**触发条件**：点击"导出"按钮

**执行逻辑**：
1. 收集当前查询条件
2. 调用 `POST feedback/division/export` 接口导出
3. 浏览器下载 Excel 文件

#### 按钮2：回复（列表行操作）

**触发条件**：选择 state 在 [4,5] 且有编辑权限的反馈单点击"回复"

**执行逻辑**：
1. 调用 `openTab` 打开新标签页
2. 路由：`/afterSales/brand/feedback/detail/${id}`
3. 调用 `GET feedback/detail/${id}` 加载详情
4. 在详情页填写回复内容（commentContent，必填）
5. 调用 `POST feedback/answer` 接口提交回复
6. 提交数据：`{ commentContent, id, fileDTOList: attachmentsRef.current }`
7. 成功后关闭标签页 `handleCloseTab()`

#### 按钮3：完结（列表行操作）

**触发条件**：选择 state 在 [4,5] 且有编辑权限的反馈单点击"完结"

**执行逻辑**：
1. 弹出确认框 `Modal.confirm({ title: '提示', children: '确认完结该反馈吗？' })`
2. 确认后调用 `POST feedback/end/${id}` 接口完结反馈单
3. 成功后关闭标签页 `handleCloseTab()`

#### 按钮4：取消（列表行操作）

**触发条件**：选择 state 不在 [6,7,8] 且有编辑权限的反馈单点击"取消"

#### 详情页组件

##### 反馈回复记录组件（FeedbackChat）

详情页底部展示反馈回复记录组件，以聊天气泡形式展示反馈和回复的历史记录：
- 每条记录显示操作人（operationUserName）、所属门店（dept）、操作时间（operationTime）
- 事业部消息在左侧，经销商消息在右侧（根据 `from='brand'` 判断）
- 支持图片预览（Picture 组件）、视频播放（video 标签）、文件下载（a 标签）
- 附件按 tab 分组展示

##### 评价组件（Evaluation）

当详情页 state=7（已评价）时，展示评价组件：
- 显示评价星级（Rate 组件，allowHalf，allowClear，disabled）
- 显示评价内容（TextArea，disabled）
- 数据通过 `evaluationRef.current?.loadData()` 加载

### 选择弹窗

本页面无选择弹窗。评价功能在详情页通过评价组件展示，不单独弹出评价弹窗。

### 保存校验

- 校验1：回答内容必填 —— 确保回答内容完整，便于经销商理解处理结果

### 提交校验

- 校验1：回答内容必填 —— 确保回答内容完整
- 校验2：反馈单状态校验 —— 仅已提交/处理中状态的反馈单可回答，已回答状态可追评

### 状态机

```
[已提交] ──事业部受理──→ [处理中] ──事业部回答──→ [已回答] ──完成──→ [已完成]
                              |
                              └──经销商追评──→ [处理中]

[已回答] ──事业部追评──→ [处理中] ──事业部回答──→ [已回答]
```

| 当前状态 | 触发动作 | 目标状态 |
|---------|---------|---------|
| 已提交 | 事业部受理 | 处理中 |
| 处理中 | 事业部回答 | 已回答 |
| 已回答 | 经销商追评 | 处理中 |
| 已回答 | 事业部追评 | 处理中 |
| 已回答 | 完成 | 已完成 |
| 已完成 | 评价 | 已评价 |

### 报错一览表

| 报错信息 | 提示节点 | 根因与解决方案 | 等级 | 详细逻辑 |
|---------|---------|---------------|------|---------|
| 请求失败 | 查询/操作时 | 接口返回非成功状态；查看接口返回消息 | 错误 | 接口调用失败 |
| 请选择一条数据 | 行操作时 | 未选择数据行；选择一条数据后操作 | 警告 | 行操作前校验选中行 |
| 回答内容不能为空 | 回答/追评时 | `ANSWER_CONTENT` 字段未填写；填写回答内容 | 错误 | 必填校验 |
| 确定完结该反馈单吗？ | 完成时 | 二次确认；确认后执行完结 | 提示 | 完结前确认 |
| 该反馈单不可回答 | 回答时 | 反馈单状态非已提交/处理中；确认反馈单状态 | 错误 | 状态校验 |
| 该反馈单不可完结 | 完成时 | 反馈单状态非已回答；确认反馈单状态 | 错误 | 状态校验 |
| 导出无数据 | 导出时 | 查询结果为空；调整查询条件 | 警告 | 导出前校验数据 |
| 网络异常/接口超时 | 任意接口调用 | 网络中断或接口响应超时，检查网络及后端超时配置 | error | axios catch 或 timeout |
| 权限不足 | 点击操作按钮 | 当前用户无对应按钮权限码，联系管理员授权 | error | permissionList 校验未通过 |

| 值集数据不显示 | 下拉选项 | 值集 MBO.FEEDBACK_TYPE 等未配置，检查值集配置 | warning | lookupCode 查询返回空 |

| 评价内容不能为空 | 提交评价 | 未填写评价内容，填写后提交 | error | 前端校验 EVALUATE_CONTENT 非空 |

#### 报错1：请求失败
- **触发条件**：调用 `feedback/*` 系列接口（查询/回答/追评/完成/评价/导出）时，接口返回非成功状态或网络异常
- **逻辑分析**：前端 axios 请求未捕获到成功响应，可能原因：①mbo-business 微服务未启动或不可用；②当前用户登录态过期（TOKEN 失效）；③接口入参格式错误（如 id 为 null、回答内容超长）；④数据库连接异常导致服务端 500。需查看浏览器 Network 面板中对应请求的 Response Body 获取具体错误消息，再针对性排查。
- **排查SQL**：
  ```sql
  -- 查询近期被操作但回答内容异常（超长或为空）的反馈单，定位入参问题
  SELECT 反馈单.QUESTIONID    AS 问题编号,
         反馈单.TITLE         AS 问题标题,
         反馈单.STATE         AS 问题状态,
         反馈单.ANSWER_NAME   AS 处理人,
         反馈单.LAST_UPDATE_DATE AS 最后更新时间
  FROM FEEDBACK 反馈单
  WHERE 反馈单.ANSWER_CONTENT IS NULL
     OR LENGTH(反馈单.ANSWER_CONTENT) > 2000
  ORDER BY 反馈单.LAST_UPDATE_DATE DESC;
  ```

#### 报错3：回答内容不能为空
- **触发条件**：点击"回答"或"追评"提交时，`ANSWER_CONTENT` 字段为空或仅含空白字符
- **逻辑分析**：前端表单校验 `evaluateFormDs.validate()` / answerForm 校验 `ANSWER_CONTENT` 必填，trim 后为空则阻止提交；后端 `feedback/answer`、`feedback/comment` 接口同样对 `ANSWER_CONTENT` 做 `@NotBlank` 校验，双重保障。解决方案：填写回答内容后重新提交。
- **排查SQL**：
  ```sql
  -- 查询历史回答内容为空但状态已变更为已回答的异常反馈单
  SELECT 反馈单.QUESTIONID      AS 问题编号,
  ```

#### 报错5：该反馈单不可回答
- **触发条件**：对状态非"已提交/处理中"的反馈单点击"回答"按钮
- **逻辑分析**：后端 `feedback/answer` 接口校验 `FEEDBACK.STATE` 必须为已提交(1)或处理中(2)，若为已回答(3)/已完成(4)则抛出该错误。常见场景：①列表数据未刷新，反馈单已被他人回答；②并发操作，两个事业部用户同时回答同一反馈单；③经销商已追评将状态改为处理中后又再次追评。解决方案：刷新列表确认反馈单当前状态后再操作。
- **排查SQL**：
  ```sql
  -- 查询反馈单当前状态，确认是否处于可回答状态（已提交=1 / 处理中=2）
  SELECT 反馈单.QUESTIONID      AS 问题编号,
         反馈单.TITLE           AS 问题标题,
         反馈单.STATE           AS 问题状态,
         反馈单.ANSWER_NAME     AS 最近处理人,
         反馈单.LAST_UPDATE_DATE AS 最后更新时间
  FROM FEEDBACK 反馈单
  WHERE 反馈单.QUESTIONID = :问题编号
    AND 反馈单.STATE NOT IN (1, 2);
  ```

#### 报错6：该反馈单不可完结
- **触发条件**：对状态非"已回答"的反馈单点击"完成"按钮
- **逻辑分析**：后端 `feedback/end/${id}` 接口校验 `FEEDBACK.STATE` 必须为已回答(3)，若为已提交(1)/处理中(2)/已完成(4)则抛出该错误。常见场景：①反馈单尚在处理中未回答；②已被他人完结；③列表未刷新导致状态显示滞后。解决方案：刷新列表确认状态为已回答后再完结。
- **排查SQL**：
  ```sql

  SELECT 反馈单.QUESTIONID      AS 问题编号,

         反馈单.STATE           AS 问题状态,
  ```

#### 报错7：导出无数据
- **触发条件**：点击"导出"按钮时，当前查询条件下列表结果为空
- **逻辑分析**：前端先调用 `POST feedback/division/page` 查询总数，若 total=0 则弹出该警告，不调用导出接口；或后端导出接口查询结果为空返回空文件。常见场景：①查询条件过严（时间范围/问题类型/问题状态组合无数据）；②事业部视角下无可见反馈单；③提交时间范围默认近一个月但该时段无数据。解决方案：放宽查询条件（如扩大时间范围、清空问题类型筛选）后重试。
- **排查SQL**：
  ```sql
  -- 查询当前查询条件下反馈单数量，确认是否真的无数据
  SELECT COUNT(*)              AS 反馈单总数,
         SUM(CASE WHEN 反馈单.STATE = 1 THEN 1 ELSE 0 END) AS 已提交数,
         SUM(CASE WHEN 反馈单.STATE = 2 THEN 1 ELSE 0 END) AS 处理中数,
         SUM(CASE WHEN 反馈单.STATE = 3 THEN 1 ELSE 0 END) AS 已回答数,
         SUM(CASE WHEN 反馈单.STATE = 4 THEN 1 ELSE 0 END) AS 已完成数
  FROM FEEDBACK 反馈单
  WHERE 反馈单.CREATE_TIME BETWEEN :开始时间 AND :结束时间
    AND (:问题类型 IS NULL OR 反馈单.TYPE_CODE = :问题类型)
    AND (:问题状态 IS NULL OR 反馈单.STATE = :问题状态)
    AND (:提交人   IS NULL OR 反馈单.CREATE_NAME LIKE '%' || :提交人 || '%');
  ```

#### 报错8：网络异常/接口超时
- **触发条件**：任意接口调用时，网络中断或接口响应超过 axios timeout 配置
- **逻辑分析**：前端 axios 请求未收到响应或响应超时，触发 catch 回调统一提示"请求失败"。常见根因：网络中断、mbo-business 服务假死、数据库慢查询等。需检查网络连通性、后端服务负载、数据库性能
- **排查SQL**：
  ```sql
  SELECT 反馈单.QUESTIONID AS 问题编号, 反馈单.TITLE AS 问题标题,
         反馈单.STATE AS 问题状态,

  FROM FEEDBACK 反馈单
  ```

#### 报错9：权限不足
- **触发条件**：点击回答、追评、完成、评价等按钮时，当前用户无对应 permissionList 权限码
- **逻辑分析**：前端 Button 组件通过 permissionList 配置权限码，HZERO 框架校验当前用户角色是否包含该权限码，未包含则按钮不可见或禁用。若强制调用接口，后端也会校验权限返回403。需联系管理员配置对应角色权限
- **排查SQL**：
  ```sql
  SELECT U.USER_NAME AS 用户名, R.ROLE_NAME AS 角色名, P.PERMISSION_CODE AS 权限码
  FROM SYS_USER U
  LEFT JOIN SYS_USER_ROLE UR ON U.USER_ID = UR.USER_ID
  LEFT JOIN SYS_ROLE R ON UR.ROLE_ID = R.ROLE_ID
  LEFT JOIN SYS_ROLE_PERMISSION RP ON R.ROLE_ID = RP.ROLE_ID
  LEFT JOIN SYS_PERMISSION P ON RP.PERMISSION_ID = P.PERMISSION_ID
  WHERE P.PERMISSION_CODE LIKE '%feedback_answer%' ORDER BY U.USER_NAME;
  ```

## 常见问题FAQ

| 问题 | 答案/排查方式 |

### 排查SQL汇总

```sql
-- 1. 查询待回复的反馈单
SELECT QUESTIONID, TITLE, TYPE_CODE, CONTENT,
       CREATE_TIME, CREATE_NAME, DISTRIBUTOR_NAME
FROM FEEDBACK
WHERE STATE = :submittedState
ORDER BY CREATE_TIME ASC;

-- 2. 查询已回答待完结的反馈单
SELECT QUESTIONID, TITLE, CONTENT, ANSWER_CONTENT,
       ANSWER_TIME, ANSWER_NAME, CREATE_NAME
FROM FEEDBACK
WHERE STATE = :answeredState
ORDER BY ANSWER_TIME DESC;

-- 3. 查询某事业部的反馈单
SELECT QUESTIONID, TITLE, STATE, CREATE_TIME, ANSWER_TIME
FROM FEEDBACK
WHERE ANSWER_NAME = :divisionUser
ORDER BY ANSWER_TIME DESC;

-- 4. 查询已完结待评价的反馈单
SELECT QUESTIONID, TITLE, ANSWER_CONTENT, ANSWER_TIME, CREATE_NAME
FROM FEEDBACK
WHERE STATE = :completedState
  AND GRADE IS NULL
ORDER BY ANSWER_TIME DESC;
```
