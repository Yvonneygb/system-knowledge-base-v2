# 工程管理-项目商机-报备解冻申请

> 本页面为低代码页面(hlod)，无独立前端源码，无自定义Controller，基于后端ServiceImpl与Entity梳理。对已冻结的项目报备申请解除冻结，恢复有效状态并重置相关生命周期信息。

## 业务流程

### 解冻如何流转

选择已冻结项目 → 填写解冻信息 → 保存 → 提交审批 → 校验进度一致性 → 审批通过恢复项目状态并更新进度。

```
用户进入报备解冻申请页面
  → 选择已冻结的项目报备（PROJECT_VALID=4）
  → 查询项目冻结信息（freezeType、freezeTime）
  → 填写解冻申请信息：
    → 解冻申请说明（reason）
    → 解冻后跟进进度（stageValueAfter）
    → 解冻后进度描述（stageDescAfter）
    → 项目信息确认（contentConfirm，Y/N）
  → 保存生成解冻申请单号
  → 提交审批，触发工作流（ENGINEERING_REPORT_JDSQ_MAIN）
  → 工作流提交回调（wfProcSubmit）：
    → 校验附件（checkContentConfirm）
    → 推送ES数据（reportToEs）
  → 工作流校验回调（volidate）：
    → 校验进度一致性（stageValueBefore <= stageValueAfter）
    → 不一致抛出"项目进度已变更，请驳回重审!"
  → 流程事件执行（eventExecute）：
    → 更新HZ_INSTANCE_ID、HZ_APPROVE_STATUS=RUN
    → 更新流程变量freezeTime、contentConfirm
  → 审批通过后执行 wfComplete → doAudit：
    → 读取报备有效周期天数（PROJ_EFFECTIVE_CYCLE）
    → 更新EPM_PROJECT：PROJECT_VALID=2，UNFREEZE_TIME=now，FREEZE_TYPE=0，FREEZE_TIME=null
    → 超项目有效期（freezeType=1/4）：重置VALID_START_DATE/VALID_END_DATE
    → 更新项目进度表（doUpdate）
    → 记录审批人、审批时间
  → onWfComplete：推送CRM（validStatus=1），更新auditStat
  → 审批拒绝执行 onUserReject：删除ES数据
```

### 全链路流程图

```
开始 → ★新建解冻申请★ → 选择已冻结项目 → 填写解冻信息 → 保存 → 提交工作流
     → 校验进度一致性 · ⚖审批通过？ → 恢复项目状态/更新进度/重置有效期/推送CRM → 结束（拒绝则删除ES数据）

上游支撑：项目档案(EPM_PROJECT)、项目报备(EPM_REPORT)、阶段定义(EPM_STAGE_DEF)、项目进度历程、系统参数、工作流引擎、CRM系统、ES搜索引擎
下游影响：项目档案有效状态、项目进度历程、CRM报备状态、ES搜索索引、项目商机查询
```

### 冻结类型区分

- **freezeType=1 超项目有效期**：项目报备后超过有效周期未产生合同，解冻后重置有效周期(VALID_START_DATE=now, VALID_END_DATE=now+effectiveCycle+1)
- **freezeType=2 进度超时更新**：项目进度超时未更新，解冻后仅恢复状态，强制更新进度(forceUpdate=2)
- **freezeType=4 其他冻结类型**：同freezeType=1处理逻辑

## 重点逻辑

### 重点逻辑1：按冻结类型差异化处理

- **业务意义**：不同冻结原因解冻后恢复方式不同，超有效期需重置周期，进度超时需强制更新进度
- **具体逻辑描述**：
  - freezeType=1/4(超有效期)：PROJECT_VALID=2, UNFREEZE_TIME=now, VALID_START_DATE=now, VALID_END_DATE=now+effectiveCycle+1, FREEZE_TYPE=0, FREEZE_TIME=null
  - freezeType=2(进度超时)：PROJECT_VALID=2, UNFREEZE_TIME=now, FREEZE_TYPE=0, FREEZE_TIME=null，不重置有效周期，强制更新进度(forceUpdate=2)

### 重点逻辑2：进度一致性校验

- **业务意义**：防止解冻申请提交后项目进度被其他单据变更，导致解冻后进度回退
- **具体逻辑描述**：
  - volidate和doAudit中均校验stageValueBefore不大于stageValueAfter
  - 若stageValueBefore > stageId(解冻后进度)，抛出"项目进度已变更，请驳回重审!"
  - doUpdate中校验解冻后阶段序号不小于解冻前阶段序号，否则抛出"阶段更新，只能前进，不能后退"

### 重点逻辑3：附件校验

- **业务意义**：确保解冻建立在真实、完整的项目信息之上
- **具体逻辑描述**：
  - onUserSubmit中调用checkContentConfirm校验附件
  - contentConfirm=Y时跳过校验
  - contentConfirm=N时，根据系统配置UnFreezeProjectConShow判断当前事业部是否需要校验附件
  - 需校验时，附件不能为空且数量不少于Redis中content_confirm_count配置值

### 重点逻辑4：多系统联动

- **业务意义**：解冻后需同步CRM和ES，确保各系统数据一致
- **具体逻辑描述**：
  - 提交时(wfProcSubmit)：单体报备且有效结束日期小于延期开始日时推送ES数据(reportToEs)
  - 审批通过(onWfComplete)：非家装单体报备推送CRM(validStatus=1)，家装单体报备仅恢复项目状态
  - 审批拒绝(onUserReject)：删除ES数据(delEsDocByUser)
  - CRM推送失败仅记录日志，不影响主流程

### 重点逻辑5：流程变量更新

- **业务意义**：将冻结时间和项目信息确认传递到工作流审批节点
- **具体逻辑描述**：
  - eventExecute中更新流程变量freezeTime和contentConfirm
  - 供审批节点展示和校验使用

### doAudit审批通过核心逻辑

```
1. 读取报备有效周期天数 effectiveCycle = sysParamRepository.queryValueByCodeAndOrgId(PROJ_EFFECTIVE_CYCLE, dept)
2. 查询项目 epmProject = selectByPrimaryKey(projectId)
3. 根据freezeType更新项目：
   → freezeType=1/4(超有效期)：
     PROJECT_VALID=2, UNFREEZE_TIME=now, VALID_START_DATE=now,
     VALID_END_DATE=now+effectiveCycle+1, FREEZE_TYPE=0, FREEZE_TIME=null
   → freezeType=2(进度超时)：
     PROJECT_VALID=2, UNFREEZE_TIME=now, FREEZE_TYPE=0, FREEZE_TIME=null
4. updateByPrimaryKey(epmProject)
5. 构建进度更新DTO(stageId=stageValueAfter, stageDesc=stageDescAfter)
6. freezeType=2时设置forceUpdate=2(强制更新)
7. 校验进度一致性：stageValueBefore > stageId时抛出"项目进度已变更，请驳回重审!"
8. doUpdate更新项目进度
9. 记录审批人auditor=当前用户名，审批时间audittime=now
```

### doUpdate项目进度更新逻辑

```
1. 查询项目当前阶段
2. 判断阶段是否改变(stageChanged)和阶段描述是否改变(stageDescChanged)
3. 若阶段改变或描述改变或强制更新(forceUpdate=2)：
   → 校验进度一致性：stageValueBefore > stageId时抛异常
   → 查询旧阶段和新阶段定义
   → 校验新阶段序号不小于旧阶段序号，否则抛出"阶段更新，只能前进，不能后退"
   → 更新项目档案STAGE_ID/STAGE_NAME/STAGE_NOTE
   → 插入项目阶段历程记录(EPM_PROJECT_STAGE)
```

### onWfComplete审批通过后处理

```
1. 读取报备有效周期(effectiveCycle)
2. monomerType=2(家装单体)：
   → PROJECT_VALID=2, UNFREEZE_TIME=now, VALID_START_DATE=now,
     VALID_END_DATE=now+effectiveCycle+1, FREEZE_TYPE=0, FREEZE_TIME=null
3. 其他(工程单体)：
   → 查询项目报备EPM_REPORT
   → 查询客户获取shortName
   → 推送CRM(acctCode/acctName/acctAbbr/orgCode/reportNo/projectName/validStatus=1)
   → CRM推送失败仅记录日志
4. 更新auditStat="审核通过"
```

### 保存校验

- 校验1：工程ID非空 —— 申请单必须关联有效的工程项目
  - **详细逻辑**：PROJECT_ID字段标注@NotNull，框架自动校验
  - **系统体现**：Entity注解校验
  - **排查SQL**：`SELECT * FROM EPM_PROJECT_UNFREEZE WHERE PROJECT_ID IS NULL;`

- 校验2：冻结类型非空 —— 必须选择冻结类型
  - **详细逻辑**：FREEZE_TYPE字段标注@NotNull，框架自动校验
  - **系统体现**：Entity注解校验
  - **排查SQL**：`SELECT * FROM EPM_PROJECT_UNFREEZE WHERE FREEZE_TYPE IS NULL;`

- 校验3：解冻后进度非空 —— 必须选择解冻后跟进进度
  - **详细逻辑**：STAGE_VALUE_AFTER字段标注@NotNull，框架自动校验
  - **系统体现**：Entity注解校验
  - **排查SQL**：`SELECT * FROM EPM_PROJECT_UNFREEZE WHERE STAGE_VALUE_AFTER IS NULL;`

- 校验4：事业部非空 —— 必须归属有效事业部
  - **详细逻辑**：DIVISION_ID字段标注@NotNull，框架自动校验
  - **系统体现**：Entity注解校验
  - **排查SQL**：`SELECT * FROM EPM_PROJECT_UNFREEZE WHERE DIVISION_ID IS NULL;`

### 提交校验

- 校验1：进度一致性 —— 解冻前进度不大于解冻后进度，防止进度回退
  - **详细逻辑**：volidate中校验stageValueBefore > stageId时抛出"项目进度已变更，请驳回重审!"
  - **系统体现**：工作流校验回调volidate
  - **排查SQL**：`SELECT PROJ_UNFREEZE_ID, STAGE_VALUE_BEFORE, STAGE_VALUE_AFTER FROM EPM_PROJECT_UNFREEZE WHERE STAGE_VALUE_BEFORE > STAGE_VALUE_AFTER;`

- 校验2：附件校验 —— contentConfirm=N且事业部在UnFreezeProjectConShow配置中时必须上传附件
  - **详细逻辑**：onUserSubmit中checkContentConfirm校验，附件为空抛出"附件不能为空"，数量不足抛出"附件必须上传且数量不少于【N】"
  - **系统体现**：工作流提交回调wfProcSubmit
  - **排查SQL**：`SELECT CONFVALUE FROM SCPSYSCONF WHERE CONFNAME = 'UnFreezeProjectConShow';`

- 校验3：阶段前进校验 —— 解冻后阶段序号不小于解冻前阶段序号
  - **详细逻辑**：doUpdate中校验newStage.seq < oldStage.seq时抛出"阶段更新，只能前进，不能后退"
  - **系统体现**：审批通过回调doAudit→doUpdate
  - **排查SQL**：`SELECT OLD.STAGE_ID, OLD.SEQ AS OLD_SEQ, NEW.STAGE_ID, NEW.SEQ AS NEW_SEQ FROM EPM_STAGE_DEF OLD, EPM_STAGE_DEF NEW WHERE OLD.STAGE_ID = #{stageValueBefore} AND NEW.STAGE_ID = #{stageValueAfter} AND NEW.SEQ < OLD.SEQ;`

### 状态机

```text
┌──────────┐  提交   ┌──────────┐  审批通过  ┌──────────┐
│  新建    │ ──────→ │ 审批中    │ ────────→ │ 审批通过  │
│ (NEW)   │         │ (RUN)   │           │(APPROVED) │
└──────────┘         └────┬─────┘           └──────────┘
      ↑                   │
      │              审批拒绝/驳回
      │                   │
      └───────────────────┘
                  │
              (REJECTED)
```

**审批通过后动作**(doAudit)：
- 读取报备有效周期PROJ_EFFECTIVE_CYCLE
- 更新EPM_PROJECT：PROJECT_VALID=2, UNFREEZE_TIME=now, FREEZE_TYPE=0, FREEZE_TIME=null
- freezeType=1/4：VALID_START_DATE=now, VALID_END_DATE=now+effectiveCycle+1
- freezeType=2：强制更新项目进度(forceUpdate=2)
- 更新项目进度表，记录审批人、审批时间
- 推送CRM(validStatus=1)

### 下游影响

- **项目档案(EPM_PROJECT)**：审批通过后PROJECT_VALID恢复为2(已生效)，FREEZE_TYPE=0，FREEZE_TIME=null，UNFREEZE_TIME记录解冻时间
- **项目有效期**：超有效期解冻(freezeType=1/4)重置VALID_START_DATE和VALID_END_DATE
- **项目进度历程(EPM_PROJECT_STAGE)**：解冻后更新项目进度，新增阶段历程记录
- **CRM系统**：同步报备有效状态validStatus=1，家装单体报备除外
- **ES搜索索引**：提交时推送ES文档，拒绝时删除ES文档
- **项目商机查询**：解冻后项目恢复在商机列表展示

#### 报错1：项目进度已变更，请驳回重审!
- **触发条件**：提交校验或审批通过时，stageValueBefore > stageValueAfter(解冻前进度大于解冻后进度)
- **逻辑分析**：volidate和doAudit方法中校验进度一致性，解冻申请提交时记录了解冻前进度stageValueBefore，若提交后项目进度被其他单据变更导致stageValueBefore大于当前进度，则解冻后进度会回退，需驳回重审
- **排查SQL**：
  ```sql
  SELECT epu.PROJ_UNFREEZE_ID, epu.PROJ_UNFREEZE_CODE, epu.PROJECT_ID,
         epu.STAGE_VALUE_BEFORE, epu.STAGE_VALUE_AFTER, epu.HZ_APPROVE_STATUS,
         ep.STAGE_ID AS 项目当前阶段ID
  FROM EPM_PROJECT_UNFREEZE epu
  JOIN EPM_PROJECT ep ON epu.PROJECT_ID = ep.PROJECT_ID
  WHERE epu.STAGE_VALUE_BEFORE > epu.STAGE_VALUE_AFTER
  -- 查出进度回退的解冻申请
  ```

#### 报错2：附件不能为空
- **触发条件**：提交解冻申请时，contentConfirm=N且事业部在UnFreezeProjectConShow配置中，但未上传附件
- **逻辑分析**：checkContentConfirm方法中按ORGANIZATION_ID查询UnFreezeProjectConShow配置，若该事业部需附件确认且contentConfirm=N，则校验附件列表非空。该报错为阻断性报错
- **排查SQL**：
  ```sql
  SELECT epu.PROJ_UNFREEZE_ID, epu.PROJ_UNFREEZE_CODE, epu.CONTENT_CONFIRM, epu.ORGANIZATION_ID,
         (SELECT COUNT(*) FROM HPFM_ATTACHMENT ha
          WHERE ha.OBJECT_ID = epu.PROJ_UNFREEZE_ID
            AND ha.OBJECT_TYPE IN (8003, 9009)) AS 附件数量
  FROM EPM_PROJECT_UNFREEZE epu
  WHERE epu.CONTENT_CONFIRM = 'N'
    AND epu.ORGANIZATION_ID IN (SELECT CONFIG_VALUE FROM SYS_PARAM WHERE PARAM_CODE = 'UnFreezeProjectConShow')
  -- 查出需附件但附件数量为0的解冻申请
  ```

#### 报错3：附件必须上传且数量不少于【N】
- **触发条件**：提交解冻申请时，附件数量小于Redis中content_confirm_count配置值
- **逻辑分析**：checkContentConfirm方法中从Redis读取content_confirm_count配置的最小附件数N，若实际附件数<N则抛出阻断性报错。需上传足够数量附件后重新提交
- **排查SQL**：
  ```sql
  SELECT epu.PROJ_UNFREEZE_ID, epu.PROJ_UNFREEZE_CODE, epu.CONTENT_CONFIRM,
         (SELECT COUNT(*) FROM HPFM_ATTACHMENT ha
          WHERE ha.OBJECT_ID = epu.PROJ_UNFREEZE_ID
            AND ha.OBJECT_TYPE IN (8003, 9009)) AS 附件数量
  FROM EPM_PROJECT_UNFREEZE epu
  WHERE epu.CONTENT_CONFIRM = 'N'
  -- 对比附件数量与Redis配置content_confirm_count
  ```

#### 报错4：阶段更新，只能前进，不能后退
- **触发条件**：解冻审批通过时，解冻后阶段(STAGE_VALUE_AFTER)的SEQ小于解冻前阶段(STAGE_VALUE_BEFORE)的SEQ
- **逻辑分析**：doUpdate方法中查询EPM_STAGE_DEF获取新旧阶段SEQ，若newStage.seq < oldStage.seq则抛出阻断性报错。需修改解冻后阶段为更高级阶段
- **排查SQL**：
  ```sql
  SELECT esd.STAGE_ID, esd.STAGE_NAME, esd.SEQ, esd.ORGANIZATION_ID
  FROM EPM_STAGE_DEF esd
  WHERE esd.ORGANIZATION_ID = :organizationId
  ORDER BY esd.SEQ
  -- 对比解冻后阶段与解冻前阶段的SEQ
  ```

## 常见问题FAQ

### Q1: 什么情况下项目报备会被冻结？

项目报备后超过系统参数设定的有效周期(PROJ_EFFECTIVE_CYCLE)未产生合同，系统自动冻结(FREEZE_TYPE=1)；或进度超时更新冻结(FREEZE_TYPE=2)。

**排查SQL:**
```sql
SELECT PROJECT_ID, PROJECT_CODE, PROJECT_VALID, FREEZE_TYPE, FREEZE_TIME
FROM EPM_PROJECT
WHERE PROJECT_VALID = 4;
```

### Q2: 超项目有效期解冻和进度超时解冻的区别？

超有效期解冻(freezeType=1/4)重置有效周期(VALID_START_DATE=now, VALID_END_DATE=now+effectiveCycle+1)；进度超时解冻(freezeType=2)仅恢复状态，强制更新进度(forceUpdate=2)，不重置有效周期。

### Q3: 为什么需要进度一致性校验？

解冻申请提交时记录了解冻前进度stageValueBefore，若提交后项目进度被其他单据变更，导致stageValueBefore大于当前进度，则解冻后进度会回退，因此需驳回重审。

**排查SQL:**
```sql
SELECT PROJ_UNFREEZE_ID, STAGE_VALUE_BEFORE, STAGE_VALUE_AFTER
FROM EPM_PROJECT_UNFREEZE
WHERE STAGE_VALUE_BEFORE > STAGE_VALUE_AFTER;
```

### Q4: 项目信息确认(contentConfirm)的作用？

contentConfirm作为工作流变量传递到审批节点，供审批人确认项目信息是否准确。Y表示已确认(跳过附件校验)，N表示未确认(需校验附件)。

### Q5: 解冻后项目有效期如何计算？

超有效期解冻时，VALID_START_DATE=当前时间，VALID_END_DATE=当前时间+PROJ_EFFECTIVE_CYCLE+1天，给予新的有效周期。

**排查SQL:**
```sql
SELECT PROJECT_ID, PROJECT_VALID, UNFREEZE_TIME, VALID_START_DATE, VALID_END_DATE
FROM EPM_PROJECT
WHERE PROJECT_ID = #{projectId};
```

### Q6: 家装单体报备解冻有何特殊处理？

家装单体报备(monomerType=2)不推送CRM，仅恢复项目状态和更新有效期。附件对象类型为9009L，工程单体为8003L。
