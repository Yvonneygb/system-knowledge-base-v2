# 门店管理-门店档案-新建门店申请

> 本页面为低代码页面(hlod)，无独立前端源码，基于后端API梳理。

## 业务流程

新建门店申请用于经销商新增门店时建立标准门店档案。用户填写门店基础信息（门店名称、类型、面积、地址、经营品牌等）后提交审批，审批通过后系统自动同步生成门店档案（MKT_TERMINAL）。工作流编码为NEW_STORE_APPLY（"新建门店"），审批通过后通过syncMktTerminal方法将申请数据落库到门店档案表，并自动生成门店编码（barCode + divisionCode + 5位Redis流水号）。

**核心流程：**
1. 经销商进入新建门店申请页面，填写门店基础信息
2. 保存草稿（hzApproveStatus=NEW）
3. 提交审批，调用wfProcSubmit发起工作流（NEW_STORE_APPLY），状态变为RUN
4. OA审批通过后回调onWfComplete，调用syncMktTerminal同步门店档案
5. 生成门店编码，插入MKT_TERMINAL表，迁移附件，状态变为APPROVED
6. 审批驳回回调onWfBreak，状态变为REJECTED

```
开始 → 填写门店信息 → 保存草稿(NEW) → 提交审批(RUN) → OA审批 → 通过？ → 是：syncMktTerminal同步门店档案(APPROVED) / 否：驳回(REJECTED) → 结束
```

- 上游支撑：经销商主数据、事业部基础设置（DIVISION_BASE_SET）、区域表（SCPAREA）、附件关系（OBJ_ATTACH_REL）、工作流引擎、OA审批系统
- 下游影响：门店档案（MKT_TERMINAL）、门店变更申请、门店装修申请、门店验收与报销

## 重点逻辑

### 重点逻辑1：工作流审批驱动

- **业务意义**：新建门店需经OA审批通过后才能正式建立门店档案
- **具体逻辑描述**：
  - 工作流编码：NEW_STORE_APPLY（"新建门店"）
  - 提交审批：wfProcSubmit方法组装流程参数，调用workflowClient.startInstanceByFlowKey发起流程
  - OA链接标题格式："新建门店申请_门店名称_申请单号_更新时间"
  - 流程参数包含：applyId、terminalApplyId、startRealName、custId、terminalType、terminalNameFlag、terminalStat、tradeYears
  - 审批状态：NEW(新建) → RUN(审批中) → APPROVED(已审批) / REJECTED(已驳回)

### 重点逻辑2：门店编码自动生成

- **业务意义**：审批通过后自动生成唯一门店编码，确保编码规范统一
- **具体逻辑描述**：
  - 编码规则：terminalCode = barCode + divisionCode + 5位流水号
  - 流水号通过Redis自增生成，key = "ae:terminal:" + divisionCode + ":" + barCode
  - 格式化：String.format("%05d", serialNumber)，补零到5位
  - barCode为车辆简称，divisionCode为事业部编码

### 重点逻辑3：审批通过同步门店档案

- **业务意义**：审批通过后将申请数据同步到门店档案表（MKT_TERMINAL），正式建立门店档案
- **具体逻辑描述**：
  - syncMktTerminal方法：
    1. 查询申请单，不存在抛CommonException("单据信息不匹配")
    2. 根据城市ID查询SCPAREA区域表，生成门店编码
    3. 更新申请单：hzApproveStatus=APPROVED、checkTime=now、checkor=当前用户
    4. 通过MktTerminalConvert转换为MktTerminal实体，设置usable=2、objectVersionNumber=1
    5. insertSelective插入门店档案表

### 重点逻辑4：附件迁移

- **业务意义**：审批通过后将申请阶段的附件迁移到新门店档案下
- **具体逻辑描述**：
  - onWfComplete方法中：
    1. 查询附件关系ObjAttachRel（attachConfId=8122）
    2. 查询附件类型ObjAttachType（attachConfId=8123）
    3. 将附件attachConfId改为8123、objId改为新门店terminalId
    4. attachTypeId按组织匹配
    5. batchInsert批量插入附件关系到新门店

### 重点逻辑5：门店名称标识计算

- **业务意义**：根据门店类型和名称计算标识，用于工作流分支路由
- **具体逻辑描述**：
  - terminalType==2 → "1"
  - terminalName==null → "3"
  - terminalName包含"五金店" → "2"
  - terminalName包含"优选店" → "2"
  - 其他 → "3"

#### 按钮1：保存（详情页）

- **业务意义**：保存门店申请草稿数据
- **具体逻辑描述**：
  - 保存主表MktTerminalApply数据
  - 级联保存行表MktTerminalApplyLine（经销品类品牌明细）
  - 级联保存品牌表MktTerminalApplyBrand（其他品类明细）
  - hzApproveStatus设为NEW

#### 按钮2：提交（详情页）

- **业务意义**：提交门店申请进入OA审批流程
- **具体逻辑描述**：
  - 调用wfProcSubmit方法
  - 组装流程参数：applyId、terminalApplyId、startRealName、custId、terminalType、terminalNameFlag、terminalStat、tradeYears
  - OA链接标题："新建门店申请_门店名称_申请单号_更新时间"
  - 调用workflowClient.startInstanceByFlowKey发起流程（FlowKey=NEW_STORE_APPLY）
  - 回写hzInstanceId和hzApproveStatus=RUN

#### 按钮3：同步门店档案（后端回调）

- **业务意义**：审批通过后自动同步门店档案
- **具体逻辑描述**：
  - OA审批通过后回调onWfComplete
  - 调用syncMktTerminal：
    1. 生成门店编码（barCode + divisionCode + 5位Redis流水号）
    2. 更新申请单hzApproveStatus=APPROVED
    3. 转换为MktTerminal实体，insertSelective插入门店档案表
  - 迁移附件到新门店

#### 报错1：单据信息不匹配
- **触发条件**：OA审批通过回调onWfComplete→syncMktTerminal时，按terminalApplyId调用selectByPrimaryKey查询MKT_TERMINAL_APPLY返回null
- **逻辑分析**：审批通过同步门店档案前需读取申请单数据用于转换MktTerminal实体。若申请单在OA审批期间被其他用户物理删除、terminalApplyId传值错误（如工作流变量丢失）、或并发场景下被清理，查询返回空，无法组装门店档案数据，抛CommonException中断同步流程，门店档案不会生成，需人工核查申请单状态后重新触发同步。
- **排查SQL**：
  ```sql
  SELECT t.terminal_apply_id   AS 申请单ID,
         t.terminal_apply_no   AS 申请单号,
         t.terminal_name       AS 门店名称,
         t.hz_approve_status   AS 审批状态,
         t.hz_instance_id      AS 工作流实例ID
  FROM   mkt_terminal_apply t
  WHERE  t.hz_approve_status = 'RUN'
  AND    NOT EXISTS (SELECT 1 FROM mkt_terminal m WHERE m.terminal_code = t.terminal_code)
  ORDER  BY t.create_time DESC;
  ```

#### 报错2：当前数据不存在
- **触发条件**：OA审批驳回回调onWfBreak时，按terminalApplyId调用selectByPrimaryKey查询MKT_TERMINAL_APPLY返回null
- **逻辑分析**：审批驳回需更新申请单hzApproveStatus=REJECTED并记录驳回意见。若回调期间申请单被删除、OA回调报文的单据ID与DMS不一致（如OA流程配置错误、ID映射异常），查询返回空，无法更新状态，申请单滞留RUN状态，需核查OA回调报文与申请单数据一致性。
- **排查SQL**：
  ```sql
  SELECT t.terminal_apply_id   AS 申请单ID,
         t.terminal_apply_no   AS 申请单号,
         t.hz_approve_status   AS 审批状态,
         t.hz_instance_id      AS 工作流实例ID,
         t.creator             AS 申请人
  FROM   mkt_terminal_apply t
  WHERE  t.hz_approve_status = 'RUN'
  AND    t.update_time < SYSDATE - 1
  ORDER  BY t.update_time DESC;
  ```

#### 报错3：门店编码生成失败
- **触发条件**：syncMktTerminal→getMktTerminalCode生成门店编码时，Redis自增失败或SCPAREA区域数据查询为空
- **逻辑分析**：门店编码规则为barCode+divisionCode+5位Redis流水号（key="ae:terminal:"+divisionCode+":"+barCode）。若Redis连接异常、key被误删、或按城市ID查询SCPAREA区域表返回null（城市ID未维护、区域数据缺失），无法生成有效编码，同步门店档案流程中断。需核查Redis连通性及SCPAREA区域数据完整性。
- **排查SQL**：
  ```sql
  SELECT t.terminal_apply_id   AS 申请单ID,
         t.terminal_apply_no   AS 申请单号,
         t.city_areaname       AS 城市名称,
         t.bar_code            AS 车辆简称,
         t.division_code       AS 事业部编码,
         s.areaid              AS 区域ID
  FROM   mkt_terminal_apply t
  LEFT   JOIN scparea s ON s.areaname = t.city_areaname
   WHERE  t.hz_approve_status = 'APPROVED'
   AND    (s.areaid IS NULL OR t.bar_code IS NULL OR t.division_code IS NULL)
   ORDER  BY t.create_time DESC;
   ```

#### 报错7：网络请求失败
- **触发条件**：前端调用后端接口（保存、提交、同步门店档案）时，请求超时或后端服务不可达
- **逻辑分析**：低代码页面通过axios请求后端API，若后端ae-business服务未启动、网络中断、网关超时、或数据库连接池耗尽导致请求堆积，axios捕获网络异常，前端展示通用错误提示。需核查后端服务健康状态、网络连通性、网关配置及数据库连接池。
- **排查SQL**：

  ```sql
  FROM   mkt_terminal_apply t
  WHERE  t.hz_approve_status = 'RUN'
  AND    t.update_time >= SYSDATE - 1/24;
  ```

## 常见问题FAQ

**Q1：门店编码如何生成？**
A：审批通过后自动生成，编码规则：barCode + divisionCode + 5位Redis流水号。流水号通过Redis自增生成，key = "ae:terminal:" + divisionCode + ":" + barCode。

**Q2：审批流程是什么？**
A：工作流编码NEW_STORE_APPLY（"新建门店"），提交后进入OA审批，审批通过回调onWfComplete同步门店档案，审批驳回回调onWfBreak更新状态。

**Q3：审批通过后会做什么？**
A：1)生成门店编码 2)更新申请单状态为APPROVED 3)同步数据到MKT_TERMINAL门店档案表 4)迁移附件到新门店。

**Q4：门店名称标识有什么用？**
A：terminalNameFlag用于工作流分支路由：terminalType==2→"1"，包含"五金店"/"优选店"→"2"，其他→"3"。

**Q5：OA链接标题格式是什么？**
A："新建门店申请_门店名称_申请单号_更新时间"。
