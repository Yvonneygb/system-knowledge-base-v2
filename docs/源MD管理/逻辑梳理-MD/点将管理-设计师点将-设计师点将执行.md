# 点将管理-设计师点将-设计师点将执行

> 后端代码位于 mbo-business 微服务，API 路径前缀为 `mlt/designApply/*`。

## 业务流程

```
设计点将审批通过
        |
        ├── 开始设计 ──→ 设计状态变更
        |
        ├── 上传设计图纸 ──→ 弹窗上传(设计图/效果图/施工图及软装图)
        |
        ├── 图纸确认 ──→ 选择签订人 ──→ 发起图纸验收 ──→ FDD签署
        |
        ├── 下单 ──→ 设计师确认接单
        |
        ├── 区域确认 ──→ 弹窗展示申请详情+原始结构图上传 ──→ 提交面积 ──→ 发起FDD签署
        |
        ├── 终止 ──→ 填写终止申请 ──→ 提交终止 ──→ 进入终止审批流程
        |
        ├── 同步CRM ──→ 推送CRM订单
        ├── 同步OA ──→ 推送OA流程
        ├── 同步FDD ──→ 推送法大大签署
        |
        └── 查看反馈 ──→ 弹窗展示经销商反馈列表
```

设计执行全链路：开始设计 → 上传图纸 → 图纸确认 → 下单 → 区域确认 → 完成

### 上游依赖

| 上游模块 | 依赖类型 | 依赖说明 | 依赖成立条件 |
|---------|---------|---------|-------------|
| 设计师点将管理 | 数据依赖 | 审批通过的设计点将申请进入本页面执行 | 申请审批状态为已通过 |
| 经销商点将-设计点将 | 数据依赖 | 经销商反馈设计结果，反馈数据展示在查看反馈弹窗 | 经销商已提交反馈 |
| 讲师档案 | 数据依赖 | 签订人选择引用讲师档案签署人数据 | 签订人已在讲师档案中配置 |
| FDD(法大大) | 接口依赖 | 区域确认和图纸确认时发起法大大电子签署 | 法大大签署服务可用 |

### 下游影响

- 终止项目后生成终止申请，回到管理页面进行终止审批
- 同步CRM后更新CRM订单状态和单号
- 同步OA后推送OA审批流程
- 同步FDD后推送法大大签署流程
- 图纸确认后经销商可查看验收结果并反馈
- 完成执行后自动刷新设计师饱和度统计

## 重点逻辑

### 重点逻辑1：固定pageType=design

- **业务意义**：区分设计点将执行数据与其他类型点将数据，确保列表只展示设计点将的执行记录
- **具体逻辑描述**：列表查询固定传递 pageType=design，后端按此参数筛选设计点将执行数据

### 重点逻辑2：设计执行流程跟踪

- **业务意义**：跟踪设计服务从开始到完成的全过程，确保服务按期推进
- **具体逻辑描述**：执行流程为 开始设计→上传图纸→图纸确认→下单→区域确认→完成，每个节点状态变更需记录操作人和时间

### 重点逻辑3：上传图纸回填

- **业务意义**：编辑图纸时需展示已上传的图纸，避免重复上传
- **具体逻辑描述**：上传图纸弹窗包含三个 UploadDrawing 组件(设计图/效果图/施工图及软装图)，编辑前先通过 getUploadDetail 接口查询已有图纸回填

### 重点逻辑4：签订人选择

- **业务意义**：FDD签署需指定有效的签订人，确保签署法律效力
- **具体逻辑描述**：签订人数据来自 signerDS，通过 legalEntityName 查询法人主体下的签署人，图纸确认和区域确认时需选择签订人

### 重点逻辑5：终止项目关联

- **业务意义**：终止申请需关联原申请，便于追溯终止原因和原服务信息
- **具体逻辑描述**：终止项目弹窗填写当前进展和终止原因，提交时以 relationApplyCode 关联原申请，生成终止申请

### 重点逻辑6：饱和度联动

- **业务意义**：执行完成后自动更新设计师饱和度，作为后续点将排期与服务冲突判断的依据
- **具体逻辑描述**：完成确认后自动刷新设计师饱和度统计，影响设计师饱和度菜单中该设计师的已排期天数

### 重点逻辑7：反馈列表展示

- **业务意义**：查看经销商对设计结果的反馈，掌握服务满意度
- **具体逻辑描述**：查看反馈弹窗通过 queryFeedback 接口查询经销商反馈记录，包含反馈结果/反馈人/反馈内容/时间

#### 弹窗1：面积确认弹窗（单选）

由 Header 按钮"面积确认"触发，调用 handleConfirmArea，弹窗标题"面积确认"，宽度 1200，okText="提交"。提交前校验 confirmAreaRef.current.generalFormDS.validate()，提交参数：applyCode、scaleArea、structureList、signerId(accountId)、signerName(name)、signerPhone(mobile)，调用 areaConfirm 接口（POST mlt/designApply/areaConfirm），成功后刷新列表。

入参表格：

| 字段名 | 数据库列名 | 组件 | 业务释义 | 显隐条件 | 取值/赋值逻辑 |
|--------|-----------|------|---------|---------|-------------|
| 申请详情 | - | DesignApplyDetail | 展示申请详细信息 | 始终显示 | applyCode=当前行, type=view, showRemark, state={isConfirmArea: true}，getSigners 回调传入 |
| 原始结构图 | - | UploadDrawing | 上传原始结构图文件 | 始终显示 | ContentCard 标题"原始结构图"，提交时 getFileList 作为 structureList 参数 |
| 面积 | SCALE_AREA | NumberField | 确认设计面积 | 始终显示 | DesignApplyDetail 内部 generalFormDS 字段，必填 |
| 签订人 | SIGNER | Select | FDD签署签订人 | 始终显示 | DesignApplyDetail 内部 generalFormDS 字段，options=signerDS, 通过 legalEntityName 查询，提交取 accountId/name/mobile |

查询SQL：

```sql
SELECT SIGNER_ID, SIGNER_NAME, SIGNER_PHONE
FROM MA_SIGNER
WHERE LEGAL_ENTITY_NAME = :legalEntityName
  AND STATUS = 'ACTIVE';
```

|--------|-----------|------|---------|---------|-------------|

查询SQL：

```sql
SELECT MDF.OPERATION_TIME   AS "时间",
       MDF.DISTRIBUTOR_NAME AS "反馈人",
       MDF.FEEDBACK_RESULT  AS "反馈结果",
       MDF.FEEDBACK_COMMENTS AS "反馈内容"
FROM MA_DESIGN_FEEDBACK MDF
WHERE MDF.APPLY_CODE = :applyCode
ORDER BY MDF.OPERATION_TIME DESC;
```

- 校验3：终止项目时当前进展、终止原因必填 —— 确保终止原因可追溯
- 校验4：上传图纸时文件格式和大小校验 —— 确保图纸文件有效

#### 报错1：请选择一条数据
- **触发条件**：点击查看申请、查看确认书、特殊取消、结束执行、同步OA/FDD/CRM、下载图纸、设计改派、查看反馈、上传图纸、下单、区域确认、开始设计、图纸确认、终止等行操作按钮时，未选择数据或选择了多行
- **逻辑分析**：前端在执行单选操作前校验选中行数量，若 selectedRows.length ≠ 1 则阻止操作并提示"请选择一条数据"。单选操作需要明确的目标申请，未选择时无法确定操作对象，多选时操作对象不唯一
- **排查SQL**：
  ```sql
  SELECT APPLY_CODE AS 申请编码,
         APPLY_USER_NAME AS 申请人,
         DESIGN_NAME AS 设计名称,
         LECTURER_NAME AS 设计师,
         ORDER_LECTURE_STATE AS 点将状态,
         APPROVAL_STATE AS 审核状态
  FROM DESIGN_APPLY
  WHERE APPLY_TYPE_ONE = 'design'
  ORDER BY CREATE_DATE DESC;
  ```

#### 报错2：请求失败
- **触发条件**：调用 mlt/designApply/* 系列接口时，后端返回 HTTP 状态码非 2xx
- **逻辑分析**：前端通过 axios 调用后端接口，若响应状态码非 2xx 或网络异常则触发错误回调，统一提示"请求失败"。常见根因包括：mbo-business 微服务未启动或异常、数据库连接失败、SQL 执行超时、后端业务异常未捕获、外部系统（OA/FDD/CRM/文件存储）调用失败、网络中断等。需检查 mbo-business 微服务运行状态、外部系统连通性、文件存储服务、后端日志定位具体异常堆栈
- **排查SQL**：
  ```sql
  SELECT APPLY_CODE AS 申请编码,
         DESIGN_NAME AS 设计名称,
         ORDER_LECTURE_STATE AS 点将状态,
         APPROVAL_STATE AS 审核状态,
         CRM_ORDER_STATUS AS CRM订单状态,
         ERROR_INFO AS 异常问题,
         TO_CHAR(LAST_UPDATE_DATE,'YYYY-MM-DD HH24:MI:SS') AS 最后更新时间
  FROM DESIGN_APPLY
  WHERE APPLY_TYPE_ONE = 'design'
    AND LAST_UPDATE_DATE >= SYSDATE - 1
  ORDER BY LAST_UPDATE_DATE DESC;
  ```

#### 报错3：当前进展不能为空
- **触发条件**：提交终止项目时，CURRENT_PROGRESS 字段为空
- **逻辑分析**：前端终止项目弹窗对 currentProgress 字段配置 required 校验，提交前校验当前进展是否填写，为空则阻止提交并提示"当前进展不能为空"。当前进展用于记录终止时的项目状态，便于追溯终止原因
- **排查SQL**：
  ```sql
  SELECT APPLY_CODE AS 申请编码,
         RELATION_APPLY_CODE AS 关联原申请,
         APPLY_USER_NAME AS 申请人,
         CURRENT_PROGRESS AS 当前进展,
         TERMINATION_REASON AS 终止原因
  FROM DESIGN_APPLY
  WHERE APPLY_TYPE = 'termination'
    AND (CURRENT_PROGRESS IS NULL OR CURRENT_PROGRESS = '');
  ```

#### 报错4：终止原因不能为空

- **排查SQL**：
  ```sql

         APPLY_USER_NAME AS 申请人,

         TERMINATION_REASON AS 终止原因
  ```

#### 报错5：签订人不能为空

- **逻辑分析**：前端图纸确认弹窗对 signer 字段配置 required 校验，提交前校验签订人是否选择，为空则阻止提交并提示"签订人不能为空"。签订人用于法大大电子签署，必须明确签署责任主体

#### 报错6：面积确认校验失败
- **触发条件**：提交区域确认时，generalFormDS.validate() 校验未通过，SCALE_AREA 等必填字段为空
- **逻辑分析**：前端区域确认弹窗通过 generalFormDS.validate() 校验表单，对 SCALE_AREA（确认面积）等字段配置 required 校验，提交前校验完整性，校验不通过则提示"面积确认校验失败"。面积用于计算设计费用，必须明确
- **排查SQL**：

#### 报错7：单个文件不能大于30MB
- **触发条件**：上传图纸时，所选文件 file.size > 30 * 1024 * 1024（30MB）
- **逻辑分析**：前端 UploadDrawing 组件 beforeUpload 钩子校验文件大小，超过30MB则阻止上传并提示"单个文件不能大于30MB"。限制源于OSS存储和后端解析性能考虑，大文件需压缩或拆分后上传
- **排查SQL**：
  ```sql
  SELECT APPLY_CODE AS 申请编码,
         FILE_NAME AS 文件名,
         FILE_SIZE AS 文件大小,
         FILE_URL AS 文件地址
  FROM DESIGN_DRAWING_FILE
  WHERE FILE_SIZE > 30 * 1024 * 1024
  ORDER BY CREATION_DATE DESC;
  ```

#### 报错8：上传失败
- **触发条件**：上传图纸时，OSS 上传抛错（onUploadError）或上传成功但响应无 fileUrl（onUploadSuccess res.fileUrl 为空）
- **逻辑分析**：前端 UploadDrawing 组件 onUploadError 钩子捕获上传异常提示"上传失败：{err.message}"，onUploadSuccess 钩子校验响应 fileUrl 字段，为空则提示"上传失败：{res.message}"。常见根因：OSS 存储服务不可用、bucketName/bucketDirectory 配置错误、storageCode 未配置、文件格式不被接受、网络中断等
- **排查SQL**：
  ```sql
  SELECT APPLY_CODE AS 申请编码,
         FILE_NAME AS 文件名,
         FILE_URL AS 文件地址,
         ERROR_INFO AS 异常信息
  FROM DESIGN_DRAWING_FILE
  WHERE FILE_URL IS NULL
     OR ERROR_INFO IS NOT NULL
  ORDER BY CREATION_DATE DESC;
  ```

#### 报错9：同步外部系统失败
- **触发条件**：点击同步CRM/同步OA/同步FDD按钮，调用 pushCrm/pushOa/pushFdd 接口返回失败
- **逻辑分析**：前端通过 PRequest 调用 pushCrm/pushOa/pushFdd 接口，接口返回 success=false 或非2xx状态码时触发错误回调。常见根因：CRM/OA/FDD 外部系统不可用、数据不符合外部接口要求、申请状态不允许同步、网络中断等。后端会将异常写入 ERROR_INFO 字段
- **排查SQL**：
  ```sql
  SELECT APPLY_CODE AS 申请编码,
         DESIGN_NAME AS 设计名称,
         CRM_ORDER_CODE AS CRM单号,
         CRM_ORDER_STATUS AS CRM订单状态,
  ```

#### 报错11：权限不足
- **触发条件**：点击查看申请、开始接单、面积确认、开始设计、图纸验收、终止项目、同步CRM/OA/FDD等按钮时，当前用户无对应 permissionList 权限码
- **逻辑分析**：前端 Button 组件通过 permissionList 配置权限码（如 hzero.general_manage.design.design_general_execute.ps.show_apply 等），HZERO 框架校验当前用户角色是否包含该权限码，未包含则按钮不可见或禁用。若强制调用接口，后端也会校验权限返回403。需联系管理员配置对应角色权限
- **排查SQL**：
  ```sql
  SELECT U.USER_NAME AS 用户名,
         R.ROLE_NAME AS 角色名,
         P.PERMISSION_CODE AS 权限码
  FROM SYS_USER U
  LEFT JOIN SYS_USER_ROLE UR ON U.USER_ID = UR.USER_ID
  LEFT JOIN SYS_ROLE R ON UR.ROLE_ID = R.ROLE_ID
  LEFT JOIN SYS_ROLE_PERMISSION RP ON R.ROLE_ID = RP.ROLE_ID
  LEFT JOIN SYS_PERMISSION P ON RP.PERMISSION_ID = P.PERMISSION_ID
  WHERE P.PERMISSION_CODE LIKE 'hzero.general_manage.design.design_general_execute.ps.%'
  ORDER BY U.USER_NAME;
  ```

- **触发条件**：查看申请、查看反馈、上传图纸等操作时，接口返回数据为空或申请编码不存在
- **逻辑分析**：前端通过 applyCode 调用详情接口，后端查询 DESIGN_APPLY 表无对应记录或记录已逻辑删除，返回空数据。常见根因：申请编码错误、申请已被删除、跨租户查询、数据权限隔离等。需检查 APPLY_CODE 有效性及数据权限
- **排查SQL**：
  ```sql
  SELECT APPLY_CODE AS 申请编码,
         APPLY_USER_NAME AS 申请人,
         ORDER_LECTURE_STATE AS 点将状态,
         DELETE_FLAG AS 删除标记
  FROM DESIGN_APPLY
  WHERE APPLY_TYPE_ONE = 'design'
    AND (DELETE_FLAG = 'Y' OR APPLY_CODE IS NULL);
  ```

#### 报错13：状态不允许操作
- **触发条件**：点击开始接单、开始设计、图纸验收、终止项目等按钮时，申请状态不在允许操作的状态范围内
- **逻辑分析**：后端校验申请状态机，如开始接单要求 ORDER_LECTURE_STATE 为待接单、开始设计要求为已接单、图纸验收要求图纸已上传、终止项目要求非已完成等。状态不匹配时后端返回业务异常，前端提示后端返回的 message。需检查申请当前状态及操作流程
- **排查SQL**：
  ```sql
  SELECT APPLY_CODE AS 申请编码,
         DESIGN_NAME AS 设计名称,
         ORDER_LECTURE_STATE AS 点将状态,
         DESIGN_STATE AS 设计状态,
         APPROVAL_STATE AS 审核状态,
         ERROR_INFO AS 异常问题
  FROM DESIGN_APPLY
  WHERE APPLY_TYPE_ONE = 'design'
    AND ORDER_LECTURE_STATE NOT IN ('pending_order','ordered','designing','drawing_uploaded','finished')
  ORDER BY CREATE_DATE DESC;
  ```
