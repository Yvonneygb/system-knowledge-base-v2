# 点将管理-基础管理-档案审批

> 后端代码位于 mbo-business 微服务（源码未包含在当前源码目录下），前端 API 路径前缀为 `mlt/maLecturerApproval/*`。本文档基于前端代码与接口契约梳理，后端实现以微服务实际代码为准。

## 业务流程

### 业务流程图

```
讲师档案/价格提交审批
        |
        v
档案审批列表(本页面) ──init──→ 加载讲师类型(getLecturerTypeList) ──→ 自动查询
        |
        ├──→ 查看详情 ──→ 跳转讲师档案详情页(/detail/{id}/view)
        └──→ 审批 ──→ 跳转审批详情页(/detail/{id}/{approvalType}Approval)
                           |
                           ├──→ approvalType=archives ──→ 讲师档案审批
                           └──→ approvalType=price    ──→ 讲师牌价审批
```

### 闭环四步

1. **查看待审**：按审批类型筛出待处理的三类单据（档案审批 / 价格审批 / 价格变更审批）
2. **审核核对**：核对档案资质与价格合理性
3. **执行审批**：选择通过或拒绝并填写审批意见
4. **结果回写**：通过则档案/价格生效，拒绝则退回修改重提

### 全链路流程图

```
开始 → 查看待审批单(三类) → ★讲师审批执行★ → ⚖是否通过？ → 回写档案/价格 → 结束（拒绝退回修改重提）
```

### 上游依赖

| 上游模块 | 依赖类型 | 依赖说明 | 依赖成立条件 |
|---------|---------|---------|-------------|
| 讲师档案管理 | 数据依赖 | 提交审批后生成审批记录，提供档案基本信息 | 讲师档案已提交审批 |
| HZERO 权限服务 | 服务依赖 | 提供按钮权限校验 | 用户已登录并分配权限编码 |
| HZERO 值集服务 | 服务依赖 | 提供讲师类型、审批状态、审批类型等值集 | 值集编码已配置（MBO.LECTURER_TYPE、MBO.APPROVAL_STATUS、MBO.APPROVAL_TYPE） |
| 事业部数据 | 数据依赖 | 提供负责事业部下拉选项 | 事业部主档已维护 |

### 下游影响

- **讲师档案详情页**：查看详情跳转，openTab 新标签页打开
- **讲师档案审批详情页**：审批操作跳转，openTab 新标签页，传入 `lecturerApprovalId`
- **讲师档案状态**：审批通过后档案状态更新为"生效"
- **讲师价格**：价格审批通过后生效；价格变更审批通过后更新为新价格

## 重点逻辑

### 重点逻辑1：审批中锁定

- **业务意义**：避免审核对象与实际内容不一致，保证审批依据的稳定性
- **具体逻辑描述**：
  - 档案提交后进入"审批中"状态
  - 提交人不能再修改档案内容
  - 审批人看到的内容与提交时一致

### 重点逻辑2：通过即生效

- **业务意义**：审批通过是档案/价格可被点将业务选用的前置条件
- **具体逻辑描述**：
  - 档案审批通过 → 档案状态转为"生效"
  - 价格审批通过 → 价格同步生效
  - 价格变更审批通过 → 价格更新为新价格
  - 生效后方可被点将业务选用

### 重点逻辑3：拒绝可重提

- **业务意义**：保证审批不通过时业务可闭环修正
- **具体逻辑描述**：
  - 审批拒绝必须填写审批意见
  - 档案状态退回可编辑
  - 提交人按意见修改后可再次提交审批

### 重点逻辑4：初始化讲师类型加载

- **业务意义**：仅展示有审批数据的讲师类型，避免空查询
- **具体逻辑描述**：
  1. 调用 `lecturerProfileApi.getLecturerTypeList` 获取类型列表 `typeList`
  2. 查询值集 `MBO.LECTURER_TYPE` 获取全部类型 `lovData`
  3. 过滤 `lovData` 中 `value` 在 `typeList` 中的项
  4. 加载到查询栏讲师类型下拉，自动设置默认值 `newTypeList[0]?.value`
  5. 触发列表查询

### 重点逻辑5：审批状态值集过滤

- **业务意义**：审批列表只展示已提交的审批单，过滤掉"待提交"状态
- **具体逻辑描述**：
  - 查询栏审批状态使用值集 `MBO.APPROVAL_STATUS`
  - 通过 `transformResponse` 过滤掉 `to_be_submit`（待提交）选项
  - 仅展示已提交的审批状态

### 重点逻辑6：审批跳转

- **业务意义**：根据审批类型路由到对应审批页面，复用同一列表入口
- **具体逻辑描述**：
  - 点击"审批"按钮，根据 `approvalType` 跳转不同审批页面
  - **archives（档案审批）**：跳转 `/detail/{id}/archivesApproval`，标题"讲师档案审批"
  - **price（牌价审批）**：跳转 `/detail/{id}/priceApproval`，标题"讲师牌价审批"
  - 跳转时通过 `state` 传入 `lecturerApprovalId` 参数

### 重点逻辑7：查询参数 pageType

- **业务意义**：区分不同类型讲师的审批数据
- **具体逻辑描述**：
  - 查询时 `pageType` 参数取值为 `lecturerType`（讲师类型值）
  - 未选择讲师类型时提示"请选择讲师类型"并阻止查询

## 详细逻辑

### 三类审批场景

| 审批类型 | 审批接口 | 审批内容 | 回写逻辑 |
|---------|---------|---------|---------|
| 档案审批（archives） | archivesAudit | 讲师档案基本信息 | 通过→档案生效；拒绝→档案退回可编辑 |
| 价格审批（price） | priceAudit | 讲师首次定价 | 通过→价格生效；拒绝→价格维持原值 |
| 价格变更审批（priceChange） | priceChangeApproval | 价格调整（原价/新价/调价理由） | 通过→价格更新为新价格；拒绝→价格维持原值 |

### 审批状态流转

```
待审批 → 审批通过 / 审批拒绝
```

- 审批状态由值集 `MBO.APPROVAL_RESULT` 定义
- 审批通过后自动回写讲师档案状态/价格
- 审批拒绝后讲师档案状态回退，允许修改重新提交

### 与讲师档案的关联

- 通过 `lecturerArchivesCode` 关联讲师档案
- 审批结果直接驱动讲师档案的状态变更
- 审批单中可查看关联讲师档案的详细信息

### 列表页

- **路由**：`/general/base/profileApproval`
- **主查询 API**：`POST mlt/maLecturerApproval/list`
- **分页 API**：`POST mlt/maLecturerApproval/page`
- **查询条件**：讲师类型（必填）、讲师姓名、负责事业部、审批状态
- **列表字段**：讲师档案编码、讲师姓名、审批类型、审批状态、讲师类型、所属部门、负责事业部、负责区域、标签、申请时间
- **操作按钮**：审批、查看详情

### 审批操作逻辑

#### 档案审批（archivesAudit）

1. 查看待审批讲师档案的详细信息（个人档案 + 讲师档案）
2. 审批人审核档案信息的完整性和合理性
3. 执行审批：
   - 通过 → 调用 `POST mlt/maLecturerApproval/archivesAudit`，传入审批结果=通过
   - 拒绝 → 调用 `POST mlt/maLecturerApproval/archivesAudit`，传入审批结果=拒绝 + 审批意见
4. 审批结果回写：
   - 通过 → 讲师档案状态更新为"生效"
   - 拒绝 → 讲师档案状态更新为"审批拒绝"

#### 价格审批（priceAudit）

1. 查看待审批讲师的价格信息（通过 `GET mlt/maLecturerApproval/queryCrmLecturerPriceList` 获取价格列表）
2. 审批人审核价格的合理性
3. 执行审批：
   - 通过 → 调用 `POST mlt/maLecturerApproval/priceAudit`，传入审批结果=通过
   - 拒绝 → 调用 `POST mlt/maLecturerApproval/priceAudit`，传入审批结果=拒绝 + 审批意见
4. 审批结果回写：
   - 通过 → 讲师价格生效
   - 拒绝 → 价格维持原值

#### 价格变更审批（priceChangeApproval）

1. 查看待审批讲师的价格变更信息（原价格、新价格、变更原因）
2. 审批人审核价格变更的合理性
3. 执行审批：
   - 通过 → 调用 `POST mlt/maLecturerApproval/priceChangeApproval`，传入审批结果=通过
   - 拒绝 → 调用 `POST mlt/maLecturerApproval/priceChangeApproval`，传入审批结果=拒绝 + 审批意见
4. 审批结果回写：
   - 通过 → 讲师价格更新为新价格
   - 拒绝 → 价格维持原值不变

### 保存/提交校验

- 校验1：审批意见 approvalComments 必填 —— 保证审批拒绝时有可追溯的拒绝理由
  - **详细逻辑**：审批结果为"拒绝"时，approvalComments 必填；通过时可选
  - **系统体现**：前端表单校验，未填写时阻止提交
  - **排查SQL**：
    ```sql
    SELECT LECTURER_APPROVAL_ID, LECTURER_APPROVAL_CODE, APPROVAL_RESULT, APPROVAL_REMARK
    FROM MA_LECTURER_APPROVAL
    WHERE APPROVAL_RESULT = 'reject' AND (APPROVAL_REMARK IS NULL OR APPROVAL_REMARK = '');
    ```
- 校验2：档案审批通过时讲师级别 lecturerLevel 必填 —— 保证生效档案具备完整等级信息
  - **详细逻辑**：approvalType=archives 且结果=通过时，校验关联档案的 lecturerLevel 非空
  - **系统体现**：后端 archivesAudit 接口校验，不通过返回业务异常
  - **排查SQL**：
    ```sql
    SELECT la.LECTURER_APPROVAL_CODE, la.LECTURER_ARCHIVES_CODE
    FROM MA_LECTURER_APPROVAL la
    LEFT JOIN MA_LECTURER_ARCHIVE ar ON la.LECTURER_ARCHIVES_CODE = ar.LECTURER_ARCHIVES_CODE
    WHERE la.APPROVAL_TYPE = 'archives' AND la.APPROVAL_RESULT = 'pass'
      AND (ar.LECTURER_LEVEL IS NULL OR ar.LECTURER_LEVEL = '');
    ```
- 校验3：档案审批通过时牌价 priceInfo 必填 —— 保证生效档案可参与点将计价
  - **详细逻辑**：approvalType=archives 且结果=通过时，校验关联档案的 priceInfo 非空
  - **系统体现**：后端 archivesAudit 接口校验
  - **排查SQL**：
    ```sql
    SELECT la.LECTURER_APPROVAL_CODE, la.LECTURER_ARCHIVES_CODE
    FROM MA_LECTURER_APPROVAL la
    LEFT JOIN MA_LECTURER_ARCHIVE ar ON la.LECTURER_ARCHIVES_CODE = ar.LECTURER_ARCHIVES_CODE
    WHERE la.APPROVAL_TYPE = 'archives' AND la.APPROVAL_RESULT = 'pass'
      AND (ar.PRICE IS NULL OR ar.PRICE = 0);
    ```

### 状态机

```
待审批(approving) ──审批通过──→ 审批通过(pass)
待审批(approving) ──审批拒绝──→ 审批拒绝(reject)
```

| 状态机名称 | 状态释义 | 可执行的操作 |
|-----------|---------|-------------|
| 待审批（approving） | 已提交待审批人处理 | 审批通过、审批拒绝 |
| 审批通过（pass） | 审批通过，档案/价格已生效 | 无（终态） |
| 审批拒绝（reject） | 审批拒绝，档案退回可编辑 | 提交人修改后重新提交 |

### 常见问题

- **Q1：档案审批、价格审批、价格变更审批有什么区别？**
  A：档案审批是对讲师档案基本信息的审批；价格审批是对讲师首次设定价格的审批；价格变更审批是对讲师价格变更的审批。三者审批接口不同（archivesAudit/priceAudit/priceChangeApproval），回写逻辑也不同。

- **Q2：审批拒绝后能否重新提交？**
  A：可以。审批拒绝后，讲师档案状态回退，用户可在讲师档案菜单修改后重新提交审批。

- **Q3：审批通过后能否撤销？**
  A：审批通过后不支持撤销，如需变更需走变更审批流程。

- **Q4：价格变更审批中原价格和新价格如何记录？**
  A：提交价格变更时，系统自动记录原价格（ORIGINAL_PRICE）和新价格（NEW_PRICE），审批人可对比查看。

- **Q5：一个审批单能否多次审批？**
  A：不可以。每个审批单仅可审批一次，审批后状态终态化。

- **Q6：讲师类型下拉为空？**
  A：检查 getLecturerTypeList 接口返回，确认有审批数据的类型，并确认值集 MBO.LECTURER_TYPE 已配置。

- **Q7：审批跳转页面错误？**
  A：检查 approvalType 字段值（archives/price），路由配置是否正确。

- **Q8：审批状态无待提交选项？**
  A：值集已过滤 to_be_submit，仅展示已提交状态，属正常设计。

- **Q9：列表无数据？**
  A：确认讲师类型选择正确，该类型下是否有审批数据。
