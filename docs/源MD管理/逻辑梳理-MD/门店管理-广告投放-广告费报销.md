# 门店管理-广告投放-广告费报销

## 业务流程

### 业务流程图

```text
广告投放申请        新建广告费报销      保存报销单         提交审批          OA审批
(已审批通过)  →   关联申请单     →   填写报销金额  →   校验金额    →   推送OA审批
                 选择额度内/外       选择发票信息       检查在途单据       ↓
                                                       ↓        审批通过/驳回
                                                    推送OA数据    OA回调处理
                                                                 更新报销信息
```

### 上游依赖

| 上游模块 | 依赖类型 | 依赖说明 | 依赖成立条件 |
|---------|---------|---------|------------|
| 广告投放申请 | 数据依赖 | 提供已审批通过的申请单、申请总金额、可用资源额度 | 申请单已审批通过 |
| 额度内资源额度 | 数据依赖 | 提供额度内可用金额 | 年度资源额度已配置 |
| OA审批系统 | 配置依赖 | 推送OA审批表单，接收OA回调结果 | OA单据配置已配置 |
| 值集配置 | 配置依赖 | 支付方式、费用类型、发票类型等值集 | AE_PAY_TYPE/AE_BX_TYPE/AE_INVOICE_TYPE值集已配置 |
| 工作流引擎 | 配置依赖 | 发起审批流程SUB_ADJ_FEE_BX_APPLY | 工作流已部署 |

### 下游影响

- 影响1：广告报销发票兑现
  - 报销审批通过后可发起发票兑现申请

- 影响2：申请单报销状态更新
  - 报销审批通过后更新申请单的已报销金额和报销完成状态

- 影响3：额度内资源额度占用
  - 额度内报销审批通过后占用资源额度

## 重点逻辑

### 重点逻辑1：报销金额校验 {核心校验}

- **业务意义**：确保报销金额不超过申请金额和可用额度

- **具体逻辑描述**

  - 第1点：本次报销金额必须>0

  - 第2点：本次报销金额不超过申请总金额

  - 第3点：额度内报销金额不超过可使用资源额度

  - 第4点：本次批准金额不超过本次报销金额

### 重点逻辑2：在途单据校验 {防重复提交}

- **业务意义**：防止同一申请单存在多个在途的报销单

- **具体逻辑描述**

  - 第1点：提交前检查同一申请单号是否已有审批中(RUN)的报销单

  - 第2点：存在在途单据时报错，提示已有在途的广告投放申请单

### 重点逻辑3：OA审批集成 {OA集成}

- **业务意义**：广告费报销走OA审批流程

- **具体逻辑描述**

  - 第1点：提交时组装报销数据推送到OA系统

  - 第2点：OA审批通过回调时，更新报销金额、批准金额、支付方式、供应商等字段

  - 第3点：额度内报销回调时更新发票号、发票内容、发票类型、税率、未含税金额等信息

  - 第4点：通过callbackSource变量(1=通过/2=驳回)驱动工作流分支

### 重点逻辑4：额度内与额度外区分 {费用类型}

- **业务意义**：报销分为额度内和额度外，OA回调处理的数据不同

- **具体逻辑描述**

  - 第1点：bxType=1为额度内，OA回调时更新发票相关信息

  - 第2点：bxType=2为额度外（销售费用-额度外其他补贴），无单独发票字段

  - 第3点：额度内需校验费用项目是否存在，额度外也需校验

#### 按钮1：提交（详情页）

- **触发条件**：审批状态为NEW
- **执行逻辑**：
  - 第1点：校验本次报销金额>0
  - 第2点：校验本次报销金额不超过申请总金额
  - 第3点：额度内校验报销金额不超过可使用资源额度
  - 第4点：校验本次批准金额不超过本次报销金额
  - 第5点：检查同一申请单号是否已有在途报销单
  - 第6点：推送OA审批，发起工作流
- **接口调用**：GET /v1/{organizationId}/fin-fee-bx-headers/check + OA推送接口 + 工作流发起接口
- **排查SQL**：

```sql
SELECT bx_id, bx_no, fee_apply_no, bx_type, this_standard_amt, total_apply_amt_bx, hz_approve_status
FROM fin_fee_bx_header WHERE bx_id = {id};
-- 检查在途单据
SELECT COUNT(*) FROM fin_fee_bx_header WHERE fee_apply_no = #{feeApplyNo} AND hz_approve_status = 'RUN';
```

#### 按钮2：打印（详情页）

- **触发条件**：常显
- **执行逻辑**：
  - 第1点：查询报销单头表数据
  - 第2点：翻译值集（支付方式、费用类型）
  - 第3点：查询流程审批历史
- **接口调用**：GET /v1/{organizationId}/fin-fee-bx-headers/detail/print
- **排查SQL**：无

### 保存校验

- 校验1：报销金额校验 —— 确保报销金额大于0

  - 详细逻辑

    - 第1点：额度内(bxType=1)且广告费报销(saveType=2)时校验

    - 第2点：本次报销金额<=0时报错"本次报销金额必须大于0！"

  - 系统体现：阻断性报错

  - 排查SQL：

    ```sql
    SELECT this_standard_amt FROM fin_fee_bx_header WHERE bx_id = {id};
    ```

- 校验2：申请金额校验 —— 报销金额不超过申请总金额

  - 详细逻辑

    - 第1点：本次报销金额>申请总金额时报错

  - 系统体现：阻断性报错

  - 排查SQL：

    ```sql
    SELECT this_standard_amt, total_apply_amt_bx FROM fin_fee_bx_header WHERE bx_id = {id};
    ```

- 校验3：额度内可用金额校验 —— 额度内报销不超可用

  - 详细逻辑

    - 第1点：本次报销金额>额度内可用金额时报错

  - 系统体现：阻断性报错

  - 排查SQL：

    ```sql
    SELECT this_standard_amt, in_can_use_amt FROM fin_fee_bx_header WHERE bx_id = {id} AND bx_type = 1;
    ```

- 校验4：批准金额校验 —— 批准金额不超过报销金额

  - 详细逻辑

    - 第1点：本次批准金额>本次报销金额时报错

  - 系统体现：阻断性报错

  - 排查SQL：

    ```sql
    SELECT this_standard_amt, this_authorize_standard_amt FROM fin_fee_bx_header WHERE bx_id = {id};
    ```

### 提交校验

- 校验1：在途单据校验 —— 防止重复提交

  - 详细逻辑

    - 第1点：查询同一申请单号下审批状态为RUN的报销单数量

    - 第2点：存在在途单据时报错"已有在途的广告投放申请单"

  - 系统体现：阻断性报错

  - 排查SQL：

    ```sql
    SELECT COUNT(*) FROM fin_fee_bx_header WHERE fee_apply_no = #{feeApplyNo} AND hz_approve_status = 'RUN';
    ```

- 校验2：费用项目校验 —— 确保费用项目存在

  - 详细逻辑

    - 第1点：额度内且支付方式非3时，费用项目不能为空

    - 第2点：额度外时，费用项目不能为空

  - 系统体现：阻断性报错

  - 排查SQL：

    ```sql
    SELECT object_name, bx_type, pay_type FROM fin_fee_bx_header WHERE bx_id = {id};
    ```

### 状态机

#### 状态机流转图

```text
NEW(新建) ──提交──→ RUN(审批中) ──OA审批通过──→ APPROVED(已审核)
                        │
                        │OA审批驳回
                        ↓
                   回到NEW
```

#### 状态机列表

| 状态机名称 | 状态释义 | 可执行的操作 |
|-----------|---------|------------|
| NEW | 新建，未提交 | 编辑、保存、提交 |
| RUN | 审批中，OA审批中 | 无（等待OA审批结果） |
| APPROVED | 已审核，OA审批通过 | 发起发票兑现、打印 |

#### 报错1：本次报销金额必须大于0！
- **触发条件**：点击"提交"按钮，额度内（BX_TYPE=1）且广告费报销（SAVE_TYPE=2）时，校验本次报销金额thisStandardAmt<=0
- **逻辑分析**：报销单需有有效报销金额才能占用资源额度与推送OA。校验逻辑读取FIN_FEE_BX_HEADER.THIS_STANDARD_AMT，若该值<=0则抛出阻断性异常，阻止OA推送和工作流发起。常见根因：用户未填写报销金额、金额被错误置0、或前端未做必填校验直接提交空单。
- **排查SQL**：
  ```sql
  SELECT bx_id                AS 报销单ID,
         bx_no                AS 报销单号,
         fee_apply_no         AS 申请单号,
         bx_type              AS 费用类型,
         this_standard_amt    AS 本次报销金额,
         hz_approve_status    AS 审批状态
  FROM   fin_fee_bx_header
  WHERE  save_type = 2
  AND    bx_type = 1
  AND    (this_standard_amt IS NULL OR this_standard_amt <= 0)
  ORDER  BY create_time DESC;
  ```

#### 报错2：本次报销金额不能超过申请总金额！
- **触发条件**：点击"提交"按钮，校验本次报销金额thisStandardAmt>申请总金额totalApplyAmtBx
- **逻辑分析**：报销金额受申请单总金额约束。校验逻辑读取FIN_FEE_BX_HEADER.THIS_STANDARD_AMT与TOTAL_APPLY_AMT_BX，当本次报销金额超过申请总金额则抛异常。常见根因：用户输入报销金额超限、申请单金额被修改、或前端未实时带入最新申请总金额。
- **排查SQL**：
  ```sql
  SELECT bx_id                AS 报销单ID,
         bx_no                AS 报销单号,
         fee_apply_no         AS 申请单号,
         this_standard_amt    AS 本次报销金额,
         total_apply_amt_bx   AS 申请总金额,
         hz_approve_status    AS 审批状态
  FROM   fin_fee_bx_header
  WHERE  save_type = 2
  AND    this_standard_amt > total_apply_amt_bx
  ORDER  BY create_time DESC;
  ```

#### 报错3：本次报销金额不可超过可使用资源额度！
- **触发条件**：点击"提交"按钮，额度内（BX_TYPE=1）时，校验本次报销金额thisStandardAmt>额度内可用金额inCanUseAmt
- **逻辑分析**：额度内报销需占用资源额度，报销金额不能超过当前可用额度。校验逻辑读取FIN_FEE_BX_HEADER.THIS_STANDARD_AMT与IN_CAN_USE_AMT，当BX_TYPE=1且本次报销金额>额度内可用金额时抛异常。常见根因：资源额度已被其他报销单占用、额度未及时刷新、或用户输入报销金额超限。
- **排查SQL**：
  ```sql
  SELECT bx_id                AS 报销单ID,
         bx_no                AS 报销单号,
         fee_apply_no         AS 申请单号,
         bx_type              AS 费用类型,
         this_standard_amt    AS 本次报销金额,
         in_can_use_amt       AS 额度内可用金额,
         hz_approve_status    AS 审批状态
  FROM   fin_fee_bx_header
  WHERE  save_type = 2
  AND    bx_type = 1
  AND    this_standard_amt > in_can_use_amt
  ORDER  BY create_time DESC;
  ```

#### 报错4：本次批准金额不可超过本次报销金额！
- **触发条件**：点击"提交"按钮，校验本次批准金额thisAuthorizeStandardAmt>本次报销金额thisStandardAmt
- **逻辑分析**：OA回调写入的批准金额不能超过用户提交的报销金额。校验逻辑读取FIN_FEE_BX_HEADER.THIS_AUTHORIZE_STANDARD_AMT与THIS_STANDARD_AMT，当批准金额超过报销金额则抛异常。常见根因：OA审批时批准金额被错误调大、数据回写异常、或前端未做边界校验。
- **排查SQL**：
  ```sql
  SELECT bx_id                       AS 报销单ID,
         bx_no                       AS 报销单号,
         this_standard_amt           AS 本次报销金额,
         this_authorize_standard_amt AS 本次批准金额,
         hz_approve_status           AS 审批状态
  FROM   fin_fee_bx_header
  WHERE  save_type = 2
  AND    this_authorize_standard_amt > this_standard_amt
  ORDER  BY create_time DESC;
  ```

#### 报错5：已有在途的广告投放申请单
- **触发条件**：点击"提交"按钮，校验同一申请单号FEE_APPLY_NO下已存在审批状态为RUN的报销单
- **逻辑分析**：为防止同一申请单重复报销，提交前查询FIN_FEE_BX_HEADER中同一FEE_APPLY_NO且HZ_APPROVE_STATUS='RUN'的记录数。若存在在途单据则抛异常，阻止重复提交。常见根因：用户在第一张报销单审批未完成时又提交第二张、或前端未做在途校验。
- **排查SQL**：
  ```sql
  SELECT fee_apply_no        AS 申请单号,
         COUNT(*)            AS 在途单据数,
         LISTAGG(bx_no, ',') WITHIN GROUP (ORDER BY bx_no) AS 在途报销单号
  FROM   fin_fee_bx_header
  WHERE  save_type = 2
  AND    hz_approve_status = 'RUN'
  GROUP  BY fee_apply_no
  HAVING COUNT(*) >= 1;
  ```

#### 报错6：推送OA失败：门店广告投放报销申请不存在
- **触发条件**：点击"提交"按钮推送OA时，按bxId查询FIN_FEE_BX_HEADER返回null
- **逻辑分析**：OA推送前需查询报销单组装数据。若单据在推送前被其他用户删除（物理删除），或bxId传值错误，查询返回空，无法组装OA数据导致推送失败。常见根因：并发操作删除单据、传参错误、或事务未提交即调用OA推送。
- **排查SQL**：
  ```sql
  SELECT bx_id                AS 报销单ID,
         bx_no                AS 报销单号,
         stat                 AS 单据状态,
         hz_approve_status    AS 审批状态
  FROM   fin_fee_bx_header
  WHERE  save_type = 2
  AND    bx_id = #{传入的bxId};
  ```

#### 报错7：费用项目未找到！
- **触发条件**：OA推送时，按报销单费用项目配置查询费用项目主数据返回null
- **逻辑分析**：OA推送需用费用项目组装OA表单。若报销单关联的费用项目（OBJECT_NAME）在费用项目主数据表中不存在、费用项目被停用删除、或配置错误，查询返回空，无法组装OA数据。常见根因：费用项目主数据未同步、配置错误、或报销单费用项目字段为空。
- **排查SQL**：
  ```sql
  SELECT bx_id                AS 报销单ID,
         bx_no                AS 报销单号,
         object_name          AS 费用项目,
         bx_type              AS 费用类型,
         pay_type             AS 支付方式
  FROM   fin_fee_bx_header
  WHERE  save_type = 2
  AND    (object_name IS NULL OR object_name NOT IN (SELECT project_code FROM fin_fee_project WHERE stat = 1))
  ORDER  BY create_time DESC;
  ```

#### 报错8：OA回调失败：广告投放报销申请不存在！
- **触发条件**：OA审批完成回调DMS时，按回调报文中的bxId查询FIN_FEE_BX_HEADER返回null
- **逻辑分析**：OA回调处理需更新报销单审批状态、批准金额、发票信息等。若回调期间单据被删除，或OA回调报文的单据ID与DMS不一致（如OA配置错误、ID映射异常），查询返回空，回调处理失败，审批状态无法更新。常见根因：单据被并发删除、OA配置错误、或回调报文ID丢失。
- **排查SQL**：
  ```sql
  SELECT bx_id                AS 报销单ID,
         bx_no                AS 报销单号,
         hz_approve_status    AS 审批状态,
         hz_instance_id       AS 工作流实例ID,
         callback_source      AS 回调来源
  FROM   fin_fee_bx_header
  WHERE  save_type = 2
  AND    bx_id = #{OA回调报文中的bxId};
  ```

#### 报错9：ID不能为空
- **触发条件**：OA回调处理方法接收到的bxId参数为null或空字符串
- **逻辑分析**：OA回调接口需用bxId定位单据。若OA系统未正确配置回调用单据ID字段，或回调报文丢失ID字段，DMS接收到的ID为空，无法执行后续更新逻辑。常见根因：OA单据配置缺失ID字段、回调报文格式异常、或接口映射错误。
- **排查SQL**：
  ```sql
  SELECT bx_id                AS 报销单ID,
         bx_no                AS 报销单号,
         hz_instance_id       AS 工作流实例ID,
         hz_approve_status    AS 审批状态
  FROM   fin_fee_bx_header
  WHERE  save_type = 2
  AND    hz_approve_status = 'RUN'
  AND    bx_id IS NULL
  ORDER  BY create_time DESC;
  ```

#### 报错10：报销申请不存在

- **逻辑分析**：提交校验需查询报销单确认单据存在且状态合法。若单据已被删除、bxId传值错误、或事务未提交即调用校验，查询返回空，无法继续提交逻辑。常见根因：单据被并发删除、前端传参错误、或保存失败后误调提交。
- **排查SQL**：
  ```sql
  SELECT bx_id                AS 报销单ID,
         bx_no                AS 报销单号,
         stat                 AS 单据状态,
         hz_approve_status    AS 审批状态
  FROM   fin_fee_bx_header
  WHERE  save_type = 2

  ```

#### 报错11：主键不能为空!
- **触发条件**：工作流回调更新报销单时，接收到的bxId（单据主键）为null或0
- **逻辑分析**：工作流回调需用bxId定位并更新报销单审批状态。若工作流配置未正确传回单据ID、回调报文丢失ID、或保存时未正确回写BX_ID，会导致主键为空，无法执行更新逻辑。常见根因：工作流配置错误、回调报文异常、或自增序列未取回。
- **排查SQL**：
  ```sql
  SELECT bx_id                AS 报销单ID,
         bx_no                AS 报销单号,
         hz_instance_id       AS 工作流实例ID,
         hz_approve_status    AS 审批状态
  FROM   fin_fee_bx_header
  WHERE  save_type = 2
  AND    hz_approve_status = 'RUN'
  AND    (bx_id IS NULL OR bx_id = 0)
  ORDER  BY create_time DESC;
  ```
