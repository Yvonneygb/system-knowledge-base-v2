# 门店管理-装修报表-门额度内兑现统计报表

> 本页面为低代码页面(hlod)，无独立前端源码，基于后端API梳理。

## 业务流程

门额度内兑现统计报表用于查询门店装修额度内兑现的汇总统计数据及明细信息。主查询按门店、经销商、交易公司、事业部等维度统计额度内兑现汇总数据（可兑现总额、已兑现金额、剩余未兑现金额等），明细查询展示每笔兑现单的详细信息。本页面为纯查询报表，仅支持查看和导出，不支持新增、修改、删除等写操作。

**核心流程：**
1. 用户进入门额度内兑现统计报表页面
2. 填写查询条件（验收报销单号、事业部、交易公司、经销商、门店、开票单位等）
3. 点击查询，调用主查询接口分页返回额度内兑现汇总数据
4. 用户可查看明细，调用明细查询接口获取每笔兑现单详细信息
5. 用户查看报表数据，可导出Excel归档

```
开始 → 设定查询条件 → 点击查询 → 主查询FIN_FEE_TERMINAL_CASHOUT_VIEW视图 → 返回汇总数据 → 查看明细(getCashoutLine查询fin_fee_terminal_cashout表) → 导出Excel → 结束
```

- 上游支撑：额度内兑现单（FIN_FEE_TERMINAL_CASHOUT）、门店验收与报销单（FIN_FEE_CHECK_BX_HEADER）、事业部基础设置（DIVISION_BASE_SET）、值集（HPFM_LOV_VALUE）、hlod报表引擎
- 下游影响：额度内兑现情况分析、核销/兑现金额核对、复核进度监控、Excel导出归档、内部管理决策参考

## 重点逻辑

### 重点逻辑1：纯报表查询页面【只读查询】

- **业务意义**：供内部人员查询门店装修额度内兑现的汇总统计报表信息，了解额度内兑现的整体情况
- **具体逻辑描述**：
  - 本页面为hlod低代码报表页面，无独立前端源码
  - 仅提供查询和导出功能，不支持新增、修改、删除操作
  - 主查询数据来源于视图 `EPMS.FIN_FEE_TERMINAL_CASHOUT_VIEW`，包含可兑现总额、已兑现金额、剩余未兑现金额等汇总指标

### 重点逻辑2：主查询与明细查询双接口

- **业务意义**：主查询展示汇总统计，明细查询展示每笔兑现单详情，满足不同粒度的数据查看需求
- **具体逻辑描述**：
  - 主查询（finFeeTerminalCashoutListSearch）：查询 `EPMS.FIN_FEE_TERMINAL_CASHOUT_VIEW` 视图，返回汇总数据，按CHECK_BX_ID降序排列
  - 明细查询（finFeeTerminalCashoutListGetCashoutLine）：查询 `FIN_FEE_TERMINAL_CASHOUT` 表，LEFT JOIN `FIN_FEE_CHECK_BX_HEADER` 和 `DIVISION_BASE_SET`，返回每笔兑现单详情
  - 明细查询排除"超额作废"记录：`h.audit_stat != '超额作废'`

### 重点逻辑3：金额字段格式化

- **业务意义**：统一金额展示格式，确保报表数据可读性
- **具体逻辑描述**：
  - 主查询：金额字段使用 `TO_CHAR(..., '999999999990.99')` 格式化（无FM前缀，保留前导空格）
  - 明细查询：金额字段使用 `TO_CHAR(..., 'FM999999999990.00')` 格式化（带FM前缀，无前导空格，2位小数）
  - 日期字段统一 `TO_CHAR(..., 'YYYY-MM-DD')` 格式化

### 重点逻辑4：支付方式值集翻译

- **业务意义**：将支付方式编码翻译为可读含义
- **具体逻辑描述**：
  - 通过子查询 `HZERO.HPFM_LOV_VALUE` 翻译，LOV_CODE = 'AE.PAY_TYPE'
  - SQL：`(SELECT meaning FROM HZERO.HPFM_LOV_VALUE WHERE LOV_CODE = 'AE.PAY_TYPE' and value = v.PAY_TYPE)`

### 重点逻辑5：查询条件匹配规则

- **业务意义**：支持多维度灵活筛选额度内兑现数据
- **具体逻辑描述**：
  - 模糊查询（LIKE '%xxx%'）：验收报销单号、事业部名称、开票单位名称、交易公司名称、经销商名称
  - 精确查询：事业部ID、开票单位编码、门店编码、经销商编码
  - 主查询和明细查询使用相同的查询条件参数集

### 后端接口Mapper SQL

**主查询SQL：**
```sql
-- 额度内兑现统计报表主查询
SELECT
    v.CHECK_BX_ID,
    v.CHECK_BX_CODE,
    v.DIVISION_ID,
    v.DIVISION_NAME,
    v.TRADING_COMPANY_NAME,
    v.CUST_CODE,
    v.CUST_NAME,
    v.BILLING_UNIT_CODE,
    v.BILLING_UNIT_NAME,
    v.TERMINAL_CODE,
    v.COST_CENTER_NAME,
    TO_CHAR(v.REDUCE_AMT, '999999999990.99') AS REDUCE_AMT,
    TO_CHAR(v.CASHOUT_AMT, '999999999990.99') AS CASHOUT_AMT,
    TO_CHAR(v.ALL_REDUCE_AMT, '999999999990.99') AS ALL_REDUCE_AMT,
    TO_CHAR(v.ALL_CASHOUT_AMT, '999999999990.99') AS ALL_CASHOUT_AMT,
    (SELECT meaning FROM HZERO.HPFM_LOV_VALUE WHERE LOV_CODE = 'AE.PAY_TYPE' AND value = v.PAY_TYPE) AS PAY_TYPE,
    TO_CHAR(v.NO_REDUCE_AMT, '999999999990.99') AS NO_REDUCE_AMT,
    TO_CHAR(v.NO_CASHOUT_AMT, '999999999990.99') AS NO_CASHOUT_AMT
FROM epms.FIN_FEE_TERMINAL_CASHOUT_VIEW v
WHERE 1 = 1
    AND v.check_bx_code LIKE '%' || #{checkBxCode} || '%'       -- 验收报销单号（模糊）
    AND v.division_id = #{divisionId}                           -- 事业部ID（精确）
    AND v.division_name LIKE '%' || #{divisionName} || '%'      -- 事业部名称（模糊）
    AND v.billing_unit_code = #{billingUnitCode}                -- 开票单位编码（精确）
    AND v.billing_unit_name LIKE '%' || #{billingUnitName} || '%' -- 开票单位名称（模糊）
    AND v.trading_company_name LIKE '%' || #{tradingCompanyName} || '%' -- 交易公司名称（模糊）
    AND v.terminal_code = #{terminalCode}                       -- 门店编码（精确）
    AND v.cust_code = #{custCode}                               -- 经销商编码（精确）
    AND v.cust_name LIKE '%' || #{custName} || '%'              -- 经销商名称（模糊）
ORDER BY v.CHECK_BX_ID DESC
```

#### 报错1：查询结果为空
- **触发条件**：点击"查询"按钮，按当前查询条件（验收报销单号、事业部、交易公司、经销商、门店、开票单位等）查询EPMS.FIN_FEE_TERMINAL_CASHOUT_VIEW视图返回空结果集
- **逻辑分析**：主查询从FIN_FEE_TERMINAL_CASHOUT_VIEW视图汇总额度内兑现数据，明细查询从FIN_FEE_TERMINAL_CASHOUT表查询并排除"超额作废"记录。若查询条件过严（如经销商编码拼写错误、事业部ID不匹配）、或验收报销单尚未生成兑现单、或兑现单全部为"超额作废"被排除、或用户组织ID与数据不匹配，均会返回空结果。该报错为提示性，不影响系统。
- **排查SQL**：
  ```sql
  SELECT check_bx_id          AS 验收报销单ID,
         check_bx_code        AS 验收报销单号,
         cust_name            AS 经销商名称,
         terminal_name        AS 门店名称,
         audit_stat           AS 审核状态,
         organization_id      AS 组织ID
  FROM   fin_fee_terminal_cashout
  WHERE  organization_id = #{当前用户组织ID}
  AND    audit_stat != '超额作废'
  ORDER  BY create_time DESC;
  ```

#### 报错2：支付方式翻译为空
- **触发条件**：查询结果展示时，子查询 `(SELECT meaning FROM HZERO.HPFM_LOV_VALUE WHERE LOV_CODE = 'AE.PAY_TYPE' AND value = v.PAY_TYPE)` 返回空
- **逻辑分析**：报表通过子查询关联HZERO.HPFM_LOV_VALUE值集表翻译支付方式编码为可读含义（如"现金"、"银行转账"）。若值集配置缺失（LOV_CODE='AE.PAY_TYPE'未配置）、或兑现单的PAY_TYPE值未在值集中维护（如新增支付方式未同步值集）、或值表数据被误删，子查询返回空，支付方式列显示空白，影响报表可读性但不阻断查询。
- **排查SQL**：
  ```sql
  SELECT v.pay_type                AS 支付方式编码,
         COUNT(*)                  AS 兑现单数量
  FROM   fin_fee_terminal_cashout v
  WHERE  v.pay_type IS NOT NULL
  AND    NOT EXISTS (
           SELECT 1
           FROM   hzero.hpfm_lov_value lv
           WHERE  lv.lov_code = 'AE.PAY_TYPE'
           AND    lv.value = v.pay_type
         )
  GROUP  BY v.pay_type
  ORDER  BY 兑现单数量 DESC;
  ```

## 常见问题FAQ

**Q1：主查询和明细查询的区别？**
A：主查询（finFeeTerminalCashoutListSearch）查询 `EPMS.FIN_FEE_TERMINAL_CASHOUT_VIEW` 视图，返回按验收报销单汇总的统计数据；明细查询（finFeeTerminalCashoutListGetCashoutLine）查询 `FIN_FEE_TERMINAL_CASHOUT` 表，返回每笔兑现单的详细信息。

**Q2：明细查询排除了哪些数据？**
A：排除了审核状态为"超额作废"的记录：`h.audit_stat != '超额作废'`。

**Q3：金额字段格式化方式？**
A：主查询使用 `TO_CHAR(..., '999999999990.99')`（无FM前缀），明细查询使用 `TO_CHAR(..., 'FM999999999990.00')`（带FM前缀，无前导空格）。

**Q4：支付方式如何展示？**
A：通过子查询 `HZERO.HPFM_LOV_VALUE`（LOV_CODE = 'AE.PAY_TYPE'）将编码翻译为可读含义。

**Q5：报表是否支持新增/修改/删除？**
A：不支持，本页面为纯查询报表，仅支持查看和导出。
