# 工程管理-项目往来-工程核销发票上传

> 本页面为低代码页面(hlod)，无独立前端源码，基于后端API梳理。

## 业务流程

```text
用户进入工程核销发票上传页面
  → 选择项目/合同/折扣政策
  → 上传发票影像文件 → 触发OCR识别(POST /invoice-identify)
    → OCR返回发票代码/号码/日期/金额/购销方等信息 → 自动回填
  → 补充/修改发票主要信息(发票代码、号码、开票日期、金额等)
  → 补充/修改发票详细信息(货物名称、数量、单价、金额、税率等)
  → 可Excel导入发票明细(POST /import-line)
  → 保存(POST /insert或/update)
    → 生成核销单号(AE.INVOICE_VERIFER_NO/AE.JZ_INVOICE_VERIFER_NO)
    → 校验发票号码+代码不重复、行金额=单价×数量、明细汇总=发票总金额
  → 提交审批 → 触发工作流(INVOICE_WF_UPLOAD_AW/INVOICE_JZHXFPSC_AW)
    → 审批通过 → 发票信息生效(effectStatus=valid) → 可用于真实性核销
    → 审批驳回 → 流程中断
  → 可终止(POST /terminate)/撤回终止(POST /undo-terminate)
```

### 全链路流程图

```text
开始 → 选择项目/合同 → 上传发票影像 → OCR识别 → ★保存核销发票上传单★
  → 提交审批(工作流) → ⚖审批通过？
    ├── 是 → 发票明细生效(valid) → 可参与真实性核销 → 结束
    └── 否 → 驳回中断 → 结束
  → 终止 → 记录终止历史 → 结束
  → 撤回终止 → 恢复正常 → 结束
```

### 关键规则

- **四部分数据**：一份上传单包含发票影像(EPM_UPLOAD_INVOICE)、发票主要信息(EPM_UPLOAD_INVOICE_INFO)、发票详细信息(EPM_UPLOAD_INVOICE_DETAILS)、附件
- **OCR识别+手工修正**：上传发票影像后调用OCR自动识别，识别结果可手工修正，operationFlag=2为OCR识别、1为手工修改、0为手工新增
- **发票唯一性**：同一核销单下发票代码+发票号码不可重复，且不能已被其它单核销
- **金额校验**：明细行金额=单价×数量(允许0.01差异)，明细汇总金额=发票主要信息总金额
- **工程/家装区分**：isHome=1工程使用AE.INVOICE_VERIFER_NO编码+INVOICE_WF_UPLOAD_AW工作流，isHome=2家装使用AE.JZ_INVOICE_VERIFER_NO编码+INVOICE_JZHXFPSC_AW工作流

## 重点逻辑

### 重点逻辑1：OCR发票识别

- **业务意义**：上传发票影像文件后自动识别发票信息，减少人工录入工作量
- **具体逻辑描述**：
  - 通过附件UUID获取文件URL，调用sysFileService.getSignedUrl获取签名URL
  - 调用OcrSdkService.ocrCheckInvoice进行OCR识别
  - OCR返回结果包含发票代码、发票号码、开票日期、金额、校验码、购销方信息、明细行等
  - 识别结果自动回填到发票主要信息和详细信息字段，operationFlag=2标记为OCR识别
  - 跳过货物名称为"(详见销货清单)"的明细行
  - 通过规格型号自动匹配基本单位(selectUomByModel)
  - OCR识别失败时抛出异常，不阻断保存(try-catch包裹)

### 重点逻辑2：发票重复校验

- **业务意义**：防止同一张发票被重复上传核销，确保发票唯一性
- **具体逻辑描述**：
  - beforeSave方法中遍历发票主要信息，校验发票代码+发票号码非空且不重复
  - 调用checkInvoices方法，通过selectCountOfInvoiceCode查询该发票是否已被其它核销单核销
  - 发票详细信息校验：每条明细的发票代码+号码必须在主要信息中存在
  - 校验失败时抛出CommonException，包含所有错误信息

### 重点逻辑3：保存逻辑

- **业务意义**：保存核销发票上传单，包含影像、主要信息、详细信息、附件四部分数据
- **具体逻辑描述**：
  - 新增(doInsert)：自动生成核销单号(编码规则AE.INVOICE_VERIFER_NO/AE.JZ_INVOICE_VERIFER_NO)，auditStat="新建"，保存四部分数据
  - 修改(doUpdate)：保留原auditStat/hzInstanceId/hzApproveStatus/wfflag/organizationId，更新四部分数据
  - 保存前调用beforeSave校验发票唯一性和完整性
  - 附件通过objAttachRelService.saveData保存关联关系

### 重点逻辑4：导入发票明细

- **业务意义**：支持通过Excel导入发票详细信息，提高录入效率
- **具体逻辑描述**：
  - 导入时逐行校验：凭证号码非空且存在、发票号码非空、发票代码非空、发票数量非空且>0、单价非空、转换率非空、规格型号非空
  - 税率校验：0-100范围内
  - 导入数据匹配已有明细(seq+凭证号码匹配)，匹配到则更新(OCR识别的改为手工修改flag=1)，未匹配则新增(flag=0)
  - 错误信息按行号收集，返回所有错误

### 重点逻辑5：终止与撤回终止

- **业务意义**：对核销发票上传单进行终止操作，支持撤回终止恢复
- **具体逻辑描述**：
  - 终止(terminate)：调用invoiceCancelHandle(handleType="disable")，记录终止历史
  - 撤回终止(undoTerminate)：调用invoiceCancelHandle(handleType="enable")，恢复正常状态
  - bizType区分：isHome=2为211116(家装)，否则210906(工程)
  - 终止/撤回终止通过invoiceCancelService.handle处理，记录操作原因和操作人

### 重点逻辑6：审批完成回调

- **业务意义**：审批通过后更新发票有效状态，确保核销数据生效可用于真实性核销
- **具体逻辑描述**：
  - wfComplete：审批非驳回时，更新发票主要信息和详细信息的effectStatus="valid"
  - onProcComplete：校验发票详细信息非空，更新主要信息和详细信息的effectStatus="valid"
  - wfProcSubmit：提交工作流前校验主要信息和详细信息非空，调用beforeSave和verifyData校验，按isHome选择工作流编码

### 重点逻辑7：金额校验

- **业务意义**：确保发票明细金额计算正确，明细汇总与发票总金额一致
- **具体逻辑描述**：
  - verifyData方法：查询发票主要信息和详细信息
  - 行级校验：单价×数量=金额(允许0.01差异)
  - 汇总校验：同一发票号码的明细行金额汇总=发票主要信息总金额(allAmount)
  - 校验失败时收集所有错误信息一次性抛出

#### 按钮1：OCR识别（详情页）

- **触发条件**：已上传发票影像文件
- **处理逻辑**：
  1. 通过附件UUID获取文件URL，获取签名URL
  2. 调用OcrSdkService.ocrCheckInvoice识别
  3. 解析OCR返回结果，组装发票主要信息和详细信息
  4. 通过规格型号自动匹配基本单位
  5. operationFlag=2标记为OCR识别

#### 按钮2：保存（详情页）

- **触发条件**：新建或编辑状态
- **处理逻辑**：
  1. 调用beforeSave校验发票唯一性和完整性
  2. 新增时生成核销单号(编码规则AE.INVOICE_VERIFER_NO/AE.JZ_INVOICE_VERIFER_NO)，auditStat="新建"
  3. 保存发票影像、主要信息、详细信息、附件四部分数据
  4. 修改时保留原审批状态相关信息

#### 按钮3：提交审批（详情页）

- **触发条件**：保存且校验通过
- **处理逻辑**：
  1. 查询发票主要信息和详细信息，非空校验
  2. 调用beforeSave校验发票唯一性
  3. 调用verifyData校验金额(单价×数量=金额，明细汇总=总金额)
  4. 按isHome选择工作流编码(工程INVOICE_WF_UPLOAD_AW/家装INVOICE_JZHXFPSC_AW)
  5. 启动工作流实例，更新hzInstanceId和hzApproveStatus=RUN

#### 按钮4：终止（详情页）

- **触发条件**：非终止状态
- **处理逻辑**：调用invoiceCancelHandle(handleType="disable")，记录终止历史

#### 按钮5：撤回终止（详情页）

- **触发条件**：已终止状态
- **处理逻辑**：调用invoiceCancelHandle(handleType="enable")，恢复正常状态

### 保存校验

#### 校验1：发票号码和发票代码不可重复 —— 防止同一张发票重复上传

- **详细逻辑**：beforeSave方法中遍历发票主要信息，校验发票代码+发票号码非空且在同一条上传单内不重复，同时调用checkInvoices校验该发票是否已被其它单核销
- **系统体现**：beforeSave方法中invoiceSet去重校验+selectCountOfInvoiceCode跨单校验
- **排查SQL**：
```sql
SELECT INVOICE_CODE, INVOICE_NUMBER, COUNT(*)
FROM EPM_UPLOAD_INVOICE_INFO
WHERE INVOICE_VERIFER_ID = #{invoiceVeriferId}
GROUP BY INVOICE_CODE, INVOICE_NUMBER
HAVING COUNT(*) > 1;
```

#### 校验2：发票详细信息关联主要信息 —— 确保明细行发票号码在主要信息中存在

- **详细逻辑**：遍历发票详细信息，校验每条明细的发票代码+号码在主要信息集合中存在
- **系统体现**：beforeSave方法中detail校验invoiceSet.contains
- **排查SQL**：
```sql
SELECT d.INVOICE_CODE, d.INVOICE_NUMBER
FROM EPM_UPLOAD_INVOICE_DETAILS d
WHERE d.INVOICE_VERIFER_ID = #{invoiceVeriferId}
  AND NOT EXISTS (
    SELECT 1 FROM EPM_UPLOAD_INVOICE_INFO i
    WHERE i.INVOICE_VERIFER_ID = d.INVOICE_VERIFER_ID
      AND i.INVOICE_CODE = d.INVOICE_CODE
      AND i.INVOICE_NUMBER = d.INVOICE_NUMBER
  );
```

### 提交校验

#### 校验1：发票主要信息不能为空 —— 确保上传单有发票主信息

- **详细逻辑**：提交工作流前查询发票主要信息，为空则报错
- **系统体现**：wfProcSubmit方法中epmUploadInvoiceInfoService.select结果为空时抛CommonException
- **排查SQL**：
```sql
SELECT COUNT(*) FROM EPM_UPLOAD_INVOICE_INFO WHERE INVOICE_VERIFER_ID = #{invoiceVeriferId};
```

#### 校验2：发票详细信息不能为空 —— 确保上传单有发票明细

- **详细逻辑**：提交工作流前和流程节点完成时查询发票详细信息，为空则报错
- **系统体现**：wfProcSubmit和onProcComplete方法中selectByInvoiceVeriferId结果为空时抛CommonException
- **排查SQL**：
```sql
SELECT COUNT(*) FROM EPM_UPLOAD_INVOICE_DETAILS WHERE INVOICE_VERIFER_ID = #{invoiceVeriferId};
```

#### 校验3：行金额校验 —— 确保明细金额计算正确且汇总一致

- **详细逻辑**：verifyData方法校验：单价×数量=金额(允许0.01差异)，同一发票号码的明细行金额汇总=发票主要信息总金额(allAmount)
- **系统体现**：verifyData方法中逐行计算并汇总比对，错误收集后一次性抛出
- **排查SQL**：
```sql
SELECT i.INVOICE_NUMBER, i.ALL_AMOUNT, NVL(SUM(d.AMOUNT), 0) AS detail_sum
FROM EPM_UPLOAD_INVOICE_INFO i
LEFT JOIN EPM_UPLOAD_INVOICE_DETAILS d
  ON d.INVOICE_VERIFER_ID = i.INVOICE_VERIFER_ID
 AND d.INVOICE_NUMBER = i.INVOICE_NUMBER
WHERE i.INVOICE_VERIFER_ID = #{invoiceVeriferId}
GROUP BY i.INVOICE_NUMBER, i.ALL_AMOUNT;
```

```text
[新建NEW] ──提交──> [审批中RUN] ──审批通过──> [已审批APPROVED]
```

| INTERRUPT | 审批驳回 | 终止 |
| TERMINATED | 已终止 | 撤回终止 |

#### 报错1：请选中要上传的发票
- **触发条件**：OCR识别时，未选择发票文件(DTO为空)
- **逻辑分析**：invoiceIdentify方法中校验DTO非空，若为空则抛出阻断性报错。需选择发票文件后重试
- **排查SQL**：
  ```sql
  SELECT euii.UPLOAD_INVOICE_INFO_ID, euii.INVOICE_NO, euii.INVOICE_CODE, euii.EFFECT_STATUS
  FROM EPM_UPLOAD_INVOICE_INFO euii
  WHERE euii.UPLOAD_INVOICE_INFO_ID = :uploadInvoiceInfoId
  -- 校验发票上传单是否存在
  ```

#### 报错2：附件uuid:xxx未找到对应的附件
- **触发条件**：OCR识别时，附件UUID对应的文件不存在
- **逻辑分析**：fileClient.getAttachmentFiles按UUID查询附件，若返回空则抛出阻断性报错。需检查文件上传是否成功
- **排查SQL**：
  ```sql
  SELECT ha.ATTACHMENT_ID, ha.ATTACHMENT_UUID, ha.FILE_NAME, ha.FILE_URL, ha.OBJECT_ID
  FROM HPFM_ATTACHMENT ha
  WHERE ha.ATTACHMENT_UUID = :attachmentUuid
  -- 若返回空，说明附件不存在
  ```

#### 报错3：附件uuid:xxx ocr接口识别失败
- **触发条件**：OCR识别时，OCR服务不可用或文件格式不支持
- **逻辑分析**：调用OCR接口识别发票，若返回非2xx或payload为空则抛出阻断性报错。需检查OCR服务连通性和文件格式
- **排查SQL**：
  ```sql
  SELECT ha.ATTACHMENT_ID, ha.ATTACHMENT_UUID, ha.FILE_NAME, ha.FILE_URL, ha.FILE_TYPE
  FROM HPFM_ATTACHMENT ha
  WHERE ha.ATTACHMENT_UUID = :attachmentUuid
  -- 检查附件文件类型是否被OCR支持
  ```

#### 报错4：OCR校验异常，返回开票时间错误
- **触发条件**：OCR识别时，OCR返回的开票日期格式不符合yyyy-MM-dd
- **逻辑分析**：invoiceInfoCovert方法中用LocalDate.parse解析开票日期，若解析失败则抛出中等优先级报错。需检查发票影像清晰度
- **排查SQL**：
  ```sql
  SELECT euii.UPLOAD_INVOICE_INFO_ID, euii.INVOICE_NO, euii.INVOICE_DATE, euii.EFFECT_STATUS
  FROM EPM_UPLOAD_INVOICE_INFO euii
  WHERE euii.INVOICE_DATE IS NOT NULL
    AND REGEXP_LIKE(euii.INVOICE_DATE, '^[0-9]{4}-[0-9]{2}-[0-9]{2}$') = 0
  -- 查出开票日期格式异常的发票
  ```

#### 报错5：发票主要明细校验异常:xxx
- **触发条件**：保存发票时，发票号码+代码为空或重复，或已被其它单核销
- **逻辑分析**：beforeSave方法中校验发票主要信息(号码+代码非空、不重复、未被核销)，失败则抛出阻断性报错。需修正发票信息后重试

  ```sql
  WHERE euii.INVOICE_NO IS NULL OR euii.INVOICE_CODE IS NULL
     OR euii.IS_VERIFIED = 'Y'
  -- 查出号码/代码为空或已核销的发票
  ```

#### 报错6：发票详细明细校验异常:xxx
- **触发条件**：保存发票时，明细行发票代码+号码在主要信息中不存在
- **逻辑分析**：beforeSave方法中校验明细行的发票代码+号码必须在主要信息中存在，失败则抛出阻断性报错。需修正明细信息后重试
- **排查SQL**：
  ```sql
  SELECT euid.UPLOAD_INVOICE_DETAILS_ID, euid.INVOICE_NO, euid.INVOICE_CODE,
         euii.UPLOAD_INVOICE_INFO_ID AS 主要信息存在性
  FROM EPM_UPLOAD_INVOICE_DETAILS euid
  LEFT JOIN EPM_UPLOAD_INVOICE_INFO euii
    ON euid.INVOICE_NO = euii.INVOICE_NO AND euid.INVOICE_CODE = euii.INVOICE_CODE
  WHERE euii.UPLOAD_INVOICE_INFO_ID IS NULL
  -- 查出明细行对应主要信息不存在的发票
  ```

#### 报错10：发票号码[xxx]，详情行计算金额[xxx]有误
- **触发条件**：提交审批时，明细行单价×数量≠金额(允许0.01差异)
- **逻辑分析**：verifyData方法中校验每行UNIT_PRICE×QTY≈AMOUNT(差异>0.01则失败)，若不一致则抛出阻断性报错。需修正明细金额后重试
- **排查SQL**：
  ```sql
  SELECT euid.UPLOAD_INVOICE_DETAILS_ID, euid.INVOICE_NO, euid.UNIT_PRICE, euid.QTY, euid.AMOUNT,
         ABS(euid.UNIT_PRICE * euid.QTY - euid.AMOUNT) AS 金额差异
  FROM EPM_UPLOAD_INVOICE_DETAILS euid
  WHERE ABS(euid.UNIT_PRICE * euid.QTY - euid.AMOUNT) > 0.01
  -- 查出金额计算有误的明细行
  ```

#### 报错11：发票号码[xxx]，详情信息行汇总金额与主要总金额不一致
- **触发条件**：提交审批时，明细行金额汇总≠发票总金额
- **逻辑分析**：verifyData方法中按INVOICE_NO汇总明细行金额，若与主要信息INVOICE_AMOUNT不一致则抛出阻断性报错。需修正金额后重试
- **排查SQL**：
  ```sql
  SELECT euii.INVOICE_NO, euii.INVOICE_AMOUNT AS 主要总金额,
         (SELECT SUM(euid.AMOUNT) FROM EPM_UPLOAD_INVOICE_DETAILS euid
          WHERE euid.INVOICE_NO = euii.INVOICE_NO) AS 明细汇总金额,
         ABS(euii.INVOICE_AMOUNT - (SELECT SUM(euid.AMOUNT) FROM EPM_UPLOAD_INVOICE_DETAILS euid
          WHERE euid.INVOICE_NO = euii.INVOICE_NO)) AS 金额差异
  FROM EPM_UPLOAD_INVOICE_INFO euii
  WHERE ABS(euii.INVOICE_AMOUNT - (SELECT SUM(euid.AMOUNT) FROM EPM_UPLOAD_INVOICE_DETAILS euid
          WHERE euid.INVOICE_NO = euii.INVOICE_NO)) > 0.01
  -- 查出汇总金额不一致的发票
  ```

  ```sql
  GROUP BY euii.INVOICE_CODE, euii.INVOICE_NUMBER
  HAVING COUNT(*) > 1
  -- 查出同一上传单内重复的发票
  ```

- **逻辑分析**：beforeSave方法中校验每条详细信息的发票代码+号码必须在主要信息invoiceSet中存在，若不存在则收集错误后抛出阻断性报错。需修正明细关联
- **排查SQL**：
  ```sql
  SELECT euid.UPLOAD_INVOICE_DETAILS_ID, euid.INVOICE_CODE, euid.INVOICE_NUMBER
  FROM EPM_UPLOAD_INVOICE_DETAILS euid
  WHERE euid.INVOICE_VERIFER_ID = :invoiceVeriferId
    AND NOT EXISTS (
      SELECT 1 FROM EPM_UPLOAD_INVOICE_INFO euii
      WHERE euii.INVOICE_VERIFER_ID = euid.INVOICE_VERIFER_ID
        AND euii.INVOICE_CODE = euid.INVOICE_CODE
        AND euii.INVOICE_NUMBER = euid.INVOICE_NUMBER
    )
  -- 查出明细行对应主要信息不存在的发票
  ```

#### 报错22：xxx已被其它单进行核销.
- **触发条件**：保存发票时，发票号码+代码已被其它核销单核销
- **逻辑分析**：beforeSave方法中调用checkInvoices，通过selectCountOfInvoiceCode查询该发票是否已被其它核销单(INVOICE_VERIFER_ID不同)核销，若count>0则抛出阻断性报错。需更换未核销发票
- **排查SQL**：
  ```sql
  SELECT euii.INVOICE_CODE, euii.INVOICE_NUMBER, euii.INVOICE_VERIFER_ID, euii.EFFECT_STATUS
  FROM EPM_UPLOAD_INVOICE_INFO euii
  WHERE euii.INVOICE_CODE = :invoiceCode
    AND euii.INVOICE_NUMBER = :invoiceNumber
    AND euii.INVOICE_VERIFER_ID <> :currentInvoiceVeriferId
    AND euii.EFFECT_STATUS = 'valid'
  -- 查出已被其它单核销的发票
  ```

### 常见问题

**Q1: OCR识别后发票信息不完整怎么办？**
A: 可能是发票影像模糊、格式不规范或OCR服务识别精度限制。处理方式：手工补充修正识别结果，或重新上传清晰影像。

**Q2: 导入发票明细后金额校验失败怎么办？**
A: 导入数据中金额字段格式错误或与发票总金额不一致。检查导入Excel中金额列格式，确保明细金额合计=发票总金额，且单价×数量=金额。

**Q3: 核销发票上传的编号如何生成？**
A: 工程使用编码规则AE.INVOICE_VERIFER_NO，家装使用AE.JZ_INVOICE_VERIFER_NO。凭证号码通过AE.INVOICE_CANCELLATION_UPLOAD生成。

**Q4: 家装和工程场景的区别？**
A: 家装(isHome=2)使用AE.JZ_INVOICE_VERIFER_NO编码规则+INVOICE_JZHXFPSC_AW工作流+homeExport导出接口，工程(isHome=1)使用AE.INVOICE_VERIFER_NO编码规则+INVOICE_WF_UPLOAD_AW工作流+export导出接口。

**Q5: 终止和撤回终止的作用？**
A: 终止(terminate)用于中止核销发票流程，handleType="disable"，终止后发票不可用。撤回终止(undoTerminate)用于恢复被误终止的发票，handleType="enable"。bizType区分：isHome=2为211116(家装)，否则210906(工程)。

**Q6: 审批通过后发票数据如何生效？**
A: wfComplete和onProcComplete中，审批非驳回时更新EPM_UPLOAD_INVOICE_INFO和EPM_UPLOAD_INVOICE_DETAILS的effectStatus="valid"，使发票可用于真实性核销关联。
