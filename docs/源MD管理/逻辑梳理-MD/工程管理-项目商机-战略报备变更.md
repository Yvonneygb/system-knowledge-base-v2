# 工程管理-项目商机-战略报备变更

> 本页面为低代码页面(hlod)和前端页面混合。工程战略报备变更列表页为hlod低代码页面，家装战略网点分配/变更有独立前端页面StrategicNetworkPoints。基于后端API和前端代码梳理。

## 业务流程

### 战略报备变更怎么流转

发起变更申请并推送OA审批，通过后同步更新授权与网点。

```
用户进入战略报备变更页面
  → 填写查询条件，调用变更列表接口（GET /epm-project-auth-ecns）
  → 新增变更：选择战略项目报备
    → 调用获取项目报备经销商授权接口（GET /get-report-auth）
    → 查看当前授权经销商列表和网点信息
  → 编辑变更经销商列表（新增/失效/恢复生效）
  → 保存变更（POST /save）或保存并提交（POST /save-and-submit）
  → 提交后触发工作流（STRATEGIC_REPORT_CHANGE_MAIN）
  → 推送OA审批（BillnameEnum.ZLBBBG="战略报备变更"）
  → 审批通过后：
    → 更新战略项目报备的经销商明细（新增/失效/恢复生效）
    → 记录变更前原经销商列表（EPM_PROJECT_AUTH_ECN_ORIGINAL）
```

### 全链路流程图

```
开始 → ★发起战略报备变更★ → ⚖OA审批通过？ → 同步更新项目/报备授权与网点 → 结束（拒绝则重提）

上游支撑：战略项目报备、OA审批系统、经销商主数据、值集配置
下游影响：项目/报备授权变更、报备网点变更、意向单校验
```

## 重点逻辑

### 重点逻辑1：变更类型区分（多场景共用）

- **业务意义**：同一套代码支撑工程战略变更、家装战略变更、家装网点分配变更、家装单体报备变更四种场景，通过变更类型字段(ecnType)区分
- **具体逻辑描述**：
  - ecnType=1或空时，为工程战略变更，附件对象类型为8070，审批通过后更新项目授权经销商和报备授权经销商
  - ecnType=2时，为家装战略变更，附件对象类型为9006，审批通过后仅更新报备授权经销商
  - ecnType=3时，为家装战略网点分配/变更，附件对象类型为9007，审批通过后更新报备网点信息
  - ecnType=4时，为家装单体报备变更，附件对象类型为9008，根据单体变更类型(changeType)区分变更附件(1)或变更网点(2)

### 重点逻辑2：审批通过后经销商/网点同步（核心逻辑）

- **业务意义**：审批通过后需将变更内容同步到正式的授权表，确保经销商和网点数据与变更一致
- **具体逻辑描述**：
  - 调整类型为"新增"(authEcnType=2)时，在项目授权表(EPM_PROJECT_AUTH)和报备授权表(EPM_REPORT_AUTH)中插入新记录（禁用标记disabled=1-未禁用）
  - 调整类型为"失效"(authEcnType=1)时，先校验该经销商是否存在已审核的意向单(SA_OUT_BILL_HEAD中PROJECT_INTENTION=2且HZ_APPROVE_STATUS=APPROVED)，若存在则报错阻断；校验通过后将禁用标记更新为2
  - 调整类型为"恢复生效"(authEcnType=3)时，将禁用标记更新为1
  - 家装网点变更(ecnType=3)场景下，在EPM_REPORT_AUTH_BRANCH表中新增/失效/恢复网点记录

### 重点逻辑3：OA审批推送与回调（外部集成）

- **业务意义**：变更单提交后推送OA审批，OA审批结果通过回调接口回写
- **具体逻辑描述**：
  - 工程战略变更推送OA单据名称为"战略报备变更"(BillnameEnum.ZLBBBG)
  - 家装战略变更推送"家装战略报备经销商变更"(BillnameEnum.EPMS_JZZLBBJXSBG)
  - 家装网点分配变更推送"家装战略网点分配/变更"(BillnameEnum.EPMS_JZZLWDFPBG)
  - OA回调时(doProcessOA)，若最终审批人标记为Y且结果为"同意"，则设置回调来源为OA_PASS；若结果非"同意"，则设置为OA_REJECT
  - 家装战略变更的OA回调(doProcessOAHomeStrategicChange)不判断最终审批人标记，直接根据审批结果设置回调来源
  - 回调后更新CALLBACK_SOURCE字段，等待条件扫描后触发后续业务逻辑

### 重点逻辑4：工作流审批回调

- **业务意义**：工作流审批通过后执行实际的授权同步逻辑
- **具体逻辑描述**：
  - 工作流编码：STRATEGIC_REPORT_CHANGE_MAIN（战略报备变更）
  - wfComplete判断审批结果为APPROVED时，根据ecnType分别调用：
    - ecnType=3：doUpdateProjectBranchAuth（家装网点变更）
    - ecnType=4：doProjectAuth（家装单体报备变更）
    - 其他：doUpdateProjectAuth（战略项目报备变更）

### 重点逻辑5：变更前留档

- **业务意义**：记录变更前的原经销商列表，便于追溯和回查
- **具体逻辑描述**：
  - 保存时将变更前的经销商列表写入EPM_PROJECT_AUTH_ECN_ORIGINAL表
  - 包含经销商ID、编码、名称、是否失效状态
  - 编辑已有变更单时，先删除旧的原经销商记录再重新插入

### 重点逻辑6：家装单体报备变更

- **业务意义**：支持家装单体报备的附件变更和网点变更两种子类型
- **具体逻辑描述**：
  - changeType=1时为变更附件：将变更单的附件复制关联到报备单(attachConfId=9004)
  - changeType=2时为变更网点：调用doUpdateProjectBranchAuth更新网点信息

### save保存逻辑

1. 校验reportAuthBranchEcnList非空，为空时抛出"请至少维护一行网点调整"
2. 若projectAuthEcnId为空（新建）：
   - 生成变更单号（编码规则AE.PROJECT_AUTH_ECN_CODE）
   - 插入EPM_PROJECT_AUTH_ECN主表
   - 批量插入原经销商列表(EPM_PROJECT_AUTH_ECN_ORIGINAL)
   - 批量插入网点调整列表(EPM_REPORT_AUTH_BRANCH_ECN)
   - 批量插入附件(EPM_PROJECT_ATTACH)
3. 若projectAuthEcnId不为空（编辑）：
   - 更新主表
   - 删除旧原经销商列表后重新插入
   - 删除旧网点调整列表后重新插入
   - 删除旧附件后重新插入

### saveAndSubmit保存并提交逻辑

1. 调用save保存变更数据
2. 构建WorkFlowDTO，设置flowCode、businessKey、businessId
3. 调用workFlowStart启动工作流

### wfComplete审批通过回调逻辑

```
wfComplete(dto) → 判断审批结果 == APPROVED → 根据ecnType分支：
  ecnType=3 → doUpdateProjectBranchAuth（家装网点变更）
  ecnType=4 → doProjectAuth（家装单体报备变更）
  其他 → doUpdateProjectAuth（战略项目报备变更）
```

### doUpdateProjectAuth战略项目报备变更逻辑

1. 查询变更明细行(EPM_PROJECT_AUTH_ECN_LINE)
2. 查询客户组织信息(CustomerOrg)
3. 获取reportId：ecnType=2时从项目带出，其他时查询AUDIT_STAT="二次报备通过"的报备
4. 查询已审核意向单(SA_OUT_BILL_HEAD中PROJECT_INTENTION=2且HZ_APPROVE_STATUS=APPROVED)
5. 查询项目授权(EPM_PROJECT_AUTH)和报备授权(EPM_REPORT_AUTH)
6. 遍历变更明细行：
   - authEcnType=2(新增)：插入项目授权和报备授权记录(disabled=1)
   - authEcnType=1(失效)：校验意向单，通过后更新disabled=2
   - authEcnType=3(恢复生效)：更新disabled=1
7. 批量插入和更新项目授权、报备授权

### 保存校验

- 校验1：网点调整至少一行 —— 确保变更单有实际调整内容
  - **详细逻辑**：保存时校验reportAuthBranchEcnList不能为空
  - **系统体现**：阻断性报错，提示"请至少维护一行网点调整"
  - **排查SQL**：`SELECT COUNT(*) FROM EPM_REPORT_AUTH_BRANCH_ECN WHERE PROJECT_AUTH_ECN_ID = #{变更单ID};`

- 校验2：项目ID不能为空 —— 确保关联了有效的战略项目
  - **详细逻辑**：获取报备授权时校验projectId不能为空
  - **系统体现**：阻断性报错，提示"项目ID不能为空!"
  - **排查SQL**：`SELECT * FROM EPM_PROJECT_AUTH_ECN WHERE PROJECT_AUTH_ECN_ID = #{变更单ID} AND PROJECT_ID IS NULL;`

- 校验3：主键不能为空 —— 查看详情时校验
  - **详细逻辑**：detail接口校验projectAuthEcnId非空
  - **系统体现**：阻断性报错，提示"主键不能为空!"
  - **排查SQL**：`SELECT * FROM EPM_PROJECT_AUTH_ECN WHERE PROJECT_AUTH_ECN_ID IS NULL;`

### 提交校验

- 校验1：失效经销商存在已审核意向单时阻断 —— 防止有业务往来的经销商被误失效
  - **详细逻辑**：审批通过后执行doUpdateProjectAuth时，若调整类型为失效(authEcnType=1)且该经销商存在项目意向=2且审批状态=APPROVED的意向单，则报错
  - **系统体现**：阻断性报错，提示"失效经销商存在有意向单，失效失败！"
  - **排查SQL**：
    ```sql
    SELECT s.* FROM SA_OUT_BILL_HEAD s
    INNER JOIN EPM_PROJECT_AUTH_ECN_LINE l ON s.CUSTOMER_ID = l.CUSTOMER_ID
    WHERE l.PROJECT_AUTH_ECN_ID = #{变更单ID}
    AND l.AUTH_ECN_TYPE = 1
    AND s.PROJECT_INTENTION = 2
    AND s.HZ_APPROVE_STATUS = 'APPROVED';
    ```

- 校验2：OA回传单号校验 —— OA回调时校验变更单存在
  - **详细逻辑**：doProcessOA/doProcessOAHomeStrategicChange中根据ID查询变更单，不存在时报错
  - **系统体现**：阻断性报错，提示"OA回传单号不存在，请检查！"
  - **排查SQL**：`SELECT * FROM EPM_PROJECT_AUTH_ECN WHERE PROJECT_AUTH_ECN_ID = #{OA回传ID};`

- 校验3：工作流提交 —— 保存并提交走工作流审批
  - **详细逻辑**：调用saveAndSubmit接口，先保存数据再启动工作流STRATEGIC_REPORT_CHANGE_MAIN
  - **系统体现**：工作流编码STRATEGIC_REPORT_CHANGE_MAIN
  - **排查SQL**：`SELECT PROJECT_AUTH_ECN_ID, PROJECT_AUTH_ECN_CODE, HZ_APPROVE_STATUS, HZ_INSTANCE_ID FROM EPM_PROJECT_AUTH_ECN WHERE PROJECT_AUTH_ECN_ID = #{变更单ID};`

### 状态机

```text
NEW(新建) ──→ 保存 ──→ NEW(新建)
  │
  └──→ 保存并提交 ──→ RUN(审批中) ──→ OA审批
                                            │
                                    ┌───────┴───────┐
                                    ▼               ▼
                              APPROVED(审批通过)  REJECTED(审批拒绝)
                                    │               │
                                    ▼               ▼
                            更新经销商/网点      可重新提交
                                    │
                                    ▼
                              REBUT(已驳回) ──→ 可重新编辑提交
```

| 状态 | 状态释义 | 可执行的操作 |
|------|---------|------------|
| NEW | 新建 | 保存、保存并提交 |
| RUN | 审批中 | 等待OA审批结果回调 |
| APPROVED | 审批通过 | 查看（不可编辑） |
| REJECTED | 审批拒绝 | 重新编辑、保存并提交 |
| REBUT | 已驳回 | 重新编辑、保存并提交 |
| WITHDRAW | 已撤回 | 重新编辑、保存并提交 |
| INTERRUPT | 终止 | 查看（不可编辑） |

#### 报错1：请至少维护一行网点调整
- **触发条件**：保存战略报备变更单时，网点调整明细行(reportAuthBranchEcnList)为空或未填写
- **逻辑分析**：save方法中校验reportAuthBranchEcnList非空，因变更单必须包含至少一条网点调整数据(新增/失效/恢复)。该报错为阻断性报错
- **排查SQL**：
  ```sql
  SELECT epae.PROJECT_AUTH_ECN_ID, epae.PROJECT_AUTH_ECN_CODE, epae.HZ_APPROVE_STATUS,
         (SELECT COUNT(*) FROM EPM_REPORT_AUTH_BRANCH_ECN rab
          WHERE rab.PROJECT_AUTH_ECN_ID = epae.PROJECT_AUTH_ECN_ID) AS 网点调整行数
  FROM EPM_PROJECT_AUTH_ECN epae
  WHERE epae.PROJECT_AUTH_ECN_ID = :projectAuthEcnId
  -- 若网点调整行数为0，则触发该报错
  ```

#### 报错2：项目ID不能为空!
- **触发条件**：获取报备授权(getReportAuth)时，未选择战略项目(projectId为空)
- **逻辑分析**：getReportAuth方法中校验projectId非空，因报备授权数据需按项目ID关联EPM_REPORT_AUTH查询。需先选择战略家装编码带出项目ID
- **排查SQL**：
  ```sql
  SELECT ep.PROJECT_ID, ep.PROJECT_CODE, ep.PROJECT_NAME, ep.REPORT_ID
  FROM EPM_PROJECT ep
  WHERE ep.PROJECT_ID = :projectId
  -- 若返回空，说明项目ID不存在或未选择
  ```

#### 报错3：主键不能为空!
- **触发条件**：查看战略报备变更单详情(detail方法)时，未传入变更单主键ID(projectAuthEcnId为空)
- **逻辑分析**：detail方法中校验projectAuthEcnId非空，因详情查询需按主键关联EPM_PROJECT_AUTH_ECN及子表。该报错为阻断性报错
- **排查SQL**：
  ```sql
  SELECT epae.PROJECT_AUTH_ECN_ID, epae.PROJECT_AUTH_ECN_CODE, epae.HZ_APPROVE_STATUS
  FROM EPM_PROJECT_AUTH_ECN epae
  WHERE epae.PROJECT_AUTH_ECN_ID = :projectAuthEcnId
  -- 校验传入的主键ID是否存在
  ```

#### 报错4：OA回传单号不存在，请检查！
- **触发条件**：OA审批回调(doProcessOA)时，根据传入ID查询EPM_PROJECT_AUTH_ECN变更单记录返回null
- **逻辑分析**：doProcessOA中selectByPrimaryKey按PROJECT_AUTH_ECN_ID查询，若返回null则抛出阻断性报错。可能原因：数据被删除、OA传递的ID错误、ID类型转换异常
- **排查SQL**：
  ```sql
  SELECT epae.PROJECT_AUTH_ECN_ID, epae.PROJECT_AUTH_ECN_CODE, epae.HZ_APPROVE_STATUS,
         epae.CALLBACK_SOURCE, epae.VALID
  FROM EPM_PROJECT_AUTH_ECN epae
  WHERE epae.PROJECT_AUTH_ECN_ID = :oaCallbackId
  -- 若返回空，说明OA回传的ID在系统中不存在
  ```

#### 报错5：失效经销商存在有意向单，失效失败！
- **触发条件**：审批通过后doUpdateProjectAuth方法中，失效的经销商(CUSTOMER_ID)存在已审核的意向单(SA_OUT_BILL_HEAD)
- **逻辑分析**：doUpdateProjectAuth中按失效经销商的CUSTOMER_ID批量查询SA_OUT_BILL_HEAD意向单，若saOutBillHeadMap包含该customerId则说明存在已审核意向单，不允许失效该经销商，抛出阻断性报错
- **排查SQL**：
  ```sql
  SELECT obh.SA_OUT_BILL_HEAD_ID, obh.SA_SALEBILLNO, obh.CUSTOMER_ID, obh.CUSTOMER_CODE,
         obh.ORDER_STAT, obh.HZ_APPROVE_STATUS
  FROM SA_OUT_BILL_HEAD obh
  WHERE obh.CUSTOMER_ID IN (:disabledCustomerIdList)
    AND obh.ORDER_STAT IN ('已审核', '审核通过')
  -- 查出失效经销商下已审核的意向单
  ```

#### 报错6：NullPointerException: epmProject
- **触发条件**：获取报备授权(getReportAuth)时，projectId在EPM_PROJECT表中不存在，后续调用epmProject.getReportId()抛出NullPointerException
- **逻辑分析**：getReportAuth方法中epmProjectRepository.selectByPrimaryKey(projectId)按PROJECT_ID查询项目档案，若项目被删除或projectId指向不存在的项目，则返回null。需检查项目档案是否存在且有效
- **排查SQL**：
  ```sql
  SELECT ep.PROJECT_ID, ep.PROJECT_CODE, ep.PROJECT_NAME, ep.REPORT_ID,
         ep.HZ_APPROVE_STATUS, ep.PROJECT_VALID
  FROM EPM_PROJECT ep
  WHERE ep.PROJECT_ID = :projectId
  -- 若返回空，说明项目档案不存在
  ```

#### 报错7：NullPointerException: epmProjectAuthEcn
- **触发条件**：查看战略报备变更单详情(detail方法)时，projectAuthEcnId在EPM_PROJECT_AUTH_ECN表中不存在，后续调用epmProjectAuthEcn.getProjectId()抛出NullPointerException
- **逻辑分析**：detail方法中selectByPrimaryKey按PROJECT_AUTH_ECN_ID查询变更单，若变更单被物理删除或ID传递错误，则返回null。需检查变更单数据是否完整
- **排查SQL**：
  ```sql
  SELECT epae.PROJECT_AUTH_ECN_ID, epae.PROJECT_AUTH_ECN_CODE, epae.PROJECT_ID,
         epae.HZ_APPROVE_STATUS, epae.ECN_TYPE
  FROM EPM_PROJECT_AUTH_ECN epae
  WHERE epae.PROJECT_AUTH_ECN_ID = :projectAuthEcnId
  -- 若返回空，说明变更单不存在
  ```

#### 报错8：变更原因不能为空
- **触发条件**：保存战略报备变更单时，REASON(变更原因)字段为空
- **逻辑分析**：低代码表单对REASON字段配置必填校验，为空时阻断保存。变更原因为申请变更的说明性字段，必须填写。需填写变更原因后重新保存
- **排查SQL**：
  ```sql
  SELECT epae.PROJECT_AUTH_ECN_ID, epae.PROJECT_AUTH_ECN_CODE, epae.REASON,
         epae.HZ_APPROVE_STATUS
  FROM EPM_PROJECT_AUTH_ECN epae
  WHERE epae.PROJECT_AUTH_ECN_ID = :projectAuthEcnId
    AND (epae.REASON IS NULL OR TRIM(epae.REASON) = '')
  -- 查出变更原因为空的变更单
  ```

## 常见问题FAQ

### Q1: 战略报备变更变更的是什么内容？

变更的是战略项目报备关联的经销商列表和网点信息，支持新增经销商、失效已有经销商和恢复生效经销商三种操作。

### Q2: 变更前的经销商信息是否会保留？

是的，变更前的原经销商列表会记录到EPM_PROJECT_AUTH_ECN_ORIGINAL表中进行留档。

### Q3: 变更审批通过后如何处理？

根据变更内容更新EPM_REPORT_AUTH和EPM_PROJECT_AUTH表：新增的经销商插入授权记录，失效的经销商更新状态为失效(disabled=2)，恢复生效的经销商更新状态为未禁用(disabled=1)。

### Q4: 变更单保存后经销商列表为空？

**可能原因**: 选择战略家装编码后未触发handleBeforeSelect回调，导致报备授权数据未加载。

**排查SQL:**
```sql
SELECT * FROM EPM_REPORT_AUTH WHERE REPORT_ID = (SELECT REPORT_ID FROM EPM_PROJECT WHERE PROJECT_ID = #{项目ID});
```

### Q5: OA审批通过后经销商状态未更新？

**可能原因**: OA回调未成功写入CALLBACK_SOURCE字段，或等待条件扫描未触发。

**排查SQL:**
```sql
SELECT PROJECT_AUTH_ECN_ID, HZ_APPROVE_STATUS, CALLBACK_SOURCE FROM EPM_PROJECT_AUTH_ECN WHERE PROJECT_AUTH_ECN_ID = #{变更单ID};
```

### Q6: 家装战略变更OA推送失败？

**可能原因**: OA_BILL_REF表中缺少对应单据名称配置。

**排查SQL:**
```sql
SELECT * FROM OA_BILL_REF WHERE BILL_NAME IN ('战略报备变更', '家装战略报备经销商变更', '家装战略网点分配/变更');
```
