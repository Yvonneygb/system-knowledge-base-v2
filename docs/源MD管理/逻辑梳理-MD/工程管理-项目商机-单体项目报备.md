# 工程管理-项目商机-单体项目报备

> 本页面为低代码页面(hlod)，无独立前端源码，基于后端API梳理。后端Controller为ReportController（API: `/v1/{organizationId}/report/`）和EpmReportController（API: `/v1/{organizationId}/epm-reports`），ServiceImpl为EpmReportServiceImpl（3093行）。核心表为EPM_REPORT（报备表）和EPM_PROJECT（项目信息表）。报备类型reportType=1为单体报备，工作流编码PROJECT_DTBB_MAIN。

## 业务流程

```
用户进入单体项目报备列表页面
  → 填写查询条件，调用报备列表接口（POST /report/getReportList）
  → 新增报备：填写项目基本信息（项目编码、项目名称、客户、区域等）
  → 保存前数据处理：
    → 关联战略项目清理（非战略工程时清空关联）
    → 经纬度必填校验（不能为空且不能为0）
    → 收货人校验（含运费经销商+REPORT ADD FLAG开启时）
  → 保存报备数据（EPM_REPORT表，reportType=1）
  → 保存经销商授权信息（EPM_REPORT_AUTH表）
  → 提交审批前校验（workFlowStartVolidate）：
    → 查重拦截校验（ES相似度查重）
    → 可报备数量校验
    → 申诉次数校验
  → 提交审批，触发工作流（PROJECT_DTBB_MAIN）
  → OA审批推送（根据EPM_OA_BILL_REF找OA表单ID）
  → 审批通过后回调wfComplete：
    → 同步到项目表（EPM_PROJECT）
    → 推送CRM报备信息（indivireportAdd接口）
    → 推送CRM地址
    → 推送ES索引
  → 审批驳回：审核状态回退为"新建"，查重标记重置为N，删除ES数据
```

## 重点逻辑

### 重点逻辑1：报备类型区分

- **业务意义**：系统支持4种报备类型共用后端代码，通过reportType区分业务逻辑
- **具体逻辑描述**：
  - 1、单体报备reportType=1，战略报备reportType=2，家装战略reportType=3，家装单体reportType=4
  - 2、本菜单为工程单体报备，列表查询固定传参reportType=1
  - 3、不同报备类型走不同工作流编码，单体报备使用PROJECT_DTBB_MAIN

### 重点逻辑2：保存前数据处理

- **业务意义**：确保报备数据完整性和一致性，防止无效数据保存
- **具体逻辑描述**：
  - 1、关联战略项目清理：单体报备但工程类型不是"战略工程"时，自动清除关联的战略项目信息
  - 2、经纬度必填校验：工程单体报备保存时，经纬度不能为空且不能为0，精度取小数点后7位
  - 3、收货人校验：系统参数"REPORT ADD FLAG"开启且经销商为含运费时，收货人和收货人电话必填
  - 4、交易公司ID必须大于0

### 重点逻辑3：提交流程校验（查重拦截）

- **业务意义**：防止同城相似项目重复报备，避免撞单
- **具体逻辑描述**：
  - 1、查重开关判断：根据当前组织是否配置查重校验值集(AE.REPEAT_REPORT_VERIFY_ORG)决定是否开启查重
  - 2、白名单跳过：项目名称包含查重关键字白名单内容时，跳过查重拦截
  - 3、可报备数量校验：检查经销商可报备次数额度(EPM_REPORT_QUANTITY_CONFIG)，包括有效额度和临时额度
  - 4、ES相似度查重：同城范围内通过ES搜索相似项目，相似度范围由系统参数ReportSimilarLower/ReportSimilarUpper控制
  - 5、查重拦截结果：存在相似项目则返回"项目冲突，不予报备"，标记DUPLICATE_REPORTING=Y
  - 6、申诉提交：被查重拦截后可通过申诉重新提交，申诉有次数限制(EPM_REPORT_APPEAL_CONFIG)

### 重点逻辑4：OA审批推送

- **业务意义**：报备审批通过OA系统执行，实现审批流程标准化
- **具体逻辑描述**：
  - 1、提交审批时，根据OA单据关系表(EPM_OA_BILL_REF)找到"单体项目报备"对应的OA表单ID
  - 2、将报备信息（项目编码、客户、地址、产品线、乙方信息等）组装后推送到OA
  - 3、乙方信息作为OA重复表行数据推送

### 重点逻辑5：审批通过后处理

- **业务意义**：审批通过后同步生成正式项目，驱动后续合同和折扣业务
- **具体逻辑描述**：
  - 1、同步到项目表：doSendMonomerProject方法将报备数据复制到EPM_PROJECT表（排除查重标记、ES推送状态等字段）
  - 2、推送CRM报备信息：调用EBS接口(indivireportAdd)推送经销商编码、名称、事业部、报备号、项目名称、有效状态到CRM
  - 3、推送CRM地址：推送报备工程的收货地址到CRM，异常不影响主流程
  - 4、推送ES：将报备数据索引到ES(IDX_EPM_REPORT)，便于后续查重

### 重点逻辑6：审批驳回后处理

- **业务意义**：审批驳回后恢复报备到可编辑状态，允许修改后重新提交
- **具体逻辑描述**：
  - 1、审核状态回退为"新建"
  - 2、报备时间清空
  - 3、查重拦截标记重置为N（中断后提交需重新走查重拦截）
  - 4、删除ES中的数据

### 重点逻辑7：二次报备

- **业务意义**：同一项目支持二次报备，适应项目信息变更场景
- **具体逻辑描述**：
  - 1、同一项目编码支持二次报备，报备次数reportTimes=2
  - 2、已二次报备且审批通过的项目不允许再次报备
  - 3、已二次报备但流程未完成的项目提示"尚未启动流程"

### 重点逻辑8：报备有效期与冻结

- **业务意义**：报备有有效期限制，超期未产生合同则冻结，防止长期占用商机
- **具体逻辑描述**：
  - 1、报备审批通过后设定有效期，超过有效周期未产生合同则项目冻结
  - 2、冻结后可申请解冻（流程编码ENGINEERING_REPORT_JDSQ_MAIN）
  - 3、小型项目报备校验三个月内是否存在有效合同，不存在则失效报备

### 选择弹窗

#### 弹窗1：经销商选择弹窗

- **触发位置**：报备详情页"经销商"字段LOV点击
- **数据来源**：LOV: AE.FIND_CUSTOMER
- **查询SQL**：`SELECT CUSTOMER_ID, CUSTOMER_CODE, CUSTOMER_NAME, SHORT_NAME FROM CUSTOMER WHERE ENABLED_FLAG = 1`

#### 弹窗2：关联战略项目选择弹窗

- **触发位置**：报备详情页"关联战略项目"字段LOV点击
- **数据范围**：已审批通过的战略报备项目
- **查询SQL**：`SELECT PROJECT_ID, PROJECT_CODE, PROJECT_NAME FROM EPM_PROJECT WHERE REPORT_TYPE = 2 AND HZ_APPROVE_STATUS = 'APPROVED' AND PROJECT_VALID = 4`

#### 弹窗3：交易公司选择弹窗

- **触发位置**：报备详情页"交易公司"字段LOV点击
- **数据范围**：事业部关联的交易公司
- **查询SQL**：`SELECT ETC.TRADING_COMPANY_ID, ETC.TRADING_COMPANY_NAME FROM EPM_TRADING_COMPANY ETC INNER JOIN EPM_DIVISION_TRADING_REL DTR ON ETC.TRADING_COMPANY_ID = DTR.TRADING_COMPANY_ID WHERE DTR.DIVISION_ID = :divisionId`

### 保存校验

- 校验1：经纬度必填 —— 工程单体报备经纬度不能为空
  - **详细逻辑**：reportType=1时，latitude和longitude不能为空
  - **系统体现**：toast提醒"经纬度不能为空"
  - **排查SQL**：`SELECT REPORT_ID, PROJECT_CODE FROM EPM_REPORT WHERE REPORT_TYPE = 1 AND (LATITUDE IS NULL OR LONGITUDE IS NULL)`

- 校验2：经纬度不为0 —— 经纬度值不能为0
  - **详细逻辑**：latitude和longitude不能为0
  - **系统体现**：toast提醒"项目地址经纬度异常，经纬度为0，请重新维护工程所在地信息"
  - **排查SQL**：`SELECT REPORT_ID, PROJECT_CODE FROM EPM_REPORT WHERE REPORT_TYPE = 1 AND (LATITUDE = 0 OR LONGITUDE = 0)`

- 校验3：收货人必填 —— 含运费经销商收货人校验
  - **详细逻辑**：系统参数"REPORT ADD FLAG"开启且经销商INCLUDE_FREIGHT_FLAG=Y时，takeMan和phoneCode必填
  - **系统体现**：toast提醒"收货人不能为空"/"收货人号码不能为空"
  - **排查SQL**：`SELECT R.REPORT_ID FROM EPM_REPORT R JOIN CUSTOMER_ORG CO ON CO.CUSTOMER_ID = R.CUSTOMER_ID WHERE CO.INCLUDE_FREIGHT_FLAG = 'Y' AND (R.TAKE_MAN IS NULL OR R.PHONE_CODE IS NULL)`

- 校验4：交易公司ID合法 —— 交易公司ID必须大于0
  - **详细逻辑**：tradingCompanyId必须>0
  - **系统体现**：toast提醒"交易公司id必须大于0"
  - **排查SQL**：`SELECT REPORT_ID FROM EPM_REPORT WHERE TRADING_COMPANY_ID <= 0`

- 校验5：非战略工程时清空关联 —— 单体报备非战略工程类型时清除关联战略项目
  - **详细逻辑**：reportType=1且projectSource!='2'时，自动清空relProjectId/relProjectCode/relProjectName
  - **系统体现**：保存时自动处理

### 提交校验

- 校验1：查重拦截标记 —— 标记为Y时禁止直接提交
  - **详细逻辑**：DUPLICATE_REPORTING=Y时需走申诉流程
  - **系统体现**：toast提醒"请通过申诉提交"
  - **排查SQL**：`SELECT REPORT_ID FROM EPM_REPORT WHERE DUPLICATE_REPORTING = 'Y' AND REPORT_ID = :reportId`

- 校验2：查重开关 —— 组织是否配置查重校验
  - **详细逻辑**：查询值集AE.REPEAT_REPORT_VERIFY_ORG是否包含当前组织ID
  - **排查SQL**：`SELECT * FROM HPF_LOV_VALUE WHERE LOV_ID = (SELECT LOV_ID FROM HPF_LOV WHERE LOV_CODE = 'AE.REPEAT_REPORT_VERIFY_ORG') AND VALUE = :organizationId`

- 校验3：可报备数量 —— 经销商有效报备额度校验
  - **详细逻辑**：检查EPM_REPORT_QUANTITY_CONFIG中经销商的maxQty和临时额度
  - **排查SQL**：`SELECT RQC.CUSTOMER_ID, RQC.MAX_QTY, RQC.TMP_EXTRA_QTY, RQC.TMP_START_DATE, RQC.TMP_END_DATE FROM EPM_REPORT_QUANTITY_CONFIG RQC WHERE RQC.CUSTOMER_ID = :customerId`

- 校验4：申诉次数 —— 经销商当月申诉次数校验
  - **详细逻辑**：检查EPM_REPORT_APPEAL_CONFIG中经销商当月申诉次数
  - **排查SQL**：`SELECT RAC.CUSTOMER_ID, RAC.APPEAL_NUM, RAC.APPEAL_NUM_TMP FROM EPM_REPORT_APPEAL_CONFIG RAC WHERE RAC.CUSTOMER_ID = :customerId AND RAC.APPEAL_YEAR = :year AND RAC.APPEAL_MONTH = :month`

- 校验5：ES相似度查重 —— 同城同地址相似项目匹配
  - **详细逻辑**：通过ES索引IDX_EPM_REPORT查询同城相似项目，相似度范围由系统参数ReportSimilarLower/ReportSimilarUpper控制
  - **系统体现**：toast提醒"项目冲突，不予报备"

- 校验6：OA单据关系 —— 必须维护EPMS与OA表单对应关系
  - **详细逻辑**：查询EPM_OA_BILL_REF中"单体项目报备"对应的OA表单ID
  - **系统体现**：toast提醒"请先维护EPMS单据和OA表单对应关系表"

#### 报错1：经纬度不能为空
- **触发条件**：保存工程单体报备时，LATITUDE或LONGITUDE字段为空
- **逻辑分析**：保存校验中检查工程单体报备(REPORT_TYPE=1)的经纬度必填，因工程报备需定位项目所在地。该报错为toast提醒级别
- **排查SQL**：
  ```sql
  SELECT er.REPORT_ID, er.REPORT_CODE, er.PROJECT_CODE, er.LATITUDE, er.LONGITUDE, er.ADDRESS
  FROM EPM_REPORT er
  WHERE er.REPORT_TYPE = 1
    AND (er.LATITUDE IS NULL OR er.LONGITUDE IS NULL)
  -- 查出经纬度为空的工程单体报备
  ```

  ```sql
  -- 若返回空，则需维护交易公司主数据
  ```

#### 报错33：请先配置系统参数-经销商可报备数量:ReportCustomerApplyNum
- **触发条件**：新建报备时，SYS_PARAM未配置PARAM_CODE='ReportCustomerApplyNum'
- **逻辑分析**：在新建报备校验方法中查询SYS_PARAM表，若未配置经销商可报备数量则报错。需在SYS_PARAM中配置参数ReportCustomerApplyNum
- **排查SQL**：
  ```sql
  SELECT sp.PARAM_ID, sp.PARAM_CODE, sp.PARAM_NAME, sp.VALUE, sp.ORGANIZATION_ID
  FROM SYS_PARAM sp
  WHERE sp.PARAM_CODE = 'ReportCustomerApplyNum'
    AND sp.ORGANIZATION_ID = :orgId
  -- 若返回空，则需在SYS_PARAM表中补充配置
  ```

#### 报错34：经销商可报备数量剩余xxx条
- **触发条件**：新建报备时，经销商当月已用报备数量达到配置上限
- **逻辑分析**：在校验方法中按customerCode统计当月已报备数量，与SYS_PARAM配置的ReportCustomerApplyNum对比，若已达上限则报错。报错信息中显示剩余可报备数量
- **排查SQL**：
  ```sql
  SELECT sp.VALUE AS 配置可报备数量,
         (SELECT COUNT(*) FROM EPM_REPORT er
          WHERE er.CUSTOMER_CODE = :customerCode
            AND er.REPORT_TYPE = 1
            AND EXTRACT(MONTH FROM er.CREATION_DATE) = EXTRACT(MONTH FROM SYSDATE)
            AND EXTRACT(YEAR FROM er.CREATION_DATE) = EXTRACT(YEAR FROM SYSDATE)) AS 当月已报备数量
  FROM SYS_PARAM sp
  WHERE sp.PARAM_CODE = 'ReportCustomerApplyNum'
    AND sp.ORGANIZATION_ID = :orgId
  ```


## 常见问题FAQ

**Q1: 提交报备提示"项目冲突"怎么办？**
A: 同城存在相似项目被查重拦截。确认是否为不同项目：若是则走申诉流程（注意申诉次数受EPM_REPORT_APPEAL_CONFIG限制）；若否则修改项目信息后重新提交。排查SQL：通过ES索引IDX_EPM_REPORT查询同城相似项目。

**Q2: 报备审批通过但CRM未收到推送？**
A: 推送CRM接口异常但不影响主流程。查看日志中"推送单体报备到crm异常"或"单体报备审核通过后地址推送CRM异常"。报备数据已审批通过，CRM数据可后续手动补推。

**Q3: ES查询模式无数据？**
A: ES索引数据未同步。检查ES_PUSH_STATUS字段，手动触发推送ES接口：`GET /v1/{orgId}/report/report-to-es`。排查SQL：`SELECT REPORT_ID, ES_PUSH_STATUS FROM EPM_REPORT WHERE REPORT_TYPE = 1 AND HZ_APPROVE_STATUS = 'APPROVED'`

**Q4: 二次报备提示已存在？**
A: 同一项目编码已有二次报备记录。排查SQL：`SELECT * FROM EPM_REPORT WHERE PROJECT_CODE = :code AND REPORT_TIMES = 2`。若已审批通过则不可再次报备；若流程未完成则提示"尚未启动流程"。

**Q5: 经纬度保存报错？**
A: 工程单体报备经纬度必填且不能为0。确保项目地址已标注经纬度，可通过箭牌标注或地图选点获取。排查SQL：`SELECT REPORT_ID, LATITUDE, LONGITUDE FROM EPM_REPORT WHERE REPORT_TYPE = 1 AND (LATITUDE IS NULL OR LONGITUDE IS NULL OR LATITUDE = 0 OR LONGITUDE = 0)`

**Q6: 查重拦截后无法提交？**
A: 查重标记DUPLICATE_REPORTING=Y时需走申诉流程。通过申诉功能提交，注意申诉次数受EPM_REPORT_APPEAL_CONFIG配置限制。排查SQL：`SELECT RAC.APPEAL_NUM, RAC.APPEAL_NUM_TMP FROM EPM_REPORT_APPEAL_CONFIG RAC WHERE RAC.CUSTOMER_ID = :customerId AND RAC.APPEAL_YEAR = :year AND RAC.APPEAL_MONTH = :month`

**Q7: 报备审批通过后项目表未同步？**
A: 审批回调wfComplete异常。检查HZ_APPROVE_STATUS和CALLBACK_SOURCE字段，确认OA回调是否正常。排查SQL：`SELECT REPORT_ID, HZ_APPROVE_STATUS, CALLBACK_SOURCE FROM EPM_REPORT WHERE REPORT_ID = :reportId`。处理：确认EPM_PROJECT表中是否有对应记录，手动触发doSendMonomerProject。

**Q8: 报备数据删除后关联数据残留？**
A: 批量删除级联关系复杂。确认删除逻辑覆盖：折扣申请→合同→项目阶段→项目信息→工作流任务→报备主表。排查SQL：`SELECT * FROM EPM_PROJECT WHERE REPORT_ID = :deletedReportId`
