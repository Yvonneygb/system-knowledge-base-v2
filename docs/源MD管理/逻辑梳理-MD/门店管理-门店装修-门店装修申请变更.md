# 门店管理-门店装修-门店装修申请变更

## 业务流程

```
门店装修申请变更列表页(hlod低代码页面)
        │
        ├── 新增 ──→ 选择装修申请单(LOV,仅APPROVED状态) ──→ 联动带出门店/经销商/装修信息
        │              ──→ 填写变更信息(变更后面积/标准/金额等) ──→ 保存
        │                                    │
        │                                    ▼
        │                              生成变更单号 ──→ HZ_APPROVE_STATUS=NEW
        │                              原申请单标记IS_MODIFY=2(变更中)
        │                                    │
        │                                    ▼
        │                              提交审批 ──→ 校验预算年度 ──→ 启动OA工作流(SUB_STORE_DECORATION_CHANGE)
        │                                    │
        │                                    ▼
        │                              OA审批流程中(多节点:经销商上传照片/设计师提交方案/设计经理审批等)
        │                                    │
        │                         ├──审批通过──→ HZ_APPROVE_STATUS=APPROVED
        │                         │              ├─ 计算超期天数/扣减比例
        │                         │              └─ 回写原申请单(changeValue)
        │                         │
        │                         ├──审批驳回──→ HZ_APPROVE_STATUS=REJECTED
        │                         │
        │                         └──退回──→ HZ_APPROVE_STATUS=REBUT
        │
        ├── 作废 ──→ 变更单INTERRUPT ──→ 原申请单IS_MODIFY=3(变更作废)
        │
        └── 删除 ──→ 仅NEW状态 ──→ 恢复原申请单IS_MODIFY=0
```

## 重点逻辑

### 重点逻辑1：变更回写原申请单

- **业务意义**：变更审批通过后将变更后的标准/金额回写原装修申请单，保证前后信息一致
- **具体逻辑描述**：
  - 审批通过后调用finFeeApplyFinishedHeader.changeValue(dbFinFeeApplyChangeHeader)
  - 回写字段包括：装修面积/标准/金额/设计师/装修周期/超期天数/扣减比例等
  - 原申请单标记isModify=1(已变更)

### 重点逻辑2：变更状态互斥

- **业务意义**：通过原申请单isModify字段控制变更/关闭/提交的互斥关系
- **具体逻辑描述**：
  - 新增变更：原申请单isModify=2(变更中)
  - 删除变更：原申请单isModify=0(恢复正常)
  - 作废变更：原申请单isModify=3(变更作废)
  - 原申请单提交时校验isModify≠2，防止"单据正在申请变更中，不可提交"

### 重点逻辑3：超期扣减计算

- **业务意义**：变更审批通过时重新计算超期天数和扣减比例
- **具体逻辑描述**：
  - 装修间隔期至 = 装修完成时间 + Waiting_Days - Advance_Permissible_Period
  - 超期天数 = (装修完成时间 - 交付设计时间) - 装修周期
  - 扣减比例 = 超期天数 × Deduct_Pro / 100（封顶100%）

### 保存校验

- 校验1：装修申请单号必填 —— 确保关联有效的装修申请
  - **详细逻辑**：前端DataSet字段terminalApplyNoLov required=true
  - **系统体现**：C7N内置必填校验
  - **排查SQL**：`SELECT TERMINAL_CHANGE_ID FROM FIN_FEE_APPLY_CHANGE_HEADER WHERE TERMINAL_APPLY_ID IS NULL`

- 校验2：原申请单存在 —— 确保关联的装修申请单有效
  - **详细逻辑**：doInsert时查询FinFeeApplyFinishedHeader，null则抛异常
  - **系统体现**：后端抛异常"未获取到门店申请信息"
  - **排查SQL**：`SELECT * FROM FIN_FEE_APPLY_FINISHED_HEADER WHERE TERMINAL_APPLY_ID={id}`

- 校验3：装修周期≤公司参数 —— 控制装修时效上限
  - **详细逻辑**：doUpdate时validDecorationDays校验
  - **系统体现**：后端validSystemParam校验
  - **排查SQL**：`SELECT PARAM_VALUE FROM SYS_PARAM WHERE PARAM_CODE='Decoration_Days'`

### 提交校验

- 校验1：预算年度≤当前年份 —— 防止提前发起未来年度变更
  - **详细逻辑**：wfProcSubmit时校验budYear-LocalDate.now().getYear()≤0
  - **系统体现**：后端抛异常"门店装修申请与进度更新单据预算年度大于当前年度，无法发起验收"
  - **排查SQL**：`SELECT TERMINAL_CHANGE_ID, BUD_YEAR FROM FIN_FEE_APPLY_CHANGE_HEADER WHERE BUD_YEAR > EXTRACT(YEAR FROM SYSDATE)`

### 状态机

```text
NEW(新建) ──提交审批──→ RUN(审批中) ──┬──审批通过──→ APPROVED(已审批)
                                       │              ├─ 计算超期/扣减比例
                                       │              └─ 回写原申请单(changeValue)
                                       │
                                       ├──审批驳回──→ REJECTED(已驳回)
                                       │
                                       └──退回──→ REBUT(已退回)

任意非APPROVED ──作废──→ INTERRUPT(已作废) ──→ 原申请单isModify=3
NEW ──删除──→ (删除) ──→ 原申请单isModify=0
```

### 工作流

- **工作流编码**：`SUB_STORE_DECORATION_CHANGE`（门店装修申请变更）
- **编码规则**：`AE.TERMINAL_CHANGE_NO`（变更单号，参数divisionCode）
- **审批节点**：经销商上传装修后照片 → 门店设计师提交方案 → 软装设计师提交方案 → 设计经理审批 → 展示总监审批

## 常见问题FAQ

### Q1：新增变更时报"未获取到门店申请信息"

**根因**：关联的装修申请单(terminalApplyId)不存在或已被删除
**解决方案**：重新选择有效的已审批装修申请单

### Q2：提交时报"门店装修申请与进度更新单据预算年度大于当前年度"

**根因**：变更单的预算年度(budYear)大于当前年份
**解决方案**：确认原申请单的预算年度是否正确，或联系财务调整

### Q3：审批通过时报"装修完成时间为空"或"交付设计时间为空"

**根因**：变更单未填写装修完成时间或交付设计时间
**解决方案**：在变更单中补填装修完成时间和交付设计时间

### Q4：删除时报"不能删除非制单状态的单据"

**根因**：变更单状态非NEW，可能已提交审批
**解决方案**：仅NEW状态可删除，已提交的需通过审批驳回后才能删除

### Q5：原申请单提交时报"单2据正在申请变更中，不可提交"

**根因**：原申请单isModify=2，已有进行中的变更申请
**解决方案**：先完成或删除/作废变更申请，再提交原申请单

#### 报错7：门店装修申请与进度更新单据预算年度大于当前年度，无法发起验收

  FROM   fin_fee_apply_change_header c

#### 报错12：本次店面装修面积不能大于门店面积
- **触发条件**：详情页编辑面积字段时，前端校验thistimeTerminalArea(本次店面装修面积)>terminalArea(门店面积)
- **逻辑分析**：本次店面装修面积不应超过门店总面积，防止面积超限导致补贴金额计算异常。变更后面积用于重新计算政策补贴金额和申请补贴金额，若本次装修面积>门店面积，金额计算将超出实际范围。前端message.info提示并回填为门店面积，需修改本次装修面积至≤门店面积。
- **排查SQL**：
  ```sql
  SELECT c.id                     AS 变更单ID,
         c.terminal_change_no     AS 变更单号,
         c.terminal_area          AS 门店面积,
         c.thistime_terminal_area AS 本次店面装修面积
  FROM   fin_fee_apply_change_header c
  WHERE  c.thistime_terminal_area > c.terminal_area;
  ```

#### 报错13：店面实际装修面积不能大于本次店面装修面积
