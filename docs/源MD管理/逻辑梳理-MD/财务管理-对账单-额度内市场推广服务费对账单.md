# 财务管理-对账单-额度内市场推广服务费对账单

## 业务流程

### 业务流程图

```text
额度内市场推广服务费对账单页面(hlod低代码页面)
        │
        ├── 查询对账单列表 ──→ GET /inlimit-balance-account/selectList
        │                       （按事业部/交易公司/法人/年月查询）
        │
        ├── 查询明细行 ──→ GET /inlimit-balance-account/selectLineDetails
        │
        ├── 查询明细汇总 ──→ GET /inlimit-balance-account/selectDetailsTotal
        │
        ├── 重新生成 ──→ POST /inlimit-balance-account/regenerate
        │                  └── 汇总明细行总额，插入/更新头行数据
        │
        └── 更新推送状态 ──→ POST /inlimit-balance-account/update-status
```

### 上游依赖

| 上游模块 | 依赖类型 | 依赖说明 | 依赖成立条件 |
|---------|---------|---------|------------|

- 影响2：财务核算
  - 对账单数据用于财务核算与报表

## 重点逻辑

### 重点逻辑1：对账单重新生成 {数据重生成}

- **业务意义**：当数据有误或需要更新时，支持重新生成对账单，确保账单与账户一致

- **具体逻辑描述**

  - 第1点：通过regenerate接口重新生成对账单数据

  - 第2点：汇总明细行总额，计算期初余额、扣减金额、到期调整、其他调整、额度内兑现、期末余额

  - 第3点：插入或更新BUD_INLIMIT_BALANCE_ACCOUNT头表和BUD_INLIMIT_ACCOUNT_LINE行表

### 重点逻辑2：推送状态管理 {推送控制}

- **业务意义**：对账单支持推送外部系统，推送状态供外部对账跟踪

- **具体逻辑描述**

  - 第1点：通过update-status接口批量更新推送状态

  - 第2点：推送状态标记对账单是否已推送外部系统

#### 报错1：重新生成失败
- **触发条件**：用户点击"重新生成"按钮，regenerate接口执行汇总计算时抛出异常
- **逻辑分析**：重新生成接口按入参（事业部+交易公司+开票单位+起始时间）汇总明细行（BUD_INLIMIT_ACCOUNT_LINE）总额，计算期初余额、扣减金额、到期调整、其他调整、额度内兑现、期末余额，插入/更新BUD_INLIMIT_BALANCE_ACCOUNT头表。失败根因有三类：(1)明细数据未就绪，上游MKT_INLIMIT_BALANCE_DETAILS明细行数据未生成或未同步；(2)汇总计算异常，如除零错误（税率为0时计算不含税金额）或金额溢出；(3)头表唯一约束冲突（同事业部+交易公司+年月重复生成）。需核查明细行数据及汇总日志
- **排查SQL**：
  ```sql
  -- 核查明细行数据是否就绪
  SELECT COUNT(*) AS 明细行数, SUM(AMOUNT) AS 明细金额合计
  FROM BUD_INLIMIT_ACCOUNT_LINE
  WHERE INLIMIT_BALANCE_ACCOUNT_ID IN (
    SELECT INLIMIT_BALANCE_ACCOUNT_ID
    FROM BUD_INLIMIT_BALANCE_ACCOUNT
    WHERE ENTNAME = #{entname} AND YEARMONTH = #{yearmonth}
  );
  -- 核查头表是否已存在（唯一约束冲突排查）
  SELECT INLIMIT_BALANCE_ACCOUNT_ID, ENTNAME, TRADING_COMPANY_CODE, YEARMONTH, S_STAT
  FROM BUD_INLIMIT_BALANCE_ACCOUNT
  WHERE ENTNAME = #{entname} AND YEARMONTH = #{yearmonth};
  ```

#### 报错2：查询无数据
- **触发条件**：用户按事业部/交易公司/年月查询对账单，BUD_INLIMIT_BALANCE_ACCOUNT表返回空结果集
- **逻辑分析**：对账单头表数据由"重新生成"操作写入，非自动生成。无数据根因有二：(1)从未执行过重新生成，头表为空；(2)查询条件（ENTNAME+TRADING_COMPANY_CODE+YEARMONTH）与头表记录不匹配。需先执行重新生成，再查询确认
- **排查SQL**：
  ```sql
  SELECT INLIMIT_BALANCE_ACCOUNT_ID, ENTNAME, TRADING_COMPANY_CODE, BILLING_UNIT_CODE,
         YEARMONTH, BEGINNING_BALANCE, ACTUAL_ENDING_BALANCE, SEND_STATUS, S_STAT
  FROM BUD_INLIMIT_BALANCE_ACCOUNT
  WHERE (ENTNAME = #{entname} OR #{entname} IS NULL)
    AND (TRADING_COMPANY_CODE = #{tradingCompanyCode} OR #{tradingCompanyCode} IS NULL)
    AND (YEARMONTH = #{yearmonth} OR #{yearmonth} IS NULL)
  ORDER BY YEARMONTH DESC;
  ```

#### 报错3：生成出库单的日期最迟为前一个月
- **触发条件**：用户在重新生成时传入的查询年月（yearmonth）超过当前年月
- **逻辑分析**：后端BudInlimitBalanceAccountServiceImpl.regenerate方法中，将当前年月（cal.get(Calendar.YEAR)+"/"+cal.get(Calendar.MONTH)）作为可查询上限，校验format1.parse(newYearMonth).getTime() < format1.parse(yearmonth).getTime()时抛出IllegalArgumentException("生成出库单的日期最迟为前一个月")。该校验防止生成未来月份的对账单，因为未来月份的明细数据尚未产生。需将查询年月调整为当前月或更早
- **排查SQL**：
  ```sql
  -- 核查当前已有的最大年月
  SELECT MAX(YEARMONTH) AS 最大年月, TO_CHAR(SYSDATE, 'YYYY/MM') AS 当前年月
  FROM BUD_INLIMIT_BALANCE_ACCOUNT
  WHERE ENTNAME = #{entname};
  ```

#### 报错4：推送状态更新失败
- **触发条件**：用户点击"更新推送状态"按钮，POST /v1/{organizationId}/inlimit-balance-account/update-status接口执行失败
- **逻辑分析**：updateStatus方法接收BalanceAccountBatchSendDTO，从中获取inlimitBalanceAccountIds列表。若ids为空（CollectionUtils.isEmpty(ids)）则直接return不处理，不抛异常但前端无效果。失败根因有三类：(1)未选中记录，ids为空；(2)选中记录的SEND_STATUS已为2（已推送），不可重复推送；(3)数据库更新异常。需确认选中记录且SEND_STATUS不为2后重试
- **排查SQL**：
  ```sql
  -- 核查选中记录的当前推送状态
  SELECT INLIMIT_BALANCE_ACCOUNT_ID, ENTNAME, YEARMONTH, SEND_STATUS, S_STAT
  FROM BUD_INLIMIT_BALANCE_ACCOUNT
  WHERE INLIMIT_BALANCE_ACCOUNT_ID IN (#{ids});
  ```

#### 报错5：网络请求失败
- **触发条件**：用户点击查询/重新生成/更新推送状态按钮，前端调用对应接口返回非2xx状态码或超时
- **逻辑分析**：本页面为hlod低代码页面，数据通过后端BudInlimitBalanceAccountController提供。网络请求失败根因有四类：(1)ae-business服务未启动或宕机；(2)数据库连接异常；(3)重新生成时数据量过大，分页循环（每次200条）执行超时；(4)网关或网络层故障。需先确认ae-business服务健康状态
- **排查SQL**：
  ```sql
  -- 核查头表数据量是否异常
  SELECT COUNT(*) AS 总对账单数, COUNT(DISTINCT YEARMONTH) AS 年月数
  FROM BUD_INLIMIT_BALANCE_ACCOUNT;
  ```

#### 报错6：权限不足
- **触发条件**：用户登录后进入额度内市场推广服务费对账单页面，当前用户无对应事业部的数据权限
- **逻辑分析**：本页面按事业部维度查询，数据权限通过用户上下文控制可见事业部范围。权限不足根因有二：(1)用户未分配对应事业部的数据权限，查询时自动过滤导致空结果；(2)用户未分配菜单访问权限，页面入口不可见。需联系管理员在权限系统中分配对应事业部数据权限
- **排查SQL**：
  ```sql
  -- 核查用户可访问的事业部
  SELECT USER_ID, DIVISION_ID, DIVISION_NAME, ENABLED
  FROM USER_DIVISION_AUTH
  WHERE USER_ID = #{userId};
  ```
