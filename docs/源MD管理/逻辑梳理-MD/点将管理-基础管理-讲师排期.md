# 点将管理-基础管理-讲师排期

> 后端代码位于 mbo-business 微服务（源码未包含在当前源码目录下），前端 API 路径前缀为 `mlt/maLecturerSchedule/*`。本文档基于前端代码与接口契约梳理，后端实现以微服务实际代码为准。

## 业务流程

### 业务流程图

```
讲师排期管理(本页面)
        |
        ├──→ 新建排期 ──→ 弹窗填写(日期类型+日期范围+原因) ──→ 调用 save 接口
        |                                                      |
        |                                                      └──→ 刷新日历
        |
        ├──→ 取消排期 ──→ 弹窗填写(日期范围) ──→ 调用 cancel 接口
        |                                          |
        |                                          └──→ 刷新日历
        |
        └──→ LecturerCalendar 日历组件 ──→ 展示讲师排期日程
```

### 即时生效三步

1. **查询排期**：通过 LecturerCalendar 日历组件展示讲师当前排期
2. **添加排期**：弹窗填写日期类型、日期范围、原因，提交后即时生效
3. **取消排期**：弹窗填写日期范围，提交后即时释放讲师时间

### 全链路流程图

```
开始 → 查询讲师排期 → ★排期维护★ → 讲师时间占用/释放 → 供点将查询可用时间 → 结束
```

**使用原则**：排期只反映时间占用，不代表点将单据本身；点将取消后需及时取消对应排期，避免讲师资源被长期虚占。

### 上游依赖

| 上游模块 | 依赖类型 | 依赖说明 | 依赖成立条件 |
|---------|---------|---------|-------------|
| 讲师档案管理 | 数据依赖 | 提供讲师基础信息与档案编码 | 讲师档案已生效 |
| HZERO 权限服务 | 服务依赖 | 提供按钮权限校验 | 用户已登录并分配权限编码 |
| HZERO 值集服务 | 服务依赖 | 提供日期类型值集 | 值集 MBO.DATE_TYPE 已配置 |

### 下游影响

- **讲师排期日历**：排期数据展示，LecturerCalendar 组件渲染
- **点将申请**：排期影响讲师可用性校验，已排期时间段不可被点用
- **讲师饱和度统计**：排期数据作为统计来源

## 重点逻辑

### 重点逻辑1：同期不可重复

- **业务意义**：从源头避免讲师被重复点用，保证排期数据的唯一性
- **具体逻辑描述**：
  - 已排期的时间段不允许再次排期
  - 添加时做冲突校验：新排期时间段与已有排期时间段存在交集即为冲突
  - 冲突时提示"该讲师在指定时间段已有排期，请重新选择"

### 重点逻辑2：即时生效

- **业务意义**：便于业务临时调整讲师安排，无需等待审批
- **具体逻辑描述**：
  - 排期不走审批流程
  - 添加与取消均立即生效
  - 无工作流编码

### 重点逻辑3：驱动可用标识

- **业务意义**：排期是点将选人与饱和度统计的基础数据
- **具体逻辑描述**：
  - 排期结果决定讲师在点将选人列表中的可用标识
  - 排期数据是讲师饱和度统计的数据来源
  - 已排期时间段讲师在点将列表中标记为不可用

### 重点逻辑4：新建排期

- **业务意义**：登记讲师时间占用，标记不可用时段
- **具体逻辑描述**：
  1. 点击"新建排期"按钮，打开 Modal 弹窗
  2. 填写日期类型（dateType，Select 必填，值集 MBO.DATE_TYPE）
  3. 填写日期（date，DatePicker 范围必填，转换为 startDate 和 endDate）
  4. 填写原因（reason，TextField 选填）
  5. 提交时将日期数组转换为 startDate 和 endDate（格式 YYYY-MM-DD）
  6. 调用 `POST mlt/maLecturerSchedule/save` 接口
  7. 成功后通过 `setToggleTag(!toggleTag)` 刷新日历组件

### 重点逻辑5：取消排期

- **业务意义**：释放讲师时间占用，恢复可用状态
- **具体逻辑描述**：
  1. 点击"取消排期"按钮，打开 Modal 弹窗
  2. 填写日期（date，DatePicker 范围必填）
  3. 提交时转换为 startDate 和 endDate，通过 params 参数传递
  4. 调用 `POST mlt/maLecturerSchedule/cancel` 接口
  5. 成功后刷新日历

### 重点逻辑6：日历刷新机制

- **业务意义**：保证排期操作后日历视图及时更新
- **具体逻辑描述**：
  - 通过 `toggleTag` 状态变量控制日历刷新
  - 新建/取消排期成功后执行 `setToggleTag(!toggleTag)`
  - LecturerCalendar 组件接收 `refresh` 属性，值变化时重新加载数据

### 重点逻辑7：表单动态渲染

- **业务意义**：复用弹窗结构，按字段配置动态渲染表单项
- **具体逻辑描述**：
  - 新建和取消弹窗的表单项通过 `createDSProps.fields` 和 `cancelDSProps.fields` 动态渲染
  - `dateType` 字段渲染为 Select 组件
  - `date` 字段渲染为 DatePicker 组件
  - 其他字段渲染为 TextField 组件

### 保存/提交校验

- 校验1：新建排期时 dateType（日期类型）必填 —— 区分排期类型便于统计
  - **详细逻辑**：dateType 字段为空时阻止提交
  - **系统体现**：前端表单校验，提示"日期类型不能为空"
  - **排查SQL**：
    ```sql
    SELECT LECTURER_SCHEDULE_ID, LECTURER_ARCHIVES_CODE, START_DATE, END_DATE
    FROM MA_LECTURER_SCHEDULE
    WHERE DATE_TYPE IS NULL OR DATE_TYPE = '';
    ```
- 校验2：新建排期时 date（日期范围）必填 —— 排期时间区间是排期的核心数据
  - **详细逻辑**：date 字段为空时阻止提交，提交时转换为 startDate/endDate
  - **系统体现**：前端表单校验，提示"日期不能为空"
  - **排查SQL**：
    ```sql
    SELECT LECTURER_SCHEDULE_ID, LECTURER_ARCHIVES_CODE
    FROM MA_LECTURER_SCHEDULE
    WHERE START_DATE IS NULL OR END_DATE IS NULL;
    ```
- 校验3：取消排期时 date（日期范围）必填 —— 明确取消的时间区间
  - **详细逻辑**：date 字段为空时阻止提交
  - **系统体现**：前端表单校验，提示"日期不能为空"
  - **排查SQL**：
    ```sql
    SELECT LECTURER_SCHEDULE_ID, LECTURER_ARCHIVES_CODE, STATUS
    FROM MA_LECTURER_SCHEDULE
    WHERE STATUS = 'cancelled' AND (START_DATE IS NULL OR END_DATE IS NULL);
    ```
- 校验4：排期时间段不可与该讲师已有排期冲突 —— 避免讲师被重复点用
  - **详细逻辑**：新排期时间段与已有有效排期时间段存在交集即冲突
  - **系统体现**：后端 save 接口校验，冲突时返回业务异常
  - **排查SQL**：
    ```sql
    SELECT a.LECTURER_SCHEDULE_ID AS 排期1, b.LECTURER_SCHEDULE_ID AS 排期2,
           a.LECTURER_ARCHIVES_CODE AS 讲师档案编码,
           TO_CHAR(a.START_DATE,'YYYY-MM-DD') AS 排期1开始,
           TO_CHAR(a.END_DATE,'YYYY-MM-DD') AS 排期1结束,
           TO_CHAR(b.START_DATE,'YYYY-MM-DD') AS 排期2开始,
           TO_CHAR(b.END_DATE,'YYYY-MM-DD') AS 排期2结束
    FROM MA_LECTURER_SCHEDULE a
    JOIN MA_LECTURER_SCHEDULE b ON a.LECTURER_SCHEDULE_ID < b.LECTURER_SCHEDULE_ID
      AND a.LECTURER_ARCHIVES_ID = b.LECTURER_ARCHIVES_ID
      AND a.STATUS = 'active' AND b.STATUS = 'active'
      AND a.START_DATE <= b.END_DATE AND a.END_DATE >= b.START_DATE;
    ```

### 状态机

```
有效(active) ──取消排期──→ 已取消(cancelled)
```

| 状态机名称 | 状态释义 | 可执行的操作 |
|-----------|---------|-------------|
| 有效（active） | 排期生效中，讲师对应时间段被占用 | 取消排期 |
| 已取消（cancelled） | 排期已取消，讲师对应时间段释放为可用 | 无（终态） |

### 排查SQL

```sql
-- 查询讲师排期列表
SELECT
  ls.LECTURER_ARCHIVES_CODE AS 讲师档案编码,
  la.LECTURER_NAME     AS 讲师姓名,
  ls.DATE_TYPE         AS 日期类型,
  TO_CHAR(ls.START_DATE, 'YYYY-MM-DD') AS 开始日期,
  TO_CHAR(ls.END_DATE, 'YYYY-MM-DD') AS 结束日期,
  ls.REASON            AS 原因,
  ls.STATUS            AS 状态
FROM MA_LECTURER_SCHEDULE ls
LEFT JOIN MA_LECTURER_ARCHIVE la ON ls.LECTURER_ARCHIVES_ID = la.LECTURER_ARCHIVES_ID
WHERE ls.STATUS = 'active'
ORDER BY ls.START_DATE DESC;

-- 查询某日期范围内有排期的讲师
SELECT DISTINCT
  ls.LECTURER_ARCHIVES_CODE AS 讲师档案编码,
  la.LECTURER_NAME     AS 讲师姓名,
  TO_CHAR(ls.START_DATE, 'YYYY-MM-DD') AS 排期开始,
  TO_CHAR(ls.END_DATE, 'YYYY-MM-DD') AS 排期结束
FROM MA_LECTURER_SCHEDULE ls
LEFT JOIN MA_LECTURER_ARCHIVE la ON ls.LECTURER_ARCHIVES_ID = la.LECTURER_ARCHIVES_ID
WHERE ls.STATUS = 'active'
  AND ls.START_DATE <= TO_DATE('2026-12-31', 'YYYY-MM-DD')
  AND ls.END_DATE >= TO_DATE('2026-01-01', 'YYYY-MM-DD');

-- 查询排期冲突的讲师（同一讲师排期日期重叠）
SELECT
  a.LECTURER_ARCHIVES_CODE AS 讲师档案编码,
  TO_CHAR(a.START_DATE, 'YYYY-MM-DD') AS 排期1开始,
  TO_CHAR(a.END_DATE, 'YYYY-MM-DD') AS 排期1结束,
  TO_CHAR(b.START_DATE, 'YYYY-MM-DD') AS 排期2开始,
  TO_CHAR(b.END_DATE, 'YYYY-MM-DD') AS 排期2结束
FROM MA_LECTURER_SCHEDULE a
JOIN MA_LECTURER_SCHEDULE b ON a.LECTURER_SCHEDULE_ID < b.LECTURER_SCHEDULE_ID
  AND a.LECTURER_ARCHIVES_ID = b.LECTURER_ARCHIVES_ID
  AND a.STATUS = 'active' AND b.STATUS = 'active'
  AND a.START_DATE <= b.END_DATE AND a.END_DATE >= b.START_DATE;
```

#### 报错1：日期类型不能为空
- **触发条件**：新建排期提交时，dateType 字段为空
- **逻辑分析**：前端表单对 dateType 字段配置 required 校验，提交前执行字段校验，若值为空则阻止提交并提示"日期类型不能为空"。dateType 用于区分排期类型（如出差、休假、培训等），是排期统计的分类依据，必须填写
- **排查SQL**：
  ```sql
  SELECT LECTURER_SCHEDULE_ID AS 排期ID,
         LECTURER_ARCHIVES_CODE AS 讲师档案编码,
         LECTURER_NAME AS 讲师姓名,
         TO_CHAR(START_DATE,'YYYY-MM-DD') AS 开始日期,
         TO_CHAR(END_DATE,'YYYY-MM-DD') AS 结束日期
  FROM MA_LECTURER_SCHEDULE
  WHERE DATE_TYPE IS NULL OR DATE_TYPE = '';
  ```

#### 报错2：日期不能为空
- **触发条件**：新建排期或取消排期提交时，date 日期范围字段为空
- **逻辑分析**：前端 DatePicker(range) 组件对 date 字段配置 required 校验，提交前校验日期范围是否填写，为空则阻止提交并提示"日期不能为空"。日期范围是排期的核心数据，新建时用于确定占用时段，取消时用于确定释放时段，必须填写
- **排查SQL**：
  ```sql
  SELECT LECTURER_SCHEDULE_ID AS 排期ID,
         LECTURER_ARCHIVES_CODE AS 讲师档案编码,
         LECTURER_NAME AS 讲师姓名,
         DATE_TYPE AS 日期类型,
         STATUS AS 状态
  FROM MA_LECTURER_SCHEDULE
  WHERE START_DATE IS NULL OR END_DATE IS NULL;
  ```

#### 报错3：该讲师在指定时间段已有排期，请重新选择
- **触发条件**：新建排期提交时，新排期时间段与该讲师已有有效排期（STATUS='active'）时间段存在交集
- **逻辑分析**：后端 save 接口在保存前执行冲突校验，查询 MA_LECTURER_SCHEDULE 表中同一讲师（LECTURER_ARCHIVES_ID 相同）且状态为 active 的排期记录，判断新排期的 [START_DATE, END_DATE] 与已有排期的 [START_DATE, END_DATE] 是否存在交集（新排期.START_DATE <= 已有.END_DATE AND 新排期.END_DATE >= 已有.START_DATE）。若存在交集则抛出业务异常，提示"该讲师在指定时间段已有排期，请重新选择"。此校验从源头避免讲师被重复点用，保证排期数据唯一性
- **排查SQL**：
  ```sql
  SELECT a.LECTURER_SCHEDULE_ID AS 排期1ID,
         b.LECTURER_SCHEDULE_ID AS 排期2ID,
         a.LECTURER_ARCHIVES_CODE AS 讲师档案编码,
         a.LECTURER_NAME AS 讲师姓名,
         TO_CHAR(a.START_DATE,'YYYY-MM-DD') AS 排期1开始,
         TO_CHAR(a.END_DATE,'YYYY-MM-DD') AS 排期1结束,
         TO_CHAR(b.START_DATE,'YYYY-MM-DD') AS 排期2开始,
         TO_CHAR(b.END_DATE,'YYYY-MM-DD') AS 排期2结束
  FROM MA_LECTURER_SCHEDULE a
  JOIN MA_LECTURER_SCHEDULE b ON a.LECTURER_SCHEDULE_ID < b.LECTURER_SCHEDULE_ID
    AND a.LECTURER_ARCHIVES_ID = b.LECTURER_ARCHIVES_ID
    AND a.STATUS = 'active' AND b.STATUS = 'active'
    AND a.START_DATE <= b.END_DATE AND a.END_DATE >= b.START_DATE;
  ```

#### 报错4：请求失败
- **触发条件**：调用 mlt/maLecturerSchedule/save、cancel 或 list 接口时，后端返回 HTTP 状态码非 2xx
- **逻辑分析**：前端通过 axios 调用后端接口，若响应状态码非 2xx 或网络异常则触发错误回调，统一提示"请求失败"。常见根因包括：mbo-business 微服务未启动或异常、数据库连接失败、SQL 执行超时、后端业务异常未捕获、网络中断等。需检查 mbo-business 微服务运行状态、数据库连接池、后端日志定位具体异常堆栈
- **排查SQL**：
  ```sql
  -- 检查近期异常排期记录（结合后端日志时间排查）
  SELECT LECTURER_SCHEDULE_ID AS 排期ID,
         LECTURER_ARCHIVES_CODE AS 讲师档案编码,
         LECTURER_NAME AS 讲师姓名,
         STATUS AS 状态,
         TO_CHAR(LAST_UPDATE_DATE,'YYYY-MM-DD HH24:MI:SS') AS 最后更新时间,
         LAST_UPDATED_BY AS 最后更新人
  FROM MA_LECTURER_SCHEDULE
  WHERE LAST_UPDATE_DATE >= SYSDATE - 1
  ORDER BY LAST_UPDATE_DATE DESC;
  ```

#### 报错6：权限不足
- **触发条件**：点击新建、取消排期等按钮时，当前用户无对应 permissionList 权限码
- **逻辑分析**：前端 Button 组件通过 permissionList 配置权限码，HZERO 框架校验当前用户角色是否包含该权限码，未包含则按钮不可见或禁用。若强制调用接口，后端也会校验权限返回403。需联系管理员配置对应角色权限
- **排查SQL**：
  ```sql
  SELECT U.USER_NAME AS 用户名, R.ROLE_NAME AS 角色名, P.PERMISSION_CODE AS 权限码
  FROM SYS_USER U
  LEFT JOIN SYS_USER_ROLE UR ON U.USER_ID = UR.USER_ID
  LEFT JOIN SYS_ROLE R ON UR.ROLE_ID = R.ROLE_ID
  LEFT JOIN SYS_ROLE_PERMISSION RP ON R.ROLE_ID = RP.ROLE_ID
  LEFT JOIN SYS_PERMISSION P ON RP.PERMISSION_ID = P.PERMISSION_ID
  WHERE P.PERMISSION_CODE LIKE '%lecturer_schedule%' ORDER BY U.USER_NAME;
  ```

#### 报错7：数据不存在
- **触发条件**：取消排期等操作时，接口返回数据为空或排期ID不存在
- **逻辑分析**：前端通过 lecturerScheduleId 调用接口，后端查询 MA_LECTURER_SCHEDULE 表无对应记录或记录已逻辑删除，返回空数据。常见根因：排期ID错误、排期已被删除、跨租户查询、数据权限隔离等。需检查 LECTURER_SCHEDULE_ID 有效性及数据权限
- **排查SQL**：
  ```sql
  SELECT LECTURER_SCHEDULE_ID AS 排期ID, LECTURER_NAME AS 讲师姓名,
         STATUS AS 状态, DELETE_FLAG AS 删除标记
  FROM MA_LECTURER_SCHEDULE
  WHERE DELETE_FLAG = 'Y' OR LECTURER_SCHEDULE_ID IS NULL;
  ```

#### 报错8：状态不允许操作
- **触发条件**：点击取消排期按钮时，排期状态不允许取消
- **逻辑分析**：后端校验状态机，如已取消（cancelled）不可重复取消、已过期不可取消等。状态不匹配时后端返回业务异常。需检查排期当前状态及操作流程

#### 报错9：值集数据不显示
- **触发条件**：查询条件或新建排期弹窗中日期类型等下拉选项为空
- **逻辑分析**：前端通过 lookupCode 查询值集 MBO.SCHEDULE_DATE_TYPE 等，值集未配置或未启用则下拉选项为空。需在值集管理页面配置对应值集

#### 报错10：讲师不能为空

- **逻辑分析**：前端表单对 lecturerArchivesCode 字段配置 required 校验，提交前校验讲师是否选择，为空则阻止提交并提示"讲师不能为空"。讲师是排期的核心对象，必须明确

### 常见问题

- **Q1：添加排期时时间冲突如何处理？**
  A：系统自动校验排期冲突，如该讲师在目标时间段已有排期，会提示冲突信息，不允许保存。

- **Q2：取消排期后能否恢复？**
  A：取消排期为即时生效操作，取消后需重新添加排期。

- **Q3：排期是否需要审批？**
  A：不需要。讲师排期无工作流，添加和取消均为即时生效。

- **Q4：排期与点将业务如何关联？**
  A：点将业务选择讲师时，通过查询讲师排期判断可用性。点将单创建成功后会回写关联单号（RELATED_ORDER_CODE）到排期记录。

- **Q5：一个讲师一天可以有多少个排期？**
  A：无数量限制，但同一讲师的排期时间段不可重叠（冲突校验）。

- **Q6：日历不显示排期？**
  A：检查 LecturerCalendar 组件 refresh 属性，确认排期数据存在。

- **Q7：新建排期后日历未刷新？**
  A：检查 setToggleTag 是否执行，onSuccess 回调是否触发。

- **Q8：取消排期失败？**
  A：检查日期范围内是否有排期数据，cancel 接口返回内容。
