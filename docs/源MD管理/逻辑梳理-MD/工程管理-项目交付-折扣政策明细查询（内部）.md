## 业务流程

### 业务流程图

```text
用户进入折扣政策明细查询页面（低代码页面hlod，内部使用）
    │
    ├── 设置查询条件（政策编码、政策名称、有效状态、销售渠道、有效日期等）
    │
    ├── 点击查询 → POST /terminalReport/discount-policy-report/search
    │       ├── 关联折扣政策头表+行表+行明细+扩展表
    │       ├── 值集翻译（政策类型、订单类型、销售渠道、申请类型、优惠方式等）
    │       └── 适用客户编码列表通过LISTAGG聚合
    │
    └── 导出 → GET /terminalReport/discount-policy-report/export
            └── @ProcessLovValue翻译后全量导出（asyncThreshold=10000）
```

## 重点逻辑

### 重点逻辑1：纯查询页面，无增删改操作

- **业务意义**：供内部人员查询折扣政策的产品明细信息，了解各产品的折扣率、特价、封顶数量等详细配置

- **具体逻辑描述**

  - 第1点：本页面为hlod低代码报表页面，无独立前端源码，仅提供查询和导出功能

  - 第2点：不支持新增、修改、删除操作

  - 第3点：查询结果关联产品拓展表，展示月平均动销数量、库存消化月数、现有量、库龄等扩展信息

### 重点逻辑2：产品明细行关联二级明细

- **业务意义**：折扣政策产品明细行下可挂载二级明细行，定义不同折扣率/特价阶梯

- **具体逻辑描述**

  - 第1点：每个产品明细行(applicationType=1产品/2型号)下可有多条二级明细行，定义不同折扣率/特价

  - 第2点：申请类型=3(全产品)时，无二级明细行，折扣率/特价直接在产品行上

### 重点逻辑3：多表关联查询

- **业务意义**：通过多表关联获取完整的政策明细信息

- **具体逻辑描述**

  - 第1点：头表(EPM_DISCOUNT_POLICY) INNER JOIN 行表(ITEM) INNER JOIN 行明细(ITEM_LINE)

  - 第2点：LEFT JOIN 扩展表(ITEM_EXT) LEFT JOIN 行扩展(DPIL_EXT)

### 重点逻辑4：适用客户编码聚合

- **业务意义**：将政策关联的多个客户编码聚合为一个字符串展示

- **具体逻辑描述**

  - 第1点：通过LISTAGG函数将EPM_DISCOUNT_POLICY_CUSTOMER中的customer_code逗号拼接

### 重点逻辑5：有效日期区间查询

- **业务意义**：查询某日期区间内有交集的政策

- **具体逻辑描述**

  - 第1点：传入effectiveDateStart时，要求政策effective_date_start ≤ 查询日期 AND effective_date_end ≥ 查询日期

  - 第2点：即查询日期落在政策有效期内

### 重点逻辑6：业务类型动态翻译

- **业务意义**：根据销售渠道选择不同值集翻译业务类型

- **具体逻辑描述**

  - 第1点：channel=1(家装)用epm.home.business_type1

  - 第2点：channel=3(样品)用epm.home.business_type2

  - 第3点：其他(工程)用epm.engineer.business_type

**报表查询SQL（discountPolicyReportSearch）：**

```sql
SELECT t.discount_policy_code,
       (SELECT username FROM scpuser WHERE userid = t.creator) AS username,
       t.createtime, t.discount_policy_name,
       (SELECT meaning FROM HPFM_LOV_VALUE WHERE LOV_CODE = 'AE.EPM.POLICY_TYPE' AND value = t.policy_type) AS policyType,
       TO_CHAR(t.effective_date_start, 'YYYY-MM-DD') AS effectiveDateStart,
       TO_CHAR(t.effective_date_end, 'YYYY-MM-DD') AS effectiveDateEnd,
       CASE t.valid WHEN 1 THEN '未审核' WHEN 2 THEN '有效' WHEN 3 THEN '无效' ELSE '未知' END AS valid,
       t1.item_code, t1.item_name, t1.item_model,
       ROUND(NVL(t1.stand_price, 0), 2) AS standPrice,
       DECODE(t1.valid_stat, 3, '是', '否') AS validStat,
       DECODE(t2.new_prod_flag, 'Y', '是', 'N', '否', '其它') AS newProdFlag,
       (SELECT LISTAGG(n.customer_code, ',') WITHIN GROUP (ORDER BY n.customer_code)
        FROM epm_discount_policy_customer n
        WHERE n.discount_policy_id = t.discount_policy_id) AS customerAllName,
       t4.minimum_qty, t4.capping_qty, t4.special_offer, t4.discount_rate
FROM epm_discount_policy t
  INNER JOIN epm_discount_policy_item t1 ON t1.discount_policy_id = t.discount_policy_id
  INNER JOIN epm_discount_policy_item_line t4 ON t4.discount_policy_item_id = t1.discount_policy_item_id
  LEFT JOIN epm_discount_policy_item_ext t2 ON t2.discount_policy_item_id = t1.discount_policy_item_id
```

#### 报错1：查询条件不能为空
- **触发条件**：用户点击"查询"按钮时，所有查询条件(折扣政策编码/名称/客户/项目/有效日期等)均为空
- **逻辑分析**：前端校验至少需输入一个查询条件，因折扣政策明细数据量大，强制要求至少一个过滤条件以避免全表扫描。该报错为toast提醒级别，不发起后端请求
- **排查SQL**：
  ```sql
  -- 前端校验为主，后端可结合如下SQL确认条件下的数据量
  SELECT COUNT(*) AS 满足条件数据量
  FROM EPM_DISCOUNT_POLICY edp
  WHERE (:discountPolicyCode IS NULL OR edp.DISCOUNT_POLICY_CODE LIKE '%' || :discountPolicyCode || '%')
    AND (:discountPolicyName IS NULL OR edp.DISCOUNT_POLICY_NAME LIKE '%' || :discountPolicyName || '%')
    AND (:customerCode IS NULL OR EXISTS (
        SELECT 1 FROM EPM_DISCOUNT_POLICY_CUSTOMER edpc
        WHERE edpc.DISCOUNT_POLICY_ID = edp.DISCOUNT_POLICY_ID AND edpc.CUSTOMER_CODE = :customerCode))
  ```

#### 报错2：无权限访问
- **触发条件**：非内部用户(userType≠I)访问折扣政策明细查询(内部)接口时
- **逻辑分析**：该接口为内部用户专用，后端通过当前登录用户类型(userType)校验，仅内部用户(userType=I)允许访问。经销商(userType=D)或外部用户访问时返回无权限错误。该报错为阻断性报错
- **排查SQL**：
  ```sql
  -- 校验当前用户类型
  SELECT iu.USER_ID, iu.USER_NAME, iu.USER_TYPE, iu.REAL_NAME
  FROM IAM_USER iu
  WHERE iu.USER_ID = :currentUserId
  -- 期望 USER_TYPE = 'I'，否则无权限
  ```

#### 报错3：政策失效id不允许为空
- **触发条件**：查询折扣政策失效行明细时，未传入discountPolicyDisabledId参数或参数为空
- **逻辑分析**：调用getDisabledLineList接口查询EPM_DISCOUNT_POLICY_DISABLE_LINE(政策失效行表)时，必须传入discountPolicyDisabledId作为关联EPM_DISCOUNT_POLICY_DISABLE头表的外键。若为空则无法定位失效行数据，抛出阻断性报错
- **排查SQL**：
  ```sql
  -- 校验传入的政策失效ID是否存在
  SELECT edpd.DISABLE_ID, edpd.DISCOUNT_POLICY_ID, edpd.DISABLE_DATE, edpd.HZ_APPROVE_STATUS
  FROM EPM_DISCOUNT_POLICY_DISABLE edpd
  WHERE edpd.DISABLE_ID = :discountPolicyDisabledId
  -- 若返回空，说明传入的失效ID不存在
  ```

#### 报错4：查询无数据
- **触发条件**：用户点击"查询"按钮时，查询条件无匹配数据
- **逻辑分析**：后端search方法按查询条件关联EPM_DISCOUNT_POLICY、EPM_DISCOUNT_POLICY_ITEM、EPM_DISCOUNT_POLICY_ITEM_LINE多表查询，若结果集为空则前端展示"无数据"。需调整查询条件
- **排查SQL**：
  ```sql
  SELECT COUNT(*) AS 查询结果数
  FROM EPM_DISCOUNT_POLICY edp
  INNER JOIN EPM_DISCOUNT_POLICY_ITEM edpi ON edpi.DISCOUNT_POLICY_ID = edp.DISCOUNT_POLICY_ID
  WHERE (:discountPolicyCode IS NULL OR edp.DISCOUNT_POLICY_CODE LIKE '%' || :discountPolicyCode || '%')
    AND (:discountPolicyName IS NULL OR edp.DISCOUNT_POLICY_NAME LIKE '%' || :discountPolicyName || '%')
    AND (:valid IS NULL OR edp.VALID = :valid)
    AND (:itemCode IS NULL OR edpi.ITEM_CODE LIKE '%' || :itemCode || '%')
  ```

#### 报错5：导出数据量超过限制
- **触发条件**：用户点击"导出"按钮时，查询结果数据量超过@ExcelExport注解或系统配置的导出上限(默认单次10000条)
- **逻辑分析**：导出调用Repository全量查询(不分页)，关联EPM_DISCOUNT_POLICY、EPM_DISCOUNT_POLICY_ITEM、EPM_DISCOUNT_POLICY_ITEM_LINE、EPM_DISCOUNT_POLICY_ITEM_EXT多表。当结果集超过Excel单sheet上限(65536行)或系统配置的导出条数限制时抛出toast提醒。需缩小查询范围后重试
- **排查SQL**：
  ```sql
  SELECT COUNT(*) AS 待导出数据量
  FROM EPM_DISCOUNT_POLICY edp
  INNER JOIN EPM_DISCOUNT_POLICY_ITEM edpi ON edpi.DISCOUNT_POLICY_ID = edp.DISCOUNT_POLICY_ID
  INNER JOIN EPM_DISCOUNT_POLICY_ITEM_LINE edpil ON edpil.DISCOUNT_POLICY_ITEM_ID = edpi.DISCOUNT_POLICY_ITEM_ID
  WHERE (:discountPolicyCode IS NULL OR edp.DISCOUNT_POLICY_CODE LIKE '%' || :discountPolicyCode || '%')
    AND (:discountPolicyName IS NULL OR edp.DISCOUNT_POLICY_NAME LIKE '%' || :discountPolicyName || '%')
  ```

#### 报错6：报表查询超时
- **触发条件**：查询时，查询数据量过大导致数据库查询超时
- **逻辑分析**：后端search方法关联EPM_DISCOUNT_POLICY、EPM_DISCOUNT_POLICY_ITEM、EPM_DISCOUNT_POLICY_ITEM_LINE、EPM_DISCOUNT_POLICY_ITEM_EXT多表查询，若查询条件过宽导致数据量过大则可能超时。需缩小查询范围
- **排查SQL**：
  ```sql
  SELECT COUNT(*) AS 预估数据量
  FROM EPM_DISCOUNT_POLICY edp
  INNER JOIN EPM_DISCOUNT_POLICY_ITEM edpi ON edpi.DISCOUNT_POLICY_ID = edp.DISCOUNT_POLICY_ID
  -- 若数据量过大(超过10万)，建议缩小查询范围
  ```

#### 报错7：导出失败，请稍后重试
- **触发条件**：导出时，导出处理异常(如内存不足、IO异常等)
- **逻辑分析**：导出方法中try-catch捕获异常，若处理失败则提示稍后重试。需稍后重试或联系管理员查看后端日志
- **排查SQL**：
  ```sql
  SELECT sem.OBJID, sem.OBJTYPENAME, sem.ERROR_MSG, sem.CREATION_DATE
  FROM SYS_EXCEPTION_MSG sem
  WHERE sem.OBJTYPENAME = '折扣政策明细查询'
  ORDER BY sem.CREATION_DATE DESC
  ```

#### 报错8：政策明细数据不完整
- **触发条件**：查询时，政策关联数据缺失(如产品明细行、阶梯明细行、扩展信息等缺失)
- **逻辑分析**：后端search方法关联查询EPM_DISCOUNT_POLICY_ITEM_EXT扩展表，若关联数据缺失则部分字段(如SM_STATE、月平均动销数量等)为空。需检查政策数据完整性
- **排查SQL**：
  ```sql
  SELECT edpi.DISCOUNT_POLICY_ITEM_ID, edpi.ITEM_CODE, edpi.ITEM_NAME,
         edpie.SM_STATE, edpie.AVG_MONTH_DYNAMIC_SALE_NUM, edpie.INVENTORY_DIGESTION_MONTHS
  FROM EPM_DISCOUNT_POLICY_ITEM edpi
  LEFT JOIN EPM_DISCOUNT_POLICY_ITEM_EXT edpie ON edpi.DISCOUNT_POLICY_ITEM_ID = edpie.DISCOUNT_POLICY_ITEM_ID
  WHERE edpie.ID IS NULL
  -- 查出扩展信息缺失的产品明细行
  ```

### 常见问题

- 问题1：查询结果中部分产品明细行的拓展信息为空
  - 原因：EPM_DISCOUNT_POLICY_ITEM_EXT表中无对应记录，可能为历史数据
  - 解决思路：确认该产品明细行是否需要拓展信息，如需要可重新生成

- 问题2：生效状态含义不明确？
  - 原因：VALID_STAT字段使用数值编码，0=未生效/1=生效/3=已失效
  - 解决思路：通过值集翻译显示

- 问题3：有效日期查询的逻辑是什么？
  - 原因：使用区间重叠判断：政策effective_date_start ≤ 查询日期 AND effective_date_end ≥ 查询日期
  - 解决思路：即查询日期落在政策有效期内

- 问题4：业务类型为什么有不同的翻译？
  - 原因：根据销售渠道(channel)动态选择值集：channel=1用epm.home.business_type1，channel=3用epm.home.business_type2，其他用epm.engineer.business_type
  - 解决思路：这是预期行为，不同渠道使用不同业务类型值集

- 问题5：适用客户编码列表怎么展示？
  - 原因：通过LISTAGG函数将EPM_DISCOUNT_POLICY_CUSTOMER表中该政策关联的所有customer_code用逗号拼接
  - 解决思路：这是SQL聚合展示

- 问题6：导出时asyncThreshold=10000是什么意思？
  - 原因：当数据量超过10000条时，导出切换为异步模式，避免超时
  - 解决思路：缩小查询范围或等待异步导出完成
