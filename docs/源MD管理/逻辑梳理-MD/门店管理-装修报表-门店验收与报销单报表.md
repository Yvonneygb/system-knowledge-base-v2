# 门店管理-装修报表-门店验收与报销单报表

> 本页面为低代码页面(hlod)，无独立前端源码，基于后端API梳理。

## 业务流程

门店验收与报销单报表用于查询门店装修验收报销单的详细信息，包括验收单号、门店信息、经销商信息、验收面积、验收标准、报销金额、发票信息、审批进度等。数据来源于验收报销单头表 `FIN_FEE_CHECK_BX_HEADER`，关联工作流任务历史表、交易公司表、事业部表获取补充信息。本页面为纯查询报表，仅支持查看和导出，不支持新增、修改、删除等写操作。

**核心流程：**
1. 用户进入门店验收与报销单报表页面
2. 填写查询条件（事业部、交易公司、开票单位、经销商、创建时间范围等）
3. 点击查询，调用后端接口分页返回验收报销单数据
4. 用户查看报表数据，了解各门店验收报销单的审批进度和金额信息

```
开始 → 设定查询条件 → 点击查询 → 后端分页查询FIN_FEE_CHECK_BX_HEADER（关联工作流/交易公司/事业部） → 返回验收报销单数据列表 → 查看报表/导出Excel → 结束
```

- 上游支撑：门店验收与报销单（FIN_FEE_CHECK_BX_HEADER）、门店装修申请单（FIN_FEE_APPLY_FINISHED_HEADER）、工作流任务历史（HWKF_RUN_TASK_HISTORY）、交易公司（EPM_TRADING_COMPANY）、事业部基础设置（DIVISION_BASE_SET）、hlod报表引擎
- 下游影响：验收报销情况分析、各维度报销金额核对、审批进度监控、Excel导出归档、内部管理决策参考

## 重点逻辑

### 重点逻辑1：纯报表查询页面【只读查询】

- **业务意义**：供内部人员查询门店验收与报销单的汇总报表信息，了解验收报销的整体情况及各维度报销金额
- **具体逻辑描述**：
  - 本页面为hlod低代码报表页面，无独立前端源码
  - 仅提供查询和导出功能，不支持新增、修改、删除操作
  - 数据来源于验收报销单头表 `FIN_FEE_CHECK_BX_HEADER`，包含额度内/额度外/门头的验收标准、复核标准及可报销金额

### 重点逻辑2：审批节点名称动态获取

- **业务意义**：根据审批状态动态展示当前审批节点名称，便于用户了解单据审批进度
- **具体逻辑描述**：
  - 通过CASE语句处理：HZ_APPROVE_STATUS='NEW'时显示"新建"，='APPROVED'时显示"已审核"
  - 其他状态通过LEFT JOIN `HZERO.HWKF_RUN_TASK_HISTORY` 表，取STATUS='RUN'的节点名称（NODE_NAME）
  - 关联条件：`cbh.HZ_INSTANCE_ID = sp.INSTANCE_ID`

### 重点逻辑3：签名状态子查询关联

- **业务意义**：获取对应装修申请单的签名状态，用于判断装修申请是否已电子签名
- **具体逻辑描述**：
  - 通过子查询从 `FIN_FEE_APPLY_FINISHED_HEADER` 表获取签名状态
  - SQL：`(SELECT afh.signature_state FROM epms.fin_fee_apply_finished_header afh WHERE afh.terminal_apply_id = cbh.terminal_apply_id)`

### 重点逻辑4：免扣比例计算

- **业务意义**：计算验收超期和装修超期的免扣比例合计，用于报销金额核算
- **具体逻辑描述**：
  - `check_free_proportion = NVL(check_overtime_free, 0) + NVL(decoration_overtime_free, 0)`
  - check_overtime_free：验收提单超期减免(%)
  - decoration_overtime_free：装修超期减免(%)

### 重点逻辑5：时间范围查询含当天

- **业务意义**：结束时间查询包含当天数据，避免遗漏当天创建的单据
- **具体逻辑描述**：
  - 创建时间范围使用 `to_date` 转换
  - 结束日期加1天（`+ 1`）实现包含当天：`create_time <= to_date(#{endTime}, 'yyyy-mm-dd') + 1`

#### 按钮1：查询（列表页查询区域）

- **业务意义**：根据查询条件搜索验收报销单报表数据
- **具体逻辑描述**：
  - 点击查询按钮，触发POST `/v1/{organizationId}/terminalReport/mkt-terminal-check-bx-list/search` 接口
  - 请求参数为MktTerminalCheckBxListSearchDTO，包含organizationId、tradingCompanyName、billingUnitCode、billingUnitName、custCode、custName、startTime、endTime
  - 后端通过PageHelper.doPageAndSort实现分页查询
  - 查询FIN_FEE_CHECK_BX_HEADER表，关联HWKF_RUN_TASK_HISTORY、EPM_TRADING_COMPANY、DIVISION_BASE_SET
  - 返回MktTerminalCheckBxListSearchVO分页结果

#### 按钮2：导出（列表页查询区域）

- **业务意义**：将查询结果导出为Excel文件，供内部管理决策与归档使用
- **具体逻辑描述**：
  - 点击导出按钮，将当前查询条件下的报表数据导出为Excel
  - 导出数据与查询结果一致

### 后端接口Mapper SQL

```sql
-- 门店验收与报销单报表查询
SELECT cbh.*
FROM (
    SELECT
        cbh.*,
        0 AS fact_invoice_notax_amt,
        0 AS fact_invoice_amt,
        0 AS this_can_bx_amt,
        0 AS this_cashout_proportion,
        (NVL(cbh.check_overtime_free, 0) + NVL(cbh.decoration_overtime_free, 0)) AS check_free_proportion,
        CASE cbh.HZ_APPROVE_STATUS
            WHEN 'NEW' THEN '新建'
            WHEN 'APPROVED' THEN '已审核'
            ELSE sp.NODE_NAME
        END AS procname,
        (SELECT afh.signature_state
         FROM epms.fin_fee_apply_finished_header afh
         WHERE afh.terminal_apply_id = cbh.terminal_apply_id) AS signatureState,
        dbs.division_name AS divisionName,
        dbs.division_id,
        etc.address
    FROM epms.fin_fee_check_bx_header cbh
    LEFT JOIN hzero.HWKF_RUN_TASK_HISTORY sp
        ON cbh.HZ_INSTANCE_ID = sp.INSTANCE_ID
        AND sp.STATUS = 'RUN'
    LEFT JOIN epms.epm_trading_company etc
        ON cbh.trading_company_id = etc.trading_company_id
    LEFT JOIN epms.DIVISION_BASE_SET DBS
        ON dbs.organization_id = cbh.organization_id
) cbh
WHERE 1 = 1
    AND organization_id = #{organizationId}                        -- 事业部ID（精确）
    AND trading_company_name LIKE '%' || #{tradingCompanyName} || '%'  -- 交易公司名称（模糊）
    AND billing_unit_code = #{billingUnitCode}                     -- 开票单位编码（精确）
    AND billing_unit_name LIKE '%' || #{billingUnitName} || '%'    -- 开票单位名称（模糊）
    AND create_time >= TO_DATE(#{startTime}, 'yyyy-mm-dd')         -- 创建时间范围-开始
    AND create_time <= TO_DATE(#{endTime}, 'yyyy-mm-dd') + 1       -- 创建时间范围-结束（含当天）
    AND cust_code = #{custCode}                                    -- 经销商编码（精确）
    AND cust_name LIKE '%' || #{custName} || '%'                   -- 经销商名称（模糊）
```

#### 报错1：查询结果为空
- **触发条件**：点击"查询"按钮，按当前查询条件（事业部、交易公司、开票单位、经销商、创建时间范围等）查询FIN_FEE_CHECK_BX_HEADER返回空结果集
- **逻辑分析**：报表查询FIN_FEE_CHECK_BX_HEADER关联工作流任务历史表（HWKF_RUN_TASK_HISTORY）、交易公司表（EPM_TRADING_COMPANY）、事业部基础设置表（DIVISION_BASE_SET）。若查询条件过严（如经销商名称拼写错误、时间范围不含数据）、或验收报销单尚未创建、或用户组织ID（ORGANIZATION_ID）与数据不匹配，均会返回空结果。该报错为提示性，不影响系统，仅提示用户调整条件。
- **排查SQL**：
  ```sql
  SELECT check_bx_id        AS 验收报销单ID,
         check_bx_code      AS 验收报销单号,
         cust_name          AS 经销商名称,
         terminal_name      AS 门店名称,
         organization_id    AS 组织ID,
         create_time        AS 创建时间
  FROM   fin_fee_check_bx_header
  WHERE  organization_id = #{当前用户组织ID}
  ORDER  BY create_time DESC;
  ```

#### 报错2：签名状态子查询返回多行
- **触发条件**：查询结果展示时，子查询 `(SELECT afh.signature_state FROM epms.fin_fee_apply_finished_header afh WHERE afh.terminal_apply_id = cbh.terminal_apply_id)` 返回多行
- **逻辑分析**：报表通过子查询关联FIN_FEE_APPLY_FINISHED_HEADER获取装修申请单的签名状态，期望一个装修申请单ID（TERMINAL_APPLY_ID）对应一条签名状态记录。若FIN_FEE_APPLY_FINISHED_HEADER存在重复数据（如同一TERMINAL_APPLY_ID多条记录）、或历史数据迁移产生重复、或装修申请单被多次完工验收生成多条finished_header记录，子查询返回多行导致Oracle抛出ORA-01427单行子查询返回多行错误，整条查询失败。
- **排查SQL**：
  ```sql
  SELECT afh.terminal_apply_id   AS 装修申请单ID,
         COUNT(*)                AS 签名状态记录数
  FROM   fin_fee_apply_finished_header afh
  GROUP  BY afh.terminal_apply_id
  HAVING COUNT(*) > 1
  ORDER  BY 签名状态记录数 DESC;
  ```

## 常见问题FAQ

**Q1：报表数据来源是什么？**
A：数据来源于验收报销单头表 `FIN_FEE_CHECK_BX_HEADER`，关联工作流任务历史表（HWKF_RUN_TASK_HISTORY）、交易公司表（EPM_TRADING_COMPANY）、事业部基础设置表（DIVISION_BASE_SET）获取补充信息。

**Q2：审批节点名称如何展示？**
A：通过CASE语句处理：HZ_APPROVE_STATUS='NEW'显示"新建"，='APPROVED'显示"已审核"，其他状态取工作流运行中任务节点名称（HWKF_RUN_TASK_HISTORY.NODE_NAME）。

**Q3：报表是否支持导出？**
A：是，支持导出Excel，供内部管理决策与归档使用。

**Q4：报表是否支持新增/修改/删除？**
A：不支持，本页面为纯查询报表，仅支持查看和导出。相关写操作在"门店装修-门店验收与报销单"页面进行。

**Q5：免扣比例如何计算？**
A：`check_free_proportion = NVL(check_overtime_free, 0) + NVL(decoration_overtime_free, 0)`，即验收提单超期减免(%) + 装修超期减免(%)。

**Q6：结束时间查询是否包含当天？**
A：是，SQL中结束日期加1天（`+ 1`）实现包含当天：`create_time <= to_date(#{endTime}, 'yyyy-mm-dd') + 1`。
