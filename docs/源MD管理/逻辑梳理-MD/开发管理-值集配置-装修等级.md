# 开发管理-值集配置-装修等级

> **说明**：本菜单为 HZERO 平台标准 LOV 值集配置页面，对应 LOV 编码 `AE.FIXUP_GRADE`，无需业务后端代码，所有 CRUD 操作通过 HZERO 平台通用值集服务完成。本文档梳理值集配置规则及其在业务模块中的引用关系。

## 业务流程

### 业务流程图

```
用户进入 HZERO 平台 LOV 值集配置页面（LOV编码 AE.FIXUP_GRADE）
        |
        ├── 查询装修等级值项列表
        |       └── 按值编码/值名称/状态筛选
        |
        ├── 新建值项 ──→ 填写值编码、值名称、描述、排序号、开始/结束日期
        |
        ├── 编辑值项 ──→ 修改值项信息
        |
        ├── 删除值项 ──→ 确认后删除
        |
        ├── 启用/禁用值项 ──→ 切换值项启用状态
        |
        └── 装修等级被以下业务引用：
                ├── 门店装修申请（选择装修等级）
                ├── 门店验收报销（本次店面/门头装修等级）
                ├── 财务费用申请关店/变更/变更关店（门店装修等级）
                └── 门店装修标准设置（按等级配置报销标准）
```

### 上游依赖

| 上游模块 | 依赖类型 | 依赖说明 | 依赖成立条件 |
|---------|---------|---------|-------------|
| HZERO 平台 LOV 服务 | 平台服务 | 提供值集 `AE.FIXUP_GRADE` 的 CRUD 接口、值翻译接口 | HZERO 平台已部署且 LOV 服务可用 |
| HZERO 低代码平台（hlod） | 平台服务 | 页面渲染、查询栏与列表配置驱动 | 低代码页面已配置并发布 |
| HZERO 组织服务 | 平台服务 | 通过 `TAG` 字段标记值项适用的事业部（organization_id） | 多事业部场景下需配置 TAG |

### 下游影响

- **门店装修申请**：通过 `lookupCode: 'AE.FIXUP_GRADE'` 引用值集，选择门店装修等级，提交时校验是否有对应的报销政策标准。
- **门店验收报销**：选择"本次店面装修等级"和"本次门头装修等级"，匹配 `TERMINAL_DECORATE_LINE` 标准行计算补贴金额。
- **门店装修标准设置**：以装修等级为维度字段，定义不同等级对应的补贴标准（额度内/额度外单价）。
- **财务费用申请（关店/变更/变更关店）**：展示并校验门店装修等级，匹配报销政策。
- **门店主数据/网点申请单/门店变更**：作为门店属性字段，标识门店当前装修等级。

## 重点逻辑

### 重点逻辑1：LOV 值集配置

- **业务意义**：装修等级是门店管理和财务报销的核心基础数据，不同装修等级对应不同的报销标准，需统一配置和维护。
- **具体逻辑描述**：通过 HZERO 平台标准 LOV 配置界面维护值集 `AE.FIXUP_GRADE`，每个装修等级对应一个 `VALUE`（值编码）和 `MEANING`（值名称）。所有业务表中 `FIXUP_GRADE` 字段统一存储 `VALUE`（Long 类型数值），界面展示时通过 `lovService.getMeaning("AE.FIXUP_GRADE", value)` 翻译为 `MEANING`（中文含义）。

### 重点逻辑2：值编码唯一性

- **业务意义**：确保同一 LOV 下值编码不重复，避免业务引用歧义。
- **具体逻辑描述**：同一 `LOV_CODE = 'AE.FIXUP_GRADE'` 下 `VALUE` 字段唯一。新增/编辑保存时由 HZERO 平台校验，若重复提示"等级编码已存在"。

### 重点逻辑3：生效日期控制

- **业务意义**：值项可通过开始/结束日期控制生效范围，支持装修等级的版本化管理。
- **具体逻辑描述**：值项配置 `START_DATE` 和 `END_DATE`，业务查询时仅返回当前日期在生效范围内的值项，过期或未生效的值项不在下拉列表中展示。

### 重点逻辑4：排序号控制

- **业务意义**：控制值项在下拉列表中的展示顺序，提升用户选择体验。
- **具体逻辑描述**：通过 `ORDER_SEQ` 字段控制值项展示顺序，查询时按 `ORDER_SEQ` 升序排列。

### 重点逻辑5：多事业部适配

- **业务意义**：支持不同事业部自定义装修等级的值和含义。
- **具体逻辑描述**：当前所有事业部共用同一套 `VALUE → MEANING` 映射，通过 `TAG` 字段区分适用的事业部（`organization_id`）。如需支持不同事业部自定义，需在 Java 翻译层增加 `organizationId` 参数，并调整值集配置方式。

#### 按钮1：新建（列表工具栏）

**触发条件**：点击"新建"按钮

**执行逻辑**：
1. 打开新建值项弹窗/抽屉
2. 填写值编码、值名称、描述、排序号、开始/结束日期
3. 保存时校验值编码唯一性、必填项
4. 调用 HZERO 平台 LOV 服务新增接口写入 `HPFM_LOV_VALUE` 表

#### 按钮2：编辑（列表行操作）

**触发条件**：选择一条数据点击"编辑"

**执行逻辑**：
1. 打开编辑值项弹窗/抽屉，回显当前值项数据
2. 修改值项信息（值编码通常不可编辑）
3. 保存时校验必填项
4. 调用 HZERO 平台 LOV 服务更新接口更新 `HPFM_LOV_VALUE` 表

#### 按钮3：删除（列表行操作）

**触发条件**：选择一条数据点击"删除"

**执行逻辑**：
1. 弹出确认框："确定删除该装修等级吗？"
2. 确认后调用 HZERO 平台 LOV 服务删除接口
3. 检查该值项是否被业务数据引用，若被引用则提示无法删除

#### 按钮4：启用/禁用（列表行操作）

**触发条件**：选择一条数据点击"启用/禁用"

**执行逻辑**：
1. 切换 `ENABLE_FLAG` 字段值（1↔0）
2. 调用 HZERO 平台 LOV 服务更新接口
3. 禁用后该值项不在业务下拉列表中展示

- 校验1：值编码必填 —— 确保值项有唯一标识

### 报错一览表

| 报错信息 | 提示节点 | 根因与解决方案 | 等级 | 详细逻辑 |
|---------|---------|---------------|------|---------|
| 等级编码已存在 | 新增/编辑保存时 | 同一 LOV 下 `VALUE` 重复；使用不同的编码 | 错误 | 保存前查询 `HPFM_LOV_VALUE` 校验 `VALUE` 唯一性 |
| 值编码不能为空 | 新增/编辑保存时 | `VALUE` 字段未填写；填写值编码 | 错误 | 必填校验 |
| 值名称不能为空 | 新增/编辑保存时 | `MEANING` 字段未填写；填写值名称 | 错误 | 必填校验 |
| 店面装修等级没有对应的政策标准 | 门店装修申请提交时 | 装修等级未配置对应的报销政策标准；在装修标准配置中补充该等级的报销标准 | 错误 | 提交校验查询 `TERMINAL_DECORATE_LINE` 无对应标准行 |
| 无政策标准不能提交！ | 门店装修申请提交时 | `FIXUP_GRADE` 为空或 0；选择有效的装修等级 | 错误 | 提交校验 `FIXUP_GRADE` 非空非 0 |
| 店面装修等级没有有效期内的政策标准！ | 门店装修申请提交时 | 装修等级在有效期内无对应标准；检查 `TERMINAL_DECORATE_LINE` 配置 | 错误 | 提交校验精确匹配有效期内标准行无结果 |
| 值集编码不存在 | 查询时 | 值集 `AE.FIXUP_GRADE` 未创建；先在 HZERO 值集管理中创建值集 | 错误 | 查询 `HPFM_LOV` 无对应 `LOV_CODE` |
| 网络异常/接口超时 | 任意接口调用 | 网络中断或接口响应超时，检查网络及后端超时配置 | error | axios catch 或 timeout |
| 权限不足 | 点击操作按钮 | 当前用户无对应按钮权限码，联系管理员授权 | error | permissionList 校验未通过 |
| 数据不存在 | 编辑/删除 | 值项ID不存在或已删除，检查 LOV_VALUE_ID 有效性 | error | 接口返回数据为空 |
| 状态不允许操作 | 启用/禁用 | 值项状态不允许该操作，如已启用不可重复启用，检查 ENABLE_FLAG | error | 后端校验状态机失败 |
| 描述不能为空 | 保存提交 | 未填写描述，填写后保存 | error | 前端校验 DESCRIPTION 非空 |
| 排序号不能为空 | 保存提交 | 未填写排序号，填写后保存 | error | 前端校验 ORDER_SEQ 非空 |

#### 报错1：等级编码已存在
- **触发条件**：新增或编辑保存装修等级值项时，同一 LOV（AE.FIXUP_GRADE）下 VALUE 字段与已有值项重复
- **逻辑分析**：后端保存前查询 HPFM_LOV_VALUE 表，校验同一 LOV_CODE='AE.FIXUP_GRADE' 下 VALUE 唯一性，若存在重复则提示"等级编码已存在"。确保值编码唯一，避免业务引用歧义
- **排查SQL**：
  ```sql
  SELECT VALUE AS 值编码,
         COUNT(*) AS 重复数量,
         LISTAGG(MEANING, ',') WITHIN GROUP (ORDER BY LOV_VALUE_ID) AS 值名称列表
  FROM HPFM_LOV_VALUE
  WHERE LOV_CODE = 'AE.FIXUP_GRADE'
  GROUP BY VALUE
  HAVING COUNT(*) > 1;
  ```

#### 报错2：值编码不能为空
- **触发条件**：新增或编辑保存时，VALUE 字段未填写
- **逻辑分析**：前端表单对 VALUE 字段配置 required 校验，提交前校验值编码是否填写，为空则阻止提交并提示"值编码不能为空"。值编码是值项的唯一标识，业务表存储此值，必须明确
- **排查SQL**：
  ```sql
  SELECT LOV_VALUE_ID AS 值项ID,
         LOV_CODE AS LOV编码,
         VALUE AS 值编码,
         MEANING AS 值名称,
         ENABLE_FLAG AS 状态
  FROM HPFM_LOV_VALUE
  WHERE LOV_CODE = 'AE.FIXUP_GRADE'
    AND (VALUE IS NULL OR VALUE = '');
  ```

#### 报错3：值名称不能为空
- **触发条件**：新增或编辑保存时，MEANING 字段未填写
- **逻辑分析**：前端表单对 MEANING 字段配置 required 校验，提交前校验值名称是否填写，为空则阻止提交并提示"值名称不能为空"。值名称用于界面展示，必须明确
- **排查SQL**：
  ```sql
  SELECT LOV_VALUE_ID AS 值项ID,
         LOV_CODE AS LOV编码,
         VALUE AS 值编码,
         MEANING AS 值名称,
         ENABLE_FLAG AS 状态
  FROM HPFM_LOV_VALUE
  ```

#### 报错9：权限不足
- **触发条件**：点击新增、编辑、删除、启用/禁用等按钮时，当前用户无对应 permissionList 权限码
- **逻辑分析**：前端 Button 组件通过 permissionList 配置权限码，HZERO 框架校验当前用户角色是否包含该权限码，未包含则按钮不可见或禁用。若强制调用接口，后端也会校验权限返回403。需联系管理员配置对应角色权限
- **排查SQL**：
  ```sql
  SELECT U.USER_NAME AS 用户名, R.ROLE_NAME AS 角色名, P.PERMISSION_CODE AS 权限码
  FROM SYS_USER U
  LEFT JOIN SYS_USER_ROLE UR ON U.USER_ID = UR.USER_ID
  LEFT JOIN SYS_ROLE R ON UR.ROLE_ID = R.ROLE_ID
  LEFT JOIN SYS_ROLE_PERMISSION RP ON R.ROLE_ID = RP.ROLE_ID
  LEFT JOIN SYS_PERMISSION P ON RP.PERMISSION_ID = P.PERMISSION_ID
  WHERE P.PERMISSION_CODE LIKE '%fixup_grade%' ORDER BY U.USER_NAME;
  ```

## 常见问题FAQ

| 问题 | 答案/排查方式 |
|------|-------------|
| 装修等级下拉无选项 | 1. 检查值集 `AE.FIXUP_GRADE` 是否创建；2. 检查值项 `ENABLE_FLAG` 是否为 1；3. 检查当前组织是否有值集数据（`TAG` 字段） |
| 装修等级与报销标准不匹配 | 1. 检查装修标准配置中是否包含该等级；2. 在财务费用申请页面提示"店面装修等级没有对应的政策标准"时补充配置 |
| 装修等级排序不正确 | 1. 检查 `ORDER_SEQ` 字段值；2. 按期望顺序调整排序号 |
| 新增装修等级后其他页面不显示 | 1. 检查 `ENABLE_FLAG` 是否为 1（启用）；2. 检查 `START_DATE`/`END_DATE` 生效范围；3. 清除浏览器缓存刷新页面 |
| OA 推送装修等级显示数值而非中文 | 检查 `lovService.getMeaning` 翻译是否正常，确认 `HPFM_LOV_VALUE` 中有对应 `VALUE` 的 `MEANING` |
| OA 回写装修等级失败 | 检查 `lovService.getValue` 反向翻译是否正常，确认 `MEANING` 能反查到 `VALUE` |
