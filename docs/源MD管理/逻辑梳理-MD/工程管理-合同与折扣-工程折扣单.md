# 工程管理-合同与折扣-工程折扣单

---

## 业务流程

### 业务流程图

```text
开始 → ★新建工程折扣单★ → 选择政策类型 → 填写折扣信息 → 维护产品明细 → 维护客户明细 → 保存 → 提交审批 → ⚖审批通过？
  ├─（通过）折扣单生效 → 可用于工程订单折扣 → 结束
  ├─（拒绝）可修改后重新提交 → 结束
  └─（撤回）状态恢复为新建 → 可继续编辑 → 结束
```

### 上游依赖

| 上游模块 | 依赖类型 | 依赖说明 | 依赖成立条件 |
|---------|---------|---------|------------|
| 产品主档（LNK_PROD） | 数据依赖 | 产品明细选择产品 | 产品已维护 |
| 经销商主档 | 数据依赖 | 适用客户选择经销商 | 经销商已维护 |
| 价目表 | 数据依赖 | 获取产品价格 | 价目表已维护 |
| OA工作流引擎 | 服务依赖 | 提交审批触发工作流 | 工作流已配置 |
| 值集AE.EPM.POLICY_TYPE | 配置依赖 | 政策类型选择 | 值集已维护 |
| 值集HWKF.APPROVE_STATUS | 配置依赖 | 审核状态显示 | 值集已维护 |

### 下游影响

- 影响1：工程订单折扣
  - 审批通过的折扣单在工程订单中作为折扣依据

## 重点逻辑

### 重点逻辑1：工程折扣单与家装折扣政策共用后端 `共用代码`

- **业务意义**：工程折扣单与家装折扣政策申请共用EpmDiscountPolicyController，通过参数区分

- **具体逻辑描述**

  - 第1点：共用后端Controller EpmDiscountPolicyController，API路径/v1/{orgId}/epm-discount-policy

  - 第2点：工程折扣单使用工程渠道参数，家装折扣政策使用家装渠道（channel=3）

### 重点逻辑2：政策类型决定适用范围 `动态必填`

- **业务意义**：不同政策类型对应不同的适用范围字段

- **具体逻辑描述**

  - 第1点：政策类型=1（按客户）时，适用客户必填

  - 第2点：政策类型=2（按区域）时，适用区域必填

  - 第3点：政策类型=3（按客户分类）时，适用客户分类必填

  - 第4点：政策类型=4（按省份）时，适用省份必填

### 状态机

#### 状态机流转图

```text
NEW（新建） ──提交──→ RUN（审批中） ──审批通过──→ APPROVED（已审核）
                         │
                         ├──审核拒绝──→ REJECTED ──提交──→ RUN
                         └──撤回──→ NEW
```

#### 状态机列表

| 状态机名称 | 状态释义 | 可执行的操作 |
|-----------|---------|------------|
| NEW | 新建 | 编辑、保存、提交、删除 |
| RUN | 审批中 | 查看 |
| APPROVED | 已审核 | 查看 |
| REJECTED | 审核拒绝 | 编辑、保存、提交 |

#### 报错1：政策名称不能为空
- **触发条件**：保存折扣单时，DISCOUNT_POLICY_NAME字段为空
- **逻辑分析**：在保存校验中检查折扣政策头EPM_DISCOUNT_POLICY的DISCOUNT_POLICY_NAME字段，该字段为必填项(数据库定义为VARCHAR(30))。若用户未填写政策名称则弹出toast提醒。该报错为前端toast提醒级别，不阻断保存流程
- **排查SQL**：
  ```sql
  SELECT edp.DISCOUNT_POLICY_ID, edp.DISCOUNT_POLICY_CODE, edp.DISCOUNT_POLICY_NAME,
         edp.HZ_APPROVE_STATUS, edp.VALID
  FROM EPM_DISCOUNT_POLICY edp
  WHERE edp.CHANNEL = 4
    AND (edp.DISCOUNT_POLICY_NAME IS NULL OR TRIM(edp.DISCOUNT_POLICY_NAME) = '')
  ```

#### 报错2：请先维护OA系统信息

- **排查SQL**：
