# 门店管理-门店装修-门店装修额度外兑现

## 业务流程

```
门店装修额度外兑现列表页(hlod低代码页面)
        │
        ├── 新增 ──→ 选择已审批的验收报销单(LOV) ──→ 联动带出门店/经销商/报销金额
        │              ──→ 填写兑现信息(兑现金额/发票明细/资源明细) ──→ 保存
        │                                    │
        │                                    ▼
        │                              生成兑现单号(事业部编码+AE.TERMINAL_CASHOUT_CODE) ──→ HZ_APPROVE_STATUS=NEW
        │                                    │
        │                                    ▼
        │                              提交审批 ──→ 启动OA工作流(STORE_FIN_FEE_TERMINAL_RE_CASH)
        │                                    │
        │                                    ▼
        │                              OA审批流程中
        │                                    │
        │                         ├──审批通过──→ HZ_APPROVE_STATUS=APPROVED
        │                         │              ├─ 回写验收报销单兑现信息
        │                         │              ├─ 同步资金池(EBS)
        │                         │              └─ 分摊接口处理
        │                         │
        │                         └──审批驳回──→ HZ_APPROVE_STATUS=REJECTED
        │
        └── 删除 ──→ 删除兑现单及关联发票明细/资源明细
```

## 重点逻辑

### 重点逻辑1：额度外兑现金额计算

- **业务意义**：将验收报销单中额度外可报销金额实际支取出来
- **具体逻辑描述**：
  - 本次申请兑现金额(thisApplyCashoutAmt) ≤ 剩余可兑金额(thisSurCashoutAmt)
  - 税后兑现金额 = 申请兑现金额 - 发票税额
  - 发票税额 = 发票明细中各taxAmount之和
  - 不含税发票金额 = 含税发票金额 - 发票税额

### 重点逻辑2：计提年份自动带出

- **业务意义**：根据验收报销单号自动带出计提年份
- **具体逻辑描述**：
  - 若withholdingTimeYear为空，从checkBxCode截取前缀查询withholdingTimeYear
  - 截掉最后2位字符后查询数据库获取计提年份

### 重点逻辑3：发票明细与资源明细

- **业务意义**：兑现单关联发票明细和资源信息明细
- **具体逻辑描述**：
  - 发票明细(FinFeeTerminalReCashInv)：记录各发票的税额信息
  - 资源明细(FinFeeTerminalReCashLine)：记录资源信息，含税额汇总
  - 保存时自动计算发票税额合计并回写到资源明细行

### 保存校验

- 校验1：验收报销单必填 —— 确保关联有效的验收报销单
  - **详细逻辑**：前端必填校验
  - **系统体现**：C7N内置校验
  - **排查SQL**：`SELECT TERMINAL_CASHOUT_ID FROM FIN_FEE_TERMINAL_RE_CASHOUT WHERE CHECK_BX_ID IS NULL`

- 校验2：兑现金额≤剩余可兑额度 —— 防止超额兑现
  - **详细逻辑**：thisApplyCashoutAmt ≤ thisSurCashoutAmt
  - **系统体现**：前端/后端校验
  - **排查SQL**：`SELECT TERMINAL_CASHOUT_ID, THIS_APPLY_CASHOUT_AMT, THIS_SUR_CASHOUT_AMT FROM FIN_FEE_TERMINAL_RE_CASHOUT WHERE THIS_APPLY_CASHOUT_AMT > THIS_SUR_CASHOUT_AMT`

### 提交校验

- 校验1：兑现数据完整性 —— 确保发票明细和资源明细完整
  - **详细逻辑**：提交时校验发票明细和资源明细非空
  - **系统体现**：后端校验
  - **排查SQL**：`SELECT * FROM FIN_FEE_TERMINAL_RE_CASH_INV WHERE TERMINAL_CASHOUT_ID={id}`

### 状态机

```text
NEW(新建) ──提交审批──→ RUN(审批中) ──┬──审批通过──→ APPROVED(已审批)
                                       │              ├─ 回写验收报销单
                                       │              ├─ 同步资金池(EBS)
                                       │              └─ 分摊接口处理
                                       │
                                       └──审批驳回──→ REJECTED(已驳回)

任意状态 ──删除──→ (删除)
```

### 工作流

- **工作流编码**：`STORE_FIN_FEE_TERMINAL_RE_CASH`（门店装修兑现额度外）
- **编码规则**：`AE.TERMINAL_CASHOUT_CODE`（兑现单号，前缀为事业部编码divisionCode）

## 常见问题FAQ

### Q1：兑现金额超过剩余可兑额度

**根因**：thisApplyCashoutAmt > thisSurCashoutAmt
**解决方案**：调整兑现金额不超过剩余可兑额度

### Q2：计提年份未带出

**根因**：验收报销单号格式不正确或数据库中无对应计提年份记录
**解决方案**：检查验收报销单号格式，确认withholdingTimeYear查询有数据

#### 报错17：额度外预算数据不存在，请检查
- **触发条件**：doUpdateOutlimitAmt更新额度外预算时，按budYear+terminalCode查询MKT_OUTLIMIT_BUD_HEADER的selectByBudYear返回空(isEnd≠2非最终兑现时)
- **逻辑分析**：非最终兑现时需更新额度外预算剩余金额，需查询MKT_OUTLIMIT_BUD_HEADER获取预算信息。若预算数据未配置(门店+年度组合不存在)、预算数据被删除、或budYear/terminalCode不匹配，查询返回空抛异常。需核查额度外预算数据配置。
- **排查SQL**：
  ```sql
  SELECT c.terminal_code    AS 门店编码,
         c.bud_year         AS 预算年度,
         c.hz_approve_status AS 审批状态,
         NVL((SELECT COUNT(1)
              FROM   mkt_outlimit_bud_header m
              WHERE  m.terminal_code = c.terminal_code
              AND    m.bud_year = c.bud_year), 0) AS 预算记录数
  FROM   fin_fee_cashout_header c
  WHERE  c.cashout_type = 2
  AND    c.is_end <> 2
  AND    c.terminal_code IS NOT NULL
  AND    c.bud_year IS NOT NULL
  AND    NOT EXISTS (SELECT 1 FROM mkt_outlimit_bud_header m
                     WHERE  m.terminal_code = c.terminal_code
                     AND    m.bud_year = c.bud_year)
  ORDER  BY c.creation_date DESC;
  ```
