# 问题反馈-问题反馈

> **说明**：本菜单后端代码位于 `mbo-business` 微服务，API 路径前缀为 `feedback/*`。前端源码位于 `arrow-mbo/src/pages/afterSales/feedback/dealer/list.tsx`。经销商提交问题反馈，跟踪问题处理进度。

## 业务流程

### 业务流程图

```
经销商用户进入问题反馈页面
        |
        ├── 查询反馈单列表
        |       └── 按问题编号/问题类型/问题状态/提交时间筛选
        |
        ├── 新建反馈单 ──→ 跳转反馈单详情页（add模式）
        |       └── 填写问题标题、问题类型、问题描述、附件等
        |
        ├── 查看详情 ──→ 跳转反馈单详情页（detail模式）
        |
        ├── 编辑反馈单 ──→ 跳转反馈单详情页（edit模式）
        |
        ├── 删除反馈单 ──→ 确认后调用删除接口
        |
        ├── 取消反馈单 ──→ 确认后调用取消接口
        |
        ├── 重新反馈 ──→ 对已回答的问题进行追加反馈
        |
        ├── 评价 ──→ 弹出评价弹窗
        |       ├── 星级评分（1-5星）
        |       └── 评价内容
        |
        └── 导出 ──→ 导出反馈单列表到 Excel
```

### 上游依赖

| 上游模块 | 依赖类型 | 依赖说明 | 依赖成立条件 |
|---------|---------|---------|-------------|
| mbo-business 微服务 | 后端服务 | 提供反馈单 CRUD、提交、取消、评价等接口（`feedback/*`） | 微服务已部署且可用 |
| HZERO 值集平台 | 平台服务 | 提供问题类型、问题状态值集 | 值集已配置 |
| HZERO 文件服务 | 平台服务 | 附件上传与下载 | 文件服务可用 |
| HZERO 用户服务 | 平台服务 | 获取当前登录用户、经销商、门店信息 | 用户已登录 |

### 下游影响

- **事业部/品牌方问题回复**：经销商提交反馈后，事业部/品牌方可通过 `feedback/division/page` 查看并回复问题。
- **评价系统**：问题完成后经销商可对处理结果进行评价，评价数据写入 `FEEDBACK` 表。

## 重点逻辑

### 重点逻辑1：反馈单状态流转

- **业务意义**：反馈单有完整的状态生命周期，不同状态下可执行的操作不同，确保问题处理流程闭环。
- **具体逻辑描述**：状态值集 `MBO.FEEDBACK_STATE`，状态流转为：草稿→已提交→处理中→已回答→已完成；已提交→已取消。新增反馈单默认为草稿状态，提交后变为已提交，事业部回复后变为处理中/已回答，问题完成后变为已完成。

### 重点逻辑2：问题类型配置

- **业务意义**：对问题进行分类管理，便于统计分析和分派处理。
- **具体逻辑描述**：问题类型分为产品问题、订单问题、系统问题、其他。通过值集配置，前端 Select 组件加载选项。

### 重点逻辑3：评价功能

- **业务意义**：经销商对问题处理结果进行满意度评价，帮助改进服务质量。
- **具体逻辑描述**：问题状态为已完成时，经销商可弹出评价弹窗，填写星级评分（1-5星）和评价内容，提交后调用 `feedback/evaluate` 接口写入 `FEEDBACK` 表的 `GRADE` 和 `EVALUATE_CONTENT` 字段。

### 重点逻辑4：附件上传

- **业务意义**：支持经销商上传问题相关截图或文件，便于问题定位和处理。
- **具体逻辑描述**：详情页提供附件上传组件，调用 HZERO 文件服务上传文件，文件信息关联到反馈单。

2. 路由：`/afterSales/dealer/feedback/add`

#### 按钮2：导出（列表工具栏）

**触发条件**：点击"导出"按钮

**执行逻辑**：
1. 收集当前查询条件
2. 调用 `POST feedback/distributor/export` 接口导出
3. 浏览器下载 Excel 文件

#### 按钮3：编辑（列表行操作）

**触发条件**：选择 state=1（草稿）的反馈单点击"编辑"

**执行逻辑**：
1. 调用 `openTab` 打开新标签页
2. 路由：`/afterSales/dealer/feedback/edit/${id}`
3. 调用 `GET feedback/detail/${id}` 加载详情

#### 按钮4：删除（列表行操作）

**触发条件**：选择 state=1（草稿）的反馈单点击"删除"

**执行逻辑**：
1. 弹出确认框："确定删除该反馈单吗？"
2. 确认后调用 `DELETE feedback/delete/${id}` 接口
3. 成功后刷新列表

#### 按钮5：取消（列表行操作）

**触发条件**：选择 state 不在 [6,7,8] 的反馈单点击"取消"

**执行逻辑**：
1. 弹出确认框："确定取消该反馈单吗？"
2. 确认后调用 `POST feedback/cancel/${id}` 接口
3. 成功后刷新列表

#### 按钮6：评价（列表行操作）

**触发条件**：选择 state=6（已完成）的反馈单点击"评价"

**执行逻辑**：
1. 弹出评价弹窗（Modal，size=large，closable，resizable，destroyOnClose）
2. 星级评分（Rate 组件，1-5星，必填，allowHalf=false，allowClear）
3. 评价内容（TextArea，name=evaluateContent，最多500字，showLengthInfo）
4. 点击确认：
   - 校验表单 `evaluateFormDs.validate()`
   - 调用 `POST feedback/evaluate` 接口提交评价
   - 成功后刷新列表 `tableDS.query()`
5. 点击取消：重置表单 `evaluateFormDs.reset()`

### 选择弹窗

#### 弹窗1：评价弹窗

**触发条件**：在列表页选择 state=6（已完成）的反馈单点击"评价"按钮

**弹窗配置**：`Modal.open({ title: '评价', size: 'large', closable: true, resizable: true, destroyOnClose: true })`

**弹窗内容**：
- Form 组件绑定 `evaluateFormDs`（autoCreate: true）
- Rate 组件：name='grade'，allowHalf=false，allowClear，help 显示星级说明（5星=非常满意，1星=非常不满意）

**入参表格**：

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| id | Long | 是 | 反馈单ID（取自当前行记录） |
| grade | Long | 是 | 评价星级（1-5），Rate 组件 |
| evaluateContent | String | 否 | 评价内容（最多500字），TextArea 组件 |

**提交接口**：`POST feedback/evaluate`

**提交逻辑**：
1. 点击确定（onOk）：
   - 校验表单 `evaluateFormDs.validate()`

   - 成功后刷新列表 `tableDS.query()`
2. 点击取消（onCancel）：
   - 重置表单 `evaluateFormDs.reset()`

### 保存校验

- 校验1：问题标题必填 —— 确保反馈单有明确的问题概述
- 校验2：问题类型必填 —— 确保问题分类清晰，便于分派处理
- 校验3：问题描述必填 —— 确保问题内容完整，便于处理人定位问题

### 提交校验

- 校验1：问题标题必填 —— 确保反馈单有明确的问题概述
- 校验2：问题类型必填 —— 确保问题分类清晰
- 校验3：问题描述必填 —— 确保问题内容完整
- 校验4：草稿状态才能提交 —— 仅草稿状态反馈单可提交，提交后状态变为已提交

### 状态机

```
[草稿] ──提交──→ [已提交] ──事业部受理──→ [处理中] ──事业部回答──→ [已回答] ──完成──→ [已完成]
                    |
                    └──取消──→ [已取消]

[已回答] ──经销商重新反馈──→ [处理中] ──事业部回答──→ [已回答]
```

| 当前状态 | 触发动作 | 目标状态 |
|---------|---------|---------|
| 草稿 | 提交 | 已提交 |
| 草稿 | 删除 | （删除） |
| 已提交 | 事业部受理 | 处理中 |
| 已提交 | 取消 | 已取消 |
| 处理中 | 事业部回答 | 已回答 |
| 已回答 | 经销商重新反馈 | 处理中 |
| 已回答 | 完成 | 已完成 |
| 已完成 | 评价 | 已评价 |

#### 报错1：请求失败
- **触发条件**：调用 feedback/* 系列接口时，后端返回 HTTP 状态码非 2xx
- **逻辑分析**：前端通过 axios 调用后端接口，若响应状态码非 2xx 或网络异常则触发错误回调，统一提示"请求失败"。常见根因包括：mbo-business 微服务未启动或异常、数据库连接失败、SQL 执行超时、后端业务异常未捕获、文件服务异常、网络中断等。需检查 mbo-business 微服务运行状态、文件服务连通性、后端日志定位具体异常堆栈
- **排查SQL**：
  ```sql
  SELECT QUESTIONID AS 问题编号,
         TITLE AS 问题标题,
         STATE AS 问题状态,
         TO_CHAR(LAST_UPDATE_DATE,'YYYY-MM-DD HH24:MI:SS') AS 最后更新时间
  FROM FEEDBACK
  WHERE LAST_UPDATE_DATE >= SYSDATE - 1
  ORDER BY LAST_UPDATE_DATE DESC;
  ```

#### 报错2：请选择一条数据
- **触发条件**：点击编辑、删除、取消、重新反馈、评价等行操作按钮时，未选择数据或选择了多行
- **逻辑分析**：前端在执行单选操作前校验选中行数量，若 selectedRows.length ≠ 1 则阻止操作并提示"请选择一条数据"。单选操作需要明确的目标反馈单，未选择时无法确定操作对象，多选时操作对象不唯一
- **排查SQL**：
  ```sql
  SELECT QUESTIONID AS 问题编号,
         TITLE AS 问题标题,
         TYPE_CODE AS 问题类型,
         STATE AS 问题状态,
         CREATE_NAME AS 提交人
  FROM FEEDBACK
  ORDER BY CREATE_TIME DESC;
  ```


#### 报错10：权限不足
- **触发条件**：点击新建、编辑、删除、取消、重新反馈、评价等按钮时，当前用户无对应 permissionList 权限码
- **逻辑分析**：前端 Button 组件通过 permissionList 配置权限码，HZERO 框架校验当前用户角色是否包含该权限码，未包含则按钮不可见或禁用。若强制调用接口，后端也会校验权限返回403。需联系管理员配置对应角色权限
- **排查SQL**：
  ```sql
  SELECT U.USER_NAME AS 用户名, R.ROLE_NAME AS 角色名, P.PERMISSION_CODE AS 权限码
  FROM SYS_USER U
  LEFT JOIN SYS_USER_ROLE UR ON U.USER_ID = UR.USER_ID
  LEFT JOIN SYS_ROLE R ON UR.ROLE_ID = R.ROLE_ID
  LEFT JOIN SYS_ROLE_PERMISSION RP ON R.ROLE_ID = RP.ROLE_ID
  LEFT JOIN SYS_PERMISSION P ON RP.PERMISSION_ID = P.PERMISSION_ID
  WHERE P.PERMISSION_CODE LIKE '%feedback%' ORDER BY U.USER_NAME;
  ```

#### 报错11：数据不存在
- **触发条件**：编辑、删除、取消等操作时，接口返回数据为空或问题编号不存在
- **逻辑分析**：前端通过 questionId 调用接口，后端查询 FEEDBACK 表无对应记录或记录已逻辑删除，返回空数据。常见根因：问题编号错误、反馈单已被删除、跨租户查询、数据权限隔离等。需检查 QUESTIONID 有效性及数据权限
- **排查SQL**：
  ```sql
  SELECT QUESTIONID AS 问题编号, TITLE AS 问题标题, STATE AS 问题状态,
         DELETE_FLAG AS 删除标记
  FROM FEEDBACK
  WHERE DELETE_FLAG = 'Y' OR QUESTIONID IS NULL;
  ```

#### 报错12：状态不允许操作
- **触发条件**：点击删除、取消、重新反馈等按钮时，反馈单状态不允许该操作
- **逻辑分析**：后端校验状态机，如删除要求 STATE=0（草稿）、取消要求 STATE=1（已提交）、重新反馈要求 STATE=3（已回答）等。状态不匹配时后端返回业务异常。需检查反馈单当前状态及操作流程
- **排查SQL**：
  ```sql
  SELECT QUESTIONID AS 问题编号, TITLE AS 问题标题, STATE AS 问题状态,
         ERROR_INFO AS 异常问题
  FROM FEEDBACK
  WHERE STATE NOT IN (0,1,2,3,4,5)
  ORDER BY CREATE_TIME DESC;
  ```

#### 报错13：值集数据不显示
- **触发条件**：查询条件或列表中问题类型等下拉选项为空
- **逻辑分析**：前端通过 lookupCode 查询值集 MBO.FEEDBACK_TYPE、MBO.FEEDBACK_STATE 等，值集未配置或未启用则下拉选项为空。需在值集管理页面配置对应值集
- **排查SQL**：
  ```sql
  SELECT LOOKUP_CODE AS 值集编码, LOOKUP_VALUE_CODE AS 值编码,
         LOOKUP_VALUE_NAME AS 值名称, ENABLE_FLAG AS 启用标记
  FROM SYS_LOOKUP_VALUE
  WHERE LOOKUP_CODE IN ('MBO.FEEDBACK_TYPE','MBO.FEEDBACK_STATE')
    AND ENABLE_FLAG = 'N' ORDER BY LOOKUP_CODE;
  ```

#### 报错14：附件上传失败
- **触发条件**：上传反馈单附件时，OSS 上传抛错或上传成功但响应无 fileUrl
- **逻辑分析**：前端上传组件 onUploadError 钩子捕获上传异常提示"上传失败"，onUploadSuccess 钩子校验响应 fileUrl 字段，为空则提示"上传失败"。常见根因：OSS 存储服务不可用、bucketName 配置错误、文件格式不被接受、网络中断等
- **排查SQL**：
  ```sql
  SELECT QUESTIONID AS 问题编号, FILE_NAME AS 文件名,
         FILE_URL AS 文件地址, ERROR_INFO AS 异常信息
  FROM FEEDBACK_FILE
  WHERE FILE_URL IS NULL OR ERROR_INFO IS NOT NULL
  ORDER BY CREATION_DATE DESC;
  ```

#### 报错15：评价星级不能为空
- **触发条件**：提交评价时，STAR_LEVEL 字段为空
- **逻辑分析**：前端评价弹窗对 starLevel 字段配置 required 校验，提交前校验评价星级是否选择，为空则阻止提交并提示"评价星级不能为空"。评价星级用于量化反馈处理质量，必须明确

### 排查SQL汇总

```sql
-- 1. 查询反馈单列表
SELECT QUESTIONID, TITLE, TYPE_CODE, STATE,
       CREATE_TIME, ANSWER_TIME, CREATE_NAME, ANSWER_NAME,
       GRADE, EVALUATE_CONTENT, DISTRIBUTOR_NAME
FROM FEEDBACK
WHERE QUESTIONID = :questionId
ORDER BY CREATE_TIME DESC;

-- 2. 查询未评价的已完成反馈单
SELECT QUESTIONID, TITLE, CONTENT, ANSWER_TIME, CREATE_NAME
FROM FEEDBACK
WHERE STATE = :completedState
  AND GRADE IS NULL
ORDER BY ANSWER_TIME DESC;

-- 3. 查询某经销商的反馈单
SELECT QUESTIONID, TITLE, STATE, CREATE_TIME
FROM FEEDBACK
WHERE DISTRIBUTOR_NAME = :distributorName
ORDER BY CREATE_TIME DESC;

-- 4. 校验问题编号唯一性
SELECT QUESTIONID, COUNT(*) AS cnt
FROM FEEDBACK
GROUP BY QUESTIONID
HAVING COUNT(*) > 1;
```
