# 门店管理-门店报表-额度外占用预算明细

> 本页面为低代码页面(hlod)，无独立前端源码，基于后端API梳理。

## 业务流程

额度外占用预算明细报表用于查询额度外预算的占用明细，包括占用金额、预算年度、申请单号、门店信息、经销商信息等。数据来源于占用金额视图（VIEW_OCCUPY_AMT）和大客户报销/兑付表（CUST_DH_REIMBURSE_HEAD/CUST_DH_CASHOUT_HEAD），通过4段UNION ALL分别统计终端费用申请占用、兑付占用、兑付超额占用、大客户DH报销占用。本页面为纯查询报表，仅支持查看和导出，不支持新增、修改、删除等写操作。

**核心流程：**
1. 用户进入额度外占用预算明细报表页面
2. 填写查询条件（事业部、预算年度、门店编码、经销商编码、开票单位编码、交易公司编码等）
3. 点击查询，调用后端接口分页返回额度外占用预算明细数据
4. 用户查看报表数据，可导出Excel归档（标题"额度外占用预算明细"）

```
开始 → 设定查询条件 → 点击查询 → 后端4段UNION ALL查询(view_occupy_amt + CUST_DH_REIMBURSE_HEAD + CUST_DH_CASHOUT_HEAD) → 过滤occupy_amt>0 → 返回占用明细 → 查看报表/导出Excel → 结束
```

- 上游支撑：占用金额视图（VIEW_OCCUPY_AMT）、大客户报销头表（CUST_DH_REIMBURSE_HEAD）、大客户兑付头表（CUST_DH_CASHOUT_HEAD）、客户（CUSTOMER）、客户法人（CUSTOMER_LEGAL_ENTITY）、事业部基础设置（DIVISION_BASE_SET）、交易公司（EPM_TRADING_COMPANY）、hlod报表引擎
- 下游影响：额度外预算占用分析、预算执行情况监控、Excel导出归档、内部管理决策参考

## 重点逻辑

### 重点逻辑1：纯报表查询页面【只读查询】

- **业务意义**：供内部人员查询额度外预算的占用明细，了解预算执行情况
- **具体逻辑描述**：
  - 本页面为hlod低代码报表页面，无独立前端源码
  - 仅提供查询和导出功能，不支持新增、修改、删除操作
  - 数据来源于4段UNION ALL查询，覆盖终端和大客户两类业务

### 重点逻辑2：4段UNION ALL统计逻辑

- **业务意义**：分别统计4种不同业务场景的额度外预算占用
- **具体逻辑描述**：
  - 第1段（终端费用申请占用）：`view_occupy_amt`视图，条件 `(afh_stat='APPROVED' or afh_stat='RUN') and cbh_stat='NEW'`，占用金额=out_apply_amt
  - 第2段（兑付占用）：`view_occupy_amt`视图，条件 `cbh_stat='RUN'`，占用金额=out_can_bx_amt
  - 第3段（兑付超额占用）：`view_occupy_amt`视图，条件 `trc_stat='APPROVED'`，占用金额=out_sur_bx_amt
  - 第4段（大客户DH报销占用）：`CUST_DH_REIMBURSE_HEAD` + `CUST_DH_CASHOUT_HEAD`，条件 `HZ_APPROVE_STATUS IN ('RUN','APPROVED','REBUT')`，占用金额=报销额度外金额-已申请兑付金额

### 重点逻辑3：大客户DH报销占用计算

- **业务意义**：计算大客户门头报销的额度外占用金额
- **具体逻辑描述**：
  - 报销占用：`NVL(OUT_BX_AMT, 0) - (SELECT NVL(SUM(OUT_CASHOUT_APPLY_AMT), 0) FROM CUST_DH_CASHOUT_HEAD WHERE REIMBURSE_HEAD_ID=t.ID AND HZ_APPROVE_STATUS IN ('RUN','REBUT'))`
  - 即：报销额度外金额 - 已申请兑付金额（审批中或已驳回的）
  - 跨年度兑付占用：`CUST_DH_CASHOUT_HEAD`中`YEAR <> CUST_DH_REIMBURSE_HEAD.YEAR`的记录，占用金额=OUT_CASHOUT_APPLY_AMT

### 重点逻辑4：只展示占用金额大于0的记录

- **业务意义**：过滤掉占用金额为0或负数的记录，只展示实际有占用的明细
- **具体逻辑描述**：
  - 外层统一过滤条件：`bod.occupy_amt > 0`
  - 确保报表只展示有实际预算占用的记录

### 重点逻辑5：查询条件匹配规则

- **业务意义**：支持多维度灵活筛选额度外占用预算明细
- **具体逻辑描述**：
  - 精确查询：预算年度、门店编码、经销商编码、开票单位编码、交易公司编码
  - 事业部ID通过子查询转换：`bod.division_id = (SELECT dbs.division_id FROM division_base_set dbs WHERE dbs.organization_id = #{divisionId})`
  - 注意：DTO中organizationId字段在SQL中未使用

### 后端接口Mapper SQL

```sql
-- 额度外占用预算明细查询（4段UNION ALL）
SELECT * FROM (
    -- 第1段：终端费用申请占用
    SELECT voa.out_apply_amt AS occupy_amt, voa.bud_year, voa.afh_audit_stat AS audit_stat,
           voa.terminal_apply_no AS apply_code, voa.afh_create_time AS apply_time,
           voa.terminal_code, voa.terminal_name, voa.cust_code, voa.cust_name,
           voa.billing_unit_code, voa.billing_unit_name, voa.trading_company_code, voa.trading_company_name,
           voa.division_id, voa.division_name
    FROM epms.view_occupy_amt voa
    WHERE (voa.afh_stat = 'APPROVED' OR voa.afh_stat = 'RUN') AND (voa.cbh_stat = 'NEW')

    UNION ALL
    -- 第2段：兑付占用
    SELECT voa.out_can_bx_amt AS occupy_amt, voa.bud_year, voa.cbh_audit_stat AS audit_stat,
           voa.check_bx_code AS apply_code, voa.cbh_create_time AS apply_time,
           voa.terminal_code, voa.terminal_name, voa.cust_code, voa.cust_name,
           voa.billing_unit_code, voa.billing_unit_name, voa.trading_company_code, voa.trading_company_name,
           voa.division_id, voa.division_name
    FROM epms.view_occupy_amt voa
    WHERE voa.cbh_stat = 'RUN'

    UNION ALL
    -- 第3段：兑付超额占用
    SELECT voa.out_sur_bx_amt AS occupy_amt, voa.bud_year, voa.trc_audit_stat AS audit_stat,
           voa.terminal_cashout_code AS apply_code, voa.trc_create_time AS apply_time,
           voa.terminal_code, voa.terminal_name, voa.cust_code, voa.cust_name,
           voa.billing_unit_code, voa.billing_unit_name, voa.trading_company_code, voa.trading_company_name,
           voa.division_id, voa.division_name
    FROM epms.view_occupy_amt voa
    WHERE voa.trc_stat = 'APPROVED'

    UNION ALL
    -- 第4段：大客户DH报销占用
    SELECT dh_occupy.occupy_amt, dh_occupy.bud_year, dh_occupy.audit_stat, dh_occupy.apply_code, dh_occupy.apply_time,
           NULL AS terminal_code, NULL AS terminal_name,
           cus.CUSTOMER_CODE AS cust_code, cus.CUSTOMER_NAME AS cust_name,
           cus_legal.LEGAL_ENTITY_CODE AS billing_unit_code, cus_legal.LEGAL_ENTITY_NAME AS billing_unit_name,
           company.TRADING_COMPANY_CODE AS trading_company_code, cus_legal.trading_company_name AS trading_company_name,
           ent.division_id, ent.DIVISION_NAME AS division_name
    FROM (
        -- 大客户报销占用
        SELECT NVL(t.OUT_BX_AMT, 0) - (
            SELECT NVL(SUM(OUT_CASHOUT_APPLY_AMT), 0) FROM epms.CUST_DH_CASHOUT_HEAD cashout
            WHERE cashout.REIMBURSE_HEAD_ID = t.ID AND cashout.HZ_APPROVE_STATUS IN ('RUN','REBUT')
        ) AS occupy_amt,
        to_char(t.YEAR) AS bud_year, t.AUDIT_STAT AS audit_stat, t.REIMBURSE_CODE AS apply_code, t.CREATED AS apply_time,
        t.CUSTOMER_ID AS customer_id, t.CUSTOMER_LEGAL_ID AS customer_legal_id, t.ENTID AS entid
        FROM epms.CUST_DH_REIMBURSE_HEAD t
        WHERE t.HZ_APPROVE_STATUS IN ('RUN','APPROVED','REBUT')

        UNION ALL
        -- 跨年度兑付占用
        SELECT NVL(t.OUT_CASHOUT_APPLY_AMT, 0) AS occupy_amt,
        to_char(t.YEAR) AS bud_year, t.AUDIT_STAT AS audit_stat, t.CASHOUT_NO AS apply_code, t.CREATED AS apply_time,
        t.CUSTOMER_ID AS customer_id, t.CUSTOMER_LEGAL_ID AS customer_legal_id, t.ENTID AS division_id
        FROM epms.CUST_DH_CASHOUT_HEAD t
        LEFT JOIN epms.CUST_DH_REIMBURSE_HEAD t2 ON t.REIMBURSE_HEAD_ID = t2.ID
        WHERE t.HZ_APPROVE_STATUS IN ('RUN','REBUT') AND t.YEAR <> t2.YEAR
    ) dh_occupy
    LEFT JOIN epms.CUSTOMER cus ON cus.CUSTOMER_ID = dh_occupy.customer_id
    LEFT JOIN epms.CUSTOMER_LEGAL_ENTITY cus_legal ON cus_legal.REL_ID = dh_occupy.customer_legal_id
    LEFT JOIN epms.DIVISION_BASE_SET ent ON dh_occupy.entid = ent.ORGANIZATION_ID
    LEFT JOIN epms.EPM_TRADING_COMPANY company ON cus_legal.TRADING_COMPANY_ID = company.TRADING_COMPANY_ID
) bod
WHERE bod.occupy_amt > 0                                       -- 只展示占用金额>0的记录
    AND bod.division_id = (SELECT dbs.division_id FROM division_base_set dbs WHERE dbs.organization_id = #{divisionId})  -- 事业部ID
    AND bod.bud_year = #{budYear}                              -- 预算年度（精确）
    AND bod.terminal_code = #{terminalCode}                    -- 门店编码（精确）
    AND bod.cust_code = #{custCode}                            -- 经销商编码（精确）
    AND bod.billing_unit_code = #{billingUnitCode}             -- 开票单位编码（精确）
    AND bod.trading_company_code = #{tradingCompanyCode}       -- 交易公司编码（精确）
```

#### 报错1：查询结果为空
- **触发条件**：点击"查询"按钮，按当前查询条件（事业部、预算年度、门店编码、经销商编码、开票单位编码、交易公司编码等）查询4段UNION ALL返回空结果集
- **逻辑分析**：报表通过4段UNION ALL分别统计终端费用申请占用（VIEW_OCCUPY_AMT，afh_stat=APPROVED/RUN且cbh_stat=NEW）、兑付占用（cbh_stat=RUN）、兑付超额占用（trc_stat=APPROVED）、大客户DH报销占用（CUST_DH_REIMBURSE_HEAD+CUST_DH_CASHOUT_HEAD，HZ_APPROVE_STATUS IN RUN/APPROVED/REBUT），外层过滤occupy_amt>0。若查询条件过严、或所有占用金额<=0被过滤、或预算年度下无占用记录、或事业部ID通过子查询转换失败（DIVISION_BASE_SET无匹配），均会返回空结果。该报错为提示性。
- **排查SQL**：
  ```sql
  SELECT bud_year            AS 预算年度,
         division_id         AS 事业部ID,
         occupy_amt          AS 占用金额,
         apply_code          AS 申请单号,
         cust_code           AS 经销商编码
  FROM   view_occupy_amt
  WHERE  occupy_amt > 0
  ORDER  BY bud_year DESC;
  ```

#### 报错2：大客户DH报销占用计算异常
- **触发条件**：查询结果展示时，CUST_DH_CASHOUT_HEAD中存在REIMBURSE_HEAD_ID关联不到CUST_DH_REIMBURSE_HEAD的记录，LEFT JOIN导致t2.YEAR为NULL
- **逻辑分析**：第4段UNION ALL计算大客户DH报销占用时，通过LEFT JOIN CUST_DH_CASHOUT_HEAD关联CUST_DH_REIMBURSE_HEAD，并计算跨年度兑付占用（`t.YEAR <> t2.YEAR`）。若CUST_DH_CASHOUT_HEAD.REIMBURSE_HEAD_ID指向已删除的报销单（孤儿数据）、或REIMBURSE_HEAD_ID字段值错误、或数据迁移产生脏数据，LEFT JOIN后t2（报销单）字段为NULL，`t.YEAR <> t2.YEAR`条件中NULL参与比较结果为UNKNOWN，导致跨年度兑付占用金额计算错误（漏统计或错统计），报表数据异常。
- **排查SQL**：
  ```sql
  SELECT c.cashout_no            AS 兑付单号,
         c.reimburse_head_id     AS 关联报销单ID,
         c.year                  AS 兑付年度,
         c.out_cashout_apply_amt AS 额度外兑付申请金额,
         c.hz_approve_status     AS 审批状态
  FROM   cust_dh_cashout_head c
  LEFT   JOIN cust_dh_reimburse_head t ON c.reimburse_head_id = t.id
  WHERE  c.reimburse_head_id IS NOT NULL
  AND    t.id IS NULL
  ORDER  BY c.created DESC;
  ```

#### 报错3：网络请求失败/接口调用异常
- **触发条件**：点击"查询"或"导出"按钮，调用POST /v1/{organizationId}/terminalReport/bud-over-budget-report/search或GET /bud-over-budget-report/export接口时，前端未收到响应或收到非2xx状态码（如500、502、504）
- **逻辑分析**：本页面为hlod低代码报表页面，查询依赖后端TerminalReportController.budOverBudgetSearch接口分页查询4段UNION ALL（VIEW_OCCUPY_AMT视图+CUST_DH_REIMBURSE_HEAD+CUST_DH_CASHOUT_HEAD）。若后端ae-report服务未启动、Oracle数据库连接异常、VIEW_OCCUPY_AMT视图编译错误、4段UNION ALL导致慢SQL、子查询division_base_set转换失败、网络中断、或网关转发失败，均会导致接口调用异常。因UNION ALL结构复杂，该接口对数据库性能敏感。需检查后端服务健康状态、数据库连接、视图状态、网络连通性。
- **排查SQL**：
  ```sql
  SELECT COUNT(*)            AS 占用记录总数
  FROM   view_occupy_amt
  WHERE  out_apply_amt > 0
  OR     out_can_bx_amt > 0
  OR     out_sur_bx_amt > 0;
  ```

#### 报错4：权限不足/未登录
- **触发条件**：页面加载或点击"查询"/"导出"按钮时，接口返回401未授权或403禁止访问，或前端路由守卫拦截
- **逻辑分析**：本报表接口声明@Permission(level = ResourceLevel.ORGANIZATION)，要求用户具备组织级权限。若用户未登录（token过期/丢失）、或当前角色未分配该报表菜单权限、或organizationId路径参数与用户所属组织不匹配，均会触发权限校验失败。hlod低代码页面通过路由配置和接口权限双重校验，任一环节失败均阻断访问。需重新登录或联系管理员分配报表查看权限。
- **排查SQL**：
  ```sql
  SELECT '权限校验为应用层逻辑，无对应数据表' AS 提示
  FROM   dual;
  ```

#### 报错5：导出失败：网络异常
- **触发条件**：点击"导出"按钮，调用GET /v1/{organizationId}/terminalReport/bud-over-budget-report/export接口过程中，网络中断、后端响应超时或Excel文件流传输中断
- **逻辑分析**：导出接口通过@ExcelExport(value = BudOverBudgetExportVO.class, asyncThreshold = 10000)注解实现Excel导出，超过1万条数据异步导出。后端先全量查询4段UNION ALL数据再生成Excel文件流返回。若查询数据量较大导致响应超时、或异步导出任务排队失败、或生成Excel过程中内存溢出、或网络不稳定导致文件流中断、或浏览器下载被拦截，均会触发导出失败。需重试导出或缩小查询条件（如限定预算年度、事业部）减少数据量。
- **排查SQL**：
  ```sql
  SELECT bud_year            AS 预算年度,
         COUNT(*)            AS 占用记录数
  FROM   view_occupy_amt
  WHERE  out_apply_amt > 0
  GROUP  BY bud_year
  ORDER  BY bud_year DESC;
  ```

## 常见问题FAQ

**Q1：报表数据来源是什么？**
A：数据来源于4段UNION ALL查询：前3段查询`VIEW_OCCUPY_AMT`视图（终端费用申请/兑付/超额占用），第4段查询`CUST_DH_REIMBURSE_HEAD`和`CUST_DH_CASHOUT_HEAD`（大客户DH报销/兑付占用）。

**Q2：4段UNION ALL分别对应什么业务？**
A：第1段-终端费用申请占用(afh_stat=APPROVED/RUN且cbh_stat=NEW)，第2段-兑付占用(cbh_stat=RUN)，第3段-兑付超额占用(trc_stat=APPROVED)，第4段-大客户DH报销占用(HZ_APPROVE_STATUS=RUN/APPROVED/REBUT)。

**Q3：为什么只展示占用金额>0的记录？**
A：外层过滤条件`bod.occupy_amt > 0`，确保报表只展示有实际预算占用的记录，排除占用金额为0或负数的记录。

**Q4：导出Excel的标题是什么？**
A：标题为"额度外占用预算明细"，超过1万条数据时异步导出。

**Q5：报表是否支持新增/修改/删除？**
A：不支持，本页面为纯查询报表，仅支持查看和导出。
