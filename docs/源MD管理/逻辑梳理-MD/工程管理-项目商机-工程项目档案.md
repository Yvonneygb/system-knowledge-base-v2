# 工程管理-项目商机-工程项目档案

> 本页面为低代码页面(hlod)，无独立前端源码，基于后端API梳理。后端Controller为EpmProjectController（API: `/v1/{organizationId}/epm-projects`）提供detail接口，EpmProjectManagerController（API: `/v1/{organizationId}/epm-project-manager`）提供校验接口。核心表为EPM_PROJECT（项目档案表）。本页面为只读查看页面，数据由上游模块（报备审批通过、进度更新、冻结/解冻等）自动写入。

## 业务流程

```
用户进入工程项目档案页面
  → 填写查询条件（项目编码、项目名称、客户名称、报备类型、项目状态等）
  → 调用项目档案列表接口（POST /report/getReportList）
  → 点击某条记录查看详情
  → 调用项目信息明细接口（GET /epm-projects/{projectId}/detail）
  → 系统返回项目完整信息（含报备信息、合同信息、阶段信息、授权信息等）

数据写入流程（由上游模块触发）：
  → 报备审批通过 → doSendMonomerProject → INSERT/UPDATE EPM_PROJECT
  → 项目进度更新 → doMotionUpdate → UPDATE EPM_PROJECT + INSERT EPM_PROJECT_STAGE
  → 项目冻结 → 定时任务 → UPDATE EPM_PROJECT(FREEZE_TYPE/FREEZE_TIME)
  → 项目解冻 → 解冻审批通过 → UPDATE EPM_PROJECT(UNFREEZE_TIME)
  → 项目失效 → 失效审批通过 → UPDATE EPM_PROJECT(PROJECT_VALID=3)
  → 合同签订确认 → UPDATE EPM_PROJECT(合同信息回写)
```

## 重点逻辑

### 重点逻辑1：报备审核写入项目档案

- **业务意义**：报备审批通过后生成正式项目档案，作为项目唯一权威数据源
- **具体逻辑描述**：
  - 1、首次报备：将报备数据转换为EpmProject对象，设置PROJECT_VALID=2(已生效)，VALID_START_DATE=当前时间，VALID_END_DATE=VALID_START_DATE+项目有效周期天数(系统参数Proj_Effective_Cycle)，INSERT到EPM_PROJECT
  - 2、二次报备：根据PROJECT_ID查询已有项目档案并UPDATE，更新报备时间、阶段、交易公司、甲乙方、项目名称等字段
  - 3、字段校验：写入前检查EPM_PROJECT表是否存在报备表缺少的字段，若缺失则抛错
  - 4、项目授权同步：审核通过后先删除原有授权记录，再批量插入新授权记录
  - 5、乙方信息同步：审核通过后先删除原有乙方记录，再批量插入新乙方记录

### 重点逻辑2：项目进度更新写入档案

- **业务意义**：项目阶段变更时同步更新档案，记录阶段历程
- **具体逻辑描述**：
  - 1、阶段变更校验：新阶段序号必须大于等于旧阶段序号，否则报错"阶段更新，只能前进，不能后退"
  - 2、并发校验：若单据中当前进度与项目档案中的进度不一致，报错"项目进度已变更，请驳回重审!"
  - 3、更新字段：STAGE_DESC、STAGE_ID、STAGE_NAME、STAGE_NOTE
  - 4、阶段历程记录：每次阶段变更同时INSERT一条EPM_PROJECT_STAGE记录

### 重点逻辑3：项目冻结机制

- **业务意义**：超期未签合同或进度超时的项目自动冻结，防止长期占用商机
- **具体逻辑描述**：
  - 1、自动冻结：系统定时任务检测项目有效期超期或进度更新超时，自动将PROJECT_VALID置为4(已冻结)
  - 2、冻结类型FREEZE_TYPE：1=超项目有效期(有效期内未签合同)；2=进度超时更新；4=有效期内已签合同但超期
  - 3、有效周期通过系统参数Proj_Effective_Cycle配置

### 重点逻辑4：项目解冻逻辑

- **业务意义**：冻结的项目可通过解冻申请恢复生效
- **具体逻辑描述**：
  - 1、解冻申请审批通过后，更新PROJECT_VALID=2(已生效)，FREEZE_TYPE=0，记录UNFREEZE_TIME
  - 2、解冻时若进度阶段与档案不一致，同步更新档案进度

### 重点逻辑5：项目失效/恢复逻辑

- **业务意义**：项目可主动失效和恢复，管理项目生命周期
- **具体逻辑描述**：
  - 1、失效：失效申请审批通过后，PROJECT_VALID=3(已失效)，记录CHANGE_VALID_USER/CHANGE_VALID_TIME/CHANGE_VALID_REASON
  - 2、恢复生效：恢复申请审批通过后，PROJECT_VALID=2(已生效)，重新计算有效期

### 重点逻辑6：合同信息回写

- **业务意义**：合同签订确认时将合同信息回写到项目档案，保持数据一致
- **具体逻辑描述**：
  - 1、项目合同签订确认时，回写以下字段至项目档案：CONTRACT_CODE、CONTRACT_AMOUNT、PERFORMANCE_SECURITY、GUARANTEE_AMOUNT、GUARANTEE_PERIOD、CONTRACT_SIGNUP_DATE、PERIOD_START_DATE、PERIOD_END_DATE

#### 报错1：查询条件不能为空
- **触发条件**：查询项目档案列表时，所有查询条件(项目编码/名称/客户/状态等)均为空
- **逻辑分析**：查询接口校验至少需输入一个查询条件，因项目档案数据量大，强制要求至少一个过滤条件以避免全表扫描。该报错为阻断性报错
- **排查SQL**：
  ```sql
  SELECT COUNT(*) AS 项目档案总量
  FROM EPM_PROJECT ep
  WHERE ep.PROJECT_VALID IN (1, 2, 3, 4)
  -- 评估全表数据量，确认需缩小查询范围
  ```

#### 报错2：项目数据不存在
- **触发条件**：查询项目档案详情(detail接口)时，根据projectId未查到EPM_PROJECT记录
- **逻辑分析**：detail接口按PROJECT_ID查询EPM_PROJECT，若返回null则抛出阻断性报错。可能原因：项目ID不存在、项目已被物理删除、ID类型转换异常
- **排查SQL**：
  ```sql
  SELECT ep.PROJECT_ID, ep.PROJECT_CODE, ep.PROJECT_NAME, ep.PROJECT_VALID, ep.STAGE_ID
  FROM EPM_PROJECT ep
  WHERE ep.PROJECT_ID = :projectId
  -- 若返回空，说明项目ID不存在
  ```

#### 报错3：项目档案表（epm_project）缺失以下字段：xxx
- **触发条件**：报备审核时，EPM_PROJECT表结构与EPM_REPORT不一致，存在EPM_REPORT有但EPM_PROJECT无的字段
- **逻辑分析**：报备审核时按字段名比对EPM_REPORT与EPM_PROJECT表结构，将EPM_REPORT独有的字段收集到缺失列表并抛出阻断性报错。需DBA补齐EPM_PROJECT表缺失字段
- **排查SQL**：
  ```sql
  SELECT atc.COLUMN_NAME, atc.DATA_TYPE, atc.DATA_LENGTH
  FROM ALL_TAB_COLUMNS atc
  WHERE atc.TABLE_NAME = 'EPM_REPORT'
    AND atc.OWNER = :schemaOwner
    AND atc.COLUMN_NAME NOT IN (
        SELECT atc2.COLUMN_NAME
        FROM ALL_TAB_COLUMNS atc2
        WHERE atc2.TABLE_NAME = 'EPM_PROJECT'
          AND atc2.OWNER = :schemaOwner
    )
  ORDER BY atc.COLUMN_NAME
  ```

#### 报错4：项目进度已变更，请驳回重审!
- **触发条件**：项目进度更新时，单据进度stageValueBefore与项目档案当前STAGE_ID不一致(并发场景)
- **逻辑分析**：doUpdate方法中查询EPM_PROJECT获取当前STAGE_ID，若stageValueBefore > 当前STAGE_ID说明项目进度已被其他单据变更，当前单据基于旧进度提交，需驳回重审
- **排查SQL**：
  ```sql
  SELECT ep.PROJECT_ID, ep.PROJECT_CODE, ep.STAGE_ID AS 当前阶段ID, ep.STAGE_NAME,
         ep.PROJECT_VALID, ep.LAST_UPDATE_DATE
  FROM EPM_PROJECT ep
  WHERE ep.PROJECT_ID = :projectId
  -- 对比单据的stageValueBefore与项目当前STAGE_ID
  ```

#### 报错5：阶段更新，只能前进，不能后退
- **触发条件**：项目进度更新时，新选择阶段的SEQ小于当前阶段的SEQ
- **逻辑分析**：doUpdate方法中查询EPM_STAGE_DEF获取新旧阶段SEQ，若newStage.seq < oldStage.seq则抛出阻断性报错。项目阶段代表里程碑，不允许倒退
- **排查SQL**：
  ```sql
  SELECT esd.STAGE_ID, esd.STAGE_NAME, esd.SEQ, esd.ORGANIZATION_ID
  FROM EPM_STAGE_DEF esd
  WHERE esd.ORGANIZATION_ID = :organizationId
  ORDER BY esd.SEQ
  -- 对比新阶段与当前阶段的SEQ
  ```

#### 报错6：请配置{orgId}公司参数'Proj_Effective_Cycle'
- **触发条件**：报备审核时，SYS_PARAM表中未配置PARAM_CODE='Proj_Effective_Cycle'的系统参数
- **逻辑分析**：报备审核时按ORGANIZATION_ID和PARAM_CODE='Proj_Effective_Cycle'查询SYS_PARAM，若为空则抛出阻断性报错。该参数用于计算项目有效周期天数，缺失则无法确定项目过期时间
- **排查SQL**：
  ```sql
  SELECT sp.PARAM_ID, sp.PARAM_CODE, sp.PARAM_NAME, sp.VALUE, sp.ORGANIZATION_ID
  FROM SYS_PARAM sp
  WHERE sp.PARAM_CODE = 'Proj_Effective_Cycle'
    AND sp.ORGANIZATION_ID = :orgId
  -- 若返回空，则需在SYS_PARAM表中补充配置
  ```

#### 报错7：战略经理变更申请明细行不存在！
- **触发条件**：战略经理变更申请时，变更申请明细行查询为空
- **逻辑分析**：在EpmProjectManagerServiceImpl方法中校验，战略经理变更申请需关联明细行数据，若明细行不存在则报错。需检查变更申请明细数据是否正确创建
- **排查SQL**：
  ```sql
  SELECT epm.MANAGER_ID, epm.PROJECT_ID, epm.HZ_APPROVE_STATUS,
         (SELECT COUNT(*) FROM EPM_PROJECT_MANAGER_LINE epml
          WHERE epml.MANAGER_ID = epm.MANAGER_ID) AS 明细行数
  FROM EPM_PROJECT_MANAGER epm
  WHERE epm.MANAGER_ID = :managerId
    AND NOT EXISTS (SELECT 1 FROM EPM_PROJECT_MANAGER_LINE epml
                    WHERE epml.MANAGER_ID = epm.MANAGER_ID)
  ```

#### 报错8：失效原因必填
- **触发条件**：项目失效申请时，失效原因为空
- **逻辑分析**：在ProjectServiceImpl方法中校验，项目失效必须填写失效原因，用于记录失效依据。若失效原因为空则报错
- **排查SQL**：
  ```sql
  SELECT epu.UNVALID_ID, epu.PROJECT_ID, epu.UNVALID_REASON, epu.HZ_APPROVE_STATUS
  FROM EPM_PROJECT_UNVALID epu
  WHERE epu.UNVALID_ID = :unvalidId
    AND (epu.UNVALID_REASON IS NULL OR TRIM(epu.UNVALID_REASON) = '')
  ```

#### 报错9：计算报备延期开始日失败，30天内不够xxx天工作日
- **触发条件**：计算报备延期开始日时，30天内的工作日数量不足配置的maxCount
- **逻辑分析**：在ProjectServiceImpl方法中计算报备延期开始日，需从当前日期起30天内找到足够数量的工作日(排除节假日和周末)。若工作日数量不足maxCount则报错。需检查工作日历配置或调整maxCount参数
- **排查SQL**：
  ```sql
  SELECT COUNT(*) AS 30天内工作日数
  FROM (
    SELECT TRUNC(SYSDATE) + LEVEL - 1 AS cal_date
    FROM DUAL
    CONNECT BY LEVEL <= 30
  ) d
  WHERE TO_CHAR(d.cal_date, 'DY', 'NLS_DATE_LANGUAGE=AMERICAN') NOT IN ('SAT', 'SUN')
    AND NOT EXISTS (SELECT 1 FROM SYS_HOLIDAY sh WHERE sh.HOLIDAY_DATE = d.cal_date)
  -- 对比工作日数与配置的maxCount
  ```

## 常见问题FAQ

**Q1: 工程项目档案包含哪些信息？**
A: 包含项目报备信息、合同信息、项目阶段、经销商授权等多维度数据，通过detail接口聚合返回。数据由上游模块自动写入，本页面为只读查看。

**Q2: 项目状态有哪些？**
A: 1=未生效, 2=已生效, 3=已失效, 4=已冻结。报备后超过有效周期未签合同会被冻结。前端对PROJECT_VALID=4(已冻结)做了二次转换，结合解冻申请状态和冻结类型展示不同状态。

**Q3: 报备审核时报错"项目档案表（epm_project）缺失以下字段：xxx"？**
A: EPM_PROJECT表结构与EPM_REPORT表结构不一致。排查SQL：`SELECT column_name FROM all_tab_columns WHERE table_name = 'EPM_REPORT' AND column_name NOT IN (SELECT column_name FROM all_tab_columns WHERE table_name = 'EPM_PROJECT')`

**Q4: 项目进度更新报错"项目进度已变更，请驳回重审!"？**
A: 并发场景下其他单据已更新了项目档案的进度。排查SQL：`SELECT p.PROJECT_ID, p.PROJECT_CODE, p.STAGE_ID, p.STAGE_NAME FROM EPM_PROJECT p WHERE p.PROJECT_ID = :projectId`

**Q5: 项目进度更新报错"阶段更新，只能前进，不能后退"？**
A: 新选择的阶段序号小于当前阶段序号，系统不允许阶段倒退。排查SQL：`SELECT sd.STAGE_ID, sd.STAGE_NAME, sd.SEQ FROM EPM_STAGE_DEF sd ORDER BY sd.SEQ`

**Q6: 项目报备审核时报错"请配置{orgId}公司参数'Proj_Effective_Cycle'"？**
A: 未配置项目有效周期天数系统参数。排查SQL：`SELECT * FROM SYS_PARAM WHERE PARAM_CODE = 'Proj_Effective_Cycle' AND ORGANIZATION_ID = :orgId`

**Q7: 项目已冻结但无法提交解冻申请？**
A: 项目PROJECT_VALID必须为4(已冻结)才能提交解冻申请，且不能有正在审批中的解冻申请。排查SQL：`SELECT p.PROJECT_VALID, u.HZ_APPROVE_STATUS FROM EPM_PROJECT p LEFT JOIN EPM_PROJECT_UNFREEZE u ON p.PROJECT_ID = u.PROJECT_ID WHERE p.PROJECT_ID = :projectId`

**Q8: 折扣校验时项目档案标识(PROJECT_ARCHIVE)如何取值？**
A: PROJECT_ARCHIVE取自EPM_PROJECT.IS_LOCAL字段，2=本地(项目档案)，1=异地。排查SQL：`SELECT p.PROJECT_ID, p.IS_LOCAL FROM EPM_PROJECT p WHERE p.PROJECT_ID = :projectId`
