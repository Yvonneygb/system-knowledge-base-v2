# 电子合同管理-经销商-合同管理

> 后端代码位于 mbo-business 微服务，API 路径前缀为 `ch/contract/process/*`。

## 业务流程

```
经销商进入合同管理页面
        |
        ├── 查询合同列表 ──→ 按合同编号/名称/类型/签署状态/创建时间筛选
        |
        ├── 查看详情 ──→ 根据合同类型跳转不同详情页
        |       |
        |       ├── 活动点将合同 ──→ 调用 mlt/activityApply/detail
        |       ├── 特训营点将合同 ──→ 调用 mlt/trainCampApply/detail
        |       └── 设计点将合同 ──→ 调用 mlt/designApply/detail
        |
        └── 签署合同 ──→ 阅读条款 ──→ 在线签署 / 拒签
```

经销商仅可见自身权限范围内的合同，签署与拒签均按权限隔离。

### 上游依赖

| 上游模块 | 依赖类型 | 依赖说明 | 依赖成立条件 |
|---------|---------|---------|-------------|
| 品牌方合同签署 | 数据依赖 | 品牌方发起签署后生成经销商待签署合同 | 品牌方已发起合同签署 |
| 值集管理 | 数据依赖 | 提供合同类型、签署状态下拉选项 | 值集已配置 |
| 合同模板 | 数据依赖 | 合同条款来源于模板配置 | 模板已生效 |
| 电子签章系统 | 接口依赖 | 在线签署通过电子签章完成 | 签章系统可用 |

### 下游影响

- 签署后合同状态流转为已签署，品牌方继续后续处理
- 拒签后合同进入拒签状态，品牌方在异常处理页面处理
- 签署记录归档，供后续追溯

## 重点逻辑

### 重点逻辑1：经销商数据隔离

- **业务意义**：经销商仅能查看和管理自己作为签署方的合同，互不越权
- **具体逻辑描述**：数据隔离通过 API ch/contract/process/pageForAgent 实现，仅返回当前经销商的合同

### 重点逻辑2：合同类型分详情接口

- **业务意义**：不同合同类型关联不同业务申请，需调用对应详情接口获取关联信息
- **具体逻辑描述**：活动点将合同调用 mlt/activityApply/detail，特训营点将合同调用 mlt/trainCampApply/detail，设计点将合同调用 mlt/designApply/detail

### 重点逻辑3：签署与拒签

- **业务意义**：经销商可在线签署或拒签，签署即确认合作条款，拒签则留痕终止
- **具体逻辑描述**：签署前需阅读并同意合同条款，签署通过电子签章完成，拒签需填写拒签原因

### 重点逻辑4：经销商不可修改合同

- **业务意义**：合同内容由品牌方维护，经销商仅能签署或拒签
- **具体逻辑描述**：经销商不可修改合同内容，仅能查看合同详情、在线签署、拒签、下载合同PDF

查询SQL：

```sql
SELECT EC.UNIFY_CONTRACT_CODE       AS "合同统一编号",
       EC.ELECTRONIC_CONTRACT_CODE  AS "合同编号",
       EC.SOURCE_DOCUMENT_CODE      AS "来源合同编号",
       EC.CONTRACT_TYPE_NAME        AS "合同类型",
       EC.CONTRACT_YEAR             AS "合同年度",
       EC.CONTRACT_SUB_TYPE_NAME    AS "子合同类型",
       EC.AGENT_NAME                AS "经销商",
       EC.TRADE_COMPANY_NAME        AS "交易公司",
       EC.CONTRACT_VIOLD_TIME       AS "合同有效期",
       EC.BILL_ACCT_CODE            AS "法人编码",
       EC.BILL_ACCT_NAME            AS "法人名称",
       EC.CONTRACT_STATUS_NAME      AS "状态",
       EC.CREATE_USER_NAME          AS "创建人",
       TO_CHAR(EC.CREATE_TIME,'YYYY-MM-DD HH24:MI:SS') AS "创建时间",
       EC.INITIATOR                 AS "发起人",
       TO_CHAR(EC.INITIATE_TIME,'YYYY-MM-DD HH24:MI:SS') AS "发起时间",
       TO_CHAR(EC.COMPLETE_TIME,'YYYY-MM-DD HH24:MI:SS') AS "完成时间"
FROM ELECTRONIC_CONTRACT EC
WHERE EC.AGENT_ID = :currentAgentId
  AND EC.CONTRACT_TYPE = :contractType
  AND (:electronicContractCode IS NULL OR EC.ELECTRONIC_CONTRACT_CODE LIKE '%' || :electronicContractCode || '%')
  AND (:status IS NULL OR EC.CONTRACT_STATUS = :status)
  AND (:initiateTimeStart IS NULL OR EC.INITIATE_TIME >= TO_DATE(:initiateTimeStart, 'YYYY-MM-DD'))
  AND (:initiateTimeEnd IS NULL OR EC.INITIATE_TIME < TO_DATE(:initiateTimeEnd, 'YYYY-MM-DD') + 1)
ORDER BY EC.CREATE_TIME DESC;
```

### 标签页（Tabs）

> 前端代码：`contract/management/list.tsx` 的 `tableTabs` + `handleChangeTab`。页面通过 `Tabs` 组件切换不同合同类型，切换时调用 `handleChangeTab` 重新查询列表。

| 标签页名称 | 合同类型 key | 说明 |
|-----------|-------------|------|
| 经销合同 | DISTRIBUTION | 经销合同列表 |
| 装修协议 | DECORATION | 装修协议列表 |
| 广告协议 | ADVERTISING | 广告协议列表 |
| 点将合同 | DJ | 点将合同列表（设计/活动/特训营） |

#### 标签页切换逻辑

1. 点击标签页调用 `handleChangeTab(key)`
2. `setActiveTab(key)` 设置当前激活标签页
3. `tableDS?.queryDataSet?.getField('initiateTime')?.set('disabled', isDJ)` 根据合同类型禁用/启用合同发起日期查询字段（DJ类型时禁用）
4. `tableDS?.queryDataSet?.current?.set('initiateTime', isDJ ? undefined : initiateTimeDefaultValue)` 设置合同发起日期默认值（DJ类型时清空，其他类型设置为当月起止时间）
5. `tableDS.setQueryParameter('contractType', key)` 设置查询参数 contractType
6. `tableDS.query()` 重新查询列表

### 保存/提交校验

- 校验1：签署前需勾选同意合同条款 —— 确保经销商已确认合作条款
- 校验2：拒签时拒签原因必填 —— 确保拒签原因可追溯
- 校验3：签署时电子签章服务可用 —— 确保签署服务正常

### 状态机

```
[品牌方发起签署] --推送--> [待签署(waiting_sign)]
                                |
                      +---------+---------+
                      v                   v
                [经销商签署]          [经销商拒签]
                      |                   |
                      v                   v
              [已签署(signed)]     [拒签(refuse_seal)]
                      |                   |
                      v                   v
              [品牌方继续处理]     [品牌方异常处理]
```

| 状态 | 状态说明 | 经销商可执行操作 |
|------|---------|----------------|
| temporary | 临时/草稿 | 无(品牌方编辑中) |
| waiting_sign | 待签署 | 签署合同、查看详情 |
| signed | 已签署 | 查看详情、下载合同 |
| refuse_seal | 拒签 | 查看详情 |
| completed | 已完成 | 查看详情、下载合同 |
| reject_oa | OA驳回 | 查看详情 |
| pending | OA审批中 | 查看详情 |

#### 报错1：请先阅读并同意合同条款
- **触发条件**：点击签署按钮时，未勾选同意合同条款复选框
- **逻辑分析**：前端校验同意条款复选框是否勾选，未勾选则阻止签署并提示"请先阅读并同意合同条款"。确保经销商已阅读并确认合作条款，具备签署意愿的法律依据
- **排查SQL**：
  ```sql
  SELECT ELECTRONIC_CONTRACT_CODE AS 合同编号,
         CONTRACT_NAME AS 合同名称,
         CONTRACT_STATUS AS 签署状态,
         AGENT_NAME AS 经销商
  FROM ELECTRONIC_CONTRACT
  WHERE CONTRACT_STATUS = 'waiting_sign'
  ORDER BY CREATION_DATE DESC;
  ```

#### 报错2：请填写拒签原因
- **触发条件**：拒签提交时，REFUSE_REASON 字段为空
- **逻辑分析**：前端拒签弹窗对 refuseReason 字段配置 required 校验，提交前校验拒签原因是否填写，为空则阻止提交并提示"请填写拒签原因"。拒签原因用于记录经销商拒签依据，便于品牌方后续处理
- **排查SQL**：
  ```sql
  SELECT ELECTRONIC_CONTRACT_CODE AS 合同编号,
         CONTRACT_NAME AS 合同名称,
         CONTRACT_STATUS AS 签署状态,
         REFUSE_REASON AS 拒签原因,
         TO_CHAR(SIGN_TIME,'YYYY-MM-DD HH24:MI:SS') AS 签署时间
  FROM ELECTRONIC_CONTRACT
  WHERE CONTRACT_STATUS = 'refuse_seal'
    AND (REFUSE_REASON IS NULL OR REFUSE_REASON = '');
  ```

#### 报错3：合同PDF生成中，请稍后
- **触发条件**：下载合同PDF时，合同已完成但PDF未生成
- **逻辑分析**：前端校验 PDF_URL 字段非空，若为空说明PDF异步生成未完成，提示"合同PDF生成中，请稍后"。合同PDF由签署完成后异步生成，通常几秒内完成，刷新页面后重试即可
- **排查SQL**：
  ```sql
  SELECT ELECTRONIC_CONTRACT_CODE AS 合同编号,
         CONTRACT_NAME AS 合同名称,
         CONTRACT_STATUS AS 签署状态,
         PDF_URL AS 合同PDF地址,
         TO_CHAR(SIGN_TIME,'YYYY-MM-DD HH24:MI:SS') AS 签署时间
  FROM ELECTRONIC_CONTRACT
  WHERE CONTRACT_STATUS IN ('signed', 'completed')
    AND (PDF_URL IS NULL OR PDF_URL = '');
  ```

#### 报错4：签署服务不可用
- **触发条件**：调用电子签章接口时，签章系统异常
- **逻辑分析**：后端调用电子签章系统接口，若签章服务不可用、网络异常、签章参数错误等则接口返回失败，提示"签署服务不可用"。需联系运维检查签章系统运行状态、网络连通性、签章服务配置
- **排查SQL**：
  ```sql
  SELECT ELECTRONIC_CONTRACT_CODE AS 合同编号,
         CONTRACT_NAME AS 合同名称,
         CONTRACT_STATUS AS 签署状态,
         AGENT_NAME AS 经销商,
         TO_CHAR(LAST_UPDATE_DATE,'YYYY-MM-DD HH24:MI:SS') AS 最后更新时间
  FROM ELECTRONIC_CONTRACT
  WHERE CONTRACT_STATUS = 'waiting_sign'
  ORDER BY LAST_UPDATE_DATE DESC;
  ```

#### 报错5：签署异常
- **触发条件**：调用签章接口时，返回非成功状态
- **逻辑分析**：后端调用签章接口，若签章流程异常、签署人信息错误、合同内容异常、签章服务超时等则接口返回非成功状态，提示"签署异常: {具体错误信息}"。需检查签章服务日志、签署人信息、合同内容完整性
- **排查SQL**：
  ```sql
  SELECT ELECTRONIC_CONTRACT_CODE AS 合同编号,
         CONTRACT_NAME AS 合同名称,
         CONTRACT_STATUS AS 签署状态,
         AGENT_NAME AS 经销商,
         SIGN_URL AS 签署链接
  FROM ELECTRONIC_CONTRACT
  WHERE CONTRACT_STATUS = 'waiting_sign'
    AND (SIGN_URL IS NULL OR SIGN_URL = '');
  ```

#### 报错6：网络异常/接口超时
- **触发条件**：任意接口调用时，网络中断或接口响应超过 axios timeout 配置
- **逻辑分析**：前端 axios 请求未收到响应或响应超时，触发 catch 回调统一提示"请求失败"。常见根因：网络中断、mbo-business 服务假死、数据库慢查询、签章系统响应慢等。需检查网络连通性、后端服务负载、签章系统状态
- **排查SQL**：
  ```sql
  SELECT ELECTRONIC_CONTRACT_CODE AS 合同编号, CONTRACT_NAME AS 合同名称,
         CONTRACT_STATUS AS 签署状态,
         TO_CHAR(LAST_UPDATE_DATE,'YYYY-MM-DD HH24:MI:SS') AS 最后更新时间
  FROM ELECTRONIC_CONTRACT
  WHERE LAST_UPDATE_DATE >= SYSDATE - 1
  ORDER BY LAST_UPDATE_DATE DESC;
  ```

#### 报错7：权限不足
- **触发条件**：点击签署、拒签等按钮时，当前用户无对应 permissionList 权限码
- **逻辑分析**：前端 Button 组件通过 permissionList 配置权限码，HZERO 框架校验当前用户角色是否包含该权限码，未包含则按钮不可见或禁用。若强制调用接口，后端也会校验权限返回403。需联系管理员配置对应角色权限
- **排查SQL**：
  ```sql
  SELECT U.USER_NAME AS 用户名, R.ROLE_NAME AS 角色名, P.PERMISSION_CODE AS 权限码
  FROM SYS_USER U
  LEFT JOIN SYS_USER_ROLE UR ON U.USER_ID = UR.USER_ID
  LEFT JOIN SYS_ROLE R ON UR.ROLE_ID = R.ROLE_ID
  LEFT JOIN SYS_ROLE_PERMISSION RP ON R.ROLE_ID = RP.ROLE_ID
  LEFT JOIN SYS_PERMISSION P ON RP.PERMISSION_ID = P.PERMISSION_ID
  WHERE P.PERMISSION_CODE LIKE '%electronic_contract%' ORDER BY U.USER_NAME;
  ```

#### 报错8：合同不存在
- **触发条件**：查看、签署等操作时，接口返回数据为空或合同编码不存在
- **逻辑分析**：前端通过 contractCode 调用详情接口，后端查询 ELECTRONIC_CONTRACT 表无对应记录或记录已逻辑删除，返回空数据。常见根因：合同编码错误、合同已被删除、跨租户查询、数据权限隔离等。需检查 ELECTRONIC_CONTRACT_CODE 有效性及数据权限
- **排查SQL**：
  ```sql
  SELECT ELECTRONIC_CONTRACT_CODE AS 合同编号, CONTRACT_NAME AS 合同名称,
         CONTRACT_STATUS AS 签署状态, DELETE_FLAG AS 删除标记
  FROM ELECTRONIC_CONTRACT
  WHERE DELETE_FLAG = 'Y' OR ELECTRONIC_CONTRACT_CODE IS NULL;
  ```

#### 报错9：状态不允许操作
- **触发条件**：点击签署、拒签等按钮时，合同状态不允许该操作
- **逻辑分析**：后端校验状态机，如已签署（signed）不可重复签署、已完成（completed）不可拒签等。状态不匹配时后端返回业务异常。需检查合同当前状态及操作流程
- **排查SQL**：
  ```sql
  SELECT ELECTRONIC_CONTRACT_CODE AS 合同编号, CONTRACT_NAME AS 合同名称,
         CONTRACT_STATUS AS 签署状态, ERROR_INFO AS 异常问题
  FROM ELECTRONIC_CONTRACT
  WHERE CONTRACT_STATUS NOT IN ('waiting_sign','signed','completed','refuse_seal')
  ORDER BY CREATE_DATE DESC;
  ```

#### 报错10：值集数据不显示
- **触发条件**：查询条件或列表中合同状态等下拉选项为空
- **逻辑分析**：前端通过 lookupCode 查询值集 MBO.CONTRACT_STATUS 等，值集未配置或未启用则下拉选项为空。需在值集管理页面配置对应值集
- **排查SQL**：
  ```sql
  SELECT LOOKUP_CODE AS 值集编码, LOOKUP_VALUE_CODE AS 值编码,
         LOOKUP_VALUE_NAME AS 值名称, ENABLE_FLAG AS 启用标记
  FROM SYS_LOOKUP_VALUE
  WHERE LOOKUP_CODE IN ('MBO.CONTRACT_STATUS','MBO.CONTRACT_TYPE')
    AND ENABLE_FLAG = 'N' ORDER BY LOOKUP_CODE;
  ```

#### 报错11：短信验证码错误
- **触发条件**：签署验证时，短信验证码输入错误或已过期
- **逻辑分析**：后端校验短信验证码与发送记录是否一致且在有效期内，校验失败则返回业务异常。需重新获取验证码后输入
- **排查SQL**：
  ```sql
  SELECT ELECTRONIC_CONTRACT_CODE AS 合同编号, AGENT_NAME AS 经销商,
         SMS_SEND_TIME AS 短信发送时间, SMS_EXPIRE_TIME AS 短信过期时间,
         VERIFY_STATUS AS 验证状态
  FROM ELECTRONIC_CONTRACT_SMS
  WHERE VERIFY_STATUS = 'fail'
    AND SMS_SEND_TIME >= SYSDATE - 1
  ORDER BY SMS_SEND_TIME DESC;
  ```

### 常见问题

| 问题 | 排查方式 |
|------|---------|
| 经销商能修改合同内容吗 | 不能，经销商仅能查看合同内容并进行签署或拒签，合同内容由品牌方维护 |
| 拒签后还能重新签署吗 | 不能，拒签后合同进入拒签状态，需品牌方重新发起签署流程 |
| 合同列表为什么看不到某些合同 | 经销商仅能看到自己作为签署方的合同，数据通过 pageForAgent 接口隔离 |
| 下载合同PDF提示生成中怎么办 | 合同完成后PDF异步生成，通常几秒内完成，刷新页面后重试即可 |
| 不同合同类型查看详情跳转不同页面 | 活动点将调用 activityApply/detail，特训营点将调用 trainCampApply/detail，设计点将调用 designApply/detail |
