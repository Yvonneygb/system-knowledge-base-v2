# 工程管理-项目合同-经销商工程合同

> 本页面为低代码页面(hlod)，无独立前端源码，基于后端API梳理。后端Controller为EpmProjectContractController（API: `/v1/{organizationId}/epm-project-contracts`）和ContractController（API: `/v1/{organizationId}/contracts/`）。contractType=2区分经销合同，contractCharacter区分经销商/自营。

## 业务流程

```
用户进入经销商工程合同列表页面
  → 填写查询条件（合同编码、合同名称、客户、项目等）
  → 调用合同列表接口（GET /contracts/contract-list）
  → 查看合同详情（GET /contracts/get-contract-detail）
  → 新增合同：选择报备项目弹窗（GET /contracts/get-project-data）
    → 选择交易公司/开票单位（GET /contracts/trading-company-customer）
    → 选择收货地址（GET /contracts/get-reference-customer-address）
    → 选择产品/引用政策产品（POST /contracts/get-discount-policy）
    → 获取折扣率（POST /contracts/std-discount）
    → 保存合同（POST /epm-project-contracts/save-data）
    → 保存并提交工作流（POST /epm-project-contracts/save-data-submit）
  → 合同提交审批流程（POST /epm-project-contracts/do-Contract-Check）
  → 审批通过后自动更新项目阶段（doContractCheck → doMotionUpdate）
  → 审批拒绝/驳回（wfComplete → wfChangeUpdate）
```

## 重点逻辑

### 重点逻辑1：合同编码自动生成

- **业务意义**：确保每个合同有唯一可追溯的编码，编码中包含事业部信息
- **具体逻辑描述**：
  - 1、新增合同时，通过编码规则`AE.EPM_PROJECT_CONTRACT`生成编码
  - 2、最终编码格式为：事业部编码(deptCode) + 编码规则生成码 + 序列号
  - 3、增补合同时，mainContractId记录原始合同ID，supplementType=2(增补)

### 重点逻辑2：签约方式区分

- **业务意义**：经销商工程合同与自营工程合同通过contractType字段区分，走不同业务逻辑
- **具体逻辑描述**：
  - 1、经销商工程合同固定contractType=2(经销)，列表查询固定传参contractType=2
  - 2、contractCharacter字段区分经销商/自营（AR：收款合同；AP：付款合同）
  - 3、经销合同(contractType=2)且非家装(isHome!=2)时，需处理收货地址(saveCustomerAddress)
  - 4、自营合同(contractType=1)时，根据客户分类(customerClass)自动设置操作模式(contractMode)

### 重点逻辑3：审批流程按区域区分

- **业务意义**：不同区域的经销商工程合同使用不同的审批流程，实现差异化审核
- **具体逻辑描述**：
  - 1、东区使用SUB_CONTRACT_JXSGCHT_EAST
  - 2、西区使用SUB_CONTRACT_JXSGCHT_WEST
  - 3、南区使用SUB_CONTRACT_JXSGCHT_SOUTH
  - 4、北区使用SUB_CONTRACT_JXSGCHT_NORTH
  - 5、审批人确定逻辑：若关联战略工程，取战略项目区域经理；否则按经销商编码匹配AE.CONTRACT_LINK_DISTRIBUTOR值集，匹配到则取AE.INTERNAL_CUSTOMER_APPROVER配置的审批人，未匹配到则取经销商档案业务员

### 重点逻辑4：战略工程关联

- **业务意义**：合同可关联战略工程，享受战略工程特殊折扣政策
- **具体逻辑描述**：
  - 1、勾选"战略工程相关"(strategicRelated=2)后，可选择战略项目和战略协议
  - 2、parameterCompletion方法中，从项目(EpmProject)强制写回战略报备信息到合同，避免沿用前端缓存
  - 3、战略协议(isFrame=2)无需维护折扣单，saveDiscountApply方法直接return

### 重点逻辑5：纯定制合同处理

- **业务意义**：纯定制合同不要求维护产品清单，简化操作流程
- **具体逻辑描述**：
  - 1、isCustom=2时为纯定制合同，不要求维护产品清单信息
  - 2、保存时清除折扣相关信息：删除EPM_CONTRACT_ITEM、EPM_DISCOUNT_APPLY_LINE、EPM_DISCOUNT_APPLY_PLAN、EPM_DISCOUNT_APPLY
  - 3、非纯定制时，产品清单数据保存到EPM_CONTRACT_ITEM表，折扣信息保存到EPM_DISCOUNT_APPLY表
  - 4、一揽子合同(orderQtyCtrlType=2)时，合同数量默认为1

### 重点逻辑6：小型项目校验

- **业务意义**：小型项目只能存在一个生效的合同，限制重复签约
- **具体逻辑描述**：
  - 1、projectCategory=small时为小型项目，否则默认为normal(常规项目)
  - 2、小型项目校验：通过smallProjectCheck查询该项目是否已有生效合同，count>0则报错"报备类型为小型项目，只能存在一个生效的合同"
  - 3、小型项目自动赋默认值：priceContainTax=2(含税)、priceContainFreight=2(含运费)、discountType=2、planDateDefault=当前时间+1月

### 选择弹窗

#### 弹窗1：报备项目选择弹窗

- **触发位置**：合同详情页"报备项目编码"字段LOV点击
- **接口**：`GET /v1/{organizationId}/contracts/get-project-data`
- **Controller**：ContractController.getProjectData
- **返回**：Page\<EpmProjectDataVO\>，可关联的已报备项目列表
- **选择后赋值**：自动填充项目编码、项目名称、客户编码、客户名称、业主类型等字段
- **查询SQL**：
```sql
SELECT * FROM EPM_PROJECT
WHERE ORGANIZATION_ID = #{organizationId}
  AND PROJECT_STAT = 5
  AND CUSTOMER_ID IS NOT NULL
ORDER BY PROJECT_ID DESC;
```

#### 弹窗2：交易公司/开票单位选择弹窗

- **触发位置**：合同详情页"交易公司"/"开票单位"字段LOV点击
- **接口**：`GET /v1/{organizationId}/epm-project-contracts/trading-company-customer`
- **Controller**：EpmProjectContractController.searchTradingCompany
- **返回**：Page\<CustomerLegalEntityVO\>，法人客户列表

#### 按钮1：新增（列表页）

- **触发条件**：列表页点击"新增"按钮
- **执行逻辑**：
  - 1、跳转合同详情页，所有字段为空
  - 2、签约方式默认设置为2(经销)
  - 3、选择报备项目后自动带出客户、项目等基础信息

#### 按钮2：删除（列表页行操作）

- **触发条件**：选中某行，审核状态=NEW时可点击
- **接口**：`POST /v1/{organizationId}/epm-project-contracts/delete-contract`
- **执行逻辑**：
  - 1、删除合同主表数据(EPM_PROJECT_CONTRACT)
  - 2、删除合同收货地址(EPM_CONTRACT_ADDRESS_EXT、CUSTOMER_ADDRESS)
  - 3、删除意向单关联(EPM_CONTRACT_INTENTION_REL)
  - 4、删除约定条款(EPM_CONTRACT_TERMS)
  - 5、删除周期条件(EPM_PAYMENT_PLAN_SET)
  - 6、删除产品清单(EPM_CONTRACT_ITEM)
  - 7、删除折扣单头/行/计划(EPM_DISCOUNT_APPLY、EPM_DISCOUNT_APPLY_LINE、EPM_DISCOUNT_APPLY_PLAN)

#### 按钮3：保存并提交（详情页）

- **触发条件**：详情页点击"保存并提交"按钮
- **接口**：`POST /v1/{organizationId}/epm-project-contracts/save-data-submit`
- **执行逻辑**：
  - 1、调用onUserSubmit进行用户提交前处理
  - 2、调用newSave保存合同数据
  - 3、调用validationService.validateAll进行合同校验
  - 4、调用onProcComplete流程提交前校验
  - 5、组装工作流变量（subject、customerId、isCustom、auditOAFlag、auditFlag、projectId、policyFlag等）
  - 6、确定审批人：关联战略工程取战略项目区域经理；否则按经销商编码匹配值集配置
  - 7、启动工作流

### 保存校验

- 校验1：合同名称不能为空 —— 确保合同有名称标识
  - **详细逻辑**：checkSaveData方法校验contractName非空
  - **系统体现**：保存时后端校验，抛出"合同名称不能为空"
  - **排查SQL**：`SELECT CONTRACT_NAME FROM EPM_PROJECT_CONTRACT WHERE CONTRACT_ID = #{contractId}`

- 校验2：合同名称长度不超过80 —— 防止名称过长
  - **详细逻辑**：contractName.length() > 80时报错
  - **系统体现**：保存时后端校验，抛出"合同名称过程过长，请控制长度"

- 校验3：必填内容校验 —— 确保关键信息完整
  - **详细逻辑**：contractName、tradingCompanyName、billingUnitName均不能为空
  - **系统体现**：保存时后端校验，抛出"有必填内容未填写，请填写后再保存"

- 校验4：签约单位不能为空 —— 经销非家装合同必须有签约单位
  - **详细逻辑**：contractUnit为空且contractType=2且isHome!=2时报错
  - **系统体现**：保存时后端校验，抛出"签约单位不能为空"

- 校验5：订单产品线不能为空 —— 非定制合同必须维护产品线
  - **详细逻辑**：isCustom!=2时，epmDiscountApplyDTO.orderPdtLine不能为空或0
  - **系统体现**：保存时后端校验，抛出"订单产品线不能为空，请维护订单产品线！"

- 校验6：合作结束时间大于合作开始时间 —— 家装合同时间逻辑校验
  - **详细逻辑**：isHome=2时，contractExpireDate必须晚于contractEffectDate
  - **系统体现**：保存时后端校验，抛出"合作结束时间应大于合作开始时间"

- 校验7：事业部编码不能为空 —— 新增合同时必须有事业部
  - **详细逻辑**：新增时deptCode为空或包含"null"时报错
  - **系统体现**：saveOrUpdate方法校验，抛出"事业部编码为空"

- 校验8：小型项目唯一合同 —— 小型项目只能有一个生效合同
  - **详细逻辑**：projectCategory=small时，smallProjectCheck查询count>0则报错
  - **系统体现**：smallProjectAssignment方法校验，抛出"报备类型为小型项目，只能存在一个生效的合同"
  - **排查SQL**：`SELECT COUNT(*) FROM EPM_PROJECT_CONTRACT WHERE PROJECT_ID = #{projectId} AND VALID = 2`

### 提交校验

- 校验1：合同未审核 —— 防止重复提交
  - **详细逻辑**：doCheckMotionChange方法校验hzApproveStatus不等于APPROVED
  - **系统体现**：提交时后端校验，抛出"该单据已经审核"
  - **排查SQL**：`SELECT HZ_APPROVE_STATUS FROM EPM_PROJECT_CONTRACT WHERE CONTRACT_ID = #{contractId}`

- 校验2：产品信息已维护 —— 非定制合同必须有产品清单
  - **详细逻辑**：isCustom!=2时，查询EPM_CONTRACT_ITEM count<1则报错
  - **系统体现**：doCheckMotionChange方法校验，抛出"请先维护产品信息，流程失败!"
  - **排查SQL**：`SELECT COUNT(*) FROM EPM_CONTRACT_ITEM WHERE CONTRACT_ID = #{contractId}`

- 校验3：折扣类型已维护 —— 非定制合同必须有折扣类型
  - **详细逻辑**：isCustom!=2时，查询EPM_DISCOUNT_APPLY为null则报错
  - **系统体现**：doCheckMotionChange方法校验，抛出"请先维护折扣类型，流程失败!"
  - **排查SQL**：`SELECT * FROM EPM_DISCOUNT_APPLY WHERE CONTRACT_ID = #{contractId}`

- 校验4：合同数据完整性 —— 提交前综合校验
  - **详细逻辑**：validationService.validateAll校验合同所有数据
  - **系统体现**：saveDataSubmit方法中调用，校验不通过则不启动流程

- 校验5：流程提交前校验 —— onProcComplete校验
  - **详细逻辑**：流程提交API/事件流提交前执行，校验不通过不启动流程
  - **系统体现**：saveDataSubmit方法中调用

### 状态机

#### 合同审批状态（HZ_APPROVE_STATUS）

```text
┌──────────┐  提交   ┌──────────┐  审批通过  ┌──────────┐
│   NEW    │ ──────→ │   RUN    │ ────────→ │ APPROVED │
│ (新建)   │         │ (审批中) │           │(已生效)  │
└──────────┘         └────┬─────┘           └──────────┘
                          │
                    审批拒绝/驳回
                          │
              ┌───────────┴──────────┐
              │                      │
        ┌─────▼─────┐          ┌─────▼─────┐
        │ REJECTED  │          │  REBUT   │
        │(审批拒绝) │          │ (已驳回)  │
        └───────────┘          └───────────┘
```

#### 合同有效状态（VALID）

| 状态值 | 说明 |
|--------|------|
| 1 | 未生效 |
| 2 | 已生效 |
| 3 | 已失效 |
| 7 | 失效申请中 |

#### 状态机列表

| 状态机名称 | 状态释义 | 可执行的操作 |
|-----------|---------|-------------|
| NEW | 新建 | 保存、保存并提交、编辑、删除 |
| RUN | 审批中 | 等待审批结果 |
| APPROVED | 已审批 | 失效、结案 |
| REJECTED | 已驳回 | 保存、保存并提交、编辑 |
| WITHDRAW | 已撤回 | 保存、保存并提交、编辑 |

#### 报错1：合同名称不能为空
- **触发条件**：保存合同时，合同头CONTRACT_NAME字段为空
- **逻辑分析**：在checkSaveData方法中校验，对合同头DTO的contractName属性执行非空判断，若为null或空字符串则抛出阻断性报错。该字段为合同基础标识字段，经销合同与自营合同共用此校验
- **排查SQL**：
  ```sql
  SELECT epc.CONTRACT_ID, epc.CONTRACT_CODE, epc.CONTRACT_NAME, epc.CONTRACT_TYPE
  FROM EPM_PROJECT_CONTRACT epc
  WHERE epc.CONTRACT_TYPE = 2
    AND (epc.CONTRACT_NAME IS NULL OR TRIM(epc.CONTRACT_NAME) = '')
  ```

#### 报错2：合同名称过程过长，请控制长度
- **触发条件**：保存合同时，CONTRACT_NAME字段长度超过80个字符
- **逻辑分析**：在checkSaveData方法中校验contractName长度，数据库列CONTRACT_NAME定义为VARCHAR(80)，若传入字符串长度>80则报错。需缩短合同名称至80字符以内
- **排查SQL**：
  ```sql
  SELECT epc.CONTRACT_ID, epc.CONTRACT_CODE, epc.CONTRACT_NAME, LENGTH(epc.CONTRACT_NAME) AS 名称长度
  FROM EPM_PROJECT_CONTRACT epc
  WHERE epc.CONTRACT_TYPE = 2
    AND LENGTH(epc.CONTRACT_NAME) > 80
  ```

#### 报错3：有必填内容未填写，请填写后再保存
- **触发条件**：保存合同时，contractName、tradingCompanyName、billingUnitName任一为空
- **逻辑分析**：在checkSaveData方法中批量校验必填字段，合同名称(CONTRACT_NAME)、交易公司(TRADING_COMPANY_NAME)、开票单位(BILLING_UNIT_NAME)为经销合同必填项，任一为空即报错
- **排查SQL**：
  ```sql
  SELECT epc.CONTRACT_ID, epc.CONTRACT_CODE,
         epc.CONTRACT_NAME, epc.TRADING_COMPANY_NAME, epc.BILLING_UNIT_NAME
  FROM EPM_PROJECT_CONTRACT epc
  WHERE epc.CONTRACT_TYPE = 2
    AND (epc.CONTRACT_NAME IS NULL OR epc.TRADING_COMPANY_NAME IS NULL OR epc.BILLING_UNIT_NAME IS NULL)
  ```

#### 报错4：签约单位不能为空
- **触发条件**：保存经销非家装合同时，CONTRACT_UNIT字段为空
- **逻辑分析**：在checkSaveData方法中校验，当合同为经销合同(contractType=2)且非家装(isHome!=2)时，签约单位contractUnit不能为空。家装合同跳过此校验。签约单位用于标识实际签约主体
- **排查SQL**：
  ```sql
  SELECT epc.CONTRACT_ID, epc.CONTRACT_CODE, epc.IS_HOME, epc.CONTRACT_UNIT
  FROM EPM_PROJECT_CONTRACT epc
  WHERE epc.CONTRACT_TYPE = 2
    AND NVL(epc.IS_HOME, 1) != 2
    AND (epc.CONTRACT_UNIT IS NULL OR TRIM(epc.CONTRACT_UNIT) = '')
  ```

#### 报错5：订单产品线不能为空，请维护订单产品线！
- **触发条件**：保存非纯定制合同(IS_CUSTOM!=2)时，ORDER_PDT_LINE字段为空
- **逻辑分析**：在checkSaveData方法中校验，当合同非纯定制(isCustom!=2)时，订单产品线orderPdtLine不能为空。纯定制合同跳过此校验。产品线用于后续要货订单创建和ERP推送
- **排查SQL**：
  ```sql
  SELECT epc.CONTRACT_ID, epc.CONTRACT_CODE, epc.IS_CUSTOM, epc.ORDER_PDT_LINE
  FROM EPM_PROJECT_CONTRACT epc
  WHERE epc.CONTRACT_TYPE = 2
    AND NVL(epc.IS_CUSTOM, 1) != 2
    AND (epc.ORDER_PDT_LINE IS NULL OR TRIM(epc.ORDER_PDT_LINE) = '')
  ```

#### 报错6：合作结束时间应大于合作开始时间
- **触发条件**：保存家装合同时，CONTRACT_EXPIRE_DATE <= CONTRACT_EFFECT_DATE
- **逻辑分析**：在checkSaveData方法中校验，仅对家装合同(isHome=2)执行时间逻辑校验。合作结束时间(contractExpireDate)必须大于合作开始时间(contractEffectDate)，否则报错。需修正合作期限
- **排查SQL**：
  ```sql

  ```

  ```sql
    AND epc.HZ_APPROVE_STATUS = 'APPROVED'
  ```

#### 报错44：合同有效折扣已失效，请检查。
- **触发条件**：提交合同时，关联的折扣申请单已失效
- **逻辑分析**：在提交校验方法中检查关联折扣申请单(EPM_DISCOUNT_APPLY)的有效状态，若已失效则报错。需重新维护折扣信息
- **排查SQL**：
  ```sql
  SELECT epc.CONTRACT_ID, epc.CONTRACT_CODE,
         eda.APPLY_ID, eda.VALID AS 折扣单状态
  FROM EPM_PROJECT_CONTRACT epc
  JOIN EPM_DISCOUNT_APPLY eda ON eda.CONTRACT_ID = epc.CONTRACT_ID
  WHERE epc.CONTRACT_TYPE = 2
    AND eda.VALID = 0
  ```

#### 报错45：当前事业部未设置主要销售主体，暂无法正常下单，请联系业务员处理。
- **触发条件**：提交合同时，当前事业部未配置主要销售主体
- **逻辑分析**：在提交校验方法中查询事业部主要销售主体配置，若未配置则报错。主要销售主体用于确定销售法人主体。需联系业务员配置事业部主要销售主体
- **排查SQL**：
  ```sql
  SELECT epc.CONTRACT_ID, epc.CONTRACT_CODE, epc.DEPT_CODE,
         (SELECT COUNT(*) FROM EPM_DEPT_BASE_CONFIG edbc
          WHERE edbc.DEPT_CODE = epc.DEPT_CODE
            AND edbc.MAIN_SALES_SUBJECT IS NOT NULL) AS 主要销售主体配置数
  FROM EPM_PROJECT_CONTRACT epc
  WHERE epc.CONTRACT_TYPE = 2
    AND NOT EXISTS (SELECT 1 FROM EPM_DEPT_BASE_CONFIG edbc
                    WHERE edbc.DEPT_CODE = epc.DEPT_CODE
                      AND edbc.MAIN_SALE_SUBJECT IS NOT NULL)
  ```

#### 报错46：当前事业部未设置小型项目标准折扣
- **触发条件**：保存小型项目合同时，事业部未配置小型项目标准折扣
- **逻辑分析**：在小型项目折扣处理方法中校验，当报备项目为小型项目(PROJECT_CATEGORY='SMALL')时，需查询事业部小型项目标准折扣配置，若未配置则报错
- **排查SQL**：
  ```sql
  SELECT epc.CONTRACT_ID, epc.CONTRACT_CODE, epc.DEPT_CODE, ep.PROJECT_CATEGORY
  FROM EPM_PROJECT_CONTRACT epc
  JOIN EPM_PROJECT ep ON ep.PROJECT_ID = epc.PROJECT_ID
  WHERE epc.CONTRACT_TYPE = 2
    AND ep.PROJECT_CATEGORY = 'SMALL'
    AND NOT EXISTS (SELECT 1 FROM EPM_DEPT_BASE_CONFIG edbc
                    WHERE edbc.DEPT_CODE = epc.DEPT_CODE
                      AND edbc.SMALL_PROJECT_DISCOUNT IS NOT NULL)
  ```

#### 报错47：小型项目折扣率未设置
- **触发条件**：保存小型项目合同时，小型项目折扣率为空
- **逻辑分析**：在小型项目折扣处理方法中校验，小型项目折扣率用于自动计算产品折扣价格，若为空则报错。需在事业部基础设置中配置小型项目折扣率
- **排查SQL**：
  ```sql
  SELECT epc.CONTRACT_ID, epc.CONTRACT_CODE, epc.DEPT_CODE,
         edbc.SMALL_PROJECT_DISCOUNT_RATE
  FROM EPM_PROJECT_CONTRACT epc
  JOIN EPM_PROJECT ep ON ep.PROJECT_ID = epc.PROJECT_ID
  LEFT JOIN EPM_DEPT_BASE_CONFIG edbc ON edbc.DEPT_CODE = epc.DEPT_CODE
  WHERE epc.CONTRACT_TYPE = 2
    AND ep.PROJECT_CATEGORY = 'SMALL'
    AND (edbc.SMALL_PROJECT_DISCOUNT_RATE IS NULL OR edbc.SMALL_PROJECT_DISCOUNT_RATE = 0)
  ```

#### 报错48：产品清单不能为空
- **触发条件**：同步CRM产品信息时，产品清单(EPM_CONTRACT_ITEM)无数据
- **逻辑分析**：在syncCrmProductInfo方法中校验，同步CRM前需查询产品清单，若无数据则无法同步。需先维护产品清单
- **排查SQL**：
  ```sql
  SELECT epc.CONTRACT_ID, epc.CONTRACT_CODE,
         (SELECT COUNT(*) FROM EPM_CONTRACT_ITEM eci WHERE eci.CONTRACT_ID = epc.CONTRACT_ID) AS 产品明细数
  FROM EPM_PROJECT_CONTRACT epc
  WHERE epc.CONTRACT_TYPE = 2
    AND NOT EXISTS (SELECT 1 FROM EPM_CONTRACT_ITEM eci WHERE eci.CONTRACT_ID = epc.CONTRACT_ID)
  ```

- **工程要货订单**：合同生效后(VALID=2)，可基于该合同创建要货订单

## 常见问题FAQ

**Q1: 经销商工程合同与自营工程合同的区别？**
A: 通过CONTRACT_TYPE字段区分，经销商合同contractType=2，自营合同contractType=1。自营合同需校验操作模式(contractMode)，根据客户分类(customerClass)自动设置：内部用户(1)对应自营工程(1)，外部用户(2)对应经销商服务(2)。前端路由分别为/epm-project-contract和/epm-autotrophy-contract。

**Q2: 新建合同时为什么必须先选择报备项目？**
A: 合同必须关联已报备的项目(PROJECT_STAT=5)，通过报备项目带出客户、项目等基础信息。parameterCompletion方法还会从项目强制写回战略报备信息到合同，避免沿用前端缓存。

**Q3: 哪些意向单关联可以删除？**
A: 仅状态为1(草稿)、4(已取消)、5(要货单号为空)、8(审核拒绝)、11(EBS退回)的意向单关联允许删除。judgeIntention方法校验，不在允许集合中且要货单号非空则报错。

**Q4: 合同审批通过但有效状态未变为"已生效"？**
A: 审批回调wfComplete未正确执行。排查SQL：`SELECT CONTRACT_CODE, VALID, HZ_APPROVE_STATUS, HZ_INSTANCE_ID FROM EPM_PROJECT_CONTRACT WHERE CONTRACT_ID = #{contractId}`。处理：检查HZ_INSTANCE_ID对应的流程实例状态，确认wfComplete方法是否被调用，手动修正VALID=2。

**Q5: 不同区域的审批流程有什么区别？**
A: 东区使用SUB_CONTRACT_JXSGCHT_EAST，西区使用SUB_CONTRACT_JXSGCHT_WEST，南区使用SUB_CONTRACT_JXSGCHT_SOUTH，北区使用SUB_CONTRACT_JXSGCHT_NORTH。审批人确定：关联战略工程取战略项目区域经理；否则按经销商编码匹配AE.CONTRACT_LINK_DISTRIBUTOR值集，匹配到取AE.INTERNAL_CUSTOMER_APPROVER配置，未匹配到取经销商档案业务员。

**Q6: 纯定制合同和普通合同有什么区别？**
A: 纯定制合同(IS_CUSTOM=2)不要求维护产品清单，保存时清除折扣相关信息(EPM_CONTRACT_ITEM、EPM_DISCOUNT_APPLY_LINE、EPM_DISCOUNT_APPLY_PLAN、EPM_DISCOUNT_APPLY)。普通合同需维护产品清单和折扣单。

**Q7: 小型项目合同有什么特殊处理？**
A: 小型项目(PROJECT_CATEGORY=small)只能存在一个生效的合同。自动赋默认值：含税(PRICE_CONTAIN_TAX=2)、含运费(PRICE_CONTAIN_FREIGHT=2)、折扣类型=2、计划日期默认=当前时间+1月。审批通过后不走OA审批(oaAuditStat=-1)。

**Q8: 一揽子合同有什么特殊处理？**
A: 一揽子合同(ORDER_QTY_CTRL_TYPE=2)时，产品清单和折扣明细行的合同数量(CONTRACT_QTY)默认为1。

**Q9: 战略协议合同有什么特殊处理？**
A: 战略协议(IS_FRAME=2)无需维护折扣单，saveDiscountApply方法直接return不处理折扣信息。

**Q10: 合同审批拒绝后如何处理？**
A: wfComplete方法检测到APPROVE_RESULT为REJECTED/REBUT/INTERRUPT时，调用wfChangeUpdate更新状态，非定制合同调用rejectCalculateFirstProc处理折扣明细行，更新合同HZ_APPROVE_STATUS为对应状态。
