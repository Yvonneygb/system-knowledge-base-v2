# 门店管理-装修报表-门店装修额度外报表

> 本页面为低代码页面(hlod)，无独立前端源码，基于后端API梳理。

## 业务流程

门店装修额度外报表用于查询门店装修额度外兑现（二次兑现）的详细信息，包括兑现单号、门店信息、经销商信息、发票信息、兑现金额等。数据来源于视图 `EPMS.MKT_TERMINAL_RE_CASHOUT_VIEW`，展示额度外兑现的完整明细。本页面为纯查询报表，仅支持查看和导出，不支持新增、修改、删除等写操作。

**核心流程：**
1. 用户进入门店装修额度外报表页面
2. 填写查询条件（门店编码/名称、经销商编码/名称、创建时间范围、开票单位编码/名称）
3. 点击查询，调用后端接口分页返回额度外兑现数据
4. 用户查看报表数据，可导出Excel归档

```
开始 → 设定查询条件 → 点击查询 → 后端分页查询EPMS.MKT_TERMINAL_RE_CASHOUT_VIEW → 返回额度外兑现数据列表 → 查看报表/导出Excel → 结束
```

- 上游支撑：门店装修额度外兑现单（FIN_FEE_TERMINAL_RE_CASHOUT）、门店验收与报销单（FIN_FEE_CHECK_BX_HEADER）、hlod报表引擎、组织/门店/经销商主数据
- 下游影响：额度外兑现情况分析、发票税金核对、Excel导出归档、内部管理决策参考

## 重点逻辑

### 重点逻辑1：纯报表查询页面【只读查询】

- **业务意义**：供内部人员查询门店装修额度外兑现的汇总报表信息，了解额度外兑现的整体情况及资金使用分布
- **具体逻辑描述**：
  - 本页面为hlod低代码报表页面，无独立前端源码
  - 仅提供查询和导出功能，不支持新增、修改、删除操作
  - 数据来源于额度外兑现视图 `EPMS.MKT_TERMINAL_RE_CASHOUT_VIEW`，包含兑现金额、兑现比例、发票税金等信息
  - 查询接口设置 `permissionPublic = true`，为公开权限接口

### 重点逻辑2：数据来源视图

- **业务意义**：通过视图整合多表数据，提供完整的额度外兑现明细
- **具体逻辑描述**：
  - 查询视图 `EPMS.MKT_TERMINAL_RE_CASHOUT_VIEW`，该视图整合了额度外兑现头表（FIN_FEE_TERMINAL_RE_CASHOUT）、验收报销单（FIN_FEE_CHECK_BX_HEADER）、门店信息、经销商信息等
  - 视图字段包含审核状态、兑现单号、验收报销单号、经销商信息、门店信息、发票信息、兑现金额等60+个字段

### 重点逻辑3：查询条件匹配规则

- **业务意义**：支持多维度灵活筛选额度外兑现数据
- **具体逻辑描述**：
  - 模糊查询（LIKE '%xxx%'）：门店编码、门店名称、经销商编码、经销商名称、开票单位名称
  - 精确查询：组织ID、开票单位编码
  - 范围查询：创建时间范围（startTime/endTime）
  - 时间格式校验：开始/结束时间使用正则校验 `^\d{4}-\d{2}-\d{2}$`，必须为YYYY-MM-DD格式

### 重点逻辑4：与额度外兑现管理页面共用后端代码

- **业务意义**：报表查询复用额度外兑现的查询逻辑，减少重复开发
- **具体逻辑描述**：
  - 报表查询使用ae-report模块的 `FinFeeTerminalReCashoutServiceImpl.mktTerminalReCashoutListSearch` 方法
  - 通过 `PageHelper.doPageAndSort` 实现分页查询
  - 底层调用Repository的 `mktTerminalReCashoutListSearch` 方法，查询 `EPMS.MKT_TERMINAL_RE_CASHOUT_VIEW` 视图
  - 与ae-business模块中的额度外兑现管理页面（含CRUD+工作流）使用相同的底层数据，但报表页面仅展示不可编辑

```sql
SELECT
    v.audit_stat,
    v.organization_id,
    v.division_id,
    v.entid,
    v.procname,
    v.terminal_cashout_id,
    v.terminal_cashout_code,
    v.check_bx_id,

    v.ledger_date,
    v.finished_time,
    v.out_cashout_end_time,
    v.terminal_code,
    v.terminal_name,
    v.pay_type,
    v.vendor_code,
    v.cost_center_code,
    v.note,
    v.creator_name,
    v.create_time,
    v.updator_name,
    v.update_time,
    v.cash_count,
    v.invoice_tax_rate,
    v.invoice_type,
    v.this_sur_cashout_amt,
    v.this_bx_proportion,
    v.this_apply_cashout_amt,
    v.after_tax_cashout_amt,
    v.fact_invoice_amt,
    v.invoice_tax_amt,
    v.fact_invoice_notax_amt,

    v.invoice_amt,
    v.tax_rate,
    v.tax_amount,
    v.no_tax_amt

    AND v.organization_id = #{organizationId}                     -- 组织ID（精确）
    AND v.terminal_code LIKE '%' || #{terminalCode} || '%'        -- 门店编码（模糊）

    AND v.billing_unit_name LIKE '%' || #{billingUnitName} || '%' -- 开票单位名称（模糊）
```

#### 报错1：开始时间格式必须为YYYY-MM-DD
- **触发条件**：点击"查询"按钮，调用mktTerminalReCashoutListSearch接口时，DTO中startTime字段值不符合正则 `^\d{4}-\d{2}-\d{2}$`
- **逻辑分析**：报表查询按创建时间范围筛选FIN_FEE_TERMINAL_RE_CASHOUT.CREATE_TIME，需用to_date转换字符串为日期。若前端日期选择器异常返回非标准格式（如YYYY/MM/DD或带时分秒）、或手工拼接参数格式错误，@Pattern注解校验失败抛出异常，查询无法执行。该格式校验确保to_date转换不会因格式不匹配抛出Oracle异常。
- **排查SQL**：
  ```sql
  SELECT terminal_cashout_id   AS 兑现单ID,
         terminal_cashout_code AS 兑现单号,
         cust_name             AS 经销商名称,
         terminal_name         AS 门店名称,
         create_time           AS 创建时间
  FROM   fin_fee_terminal_re_cashout
  WHERE  create_time < SYSDATE - 365
  ORDER  BY create_time DESC;
  ```

#### 报错2：结束时间格式必须为YYYY-MM-DD
- **触发条件**：点击"查询"按钮，调用mktTerminalReCashoutListSearch接口时，DTO中endTime字段值不符合正则 `^\d{4}-\d{2}-\d{2}$`
- **逻辑分析**：结束时间用于限定查询上界，SQL中通过 `create_time <= to_date(#{endTime}, 'yyyy-mm-dd') + 1` 实现含当天查询。若endTime格式错误（如传入YYYYMMDD或带时间戳），@Pattern注解校验失败抛出异常。若绕过校验传入非法字符串，to_date转换会抛出ORA-01861等Oracle格式错误，故前置正则校验提前拦截。
- **排查SQL**：
  ```sql
  SELECT terminal_cashout_id   AS 兑现单ID,
         terminal_cashout_code AS 兑现单号,
         cust_name             AS 经销商名称,
         terminal_name         AS 门店名称,
         create_time           AS 创建时间
  FROM   fin_fee_terminal_re_cashout
  WHERE  create_time >= SYSDATE - 30
  ORDER  BY create_time DESC;
  ```

#### 报错3：网络请求失败/接口调用异常
- **触发条件**：点击"查询"或"导出"按钮，调用POST /v1/{organizationId}/terminalReport/mkt-terminal-re-cashout-list/search接口时，前端未收到响应或收到非2xx状态码（如500、502、504）
- **逻辑分析**：本页面为hlod低代码报表页面，查询依赖后端TerminalReportController.mktTerminalReCashoutListSearch接口分页查询EPMS.MKT_TERMINAL_RE_CASHOUT_VIEW视图。若后端ae-report服务未启动、Oracle数据库连接异常、视图编译错误、SQL执行超时（如视图关联多表慢查询）、网络中断、或网关转发失败，均会导致接口调用异常。需检查后端服务健康状态、数据库连接、视图状态、网络连通性。


#### 报错4：权限不足/未登录

- **逻辑分析**：本报表接口声明@Permission(level = ResourceLevel.ORGANIZATION, permissionPublic = true)，permissionPublic=true表示公开权限接口，但仍需有效的登录态。若用户未登录（token过期/丢失）、或organizationId路径参数与用户所属组织不匹配、或前端路由未配置该报表菜单，均会触发权限校验失败。hlod低代码页面通过路由配置和接口权限双重校验。需重新登录或联系管理员分配报表查看权限。

## 常见问题FAQ

**Q1：报表数据来源是什么？**
A：数据来源于Oracle视图 `EPMS.MKT_TERMINAL_RE_CASHOUT_VIEW`，该视图整合了额度外兑现头表（FIN_FEE_TERMINAL_RE_CASHOUT）、验收报销单（FIN_FEE_CHECK_BX_HEADER）、门店信息、经销商信息等多表数据。

**Q2：报表支持哪些查询条件？**
A：支持门店编码、门店名称、经销商编码、经销商名称（模糊匹配）、创建时间范围、开票单位编码（精确匹配）、开票单位名称（模糊匹配）。

**Q3：报表是否支持导出？**
A：是，支持导出Excel，供内部管理决策与归档使用。

**Q4：报表是否支持新增/修改/删除？**
A：不支持，本页面为纯查询报表，仅支持查看和导出。新增/修改/删除操作在"门店装修-门店装修额度外兑现"页面进行。

**Q5：报表与额度外兑现管理页面的关系？**
A：报表查询复用额度外兑现的查询逻辑，数据来源相同，但报表页面仅展示不可编辑。额度外兑现管理页面（ae-business模块）包含完整的CRUD+工作流+推送共享/资金池功能。
