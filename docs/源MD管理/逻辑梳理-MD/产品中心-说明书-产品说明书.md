# 产品中心-说明书-产品说明书

## 业务流程

### 业务流程图

```text
开始 → ★新建产品说明书★ → 填写说明书信息（名称/编码/分类/内容） → 关联产品型号 → 上传附件 → 保存 → 提交审批 → ⚖审批通过？
  ├─（通过）说明书生效 → 可供产品前端展示 → 结束
  ├─（拒绝）状态变为审批拒绝 → 可修改后重新提交 → 结束
  └─（撤回）状态恢复为新建 → 可继续编辑 → 结束

版本升级：已审核说明书 → 版本+1 → 状态重置为新建 → 重新走审批流程
```

### 上游依赖

| 上游模块 | 依赖类型 | 依赖说明 | 依赖成立条件 |
|---------|---------|---------|------------|

### 下游影响

- 影响1：产品前端展示
  - 审批通过的说明书在产品详情中展示链接，用户可跳转查看说明书内容

- 影响2：型号关联表（ES_SPEC_MODEL）
  - 说明书关联产品型号后写入关联表，支持多对多关系

- 影响3：分类关联表（ES_SPECCLAS_REF）
  - 说明书关联产品分类后写入关联表

- 影响4：文件库（ES_DOCS）
  - 附件统一存入文件库

## 重点逻辑

### 重点逻辑1：说明书与型号多对多关联 `关联关系`

- **业务意义**：一份说明书可关联多个产品型号，一个型号也可有多份说明书

- **具体逻辑描述**

  - 第1点：通过ES_SPEC_MODEL表维护说明书与产品型号的多对多关联

  - 第2点：详情页支持关联和取消关联产品型号

### 重点逻辑2：说明书与分类多对多关联 `分类关联`

- **业务意义**：一份说明书可关联多个产品分类，按分类检索说明书

- **具体逻辑描述**

  - 第1点：通过ES_SPECCLAS_REF表维护说明书与产品分类的多对多关联

  - 第2点：分类以树形结构展示，支持选择分类节点

### 重点逻辑3：版本升级 `版本管理`

- **业务意义**：已审核说明书需要更新时，通过版本升级创建新版本，保留历史版本

- **具体逻辑描述**

  - 第1点：仅审批通过（APPROVED）且非历史版本（history≠2）的说明书可版本升级

  - 第2点：版本号+1，状态重置为新建（NEW），需重新走审批流程

  - 第3点：原版本保留为历史版本

### 重点逻辑4：审批流程 `工作流`

- **业务意义**：说明书对外展示，需审批通过后方可生效，避免错误文档流入前端

- **具体逻辑描述**

  - 第1点：提交时触发工作流SUB_PRODUCT_SPECIFICATION_MAIN

  - 第2点：审批通过后状态变为APPROVED，说明书可供展示

  - 第3点：审批拒绝后可重新编辑提交，撤回后恢复为新建

### 状态机

#### 状态机流转图

```text
NEW（新建） ──提交──→ RUN（审批中） ──审批通过──→ APPROVED（已审核）
                         │
                         ├──审核拒绝──→ REJECTED（审核拒绝） ──提交──→ RUN（审批中）
                         │
                         └──撤回──→ NEW（新建）

APPROVED（已审核） ──版本升级──→ NEW（新建，版本+1）
```

#### 状态机列表

| 状态机名称 | 状态释义 | 可执行的操作 |
|-----------|---------|------------|
| NEW | 新建 | 编辑、保存、提交、删除、关联产品 |
| RUN | 审批中 | 查看（不可编辑） |
| APPROVED | 已审核 | 查看、版本升级 |
| REJECTED | 审核拒绝 | 编辑、保存、提交、关联产品 |

#### 报错1：说明书名称不能为空！
- **触发条件**：详情页点击"保存"按钮时，说明书名称字段为空
- **逻辑分析**：前端DataSet.validate()校验说明书名称必填字段未通过，或后端实体注解@NotBlank校验失败。说明书名称是产品说明书的唯一标识，必填。
- **排查SQL**：
  ```sql
  SELECT S.ID AS 说明书ID, S.NAME AS 说明书名称, S.VERSION AS 版本,
         S.STATUS AS 状态, S.HISTORY AS 是否历史版本
  FROM LNK_PROD_MANUAL S
  WHERE S.ID = :manualId AND S.NAME IS NULL;
  ```

#### 报错2：产品编码不能为空
- **触发条件**：调用`GET /v1/{orgId}/es-specs`查询说明书PDF流时，请求参数EsSpecDTO的itemCode字段为空
- **逻辑分析**：后端`EsSpecServiceImpl.queryStreamByItemCode`方法首先校验esSpec参数及itemCode，当`StringUtils.isEmpty(esSpec.getItemCode())`为true时，抛出`CommonException("产品编码不能为空")`。该接口供产品前端展示说明书PDF时调用，itemCode为必传参数。
- **排查SQL**：
  ```sql
  -- 检查产品是否关联了说明书
  SELECT P.PROD_CODE AS 产品编码, P.PROD_NAME AS 产品名称,
         (SELECT COUNT(1) FROM ES_SPEC_MODEL M WHERE M.ITEM_CODE = P.PROD_CODE) AS 关联说明书数
  FROM LNK_PROD P
  WHERE P.PROD_CODE = :产品编码;
  ```

#### 报错3：说明书不存在
- **触发条件**：调用`GET /v1/{orgId}/es-specs`查询说明书PDF流时，根据itemCode、manualItemCode、attachmentUuid查询ES_SPEC未找到记录
- **逻辑分析**：后端`EsSpecServiceImpl.queryStreamByItemCode`调用`esSpecRepository.selectSpecDocs(itemCode, manualItemCode, attachmentUuid)`查询说明书，返回vo为null时抛出`CommonException("说明书不存在")`。根因可能为：1）产品未关联说明书；2）说明书未审批通过（APPROVED）；3）说明书为历史版本（history=2）未纳入查询。
- **排查SQL**：
  ```sql
  -- 检查产品编码对应的说明书是否存在且已审核
  SELECT S.SPEC_ID AS 说明书ID, S.SPEC_TITLE AS 说明书名称, S.VER AS 版本,
         S.HZ_APPROVE_STATUS AS 审批状态, S.HISTORY AS 是否历史版本,
         M.ITEM_CODE AS 关联产品编码
  FROM ES_SPEC S
  JOIN ES_SPEC_MODEL M ON M.SPEC_ID = S.SPEC_ID
  WHERE M.ITEM_CODE = :产品编码
    AND S.HZ_APPROVE_STATUS = 'APPROVED'
    AND NVL(S.HISTORY, 0) <> 2;
  ```

#### 报错4：说明书文件下载失败
- **触发条件**：调用`GET /v1/{orgId}/es-specs`查询说明书PDF流时，说明书记录存在但文件下载异常
- **逻辑分析**：后端`EsSpecServiceImpl.queryStreamByItemCode`在查询到说明书后，通过`fileClient`下载文件。若fileUrl包含`@his_data@`则获取签名URL下载，否则通过`fileClient.downloadFile`下载。下载过程抛出Exception时，logger记录错误日志并抛出`CommonException(e.getMessage())`。根因可能为：1）文件存储服务不可用；2）附件已被删除；3）文件URL失效。
- **排查SQL**：
  ```sql
  -- 检查说明书附件文档记录
  SELECT S.SPEC_ID AS 说明书ID, S.SPEC_TITLE AS 说明书名称,
         D.DOC_ID AS 文档ID, D.DOCNAME AS 文档名称, D.ATTACHMENT_UUID AS 附件UUID
  FROM ES_SPEC S
  JOIN ES_DOCS D ON D.SPEC_ID = S.SPEC_ID
  WHERE S.SPEC_ID = :说明书ID;
  ```

#### 报错5：查询参数不能为空!
- **触发条件**：调用`POST /v1/{orgId}/es-specs`（BcsApiController.querySpecUrl）查询说明书URL时，请求参数EsSpecParamDTO为null
- **逻辑分析**：后端`EsSpecServiceImpl.querySpecUrl`方法首先校验param是否为null，为null时抛出`CommonException("查询参数不能为空!")`。该接口供BCS外部系统查询说明书URL调用。
- **排查SQL**：
  ```sql
  -- 检查说明书关联型号表是否有数据（确认查询目标存在）
  SELECT COUNT(1) AS 关联型号记录数
  FROM ES_SPECMODEL_REF R
  WHERE R.ITEMCODE = :产品编码;
  ```

#### 报错6：查询类型只能是normal、custom，且对应值不能为空
- **触发条件**：调用`POST /v1/{orgId}/es-specs`查询说明书URL时，type参数不为"normal"或"custom"，或type为normal时itemCode为空，type为custom时model为空
- **逻辑分析**：后端`EsSpecServiceImpl.querySpecUrl`根据type分支校验：type="normal"时校验itemCode非空，type="custom"时校验model非空，其他type值均抛出`CommonException("查询类型只能是normal、custom，且对应值不能为空")`。normal模式按产品编码查询，custom模式按产品型号查询。
- **排查SQL**：
  ```sql
  -- 检查按产品编码(normal)或型号(custom)能否查到说明书关联
  SELECT R.ITEMCODE AS 产品编码, R.MODEL AS 产品型号, R.SPECID AS 说明书ID,
         R.MANUAL_ITEM_CODE AS 说明书物料编码
  FROM ES_SPECMODEL_REF R
  WHERE R.ITEMCODE = :产品编码 OR R.MODEL = :产品型号;
  ```

#### 报错7：权限不足，无法访问
- **触发条件**：用户访问产品说明书列表页/详情页或点击新建/导出/版本升级按钮时，当前角色未配置对应权限编码
- **逻辑分析**：前端`PERMISSION_PREFIX=arrow-ae:productInfo:esSpecProp`，新建按钮权限`arrow-ae:productInfo:esSpecProp.button.create`，导出按钮权限`arrow-ae:productInfo:esSpecProp.button.export`，列表行查看权限`arrow-ae:productInfo:esSpecProp.list.button.line.view`。HZERO权限拦截器校验失败返回403。
- **排查SQL**：
  ```sql
  -- 查询当前用户是否分配了说明书管理权限
  SELECT U.REAL_NAME AS 用户名, R.NAME AS 角色名, P.CODE AS 权限编码, P.TYPE AS 权限类型
  FROM HZERO.IAM_USER U
  JOIN HZERO.IAM_MEMBER M ON M.MEMBER_ID = U.ID
  JOIN HZERO.IAM_ROLE R ON R.ID = M.ROLE_ID
  JOIN HZERO.IAM_ROLE_PERMISSION RP ON RP.ROLE_ID = R.ID
  JOIN HZERO.IAM_PERMISSION P ON P.ID = RP.PERMISSION_ID
  WHERE U.REAL_NAME = :用户名
    AND P.CODE LIKE 'arrow-ae:productInfo:esSpecProp%';
  ```

#### 报错8：登录已过期，请重新登录
- **触发条件**：用户在说明书页面操作时，HZERO Token过期或被踢出登录
- **逻辑分析**：前端axios请求携带Authorization Token访问后端接口，后端网关校验Token有效性。Token过期时返回401状态码，前端axios响应拦截器捕获401并跳转登录页。
- **排查SQL**：
  ```sql
  -- 查询用户最近登录会话状态
  SELECT U.REAL_NAME AS 用户名, T.TOKEN_VALUE AS 令牌, T.EXPIRES_IN AS 有效期秒,
         T.CREATE_TIME AS 创建时间
  FROM HZERO.OAUTH_ACCESS_TOKEN T
  JOIN HZERO.IAM_USER U ON U.ID = T.USER_ID
  WHERE U.REAL_NAME = :用户名
  ORDER BY T.CREATE_TIME DESC;
  ```

#### 报错9：暂无数据
- **触发条件**：列表页查询返回空列表，前端DataSet无数据渲染
- **逻辑分析**：前端`es-specs/report`接口返回content为空数组。根因可能为：1）查询条件过严无匹配说明书；2）尚未创建任何说明书；3）说明书均为历史版本被过滤。前端FilterTableCom展示"暂无数据"占位。
- **排查SQL**：
  ```sql
  -- 检查说明书总数及非历史版本数量
  SELECT COUNT(1) AS 说明书总数,
         SUM(CASE WHEN NVL(HISTORY, 0) <> 2 THEN 1 ELSE 0 END) AS 当前版本数,
         SUM(CASE WHEN HZ_APPROVE_STATUS = 'APPROVED' THEN 1 ELSE 0 END) AS 已审核数
  FROM ES_SPEC;
  ```

#### 报错10：版本升级失败，请稍后重试
- **触发条件**：详情页点击"版本升级"按钮后保存时，调用`POST /v1/{orgId}/product-data/version-upgrade`接口返回异常
- **逻辑分析**：前端`handleUpgrade`将upgrade置为2、hzApproveStatus置为NEW、ver+1后保存。后端`ProductDataServiceImpl.versionUpgrade`根据specid查询原说明书主数据、关联型号、附件文档，复制创建新版本。当specid为null时直接返回null不创建新版本；当esSpecRepository.selectByPrimary查询不到原数据时后续操作NPE。版本升级按钮仅审批状态=APPROVED且history≠2时显示。
- **排查SQL**：
  ```sql
  -- 检查待版本升级的说明书状态是否符合条件
  SELECT SPEC_ID AS 说明书ID, SPEC_TITLE AS 说明书名称, VER AS 版本,
         HZ_APPROVE_STATUS AS 审批状态, HISTORY AS 是否历史版本,
         UPGRADE AS 是否升级标记, SOURCE_ID AS 源版本ID
  FROM ES_SPEC
  WHERE SPEC_ID = :说明书ID
    AND HZ_APPROVE_STATUS = 'APPROVED'
    AND NVL(HISTORY, 0) <> 2;
  ```

### 常见问题

- 问题1：说明书提交审批后能否修改
  - 原因：审批中（RUN）和审批通过（APPROVED）状态不可修改
  - 解决思路：审批拒绝后可重新编辑提交，或通过版本升级创建新版本

- 问题2：版本升级后原版本数据是否保留
  - 原因：版本升级创建新版本，原版本标记为历史版本（history=2）
  - 解决思路：原版本数据保留，可通过历史版本查看
