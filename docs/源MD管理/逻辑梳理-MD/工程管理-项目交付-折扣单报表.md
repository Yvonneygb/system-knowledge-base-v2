## 业务流程

### 业务流程图

```text
用户进入折扣单报表页面（低代码页面hlod）
    │
    ├── 设置查询条件（折扣单号、申请日期、客户、合同、项目、产品等）
    │
    ├── 点击查询 → POST /discountApply/getReportPage
    │       ├── creationDate范围转换（start/end → createDateFrom/createDateTo）
    │       ├── 关联折扣单头表+行表+客户+合同+项目+出库行汇总
    │       └── @ProcessLovValue自动翻译值集字段
    │
    └── 导出 → GET /discountApply/get-report-page-export
            └── 查询结果转换为ExportVO后全量导出
```

| 上游模块 | 依赖类型 | 依赖说明 | 依赖成立条件 |

## 重点逻辑

### 重点逻辑1：纯报表查询页面

- **业务意义**：提供折扣单数据的多维度查询和汇总展示，支撑折扣执行监控与对账

- **具体逻辑描述**

  - 第1点：本页面为hlod低代码报表页面，无独立前端源码，仅提供查询和导出功能

  - 第2点：支持按合同、客户、项目、时间等多条件查询

  - 第3点：关联查询折扣单头、行、客户、合同、项目、出库行汇总等表

### 重点逻辑2：确认出库数量汇总

- **业务意义**：汇总折扣单行对应的已出库数量，监控折扣单执行进度

- **具体逻辑描述**

  - 第1点：关联sa_out_bill_line表，按discount_apply_line_id分组汇总SUM(confirm_out_qty)

  - 第2点：确认出库金额=确认出库数量×折后单价

### 重点逻辑3：折后价格截断

- **业务意义**：折后价格和金额截断到3位小数，保证数据精度一致

- **具体逻辑描述**

  - 第1点：discounted_price使用trunc(discounted_price, 3)截断到3位小数

  - 第2点：discounted_amount使用trunc(discounted_amount, 3)截断到3位小数

### 重点逻辑4：工程家装区分

- **业务意义**：通过isHome参数区分工程和家装折扣单报表

- **具体逻辑描述**

  - 第1点：isHome=0为工程折扣单报表，isHome=2为家装折扣单报表

  - 第2点：页面固定传isHome=0

### 重点逻辑5：值集自动翻译

- **业务意义**：值集字段自动翻译为含义文本，便于阅读

- **具体逻辑描述**

  - 第1点：@ProcessLovValue注解自动翻译hzApproveStatus、contractType等值集字段

  - 第2点：翻译结果直接展示在报表中

**报表查询SQL（discountApplyReportQuery）：**

```sql
SELECT * FROM (
  SELECT da.creation_date, da.customer_code, da.customer_name,
         c.short_name, da.trading_company_name, ep.is_local,
         da.billing_unit_name, da.contract_code, da.contract_name,
         da.project_code, da.project_name, da.project_manager,
         da.discount_apply_code, da.discount_valid_date,
         da.contract_type, da.is_home, da.hz_approve_status,
         epc.strategic_related, epc.contract_amt, epc.supplement_type,
         ep.project_type, epc.valid AS contract_valid, epc.signed_date,
         report.area_full_name, report.address,
         epc.contract_unit, epc.project_category,
         dal.item_code, dal.item_name, dal.model, dal.color, dal.remark,
         dal.contract_qty, dal.replaced_qty, dal.delayed_qty, dal.active_qty, dal.ordered_qty,
         dal.stand_price, dal.base_discount_rate, dal.extra_discount_rate, dal.discount_rate,
         trunc(dal.discounted_price, 3) AS discounted_price,
         trunc(dal.discounted_amount, 3) AS discounted_amount,
         sa.confirm_out_qty,
         sa.confirm_out_qty * dal.discounted_price AS confirm_out_amount
  FROM epm_discount_apply da
    JOIN customer c ON da.customer_id = c.customer_id
    LEFT JOIN epm_project_contract epc ON da.contract_id = epc.contract_id
    LEFT JOIN epm_project ep ON ep.project_id = epc.project_id
    LEFT JOIN epm_report report ON da.project_id = report.project_id
    JOIN epm_discount_apply_line dal ON da.discount_apply_id = dal.discount_apply_id
    LEFT JOIN (SELECT SUM(sl.confirm_out_qty) confirm_out_qty, sl.discount_apply_line_id
               FROM sa_out_bill_line sl
               WHERE sl.discount_apply_line_id IS NOT NULL AND sl.discount_apply_line_id > 0
               GROUP BY sl.discount_apply_line_id) sa
      ON dal.discount_apply_line_id = sa.discount_apply_line_id
) WHERE is_home = 0
ORDER BY creation_date DESC
```

#### 报错1：查询条件时间范围不能为空
- **触发条件**：用户点击"查询"或"导出"按钮时，申请日期起止范围(creationDateStart/creationDateEnd)未选择或为空
- **逻辑分析**：前端校验申请日期范围必填，因折扣单报表数据量大，强制按EPM_DISCOUNT_APPLY.CREATION_DATE区间过滤以避免全表扫描。该报错为toast提醒级别，不发起后端请求
- **排查SQL**：
  ```sql
  -- 前端校验为主，后端可结合如下SQL确认时间范围内是否有数据
  SELECT COUNT(*) AS 期间数据量
  FROM EPM_DISCOUNT_APPLY eda
  WHERE eda.CREATION_DATE BETWEEN :creationDateStart AND :creationDateEnd
  ```

#### 报错2：导出数据量超过限制
- **触发条件**：用户点击"导出"按钮时，查询结果数据量超过@ExcelExport注解或系统配置的导出上限
- **逻辑分析**：导出调用Repository.search全量查询(不分页)，关联EPM_DISCOUNT_APPLY、EPM_DISCOUNT_APPLY_LINE、EPM_REPORT、SA_OUT_BILL_LINE多表。当结果集超过Excel单sheet上限(65536行)或系统配置的导出条数限制时抛出toast提醒。需缩小查询范围(缩短申请日期区间、增加客户/合同/项目/产品过滤条件)后重试
- **排查SQL**：
  ```sql
  SELECT COUNT(*) AS 待导出数据量
  FROM EPM_DISCOUNT_APPLY eda
  LEFT JOIN EPM_DISCOUNT_APPLY_LINE edl ON eda.DISCOUNT_APPLY_ID = edl.DISCOUNT_APPLY_ID
  WHERE eda.CREATION_DATE BETWEEN :creationDateStart AND :creationDateEnd
    AND (:customerCode IS NULL OR eda.CUSTOMER_CODE LIKE '%' || :customerCode || '%')
    AND (:contractCode IS NULL OR eda.CONTRACT_CODE LIKE '%' || :contractCode || '%')
    AND (:projectCode IS NULL OR eda.PROJECT_CODE = :projectCode)
  ```

#### 报错3：查询无数据
- **触发条件**：用户点击"查询"按钮时，查询条件无匹配数据
- **逻辑分析**：后端getReportPage方法按查询条件关联EPM_DISCOUNT_APPLY和EPM_DISCOUNT_APPLY_LINE查询，若结果集为空则前端展示"无数据"。需调整查询条件


#### 报错4：报表查询超时
- **触发条件**：查询时，查询数据量过大导致数据库查询超时
- **逻辑分析**：后端getReportPage方法关联EPM_DISCOUNT_APPLY、EPM_DISCOUNT_APPLY_LINE、EPM_PROJECT_CONTRACT、EPM_PROJECT、EPM_REPORT、SA_OUT_BILL_LINE多表查询，若查询条件过宽导致数据量过大则可能超时。需缩小查询范围
- **排查SQL**：
  ```sql
  SELECT COUNT(*) AS 预估数据量
  FROM EPM_DISCOUNT_APPLY eda
  WHERE eda.IS_HOME = 0
    AND eda.CREATION_DATE BETWEEN :creationDateStart AND :creationDateEnd
  -- 若数据量过大(超过10万)，建议缩小查询范围
  ```

#### 报错5：导出失败，请稍后重试
- **触发条件**：导出时，导出处理异常(如内存不足、IO异常等)
- **逻辑分析**：导出方法中try-catch捕获异常，若处理失败则提示稍后重试。需稍后重试或联系管理员查看后端日志
- **排查SQL**：
  ```sql
  SELECT sem.OBJID, sem.OBJTYPENAME, sem.ERROR_MSG, sem.CREATION_DATE
  FROM SYS_EXCEPTION_MSG sem
  WHERE sem.OBJTYPENAME = '折扣单报表'
  ORDER BY sem.CREATION_DATE DESC
  ```

#### 报错6：折扣单数据不完整
- **触发条件**：查询时，折扣单关联数据缺失(如客户、合同、项目等关联数据不存在)
- **逻辑分析**：后端getReportPage方法关联查询CUSTOMER、EPM_PROJECT_CONTRACT、EPM_PROJECT等表，若关联数据缺失则部分字段为空。需检查折扣单数据完整性
- **排查SQL**：
  ```sql
  SELECT eda.DISCOUNT_APPLY_ID, eda.DISCOUNT_APPLY_CODE, eda.CUSTOMER_ID, eda.CONTRACT_ID, eda.PROJECT_ID,
         c.CUSTOMER_CODE, epc.CONTRACT_CODE, ep.PROJECT_CODE
  FROM EPM_DISCOUNT_APPLY eda
  LEFT JOIN CUSTOMER c ON eda.CUSTOMER_ID = c.CUSTOMER_ID
  LEFT JOIN EPM_PROJECT_CONTRACT epc ON eda.CONTRACT_ID = epc.CONTRACT_ID
  LEFT JOIN EPM_PROJECT ep ON eda.PROJECT_ID = ep.PROJECT_ID
  WHERE eda.IS_HOME = 0
    AND (c.CUSTOMER_ID IS NULL OR epc.CONTRACT_ID IS NULL OR ep.PROJECT_ID IS NULL)
  ```

### 常见问题

- 问题1：报表查询超时？
  - 原因：查询条件过宽导致数据量过大
  - 解决思路：缩小查询条件范围，增加时间筛选

- 问题2：折后价格为什么只有3位小数？
  - 原因：SQL中使用trunc(dal.discounted_price, 3)截断到3位小数，discounted_amount同理
  - 解决思路：这是预期行为，保证数据精度一致

- 问题3：确认出库数量怎么计算的？
  - 原因：关联sa_out_bill_line表，按discount_apply_line_id分组汇总SUM(confirm_out_qty)
  - 解决思路：即该折扣单行对应的所有要货订单行的已出库数量之和

- 问题4：项目所在地和项目地址从哪里来？
  - 原因：关联epm_report表（非epm_project），通过project_id关联查询area_full_name和address
  - 解决思路：这是报表专用关联表

- 问题5：交易公司和开票单位为什么是精确匹配？
  - 原因：查询条件中tradingCompanyName和billingUnitName使用=精确匹配，而非like模糊匹配
  - 解决思路：请输入完整名称
