# 工程管理-项目商机-战略经理变更

> 本页面为低代码页面(hlod)，无独立前端源码，基于后端API与Entity梳理。后端Controller暴露2个校验接口，保存/提交通过低代码通用接口和工作流引擎完成。

## 业务流程

### 变更如何流转

创建变更申请单 → 添加战略项目明细行 → 保存校验 → 提交校验 → 工作流审批 → 审批通过回写项目经理。

```
用户进入战略经理变更页面
  → 新增变更申请单（EPM_PROJECT_MANAGER）
  → 添加变更明细行（EPM_PROJECT_MANAGER_LINE）
    → 选择战略项目（projectId、projectCode、projectName）
    → 填写原项目经理工号（empid）
    → 填写变更后项目经理工号（toEmpid）
  → 保存校验（POST /save-verify）：校验同一张单内战略项目编码不重复
  → 保存申请单和明细行
  → 提交校验（GET /submit-verify）：
    → 校验明细行存在
    → 校验战略项目无在途申请（countVerify，HZ_APPROVE_STATUS='RUN'）
  → 提交审批，触发工作流（STRATEGIC_MANAGER_CHANGE_MAIN）
  → 审批通过后执行 wfComplete：
    → 查询明细行关联的战略项目(EPM_PROJECT)和报备(EPM_REPORT)
    → 查询新项目经理用户信息(IamUser，realName)
    → 批量更新战略项目和报备的 MANAGER=realName、EMPID=toEmpid
```

### 全链路流程图

```
开始 → ★新建变更申请★ → 添加战略项目明细行 → 保存校验(项目编码不重复) → 提交校验(无在途申请)
     → 提交工作流 · ⚖审批通过？ → 更新战略项目/报备项目经理 → 结束（拒绝则修改重提）

上游支撑：战略项目(EPM_PROJECT)、报备(EPM_REPORT)、用户(IamUser)、工作流引擎
下游影响：战略项目项目经理字段、报备项目经理字段
```

## 重点逻辑

### 重点逻辑1：同一张申请单内战略项目不可重复

- **业务意义**：避免同一张变更申请单内对同一战略项目重复发起变更，造成数据冗余
- **具体逻辑描述**：
  - 保存时前端调用POST /save-verify接口，传入明细行DTO列表
  - 后端saveVerify方法遍历DTO列表，检测projectCode是否重复出现
  - 若存在重复，抛出异常"以下战略项目编码重复，请检查！{重复编码列表}"
  - 校验通过后前端才执行实际保存

### 重点逻辑2：战略项目在途申请拦截

- **业务意义**：避免同一战略项目同时存在多个审批中的变更申请，防止审批通过后项目经理被多次覆盖
- **具体逻辑描述**：
  - 提交时前端调用GET /submit-verify接口，传入epmProjectManagerId
  - 后端submitVerify方法先校验明细行存在，为空抛异常"战略经理变更申请明细行不存在！"
  - 提取明细行中所有projectCode(distinct)，调用countVerify查询
  - countVerify SQL查询EPM_PROJECT_MANAGER中HZ_APPROVE_STATUS='RUN'(审批中)的申请单关联的明细行，匹配projectCode
  - 若存在在途申请，抛出异常"以下战略项目已有在途申请，无法重复提交，请等待原申请流程完成。详情如下：{项目编码列表}"

### 重点逻辑3：工作流审批回调批量回写

- **业务意义**：审批通过后将新项目经理姓名和工号同步至战略项目及其下所有报备记录，保证数据一致性
- **具体逻辑描述**：
  - 工作流编码：STRATEGIC_MANAGER_CHANGE_MAIN（战略经理变更）
  - 审批通过回调wfComplete方法，objId为申请单ID
  - 查询申请单下所有明细行(EPM_PROJECT_MANAGER_ID=objId)
  - 提取projectIdList，批量查询战略项目(EpmProject.selectByIds)和报备(EpmReport, PROJECT_ID in projectIdList)
  - 提取toEmpid列表，查询用户信息(IamUser, LOGIN_NAME in toEmpid)，构建loginName→realName映射
  - 遍历明细行：更新对应战略项目的MANAGER=realName、EMPID=toEmpid；更新对应报备列表的MANAGER、EMPID
  - batchUpdateOptional批量更新战略项目(MANAGER, EMPID字段)
  - batchUpdateOptional批量更新报备(MANAGER, EMPID字段)

### 重点逻辑4：报备按项目分组批量更新

- **业务意义**：一个战略项目可能关联多条报备记录，变更时需同步更新所有报备的项目经理
- **具体逻辑描述**：
  - 查询报备时按PROJECT_ID in projectIdList批量查询
  - 使用groupingBy(EpmReport::getProjectId)按项目ID分组，构建projectId→List<EpmReport>映射
  - 遍历明细行时，根据projectId从映射中获取该项目的所有报备记录，逐条更新MANAGER和EMPID
  - 最终一次性batchUpdateOptional批量更新所有报备

### saveVerify保存校验逻辑

```
入参：List<EpmProjectManagerLineDTO> dtos
1. 遍历dtos，检测projectCode是否重复出现
2. 若存在重复 → 抛出 CommonException("以下战略项目编码重复，请检查！{重复编码}")
3. 校验通过 → 返回成功
```

### submitVerify提交校验逻辑

```
入参：Long epmProjectManagerId
1. 查询明细行(EPM_PROJECT_MANAGER_ID=epmProjectManagerId)
2. 明细行为空 → 抛出 CommonException("战略经理变更申请明细行不存在！")
3. 提取projectCodes(distinct)
4. 调用countVerify查询在途申请：
   SELECT distinct l.PROJECT_CODE
   FROM EPM_PROJECT_MANAGER m
   LEFT JOIN EPM_PROJECT_MANAGER_LINE l ON m.EPM_PROJECT_MANAGER_ID = l.EPM_PROJECT_MANAGER_ID
   WHERE m.HZ_APPROVE_STATUS = 'RUN'
     AND l.PROJECT_CODE IN (#{projectCodes})
5. 在途申请不为空 → 抛出 CommonException("以下战略项目已有在途申请，无法重复提交...{项目编码}")
6. 校验通过 → 返回成功
```

### wfComplete审批通过回调逻辑

```
入参：WfApproveDTO dto (objId=申请单ID)
1. 查询明细行(EPM_PROJECT_MANAGER_ID=objId)
2. 提取projectIdList(distinct)
3. 批量查询战略项目：epmProjectRepository.selectByIds(projectIdList)
4. 构建epmProjectMap: projectId → EpmProject
5. 批量查询报备：EpmReport where PROJECT_ID in projectIdList
6. 构建epmReportMap: projectId → List<EpmReport> (groupingBy)
7. 提取toEmpid列表(distinct, 非空)
8. 查询用户：IamUser where LOGIN_NAME in toEmpidList
9. 构建iamUserMap: loginName → IamUser
10. 遍历明细行：
    - 获取新用户 iamUser = iamUserMap.get(toEmpid)
    - 获取 projectId
    - 若 epmProjectMap 含 projectId：
        epmProject.setManager(iamUser.getRealName())
        epmProject.setEmpid(toEmpid)
    - 若 epmReportMap 含 projectId：
        遍历报备列表，逐条 setManager(realName)、setEmpid(toEmpid)
11. batchUpdateOptional(epmProjects, MANAGER, EMPID)
12. batchUpdateOptional(epmReports, MANAGER, EMPID)
13. return true
```

### 保存校验

- 校验1：同一张申请单内战略项目编码不可重复 —— 避免对同一战略项目重复发起变更
  - **详细逻辑**：前端调用POST /save-verify接口，后端saveVerify遍历DTO列表检测projectCode重复，重复时抛出异常"以下战略项目编码重复，请检查！"
  - **系统体现**：保存时前端先调用校验接口，校验失败阻断保存
  - **排查SQL**：`SELECT PROJECT_CODE, COUNT(*) FROM EPM_PROJECT_MANAGER_LINE WHERE EPM_PROJECT_MANAGER_ID = #{申请单ID} GROUP BY PROJECT_CODE HAVING COUNT(*) > 1;`

### 提交校验

- 校验1：明细行必须存在 —— 申请单必须包含至少一条变更明细
  - **详细逻辑**：后端submitVerify查询明细行，为空时抛出异常"战略经理变更申请明细行不存在！"
  - **系统体现**：提交时调用GET /submit-verify接口，校验失败阻断提交
  - **排查SQL**：`SELECT COUNT(*) FROM EPM_PROJECT_MANAGER_LINE WHERE EPM_PROJECT_MANAGER_ID = #{申请单ID};`

- 校验2：战略项目无在途申请 —— 同一战略项目不可同时存在多个审批中的变更申请
  - **详细逻辑**：后端submitVerify调用countVerify查询HZ_APPROVE_STATUS='RUN'的申请单关联的项目编码，存在时抛出异常"以下战略项目已有在途申请，无法重复提交，请等待原申请流程完成。"
  - **系统体现**：提交时调用GET /submit-verify接口，countVerify SQL拦截在途申请
  - **排查SQL**：`SELECT distinct l.PROJECT_CODE FROM EPM_PROJECT_MANAGER m LEFT JOIN EPM_PROJECT_MANAGER_LINE l ON m.EPM_PROJECT_MANAGER_ID = l.EPM_PROJECT_MANAGER_ID WHERE m.HZ_APPROVE_STATUS = 'RUN' AND l.PROJECT_CODE IN (#{待提交项目编码列表});`

### 状态机

```text
┌──────────┐  提交申请  ┌──────────┐  审批通过  ┌──────────┐
│  新建    │ ────────→ │ 审批中    │ ────────→ │ 已完成   │
│ (DRAFT)  │           │ (RUN)    │           │ (APPROVED)│
└──────────┘           └────┬─────┘           └──────────┘
      ↑                      │
      │                审批拒绝
      │                      │
      └──────────────────────┘
                     │
                 (REJECTED)
```

### 下游影响

- **战略项目(EPM_PROJECT)**：审批通过后MANAGER字段更新为新项目经理真实姓名，EMPID更新为新工号
- **报备(EPM_REPORT)**：审批通过后该项目下所有报备记录的MANAGER和EMPID同步更新
- **项目透视/报备查询**：项目经理信息变更后，后续项目透视和报备查询展示新的项目经理

#### 报错1：以下战略项目编码重复，请检查！{编码列表}
- **触发条件**：保存战略经理变更申请时，同一申请单(EPM_PROJECT_MANAGER)内存在多条明细行(EPM_PROJECT_MANAGER_LINE)的PROJECT_CODE重复
- **逻辑分析**：在saveVerify方法中遍历DTO的明细行列表，按PROJECT_CODE分组统计，若任一编码出现次数>1则收集到重复列表并抛出阻断性报错。需删除重复明细行后重新保存
- **排查SQL**：
  ```sql
  SELECT epml.PROJECT_CODE, COUNT(*) AS 重复次数,
         LISTAGG(epml.EPM_PROJECT_MANAGER_LINE_ID, ',') AS 明细行ID列表
  FROM EPM_PROJECT_MANAGER_LINE epml
  WHERE epml.EPM_PROJECT_MANAGER_ID = :epmProjectManagerId
  GROUP BY epml.PROJECT_CODE
  HAVING COUNT(*) > 1
  ```

#### 报错2：战略经理变更申请明细行不存在！
- **触发条件**：提交战略经理变更申请时，申请单没有明细行(EPM_PROJECT_MANAGER_LINE查询为空)
- **逻辑分析**：在submitVerify方法中按EPM_PROJECT_MANAGER_ID查询明细行，若结果为空则抛出阻断性报错。变更申请必须至少包含一条变更明细行才能提交
- **排查SQL**：
  ```sql
  SELECT epm.EPM_PROJECT_MANAGER_ID, epm.EPM_PROJECT_MANAGER_CODE, epm.HZ_APPROVE_STATUS,
         (SELECT COUNT(*) FROM EPM_PROJECT_MANAGER_LINE epml
          WHERE epml.EPM_PROJECT_MANAGER_ID = epm.EPM_PROJECT_MANAGER_ID) AS 明细行数量
  FROM EPM_PROJECT_MANAGER epm
  WHERE epm.EPM_PROJECT_MANAGER_ID = :epmProjectManagerId
  -- 若明细行数量为0，则触发该报错
  ```

#### 报错3：以下战略项目已有在途申请，无法重复提交，请等待原申请流程完成。详情如下：{编码列表}
- **触发条件**：提交战略经理变更申请时，待提交的战略项目(PROJECT_CODE)已存在审批中(HZ_APPROVE_STATUS='RUN')的变更申请
- **逻辑分析**：在countVerify方法中按DTO中所有PROJECT_CODE批量查询EPM_PROJECT_MANAGER关联EPM_PROJECT_MANAGER_LINE，筛选HZ_APPROVE_STATUS='RUN'的申请。若存在则在途项目编码收集到列表并抛出阻断性报错，需等待原申请审批完成(APPROVED/REJECTED)后重新提交
- **排查SQL**：
  ```sql
  SELECT epm.EPM_PROJECT_MANAGER_ID, epm.EPM_PROJECT_MANAGER_CODE, epm.HZ_APPROVE_STATUS,
         epml.PROJECT_CODE, epml.PROJECT_ID, epml.EMPID, epml.TO_EMPID
  FROM EPM_PROJECT_MANAGER epm
  JOIN EPM_PROJECT_MANAGER_LINE epml ON epm.EPM_PROJECT_MANAGER_ID = epml.EPM_PROJECT_MANAGER_ID
  WHERE epm.HZ_APPROVE_STATUS = 'RUN'
    AND epml.PROJECT_CODE IN (:projectCodeList)
  ```

#### 报错4：NullPointerException: iamUser
- **触发条件**：审批通过回调(wfComplete)中，明细行TO_EMPID对应的用户在IAM_user表中不存在
- **逻辑分析**：wfComplete中按TO_EMPID列表批量查询IAM_USER构建iamUserMap，若某TO_EMPID在IAM_USER中无对应LOGIN_NAME记录，则iamUserMap.get(toEmpid)返回null，后续调用其方法时抛出NullPointerException。需检查用户数据是否同步或确认工号正确
- **排查SQL**：
  ```sql
  SELECT epml.EPM_PROJECT_MANAGER_LINE_ID, epml.PROJECT_CODE, epml.TO_EMPID,
         iu.LOGIN_NAME, iu.REAL_NAME
  FROM EPM_PROJECT_MANAGER_LINE epml
  LEFT JOIN IAM_USER iu ON iu.LOGIN_NAME = epml.TO_EMPID
  WHERE epml.EPM_PROJECT_MANAGER_ID = :epmProjectManagerId
    AND iu.LOGIN_NAME IS NULL
  -- 查出TO_EMPID对应用户不存在的明细行
  ```

#### 报错5：变更后项目经理工号不能为空
- **触发条件**：保存战略经理变更申请时，明细行TO_EMPID(变更后项目经理工号)为空
- **逻辑分析**：低代码表单对TO_EMPID字段配置必填校验，为空时阻断保存。TO_EMPID为空会导致审批通过回调时iamUserMap.get(toEmpid)返回null，进而抛出NullPointerException。需填写变更后项目经理工号后重新保存
- **排查SQL**：
  ```sql
  SELECT epml.EPM_PROJECT_MANAGER_LINE_ID, epml.EPM_PROJECT_MANAGER_ID,
         epml.PROJECT_CODE, epml.PROJECT_NAME, epml.EMPID, epml.TO_EMPID
  FROM EPM_PROJECT_MANAGER_LINE epml
  WHERE epml.EPM_PROJECT_MANAGER_ID = :epmProjectManagerId
    AND (epml.TO_EMPID IS NULL OR TRIM(epml.TO_EMPID) = '')
  -- 查出变更后项目经理工号为空的明细行
  ```

#### 报错6：战略项目编码不能为空
- **触发条件**：保存战略经理变更申请时，明细行PROJECT_CODE(战略项目编码)为空
- **逻辑分析**：低代码表单对PROJECT_CODE字段配置必填校验，为空时阻断保存。PROJECT_CODE为空会导致submitVerify中countVerify查询在途申请时无法匹配，且审批通过回调时无法定位目标战略项目。需选择战略项目后重新保存
- **排查SQL**：
  ```sql
  SELECT epml.EPM_PROJECT_MANAGER_LINE_ID, epml.EPM_PROJECT_MANAGER_ID,
         epml.PROJECT_ID, epml.PROJECT_CODE, epml.PROJECT_NAME
  FROM EPM_PROJECT_MANAGER_LINE epml
  WHERE epml.EPM_PROJECT_MANAGER_ID = :epmProjectManagerId
    AND (epml.PROJECT_CODE IS NULL OR TRIM(epml.PROJECT_CODE) = '')
  -- 查出战略项目编码为空的明细行
  ```

## 常见问题FAQ

### Q1: 审批通过后战略项目的项目经理没有更新？

**可能原因:** 工作流审批状态未更新为APPROVED，或wfComplete回调未正确触发，或TO_EMPID对应的用户不存在。

**排查SQL:**
```sql
-- 1. 查询变更申请审批状态
SELECT EPM_PROJECT_MANAGER_ID, EPM_PROJECT_MANAGER_CODE, HZ_APPROVE_STATUS, HZ_INSTANCE_ID
FROM EPM_PROJECT_MANAGER
WHERE EPM_PROJECT_MANAGER_CODE = '申请单号';

-- 2. 查询明细行TO_EMPID
SELECT EPM_PROJECT_MANAGER_LINE_ID, PROJECT_ID, PROJECT_CODE, EMPID, TO_EMPID
FROM EPM_PROJECT_MANAGER_LINE
WHERE EPM_PROJECT_MANAGER_ID = #{申请单ID};

-- 3. 检查TO_EMPID对应用户是否存在
SELECT LOGIN_NAME, REAL_NAME FROM IAM_USER
WHERE LOGIN_NAME = '#{toEmpid}';

-- 4. 查询战略项目当前项目经理
SELECT PROJECT_ID, PROJECT_CODE, MANAGER, EMPID
FROM EPM_PROJECT
WHERE PROJECT_ID IN (
    SELECT PROJECT_ID FROM EPM_PROJECT_MANAGER_LINE
    WHERE EPM_PROJECT_MANAGER_ID = #{申请单ID}
);
```

### Q2: 提交时报"战略项目已有在途申请"？

**说明:** 同一战略项目已存在审批中(HZ_APPROVE_STATUS='RUN')的变更申请，需等待原申请流程完成。

**排查SQL:**
```sql
-- 查询该战略项目的所有在途申请
SELECT m.EPM_PROJECT_MANAGER_ID, m.EPM_PROJECT_MANAGER_CODE, m.HZ_APPROVE_STATUS,
       l.PROJECT_CODE, l.EMPID, l.TO_EMPID
FROM EPM_PROJECT_MANAGER m
LEFT JOIN EPM_PROJECT_MANAGER_LINE l ON m.EPM_PROJECT_MANAGER_ID = l.EPM_PROJECT_MANAGER_ID
WHERE m.HZ_APPROVE_STATUS = 'RUN'
  AND l.PROJECT_CODE = '#{战略项目编码}';
```

### Q3: 审批通过后报备的项目经理没有同步更新？

**可能原因:** 报备记录的PROJECT_ID与变更明细行的PROJECT_ID不匹配，或报备数据不存在。

**排查SQL:**
```sql
-- 1. 查询变更明细行关联的项目ID
SELECT PROJECT_ID, PROJECT_CODE FROM EPM_PROJECT_MANAGER_LINE
WHERE EPM_PROJECT_MANAGER_ID = #{申请单ID};

-- 2. 查询这些项目下的报备记录
SELECT REPORT_ID, PROJECT_ID, MANAGER, EMPID
FROM EPM_REPORT
WHERE PROJECT_ID IN (
    SELECT PROJECT_ID FROM EPM_PROJECT_MANAGER_LINE
    WHERE EPM_PROJECT_MANAGER_ID = #{申请单ID}
);
```

### Q4: 保存时报"战略项目编码重复"？

**说明:** 同一张变更申请单内添加了相同战略项目的明细行，删除重复行后重新保存即可。

**排查SQL:**
```sql
-- 查询同一申请单内重复的项目编码
SELECT PROJECT_CODE, COUNT(*) AS CNT
FROM EPM_PROJECT_MANAGER_LINE
WHERE EPM_PROJECT_MANAGER_ID = #{申请单ID}
GROUP BY PROJECT_CODE
HAVING COUNT(*) > 1;
```

### Q5: wfComplete回调中抛出NullPointerException？

**可能原因:** 明细行TO_EMPID对应的用户在IAM_USER表中不存在，导致iamUserMap.get(toEmpid)返回null。

**排查SQL:**
```sql
-- 查询明细行TO_EMPID并检查用户是否存在
SELECT l.TO_EMPID, u.LOGIN_NAME, u.REAL_NAME
FROM EPM_PROJECT_MANAGER_LINE l
LEFT JOIN IAM_USER u ON u.LOGIN_NAME = l.TO_EMPID
WHERE l.EPM_PROJECT_MANAGER_ID = #{申请单ID}
  AND u.LOGIN_NAME IS NULL;
```
