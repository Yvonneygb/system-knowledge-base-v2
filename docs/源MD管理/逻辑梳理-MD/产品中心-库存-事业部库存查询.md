## 业务流程

### 业务流程图

```text
开始 → ★库存查询★ → 设置查询条件（产品编码/名称/型号/渠道/定位等） → 查询 → 后端注入当前用户事业部权限 → 返回库存数据 → 展示 → 结束
                                                                │
                                                    ├─DMS用户→ selectListDMS（含事业部值集过滤+经销商编码）
                                                    └─非DMS用户→ selectList（基础查询）
                                                                │
                                                    后处理：查询转换率→瓷砖产品线计算换算库存数
```

## 重点逻辑

### 重点逻辑1：事业部权限自动注入 `数据隔离`

- **业务意义**：用户只能查看自己所属事业部的库存数据，保证数据隔离

- **具体逻辑描述**

  - 第1点：后端自动注入当前用户的事业部ID（deptId）作为查询条件

  - 第2点：DMS系统用户额外注入经销商编码（acctCode），使用selectListDMS查询

  - 第3点：非DMS用户使用selectList查询，不限制经销商

### 重点逻辑2：产品编码多值查询 `批量查询`

- **业务意义**：支持一次性查询多个产品的库存，提升查询效率

- **具体逻辑描述**

  - 第1点：当产品编码输入框包含分隔符（逗号、顿号、分号、回车、换行）时，后端自动拆分为产品编码集合

  - 第2点：拆分后使用IN查询替代LIKE查询，精确匹配多个产品编码

### 重点逻辑3：库存数量上限控制 `库存上限`

- **业务意义**：展示的库存数量不超过配置的上限值，避免超量展示

- **具体逻辑描述**

  - 第1点：查询时关联LNK_INV_MAX表获取库存上限，支持Product（按产品）、ProdLine（按产品线）、ALL（全部）三种类型

  - 第2点：展示库存数量取实际库存汇总值与上限值的较小值：least(sum(库存数量), nvl(max(上限值), sum(库存数量)))

### 重点逻辑4：瓷砖产品线库存换算 `转换率计算`

- **业务意义**：瓷砖产品线需按转换率将库存数量换算为展示单位（箱）

- **具体逻辑描述**

  - 第1点：查询结果后后处理调用getInventoryListConversionRate获取转换率

  - 第2点：转换率通过Oracle函数cux_inv_convert_ex_pub.inv_um_convert计算

  - 第3点：瓷砖产品线库存换算数量 = 库存数量 / 转换率（保留2位小数，四舍五入）

  - 第4点：瓷砖产品线单位显示为"箱"，其他产品线显示产品原始单位

### 重点逻辑5：DMS用户事业部可见性过滤 `值集控制`

- **业务意义**：DMS系统用户可查看的事业部范围由值集配置控制

- **具体逻辑描述**

  - 第1点：DMS用户查询时通过DEPT_STOCK_S和DEPT_STOCK_P值集配置过滤可见事业部

  - 第2点：使用selectListDMS查询，复用queryInventoryQTY子查询

## 常见问题FAQ

### 报错一览表

| 报错信息 | 提示节点 | 根因与解决方案 | 等级 | 详细逻辑 |
|---------|---------|-------------|------|---------|
| 查询失败，请稍后重试 | 查询时 | 网络异常或后端服务不可用，检查网络连接和后端服务状态 | toast提醒 | [查看] |
| 权限不足，无法查询库存数据 | 页面加载时 | 当前用户无组织ID或事业部权限，检查用户角色和事业部值集配置 | 阻断性报错 | [查看] |

#### 报错1：查询失败，请稍后重试
- **触发条件**：点击查询按钮时，前端调用后端接口失败（HTTP非200或网络超时）
- **逻辑分析**：前端通过低代码页面（hlod）发起查询请求，后端走selectList/selectListDMS接口查询LNK_INVENTORY表。若后端服务不可用、数据库连接超时、Oracle函数cux_inv_convert_ex_pub.inv_um_convert执行异常等，均会导致请求失败。前端捕获异常后toast提示。
- **排查SQL**：
  ```sql
  -- 检查库存表是否有数据
  SELECT COUNT(1) AS 库存记录数 FROM LNK_INVENTORY WHERE ORG_ID = :organizationId;
  -- 检查产品主档是否存在
  SELECT COUNT(1) AS 产品数 FROM LNK_PROD WHERE ORG_ID = :organizationId;
  ```

#### 报错2：权限不足，无法查询库存数据
- **触发条件**：页面加载时，当前用户无组织ID或事业部权限
- **逻辑分析**：后端自动注入当前用户的事业部ID（deptId）作为查询条件。DMS用户额外通过DEPT_STOCK_S和DEPT_STOCK_P值集过滤可见事业部。若用户未配置事业部权限或值集为空，则查询不到任何库存数据。
- **排查SQL**：
  ```sql
  -- 检查用户事业部权限值集
  SELECT * FROM HPFM_LOV_VALUE WHERE LOV_CODE = 'DEPT_STOCK_S' AND ORGANIZATION_ID = :organizationId;
  SELECT * FROM HPFM_LOV_VALUE WHERE LOV_CODE = 'DEPT_STOCK_P' AND ORGANIZATION_ID = :organizationId;
  ```

#### 报错3：暂无数据
- **触发条件**：查询成功但结果集为空
- **逻辑分析**：查询条件无匹配结果，或LNK_INVENTORY表中无当前事业部/产品的库存数据。属正常提示，非异常。
- **排查SQL**：
  ```sql
  SELECT COUNT(1) AS 匹配数
  FROM LNK_INVENTORY I
  WHERE I.DEPT_ID = :deptId
    AND I.LH_PROD_ID LIKE :prodCode;
  ```

#### 报错4：用户未登录或会话已过期
- **触发条件**：页面加载或查询时，前端请求携带的token已失效
- **逻辑分析**：前端请求头中携带的Authorization token过期或无效，后端拦截器返回401状态码。前端跳转登录页。
- **排查SQL**：
  ```sql
  -- 检查用户是否存在且有效
  SELECT USER_ID, USER_NAME, STATUS FROM HPFM_USER WHERE USER_ID = :userId;
  ```

### 常见问题

- 问题1：查询结果中库存数量为0或低于实际库存
  - 原因：库存上限配置（LNK_INV_MAX）限制了展示数量。排查SQL：

    ```sql
    SELECT lim.PROD_ID, lim.DEPT_ID, lim.MAXIMUN, lim.TYPE
    FROM LNK_INV_MAX lim
    WHERE lim.PROD_ID = (SELECT ROW_ID FROM LNK_PROD WHERE PROD_CODE = #{prodCode});
    ```

  - 解决思路：检查LNK_INV_MAX表是否配置了过低的库存上限，或调整上限值

- 问题2：DMS用户查询不到某些事业部的库存
  - 原因：DMS用户的事业部可见范围由DEPT_STOCK_S/DEPT_STOCK_P值集控制。排查SQL：

    ```sql
    SELECT * FROM LNK_INVENTORY 
    WHERE DEPT_ID = #{事业部ID} 
      AND LH_PROD_ID = #{产品编码};
    ```

  - 解决思路：检查值集DEPT_STOCK_S和DEPT_STOCK_P是否包含目标事业部

- 问题3：瓷砖产品线库存换算数量不正确
  - 原因：转换率计算异常或Oracle函数cux_inv_convert_ex_pub.inv_um_convert返回错误。排查SQL：

    ```sql
    SELECT cux_inv_convert_ex_pub.inv_um_convert(#{from_uom}, #{to_uom}, #{prod_code}) AS conversion_rate
    FROM DUAL;
    ```

  - 解决思路：检查Oracle转换率函数是否正确部署，确认产品的单位配置

- 问题4：生产基地字段为空
  - 原因：LNK_PROD_BASE_CFG中IS_ACTIVE不为1。排查SQL：

    ```sql
    SELECT lpbc.DEPT_NAME, lpbc.PROD_LINE, lpbc.IS_ACTIVE
    FROM LNK_PROD_BASE_CFG lpbc
    WHERE lpbc.DEPT_NAME = #{事业部名称} AND lpbc.PROD_LINE = #{产品线};
    ```

  - 解决思路：在生产基地配置中将IS_ACTIVE设置为1
