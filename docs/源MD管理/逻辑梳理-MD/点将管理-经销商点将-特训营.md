# 点将管理-经销商点将-特训营

> 后端代码位于 mbo-business 微服务，RESTful API 路径前缀 `mlt/trainCampApply/*`。

## 业务流程

### 业务流程图

```
经销商发起特训营点将
        |
        v
特训营点将列表(本页面)
        |
        ├──新建──→ 弹窗展示特训营列表(campSelectPage) ──→ 选择特训营 ──→ 跳转详情页
        |                                            ├──保存──→ save接口 ──→ 草稿
        |                                            └──保存并提交──→ saveAndSubmit接口 ──→ 已提交
        |
        ├──编辑──→ 跳转详情页 ──→ 修改后保存/保存并提交
        |
        ├──删除──→ 校验草稿/驳回状态 ──→ delete接口
        |
        ├──取消申请──→ 校验提前7天且已签约 ──→ 弹窗填写取消原因 ──→ cancelApply接口
        |
        └──行操作──→ 查看详情/结算前确认/查看流程/编辑/删除
```

### 上游依赖

| 上游模块 | 依赖类型 | 依赖说明 | 依赖成立条件 |
|---------|---------|---------|-------------|
| 特训营管理 | 接口依赖 | 提供特训营列表供选择 | campApplyApi.campSelectPage接口可用 |
| 经销商主档 | 数据关联 | 提供经销商信息 | 当前登录用户关联经销商 |
| 法人主体 | 接口依赖 | 提供法人主体列表 | companyList(getDistributorLegalList)接口可用 |
| 讲师主档 | LOV选择 | 提供讲师列表供选择 | LOV配置可用 |
| HZERO权限服务 | 接口依赖 | 提供按钮权限校验 | permissionList权限编码 |
| 法大大电子签约 | 接口依赖 | 申请确认签合同 | useFDD钩子可用 |
| 工作流引擎 | 工作流 | 审批流程 | campApplyApproval 流程已部署 |

### 下游影响

- **特训营点将管理**：申请提交后进入管理审批，数据库共享
- **特训营详情**：查看特训营介绍，CampDetail组件
- **流程摘要组件**：查看流程展示审批历史，ProcessDetail组件
- **参训确认回执**：确认参训状态，数据回写
- **培训执行记录**：培训留痕，数据库共享
- **CRM订单系统**：同步CRM推送订单，pushCrm接口回写CRM_ORDER_CODE

## 重点逻辑

### 重点逻辑1：经销商发起视角

- **业务意义**：本菜单由经销商主动发起特训营点将申请，经销商自主选择特训营、法人主体与讲师。
- **具体逻辑描述**：通过`pageForDealer`接口实现经销商发起，后端自动按当前登录经销商过滤数据并写入DEALER_CODE、DEALER_NAME。

### 重点逻辑2：数据范围隔离

- **业务意义**：经销商仅能查看和操作自己发起的特训营点将记录，避免跨经销商数据泄露。
- **具体逻辑描述**：通过`pageForDealer`接口自动按当前登录经销商过滤，前端无需传经销商参数。

### 重点逻辑3：applyCode自动生成

- **业务意义**：保证特训营点将申请编码全局唯一、可追溯，作为主键贯穿全链路。
- **具体逻辑描述**：提交申请时系统自动生成唯一编码applyCode，写入APPLY_CODE字段。

### 重点逻辑4：特训营选择

- **业务意义**：从已发布的特训营中选择参训营次，确保参训信息来源唯一且有效。
- **具体逻辑描述**：点击"申请点将"按钮，弹窗展示特训营列表（`campApplyApi.campSelectPage`）。行操作：查看介绍（CampDetail弹窗）、报名（ApplyInfo弹窗）。报名弹窗填写：法人主体、交易公司、参训人员明细（入职日期、省市区、门店等）。

### 重点逻辑5：报名数据转换

- **业务意义**：将前端报名人员明细数据转换为后端可存储格式，保证数据完整性。
- **具体逻辑描述**：提交时将报名人员明细数据转换：entryDate格式化为YYYY-MM-DD；province数组拆分为provinceName/provinceCode、cityName/cityCode、areaName/areaCode；store对象拆分为store（terminalName）和storeCode（terminalCode）。

### 重点逻辑6：取消申请校验

- **业务意义**：约束取消申请的时间窗口与状态，避免临近培训取消影响讲师排期与参训安排。
- **具体逻辑描述**：时间校验 timeDiff >= 7（培训开始前7天），基于planStartTime，否则提示"只有培训时间开始前7天的流程可以发起点将取消申请！"；状态校验 approvalState === 'fdd_sign'（已法大大签约）；取消状态校验 !cancelApprovalState || cancelApprovalState === 'reject' || cancelApprovalState === 'oa_reject'。校验通过弹窗填写取消原因，调用`POST /mlt/trainCampApply/cancelApply`接口。

### 重点逻辑7：结算前确认

- **业务意义**：在结算前由经销商确认结算明细，保障结算数据准确。
- **具体逻辑描述**：行操作"结算前确认"，显示条件 beforeSettlementConfirmState === 'to_be_confirm'。弹窗展示CampSettleDetail结算明细。确认：beforeSettlementConfirmState=confirm；驳回：beforeSettlementConfirmState=reject。调用`POST /mlt/trainCampApply/settleBeforeConfirm`接口。

### 重点逻辑8：行操作显隐

- **业务意义**：根据申请状态差异化展示行操作，避免误操作。
- **具体逻辑描述**：编辑再发起：applyState === 'draft' 或 approvalState 为 reject/oa_reject；结算前确认：beforeSettlementConfirmState === 'to_be_confirm'；删除：applyState === 'draft' 或 approvalState 为 reject/fdd_reject/oa_reject。

### 重点逻辑9：讲师排期冲突校验

- **业务意义**：避免同一讲师在同一时间段被重复点将，保障讲师档期合理性。
- **具体逻辑描述**：保存时校验所选讲师在拟定开始时间至拟定结束时间区间内不存在已生效点将记录，存在冲突则提示并阻止保存。

### 选择弹窗

#### 弹窗1：申请点将弹窗（特训营列表选择，列表页头部"申请点将"按钮触发）

> 数据来源：`list.tsx` 的 `handleApply` + `stores/listConfig.tsx` 的 `applyListDSProps`/`applyListDScolumns`。接口 `campApplyApi.campSelectPage`。

入参：

| 参数名 | 来源 | 说明 |
|--------|------|------|
| campName | 查询栏输入 | 特训营名称模糊查询 |

列表列：序号、类型（值集MBO.CAMP_TYPE）、特训营名称、培训时间（planStartTime至planEndTime组合）、培训地点、讲师、操作（查看介绍/报名）。

行操作：
- 查看介绍：弹出特训营详情弹窗（CampDetail组件，type='camp'）
- 报名：调用 `handleSendApply`，弹出报名信息弹窗

查询SQL：

```sql
SELECT
  tc.CAMP_CODE    AS 特训营编码,
  tc.CAMP_NAME    AS 特训营名称,
  tc.CAMP_TYPE    AS 特训营类型,
  TO_CHAR(tc.PLAN_START_TIME, 'YYYY-MM-DD') AS 培训开始时间,
  TO_CHAR(tc.PLAN_END_TIME, 'YYYY-MM-DD') AS 培训结束时间,
  tc.LECTURER     AS 讲师,
  tc.ADDRESS      AS 培训地点
FROM TRAIN_CAMP tc
WHERE tc.CAMP_STATUS = 'valid'
  AND (:campName IS NULL OR tc.CAMP_NAME LIKE '%' || :campName || '%')
ORDER BY tc.CREATE_DATE DESC;
```

#### 弹窗4：交易公司选择弹窗（报名信息弹窗"交易公司"字段搜索图标触发）

#### 弹窗6：取消申请弹窗（列表页"取消点将"按钮触发）

> 数据来源：`list.tsx` 的 `handleCancel`，DataSet 为 `cancelApplyFormDSProps`。弹窗内嵌取消原因表单 + CampDetail（type='cancel'）。

入参：

| 参数名 | 来源 | 说明 |
|--------|------|------|
| applyCode | 列表选中行 | 申请编码 |
| cancelReason | 手动输入 | 取消原因（必填，TextArea） |

查询SQL：

```sql
SELECT
  tca.APPLY_CODE    AS 申请编码,
  TO_CHAR(tca.PLAN_START_TIME, 'YYYY-MM-DD') AS 培训开始时间,
  tca.APPROVAL_STATE AS 审核状态,
  ROUND((tca.PLAN_START_TIME - SYSDATE)) AS 距开始天数
FROM TRAIN_CAMP_APPLY tca
WHERE tca.APPLY_CODE = :applyCode;
```

### 保存/提交校验

> 数据来源：`list.tsx` 的 `submitApply` + `components/ApplyInfo/index.tsx` 的 `getApplyFormData`/`getUserList`。保存与保存并提交共用同一校验逻辑。

- 校验1：交易公司必填 —— applyFormDS.tradingCompanyName，明确交易主体
- 校验2：开票账户必填 —— applyFormDS.legalEntityName（选交易公司自动带出）
- 校验3：参训人员列表不能为空 —— userListDS至少1行
- 校验4：参训人员姓名必填 —— 每行name不能为空
- 校验5：参训人员手机号必填 —— 每行phone不能为空，且校验正则/^1[3456789]\d{9}$/
- 校验6：参训人员性别必填 —— 每行gender不能为空，值集MBO.CAMP_USER_SEX
- 校验7：参训人员学历必填 —— 每行education不能为空
- 校验8：参训人员所属门店必填 —— 每行store不能为空
- 校验9：参训人员省市区必填 —— 每行province不能为空
- 校验10：参训人员岗位必填 —— 每行post不能为空
- 校验11：参训人员入职日期必填 —— 每行entryDate不能为空
- 校验12：取消申请时取消原因必填 —— cancelFormDS.cancelReason
- 校验13：讲师排期冲突校验（后端） —— 避免同一讲师同一时间段被重复点将

### 状态机

流转图：

```
draft(新建) → submitted(已提交) → approved(审批通过) → valid(生效)
   → executing(执行中) → end(已完成)
rejected(审批驳回) → 可修改重提
valid → cancel_applied(取消申请中) → cancel_approved(已取消)
valid → to_be_confirm(待结算前确认) → confirm(已确认) → 结算
```

状态列表：

| 当前状态 | 触发动作 | 目标状态 |
|---------|---------|---------|
| draft | 保存并提交 | submitted |
| submitted | 审批通过 | approved |
| submitted | 审批驳回 | rejected |
| rejected | 修改后重新提交 | submitted |
| approved | 生效 | valid |
| valid | 开始执行 | executing |
| executing | 结束执行 | end |
| valid | 发起取消申请 | cancel_applied |
| cancel_applied | 取消审批通过 | cancel_approved |
| valid | 结算前确认 | to_be_confirm |
| to_be_confirm | 确认 | confirm |

### 排查SQL

```sql
-- 查询经销商特训营点将申请
SELECT
  tca.APPLY_CODE    AS 申请编码,
  tca.CAMP_NAME     AS 特训营名称,
  tca.LECTURER      AS 培训师,
  tca.APPLY_STATE   AS 点将状态,
  tca.APPROVAL_STATE AS 审核状态,
  TO_CHAR(tca.PLAN_START_TIME, 'YYYY-MM-DD') AS 开始时间,
  TO_CHAR(tca.PLAN_END_TIME, 'YYYY-MM-DD') AS 结束时间,
  tca.PRE_ORD_LECTURER_DAYS AS 拟点将天数,
  tca.REAL_ORD_LECTURER_DAYS AS 实际点将天数
FROM TRAIN_CAMP_APPLY tca
ORDER BY tca.CREATE_DATE DESC;

-- 查询可取消的特训营申请（提前7天且已签约）
SELECT
  tca.APPLY_CODE    AS 申请编码,
  TO_CHAR(tca.PLAN_START_TIME, 'YYYY-MM-DD') AS 培训开始时间,
  ROUND((tca.PLAN_START_TIME - SYSDATE)) AS 距开始天数
FROM TRAIN_CAMP_APPLY tca
WHERE tca.APPROVAL_STATE = 'fdd_sign'
  AND tca.PLAN_START_TIME > SYSDATE + 7
  AND (tca.CANCEL_APPROVAL_STATE IS NULL
       OR tca.CANCEL_APPROVAL_STATE IN ('reject', 'oa_reject'));

-- 查询待结算前确认的申请
SELECT
  tca.APPLY_CODE    AS 申请编码,
  tca.CAMP_NAME     AS 特训营名称,
  tca.BEFORE_SETTLEMENT_CONFIRM_STATE AS 结算前确认状态
FROM TRAIN_CAMP_APPLY tca
WHERE tca.BEFORE_SETTLEMENT_CONFIRM_STATE = 'to_be_confirm';

-- 查询讲师排期冲突
SELECT
  tca.APPLY_CODE    AS 申请编码,
  tca.LECTURER      AS 培训师,
  TO_CHAR(tca.PLAN_START_TIME, 'YYYY-MM-DD') AS 开始时间,
  TO_CHAR(tca.PLAN_END_TIME, 'YYYY-MM-DD') AS 结束时间
FROM TRAIN_CAMP_APPLY tca
WHERE tca.LECTURER_CODE = :lecturerCode
  AND tca.APPLY_STATE IN ('valid', 'executing')
  AND tca.PLAN_START_TIME <= :planEndTime
  AND tca.PLAN_END_TIME >= :planStartTime;
```

#### 报错1：请选择一条数据
- **触发条件**：点击编辑、删除、取消申请、结算前确认、查看流程等行操作按钮时，未选择数据或选择了多行
- **逻辑分析**：前端在执行单选操作前校验选中行数量，若 selectedRows.length ≠ 1 则阻止操作并提示"请选择一条数据"。单选操作需要明确的目标申请，未选择时无法确定操作对象，多选时操作对象不唯一
- **排查SQL**：
  ```sql
  SELECT APPLY_CODE AS 申请编码,
         CAMP_NAME AS 特训营名称,
         LECTURER AS 培训师,
         APPLY_STATE AS 申请状态,
         APPROVAL_STATE AS 审核状态
  FROM TRAIN_CAMP_APPLY
  ORDER BY CREATE_DATE DESC;
  ```

#### 报错2：只有培训时间开始前7天的流程可以发起点将取消申请！
- **触发条件**：点击取消申请按钮时，不满足"培训开始前7天"条件
- **逻辑分析**：前端计算时间差值 timeDiff = (PLAN_START_TIME - nowTime) / (24*60*60*1000)，校验 timeDiff >= 7（培训开始前至少7天）。校验不通过则提示"只有培训时间开始前7天的流程可以发起点将取消申请！"。此校验确保有充足时间通知讲师和参训人员调整安排，避免临时取消造成资源浪费
- **排查SQL**：
  ```sql
  SELECT APPLY_CODE AS 申请编码,
         CAMP_NAME AS 特训营名称,
         TO_CHAR(PLAN_START_TIME,'YYYY-MM-DD') AS 培训开始时间,
         APPROVAL_STATE AS 审核状态,
         ROUND(PLAN_START_TIME - SYSDATE) AS 距开始天数
  FROM TRAIN_CAMP_APPLY
  WHERE PLAN_START_TIME < SYSDATE + 7;
  ```

#### 报错3：该状态单据无法发起取消申请！
- **触发条件**：点击取消申请按钮时，审批状态不为 fdd_sign 或已有进行中的取消申请
- **逻辑分析**：前端执行多重校验：①校验 APPROVAL_STATE = 'fdd_sign'（已法大大签约）；②校验 CANCEL_APPROVAL_STATE 为空或为 reject/oa_reject（未取消或已驳回）。任一校验不通过则提示"该状态单据无法发起取消申请！"。确保仅已签约生效且未重复取消的单据可发起取消
- **排查SQL**：
  ```sql
  SELECT APPLY_CODE AS 申请编码,
         CAMP_NAME AS 特训营名称,
         APPROVAL_STATE AS 审核状态,
         CANCEL_APPROVAL_STATE AS 取消审核状态
  FROM TRAIN_CAMP_APPLY
  ```

#### 报错10：讲师排期冲突
- **触发条件**：保存或保存并提交时，所选讲师在拟定时间段内已有生效点将记录
- **逻辑分析**：后端保存前校验讲师排期冲突，查询 TRAIN_CAMP_APPLY 表中同一讲师（LECTURER_CODE 相同）且状态为 valid 或 executing 的点将记录，判断新申请的 [PLAN_START_TIME, PLAN_END_TIME] 与已有记录的时间段是否存在交集。若存在交集则提示"讲师排期冲突"并阻止保存。此校验避免同一讲师在同一时间段被重复点将，保障讲师档期合理性
- **排查SQL**：
  ```sql
  SELECT a.APPLY_CODE AS 申请1编码,
         b.APPLY_CODE AS 申请2编码,
         a.LECTURER AS 培训师,
         TO_CHAR(a.PLAN_START_TIME,'YYYY-MM-DD') AS 申请1开始,
         TO_CHAR(a.PLAN_END_TIME,'YYYY-MM-DD') AS 申请1结束,
         TO_CHAR(b.PLAN_START_TIME,'YYYY-MM-DD') AS 申请2开始,
         TO_CHAR(b.PLAN_END_TIME,'YYYY-MM-DD') AS 申请2结束
  FROM TRAIN_CAMP_APPLY a
  JOIN TRAIN_CAMP_APPLY b ON a.APPLY_CODE < b.APPLY_CODE
    AND a.LECTURER_CODE = b.LECTURER_CODE
    AND a.APPLY_STATE IN ('valid', 'executing')
    AND b.APPLY_STATE IN ('valid', 'executing')
    AND a.PLAN_START_TIME <= b.PLAN_END_TIME
    AND a.PLAN_END_TIME >= b.PLAN_START_TIME;
  ```

  ```sql
  SELECT U.USER_NAME AS 用户名, R.ROLE_NAME AS 角色名, P.PERMISSION_CODE AS 权限码
  ```

### 常见问题

**Q1：经销商看不到自己发起的特训营记录？**
A：检查该经销商是否正确关联当前登录用户，确认DEALER_CODE与当前登录用户关联的经销商一致。

**Q2：特训营状态未更新？**
A：状态由审批流程驱动，需联系审批人确认审批进度。

**Q3：pageForDealer接口返回数据为空？**
A：确认当前登录用户已关联经销商角色，且该经销商存在发起记录。

**Q4：申请点将弹窗无特训营数据？**
A：检查campApplyApi.campSelectPage接口，确认有生效特训营。

**Q5：报名保存失败？**
A：检查ApplyInfo组件数据，法人主体和交易公司是否选择。

**Q6：结算前确认按钮不显示？**
A：检查beforeSettlementConfirmState是否为to_be_confirm。
