# 工程管理-项目商机-价格保护函

> 本页面为低代码页面(hlod)，无独立前端源码，基于后端API梳理。后端Controller为EpmPriceProtectionLetterController（API: `/v1/{organizationId}/epm-price-protection-letters`），表为EPM_PRICE_PROTECTION_LETTER。

## 业务流程

```
用户进入价格保护函页面
  → 选择项目（projectId）
  → 调用获取价格保护函内容接口（GET /get-news-content）
  → 系统根据项目信息生成保护函内容模板（HTML格式，含占位符自动填充）
  → 用户编辑保护函内容（newsContent）
  → 点击"保存"按钮，调用保存接口（POST /save-protection-letter）
  → 系统校验：
    → 系统参数PriceProtectionReaders（保护函阅读人）不能为空
    → 项目ID不能为空
    → 保护函内容不能为空
    → 校验是否已存在进行中的价格保护函（checkHaveSameLatter）
  → 生成价格保护函编号（编码规则AE.PRICE_PROTECTION_LETTER_NO）
  → 自动带出项目关联的客户信息
  → 保存价格保护函记录
  → 用户提交审批，触发工作流（PRICE_PROTECT_AW）
  → 审批通过后回调wfComplete：
    → 计算保护函过期时间 = 审批通过时间 + PriceProtectionPeriod（天）
    → 若过期时间超过项目报备有效期结束时间，则取报备有效期结束时间
    → 更新审批状态为"审核通过"
    → 更新保护函内容中的${CURRENT_TIME}占位符为当前日期
```

## 重点逻辑

### 重点逻辑1：保护函内容模板自动生成

- **业务意义**：价格保护函有标准格式，需要根据项目信息自动填充模板内容，减少人工填写工作量，保证格式统一
- **具体逻辑描述**：
  - 1、系统内置HTML模板，包含事业部名称、项目名称、项目地址、经销商名称、联系人、联系电话、日期等占位符
  - 2、根据项目ID查询项目信息，自动填充：项目名称(${PRJ_NAME})、项目地址(${PRJ_ADDR}=省+市+区+详细地址)、经销商名称(${CUS_NAME})、报备经办人姓名(${CONTACT_NAME})、报备经办人电话(${CONTACT_TEL})、当前年份(${CURR_YEAR})、当前日期(${CURRENT_TIME})
  - 3、事业部名称(${DIVISION_NAME})从事业部基础设置中获取，默认为编码101，若用户上下文中存在DEPT信息则使用该值对应的事业部

### 重点逻辑2：保存时重复保护函校验

- **业务意义**：同一项目不应存在多条进行中的价格保护函，避免重复发起导致管理混乱
- **具体逻辑描述**：
  - 1、保存时调用checkHaveSameLatter校验该项目是否已存在进行中的价格保护函
  - 2、若存在，阻断保存并提示"该项目{项目编码}已存在进行中的价格函{编号}），无需重复发起价格保护函"
  - 3、编辑已有保护函时，排除自身（通过主键ID过滤）

### 重点逻辑3：审批通过后计算过期时间

- **业务意义**：价格保护函有有效期限，过期后不再具有价格保护效力，需要自动计算过期时间
- **具体逻辑描述**：
  - 1、审批通过时（wfComplete回调），取系统参数"价格保护函有效期时长"（PriceProtectionPeriod，单位：天）
  - 2、计算过期时间 = 审批通过时间 + 有效期天数
  - 3、若计算出的过期时间超过项目报备有效期结束时间(validEndDate)，则过期时间取项目报备有效期结束时间
  - 4、同时将模板中的${CURRENT_TIME}占位符替换为审批通过时的中文日期（如"2026年01月07日"），并更新审批状态为"审核通过"

### 重点逻辑4：价格保护函编号自动生成

- **业务意义**：每条价格保护函需要唯一编号用于追踪和管理
- **具体逻辑描述**：
  - 1、新建保存时，编号 = 事业部编码前缀 + 编码规则后缀
  - 2、前缀取事业部基础设置中的事业部编码(divisionCode)，若为空则默认使用"ARR"
  - 3、后缀通过编码规则引擎生成，规则编码为"AE.PRICE_PROTECTION_LETTER_NO"

#### 按钮1：获取保护函内容（新建页）

- **触发条件**：已选择项目时点击"获取保护函内容"按钮
- **接口**：`GET /v1/{organizationId}/epm-price-protection-letters/get-news-content`
- **执行逻辑**：
  - 1、根据projectId查询EpmProject获取项目信息
  - 2、获取事业部基础设置(DivisionBaseSet)获取事业部名称
  - 3、取项目经办人(agent)和经办人电话(agentPhone)
  - 4、获取内置HTML模板，替换占位符：${PRJ_NAME}、${DIVISION_NAME}、${PRJ_ADDR}、${CONTACT_TEL}、${CUS_NAME}、${CONTACT_NAME}、${CURR_YEAR}、${CURRENT_TIME}
  - 5、返回填充后的HTML内容

#### 按钮2：保存（新建页/编辑页）

- **触发条件**：必填项已填写时点击"保存"按钮
- **接口**：`POST /v1/{organizationId}/epm-price-protection-letters/save-protection-letter`
- **执行逻辑**：
  - 1、新建分支（priceProtectionId为null）：
    - 设置事业部ID（entid = divisionCode）
    - 调用verifyAndFillFields校验并填充字段
    - 生成保护函编号：事业部编码前缀 + 编码规则后缀
    - 插入EPM_PRICE_PROTECTION_LETTER记录
  - 2、更新分支（priceProtectionId不为null）：更新EPM_PRICE_PROTECTION_LETTER记录

### 保存校验

- 校验1：价格函阅读者配置必须存在 —— 确保审批通过后能正确推送通知
  - **详细逻辑**：verifyAndFillFields方法查询系统参数"PriceProtectionReaders"，配置值为空则报错
  - **系统体现**：阻断性报错，抛出"缺少价格函阅读者配置，请联系系统管理员"
  - **排查SQL**：`SELECT * FROM SYS_PARAM WHERE PARAM_CODE = 'PriceProtectionReaders' AND ORG_ID = :entid`

- 校验2：项目不能为空 —— 价格保护函必须关联一个项目
  - **详细逻辑**：verifyAndFillFields方法校验projectId非空
  - **系统体现**：阻断性报错，抛出"项目不能为空"
  - **排查SQL**：`SELECT * FROM EPM_PRICE_PROTECTION_LETTER WHERE PRICE_PROTECTION_ID = :id AND PROJECT_ID IS NULL`

- 校验3：保护函内容不能为空 —— 保护函必须有正文内容
  - **详细逻辑**：verifyAndFillFields方法校验newsContent非空
  - **系统体现**：阻断性报错，抛出"保护函内容不能为空"
  - **排查SQL**：`SELECT * FROM EPM_PRICE_PROTECTION_LETTER WHERE PRICE_PROTECTION_ID = :id AND NEWS_CONTENT IS NULL`

- 校验4：同一项目不能存在进行中的价格保护函 —— 防止重复发起
  - **详细逻辑**：checkHaveSameLatter方法查询该项目是否存在其他进行中的价格保护函，存在则报错
  - **系统体现**：阻断性报错，抛出"该项目{项目编码}已存在进行中的价格函{编号}），无需重复发起价格保护函"
  - **排查SQL**：
```sql
SELECT t.PRICE_PROTECTION_NO, t.PROJECT_CODE
FROM EPM_PRICE_PROTECTION_LETTER t
WHERE t.PROJECT_ID = :projectId
AND (t.AUDIT_STAT <> '审核拒绝' OR (t.AUDIT_STAT = '审核通过' AND t.EXPIRE_TIME > SYSDATE))
```

### 提交校验

- 校验1：保存校验全部通过 —— 提交前必须通过保存校验
  - **详细逻辑**：提交时触发工作流校验（volidate方法），当前实现返回null，无额外校验
  - **系统体现**：无额外校验

### 状态机

#### 状态机流转图

```text
新建(草稿) → 保存 → 提交审批 → 审批中(RUN) → 审批通过(APPROVED) → 已过期(自动)
                                    ↓
                                 驳回(REJECTED) → 修改后重新提交
```

#### 状态机列表

| 状态机名称 | 状态释义 | 可执行的操作 |
|-----------|---------|------------|
| NEW | 新建/草稿 | 保存、编辑、提交审批 |
| RUN | 审批中/运行中 | 等待审批（不可编辑） |
| APPROVED | 审批通过 | 查看（不可编辑，自动计算过期时间） |
| REJECTED | 驳回 | 修改后重新提交 |
| END | 终止/过期 | 查看（不可操作） |

#### 报错1：缺少价格函阅读者配置，请联系系统管理员
- **触发条件**：保存价格保护函时，系统参数"PriceProtectionReaders"未配置或配置值为空
- **逻辑分析**：在verifyAndFillFields方法中查询SYS_PARAM表，按PARAM_CODE='PriceProtectionReaders'及当前组织ENTID查询配置。若查询结果为空或VALUE为空，则抛出阻断性报错。该参数用于指定价格保护函的阅读人范围，缺失则无法分发
- **排查SQL**：
  ```sql
  SELECT sp.PARAM_ID, sp.PARAM_CODE, sp.PARAM_NAME, sp.VALUE, sp.ENTID
  FROM SYS_PARAM sp
  WHERE sp.PARAM_CODE = 'PriceProtectionReaders'
    AND sp.ENTID = :organizationId
  -- 若返回空或VALUE为空，则需在系统参数表中补充配置
  ```

#### 报错2：项目不能为空
- **触发条件**：保存价格保护函时，未选择项目(projectId为空)
- **逻辑分析**：在verifyAndFillFields方法中校验projectId非空，因价格保护函必须关联已报备的项目以带出客户/项目信息。该报错为阻断性报错
- **排查SQL**：
  ```sql
  SELECT eppl.PRICE_PROTECTION_ID, eppl.PRICE_PROTECTION_NO, eppl.PROJECT_ID, eppl.PROJECT_CODE
  FROM EPM_PRICE_PROTECTION_LETTER eppl
  WHERE eppl.PROJECT_ID IS NULL
  -- 查出项目为空的异常数据
  ```

#### 报错3：保护函内容不能为空
- **触发条件**：保存价格保护函时，保护函正文内容(newsContent)为空
- **逻辑分析**：在verifyAndFillFields方法中校验newsContent非空，保护函正文为审批展示的核心内容，需先点击"获取保护函内容"按钮自动生成模板内容或手动输入。该报错为阻断性报错
- **排查SQL**：
  ```sql
  SELECT eppl.PRICE_PROTECTION_ID, eppl.PRICE_PROTECTION_NO, eppl.LETTER_NAME, eppl.NEWS_CONTENT
  FROM EPM_PRICE_PROTECTION_LETTER eppl
  WHERE eppl.NEWS_CONTENT IS NULL OR TRIM(eppl.NEWS_CONTENT) = ''
  -- 查出内容为空的异常数据
  ```

#### 报错4：该项目{项目编码}已存在进行中的价格函{编号}），无需重复发起价格保护函
- **触发条件**：保存价格保护函时，同一项目(PROJECT_ID)已存在审批中(AUDIT_STAT为空或'审核中')或审批通过且未过期(EXPIRE_TIME>SYSDATE)的价格保护函
- **逻辑分析**：在checkHaveSameLatter方法中按PROJECT_ID查询EPM_PRICE_PROTECTION_LETTER表，若存在AUDIT_STAT<>'审核拒绝'且(EXPIRE_TIME为空或EXPIRE_TIME>SYSDATE)的记录，则抛出阻断性报错，避免同一项目重复发起价格保护函
- **排查SQL**：
  ```sql
  SELECT eppl.PRICE_PROTECTION_ID, eppl.PRICE_PROTECTION_NO, eppl.PROJECT_ID, eppl.PROJECT_CODE,
         eppl.AUDIT_STAT, eppl.CHECK_TIME, eppl.EXPIRE_TIME
  FROM EPM_PRICE_PROTECTION_LETTER eppl
  WHERE eppl.PROJECT_ID = :projectId
    AND eppl.AUDIT_STAT <> '审核拒绝'
    AND (eppl.EXPIRE_TIME IS NULL OR eppl.EXPIRE_TIME > SYSDATE)
  -- 若返回非空，说明已存在进行中的价格函
  ```

## 常见问题FAQ

**Q1: 为什么提示"该项目已存在进行中的价格函，无需重复发起价格保护函"？**
A: 该项目已有一张未审核拒绝且未过期的价格保护函，需等该保护函过期或审核拒绝后才能重新发起。排查SQL：`SELECT t.PRICE_PROTECTION_NO, t.AUDIT_STAT, t.EXPIRE_TIME FROM EPM_PRICE_PROTECTION_LETTER t WHERE t.PROJECT_ID = :projectId AND (t.AUDIT_STAT <> '审核拒绝' OR (t.AUDIT_STAT = '审核通过' AND t.EXPIRE_TIME > SYSDATE))`

**Q2: 保护函过期时间如何计算？**
A: 过期时间 = 审批通过时间 + 系统参数PriceProtectionPeriod（天），若超过报备有效期结束时间则取报备有效期结束时间。排查SQL：`SELECT t.PRICE_PROTECTION_ID, t.CHECK_TIME, t.EXPIRE_TIME, p.VALID_END_DATE FROM EPM_PRICE_PROTECTION_LETTER t JOIN EPM_PROJECT p ON t.PROJECT_ID = p.PROJECT_ID WHERE t.PRICE_PROTECTION_ID = :id`

**Q3: 保护函内容中的${CURRENT_TIME}什么时候被替换？**
A: 在审批通过后（wfComplete回调中）替换为当前日期的中文格式（如"2026年01月07日"）。

**Q4: 价格保护函保存时报"缺少价格函阅读者配置"？**
A: 系统参数表中未配置"PriceProtectionReaders"参数或配置值为空。排查SQL：`SELECT * FROM SYS_PARAM WHERE PARAM_CODE = 'PriceProtectionReaders'`。解决：在系统参数表中为对应组织添加配置项并设置有效值。

**Q5: 价格保护函编号生成异常？**
A: 编码规则"AE.PRICE_PROTECTION_LETTER_NO"未配置，或事业部编码为空且默认前缀"ARR"不符合预期。排查SQL：`SELECT * FROM HPFM_CODE_RULE WHERE RULE_CODE = 'AE.PRICE_PROTECTION_LETTER_NO'`。解决：检查编码规则配置和事业部基础设置中的事业部编码。
