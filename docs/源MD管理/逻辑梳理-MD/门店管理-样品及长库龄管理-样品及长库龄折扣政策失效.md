# 门店管理-样品及长库龄管理-样品及长库龄折扣政策失效

## 业务流程

### 业务流程图

```text
有效折扣政策        新建失效申请        保存失效单         提交审批          审批通过
(valid=2)     →   选择失效政策   →   填写失效原因  →   推送审批     →   原政策有效状态=失效
                  填写失效原因       生成失效单号       发起工作流       (valid=3)
```

### 上游依赖

| 上游模块 | 依赖类型 | 依赖说明 | 依赖成立条件 |
|---------|---------|---------|------------|
| 样品及长库龄折扣政策 | 数据依赖 | 提供有效的折扣政策(valid=2) | 政策已审批通过且有效 |
| 工作流引擎 | 配置依赖 | 发起失效审批流程 | 工作流已部署 |

### 下游影响

- 影响1：折扣政策有效状态变更
  - 失效审批通过后，原折扣政策的valid更新为3(失效)

- 影响2：要货订单折扣引用
  - 政策失效后，要货订单不能再引用该折扣政策

## 重点逻辑

### 重点逻辑1：失效政策关联 {政策关联}

- **业务意义**：失效单关联原折扣政策，审批通过后更新原政策状态

- **具体逻辑描述**

  - 第1点：失效单通过discountPolicyId关联原折扣政策

  - 第2点：审批通过后将原政策的valid更新为3(失效)

  - 第3点：仅有效状态(valid=2)的政策可发起失效

#### 报错1：政策已失效
- **触发条件**：点击"保存"按钮，校验关联的原折扣政策DISCOUNT_POLICY_ID对应记录的VALID=3（失效）
- **逻辑分析**：失效单只能针对有效状态（valid=2）的政策发起。校验逻辑按DISCOUNT_POLICY_ID查询EPM_DISCOUNT_POLICY.VALID，若该值=3则抛异常，阻止保存。常见根因：用户选择的政策已被其他失效单失效、政策在保存前被并发失效、或前端政策选择列表未实时刷新。
- **排查SQL**：
  ```sql
  SELECT d.discount_policy_disabled_id AS 失效单ID,
         d.discount_policy_disabled_code AS 失效单号,
         d.discount_policy_id    AS 关联政策ID,
         p.discount_policy_code  AS 政策单号,
         p.valid                 AS 政策有效状态,
         d.hz_approve_status     AS 审批状态
  FROM   epm_discount_policy_disabled d
  LEFT   JOIN epm_discount_policy p
         ON p.discount_policy_id = d.discount_policy_id
  WHERE  p.valid = 3
  ORDER  BY d.createtime DESC;
  ```

#### 报错2：政策不存在
- **触发条件**：点击"保存"按钮，按DISCOUNT_POLICY_ID查询EPM_DISCOUNT_POLICY返回null
- **逻辑分析**：失效单需关联到原折扣政策。若原政策在保存前被其他用户物理删除、DISCOUNT_POLICY_ID传值错误、或政策从未存在，查询返回空，无法关联，抛异常阻止保存。常见根因：政策被并发删除、前端传参错误、或数据不一致。
- **排查SQL**：
  ```sql
  SELECT d.discount_policy_disabled_id AS 失效单ID,
         d.discount_policy_disabled_code AS 失效单号,
         d.discount_policy_id    AS 关联政策ID,
         p.discount_policy_code  AS 政策单号
  FROM   epm_discount_policy_disabled d
  LEFT   JOIN epm_discount_policy p
         ON p.discount_policy_id = d.discount_policy_id
  WHERE  p.discount_policy_id IS NULL
  ORDER  BY d.createtime DESC;
  ```

#### 报错3：失效政策行不允许为空
- **触发条件**：点击"保存"按钮，saveData校验时，DISCOUNT_POLICY_ITEM_DTO_LIST为空或全部被标记删除
- **逻辑分析**：失效单必须关联至少一行要失效的政策产品行，否则失效无意义。校验逻辑读取discountPolicyItemDTOList，为空则抛异常。常见根因：用户未选择要失效的政策行、政策行被全部删除、或前端未传政策行数据。
- **排查SQL**：
  ```sql
  SELECT d.discount_policy_disabled_id AS 失效单ID,
         d.discount_policy_disabled_code AS 失效单号,
         d.hz_approve_status     AS 审批状态,
         COUNT(dpi.discount_policy_item_id) AS 失效政策行数
  FROM   epm_discount_policy_disabled d
  LEFT   JOIN epm_discount_policy_item dpi
         ON dpi.discount_policy_disabled_id = d.discount_policy_disabled_id
  GROUP  BY d.discount_policy_disabled_id, d.discount_policy_disabled_code, d.hz_approve_status
  HAVING COUNT(dpi.discount_policy_item_id) = 0;
  ```

#### 报错4：当前折扣政策不允许失效 请检查
- **触发条件**：点击"保存"按钮，generateCode校验时，按DISCOUNT_POLICY_CODE查询EPM_DISCOUNT_POLICY返回空
- **逻辑分析**：失效单生成编码时需查询原折扣政策确认存在，若政策编码不存在则无法确定失效类型(工程/家装/样品)和编码规则，抛异常。常见根因：用户输入错误政策编码、政策已被删除、或政策编码从未存在。
- **排查SQL**：
  ```sql
  SELECT d.discount_policy_disabled_id AS 失效单ID,
         d.discount_policy_disabled_code AS 失效单号,
         d.discount_policy_id    AS 关联政策ID,
         p.discount_policy_code  AS 政策单号,
         p.is_makt              AS 样品标识,
         p.suitable_type        AS 适用类型
  FROM   epm_discount_policy_disabled d
  LEFT   JOIN epm_discount_policy p
         ON p.discount_policy_id = d.discount_policy_id
  WHERE  p.discount_policy_id IS NULL
  ORDER  BY d.createtime DESC;
  ```

#### 报错6：仅新建状态单据允许删除.
- **触发条件**：点击"删除"按钮，doDelete校验时，失效单HZ_APPROVE_STATUS≠NEW(新建)
- **逻辑分析**：仅新建状态(HZ_APPROVE_STATUS=NEW)的失效单允许删除，已提交审批或审批通过的失效单不允许删除，避免破坏审批流程和原政策状态。校验逻辑读取HZ_APPROVE_STATUS，非NEW则抛异常。常见根因：用户尝试删除已提交或已审批的失效单、或前端未做状态判断。
- **排查SQL**：
  ```sql
  SELECT discount_policy_disabled_id AS 失效单ID,
         discount_policy_disabled_code AS 失效单号,
         hz_approve_status     AS 审批状态,
         discount_policy_id    AS 关联政策ID
  FROM   epm_discount_policy_disabled
  WHERE  hz_approve_status <> 'NEW';
  ```

#### 报错7：政策失效id不能为空
- **触发条件**：工作流审批回调(wfComplete)时，回调报文中的objId(政策失效单ID)为null
- **逻辑分析**：工作流回调处理需根据objId查询失效单并更新状态，objId为空则无法定位失效单，回调处理失败。校验逻辑读取objId，为空则抛异常。常见根因：工作流配置错误、回调报文丢失objId、或工作流实例与业务单据映射异常。
- **排查SQL**：
  ```sql
  SELECT discount_policy_disabled_id AS 失效单ID,
         discount_policy_disabled_code AS 失效单号,
         hz_approve_status     AS 审批状态,
         hz_instance_id        AS 工作流实例ID

  ```

#### 报错8：政策明细推送crm出错,请稍后再试
- **触发条件**：工作流审批通过回调(wfComplete)时，调用CRM政策失效接口(policyDisabled)，CRM返回resultLine为null
- **逻辑分析**：失效审批通过后需推送CRM同步政策失效状态，CRM返回空则无法确认同步结果，抛异常。常见根因：CRM接口超时、CRM服务不可用、或网络异常。
- **排查SQL**：
  ```sql
  SELECT d.discount_policy_disabled_id AS 失效单ID,
         d.discount_policy_disabled_code AS 失效单号,
         d.hz_approve_status     AS 审批状态,
         p.discount_policy_code  AS 政策单号,
         p.suitable_type         AS 适用类型
  FROM   epm_discount_policy_disabled d
  JOIN   epm_discount_policy p ON p.discount_policy_id = d.discount_policy_id
  WHERE  d.hz_approve_status = 'APPROVED'
  AND    p.suitable_type <> 'normal'
  ORDER  BY d.createtime DESC;
  ```

#### 报错9：政策明细推送crm出错：{lineId}:{message}
- **触发条件**：工作流审批通过回调(wfComplete)时，调用CRM政策失效接口(policyDisabled)，CRM返回success=false且message非空
- **逻辑分析**：失效审批通过后需推送CRM同步政策失效状态，CRM返回失败信息则同步失败，抛异常并提示具体CRM行ID和错误信息。常见根因：CRM政策行不存在、CRM政策行状态异常、或CRM业务校验失败。
- **排查SQL**：
  ```sql
  SELECT dpi.discount_policy_item_id AS 政策行ID,
         dpi.crm_line_id        AS CRM行ID,
         dpi.discount_policy_id AS 政策ID,
         dpi.valid_stat         AS 行有效状态
  FROM   epm_discount_policy_item dpi
  JOIN   epm_discount_policy_disabled d
         ON d.discount_policy_id = dpi.discount_policy_id
  WHERE  d.hz_approve_status = 'APPROVED'
  AND    dpi.discount_policy_disabled_id IS NOT NULL
  AND    NOT EXISTS (
    SELECT 1 FROM crm_policy_line cpl WHERE cpl.line_id = dpi.crm_line_id AND cpl.status = 'ACTIVE'
  );
  ```

### 常见问题

- 问题1：失效审批通过后原政策状态未更新
  - 原因：工作流回调处理异常
