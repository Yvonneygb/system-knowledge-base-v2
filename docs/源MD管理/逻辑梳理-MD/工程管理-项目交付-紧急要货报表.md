# 工程管理-项目交付-紧急要货报表

---

## 业务流程

### 业务流程图

```text
开始 → 设置查询条件 → ★紧急要货报表★(查询/展示/导出) → 结束（纯只读，无审批）
```

### 流程说明

1. **查询阶段**：用户填写查询条件（紧急要货单号、客户、要货单号、合同、项目、接口状态、产品等）
2. **展示阶段**：系统查询已审批通过（`STAT=5`）的紧急要货单及其明细行数据，关联要货单头、客户表获取订单和客户信息
3. **翻译阶段**：转换接口状态码为中文（S→成功，E→失败），转换订单类型、产品线为LOV含义
4. **导出阶段**：支持导出当前查询结果为Excel，纯只读查询，无审批无下游写入

## 重点逻辑

### 重点逻辑1：纯报表查询页面

- **业务意义**：供内部人员查询紧急要货订单的汇总报表信息，了解紧急要货的整体情况
- **具体逻辑描述**：
  1. 本页面为hlod低代码报表页面，无独立前端源码，仅提供查询和导出功能
  2. 不支持新增、修改、删除操作
  3. 数据来源于紧急要货订单头表（`EPM_URGENT_ORDER`）和行表（`EPM_URGENT_ORDER_LINE`）

### 重点逻辑2：数据范围过滤

- **业务意义**：仅展示已审批通过的紧急要货单数据
- **具体逻辑描述**：
  1. 查询条件固定过滤`EPM_URGENT_ORDER.STAT = 5`（已审批通过）
  2. 按`organizationId`过滤当前租户数据
  3. 经销商数据隔离：`userType=D`时自动注入客户编码过滤

### 重点逻辑3：多表关联查询

- **业务意义**：整合紧急要货单、要货单、客户等多维度数据
- **具体逻辑描述**：
  1. `EPM_URGENT_ORDER`（紧急要货单头）LEFT JOIN `EPM_URGENT_ORDER_LINE`（明细行）
  2. LEFT JOIN `SA_OUT_BILL_HEAD`（要货单头）获取订单日期、交易公司、合同、项目等信息
  3. LEFT JOIN `CUSTOMER`（客户表）获取客户编码和名称

### 重点逻辑4：LOV翻译与状态转换

- **业务意义**：将编码值翻译为用户可读的含义
- **具体逻辑描述**：
  1. 订单类型通过`LOV_CODE='AE.EPM.BILL_TYPE'`查询`HZERO.HPFM_LOV_VALUE`翻译
  2. 产品线通过`LOV_CODE='AE.ENTORGID'`查询`HZERO.HPFM_LOV_VALUE`翻译
  3. 接口状态`INTF_RESULT`：S→成功，E→失败
  4. 失效状态`IS_CANCEL`：2→失效，其他→空

### 重点逻辑5：模糊查询与精确匹配

- **业务意义**：提供灵活的查询条件匹配方式
- **具体逻辑描述**：
  1. 除接口状态（`intfResult`）为精确匹配外，其余文本条件均为LIKE模糊匹配
  2. 模糊匹配使用`'%' || #{value} || '%'`方式拼接

## 常见问题FAQ

### 报错一览表

| 报错信息 | 提示节点 | 根因与解决方案 | 等级 | 详细逻辑 |
|---------|---------|-------------|------|---------|
| 查询条件不能为空 | 查询时 | 未输入查询条件。输入至少一个查询条件后查询 | toast提醒 | [查看] |
| 导出数据量超过限制 | 导出时 | 数据量过大。缩小查询范围后导出 | toast提醒 | [查看] |

#### 报错1：查询条件不能为空
- **触发条件**：查询紧急要货报表时，所有查询条件(紧急要货单号/客户/项目/产品等)均为空
- **逻辑分析**：前端校验至少需输入一个查询条件，因报表数据量大，强制要求至少一个过滤条件以避免全表扫描。该报错为toast提醒级别
- **排查SQL**：
  ```sql
  SELECT COUNT(*) AS 报表数据量
  FROM EPM_URGENT_ORDER_HEAD euoh
  JOIN EPM_URGENT_ORDER_LINE euol ON euoh.URGENT_ORDER_HEAD_ID = euol.URGENT_ORDER_HEAD_ID
  WHERE euoh.STAT = 5
  -- 评估全表数据量
  ```

#### 报错2：导出数据量超过限制
- **触发条件**：导出紧急要货报表时，查询结果数据量超过导出上限
- **逻辑分析**：导出调用全量查询(不分页)，当结果集超过Excel单sheet上限或系统配置的导出条数限制时抛出toast提醒。需缩小查询范围后导出
- **排查SQL**：
  ```sql
  SELECT COUNT(*) AS 待导出数据量
  FROM EPM_URGENT_ORDER_HEAD euoh
  JOIN EPM_URGENT_ORDER_LINE euol ON euoh.URGENT_ORDER_HEAD_ID = euol.URGENT_ORDER_HEAD_ID
  WHERE euoh.STAT = 5
    AND (:urgentOrderCode IS NULL OR euoh.URGENT_ORDER_CODE LIKE '%' || :urgentOrderCode || '%')
    AND (:customerCode IS NULL OR euoh.CUSTOMER_CODE LIKE '%' || :customerCode || '%')
    AND (:intfResult IS NULL OR euol.INTF_RESULT = :intfResult)
  ```

**Q1：报表只展示哪些数据？**
A：仅展示紧急要货单状态`STAT=5`（已审批通过）的数据。

**Q2：接口状态筛选是精确匹配还是模糊匹配？**
A：接口状态（`intfResult`）为精确匹配（成功/失败），其余文本条件均为LIKE模糊匹配。

**Q3：订单类型和产品线显示的是编码还是含义？**
A：显示的是含义。订单类型通过`LOV_CODE='AE.EPM.BILL_TYPE'`翻译，产品线通过`LOV_CODE='AE.ENTORGID'`翻译，均查询`HZERO.HPFM_LOV_VALUE`表。

**Q4：报表数据与紧急要货订单页面数据不一致？**
A：可能存在缓存或查询条件差异。刷新页面重新查询，确认查询条件一致。
