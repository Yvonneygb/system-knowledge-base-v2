# 点将管理-特训营管理-特训营点将管理

> 后端代码位于 mbo-business 微服务（源码未包含在当前源码目录下），前端 API 路径前缀 `mlt/trainCampApply/*`。本菜单为特训营点将的管理和审批视图，通过 `pageType` 切换 manage（管理视图）/approval（审批视图）。

## 业务流程

### 业务流程图

```
经销商特训营报名点将
        |
        v
特训营点将管理列表(本页面)
        |
        ├──pageType=manage──→ 查看申请/同步CRM/特殊取消
        |                       |
        |                       └──特殊取消──→ 校验7天内且已生效 ──→ 提交cancelApply
        |
        └──pageType=approval──→ 审批 ──→ 审批通过/驳回 ──→ campApplyApproval接口
                                 ├──→ 同步OA
                                 └──→ 同步FDD
```

### 全链路流程图

```
开始 → ★提交特训营点将申请★ → ⚖审批通过？ → 执行中(生成CRM订单) → 结束
```

**业务原则**：点将状态是特训营名额占用与费用发生的唯一依据，一切变更都必须通过审批或取消审批完成，不允许绕过流程直接改单。

### 上游依赖

| 上游模块 | 依赖类型 | 依赖说明 | 依赖成立条件 |
|---------|---------|---------|-------------|
| 经销商特训营点将 | 数据库共享 | 经销商发起报名点将申请 | 经销商已登录且有报名权限 |
| 特训营管理 | 数据库关联 | 提供特训营基础数据 | CAMP_CODE 匹配 TRAIN_CAMP |
| HZERO权限服务 | permissionList、useAuthPageOption | 提供页面权限、按钮权限 | 用户已分配对应权限编码 |
| 讲师·策划师主档 | 关联查询 | 讲师/策划师信息 | LECTURER/PLANNER_ID 匹配主档 |
| 经销商主档 | 关联查询 | 经销商信息 | DISTRIBUTOR_ID 匹配主档 |
| CRM系统 | REST API | CRM订单 | 经销商CRM映射存在 |
| 工作流引擎 | 工作流接口 | 审批流程 | 工作流编码已配置 |

### 下游影响

- **特训营点将执行**：审批通过后进入执行，状态流转。
- **CRM订单系统**：同步CRM推送订单，REST API 调用 pushCrm。
- **OA审批系统**：同步OA推送流程，REST API 调用 pushOa。
- **法大大电子签约**：同步FDD推送签约，REST API 调用 pushFdd。
- **流程摘要组件**：查看流程展示审批历史，ProcessDetail 组件。
- **参训记录**：参训留痕，数据库共享。

## 重点逻辑

### 重点逻辑1：双审批流

- **业务意义**：点将申请与取消申请分别触发独立审批流，保证两类业务互不干扰。
- **具体逻辑描述**：
  - 点将申请提交触发 `campApplyApproval` 审批流。
  - 取消申请触发 `cancelApplyApproval` 审批流。
  - 两者独立运行，互不影响。

### 重点逻辑2：applyCode自动生成

- **业务意义**：保证申请编码唯一性，便于全链路追溯。
- **具体逻辑描述**：
  - 提交申请时系统自动生成唯一编码 `applyCode`。
  - 编码作为主键贯穿申请、审批、执行、取消全流程。

### 重点逻辑3：状态联动

- **业务意义**：点将申请状态与审批状态联动，确保状态机自动推进。
- **具体逻辑描述**：
  - 点将申请状态与审批状态联动。
  - 审批通过后申请状态自动变更为已通过。
  - 取消审批通过后状态变为已取消。

### 重点逻辑4：取消约束

- **业务意义**：限制取消时机，避免随意取消造成资源浪费。
- **具体逻辑描述**：
  - 仅已审批通过且未完成执行的申请可发起取消申请。
  - 已生效的点将不能直接删除，只能发起取消申请。
  - 取消审批通过后状态才变为已取消。

### 重点逻辑5：pageType页面类型切换

- **业务意义**：通过单一页面支撑管理、审批多视图，减少重复开发。
- **具体逻辑描述**：
  - 通过 `useAuthPageOption` 实现模式切换。
  - **manage（管理视图）**：显示同步CRM、特殊取消按钮。
  - **approval（审批视图）**：显示审批、同步OA、同步FDD按钮。
  - 查询接口 `pageType` 参数默认为 `manage`。

### 重点逻辑6：特殊取消校验

- **业务意义**：限制取消时机，避免临近开课取消造成资源浪费。
- **具体逻辑描述**：
  - 计算时间差值 `timeDiff = (planStartTime - nowTime) / (24*60*60*1000)`。
  - 校验条件 `1 <= timeDiff <= 7`（培训开始前1-7天内）。
  - 校验审批状态 `approvalState === 'fdd_sign'`（已法大大签约）。
  - 校验是否已发起取消：`cancelApprovalState` 不为空且不等于 `reject` 和 `oa_reject` 时提示"该单据已发起取消申请，不可重复发起！"。
  - 校验不通过提示"只有在培训开始前七天内且已生效的单据才可以发起取消申请！"。
  - 提交调用 `POST mlt/trainCampApply/cancelApply` 接口。

### 重点逻辑7：审批流程

- **业务意义**：通过审批把关名额与费用，审批通过才占用资源。
- **具体逻辑描述**：
  - 审批弹窗根据 pageType 区分。
  - **approval**：申请审批，调用 `applyApproval` 接口，`applyTypeTwo=apply`，显示签订人选择。
  - 审批参数：`applyTypeOne=camp`，`approvalResult=approved/reject`。
  - 审批人、审批时间自动填充。
  - 签订人 approval 时显示，审批意见必填。

### 重点逻辑8：查看协议书

- **业务意义**：在线查看法大大协议书，便于核对签约内容。
- **具体逻辑描述**：
  - 点击行"查看协议书"按钮，调用 `queryPDF` 接口。
  - 参数：`applyCode`、`applyTypeOne=camp`、`applyTypeTwo=apply`。
  - 成功后 `window.open` 打开PDF。

### 重点逻辑9：同步外部系统

- **业务意义**：将点将数据同步至外部系统，保证多方数据一致。
- **具体逻辑描述**：
  - **同步CRM**：仅 `pageType=manage` 显示，`POST mlt/trainCampApply/pushCrm/{applyCode}`。
  - **同步OA**：`pageType=approval` 显示，`POST mlt/trainCampApply/pushOa/{applyCode}`。
  - **同步FDD**：仅 `pageType=approval` 显示，`POST mlt/trainCampApply/pushFdd/{applyCode}`。

#### 选择弹窗

#### 弹窗1：审批弹窗（单选）

- **用途**：审批点将申请，填写审批意见与审批结果。
- **入参**：

| 参数名 | 来源 | 说明 |
|--------|------|------|
| applyCode | 选中行 | 申请编码 |
| applyTypeOne | 固定值 | camp |
| applyTypeTwo | 固定值 | apply（申请审批）/ cancel_apply（取消申请审批） |
| approvalResult | 表单 | approved/reject |
| approvalComments | 表单 | 审批意见（必填） |
| signerId | 表单 | 签订人ID（approval时显示，取signer.accountId） |
| signerName | 表单 | 签订人姓名（取signer.name） |
| signerPhone | 表单 | 签订人手机号（取signer.mobile） |

- **弹窗表单字段**（applyApprovalFormDSProps）：

| 字段名 | 组件 | 业务释义 | 显隐条件 | 取值/赋值逻辑 |
|--------|------|---------|---------|-------------|
| 审批人 | TextField | 当前审批人姓名 | 始终显示 | 自动填充当前用户realName，disabled |
| 审批时间 | DatePicker | 审批时间 | 始终显示 | 自动填充new Date()，disabled |
| 签订人 | Select | 用印授权人 | pageType=approval时显示 | options=signerDS，textField=name，valueField=accountId，审批通过时必填 |
| 审批意见 | TextArea | 审批意见 | 始终显示 | 必填，style宽度500 |

- **弹窗底部按钮**：审批通过（onOk，approvalResult=approved）、驳回（approvalResult=reject）、关闭
- **调用接口**：`POST mlt/trainCampApply/campApplyApproval`（申请审批）或 `POST mlt/trainCampApply/cancelApplyApproval`（取消申请审批），根据pageType=cancelApply判断

- **查询SQL**：
  ```sql
  SELECT tca.APPLY_CODE AS 申请编码, tca.CAMP_NAME AS 特训营名称,
         tca.APPROVAL_STATE AS 审核状态
  FROM TRAIN_CAMP_APPLY tca
  WHERE tca.APPLY_CODE = :applyCode;
  ```

#### 弹窗2：特殊取消弹窗（单选）

- **用途**：填写取消原因，发起特殊取消。
- **入参**：

| 参数名 | 来源 | 说明 |
|--------|------|------|
| applyCode | 选中行 | 申请编码 |
| cancelReason | 表单 | 取消原因（必填） |

- **查询SQL**：
  ```sql
  SELECT tca.APPLY_CODE AS 申请编码, tca.CAMP_NAME AS 特训营名称,
         TO_CHAR(tca.PLAN_START_TIME, 'YYYY-MM-DD') AS 开始时间,
         tca.APPROVAL_STATE AS 审核状态
  FROM TRAIN_CAMP_APPLY tca
  WHERE tca.APPLY_CODE = :applyCode;
  ```

### 保存校验

- 校验1：特殊取消原因必填 —— 确保取消留痕可追溯
  - **详细逻辑**：`cancelApplyFormDS.validate()` 校验取消原因必填。
  - **系统体现**：前端表单校验，后端二次校验。
  - **排查SQL**：
    ```sql
    SELECT tca.APPLY_CODE AS 申请编码, tca.CANCEL_REASON AS 取消原因
    FROM TRAIN_CAMP_APPLY tca
    WHERE tca.CANCEL_APPROVAL_STATE IS NOT NULL
      AND tca.CANCEL_REASON IS NULL;
    ```

### 提交校验

- 校验1：审批意见必填 —— 确保审批留痕完整
  - **详细逻辑**：`applyApprovalFormDS.validate()` 校验审批意见必填，通过时签订人必填。
  - **系统体现**：前端表单校验，后端二次校验。
  - **排查SQL**：
    ```sql
    SELECT tca.APPLY_CODE AS 申请编码, tca.APPROVAL_COMMENTS AS 审批意见,
           tca.SIGNER_NAME AS 签订人
    FROM TRAIN_CAMP_APPLY tca
    WHERE tca.APPROVAL_STATE = 'approved'
      AND (tca.APPROVAL_COMMENTS IS NULL OR tca.SIGNER_NAME IS NULL);
    ```

- 校验2：特殊取消时机校验 —— 防止临近开课取消造成资源浪费
  - **详细逻辑**：校验 `1 <= timeDiff <= 7` 且 `approvalState === 'fdd_sign'` 且未重复发起取消。
  - **系统体现**：前端时间差值计算与状态校验，后端二次校验。
  - **排查SQL**：
    ```sql
    SELECT tca.APPLY_CODE AS 申请编码, tca.CAMP_NAME AS 特训营名称,
           TO_CHAR(tca.PLAN_START_TIME, 'YYYY-MM-DD') AS 开始时间,
           tca.APPROVAL_STATE AS 审核状态,
           ROUND(tca.PLAN_START_TIME - SYSDATE) AS 距开始天数
    FROM TRAIN_CAMP_APPLY tca
    WHERE tca.APPROVAL_STATE = 'fdd_sign'
      AND tca.PLAN_START_TIME > SYSDATE
      AND tca.PLAN_START_TIME <= SYSDATE + 7
      AND (tca.CANCEL_APPROVAL_STATE IS NULL
           OR tca.CANCEL_APPROVAL_STATE IN ('reject', 'oa_reject'));
    ```

### 状态机

```
草稿 ──提交──→ 待审批 ──审批通过──→ 已通过 ──生效──→ 执行中 ──结束──→ 已完成
                  |
                  └──审批拒绝──→ 已拒绝
已通过 ──发起取消──→ 取消待审批 ──取消通过──→ 已取消
                       |
                       └──取消拒绝──→ 已通过
```

| 当前状态 | 触发动作 | 目标状态 |
|---------|---------|---------|
| 草稿 | 提交 | 待审批 |
| 待审批 | 审批通过 | 已通过 |
| 待审批 | 审批拒绝 | 已拒绝 |
| 已通过 | 生效 | 执行中 |
| 执行中 | 结束 | 已完成 |
| 已通过 | 发起取消 | 取消待审批 |
| 取消待审批 | 取消通过 | 已取消 |
| 取消待审批 | 取消拒绝 | 已通过 |

#### 报错1：请选择一条数据
- **触发条件**：点击查看申请、审批、同步CRM、特殊取消、同步OA、同步FDD等行操作按钮时，未选择数据或选择了多行
- **逻辑分析**：前端在执行单选操作前校验选中行数量，若 selectedRows.length ≠ 1 则阻止操作并提示"请选择一条数据"。单选操作需要明确的目标申请，未选择时无法确定操作对象，多选时操作对象不唯一
- **排查SQL**：
  ```sql
  SELECT APPLY_CODE AS 申请编码,
         DISTRIBUTOR_NAME AS 申请人,
         CAMP_NAME AS 特训营名称,
         APPLY_STATE AS 申请状态,
         APPROVAL_STATE AS 审核状态
  FROM TRAIN_CAMP_APPLY
  ORDER BY CREATE_DATE DESC;
  ```

#### 报错2：只有在培训开始前七天内且已生效的单据才可以发起取消申请！
- **触发条件**：点击特殊取消按钮时，不满足"培训开始前1-7天内且已法大大签约"条件
- **逻辑分析**：前端执行多重校验：①计算时间差值 timeDiff = (PLAN_START_TIME - nowTime) / (24*60*60*1000)，校验 1 <= timeDiff <= 7（特训营开始前1-7天内）；②校验 APPROVAL_STATE = 'fdd_sign'（已法大大签约生效）。任一校验不通过则提示"只有在培训开始前七天内且已生效的单据才可以发起取消申请！"。此校验限制取消时机，避免临近开课取消造成资源浪费，同时要求单据已生效具备业务合法性
- **排查SQL**：
  ```sql
  SELECT APPLY_CODE AS 申请编码,
         CAMP_NAME AS 特训营名称,
         TO_CHAR(PLAN_START_TIME,'YYYY-MM-DD') AS 特训营开始时间,
         APPROVAL_STATE AS 审核状态,
         ROUND(PLAN_START_TIME - SYSDATE) AS 距开始天数
  FROM TRAIN_CAMP_APPLY
  WHERE APPROVAL_STATE = 'approved'
    AND (PLAN_START_TIME <= SYSDATE
         OR PLAN_START_TIME > SYSDATE + 7
         OR APPROVAL_STATE <> 'fdd_sign');
  ```

#### 报错3：该单据已发起取消申请，不可重复发起！
- **触发条件**：点击特殊取消按钮时，该单据已存在进行中的取消申请
- **逻辑分析**：前端校验 CANCEL_APPROVAL_STATE 字段，若不为空且不等于 'reject' 和 'oa_reject'，说明已有进行中的取消申请（如待审批、审批中），提示"该单据已发起取消申请，不可重复发起！"。避免重复发起取消审批导致流程冲突
- **排查SQL**：
  ```sql
  SELECT APPLY_CODE AS 申请编码,
         CAMP_NAME AS 特训营名称,
         APPROVAL_STATE AS 审核状态,
         CANCEL_APPROVAL_STATE AS 取消审核状态
  FROM TRAIN_CAMP_APPLY
  WHERE APPROVAL_STATE = 'fdd_sign'
    AND CANCEL_APPROVAL_STATE IS NOT NULL
    AND CANCEL_APPROVAL_STATE NOT IN ('reject', 'oa_reject');
  ```

#### 报错4：审批意见不能为空
- **触发条件**：审批提交时，approvalComments 字段为空
- **逻辑分析**：前端 applyApprovalFormDS.validate() 对 approvalComments 字段配置 required 校验，提交前校验审批意见是否填写，为空则阻止提交并提示"审批意见不能为空"。审批意见用于记录审批人决策依据，保证审批留痕完整可追溯
- **排查SQL**：
  ```sql
  SELECT APPLY_CODE AS 申请编码,
         CAMP_NAME AS 特训营名称,
         APPROVAL_STATE AS 审核状态,
         APPROVAL_COMMENTS AS 审批意见
  FROM TRAIN_CAMP_APPLY
  WHERE APPROVAL_STATE IN ('approved', 'reject')
    AND (APPROVAL_COMMENTS IS NULL OR APPROVAL_COMMENTS = '');
  ```

#### 报错5：签订人不能为空
- **触发条件**：审批通过（approvalResult=approved）提交时，signerName 字段为空
- **逻辑分析**：前端在审批结果为 approved 时对 signerName 字段配置 required 校验，提交前校验签订人是否选择，为空则阻止提交并提示"签订人不能为空"。签订人用于后续法大大签约流程，审批通过后需明确签订人身份
- **排查SQL**：
  ```sql
  SELECT APPLY_CODE AS 申请编码,
         CAMP_NAME AS 特训营名称,
         APPROVAL_STATE AS 审核状态,
         SIGNER_ID AS 签订人ID,
         SIGNER_NAME AS 签订人姓名
  FROM TRAIN_CAMP_APPLY
  WHERE APPROVAL_STATE = 'approved'
    AND (SIGNER_NAME IS NULL OR SIGNER_ID IS NULL);
  ```

#### 报错6：请求失败
- **触发条件**：调用 mlt/trainCampApply/* 系列接口时，后端返回 HTTP 状态码非 2xx
- **逻辑分析**：前端通过 axios 调用后端接口，若响应状态码非 2xx 或网络异常则触发错误回调，统一提示"请求失败"。常见根因包括：mbo-business 微服务未启动或异常、数据库连接失败、SQL 执行超时、后端业务异常未捕获、外部系统（OA/FDD/CRM）调用失败、工作流引擎异常、网络中断等。需检查 mbo-business 微服务运行状态、外部系统连通性、工作流配置、后端日志定位具体异常堆栈
- **排查SQL**：
  ```sql
  SELECT APPLY_CODE AS 申请编码,
         CAMP_NAME AS 特训营名称,
         APPLY_STATE AS 申请状态,
         APPROVAL_STATE AS 审核状态,
         CRM_ORDER_STATUS AS CRM订单状态,
         ERROR_INFO AS 异常问题,
         TO_CHAR(LAST_UPDATE_DATE,'YYYY-MM-DD HH24:MI:SS') AS 最后更新时间
  FROM TRAIN_CAMP_APPLY
  WHERE LAST_UPDATE_DATE >= SYSDATE - 1
  ORDER BY LAST_UPDATE_DATE DESC;
  ```

#### 报错7：网络异常/接口超时
- **触发条件**：任意接口调用时，网络中断或接口响应超过 axios timeout 配置
- **逻辑分析**：前端 axios 请求未收到响应或响应超时，触发 catch 回调统一提示"请求失败"。常见根因：网络中断、mbo-business 服务假死、数据库慢查询、工作流引擎响应慢等。需检查网络连通性、后端服务负载、数据库性能
- **排查SQL**：
  ```sql
  SELECT APPLY_CODE AS 申请编码, CAMP_NAME AS 特训营名称,
         APPLY_STATE AS 申请状态,
         TO_CHAR(LAST_UPDATE_DATE,'YYYY-MM-DD HH24:MI:SS') AS 最后更新时间
  FROM TRAIN_CAMP_APPLY
  WHERE LAST_UPDATE_DATE >= SYSDATE - 1
  ORDER BY LAST_UPDATE_DATE DESC;
  ```

#### 报错8：权限不足
- **触发条件**：点击查看申请、审批、同步CRM/OA/FDD、特殊取消等按钮时，当前用户无对应 permissionList 权限码
- **逻辑分析**：前端 Button 组件通过 permissionList 配置权限码，HZERO 框架校验当前用户角色是否包含该权限码，未包含则按钮不可见或禁用。若强制调用接口，后端也会校验权限返回403。需联系管理员配置对应角色权限
- **排查SQL**：
  ```sql
  SELECT U.USER_NAME AS 用户名, R.ROLE_NAME AS 角色名, P.PERMISSION_CODE AS 权限码
  FROM SYS_USER U
  LEFT JOIN SYS_USER_ROLE UR ON U.USER_ID = UR.USER_ID
  LEFT JOIN SYS_ROLE R ON UR.ROLE_ID = R.ROLE_ID
  LEFT JOIN SYS_ROLE_PERMISSION RP ON R.ROLE_ID = RP.ROLE_ID
  LEFT JOIN SYS_PERMISSION P ON RP.PERMISSION_ID = P.PERMISSION_ID
  WHERE P.PERMISSION_CODE LIKE '%camp_general_manage%' ORDER BY U.USER_NAME;
  ```

#### 报错9：数据不存在
- **触发条件**：查看申请、审批等操作时，接口返回数据为空或申请编码不存在
- **逻辑分析**：前端通过 applyCode 调用详情接口，后端查询 TRAIN_CAMP_APPLY 表无对应记录或记录已逻辑删除，返回空数据。常见根因：申请编码错误、申请已被删除、跨租户查询、数据权限隔离等。需检查 APPLY_CODE 有效性及数据权限
- **排查SQL**：
  ```sql
  SELECT APPLY_CODE AS 申请编码, CAMP_NAME AS 特训营名称,
         APPLY_STATE AS 申请状态, DELETE_FLAG AS 删除标记
  FROM TRAIN_CAMP_APPLY
  WHERE DELETE_FLAG = 'Y' OR APPLY_CODE IS NULL;
  ```

#### 报错10：状态不允许操作
- **触发条件**：点击审批、特殊取消等按钮时，申请状态不在允许操作的状态范围内
- **逻辑分析**：后端校验申请状态机，如审批要求 APPLY_STATE 为待审批、特殊取消要求审批通过且培训开始前7天内等。状态不匹配时后端返回业务异常，前端提示后端返回的 message。需检查申请当前状态及操作流程
- **排查SQL**：
  ```sql
  SELECT APPLY_CODE AS 申请编码, CAMP_NAME AS 特训营名称,
         APPLY_STATE AS 申请状态, APPROVAL_STATE AS 审核状态,
         CANCEL_APPROVAL_STATE AS 取消审核状态, ERROR_INFO AS 异常问题
  FROM TRAIN_CAMP_APPLY
  WHERE APPLY_STATE NOT IN ('draft','valid','executing','finished')
  ORDER BY CREATE_DATE DESC;
  ```

#### 报错11：同步外部系统失败
- **触发条件**：点击同步CRM/同步OA/同步FDD按钮，对应推送接口返回失败
- **逻辑分析**：前端通过 PRequest 调用 pushCrm/pushOa/pushFdd 接口，接口返回 success=false 或非2xx状态码时触发错误回调。常见根因：CRM/OA/FDD 外部系统不可用、数据不符合外部接口要求、申请状态不允许同步、网络中断等。后端会将异常写入 ERROR_INFO 字段
- **排查SQL**：
  ```sql
  SELECT APPLY_CODE AS 申请编码, CAMP_NAME AS 特训营名称,
         CRM_ORDER_CODE AS CRM单号, CRM_ORDER_STATUS AS CRM订单状态,
         ERROR_INFO AS 异常问题,
         TO_CHAR(LAST_UPDATE_DATE,'YYYY-MM-DD HH24:MI:SS') AS 最后更新时间
  FROM TRAIN_CAMP_APPLY
  WHERE (ERROR_INFO IS NOT NULL OR CRM_ORDER_STATUS = 'FAIL')
    AND LAST_UPDATE_DATE >= SYSDATE - 7
  ORDER BY LAST_UPDATE_DATE DESC;
  ```

#### 报错12：值集数据不显示
- **触发条件**：查询条件或列表中申请状态、审核状态等下拉选项为空
- **逻辑分析**：前端通过 lookupCode 查询值集 MBO.APPLY_APPROVAL_STATE、MBO.ORDER_LECTURE_STATE 等，值集未配置或未启用则下拉选项为空。需在值集管理页面配置对应值集
- **排查SQL**：
  ```sql
  SELECT LOOKUP_CODE AS 值集编码, LOOKUP_VALUE_CODE AS 值编码,
         LOOKUP_VALUE_NAME AS 值名称, ENABLE_FLAG AS 启用标记
  FROM SYS_LOOKUP_VALUE
  WHERE LOOKUP_CODE IN ('MBO.APPLY_APPROVAL_STATE','MBO.ORDER_LECTURE_STATE','MBO.CANCEL_APPROVAL_STATE')
    AND ENABLE_FLAG = 'N' ORDER BY LOOKUP_CODE;
  ```

### 常见问题

**Q1：点将申请被拒绝后能否重新提交？**
A：可以，拒绝后可修改申请内容重新提交审批。

**Q2：取消申请审批被拒绝后怎么办？**
A：取消申请被拒绝后，原点将申请继续有效，可再次发起取消申请。

**Q3：pageType如何区分页面模式？**
A：通过 `useAuthPageOption` 切换：manage 为管理视图，approval 为审批视图。

**Q4：点将申请与CRM订单如何关联？**
A：点将申请审批通过后，系统自动创建CRM订单，通过 CRM_ORDER_STATUS 跟踪订单执行状态。

| 问题 | 排查方式 |
|------|---------|
| 特殊取消按钮校验不通过 | 检查 PLAN_START_TIME 与当前时间差值是否在1-7天，APPROVAL_STATE 是否为 fdd_sign |
| 审批按钮不显示 | 确认 pageType 为 approval |
| 同步FDD按钮不显示 | 确认 pageType 为 approval，仅审批视图显示 |
| 查看协议书无PDF | 检查 queryPDF 接口返回，法大大协议书是否已生成 |
| CRM同步失败 | 检查 pushCrm 接口，确认经销商CRM映射存在 |
