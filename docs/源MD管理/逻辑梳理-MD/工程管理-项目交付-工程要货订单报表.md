### 业务流程图

```text
用户进入工程要货订单报表页面（低代码页面hlod）
    │
    ├── 设置查询条件（要货单号、订单日期、客户、折扣单号、合同、项目等）

    │       ├── 经销商登录时自动注入客户编码
    │       ├── isHome=0（工程）关联项目合同表查contract_unit
    │       ├── 紧急要货标志：orderStat in (3,6,12) and bill_type=1

    ├── 查询结果补充申请人名称
```

## 重点逻辑

### 重点逻辑1：纯报表查询页面

- **业务意义**：供内部人员查询工程要货订单的汇总报表信息，了解工程要货订单整体情况

- **具体逻辑描述**

  - 第1点：本页面为hlod低代码报表页面，无独立前端源码，仅提供查询和导出功能

  - 第2点：不支持新增、修改、删除操作

  - 第3点：数据来源于要货订单头表和行表，通过searchFlag/billType区分工程要货

### 重点逻辑2：经销商数据隔离

- **业务意义**：经销商登录时仅查看自己的订单数据

- **具体逻辑描述**

  - 第1点：经销商登录(userType=D)时自动将客户编码设置为经销商编码(DC)

  - 第2点：仅查询该经销商的订单数据

### 重点逻辑3：工程家装区分

- **业务意义**：通过isHome参数区分工程和家装要货订单报表

- **具体逻辑描述**

  - 第1点：isHome=0为工程要货订单报表，isHome=2为家装要货订单报表

  - 第2点：工程时关联项目合同表查contract_unit

### 重点逻辑4：紧急要货筛选

- **业务意义**：支持筛选紧急要货订单，查看紧急订单执行情况

- **具体逻辑描述**

  - 第1点：isUrgentOrder>0时筛选orderStat in (3,6,12)且bill_type=1的订单

  - 第2点：即常规订单中状态为已提交/部分发货/发货完成

### 重点逻辑5：产品条件模式

- **业务意义**：支持按产品编码或产品型号查询，两种模式性能不同

- **具体逻辑描述**

  - 第1点：conditionFlag=1时直接关联行表like查询产品编码

  - 第2点：conditionFlag≠1时用sa_out_bill_head_id in (子查询)方式查询产品型号

### 重点逻辑6：折扣率格式化

- **业务意义**：折扣率以百分比格式展示，便于阅读

- **具体逻辑描述**

  - 第1点：discount_rate和base_discount_rate格式化为百分比

  - 第2点：计算公式：ROUND(折扣率*100, 2)%，保留2位小数

**报表查询SQL（search）：**

```sql
SELECT * FROM (
  SELECT obh.organization_id,
    lov_order_stat.meaning AS order_stat,
    obh.sa_salebillno, obh.date_invbill,
    iu.real_name AS created_name,
    lov_bill_type.meaning AS bill_type,
    obh.contract_code, obh.contract_name,
    obh.project_code, obh.project_name,
    NVL(obl.qty_bill, 0) AS qty_bill,
    NVL(obl.confirm_out_qty, 0) AS audit_qty,
    (obl.qty_bill - obl.confirm_out_qty - obl.cancel_qty) AS unshipped_qty,
    NVL(obl.price_bill, 0) AS price_bill,
    TO_CHAR(ROUND(NVL(obl.discount_rate, 0) * 100, 2), 'FM999990.00') || '%' AS discount_rate,
    NVL(obl.wtamount_bill, 0) AS wtamount_bill,
    obl.item_code, obl.item_name, obl.item_model,
    c.customer_code, c.customer_name, c.short_name
  FROM sa_out_bill_head obh
    LEFT JOIN epm_project_contract epc ON epc.contract_id = obh.contract_id
    LEFT JOIN epm_discount_policy edp ON edp.discount_policy_id = obh.discount_policy_id
    LEFT JOIN customer c ON obh.customer_id = c.customer_id
    LEFT JOIN iam_user iu ON iu.id = obh.created_by
    LEFT JOIN HPFM_LOV_VALUE lov_order_stat ON lov_order_stat.LOV_CODE = 'AE.EPM.REQUIRE_BILL.ORDER_STAT' AND lov_order_stat.value = obh.order_stat
    LEFT JOIN sa_out_bill_line obl ON obh.sa_out_bill_head_id = obl.sa_out_bill_head_id
  WHERE obh.is_home = 0
) tem
```

#### 报错1：查询条件时间范围不能为空
- **触发条件**：用户点击"查询"或"导出"按钮时，订单日期起止范围(dateInvbillStart/dateInvbillEnd)未选择或为空
- **逻辑分析**：前端在调用查询接口前校验时间范围必填，因报表数据量大，强制要求按订单日期(DATE_INVBILL)区间过滤以避免全表扫描。后端search方法接收conditionDTO后，若dateInvbillStart或dateInvbillEnd为空亦会阻断查询。该报错为阻断性报错，不发起后端请求
- **排查SQL**：
  ```sql
  -- 前端校验为主，后端可结合如下SQL确认时间范围内是否有数据
  SELECT COUNT(*) AS 期间数据量
  FROM SA_OUT_BILL_HEAD obh
  WHERE obh.IS_HOME = 0
    AND obh.DATE_INVBILL BETWEEN :dateInvbillStart AND :dateInvbillEnd
  ```

#### 报错2：导出数据量超过限制
- **触发条件**：用户点击"导出"按钮时，查询结果数据量超过@ExcelExport注解或系统配置的导出上限(默认单次10000条)
- **逻辑分析**：导出调用Repository.search全量查询(不分页)，organizationId=0时设为null以导出所有事业部数据。当结果集超过Excel单sheet上限(65536行)或系统配置的导出条数限制时抛出toast提醒。需缩小查询范围(缩短时间区间、增加客户/项目/产品过滤条件)后重试
- **排查SQL**：
  ```sql
  SELECT COUNT(*) AS 待导出数据量
  FROM SA_OUT_BILL_HEAD obh
  LEFT JOIN SA_OUT_BILL_LINE obl ON obh.SA_OUT_BILL_HEAD_ID = obl.SA_OUT_BILL_HEAD_ID
  WHERE obh.IS_HOME = 0
    AND obh.DATE_INVBILL BETWEEN :dateInvbillStart AND :dateInvbillEnd
    AND (:customerCode IS NULL OR obh.CUSTOMER_CODE = :customerCode)
    AND (:projectCode IS NULL OR obh.PROJECT_CODE = :projectCode)
  ```

#### 报错3：查询无数据
- **触发条件**：用户点击"查询"按钮时，查询条件无匹配数据
- **逻辑分析**：后端search方法按查询条件关联SA_OUT_BILL_HEAD和SA_OUT_BILL_LINE查询，若结果集为空则前端展示"无数据"。需调整查询条件
- **排查SQL**：
  ```sql
  SELECT COUNT(*) AS 查询结果数
  FROM SA_OUT_BILL_HEAD obh
  WHERE obh.IS_HOME = 0
    AND obh.DATE_INVBILL BETWEEN :dateInvbillStart AND :dateInvbillEnd
    AND (:customerCode IS NULL OR obh.CUSTOMER_CODE = :customerCode)
    AND (:projectCode IS NULL OR obh.PROJECT_CODE = :projectCode)
    AND (:saSalebillno IS NULL OR obh.SA_SALEBILLNO LIKE '%' || :saSalebillno || '%')
  ```

#### 报错4：经销商无权限查看其他客户数据
- **触发条件**：经销商登录(userType=D)时尝试查看其他客户的订单数据
- **逻辑分析**：后端search方法中经销商登录时自动将客户编码设置为经销商编码(DC)，实现数据隔离。若查询条件传入其他客户编码则被覆盖。该报错为阻断性报错
- **排查SQL**：
  ```sql
  SELECT iu.USER_ID, iu.USER_TYPE, iu.REAL_NAME
  FROM IAM_USER iu
  WHERE iu.USER_ID = :currentUserId
  -- 期望 USER_TYPE = 'D' 时仅能查看自己的订单
  ```

#### 报错5：报表查询超时
- **触发条件**：查询时，查询数据量过大导致数据库查询超时
- **逻辑分析**：后端search方法关联SA_OUT_BILL_HEAD、SA_OUT_BILL_LINE、EPM_PROJECT_CONTRACT等多表查询，若查询条件过宽导致数据量过大则可能超时。需缩小查询范围
- **排查SQL**：
  ```sql
  SELECT COUNT(*) AS 预估数据量
  FROM SA_OUT_BILL_HEAD obh
  WHERE obh.IS_HOME = 0
    AND obh.DATE_INVBILL BETWEEN :dateInvbillStart AND :dateInvbillEnd
  -- 若数据量过大(超过10万)，建议缩小查询范围
  ```

#### 报错6：导出失败，请稍后重试
- **触发条件**：导出时，导出处理异常(如内存不足、IO异常等)
- **逻辑分析**：导出方法中try-catch捕获异常，若处理失败则提示稍后重试。需稍后重试或联系管理员查看后端日志
- **排查SQL**：
  ```sql
  SELECT sem.OBJID, sem.OBJTYPENAME, sem.ERROR_MSG, sem.CREATION_DATE
  FROM SYS_EXCEPTION_MSG sem
  WHERE sem.OBJTYPENAME = '工程要货订单报表'
  ORDER BY sem.CREATION_DATE DESC
  ```

### 常见问题

- 问题1：报表数据与工程要货订单页面数据不一致
  - 原因：可能存在缓存或查询条件差异
  - 解决思路：刷新页面重新查询，确认查询条件一致

- 问题2：经销商登录为什么只能看到自己的订单？
  - 原因：经销商登录(userType=D)时系统自动将客户编码设置为经销商编码(DC)，实现数据隔离
  - 解决思路：这是预期行为，经销商仅查看自己的订单

- 问题3：产品编码和产品型号查询有什么区别？
  - 原因：产品编码(conditionFlag=1)直接在主查询关联行表like匹配；产品型号(conditionFlag≠1)用子查询方式匹配，性能不同
  - 解决思路：优先使用产品编码查询以获得更好性能

- 问题4：紧急要货筛选条件是什么？
  - 原因：isUrgentOrder>0时筛选orderStat in (3,6,12)且bill_type=1的订单
  - 解决思路：即常规订单中状态为已提交/部分发货/发货完成

- 问题5：导出时为什么organizationId=0要设为null？
  - 原因：organizationId=0表示租户级查询（全事业部），设为null使SQL中该条件不生效
  - 解决思路：这是预期行为，用于导出所有事业部的数据

- 问题6：申请人名称为什么有时显示客户简称？
  - 原因：查询结果中createdName(iam_user.real_name)为空时，通过created_by_bak关联Customer表取short_name补充显示
  - 解决思路：这是数据兼容处理，旧数据可能没有iam_user记录
