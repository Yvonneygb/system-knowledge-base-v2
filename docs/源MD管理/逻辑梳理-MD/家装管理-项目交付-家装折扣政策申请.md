# 家装管理-项目交付-家装折扣政策申请

---

## 业务流程

### 业务流程图

```text
开始 → ★新建家装折扣政策申请★ → 选择政策类型 → 填写政策信息（名称/订单类型/有效期等） → 维护产品明细 → 维护客户明细 → 保存 → 提交审批 → ⚖审批通过？
  ├─（通过）政策生效 → 可用于订单折扣 → 结束
  ├─（拒绝）可修改后重新提交 → 结束
  └─（撤回）状态恢复为新建 → 可继续编辑 → 结束
```

### 下游影响

- 影响1：家装订单折扣
  - 审批通过的折扣政策在家装订单中作为折扣依据

- 影响2：折扣政策明细（EPM_DISCOUNT_POLICY_ITEM）

- 影响3：折扣政策客户（EPM_DISCOUNT_POLICY_CUSTOMER）
  - 适用客户写入关联表

## 重点逻辑

### 重点逻辑1：政策类型决定适用范围 `动态必填`

- **业务意义**：不同政策类型对应不同的适用范围字段

- **具体逻辑描述**

  - 第1点：政策类型=1（按客户）时，适用客户必填

  - 第2点：政策类型=2（按区域）时，适用区域必填

  - 第3点：政策类型=3（按客户分类）时，适用客户分类必填

  - 第4点：政策类型=4（按省份）时，适用省份必填

### 重点逻辑2：家装渠道固定 `渠道锁定`

- **业务意义**：家装折扣政策固定为家装渠道

- **具体逻辑描述**

  - 第1点：销售渠道默认为'3'（家装），且不可编辑

### 重点逻辑3：有效期校验 `时间校验`

- **业务意义**：确保折扣政策有明确的有效期范围

- **具体逻辑描述**

  - 第1点：有效开始日期和有效结束日期必填

  - 第2点：有效结束日期必须大于有效开始日期

### 重点逻辑4：产品明细导入 `批量导入`

- **业务意义**：支持批量导入产品明细，提升效率

- **具体逻辑描述**

  - 第1点：通过importProduct接口批量导入产品明细

  - 第2点：导入后自动获取产品价格和折扣底线

### 保存校验

- 校验1：政策名称必填 —— 确保政策有明确标识

  - 详细逻辑

    - 第1点：前端校验discountPolicyName非空

 C  - 系统体现：前端提示

- 校验2：有效结束日期须大于有效开始日期 —— 确保有效期范围合法

  - 详细逻辑

    - 第1点：前端校验effectiveDateEnd > effectiveDateStart

  - 系统体现：前端日期选择器联动校验

### 提交校验

- 校验1：产品明细不能为空 —— 确保政策有实际产品内容
  - **详细逻辑**：提交时校验产品明细列表(epmDiscountPolicyItemList)非空
  - **系统体现**：阻断性报错
  - **排查SQL**：`SELECT COUNT(*) FROM EPM_DISCOUNT_POLICY_ITEM WHERE DISCOUNT_POLICY_ID = #{discountPolicyId};`

- 校验2：申请类型为产品(1)时产品编码必填 —— 确保产品类型申请有具体产品
  - **详细逻辑**：applicationType=1时itemCode必填
  - **系统体现**：前端DataSet dynamicProps required校验
  - **排查SQL**：`SELECT * FROM EPM_DISCOUNT_POLICY_ITEM WHERE DISCOUNT_POLICY_ID = #{discountPolicyId} AND APPLICATION_TYPE = 1 AND ITEM_CODE IS NULL;`

- 校验3：申请类型为型号(2)时产品型号必填 —— 确保型号类型申请有具体型号
  - **详细逻辑**：applicationType=2时itemModel必填
  - **系统体现**：前端DataSet dynamicProps required校验
  - **排查SQL**：`SELECT * FROM EPM_DISCOUNT_POLICY_ITEM WHERE DISCOUNT_POLICY_ID = #{discountPolicyId} AND APPLICATION_TYPE = 2 AND ITEM_MODEL IS NULL;`

- 校验4：单个经销商封顶数量须<=政策封顶总数量行 —— 确保封顶数量逻辑合理
  - **详细逻辑**：customerCapsNumber > 0且totalCapNumber > 0时，totalCapNumber须>=customerCapsNumber
  - **系统体现**：前端DataSet validator校验，提示"政策封顶总数量行必须大于单个经销商封顶数量"
  - **排查SQL**：`SELECT * FROM EPM_DISCOUNT_POLICY_ITEM WHERE CUSTOMER_CAPS_NUMBER > 0 AND TOTAL_CAP_NUMBER > 0 AND TOTAL_CAP_NUMBER < CUSTOMER_CAPS_NUMBER;`

- 校验5：经销商封顶量须为正整数 —— 确保封顶量合法
  - **详细逻辑**：cappingQty不能为空、不能为负数、须为整数
  - **系统体现**：前端DataSet validator校验，提示"请输入经销商封顶量"/"请输入整数"/"经销商封顶量不能为负数"
  - **排查SQL**：`SELECT * FROM EPM_DISCOUNT_POLICY_CUSTOMER WHERE CAPPING_QTY IS NULL OR CAPPING_QTY < 0;`

- 校验6：工作流提交 —— 保存并提交走工作流审批
  - **详细逻辑**：调用saveAndSubmit接口，先保存数据再启动工作流
  - **系统体现**：POST /epm-discount-policy/save-and-submit
  - **排查SQL**：`SELECT DISCOUNT_POLICY_ID, DISCOUNT_POLICY_CODE, HZ_APPROVE_STATUS FROM EPM_DISCOUNT_POLICY WHERE DISCOUNT_POLICY_ID = #{discountPolicyId};`

#### 报错1：政策名称不能为空
- **触发条件**：详情页点击"保存"按钮时，政策名称（DISCOUNT_POLICY_NAME）字段为空
- **逻辑分析**：前端校验discountPolicyName非空，或后端实体注解校验失败。政策名称是折扣政策的唯一标识，最大长度30字符，必填。
- **排查SQL**：
  ```sql
  SELECT P.DISCOUNT_POLICY_ID AS 政策ID,
         P.DISCOUNT_POLICY_CODE AS 政策编号,
         P.DISCOUNT_POLICY_NAME AS 政策名称,
         P.HZ_APPROVE_STATUS AS 审核状态
  FROM EPM_DISCOUNT_POLICY P
  WHERE P.DISCOUNT_POLICY_ID = :policyId
    AND P.DISCOUNT_POLICY_NAME IS NULL;
  ```

#### 报错2：有效结束日期须大于有效开始日期
- **触发条件**：详情页保存时，有效结束日期（EFFECTIVE_DATE_END）早于或等于有效开始日期（EFFECTIVE_DATE_START）
- **逻辑分析**：前端日期选择器联动校验effectiveDateEnd > effectiveDateStart，或后端校验失败。折扣政策需有明确且合法的有效期范围，结束日期必须大于开始日期。
- **排查SQL**：
  ```sql
  SELECT P.DISCOUNT_POLICY_CODE AS 政策编号,
         P.EFFECTIVE_DATE_START AS 有效开始日期,
         P.EFFECTIVE_DATE_END AS 有效结束日期
  FROM EPM_DISCOUNT_POLICY P
  WHERE P.DISCOUNT_POLICY_ID = :policyId
    AND P.EFFECTIVE_DATE_END <= P.EFFECTIVE_DATE_START;
  ```

#### 报错3：折扣政策名称最大输入30个字符
- **触发条件**：详情页保存时，政策名称（DISCOUNT_POLICY_NAME）长度超过30个字符
- **逻辑分析**：后端EpmDiscountPolicyServiceImpl校验折扣政策名称长度，超过30字符时抛出"折扣政策名称最大输入30个字符"。数据库字段DISCOUNT_POLICY_NAME为VARCHAR(30)。
- **排查SQL**：
  ```sql
  SELECT P.DISCOUNT_POLICY_CODE AS 政策编号,
         P.DISCOUNT_POLICY_NAME AS 政策名称,
         LENGTH(P.DISCOUNT_POLICY_NAME) AS 名称长度
  FROM EPM_DISCOUNT_POLICY P
  WHERE P.DISCOUNT_POLICY_ID = :policyId
    AND LENGTH(P.DISCOUNT_POLICY_NAME) > 30;
  ```

#### 报错4：产品明细不能为空
- **触发条件**：详情页点击"提交"按钮时，产品明细列表（lineDs）为空
- **逻辑分析**：前端handleSubmit校验lineDs.toData().length为0时提示"还未维护产品明细!"。后端EpmDiscountPolicyServiceImpl也校验产品行不能为空。提交前必须至少维护一条产品明细。
- **排查SQL**：
  ```sql
  SELECT P.DISCOUNT_POLICY_CODE AS 政策编号,
         (SELECT COUNT(*) FROM EPM_DISCOUNT_POLICY_ITEM I
          WHERE I.DISCOUNT_POLICY_ID = P.DISCOUNT_POLICY_ID) AS 产品明细数量
  FROM EPM_DISCOUNT_POLICY P
  WHERE P.DISCOUNT_POLICY_ID = :policyId;
  ```

#### 报错5：至少保留一条有效产品明细行
- **触发条件**：详情页保存时，所有产品明细行被删除（_status为delete）
- **逻辑分析**：前端handleValidator过滤非删除状态记录（validLineList），若为空则提示"至少保留一条有效产品明细行"。防止用户删除所有明细后保存空单据。
- **排查SQL**：
  ```sql
  SELECT P.DISCOUNT_POLICY_CODE AS 政策编号,
         (SELECT COUNT(*) FROM EPM_DISCOUNT_POLICY_ITEM I
          WHERE I.DISCOUNT_POLICY_ID = P.DISCOUNT_POLICY_ID
            AND I.VALID_STAT <> 3) AS 有效明细数量
  FROM EPM_DISCOUNT_POLICY P
  WHERE P.DISCOUNT_POLICY_ID = :policyId;
  ```

#### 报错6：政策封顶总数量行必须大于单个经销商封顶数量
- **触发条件**：保存产品明细时，capping=2（校验单个经销商封顶）且customerCapsNumber > totalCapNumber
- **逻辑分析**：前端LineDS的validator校验customerCapsNumber > 0且totalCapNumber > 0时，totalCapNumber须>=customerCapsNumber。后端EpmDiscountPolicyServiceImpl也校验该逻辑。确保封顶数量逻辑合理。
- **排查SQL**：
  ```sql
  SELECT I.ITEM_CODE AS 产品编码,
         I.TOTAL_CAP_NUMBER AS 政策封顶总数量,
         I.CUSTOMER_CAPS_NUMBER AS 单个经销商封顶数量
  FROM EPM_DISCOUNT_POLICY_ITEM I
  WHERE I.DISCOUNT_POLICY_ID = :policyId
    AND I.CAPPING = 2
    AND I.CUSTOMER_CAPS_NUMBER > 0
    AND I.TOTAL_CAP_NUMBER > 0
    AND I.TOTAL_CAP_NUMBER < I.CUSTOMER_CAPS_NUMBER;
  ```

#### 报错7：单个经销商封顶数量为正整数
- **触发条件**：保存产品明细时，capping=2且customerCapsNumber为空、负数或非整数
- **逻辑分析**：前端ToppingOutDS的validator校验cappingQty不能为空、不能为负数、须为整数。后端EpmDiscountPolicyServiceImpl校验"单个经销商封顶数量为正整数"。
- **排查SQL**：
  ```sql
  SELECT C.CUSTOMER_CODE AS 经销商编码,
         C.CUSTOMER_NAME AS 经销商名称
  FROM EPM_DISCOUNT_POLICY_CUSTOMER C
  WHERE C.DISCOUNT_POLICY_ID = :policyId
    AND (C.CAPPING_QTY IS NULL OR C.CAPPING_QTY < 0 OR C.CAPPING_QTY <> FLOOR(C.CAPPING_QTY));
  ```

#### 报错8：起订量需小于封顶量
- **触发条件**：阶梯政策行编辑起订量（minimumQty）时，值大于封顶量（cappingQty）
- **逻辑分析**：前端监听infoDetailDs的update事件，当name=='minimumQty'且value > record.get('cappingQty')时回滚值并提示"起订量需小于封顶量"。确保阶梯政策区间合法。
- **排查SQL**：
  ```sql
  SELECT I.ITEM_CODE AS 产品编码,
         L.MINIMUM_QTY AS 起订量,
         L.CAPPING_QTY AS 封顶量
  FROM EPM_DISCOUNT_POLICY_ITEM_LINE L
    INNER JOIN EPM_DISCOUNT_POLICY_ITEM I ON I.DISCOUNT_POLICY_ITEM_ID = L.DISCOUNT_POLICY_ITEM_ID
  WHERE I.DISCOUNT_POLICY_ID = :policyId
    AND L.MINIMUM_QTY > 0
    AND L.CAPPING_QTY > 0
    AND L.MINIMUM_QTY >= L.CAPPING_QTY;
  ```

#### 报错9：阶梯政策区间冲突
- **触发条件**：阶梯政策行编辑起订量或封顶量时，与同一产品明细下其他阶梯政策行区间重叠
- **逻辑分析**：前端监听infoDetailDs的update事件，循环比对当前行与其他行的起订量-封顶量区间。若存在重叠（A<=C && B>=C 等四种情况）则回滚值并提示"起订量与封顶量的区间与第N行阶梯政策区间冲突"。
- **排查SQL**：
  ```sql
  SELECT A.ITEM_CODE AS 产品编码,
         A.MINIMUM_QTY AS 行A起订量, A.CAPPING_QTY AS 行A封顶量,
         B.MINIMUM_QTY AS 行B起订量, B.CAPPING_QTY AS 行B封顶量
  FROM EPM_DISCOUNT_POLICY_ITEM_LINE A
    INNER JOIN EPM_DISCOUNT_POLICY_ITEM_LINE B
      ON B.DISCOUNT_POLICY_ITEM_ID = A.DISCOUNT_POLICY_ITEM_ID
     AND B.DISCOUNT_POLICY_ITEM_LINE_ID <> A.DISCOUNT_POLICY_ITEM_LINE_ID
    INNER JOIN EPM_DISCOUNT_POLICY_ITEM I ON I.DISCOUNT_POLICY_ITEM_ID = A.DISCOUNT_POLICY_ITEM_ID
  WHERE I.DISCOUNT_POLICY_ID = :policyId
    AND A.MINIMUM_QTY <= B.CAPPING_QTY
    AND A.CAPPING_QTY >= B.MINIMUM_QTY;
  ```

#### 报错10：折扣率未填写
- **触发条件**：保存时，优惠方式为折扣（preferentialType=1）的阶梯政策行折扣率（discountRate）为空
- **逻辑分析**：前端handleValidator遍历产品明细，对preferentialType==1的行校验每条阶梯政策的discountRate非空。若为空则提示"第X的第Y条明细的折扣率未填写！"。
- **排查SQL**：
  ```sql
  SELECT I.ITEM_CODE AS 产品编码,
         I.PREFERENTIAL_TYPE AS 优惠方式,
         L.MINIMUM_QTY AS 起订量,
         L.DISCOUNT_RATE AS 折扣率
  FROM EPM_DISCOUNT_POLICY_ITEM_LINE L
    INNER JOIN EPM_DISCOUNT_POLICY_ITEM I ON I.DISCOUNT_POLICY_ITEM_ID = L.DISCOUNT_POLICY_ITEM_ID
  WHERE I.DISCOUNT_POLICY_ID = :policyId
    AND I.PREFERENTIAL_TYPE = 1
    AND L.DISCOUNT_RATE IS NULL;
  ```

#### 报错11：请先选择销售渠道/政策类型/币种
- **触发条件**：详情页点击"新增"产品明细或阶梯政策时，头信息的channel、policyType或currency为空
- **逻辑分析**：前端handleLineCreate和handleInfoCreate校验头信息channel、policyType、currency非空。若任一为空则提示"请先选择销售渠道/政策类型/币种"。这些字段是产品明细和阶梯政策的前置依赖。


#### 报错12：批次开始时间和批次结束时间必须同时填写
- **触发条件**：详情页保存时，批次开始日期（BATCH_START_DATE）和批次结束日期（BATCH_END_DATE）只有一个有值
- **逻辑分析**：前端checkValidity校验(batchStartDate && !batchEndDate) || (!batchStartDate && batchEndDate)，若成立则提示"批次开始时间和批次结束时间必须同时填写或同时为空"。
- **排查SQL**：
