# 产品中心-说明书-说明书查阅数据

> **说明**：本菜单为低代码页面（hlod），前端无独立页面源码，通过低代码平台配置绑定后端接口渲染。以下内容基于后端代码梳理。

## 业务流程

### 业务流程图

```text
上游：用户查阅说明书 → 自动写入查阅日志 → 开始 → ★说明书查阅数据查询★ → 选择模式（地图/列表/汇总） → 查询 → 展示统计结果 → 结束
```

### 上游依赖

| 上游模块 | 依赖类型 | 依赖说明 | 依赖成立条件 |
|---------|---------|---------|------------|
| 说明书主档（ES_SPEC） | 数据依赖 | 查阅数据关联说明书信息 | 说明书已创建 |
| 查阅日志（ES_SEARCH_LOG） | 数据依赖 | 用户查阅说明书时自动记录的日志 | 用户已查阅说明书 |
| 产品分类主数据 | 数据依赖 | 按分类维度统计查阅数据 | 分类已维护 |
| 用户主档（HZERO.IAM_USER） | 数据依赖 | 展示查阅人信息 | 用户数据存在 |
| 低代码平台 | 配置依赖 | 页面通过低代码配置渲染 | 低代码配置已完成 |

### 下游影响

- 影响1：运营分析
  - 查阅数据供运营分析报表使用，支撑讲师和产品改进参考

- 影响2：产品改进
  - 通过查阅频次分析产品说明书关注度，指导产品改进方向

## 重点逻辑

### 重点逻辑1：双模式展示 `地图/列表+汇总`

- **业务意义**：提供不同维度的查阅数据视角，满足明细查看和汇总分析需求

- **具体逻辑描述**

  - 第1点：地图模式和列表模式共用同一接口list-mode-data，展示每条查阅记录明细

  - 第2点：汇总模式使用独立接口summary-mode-data，按说明书维度聚合统计查阅次数

### 重点逻辑2：查阅日志自动采集 `自动记录`

- **业务意义**：用户查阅说明书时系统自动记录日志，无需手动录入

- **具体逻辑描述**

  - 第1点：用户每次查阅说明书时自动写入查阅日志表

  - 第2点：日志记录包含查阅人、查阅时间、查阅的说明书、IP地址等信息

  - 第3点：查阅数据实时更新，反映最新查阅情况

### 重点逻辑3：说明书分类关联管理 `分类操作`

- **业务意义**：支持说明书分类关联/取消关联产品，以及产品分类的新增和删除

- **具体逻辑描述**

  - 第1点：save-specclas-ref-es接口支持说明书分类批量关联或取消关联产品

  - 第2点：save-item-class接口支持产品分类新增

  - 第3点：deleta-item-class接口支持产品分类删除

#### 报错1：查询失败，请稍后重试
- **触发条件**：列表/地图模式或汇总模式查询时，后端接口`GET /v1/{orgId}/manual-classification/list-mode-data`或`GET /v1/{orgId}/manual-classification/summary-mode-data`返回异常
- **逻辑分析**：低代码页面通过配置绑定后端接口渲染。后端`ManualClassificationServiceImpl.getMapMode`/`getSummaryMmode`通过`PageHelper.doPageAndSort`分页查询`ManualClassificationMapper.getMapMode`/`getSummaryMmode`。当数据库连接异常、SQL执行超时或服务不可用时，HZERO框架捕获异常返回错误响应，低代码页面展示查询失败提示。
- **排查SQL**：
  ```sql
  -- 检查查阅日志表是否有数据及数据量
  SELECT COUNT(1) AS 查阅日志总记录数,
         MIN(L.CREATION_DATE) AS 最早查阅时间,
         MAX(L.CREATION_DATE) AS 最近查阅时间
  FROM ES_SEARCH_LOG L;
  ```

#### 报错2：权限不足，无法访问
- **触发条件**：用户访问说明书查阅数据菜单或操作关联/新增/删除分类按钮时，当前角色未配置对应权限
- **逻辑分析**：低代码页面权限由低代码平台配置，后端接口`@Permission(level = ResourceLevel.ORGANIZATION, permissionLogin = true)`要求登录态访问。HZERO权限拦截器校验用户角色权限，未配置时返回403，低代码页面拦截访问。
- **排查SQL**：
  ```sql
  -- 查询当前用户角色是否分配了说明书查阅数据相关权限
  SELECT U.REAL_NAME AS 用户名, R.NAME AS 角色名, P.CODE AS 权限编码, P.TYPE AS 权限类型
  FROM HZERO.IAM_USER U
  JOIN HZERO.IAM_MEMBER M ON M.MEMBER_ID = U.ID
  JOIN HZERO.IAM_ROLE R ON R.ID = M.ROLE_ID
  JOIN HZERO.IAM_ROLE_PERMISSION RP ON RP.ROLE_ID = R.ID
  JOIN HZERO.IAM_PERMISSION P ON P.ID = RP.PERMISSION_ID
  WHERE U.REAL_NAME = :用户名
    AND P.CODE LIKE '%manual-classification%';
  ```

#### 报错3：登录已过期，请重新登录
- **触发条件**：用户在说明书查阅数据页面操作时，HZERO Token过期或被踢出登录
- **逻辑分析**：低代码页面请求携带Authorization Token访问后端接口，后端网关校验Token有效性。Token过期时返回401状态码，低代码平台捕获401并跳转登录页。常见于长时间未操作或单点登录会话超时。
- **排查SQL**：
  ```sql
  -- 查询用户最近登录会话状态
  SELECT U.REAL_NAME AS 用户名, T.TOKEN_VALUE AS 令牌, T.EXPIRES_IN AS 有效期秒,
         T.CREATE_TIME AS 创建时间
  FROM HZERO.OAUTH_ACCESS_TOKEN T
  JOIN HZERO.IAM_USER U ON U.ID = T.USER_ID
  WHERE U.REAL_NAME = :用户名
  ORDER BY T.CREATE_TIME DESC;
  ```

#### 报错4：暂无数据
- **触发条件**：列表/地图模式或汇总模式查询返回空列表，低代码表格无数据渲染
- **逻辑分析**：后端`getMapMode`/`getSummaryMmode`返回Page内容为空。根因可能为：1）查询条件过严无匹配查阅记录；2）尚无用户查阅过说明书，ES_SEARCH_LOG表无数据；3）说明书未关联产品分类。低代码表格展示"暂无数据"占位。
- **排查SQL**：
  ```sql
  -- 检查是否有查阅日志记录及关联说明书
  SELECT S.SPEC_ID AS 说明书ID, S.SPEC_TITLE AS 说明书名称,
         (SELECT COUNT(1) FROM ES_SEARCH_LOG L WHERE L.SPECID = S.SPEC_ID) AS 查阅次数
  FROM ES_SPEC S
  WHERE S.HZ_APPROVE_STATUS = 'APPROVED'
    AND NVL(S.HISTORY, 0) <> 2
  ORDER BY 查阅次数 DESC;
  ```

#### 报错5：产品分类已存在，新增失败
- **触发条件**：点击"新增分类"按钮调用`POST /v1/{orgId}/manual-classification/save-item-class`时，同一组织下相同父级ID已存在相同编码的分类
- **逻辑分析**：后端`ManualClassificationServiceImpl.saveItemClass`首先通过`manualClassificationMapper.getItemClass(dto)`按"编码+组织ID+父级ID"查询是否已存在。若`CollectionUtils.isEmpty(list)`为false（即已存在），方法直接返回不保存，不抛异常但前端未收到新增成功反馈。低代码页面根据返回结果提示新增失败。该逻辑为静默判重，无显式异常抛出。
- **排查SQL**：
  ```sql
  -- 检查同一父级下是否已存在相同编码的产品分类
  SELECT ITEM_CLASS_ID AS 分类ID, ITEM_CLASS_CODE AS 分类编码,
         ITEM_CLASS_PID AS 父级ID, ORGANIZATION_ID AS 组织ID,
         IS_END AS 是否明细
  FROM 产品分类表
  WHERE ITEM_CLASS_CODE = :分类编码
    AND ORGANIZATION_ID = :组织ID
    AND ITEM_CLASS_PID = :父级ID;
  ```

#### 报错6：分类关联/取消关联失败
- **触发条件**：点击"关联产品"按钮调用`POST /v1/{orgId}/manual-classification/save-specclas-ref-es`时，批量更新分类关联接口返回异常
- **逻辑分析**：后端`ManualClassificationServiceImpl.batchUpdateByPrimaryKey`遍历dtos列表，对每条记录设置updatetime后调用`manualClassificationMapper.updateByPrimaryKey(item)`更新。方法标注`@Transactional(rollbackFor = Exception.class)`，任一记录更新失败则整体回滚。失败原因可能为：1）关联记录SPECCLAS_REF_ID不存在；2）数据库死锁；3）并发修改冲突。
- **排查SQL**：
  ```sql
  -- 检查说明书分类关联记录是否存在
  SELECT R.SPECCLAS_REF_ID AS 关联ID, R.SPEC_ID AS 说明书ID, R.SPECCLAS_ID AS 分类ID,
         R.SEQ AS 序号, R.UPDATETIME AS 更新时间
  FROM ES_SPECCLAS_REF R
  WHERE R.SPEC_ID = :说明书ID;
  ```

#### 报错7：分类删除失败
- **触发条件**：点击"删除分类"按钮调用`POST /v1/{orgId}/manual-classification/deleta-item-class`时，删除产品分类接口返回异常
- **逻辑分析**：后端`ManualClassificationServiceImpl.deletaItemClass`直接调用`manualClassificationMapper.deletaItemClass(dto)`执行删除。方法标注`@Transactional(rollbackFor = Exception.class)`，删除失败则回滚。失败原因可能为：1）分类下存在子级分类未先删除；2）分类被说明书引用（存在ES_SPECCLAS_REF关联记录）；3）数据库外键约束冲突。
- **排查SQL**：
  ```sql
  -- 检查待删除分类是否有子级分类或被说明书引用
  SELECT C.ITEM_CLASS_ID AS 分类ID, C.ITEM_CLASS_CODE AS 分类编码,
         (SELECT COUNT(1) FROM 产品分类表 C2 WHERE C2.ITEM_CLASS_PID = C.ITEM_CLASS_ID) AS 子级分类数,
         (SELECT COUNT(1) FROM ES_SPECCLAS_REF R WHERE R.SPECCLAS_ID = C.ITEM_CLASS_ID) AS 关联说明书数
  FROM 产品分类表 C
  WHERE C.ITEM_CLASS_ID = :分类ID;
  ```

### 常见问题

- 问题1：查阅数据多久更新一次
  - 原因：查阅日志实时写入，每次查阅说明书时自动记录
  - 解决思路：数据实时更新，无需手动刷新

- 问题2：列表模式和汇总模式的区别
  - 原因：列表模式展示每条查阅明细记录，汇总模式按说明书维度聚合统计
  - 解决思路：根据分析需求选择模式，明细查看用列表模式，统计分析用汇总模式
