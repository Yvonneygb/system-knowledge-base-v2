## 重点逻辑

### 重点逻辑1：OA审批流程 {审批流转}

- **业务意义**：政策性补贴申请需经OA审批，确保补贴发放合规

- **具体逻辑描述**

  - 第1点：保存并提交时通过workFlowStart发起OA审批流程

  - 第2点：OA审批通过后通过doProcessOA回调更新审核状态为APPROVED

  - 第3点：OA审批拒绝后更新审核状态为REJECTED

  - 第4点：审批状态流转：NEW→RUN→APPROVED/REJECTED

### 重点逻辑2：资金池关联 {余额校验}

- **业务意义**：申请金额需关联资金池余额，确保补贴有充足资金来源

- **具体逻辑描述**

  - 第1点：通过select-capital接口查询资金池余额

  - 第2点：通过select-account接口查询余额账户信息

  - 第3点：申请金额不能超过资金池可用余额

### 重点逻辑3：多币种支持 {币种处理}

- **业务意义**：支持不同币种的补贴申请，匹配国际化业务需求

- **具体逻辑描述**

  - 第1点：通过get-currency接口查询可用币种

  - 第2点：不同币种的申请金额独立核算

#### 按钮1：新增（列表页）

- **触发条件**：始终可用
- **执行逻辑**：
  - 第1点：打开新建政策性补贴申请页面
  - 第2点：自动带出当前登录用户为申请人，当前时间为申请时间
- **接口调用**：无，仅前端操作

#### 按钮2：保存（编辑页）

- **触发条件**：编辑状态
- **执行逻辑**：
  - 第1点：校验头信息和行信息
  - 第2点：保存到SA_POLICY_SPECIAL_HEADER和SA_POLICY_SPECIAL_LINE
- **接口调用**：POST `/v1/{organizationId}/sa-policy-special-headers/save`
- **排查SQL**：

```sql
SELECT * FROM SA_POLICY_SPECIAL_HEADER WHERE POLICY_SPECIAL_ID = #{id};
SELECT * FROM SA_POLICY_SPECIAL_LINE WHERE POLICY_SPECIAL_ID = #{id};
```

#### 按钮3：保存并提交（编辑页）

- **触发条件**：编辑状态
- **执行逻辑**：
  - 第1点：先执行保存校验
  - 第2点：保存数据到SA_POLICY_SPECIAL_HEADER
  - 第3点：通过workFlowStart发起OA审批流程
  - 第4点：更新审核状态为RUN
- **接口调用**：POST `/v1/{organizationId}/sa-policy-special-headers/save-and-submit`
- **排查SQL**：

```sql
SELECT * FROM SA_POLICY_SPECIAL_HEADER WHERE POLICY_SPECIAL_ID = #{id} AND AUDIT_STAT = 'RUN';
```

#### 按钮4：删除（列表页）

- **触发条件**：选中未提交的记录（AUDIT_STAT为NEW或null）
- **执行逻辑**：
  - 第1点：校验单据状态为未提交
  - 第2点：删除SA_POLICY_SPECIAL_HEADER和SA_POLICY_SPECIAL_LINE数据
- **接口调用**：POST `/v1/{organizationId}/sa-policy-special-headers/remove`
- **排查SQL**：

```sql
SELECT * FROM SA_POLICY_SPECIAL_HEADER WHERE POLICY_SPECIAL_ID = #{id} AND (AUDIT_STAT IS NULL OR AUDIT_STAT = 'NEW');
```

### 保存校验

- 校验1：经销商不能为空 —— 确保申请关联明确经销商

  - 详细逻辑

    - 第1点：保存时校验经销商ID不为空

  - 系统体现：toast提醒

  - 排查SQL：

    ```sql
    SELECT * FROM SA_POLICY_SPECIAL_HEADER WHERE CUST_ID IS NULL;
    ```

- 校验2：申请金额必须大于0 —— 确保申请金额有效

  - 详细逻辑

    - 第1点：保存时校验申请金额大于0

  - 系统体现：toast提醒

  - 排查SQL：

    ```sql
    SELECT * FROM SA_POLICY_SPECIAL_HEADER WHERE APPLY_AMT <= 0;
    ```

- 校验3：交易公司不能为空 —— 确保申请关联明确交易公司

  - 详细逻辑

    - 第1点：保存时校验交易公司ID不为空

  - 系统体现：toast提醒

  - 排查SQL：

    ```sql
    SELECT * FROM SA_POLICY_SPECIAL_HEADER WHERE TRADING_COMPANY_ID IS NULL;
    ```

### 提交校验

- 校验1：保存校验全部通过 —— 确保提交前数据完整有效

  - 详细逻辑

    - 第1点：提交前先执行保存校验全部规则

    - 第2点：校验申请金额不超过资金池可用余额

  - 系统体现：阻断性报错

  - 排查SQL：

    ```sql
    SELECT H.POLICY_SPECIAL_ID, H.APPLY_AMT, C.CAPITAL_POOL 
    FROM SA_POLICY_SPECIAL_HEADER H, CAPITAL_ACCOUNT C
    WHERE H.EXT_ACCOUNT_ID = C.ACCOUNT_ID AND H.APPLY_AMT > C.CAPITAL_POOL;
    ```

### 状态机

#### 状态机流转图

```text
新建 ──保存──→ 已保存(NEW) ──保存并提交──→ 审批中(RUN) ──OA审批通过──→ 已审核(APPROVED)
                                              │
                                              └──OA审批拒绝──→ 已拒绝(REJECTED)
```

#### 状态机列表

| 状态机名称 | 状态释义 | 可执行的操作 |
|-----------|---------|------------|
| NEW | 新建/已保存未提交 | 编辑、保存、保存并提交、删除 |
| RUN | 已提交OA审批中 | 无（等待审批结果） |
| APPROVED | OA审批通过 | 查看 |
| REJECTED | OA审批拒绝 | 修改、重新提交 |

#### 报错1：经销商不能为空
- **触发条件**：用户在新建/编辑页未选择经销商直接点击保存
- **逻辑分析**：保存接口sa-policy-special-headers/save在写入SA_POLICY_SPECIAL_HEADER前校验CUST_ID非空。经销商是申请关联资金池和法人的前置条件，未选择经销商将导致后续交易公司、法人、余额账户无法带出，资金池余额校验也无从执行。校验在Controller层前置拦截，toast提示后阻断保存
- **排查SQL**：
  ```sql
  SELECT POLICY_SPECIAL_ID, POLICY_SPECIAL_NO, CUST_ID, CUST_NAME, AUDIT_STAT
  FROM SA_POLICY_SPECIAL_HEADER
  WHERE CUST_ID IS NULL OR CUST_NAME IS NULL;
  ```

#### 报错2：申请金额必须大于0
- **触发条件**：用户在申请金额输入框填写0、负数或留空后点击保存
- **逻辑分析**：保存校验APPLY_AMT > 0，因补贴申请代表实际向经销商发放的补贴金额，必须为正数。0或负数无业务意义，且会导致后续资金池扣减异常（扣减0或反向增加余额）。校验在Service层执行，toast提示后阻断保存
- **排查SQL**：
  ```sql
  SELECT POLICY_SPECIAL_ID, POLICY_SPECIAL_NO, CUST_NAME, APPLY_AMT, AUDIT_STAT
  FROM SA_POLICY_SPECIAL_HEADER
  WHERE APPLY_AMT IS NULL OR APPLY_AMT <= 0;
  ```

#### 报错3：交易公司不能为空
- **触发条件**：用户选择了经销商但未选择交易公司直接点击保存
- **逻辑分析**：交易公司是关联法人（LEGAL_ENTITY_ID）和余额账户（EXT_ACCOUNT_ID）的桥梁，未选择交易公司将导致法人信息无法带出、select-account接口无法查询余额账户、资金池余额校验无法执行。校验TRADING_COMPANY_ID非空，toast提示后阻断保存
- **排查SQL**：
  ```sql
  SELECT POLICY_SPECIAL_ID, POLICY_SPECIAL_NO, CUST_NAME, TRADING_COMPANY_ID, TRADING_COMPANY_NAME
  FROM SA_POLICY_SPECIAL_HEADER
  WHERE TRADING_COMPANY_ID IS NULL OR TRADING_COMPANY_NAME IS NULL;
  ```

#### 报错4：申请金额超过资金池余额
- **触发条件**：用户点击"保存并提交"，提交校验发现APPLY_AMT > 资金池可用余额（CAPITAL_POOL）
- **逻辑分析**：提交时通过select-capital接口查询关联余额账户（CAPITAL_ACCOUNT）的CAPITAL_POOL当前余额，校验APPLY_AMT <= CAPITAL_POOL。超出余额意味着补贴无充足资金来源，审批通过后扣减资金池将出现负数。此为阻断性报错，阻止OA流程（SA_POLICY_SPECIAL_MCS_AW）发起，需用户调减申请金额或先补充资金池
- **排查SQL**：
  ```sql
  SELECT H.POLICY_SPECIAL_ID, H.POLICY_SPECIAL_NO, H.CUST_NAME, H.APPLY_AMT,
         C.ACCOUNT_NAME, C.CAPITAL_POOL, (H.APPLY_AMT - C.CAPITAL_POOL) AS 超额金额
  FROM SA_POLICY_SPECIAL_HEADER H
  JOIN CAPITAL_ACCOUNT C ON H.EXT_ACCOUNT_ID = C.ACCOUNT_ID
  WHERE H.APPLY_AMT > C.CAPITAL_POOL
    AND H.AUDIT_STAT IN ('NEW', 'RUN');
  ```

#### 报错5：流程编码缺失，请选择流程
- **触发条件**：用户点击"保存并提交"但未选择OA审批流程（flowCode为空）
- **逻辑分析**：保存并提交接口saveAndSubmit（SaPolicySpecialHeaderServiceImpl.java:226）在执行保存前校验flowCode非空，若StringUtils.isEmpty(dto.getFlowCode())则抛出CommonException("流程编码缺失，请选择流程！")。flowCode是发起OA工作流（workFlowStart）的必要参数，缺失将导致WorkflowClient无法启动流程实例。校验在Service层前置拦截，阻断OA流程发起。需用户在提交前选择对应的审批流程
- **排查SQL**：
  ```sql
  -- 核查政策性补贴申请可用的OA流程配置
  SELECT WORKFLOW_CODE, WORKFLOW_NAME, ENABLED
  FROM HPFM_WORKFLOW_DEF
  WHERE WORKFLOW_CODE LIKE 'SA_POLICY_SPECIAL%' AND ENABLED = 1;
  ```

#### 报错6：请选择需要删除的数据
- **触发条件**：用户在列表页未选中任何记录直接点击删除按钮
- **逻辑分析**：删除接口remove（SaPolicySpecialHeaderServiceImpl.java:252）校验入参列表非空，若CollectionUtils.isEmpty(cmContractPaymentApplyList)则抛出CommonException("请选择需要删除的数据！")。根因有二：(1)前端未选中行就调用删除接口，请求体为空列表；(2)前端选中行但policySpecialId未正确传递到请求参数。校验在Service层前置拦截，toast提示后阻断删除操作。需选中至少一条记录后再点击删除
- **排查SQL**：
  ```sql
  SELECT POLICY_SPECIAL_ID, POLICY_SPECIAL_NO, CUST_NAME, APPLY_AMT, AUDIT_STAT
  FROM SA_POLICY_SPECIAL_HEADER
  WHERE AUDIT_STAT IS NULL OR AUDIT_STAT = 'NEW'
  ORDER BY CREATE_TIME DESC;
  ```

#### 报错7：无法获事业部信息
- **触发条件**：用户新建或保存政策性补贴申请时，epmDivisionService.getCurrentDivision()返回null
- **逻辑分析**：生成单据编号generateCode（SaPolicySpecialHeaderServiceImpl.java:177）和查询资金池selectCapital（SaPolicySpecialHeaderServiceImpl.java:279）均调用epmDivisionService.getCurrentDivision()获取当前事业部，若返回null则抛出CommonException("无法获事业部信息")。根因有三：(1)当前用户未配置默认事业部（HPFM_DIVISION_USER关联缺失）；(2)用户上下文中divisionId未正确设置（登录态异常）；(3)事业部配置已禁用或删除。需联系管理员为当前用户配置事业部
- **排查SQL**：
  ```sql
  -- 核查当前用户的事业部配置
  SELECT DU.USER_ID, DU.DIVISION_ID, D.ENT_NAME, D.ENABLED
  FROM HPFM_DIVISION_USER DU
  JOIN HPFM_DIVISION D ON DU.DIVISION_ID = D.ENT_ID
  WHERE DU.USER_ID = #{userId} AND D.ENABLED = 1;
  ```

#### 报错8：无法获上线文信息
- **触发条件**：用户新建政策性补贴申请生成单据编号时，DetailsHelper.getUserDetails()返回空
- **逻辑分析**：生成单据编号generateCode（SaPolicySpecialHeaderServiceImpl.java:180）调用DetailsHelper.getUserDetails()获取用户上下文，若ObjectUtils.isEmpty(customUserDetails)则抛出CommonException("无法获上线文信息")。根因有二：(1)用户登录态过期或Token失效，上下文未正确注入；(2)线程上下文未传递（异步线程或Feign调用场景丢失UserDetails）。需用户重新登录后重试
- **排查SQL**：
  ```sql
  -- 核查用户账号状态（表名以HZERO IAM实际表为准）
  SELECT USER_ID, LOGIN_NAME, STATUS, ENABLED, LAST_LOGIN_DATE
  FROM IAM_USER
  WHERE USER_ID = #{userId};
  ```

#### 报错9：单据状态不允许删除
- **触发条件**：用户选中已提交审批（AUDIT_STAT为RUN）或已审批通过（AUDIT_STAT为APPROVED）的单据点击删除
- **逻辑分析**：删除接口remove（SaPolicySpecialHeaderServiceImpl.java:250）当前实现直接按POLICY_SPECIAL_ID批量删除头表和行表，未显式校验单据状态。但根据业务规则，仅AUDIT_STAT为NEW或null的未提交单据允许删除，已提交OA审批的单据删除将导致OA流程实例残留（WFID/HZ_INSTANCE_ID指向不存在的业务单据）。前端应限制仅未提交单据可勾选删除，若绕过前端直接调用接口需后端补充状态校验。需先撤回OA审批再删除
- **排查SQL**：
  ```sql
  SELECT POLICY_SPECIAL_ID, POLICY_SPECIAL_NO, AUDIT_STAT, WFID, HZ_INSTANCE_ID,
         (CASE WHEN AUDIT_STAT IN ('RUN', 'APPROVED') THEN '已提交/已审批-不允许删除'
               ELSE '允许删除' END) AS 删除判断
  FROM SA_POLICY_SPECIAL_HEADER
  WHERE POLICY_SPECIAL_ID IN (#{id1}, #{id2});
  ```

#### 报错10：网络请求失败
- **触发条件**：用户点击保存、保存并提交、删除或查询，前端axios请求抛出网络异常或超时
- **逻辑分析**：前端调用/v1/{organizationId}/sa-policy-special-headers/*系列接口时，因后端ae-business服务不可用、网关路由异常、网络中断或请求超时导致连接失败。根因有四：(1)ae-business微服务未注册到Nacos或已宕机；(2)OA审批系统（workFlowStart）调用超时导致保存并提交接口整体超时；(3)EBS资金池查询（select-capital）接口超时；(4)网络中断或防火墙拦截。需联系运维确认ae-business、OA、EBS服务状态
- **排查SQL**：
  ```sql
  -- 核查政策性补贴申请单据量及OA流程状态分布
  SELECT AUDIT_STAT, COUNT(1) AS 单据数
  FROM SA_POLICY_SPECIAL_HEADER
  GROUP BY AUDIT_STAT
  ORDER BY AUDIT_STAT;
  ```

### 常见问题

- 问题1：OA审批流程未发起

  - 解决思路：检查OA系统连接状态，查看SA_POLICY_SPECIAL_HEADER.AUDIT_STAT是否为RUN

- 问题2：审批通过后资金池余额未扣减
  - 原因：doProcessOA回调未正确执行或资金池同步失败
  - 解决思路：检查审批回调日志，确认CAPITAL_POOL是否更新
