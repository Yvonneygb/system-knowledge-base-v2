# 点将管理-设计师点将-设计师饱和度

> 后端代码位于 mbo-business 微服务，API 路径前缀为 `mlt/designApply/*`（饱和度统计查询）。

## 业务流程

```
用户进入设计师饱和度页面
        |
        ├── 按条件查询 ──→ 设计师姓名/讲师类型/负责事业部/时间范围
        |
        ├── 查看列表 ──→ 展示设计师饱和度统计数据
        |       |
        |       └── 饱和度 = 已用天数 / 总点将天数 × 100%
        |
        ├── 查看详情 ──→ 查看设计师饱和度明细
        |
        └── 导出 ──→ 导出饱和度统计数据
```

纯查询统计页面，无工作流，饱和度数据由设计点将执行完成后自动回写形成。

### 上游依赖

| 上游模块 | 依赖类型 | 依赖说明 | 依赖成立条件 |
|---------|---------|---------|-------------|
| 设计师点将执行 | 数据依赖 | 设计点将执行完成后自动回写饱和度数据 | 设计点将执行已完成 |
| 设计师点将管理 | 数据依赖 | 设计点将审批通过后生成待作业申请，影响饱和度 | 申请审批已通过 |
| 讲师档案 | 数据依赖 | 通过讲师档案关联设计师信息和所属事业部 | 设计师已在讲师档案中配置 |

### 下游影响

- 审批时通过查看饱和度弹窗辅助审批决策
- 饱和度数据反映设计师工作负载，指导接单和设计排期
- 接近满档时预警服务冲突，影响后续点将排期

## 重点逻辑

### 重点逻辑1：饱和度计算

- **业务意义**：用已用天数占总点将天数的比例衡量设计师还有多少可派服务的余量
- **具体逻辑描述**：饱和度 = 已用天数 / 总点将天数 × 100%，超过100%表示超负荷，比例越接近满档说明可承接空间越小

### 重点逻辑2：纯查询统计

- **业务意义**：本页面仅做查询统计，不涉及工作流和审批操作
- **具体逻辑描述**：通过 page 接口查询饱和度数据，支持按设计师姓名、讲师类型、负责事业部、时间范围筛选

### 重点逻辑3：数据自动回写

- **业务意义**：饱和度不是人工填报的指标，而是由执行环节自动形成
- **具体逻辑描述**：饱和度数据由设计点将执行模块在完成确认时自动计算和更新，数据准确性取决于执行环节是否及时做完成确认

### 重点逻辑4：值集依赖

- **业务意义**：页面展示依赖多个值集用于下拉选项和状态展示
- **具体逻辑描述**：依赖值集 MBO.DESIGN_APPLY_TYPE(设计点将类型)、MBO.DESIGN_STATE(设计状态)、MBO.DESIGN_LECTURER_LEVEL(设计师级别)、MBO.APPLY_APPROVAL_STATE(审批状态)

## 详细逻辑

### 界面模块

页面由三部分组成：`Header`（标题"设计师饱和度"）、`SaturationForm`（作业饱和度只读卡片）、待作业申请列表（`Table`）。页面加载时 `SaturationForm` 自动调用饱和度接口获取当前用户数据并回填表单，同时通过 `onDetail` 回调将明细列表数据传给父组件 `loadData` 注入到待作业申请列表，全过程无查询栏、无按钮、无弹窗。

数据来源接口（`generalCommonApi`，定义于 `src/api/general/common.ts`）：
- 无 `lecturerArchivesCode` 时（本页面场景）：`GET mlt/maLecturerSaturation/getByLecturerCode`（按当前登录用户取饱和度）
- 有 `lecturerArchivesCode` 时（组件被详情页等复用）：`GET mlt/maLecturerSaturation/{lecturerArchivesCode}`（按讲师档案编码取饱和度）

> 说明：本页面饱和度接口位于 `api/general/common.ts` 的 `generalCommonApi`，而非任务指定的 `api/general/designApply.ts`。`designApply.ts` 中的接口（`page`、`detail`、各类审批/执行接口等）属于设计点将申请模块，本页面不直接调用。

查询SQL：

```sql
SELECT MLS.LECTURER_NAME    AS "设计师姓名",
       MLS.LECTURER_LEVEL   AS "讲师类型",
       MLS.ORG_NAME         AS "负责事业部",
       MLS.TOTAL_DAYS       AS "总点将天数",
       MLS.USED_DAYS        AS "已用天数",
       MLS.TOTAL_DAYS - MLS.USED_DAYS AS "剩余天数",
       MLS.SATURATION_RATE  AS "饱和度百分比",
       MLS.SATURATION_STATUS AS "状态"
FROM DESIGNER_SATURATION MLS
WHERE (:lecturerName IS NULL OR MLS.LECTURER_NAME LIKE '%' || :lecturerName || '%')
  AND (:lecturerLevel IS NULL OR MLS.LECTURER_LEVEL = :lecturerLevel)
  AND (:orgName IS NULL OR MLS.ORG_NAME = :orgName)
  AND (:startDate IS NULL OR MLS.STAT_PERIOD >= :startDate)
  AND (:endDate IS NULL OR MLS.STAT_PERIOD <= :endDate)
ORDER BY MLS.SATURATION_RATE DESC;
```

## 常见问题FAQ

### 报错一览表

| 报错信息 | 提示节点 | 根因与解决方案 | 等级 | 详细逻辑 |
|---------|---------|--------------|------|---------|
| 请求失败 | 查询饱和度 | 后端服务异常，检查后端服务状态及网络连接 | error | 后端接口返回非200状态码 |
| 数据为空 | 页面加载完成 | 当前用户未关联讲师档案或无饱和度数据，检查用户与讲师档案关联关系 | warning | 查询返回空列表 |
| 网络异常/接口超时 | 查询饱和度 | 网络中断或接口响应超时，检查网络及后端超时配置 | error | axios catch 或 timeout |
| 权限不足 | 页面访问 | 当前用户无饱和度查询权限码，联系管理员授权 | error | permissionList 校验未通过 |
| 导出失败 | 点击导出 | 导出接口异常或数据量超限，检查后端导出服务及数据量 | error | 导出接口返回失败 |
| 值集数据不显示 | 下拉选项 | 值集 MBO.DESIGN_LECTURER_LEVEL 等未配置，检查值集配置 | warning | lookupCode 查询返回空 |
| 时间范围校验失败 | 查询条件 | 开始时间大于结束时间，检查时间范围选择 | error | 前端校验 startDate <= endDate |

#### 报错1：请求失败
- **触发条件**：调用 mlt/designApply/* 查询接口时，后端返回 HTTP 状态码非 2xx
- **逻辑分析**：前端通过 axios 调用后端接口，若响应状态码非 2xx 或网络异常则触发错误回调，统一提示"请求失败"。常见根因包括：mbo-business 微服务未启动或异常、数据库连接失败、SQL 执行超时、后端业务异常未捕获、网络中断等。需检查 mbo-business 微服务运行状态、数据库连接池、后端日志定位具体异常堆栈
- **排查SQL**：
  ```sql
  SELECT LECTURER_NAME AS 设计师姓名,
         LECTURER_LEVEL AS 讲师类型,
         ORG_NAME AS 负责事业部,
         SATURATION_RATE AS 饱和度百分比,
         SATURATION_STATUS AS 状态,
         TO_CHAR(LAST_UPDATE_DATE,'YYYY-MM-DD HH24:MI:SS') AS 最后更新时间
  FROM DESIGNER_SATURATION
  WHERE LAST_UPDATE_DATE >= SYSDATE - 1
  ORDER BY LAST_UPDATE_DATE DESC;
  ```

#### 报错2：数据为空
- **触发条件**：页面加载完成查询饱和度数据时，返回空列表
- **逻辑分析**：前端查询饱和度数据返回空列表，提示"数据为空"。常见根因包括：当前用户未关联讲师档案（LECTURER_CODE 为空）、设计师无设计点将执行记录、查询条件过滤过严、统计周期内无数据等。需检查用户与讲师档案关联关系、查询条件、设计点将执行记录
- **排查SQL**：
  ```sql
  SELECT LECTURER_CODE AS 设计师编码,
         LECTURER_NAME AS 设计师姓名,
         LECTURER_LEVEL AS 讲师类型,
         ORG_NAME AS 负责事业部,
         TOTAL_DAYS AS 总点将天数,
         USED_DAYS AS 已用天数,
         SATURATION_STATUS AS 状态
  FROM DESIGNER_SATURATION
   WHERE LECTURER_CODE IS NULL
      OR TOTAL_DAYS IS NULL
      OR USED_DAYS IS NULL;
  ```

#### 报错3：网络异常/接口超时
- **触发条件**：查询饱和度数据时，网络中断或接口响应超过 axios timeout 配置
- **逻辑分析**：前端 axios 请求未收到响应或响应超时，触发 catch 回调统一提示"请求失败"。常见根因：网络中断、mbo-business 服务假死、数据库慢查询、统计SQL执行时间长等。需检查网络连通性、后端服务负载、数据库性能
- **排查SQL**：
  ```sql
  SELECT LECTURER_NAME AS 设计师姓名,
         SATURATION_STATUS AS 状态,
         TO_CHAR(LAST_UPDATE_DATE,'YYYY-MM-DD HH24:MI:SS') AS 最后更新时间
  FROM DESIGNER_SATURATION
  WHERE LAST_UPDATE_DATE >= SYSDATE - 1
  ORDER BY LAST_UPDATE_DATE DESC;
  ```

#### 报错4：权限不足
- **触发条件**：访问设计师饱和度页面或点击导出按钮时，当前用户无对应权限码
- **逻辑分析**：HZERO 框架校验当前用户角色是否包含饱和度查询/导出权限码，未包含则页面或按钮不可见。若强制调用接口，后端也会校验权限返回403。需联系管理员配置对应角色权限
- **排查SQL**：
  ```sql
  SELECT U.USER_NAME AS 用户名,
         R.ROLE_NAME AS 角色名,
         P.PERMISSION_CODE AS 权限码
  FROM SYS_USER U
  LEFT JOIN SYS_USER_ROLE UR ON U.USER_ID = UR.USER_ID
  LEFT JOIN SYS_ROLE R ON UR.ROLE_ID = R.ROLE_ID
  LEFT JOIN SYS_ROLE_PERMISSION RP ON R.ROLE_ID = RP.ROLE_ID
  LEFT JOIN SYS_PERMISSION P ON RP.PERMISSION_ID = P.PERMISSION_ID
  WHERE P.PERMISSION_CODE LIKE '%design_saturation%'
  ORDER BY U.USER_NAME;
  ```

#### 报错5：导出失败
- **触发条件**：点击导出按钮，导出接口返回失败或导出数据量超过限制
- **逻辑分析**：前端调用导出接口，后端生成Excel文件流返回。常见根因：导出数据量过大超过内存限制、OSS存储异常、文件生成异常、查询条件过宽导致全表扫描等。需缩小查询范围、检查后端导出服务配置
- **排查SQL**：
  ```sql
  SELECT COUNT(*) AS 总记录数,
         SUM(CASE WHEN SATURATION_STATUS = 'overload' THEN 1 ELSE 0 END) AS 超负荷数,
         SUM(CASE WHEN SATURATION_STATUS = 'near_full' THEN 1 ELSE 0 END) AS 接近满档数
  FROM DESIGNER_SATURATION
  WHERE STAT_PERIOD BETWEEN :startDate AND :endDate;
  ```

#### 报错6：值集数据不显示
- **触发条件**：查询条件或列表中讲师类型、状态等下拉选项为空
- **逻辑分析**：前端通过 lookupCode 查询值集 MBO.DESIGN_LECTURER_LEVEL、MBO.DESIGN_APPLY_TYPE、MBO.DESIGN_STATE、MBO.APPLY_APPROVAL_STATE 等，值集未配置或未启用则下拉选项为空。需在值集管理页面配置对应值集
- **排查SQL**：
  ```sql
  SELECT LOOKUP_CODE AS 值集编码,
         LOOKUP_VALUE_CODE AS 值编码,
         LOOKUP_VALUE_NAME AS 值名称,
         ENABLE_FLAG AS 启用标记
  FROM SYS_LOOKUP_VALUE
  WHERE LOOKUP_CODE IN ('MBO.DESIGN_LECTURER_LEVEL','MBO.DESIGN_APPLY_TYPE','MBO.DESIGN_STATE','MBO.APPLY_APPROVAL_STATE')
    AND ENABLE_FLAG = 'N'
  ORDER BY LOOKUP_CODE;
  ```

#### 报错7：时间范围校验失败
- **触发条件**：查询条件时间范围中，开始时间大于结束时间
- **逻辑分析**：前端 DatePicker(range) 组件校验时间范围合法性，若 startDate > endDate 则阻止查询并提示。需检查时间范围选择是否正确
- **排查SQL**：
  ```sql
  SELECT LECTURER_NAME AS 设计师姓名,
         STAT_PERIOD AS 统计周期,
         TO_CHAR(CREATION_DATE,'YYYY-MM-DD') AS 创建日期
  FROM DESIGNER_SATURATION
  WHERE STAT_PERIOD IS NOT NULL
  ORDER BY STAT_PERIOD DESC;
  ```

### 常见问题

| 问题 | 排查方式 |
|------|---------|
| 饱和度超过100%是什么意思 | 表示设计师已用天数超过总点将天数，处于超负荷状态，需调整排期 |
| 饱和度数据什么时候更新 | 设计师点将执行完成时自动更新 |
| 值集数据不显示 | 检查值集 MBO.DESIGN_APPLY_TYPE、MBO.DESIGN_STATE、MBO.DESIGN_LECTURER_LEVEL、MBO.APPLY_APPROVAL_STATE 是否已配置 |
| 饱和度列表无数据 | 检查查询条件是否正确，确认设计师已有点将执行记录 |
