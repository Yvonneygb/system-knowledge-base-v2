# 产品中心-产品资料-产品推广等级维护

---

## 业务流程

### 业务流程图

```text
开始 → 新增/编辑推广等级（选择产品+选择等级+备注） → 保存 → 保存校验 → 生效 → 结束（无审批）
                                      ↓
                               失效操作 → 状态置为invalid → 同步更新产品资料推广等级为C → 结束
```

### 上游依赖

| 上游模块 | 依赖类型 | 依赖说明 | 依赖成立条件 |
|---------|---------|---------|------------|
| 产品资料（LNK_PROD） | 数据依赖 | 通过产品编码关联产品主数据，获取产品名称、型号、品牌事业部、生命状态等展示信息 | 产品资料中存在该产品编码 |
| 值集CRM.PROD_PROMOTE_GRADE | 配置依赖 | 等级下拉选项的数据来源 | 值集已配置且生效 |
| 值集CRM.COMMON_STATUS | 配置依赖 | 状态下拉选项的数据来源（valid/invalid） | 值集已配置 |
| 值集CRM.PRODUCT_Z_STATE | 配置依赖 | 生命状态下拉选项的数据来源 | 值集已配置 |
| 值集AE.ITEM_ORGANIZATION | 配置依赖 | 品牌事业部下拉选项的数据来源 | 值集已配置 |

### 下游影响

- 影响1：产品资料推广等级字段同步更新
  - 保存推广等级后，同步更新LNK_PROD表的PROD_PROMOTE_GRADE字段；失效时将产品推广等级重置为C

- 影响2：产品推广等级要求配置
  - 推广等级与推广等级要求配置（prodPromoteGradesControls）配合使用，要求配置定义达到某等级需满足的指标条件

- 影响3：渠道推广力度
  - 推广等级决定产品在不同渠道的推广力度与资源分配，等级越高推广力度越大

## 重点逻辑

### 重点逻辑1：同一产品唯一有效等级 `唯一性控制`

- **业务意义**：确保每个产品在同一时间只有一个有效的推广等级，避免多个等级冲突导致推广策略混乱

- **具体逻辑描述**

  - 第1点：保存时如果新记录状态为valid，系统自动查找该产品编码是否已存在status=valid的记录

  - 第2点：如果已存在有效记录，系统自动将旧记录状态置为invalid，再插入/更新新记录

  - 第3点：此逻辑在后端ServiceImpl的saveData方法中实现，前端无感知

### 重点逻辑2：失效时产品推广等级重置为C `等级重置`

- **业务意义**：产品推广等级被失效后，产品不再具有特殊推广等级，回归默认等级C

- **具体逻辑描述**

  - 第1点：失效操作将推广等级记录状态置为invalid

  - 第2点：同步更新LNK_PROD表对应产品的PROD_PROMOTE_GRADE字段为C

  - 第3点：如果是有效保存，则将LNK_PROD表的PROD_PROMOTE_GRADE更新为实际等级值

### 重点逻辑3：保存同时更新产品资料 `数据联动`

- **业务意义**：推广等级维护与产品资料保持实时同步，确保产品资料中的推广等级字段始终反映最新状态

- **具体逻辑描述**

  - 第1点：保存推广等级后，遍历所有传入记录，根据产品编码更新LNK_PROD表

  - 第2点：有效记录更新为实际等级值，失效记录更新为C

  - 第3点：同时更新LNK_PROD的LAST_UPDATED_BY为当前操作用户

> 列表查询SQL（Mapper: LnkProdPromoteGradeMapper.xml → selectList）：

```sql
SELECT
    LPPG.ID,
    LPPG.PROD_CODE AS prodCode,
    LPPG.GRADE,
    LPPG.STATUS,
    LPPG.REMARK,
    LPPG.OBJECT_VERSION_NUMBER AS objectVersionNumber,
    lp.prod_name AS prodName,
    lp.LH_PROD_MODEL AS lHprodModel,
    lp.SM_STATE AS smState,
    t2.ORG_NAME AS deptName,
    TO_CHAR(LPPG.Creation_Date, 'yyyy-mm-dd hh24:mi:ss') AS creationDate,
    TO_CHAR(LPPG.Last_Update_Date, 'yyyy-mm-dd hh24:mi:ss') AS lastUpdateDate,
    us.REAL_NAME AS createdByName,
    us2.REAL_NAME AS lastUpdatedByName
FROM LNK_PROD_PROMOTE_GRADE LPPG
    JOIN lnk_prod lp ON LPPG.PROD_CODE = lp.PROD_CODE
    LEFT JOIN LNK_ORG_EXT T2 ON lp.dept_id = t2.row_id
    LEFT JOIN HZERO.IAM_USER us ON LPPG.CREATED_BY = us.id
    LEFT JOIN HZERO.IAM_USER us2 ON LPPG.Last_Updated_By = us2.id
WHERE 1=1
    -- 动态条件：prodCode(=)、prodName(like)、lhProdModel(like)、deptName(=)、grade(=)、smState(=)、status(=)
ORDER BY LPPG.Creation_Date DESC, LPPG.ID DESC
```

### 保存校验

- 校验1：产品编码非空 —— 确保关联到有效产品

  - 详细逻辑

    - 第1点：前端弹窗产品编码字段required=true，commonFn_formValid校验

    - 第2点：后端Entity的prodCode字段标注@NotBlank

  - 系统体现：前端弹窗必填提示+后端阻断性报错

  - 排查SQL：

    ```sql
    SELECT * FROM LNK_PROD_PROMOTE_GRADE WHERE PROD_CODE IS NULL;
    ```

- 校验2：等级非空 —— 确保指定推广等级

  - 详细逻辑

    - 第1点：前端弹窗等级字段required=true，commonFn_formValid校验

    - 第2点：后端Entity的grade字段标注@NotBlank

  - 系统体现：前端弹窗必填提示+后端阻断性报错

  - 排查SQL：

    ```sql
    SELECT * FROM LNK_PROD_PROMOTE_GRADE WHERE GRADE IS NULL;
    ```

- 校验3：同一产品唯一有效等级 —— 避免等级冲突

  - 详细逻辑

    - 第1点：后端saveData方法中，对每条status=valid的记录，查询该prodCode是否已存在valid记录

    - 第2点：如果存在，将旧记录status置为invalid后再插入/更新新记录

  - 系统体现：后端自动处理，无前端提示

  - 排查SQL：

    ```sql
    SELECT PROD_CODE, COUNT(*) AS cnt
    FROM LNK_PROD_PROMOTE_GRADE
    WHERE STATUS = 'valid'
    GROUP BY PROD_CODE
    HAVING COUNT(*) > 1;
    ```

### 提交校验

本菜单无提交/审批功能，数据保存后直接生效。

### 状态机

#### 状态机流转图

```text
[新建] → valid（有效） → 失效操作 → invalid（失效）
                                      ↓
                              不可再失效（行内失效按钮隐藏）
```

#### 状态机列表

| 状态机名称 | 状态释义 | 可执行的操作 |
|-----------|---------|------------|
| valid | 有效 | 行内失效、批量失效 |
| invalid | 失效 | 无（行内失效按钮隐藏） |

| PROD_CODE | VARCHAR2 | 产品编码 | - | 关联条件，与LNK_PROD_PROMOTE_GRADE.PROD_CODE匹配 |
| PROD_PROMOTE_GRADE | VARCHAR2 | 产品推广等级 | - | 保存推广等级时同步更新为实际等级值；失效时重置为C |
| LAST_UPDATED_BY | VARCHAR2 | 最后修改人 | - | 联动更新时设置为当前操作用户ID |

> 联动更新SQL（ServiceImpl.saveData中调用lnkProdRepository.updateByPrimaryCode）：

```sql
UPDATE LNK_PROD
SET PROD_PROMOTE_GRADE = #{grade},
    LAST_UPDATED_BY = #{userId}
WHERE PROD_CODE = #{prodCode}
```

#### 报错3：操作失败！
- **触发条件**：点击失效确认框确认后，后端保存接口返回失败
- **逻辑分析**：前端onDisabledFn方法调用POST /v1/{organizationId}/prodPromoteGrade/disable接口，后端将LNK_PROD_PROMOTE_GRADE记录状态置为invalid，同时将LNK_PROD.PROD_PROMOTE_GRADE重置为C。若产品编码不存在或数据库异常则返回失败，前端提示"操作失败！"。
- **排查SQL**：
  ```sql
  SELECT PG.ID, PG.PROD_CODE AS 产品编码, PG.GRADE AS 推广等级,
         PG.STATUS AS 状态, P.PROD_PROMOTE_GRADE AS 产品当前等级
  FROM LNK_PROD_PROMOTE_GRADE PG
    LEFT JOIN LNK_PROD P ON P.PROD_CODE = PG.PROD_CODE
  WHERE PG.ID = :recordId;
  ```

#### 报错4：产品编码不能为空
- **触发条件**：新增弹窗中未选择产品编码就点击确认按钮
- **逻辑分析**：前端onOkFn方法中先调用commonFn_formValid(ds)进行表单校验，产品编码字段配置required=true（listConfig.tsx第74行），校验不通过时弹窗提示"产品编码不能为空"并阻止提交。后端Controller的validObject方法校验LnkProdPromoteGrade实体prodCode字段的@NotBlank注解，若前端校验被绕过则后端抛出校验异常。
- **排查SQL**：
  ```sql
  -- 检查是否存在产品编码为空的推广等级记录（异常数据）
  SELECT PG.ID, PG.PROD_CODE AS 产品编码, PG.GRADE AS 推广等级, PG.STATUS AS 状态
  FROM LNK_PROD_PROMOTE_GRADE PG
  WHERE PG.PROD_CODE IS NULL OR TRIM(PG.PROD_CODE) IS NULL;
  ```

#### 报错5：等级不能为空
- **触发条件**：新增弹窗中未选择等级就点击确认按钮
- **逻辑分析**：前端onOkFn方法中commonFn_formValid校验等级字段required=true（listConfig.tsx第91行），校验不通过时弹窗提示"等级不能为空"。后端Entity的grade字段标注@NotBlank，validObject校验失败时抛出阻断性异常。
- **排查SQL**：
  ```sql
  -- 检查是否存在等级为空的推广等级记录（异常数据）
  SELECT PG.ID, PG.PROD_CODE AS 产品编码, PG.GRADE AS 推广等级, PG.STATUS AS 状态
  FROM LNK_PROD_PROMOTE_GRADE PG
  WHERE PG.GRADE IS NULL OR TRIM(PG.GRADE) IS NULL;
  ```

#### 报错6：查询失败
- **触发条件**：列表页加载或点击查询按钮时，后端列表查询接口返回失败
- **逻辑分析**：前端DataSet的transport.read调用GET /v1/{organizationId}/prodPromoteGrades接口，后端selectList方法通过LnkProdPromoteGradeMapper.selectList查询LNK_PROD_PROMOTE_GRADE关联LNK_PROD、LNK_ORG_EXT、HZERO.IAM_USER表。若数据库连接异常、SQL执行超时或关联的产品资料不存在（INNER JOIN导致数据丢失）则返回失败，前端DataSet自动提示查询失败。
- **排查SQL**：
  ```sql
  -- 检查推广等级记录关联的产品资料是否存在
  SELECT PG.PROD_CODE AS 产品编码, PG.GRADE AS 推广等级,
         P.PROD_NAME AS 产品名称
  FROM LNK_PROD_PROMOTE_GRADE PG
    LEFT JOIN LNK_PROD P ON P.PROD_CODE = PG.PROD_CODE
  WHERE P.PROD_CODE IS NULL;
  ```

#### 报错7：权限不足
- **触发条件**：当前用户无对应操作权限时点击新增/批量失效/行内失效/导出/导入按钮
- **逻辑分析**：前端按钮配置permissionList权限编码（新增/失效：hzero.product_data.product_info.promote_grade-list.ps.edit；导出：hzero.product_data.product_info.promote_grade-list.ps.export；导入：hzero.product_data.product_info.promote_grade-list.ps.import），无权限时按钮不显示。若通过API直接调用，后端@Permission(level=ResourceLevel.ORGANIZATION)注解校验组织级权限，无权限时抛出403异常。
- **排查SQL**：
  ```sql
  -- 检查用户角色权限配置（HZERO平台权限表）
  SELECT R.CODE AS 角色编码, R.NAME AS 角色名称,
         P.CODE AS 权限编码, P.NAME AS 权限名称
  FROM HZERO.IAM_ROLE R
    JOIN HZERO.IAM_ROLE_PERMISSION RP ON R.ID = RP.ROLE_ID
    JOIN HZERO.IAM_PERMISSION P ON RP.PERMISSION_ID = P.ID
  WHERE P.CODE LIKE 'hzero.product_data.product_info.promote_grade-list.ps.%'
  ORDER BY P.CODE;
  ```

#### 报错8：会话过期
- **触发条件**：用户登录会话已失效时执行任意操作（查询/新增/失效/导出/导入）
- **逻辑分析**：前端request请求携带的access_token过期，后端网关拦截返回401状态码，前端axios拦截器检测到401后弹出登录确认框提示"会话过期，请重新登录"，跳转登录页面。
- **排查SQL**：
  ```sql
  -- 检查用户登录会话状态（HZERO平台Token表）
  SELECT U.LOGIN_NAME AS 登录名, T.TOKEN, T.EXPIRE_TIME AS 过期时间,
         T.LAST_CLIENT_TIME AS 最后活跃时间
  FROM HZERO.OAUTH_ACCESS_TOKEN T
    JOIN HZERO.IAM_USER U ON T.USER_ID = U.ID
  WHERE U.LOGIN_NAME = :loginName
  ORDER BY T.EXPIRE_TIME DESC;
  ```

### 常见问题

- 问题1：推广等级被产品引用后能否删除？
  - 原因：本菜单不提供删除按钮，只提供失效操作。失效后产品推广等级重置为C
  - 解决思路：使用"行内失效"或"批量失效"按钮将状态置为invalid

- 问题2：同一产品能否有多个有效推广等级？
  - 原因：后端saveData方法自动处理唯一性，新增有效记录时自动将旧的有效记录失效
  - 解决思路：无需手动处理，系统自动保证同一产品同一时间只有一个有效推广等级

- 问题3：推广等级和推广等级要求配置的关系？
  - 原因：推广等级维护定义产品具体归属的等级（A/B/C等），推广等级要求配置（prodPromoteGradesControls）定义达到某等级需满足的指标条件
  - 解决思路：两者配合使用，要求配置评估产品指标后自动判定等级，本菜单可手动指定等级

- 问题4：失效后产品的推广等级是什么？
  - 原因：后端saveData方法中，status=invalid时将LNK_PROD.PROD_PROMOTE_GRADE重置为C
  - 解决思路：失效后产品推广等级自动回归默认值C
