## 重点逻辑

### 重点逻辑1：多维度发票查询 {查询检索}

- **业务意义**：支持按项目、合同、经销商、发票号码等多维度检索金税发票信息，满足对账与税务核对需求

- **具体逻辑描述**

  - 第1点：支持按项目编码/名称查询项目列表，定位目标项目

  - 第2点：在项目基础上按合同、经销商、发票号码组合检索发票核销记录

  - 第3点：查询结果展示发票号码、类型、开票日期、含税金额、税率及税金与未含税金额

### 重点逻辑2：税金实时折算 {税务计算}

- **业务意义**：税金与未含税金额为运行时计算值，不落库，确保展示数据始终准确

- **具体逻辑描述**

  - 第1点：专票税率非零，普票税率为零

  - 第2点：税金按含税金额与税率实时折算：未含税金额=含税金额/(1+税率)，税金=含税金额-未含税金额

### 重点逻辑3：出库单与发票核对 {核对验证}

- **业务意义**：验证发票与出库单的匹配关系，确保核销准确性

- **具体逻辑描述**

  - 第1点：通过invoice-truth/detail接口查看出库单与发票核对明细

  - 第2点：支持查询出库单列表(invoutlist)和发票信息(invoice-info)进行交叉核对

### 报错一览表

| 报错信息 | 提示节点 | 根因与解决方案 | 等级 | 详细逻辑 |

#### 报错1：查询无数据
- **触发条件**：用户在列表页输入查询条件（项目/合同/经销商/发票号码）点击查询，返回结果集为空
- **逻辑分析**：查询接口invoice-truth/list基于EPM_INVOICE_TRUTH_HEADER表过滤，要求HZ_APPROVE_STATUS='APPROVED'（H0流程审批通过）。无数据的根因有三类：(1)查询条件过窄，多条件AND过滤导致空集；(2)上游发票真实性核销流程尚未审批通过，HZ_APPROVE_STATUS仍为RUN或NEW；(3)INVOICE_VERIFER_NO（核销单号）与查询的发票号码不匹配。需逐一放宽条件确认是数据缺失还是条件过滤问题
- **排查SQL**：
  ```sql
  SELECT INVOICE_TRUTH_NO, PROJECT_CODE, CUSTOMER_CODE, INVOICE_VERIFER_NO,
         HZ_APPROVE_STATUS, AUDIT_STAT, CREATE_TIME
  FROM EPM_INVOICE_TRUTH_HEADER
  WHERE ORGANIZATION_ID = #{organizationId}
    AND (PROJECT_CODE = #{projectCode} OR #{projectCode} IS NULL)
    AND (CUSTOMER_CODE = #{customerCode} OR #{customerCode} IS NULL)
    AND (INVOICE_VERIFER_NO = #{invoiceNo} OR #{invoiceNo} IS NULL)
  ORDER BY CREATE_TIME DESC;
  ```

#### 报错2：项目不存在
- **触发条件**：用户在项目选择弹窗中输入项目编码或名称模糊查询，弹窗返回空列表
- **逻辑分析**：项目选择弹窗调用search-project接口查询EPM_PROJECT表，按PROJECT_CODE/PROJECT_NAME模糊匹配并受当前用户数据权限控制。根因有二：(1)用户输入的项目编码/名称拼写错误，LIKE '%xxx%'无法匹配；(2)当前用户对该项目无数据权限（权限组未分配），导致权限过滤后为空。需核对EPM_PROJECT是否存在该项目及用户权限配置
- **排查SQL**：
  ```sql
  SELECT PROJECT_ID, PROJECT_CODE, PROJECT_NAME, ENABLED
  FROM EPM_PROJECT
  WHERE ORGANIZATION_ID = #{organizationId}
    AND (PROJECT_CODE LIKE '%' || #{keyword} || '%' OR PROJECT_NAME LIKE '%' || #{keyword} || '%');
  ```

#### 报错3：交易公司不存在
- **触发条件**：用户在交易公司选择弹窗中根据经销商查询交易公司，弹窗返回空列表
- **逻辑分析**：交易公司选择弹窗调用do-search-trading-company接口，按CUSTOMER_CODE查询EPM_TRADING_COMPANY关联表。根因有三：(1)所选经销商编码在交易公司关联表中无记录，经销商主数据未维护交易公司关联；(2)经销商编码CUSTOMER_CODE拼写错误或与EPM_INVOICE_TRUTH_HEADER.CUSTOMER_CODE不一致；(3)交易公司关联表EPM_TRADING_COMPANY中TRADING_COMPANY_ID被禁用（ENABLED=0）。需先在经销商主数据中维护交易公司关联
- **排查SQL**：
  ```sql
  SELECT TC.TRADING_COMPANY_ID, TC.TRADING_COMPANY_CODE, TC.TRADING_COMPANY_NAME, TC.ENABLED
  FROM EPM_TRADING_COMPANY TC
  WHERE TC.CUSTOMER_CODE = #{customerCode};
  ```

#### 报错4：发票明细不存在
- **触发条件**：用户在列表页选中一条核销记录点击"查看明细"，明细页返回空或抛出记录不存在
- **逻辑分析**：查看明细调用invoice-truth/detail/{invoiceTruthId}接口，按INVOICE_TRUTH_ID查询EPM_INVOICE_TRUTH_HEADER头表和EPM_INVOICE_TRUTH_LINE行表。根因有三：(1)并发场景下他人已删除该核销单，头表记录不存在；(2)核销单头表存在但行表EPM_INVOICE_TRUTH_LINE无关联明细（INVOICE_TRUTH_ID外键失效或行数据未生成）；(3)传入的invoiceTruthId参数格式错误或为null。需核对头行表数据一致性
- **排查SQL**：
  ```sql
  SELECT H.INVOICE_TRUTH_ID, H.INVOICE_TRUTH_NO, H.AUDIT_STAT,
         (SELECT COUNT(1) FROM EPM_INVOICE_TRUTH_LINE L WHERE L.INVOICE_TRUTH_ID = H.INVOICE_TRUTH_ID) AS 行明细数
  FROM EPM_INVOICE_TRUTH_HEADER H
  WHERE H.INVOICE_TRUTH_ID = #{invoiceTruthId};
  ```

#### 报错5：网络请求失败
- **触发条件**：用户点击查询或查看明细，前端axios请求抛出网络异常或超时
- **逻辑分析**：前端调用/v1/{organizationId}/epm-invoice-truth-headers/invoice-truth/list等接口时，因后端ae-business服务不可用、网关路由异常、网络中断或请求超时导致连接失败。根因有四：(1)ae-business微服务未注册到Nacos或已宕机；(2)网关路由配置错误找不到服务；(3)网络中断或防火墙拦截；(4)SQL执行超时（EPM_INVOICE_TRUTH_HEADER数据量大且未走索引）。需联系运维确认服务状态及网络连通性
- **排查SQL**：
  ```sql
  -- 核查核销头表数据量是否异常增长导致查询超时
  SELECT COUNT(1) AS 核销单总数, MAX(CREATE_TIME) AS 最新创建时间
  FROM EPM_INVOICE_TRUTH_HEADER
  WHERE ORGANIZATION_ID = #{organizationId};
  ```

#### 报错6：权限不足
- **触发条件**：用户访问客户金税发票号码查询页面或调用接口时，返回403或"无权限访问"提示
- **逻辑分析**：后端Controller使用@Permission(level = ResourceLevel.ORGANIZATION, permissionLogin = true)控制访问权限，要求用户登录且拥有当前组织（organizationId）的访问权限。根因有三：(1)用户未分配该菜单（hlod页面）的访问角色；(2)用户当前切换的组织不在其授权组织范围内；(3)用户数据权限组未覆盖查询的项目/经销商数据。需联系管理员分配菜单角色和数据权限
- **排查SQL**：
  ```sql
  -- 核查用户在当前组织下的角色分配（表名以HZERO IAM实际表为准）
  SELECT USER_ID, ROLE_ID, ORGANIZATION_ID
  FROM IAM_USER_ROLE
  WHERE USER_ID = #{userId} AND ORGANIZATION_ID = #{organizationId};
  ```

### 常见问题

- 问题1：查询结果中税金为0
  - 原因：该发票为普票（税率为0），或发票含税金额/税率配置有误
  - 解决思路：检查发票类型，普票税率为0属正常；专票检查税率配置

- 问题2：发票号码查询无数据
  - 原因：EPM_INVOICE_TRUTH_HEADER中无匹配记录，或核销流程尚未审批通过
  - 解决思路：检查SQL `SELECT * FROM EPM_INVOICE_TRUTH_HEADER WHERE INVOICE_VERIFER_NO = #{发票号码} AND HZ_APPROVE_STATUS = 'APPROVED'`
