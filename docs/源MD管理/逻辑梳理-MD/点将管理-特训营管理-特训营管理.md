# 点将管理-特训营管理-特训营管理

> 后端代码位于 mbo-business 微服务（源码未包含在当前源码目录下），前端 API 路径前缀 `mlt/trainCamp/*`。本菜单为特训营基础信息管理，创建和维护特训营活动。

## 业务流程

### 业务流程图

```
特训营管理(本页面)
        |
        ├──→ 新建 ──→ 跳转详情页(/detail/null/add)
        ├──→ 编辑 ──→ 校验状态为draft ──→ 跳转详情页(/detail/{id}/edit)
        ├──→ 删除 ──→ 确认弹窗 ──→ 调用batchDelData接口
        ├──→ 生效/失效 ──→ 确认弹窗 ──→ 调用batchValidData接口
        ├──→ 查看详情 ──→ 跳转详情页
        └──→ 报名截止 ──→ 弹窗选择报名结束时间 ──→ 调用signEnd接口
              (行操作，需状态valid且计划开始时间>当前时间)
```

### 上游依赖

| 上游模块 | 依赖类型 | 依赖说明 | 依赖成立条件 |
|---------|---------|---------|-------------|
| HZERO权限服务 | permissionList权限编码 | 提供按钮权限校验 | 用户已分配对应权限编码 |
| HZERO值集服务 | lookupCode值集编码 | 提供特训营类型、状态值集 | 值集已发布且有效 |
| 讲师档案 | 关联查询 | 计师列表选择 | 调用 maLecturerPage 接口 |
| 门店主档 | 关联查询 | 门店分页/列表选择 | 调用 mktterminalPage/mktterminalList 接口 |

### 下游影响

- **特训营详情页**：新建/编辑跳转，openTab 新标签页打开。
- **经销商特训营点将**：特训营生效后经销商可报名点将，数据库关联。
- **特训营点将管理**：特训营作为点将申请的基础数据，数据库关联。
- **特训营点将执行**：特训营作为执行跟踪的基础数据，数据库关联。

## 重点逻辑

### 重点逻辑1：编辑状态校验

- **业务意义**：限制仅草稿状态可编辑，保证生效数据稳定性。
- **具体逻辑描述**：
  - 点击"编辑"按钮时校验特训营状态。
  - 状态必须为 `draft`（草稿），否则提示"当前状态数据无法编辑！"。
  - 校验通过跳转编辑详情页 `/detail/{specialTrainCampId}/edit`。

### 重点逻辑2：报名截止逻辑

- **业务意义**：控制报名截止时机，避免开课后仍可报名。
- **具体逻辑描述**：
  - 报名截止为行操作按钮，显示条件：
    1. `status === 'valid'`（特训营已生效）
    2. `new Date(planStartTime) > new Date()`（计划开始时间晚于当前时间）
  - 点击后弹窗选择报名结束时间。
  - 提交调用 `signEnd` 接口，参数 `campCode` 和 `campsignEndTimeCode`（格式 `YYYY-MM-DD`）。

### 重点逻辑3：生效/失效逻辑

- **业务意义**：批量控制特训营状态，生效后经销商可报名点将。
- **具体逻辑描述**：
  - 生效/失效操作支持批量（多选）。
  - 调用 `batchValidData` 接口，参数：`specialTrainCampId` 数组、`status`（valid/invalid）。
  - 接口返回 `res.data` 非空时表示错误信息，`res.message` 为成功信息。
  - 成功后刷新当前页列表。

### 重点逻辑4：特训营时间展示

- **业务意义**：直观展示特训营计划时间范围，便于掌握培训周期。
- **具体逻辑描述**：
  - 列表"特训营时间"列通过 renderer 渲染。
  - 展示 `planStartTime` 至 `planEndTime` 的时间范围。

### 重点逻辑5：删除逻辑

- **业务意义**：批量删除草稿数据，避免脏数据堆积。
- **具体逻辑描述**：
  - 删除操作支持批量（多选）。
  - 调用 `batchDelData` 接口，参数：`specialTrainCampId` 数组。
  - 确认弹窗后执行删除。

### 详情页保存校验逻辑

- **基础信息校验**：baseFormDS.validate() 校验所有必填字段。
- **讲师列表校验**(validateLectorerList)：
  1. 讲师列表不能为空。
  2. 每位讲师开始日期不能为空。
  3. 每位讲师结束日期不能为空。
  4. 讲师开始日期不能大于结束日期。
  5. 讲师开始日期不能小于特训营开始日期。
  6. 讲师结束日期不能大于特训营结束日期。
  7. 讲师介绍不能为空。
- **联动逻辑**：
  - 特训营类型(campType)或负责事业部(division)变更时，联动查询收费标准(priceDS)，参数 divisionCode + lecturerType(=campType)，并清空已选收费标准。
  - 特训营类型为 region 时显示"所属运营中心"字段且必填。

### 保存校验

- 校验1：编辑状态校验 —— 保证生效数据稳定性
  - **详细逻辑**：编辑时校验状态必须为 `draft`，否则提示"当前状态数据无法编辑！"。
  - **系统体现**：前端状态校验，后端二次校验。
  - **排查SQL**：
    ```sql
    SELECT tc.CAMP_CODE AS 特训营编码, tc.CAMP_NAME AS 特训营名称, tc.STATUS AS 状态
    FROM TRAIN_CAMP tc
    WHERE tc.STATUS <> 'draft';
    ```

### 提交校验

- 校验1：报名结束时间必填 —— 确保报名截止时间有效
  - **详细逻辑**：报名截止提交时校验 `campsignEndTimeCode` 必填。
  - **系统体现**：前端弹窗校验，后端二次校验。
  - **排查SQL**：
    ```sql
    SELECT tc.CAMP_CODE AS 特训营编码, tc.CAMPSIGN_END_TIME AS 报名结束时间
    FROM TRAIN_CAMP tc
    WHERE tc.STATUS = 'valid'
      AND tc.PLAN_START_TIME > SYSDATE
      AND tc.CAMPSIGN_END_TIME IS NULL;
    ```

### 状态机

```
草稿 ──生效──→ 生效 ──失效──→ 失效
```

| 当前状态 | 触发动作 | 目标状态 |
|---------|---------|---------|
| 草稿 | 生效(batchValidData) | 生效 |
| 生效 | 失效(batchValidData) | 失效 |

### 排查SQL

```sql
-- 查询特训营列表
SELECT
  tc.CAMP_CODE      AS 特训营编码,
  tc.CAMP_NAME      AS 特训营名称,
  tc.LECTURER       AS 讲师姓名,
  TO_CHAR(tc.PLAN_START_TIME, 'YYYY-MM-DD') AS 开始时间,
  TO_CHAR(tc.PLAN_END_TIME, 'YYYY-MM-DD') AS 结束时间,
  TO_CHAR(tc.CAMPSIGN_END_TIME, 'YYYY-MM-DD') AS 报名结束时间,
  tc.STATUS         AS 状态,
  TO_CHAR(tc.CREATION_DATE, 'YYYY-MM-DD HH24:MI:SS') AS 创建时间
FROM TRAIN_CAMP tc
ORDER BY tc.CREATION_DATE DESC;

-- 查询可报名截止的特训营（生效且未开始）
SELECT
  tc.CAMP_CODE      AS 特训营编码,
  tc.CAMP_NAME      AS 特训营名称,
  TO_CHAR(tc.PLAN_START_TIME, 'YYYY-MM-DD') AS 计划开始时间,
  TO_CHAR(tc.CAMPSIGN_END_TIME, 'YYYY-MM-DD') AS 报名截止时间
FROM TRAIN_CAMP tc
WHERE tc.STATUS = 'valid'
  AND tc.PLAN_START_TIME > SYSDATE
  AND tc.CAMPSIGN_END_TIME IS NULL;

-- 查询已生效的特训营
SELECT
  tc.CAMP_CODE      AS 特训营编码,
  tc.CAMP_NAME      AS 特训营名称,
  tc.LECTURER       AS 讲师姓名,
  tc.STATUS         AS 状态
FROM TRAIN_CAMP tc
WHERE tc.STATUS = 'valid'
ORDER BY tc.PLAN_START_TIME DESC;
```

### 报错一览表

| 请选择报名结束时间 | 报名截止提交 | 未选择时间；选择报名结束时间后提交 | 普通 | 前端 campsignEndTimeCode 必填校验 |

| 报名结束时间必须晚于当前时间 | 报名截止提交 | 报名结束时间早于当前时间，重新选择时间 | error | 后端校验 CAMPSIGN_END_TIME > SYSDATE |

#### 报错1：请选择一条数据
- **触发条件**：点击编辑按钮时，未选择数据或选择了多行
- **逻辑分析**：前端在执行编辑操作前校验选中行数量，若 selectedRows.length ≠ 1 则阻止操作并提示"请选择一条数据"。编辑操作需要明确的目标特训营，未选择时无法确定操作对象，多选时操作对象不唯一
- **排查SQL**：
  ```sql
  SELECT CAMP_CODE AS 特训营编码,
         CAMP_NAME AS 特训营名称,
         STATUS AS 状态
  FROM TRAIN_CAMP
  ORDER BY CREATION_DATE DESC;
  ```

#### 报错2：请选择至少一条数据
- **触发条件**：点击删除或生效/失效按钮时，未选择任何数据
- **逻辑分析**：前端在执行批量操作前校验选中行数量，若 selectedRows.length < 1 则阻止操作并提示"请选择至少一条数据"。删除和生效/失效支持批量操作，但至少需要一条目标数据
- **排查SQL**：
  ```sql
  SELECT CAMP_CODE AS 特训营编码,
         CAMP_NAME AS 特训营名称,
         STATUS AS 状态
  FROM TRAIN_CAMP
  WHERE STATUS IN ('draft', 'valid', 'invalid');
  ```

#### 报错3：当前状态数据无法编辑！
- **触发条件**：点击编辑按钮时，特训营状态不为 draft（草稿）
- **逻辑分析**：前端校验 STATUS = 'draft'，仅草稿状态的特训营允许编辑。生效（valid）或失效（invalid）状态的特训营已被经销商报名点将引用，编辑可能影响已发起的点将申请数据一致性，故限制编辑。校验不通过提示"当前状态数据无法编辑！"
- **排查SQL**：
  ```sql
  SELECT CAMP_CODE AS 特训营编码,
         CAMP_NAME AS 特训营名称,
         STATUS AS 状态,
         TO_CHAR(LAST_UPDATE_DATE,'YYYY-MM-DD HH24:MI:SS') AS 最后更新时间
  FROM TRAIN_CAMP
  WHERE STATUS <> 'draft';
  ```

#### 报错4：请选择报名结束时间
- **触发条件**：报名截止提交时，campsignEndTimeCode 字段为空
- **逻辑分析**：前端报名截止弹窗对 campsignEndTimeCode 字段配置 required 校验，提交前校验报名结束时间是否选择，为空则阻止提交并提示"请选择报名结束时间"。报名结束时间用于控制经销商报名截止时机，必须明确指定
- **排查SQL**：
  ```sql
  SELECT CAMP_CODE AS 特训营编码,
         CAMP_NAME AS 特训营名称,
         TO_CHAR(PLAN_START_TIME,'YYYY-MM-DD') AS 计划开始时间,
         TO_CHAR(CAMPSIGN_END_TIME,'YYYY-MM-DD') AS 报名结束时间
  FROM TRAIN_CAMP
  WHERE STATUS = 'valid'
    AND PLAN_START_TIME > SYSDATE
    AND CAMPSIGN_END_TIME IS NULL;
  ```

#### 报错5：请求失败
- **触发条件**：调用 mlt/trainCamp/* 系列接口时，后端返回 HTTP 状态码非 2xx
- **逻辑分析**：前端通过 axios 调用后端接口，若响应状态码非 2xx 或网络异常则触发错误回调，统一提示"请求失败"。常见根因包括：mbo-business 微服务未启动或异常、数据库连接失败、SQL 执行超时、后端业务异常未捕获（如生效时存在关联点将申请不允许失效）、网络中断等。需检查 mbo-business 微服务运行状态、数据库连接池、后端日志定位具体异常堆栈
- **排查SQL**：
  ```sql
  SELECT CAMP_CODE AS 特训营编码,
         CAMP_NAME AS 特训营名称,
         STATUS AS 状态,
         TO_CHAR(LAST_UPDATE_DATE,'YYYY-MM-DD HH24:MI:SS') AS 最后更新时间,
         LAST_UPDATED_BY AS 最后更新人
  FROM TRAIN_CAMP
  WHERE LAST_UPDATE_DATE >= SYSDATE - 1
  ORDER BY LAST_UPDATE_DATE DESC;
  ```

#### 报错6：网络异常/接口超时
- **触发条件**：任意接口调用时，网络中断或接口响应超过 axios timeout 配置
- **逻辑分析**：前端 axios 请求未收到响应或响应超时，触发 catch 回调统一提示"请求失败"。常见根因：网络中断、mbo-business 服务假死、数据库慢查询等。需检查网络连通性、后端服务负载、数据库性能
- **排查SQL**：
  ```sql
  SELECT CAMP_CODE AS 特训营编码, CAMP_NAME AS 特训营名称, STATUS AS 状态,
         TO_CHAR(LAST_UPDATE_DATE,'YYYY-MM-DD HH24:MI:SS') AS 最后更新时间
  FROM TRAIN_CAMP
  WHERE LAST_UPDATE_DATE >= SYSDATE - 1
  ORDER BY LAST_UPDATE_DATE DESC;
  ```

#### 报错7：权限不足
- **触发条件**：点击新建、编辑、删除、生效/失效、报名截止等按钮时，当前用户无对应 permissionList 权限码
- **逻辑分析**：前端 Button 组件通过 permissionList 配置权限码，HZERO 框架校验当前用户角色是否包含该权限码，未包含则按钮不可见或禁用。若强制调用接口，后端也会校验权限返回403。需联系管理员配置对应角色权限
- **排查SQL**：
  ```sql
  SELECT U.USER_NAME AS 用户名, R.ROLE_NAME AS 角色名, P.PERMISSION_CODE AS 权限码
  FROM SYS_USER U
  LEFT JOIN SYS_USER_ROLE UR ON U.USER_ID = UR.USER_ID
  LEFT JOIN SYS_ROLE R ON UR.ROLE_ID = R.ROLE_ID
  LEFT JOIN SYS_ROLE_PERMISSION RP ON R.ROLE_ID = RP.ROLE_ID
  LEFT JOIN SYS_PERMISSION P ON RP.PERMISSION_ID = P.PERMISSION_ID
  WHERE P.PERMISSION_CODE LIKE '%train_camp%' ORDER BY U.USER_NAME;
  ```

#### 报错8：数据不存在
- **触发条件**：编辑、删除、生效/失效等操作时，接口返回数据为空或特训营编码不存在
- **逻辑分析**：前端通过 campCode 调用详情接口，后端查询 TRAIN_CAMP 表无对应记录或记录已逻辑删除，返回空数据。常见根因：特训营编码错误、特训营已被删除、跨租户查询、数据权限隔离等。需检查 CAMP_CODE 有效性及数据权限
- **排查SQL**：
  ```sql
  SELECT CAMP_CODE AS 特训营编码, CAMP_NAME AS 特训营名称,
         STATUS AS 状态, DELETE_FLAG AS 删除标记
  FROM TRAIN_CAMP
  WHERE DELETE_FLAG = 'Y' OR CAMP_CODE IS NULL;
  ```

#### 报错9：状态不允许操作
- **触发条件**：点击生效/失效按钮时，特训营状态不允许该操作
- **逻辑分析**：后端校验状态机，如已生效不可再生效、已失效不可再失效、草稿不可直接失效等。状态不匹配时后端返回业务异常。需检查特训营当前状态及操作流程
- **排查SQL**：
  ```sql
  SELECT CAMP_CODE AS 特训营编码, CAMP_NAME AS 特训营名称,
         STATUS AS 状态, ERROR_INFO AS 异常问题
  FROM TRAIN_CAMP
  WHERE STATUS NOT IN ('draft','valid','invalid')
  ORDER BY CREATE_DATE DESC;
  ```

#### 报错10：值集数据不显示
- **触发条件**：查询条件或列表中特训营状态下拉选项为空
- **逻辑分析**：前端通过 lookupCode 查询值集 MBO.TRAIN_CAMP_STATUS 等，值集未配置或未启用则下拉选项为空。需在值集管理页面配置对应值集
- **排查SQL**：
  ```sql
  SELECT LOOKUP_CODE AS 值集编码, LOOKUP_VALUE_CODE AS 值编码,
         LOOKUP_VALUE_NAME AS 值名称, ENABLE_FLAG AS 启用标记
  FROM SYS_LOOKUP_VALUE
  WHERE LOOKUP_CODE IN ('MBO.TRAIN_CAMP_STATUS','MBO.CAMP_TYPE')
    AND ENABLE_FLAG = 'N' ORDER BY LOOKUP_CODE;
  ```

#### 报错11：特训营编码已存在
- **触发条件**：新建特训营保存时，CAMP_CODE 已存在于 TRAIN_CAMP 表
- **逻辑分析**：后端校验 CAMP_CODE 唯一性，若已存在则返回业务异常。需更换特训营编码后保存
- **排查SQL**：
  ```sql
  SELECT CAMP_CODE AS 特训营编码, COUNT(*) AS 重复数
  FROM TRAIN_CAMP
  WHERE DELETE_FLAG = 'N'
  GROUP BY CAMP_CODE
  HAVING COUNT(*) > 1;
  ```

#### 报错12：报名结束时间必须晚于当前时间
- **触发条件**：报名截止提交时，CAMPSIGN_END_TIME <= SYSDATE
- **逻辑分析**：后端校验报名结束时间必须晚于当前时间，否则经销商无法报名。需重新选择报名结束时间
- **排查SQL**：
  ```sql
  SELECT CAMP_CODE AS 特训营编码, CAMP_NAME AS 特训营名称,
         TO_CHAR(CAMPSIGN_END_TIME,'YYYY-MM-DD') AS 报名结束时间,
         TO_CHAR(SYSDATE,'YYYY-MM-DD') AS 当前时间
  FROM TRAIN_CAMP
  WHERE CAMPSIGN_END_TIME IS NOT NULL AND CAMPSIGN_END_TIME <= SYSDATE;
  ```

### 常见问题

**Q1：报名截止按钮不显示？**
A：检查特训营状态是否为 `valid`，计划开始时间是否晚于当前时间。

**Q2：编辑按钮提示无法编辑？**
A：确认特训营状态为 `draft`，非草稿状态不可编辑。

**Q3：生效/失效返回错误信息？**
A：检查接口返回 `res.data` 内容，可能有业务校验不通过。

| 问题 | 排查方式 |
|------|---------|
| 报名截止按钮不显示 | 检查 STATUS 是否为 valid，PLAN_START_TIME 是否晚于当前时间 |
| 编辑按钮提示无法编辑 | 确认 STATUS 为 draft，非草稿状态不可编辑 |
| 生效/失效返回错误信息 | 检查接口返回 res.data 内容，可能有业务校验不通过 |
