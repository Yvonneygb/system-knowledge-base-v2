# 工程管理-项目交付-工程要货订单

---

## 业务流程

### 业务流程图

```text
经销商/内部用户创建工程要货订单
    │
    ├── 选择客户（经销商）→ 选择交易公司 → 选择折扣单号
    │       ├── 折扣单号带出：折扣类型、折扣率、项目信息、合同信息、收货信息
    │       └── 自动加载折扣单产品明细到订单行
    │
    ├── 填写期望到达日期 → 自动判断订单类型（常规/计划）
    │       ├── 当月≤25号：期望日期为本月→常规订单；非本月→计划订单
    │       └── 当月>25号：仅瓷砖产品线可下常规订单，其余按计划订单规则
    │
    ├── 维护产品明细行（数量、紧急标记等）
    │       ├── 校验SM状态（Z8禁止下单、Z6计划淘汰、S6售后阶段、Z7库存发完即止）
    │       └── 紧急行数校验：仅计划订单可加紧急，每5行产品最多1行紧急
    │
    ├── 保存订单（POST /sa-out-bill-heads）
    │       ├── 保存前校验：地址、必填项
    │       ├── 保存头信息 → 保存行信息 → 保存附件
    │       ├── 扣减/返还可下单数量
    │       └── 保存后更新订单头折扣率=订单行最低审批折扣
    │
    ├── 生成CRM订单（POST /do-check-create-crm-order）
    │       ├── 校验地址信息完整性
    │       ├── 校验折扣单未过期
    │       ├── 校验开票单位有效性
    │       ├── 校验合同状态（非变更中、非已审批）
    │       ├── 校验产品下单数量未超过合同
    │       ├── 校验SM状态
    │       └── 推送CRM生成正式销售订单
    │
    └── 申请不扣订金（POST /do-application-oa）
            ├── 校验SM状态
            ├── 校验期望到达日期不晚于政策有效期
            └── 送签OA审批
```

### 下游影响

- 影响1：生成CRM销售订单
  - 审批通过后推送CRM创建正式销售订单，回写要货单号

- 影响2：推送ERP发货
  - CRM订单生成后推送ERP执行发货流程

- 影响3：占用客户可发货余额
  - 审批通过后CRM回写定金金额，占用客户可发货余额

- 影响4：扣减折扣单可下单数量
  - 保存订单时扣减折扣单/合同的可下单数量；修改/删除时返还

## 重点逻辑

### 重点逻辑1：期望到达日期自动赋值订单类型

- **业务意义**：根据当前日期和期望到达日期自动判断订单类型，控制常规订单和计划订单的下单规则

- **具体逻辑描述**

  - 第1点：当日≤25号时，期望日期为本月→常规订单(billType=1)，非本月→计划订单(billType=2)

  - 第2点：当日>25号时，仅瓷砖产品线(orderPdtLine=2)可下常规订单，非瓷砖产品线期望日期为次月→常规订单，超过次月→计划订单

  - 第3点：海外事业部(organizationId=111)且二级类目为"境外注册出口经销商"时，常规订单=13，计划订单=14，业务类型=17

  - 第4点：电商渠道(channel=2)计划订单期望日期限当月往后6个月内，常规订单限7个月内；非电商渠道计划订单限3个月内，常规订单限4个月内

### 重点逻辑2：可下单数量扣减/返还

- **业务意义**：保存订单时扣减折扣单/合同的可下单数量，防止超量下单；修改/删除时返还

- **具体逻辑描述**

  - 第1点：保存前若为已有订单，先返还可下单数量(updateActiveQty, false)

  - 第2点：保存后扣减可下单数量(updateActiveQty, true)

  - 第3点：例外：家装订单且合同类型=1且orderQtyCtrlType=2且priceType=1时跳过扣减

### 重点逻辑3：折扣率回写

- **业务意义**：保存后取订单行最低审批折扣回写到订单头，确保头表折扣率为最优惠值

- **具体逻辑描述**

  - 第1点：保存后取所有订单行中最低的EXTRA_DISCOUNT_RATE(审批折扣)

  - 第2点：回写到订单头DISCOUNT_RATE字段

### 重点逻辑4：SM状态校验

- **业务意义**：生成CRM订单前校验产品SM生命状态，防止已停产产品下单

- **具体逻辑描述**

  - 第1点：Z8状态产品禁止下单，阻断报错

  - 第2点：Z6状态产品计划淘汰中，提示关注，确认后可继续

  - 第3点：S6状态产品进入售后阶段，提示关注，确认后可继续

  - 第4点：Z7状态产品有库存数量，发完即止，提示关注，确认后可继续

### 重点逻辑5：紧急行数限制

- **业务意义**：控制紧急订单数量，防止滥用紧急通道

- **具体逻辑描述**

  - 第1点：仅计划订单(billType=2/14)可加紧急，常规订单(billType=1/13)有紧急行则报错

  - 第2点：紧急行数≤CEIL(产品行数/5)，即每5行产品最多1行紧急

### 重点逻辑6：生成CRM订单校验链

- **业务意义**：生成CRM订单前执行完整校验链，确保数据完整性和业务合规性

- **具体逻辑描述**

  - 第1点：校验地址信息完整性（省/市/县非空）

  - 第2点：校验折扣单未过期（discountValidDate+1天 > 当前时间）

  - 第3点：校验开票单位有效性(checkBill)

  - 第4点：校验合同非变更中、非已审批

  - 第5点：校验产品下单数量未超过合同(doCheckBillQty)

  - 第6点：校验SM状态

### 重点逻辑7：不扣订金OA审批

- **业务意义**：特殊情形可走OA申请免扣定金，审批后标记生效

- **具体逻辑描述**

  - 第1点：仅常规订单(billType=1/13)且无要货单号时可申请

  - 第2点：填写申请原因后送签OA审批

  - 第3点：OA审批通过后更新nodepositOaAuditStat

### 重点逻辑8：经销商登录自动带出客户

- **业务意义**：经销商登录时自动带出客户信息，简化操作

- **具体逻辑描述**

  - 第1点：用户类型为D（经销商）时自动查询并带出客户信息、收货地址

  - 第2点：经销商登录时客户字段不可编辑

### 重点逻辑9：工程意向单模式

- **业务意义**：意向单模式支持先关联合同再生成CRM订单，适用于无折扣单的场景

- **具体逻辑描述**

  - 第1点：projectIntention=2时走意向单流程，价格类型=3(价目表)，需关联合同

  - 第2点：非意向单时价格类型=1(折扣单)

  - 第3点：意向单有关联合同时校验产品数量未超合同，无关联合同时直接生成CRM

**列表查询SQL（selectList）：**

```sql
SELECT edp.discount_policy_code, edp.discount_policy_name, edp.effective_date_end,
       c.customer_code, c.customer_name, c.short_name, co.currency,
       ca.address1 AS customer_address, SOBH.*
FROM sa_out_bill_head SOBH
  LEFT JOIN epm_discount_policy edp ON SOBH.discount_policy_id = edp.discount_policy_id
  LEFT JOIN customer_org co ON SOBH.customer_id = co.customer_id
  LEFT JOIN customer c ON co.customer_id = c.customer_id
  LEFT JOIN customer_address ca ON SOBH.customer_address_id = ca.customer_address_id
WHERE SOBH.search_flag = 1
```

### 保存校验

- 校验1：期望到达日期不能为空 —— 确保填写了期望到达日期

  - 详细逻辑

    - 第1点：检查inDate不为空

  - 系统体现：阻断性报错

  - 排查SQL：

    ```sql
    SELECT IN_DATE FROM SA_OUT_BILL_HEAD WHERE SA_OUT_BILL_HEAD_ID = :id
    ```

- 校验2：期望到达日期不超过限制范围 —— 确保日期在允许范围内

  - 详细逻辑

    - 第1点：期望日期不能超过一年
    - 第2点：电商渠道计划订单限当月往后6个月内，常规订单限7个月内
    - 第3点：非电商渠道计划订单限3个月内，常规订单限4个月内

  - 系统体现：阻断性报错

  - 排查SQL：

    ```sql
    SELECT IN_DATE, BILL_TYPE, CHANNEL FROM SA_OUT_BILL_HEAD WHERE SA_OUT_BILL_HEAD_ID = :id
    ```

- 校验3：产品行不能为空 —— 确保至少有一条产品明细

  - 详细逻辑

    - 第1点：检查产品明细行列表不为空

  - 系统体现：阻断性报错

  - 排查SQL：

    ```sql
    SELECT COUNT(*) FROM SA_OUT_BILL_LINE WHERE SA_OUT_BILL_HEAD_ID = :id
    ```

- 校验4：仅计划订单允许加紧急 —— 确保常规订单无紧急行

  - 详细逻辑

    - 第1点：billType=1/13(常规)时，不应存在URGENCY=2的行

  - 系统体现：阻断性报错

  - 排查SQL：

    ```sql
    SELECT COUNT(*) FROM SA_OUT_BILL_LINE
    WHERE SA_OUT_BILL_HEAD_ID = :id AND URGENCY = 2
    ```

- 校验5：紧急行数不超过限制 —— 确保紧急行数合规

  - 详细逻辑

    - 第1点：紧急行数≤CEIL(产品行数/5)

  - 系统体现：阻断性报错

  - 排查SQL：

    ```sql
    SELECT COUNT(*) AS TOTAL_ROWS,
           SUM(CASE WHEN URGENCY = 2 THEN 1 ELSE 0 END) AS URGENT_ROWS
    FROM SA_OUT_BILL_LINE WHERE SA_OUT_BILL_HEAD_ID = :id
    ```

- 校验6：可下单数量充足 —— 确保不超过政策可下单数量

  - 详细逻辑

    - 第1点：检查各产品行下单数量不超过折扣单可下单数量

  - 系统体现：阻断性报错

  - 排查SQL：

    ```sql
    SELECT LINE.QTY_BILL, LINE.ACTIVE_QTY
    FROM SA_OUT_BILL_LINE LINE
    WHERE LINE.SA_OUT_BILL_HEAD_ID = :id AND LINE.QTY_BILL > LINE.ACTIVE_QTY
    ```

- 校验7：SM状态Z8不允许下单 —— 确保产品未停产

  - 详细逻辑

    - 第1点：检查产品SM状态不为Z8

  - 系统体现：阻断性报错

  - 排查SQL：

    ```sql
    SELECT ITEM_CODE, SM_STATE FROM SA_OUT_BILL_LINE
    WHERE SA_OUT_BILL_HEAD_ID = :id AND SM_STATE = 'Z8'
    ```

### 状态机

#### 状态机流转图

```text
NEW(新建) ──保存并提交──→ RUN(审批中) ──审批通过──→ APPROVED(已审批) → 生成CRM订单 → 推送ERP发货
  ↑                         │
  │                         ├──审批拒绝──→ REJECTED(已拒绝) ──修改后保存并提交──→ RUN
  │                         ├──审批驳回──→ REBUT(已驳回)
  │                         └──终止──────→ INTERRUPT(已终止)
  │
  └──删除──→ (删除)
```

#### 状态机列表

| 状态机名称 | 状态释义 | 可执行的操作 |
|-----------|---------|------------|
| NEW | 新建 | 编辑、保存、保存并提交、删除 |
| RUN | 审批中 | 无(等待审批结果) |
| APPROVED | 审批通过 | 生成CRM订单、查看定金库存 |
| REJECTED | 审批拒绝 | 编辑、保存、保存并提交 |
| REBUT | 已驳回 | 编辑、保存、保存并提交 |
| INTERRUPT | 已终止 | 无(流程结束) |

#### 报错1：期望到达日期不能为空
- **触发条件**：保存要货订单时，期望到达日期(IN_DATE)未填写
- **逻辑分析**：保存校验中检查IN_DATE非空，因期望到达日期为要货订单必填项，用于物流安排。该报错为阻断性报错
- **排查SQL**：
  ```sql
  SELECT obh.SA_OUT_BILL_HEAD_ID, obh.SA_SALEBILLNO, obh.IN_DATE, obh.BILL_TYPE, obh.ORDER_STAT
  FROM SA_OUT_BILL_HEAD obh
  WHERE obh.SA_OUT_BILL_HEAD_ID = :saOutBillHeadId
    AND obh.IN_DATE IS NULL
  -- 查出期望到达日期为空的订单
  ```

#### 报错2：期望到达日期超过限制范围
- **触发条件**：保存要货订单时，期望到达日期超出允许范围(超过一年；电商渠道计划订单超6个月/常规订单超7个月；非电商渠道计划订单超3个月/常规订单超4个月)
- **逻辑分析**：保存校验中按BILL_TYPE和CHANNEL计算日期上限，若IN_DATE超过上限则抛出阻断性报错。需参考日期限制规则调整日期
- **排查SQL**：
  ```sql
  SELECT obh.SA_OUT_BILL_HEAD_ID, obh.SA_SALEBILLNO, obh.IN_DATE, obh.BILL_TYPE, obh.CHANNEL,
         SYSDATE AS 当前日期,
  ```

### 常见问题

- 问题1：为什么折扣单号选择后没有带出产品明细？
  - 原因：折扣单需满足折扣有效期未过期、可下单数量>0、产品未下架且渠道适用、产品价格未失效。排查SQL：`SELECT VALID, EFFECTIVE_DATE_END, ACTIVE_QTY FROM EPM_DISCOUNT_APPLY WHERE DISCOUNT_APPLY_ID = :id`
  - 解决思路：检查折扣单状态和产品状态

- 问题2：期望到达日期为什么被清空？
  - 原因：期望到达日期有严格限制：不能超过一年；当日≤25号时非电商渠道计划订单限3个月内；当日>25号时非瓷砖产品线不能下常规订单
  - 解决思路：参考提示信息调整日期

- 问题3：生成CRM订单时报"关联合同变更中"怎么办？
  - 原因：该订单关联合同存在正在审批的变更单(ECN)。排查SQL：`SELECT * FROM EPM_PROJECT_CONTRACT_ECN WHERE CONTRACT_ID = :contractId AND HZ_APPROVE_STATUS = 'RUN'`
  - 解决思路：等合同变更审批完成后再生成CRM订单

- 问题4：紧急行数提示过多怎么办？
  - 原因：紧急行数规则：仅计划订单可加紧急，且紧急行数≤CEIL(产品行数/5)
  - 解决思路：减少紧急行数或将订单改为计划订单

- 问题5：产品SM状态为Z8无法下单怎么办？
  - 原因：Z8表示产品生命状态不允许下单。排查SQL：`SELECT SM_STATE FROM SA_OUT_BILL_LINE WHERE SA_OUT_BILL_HEAD_ID = :id AND SM_STATE = 'Z8'`
  - 解决思路：联系产品部调整产品状态

- 问题6："申请不扣订金"按钮不显示？
  - 原因：显示条件：订单可编辑 + billType=1/13 + 无要货单号或订单状态=4 + OA状态0/99/空 + 订单状态≠4
  - 解决思路：检查订单状态是否满足

- 问题7：经销商登录时客户字段为什么不可选？
  - 原因：经销商登录(userType=D)时自动带出其客户信息，不允许修改客户
  - 解决思路：这是预期行为，经销商只能为自己下单
