# 工程管理-项目交付-工程取消核销与发票作废

> **说明**：本功能集成在"工程真实性核销"详情页中，非独立菜单页面。后端Controller为EpmVeriferInvoiceDetailsController，提供/cl-verify-obs-invo接口。

---

## 业务流程

### 业务流程图

```text
开始 → ★取消核销/发票作废★ → 选择取消类型 → 确认取消 → 更新核销状态/发票状态 → 结束

取消类型：
  ├─ 取消发票（invoice）
  ├─ 取消发票明细（invoiceDetail）
  ├─ 取消出库单行核销（invLine）
  ├─ 取消核销明细（veriferDetail）
  └─ 作废发票（obsInvoice）
```

### 上游依赖

| 上游模块 | 依赖类型 | 依赖说明 | 依赖成立条件 |
|---------|---------|---------|------------|
| 工程真实性核销 | 数据依赖 | 取消核销操作基于真实性核销单 | 核销单已存在 |
| 发票数据 | 数据依赖 | 作废发票操作基于已核销发票 | 发票已核销 |
| 出库单数据 | 数据依赖 | 取消出库单行核销基于已核销出库行 | 出库行已核销 |

### 下游影响

- 影响1：核销状态
  - 取消核销后核销明细状态更新为未核销

- 影响2：发票状态
  - 作废发票后发票状态更新为作废

- 影响3：出库单状态
  - 取消出库单行核销后出库行恢复为未核销

## 重点逻辑

### 重点逻辑1：多种取消类型 `灵活取消`

- **业务意义**：支持不同粒度的取消操作，满足各种业务场景

- **具体逻辑描述**

  - 第1点：取消发票（invoice）——取消整张发票的核销

  - 第2点：取消发票明细（invoiceDetail）——取消单条发票明细的核销

  - 第3点：取消出库单行核销（invLine）——取消出库单行的核销标记

  - 第4点：取消核销明细（veriferDetail）——取消核销明细记录

  - 第5点：作废发票（obsInvoice）——将发票标记为作废

## 详细逻辑

### 其他按钮

| 按钮名称 | 按钮作用 | 所在位置 | 显隐条件/可点击条件 | 影响 |
|---------|---------|---------|-------------------|------|

#### 按钮1：取消核销（真实性核销详情页）

- **触发条件**：核销单非新建状态
- **执行逻辑**：
  - 第1点：选择取消类型（发票/发票明细/出库单行/核销明细）
  - 第2点：确认取消操作
  - 第3点：调用后端/cl-verify-obs-invo接口执行取消
  - 第4点：更新对应数据的核销状态
- **接口调用**：POST /v1/{orgId}/epm-verifer-invoice-detailss/cl-verify-obs-invo

## 数据库表详解

### 表1：EPM_VERIFER_INVOICE_DETAILS（核销发票明细表）

| 字段名 | 类型 | 释义 | 对应界面字段 | 逻辑 |
|-------|------|------|------------|------|
| VERIFER_INVOICE_DETAILS_ID | NUMBER | 主键 | 无 | 自增生成 |
| INVOICE_VERIFER_ID | NUMBER | 核销单头ID | 无 | 关联核销头表 |
| PROD_CODE | VARCHAR | 产品编码 | 无 | 关联产品主档 |

#### 报错1：核销明细不存在
- **触发条件**：取消核销时，按VERIFER_INVOICE_DETAILS_ID查询EPM_VERIFER_INVOICE_DETAILS返回null
- **逻辑分析**：取消方法中按ID查询核销明细，若返回null则抛出阻断性报错。需检查核销明细ID有效性
- **排查SQL**：
  ```sql
  SELECT vid.VERIFER_INVOICE_DETAILS_ID, vid.INVOICE_VERIFER_ID, vid.PROD_CODE,
         vid.VERIFER_QTY, vid.VERIFER_STATUS, vid.EFFECT_STATUS
  FROM EPM_VERIFER_INVOICE_DETAILS vid
  WHERE vid.VERIFER_INVOICE_DETAILS_ID = :veriferInvoiceDetailsId
  -- 若返回空，说明核销明细不存在
  ```

#### 报错2：发票不存在
- **触发条件**：作废发票时，按ID查询发票信息返回null
- **逻辑分析**：作废方法中按发票ID查询发票信息，若返回null则抛出阻断性报错。需检查发票ID有效性
- **排查SQL**：
  ```sql
  SELECT euii.UPLOAD_INVOICE_INFO_ID, euii.INVOICE_NO, euii.INVOICE_CODE, euii.EFFECT_STATUS
  FROM EPM_UPLOAD_INVOICE_INFO euii
  WHERE euii.UPLOAD_INVOICE_INFO_ID = :uploadInvoiceInfoId
  -- 若返回空，说明发票不存在
  ```

#### 报错3：核销明细状态异常,请刷新数据后重试
- **触发条件**：取消核销时，核销明细已被其他操作变更(并发修改)
- **逻辑分析**：取消方法中更新核销明细状态时，若影响行数与预期不一致则抛出阻断性报错。需刷新数据后重试
- **排查SQL**：
  ```sql
  SELECT vid.VERIFER_INVOICE_DETAILS_ID, vid.EFFECT_STATUS, vid.LAST_UPDATE_DATE,
         vid.OBJECT_VERSION_NUMBER
  FROM EPM_VERIFER_INVOICE_DETAILS vid
  WHERE vid.VERIFER_INVOICE_DETAILS_ID = :veriferInvoiceDetailsId
  -- 检查核销明细当前状态和版本号，判断是否被并发修改
  ```

#### 报错4：取消后出库单行已核销数量小于0
- **触发条件**：取消核销时，取消数量大于出库单行已核销数量
- **逻辑分析**：取消方法中更新INV_OUT_BILL_LINE的已核销数量(原已核销数量-取消数量)，若结果<0则抛出阻断性报错。需检查数据一致性
- **排查SQL**：
  ```sql
  SELECT iobl.INV_OUT_BILL_LINE_ID, iobl.VERIFERED_NUMBER, iobl.CAN_VERIFER_NUMBER,
         vid.VERIFER_QTY, vid.VERIFER_INVOICE_DETAILS_ID,
         iobl.VERIFERED_NUMBER - vid.VERIFER_QTY AS 取消后已核销数量
  FROM EPM_VERIFER_INVOICE_DETAILS vid
  JOIN INV_OUT_BILL_LINE iobl ON vid.INV_OUT_BILL_LINE_ID = iobl.INV_OUT_BILL_LINE_ID
  WHERE vid.VERIFER_INVOICE_DETAILS_ID = :veriferInvoiceDetailsId
    AND iobl.VERIFERED_NUMBER - vid.VERIFER_QTY < 0
  -- 查出取消后已核销数量<0的异常数据
  ```


### 常见问题

- 问题1：取消核销后数据能否恢复
  - 原因：取消核销操作将核销状态更新为未核销，可重新核销
  - 解决思路：取消后可重新执行核销操作

- 问题2：作废发票后能否恢复
  - 原因：作废发票操作将发票状态标记为作废
  - 解决思路：作废后需重新开具发票
