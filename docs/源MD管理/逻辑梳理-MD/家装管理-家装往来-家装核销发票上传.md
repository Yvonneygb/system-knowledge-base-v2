## 业务流程

### 业务流程图

```text
开始 → ★新建核销发票上传★ → 选择项目/经销商 → OCR发票校验 → 填写发票信息 → 添加发票明细 → 保存 → 提交审批 → ⚖审批通过？
```

## 重点逻辑

### 重点逻辑1：OCR发票校验 `发票识别`

- **业务意义**：通过OCR自动识别发票影像信息，减少手工录入

- **具体逻辑描述**

  - 第1点：上传发票影像后调用OCR接口自动识别发票信息

  - 第2点：OCR识别结果回填到发票主信息字段

  - 第3点：识别后自动校验发票是否重复

### 重点逻辑2：发票重复校验 `防重`

- **业务意义**：防止同一发票被重复核销

- **具体逻辑描述**

  - 第1点：保存时调用check-invoice接口校验发票号码是否已存在

  - 第2点：重复时阻断保存并提示

### 重点逻辑3：终止与撤回 `流程控制`

- **业务意义**：支持审批流程的终止和撤回操作

- **具体逻辑描述**

  - 第1点：终止操作将流程标记为终止状态

  - 第2点：撤回终止可恢复流程到终止前状态

### 状态机

#### 状态机流转图

```text
NEW（新建） ──提交──→ RUN（审批中） ──审批通过──→ APPROVED（已审核）
                         │                    │
                         ├──审核拒绝──→ REJECTED ──提交──→ RUN
                         ├──终止──→ TERMINATED ──撤回终止──→ RUN
                         └──撤回──→ NEW
```

#### 报错1：发票重复
- **触发条件**：保存核销发票或OCR校验时，发票号码已存在于系统中
- **逻辑分析**：后端check-invoice接口根据发票号码查询EPM_VERIFER_INVOICE相关表，若同一发票号码已存在未作废的核销记录，则阻断保存并提示"发票重复"。OCR识别成功后也会自动触发此校验，防止同一发票被重复核销。
- **排查SQL**：
  ```sql
  SELECT H.INVOICE_VERIFER_NO AS 核销单号, H.HZ_APPROVE_STATUS AS 审核状态,
         H.PROJECT_CODE AS 项目编码, H.CUSTOMER_CODE AS 经销商编码,
         H.CREATION_DATE AS 创建时间
  FROM EPM_VERIFER_INVOICE_HEADERS H
    LEFT JOIN EPM_VERIFER_INVOICE_LINES L ON L.HEAD_ID = H.INVOICE_VERIFER_ID
  WHERE L.INVOICE_NO = :invoiceNo
    AND H.HZ_APPROVE_STATUS <> 'CANCELLED'
  ORDER BY H.CREATION_DATE DESC;
  ```

#### 报错2：明细行基本单位不能为空
- **触发条件**：详情页点击"保存"按钮时，发票明细行（InvoiceDetailTableDS）中存在baseUomName为空字符串/null/undefined的记录
- **逻辑分析**：前端handleBeforeSave校验遍历invoiceDetailTableDS.records，若任一行的baseUomName为空则阻断保存并提示"明细行基本单位不能为空！"。基本单位由getBaseUom接口根据辅助单位（transformTmp）换算带出，若产品未维护单位换算关系则带出失败。
- **排查SQL**：
  ```sql
  SELECT D.INVOICE_VERIFER_ID AS 核销ID, D.ITEM_CODE AS 产品编码,
         D.UOM_NAME AS 单位, D.BASE_UOM_NAME AS 基本单位
  FROM EPM_VERIFER_INVOICE_DETAILS D
  WHERE D.INVOICE_VERIFER_ID = :invoiceVeriferId
    AND (D.BASE_UOM_NAME IS NULL OR D.BASE_UOM_NAME = '');
  ```

#### 报错3：转换率不能为0
- **触发条件**：详情页保存或提交时，发票明细行的conversionRate为空或小于等于0
- **逻辑分析**：前端handleBeforeSave和handleBeforeSubmit均会遍历invoiceDetailTableDS.records，校验conversionRate不为空且大于0。转换率由单位换算接口根据辅助单位与基本单位关系计算，若未维护换算关系则为0。
- **排查SQL**：
  ```sql
  SELECT D.INVOICE_VERIFER_ID AS 核销ID, D.ITEM_CODE AS 产品编码,
         D.UOM_NAME AS 单位, D.CONVERSION_RATE AS 转换率
  FROM EPM_VERIFER_INVOICE_DETAILS D
  WHERE D.INVOICE_VERIFER_ID = :invoiceVeriferId
    AND (D.CONVERSION_RATE IS NULL OR D.CONVERSION_RATE <= 0);
  ```

#### 报错4：明细行未存在头信息
- **触发条件**：详情页保存时，发票明细行的凭证号码(noucherNumber)-发票代码(invoiceCode)-发票号码(invoiceNumber)组合在发票主要信息中不存在
- **逻辑分析**：前端handleBeforeSave构建invoiceMainObj（头信息凭证号码-代码-号码键值对），遍历明细行校验是否在头信息中存在。若不存在则提示"明细第X行，未存在头信息，请检查！"。通常由头行凭证号码不一致或删除头信息未同步删除明细导致。
- **排查SQL**：
  ```sql
  SELECT D.NOUCHER_NUMBER AS 凭证号码, D.INVOICE_CODE AS 发票代码,
         D.INVOICE_NUMBER AS 发票号码
  FROM EPM_VERIFER_INVOICE_DETAILS D
  WHERE D.INVOICE_VERIFER_ID = :invoiceVeriferId
    AND NOT EXISTS (
      SELECT 1 FROM EPM_VERIFER_INVOICE_INFO I
      WHERE I.INVOICE_VERIFER_ID = D.INVOICE_VERIFER_ID
        AND I.NOUCHER_NUMBER = D.NOUCHER_NUMBER
        AND I.INVOICE_CODE = D.INVOICE_CODE
        AND I.INVOICE_NUMBER = D.INVOICE_NUMBER
    );
  ```

#### 报错5：发票代码-号码重复
- **触发条件**：发票主要信息行编辑发票号码或发票代码时，同一发票代码+号码组合已在其他行存在
- **逻辑分析**：前端InvoiceMain的handleCheckInvoice校验遍历dataSet.records，若发现非当前行的invoiceNumber和invoiceCode与当前行相同，则提示"发票代码-发票号码(X-Y)已在第N行存在"并回滚编辑值。防止同一发票在主要信息中重复录入。
- **排查SQL**：
  ```sql
  SELECT I.INVOICE_CODE AS 发票代码, I.INVOICE_NUMBER AS 发票号码,
         COUNT(*) AS 重复次数
  FROM EPM_VERIFER_INVOICE_INFO I
  WHERE I.INVOICE_VERIFER_ID = :invoiceVeriferId
  GROUP BY I.INVOICE_CODE, I.INVOICE_NUMBER
  HAVING COUNT(*) > 1;
  ```

#### 报错6：凭证类型或附件未选择
- **触发条件**：详情页点击"新增"发票主要信息或明细行时，发票影像行(invoiceImageTableDS)存在verifyVoucherType为空或docname为空的记录
- **逻辑分析**：前端checkVoucher校验遍历invoiceImageTableDS.records，若任一行verifyVoucherType或docname为空，则提示"第X行，请先选择凭证类型或附件"并阻断新增。凭证类型和附件是发票影像的必填前置信息。
- **排查SQL**：
  ```sql
  SELECT V.NOUCHER_NUMBER AS 凭证号码, V.VERIFY_VOUCHER_TYPE AS 凭证类型,
         V.DOCNAME AS 附件名称
  FROM EPM_VERIFER_INVOICE V
  WHERE V.INVOICE_VERIFER_ID = :invoiceVeriferId
    AND (V.VERIFY_VOUCHER_TYPE IS NULL OR V.DOCNAME IS NULL);
  ```

#### 报错7：OCR识别失败
- **触发条件**：详情页上传发票影像后触发OCR识别，OCR接口返回失败或影像不清晰
- **逻辑分析**：前端ocrIdentify调用后端invoice-identify接口，后端EpmUploadInvoiceVeriferServiceImpl调用外部OCR服务。若附件未找到、OCR接口返回失败或开票时间解析异常，后端抛出"附件uuid:X ocr接口识别失败"或"OCR校验异常，返回开票时间错误"。前端展示后端返回的失败message。
- **排查SQL**：
  ```sql
  SELECT V.INVOICE_VERIFER_ID AS 核销ID, V.NOUCHER_NUMBER AS 凭证号码,
         V.DOCNAME AS 附件名称, V.VOUCHER_ATT_UUID AS 附件UUID
  FROM EPM_VERIFER_INVOICE V
  WHERE V.INVOICE_VERIFER_ID = :invoiceVeriferId
    AND V.DOCNAME IS NOT NULL
  ORDER BY V.CREATION_DATE DESC;
  ```

#### 报错8：发票主要信息不能为空
- **触发条件**：详情页点击"提交"按钮时，发票主要信息（epmUploadInvoiceInfos）为空集合
- **逻辑分析**：后端wfProcSubmit方法根据invoiceVeriferId查询EPM_VERIFER_INVOICE_INFO，若集合为空则抛出"单据【X】，发票主要信息不能为空"。提交前必须至少维护一条发票主要信息。
- **排查SQL**：
  ```sql
  SELECT H.INVOICE_VERIFER_NO AS 核销单号, H.HZ_APPROVE_STATUS AS 审核状态,
         (SELECT COUNT(*) FROM EPM_VERIFER_INVOICE_INFO I
          WHERE I.INVOICE_VERIFER_ID = H.INVOICE_VERIFER_ID) AS 主要信息数量
  FROM EPM_VERIFER_INVOICE_HEADERS H
  WHERE H.INVOICE_VERIFER_ID = :invoiceVeriferId;
  ```

#### 报错9：发票详细信息不能为空
- **触发条件**：详情页点击"提交"按钮时，发票详细信息（epmUploadInvoiceDetailss）为空集合
- **逻辑分析**：后端wfProcSubmit和onProcComplete方法根据invoiceVeriferId查询EPM_VERIFER_INVOICE_DETAILS，若集合为空则抛出"单据【X】，发票详细信息不能为空"或"提交流程发票详细信息不能为空!"。提交前必须至少维护一条发票详细信息。
- **排查SQL**：
  ```sql
  SELECT H.INVOICE_VERIFER_NO AS 核销单号, H.HZ_APPROVE_STATUS AS 审核状态,
         (SELECT COUNT(*) FROM EPM_VERIFER_INVOICE_DETAILS D
          WHERE D.INVOICE_VERIFER_ID = H.INVOICE_VERIFER_ID) AS 详细信息数量
  FROM EPM_VERIFER_INVOICE_HEADERS H
  WHERE H.INVOICE_VERIFER_ID = :invoiceVeriferId;
  ```

#### 报错10：详情行汇总金额与主要总金额不一致
- **触发条件**：详情页提交时，发票明细行的单价×数量汇总金额与发票主要信息的总金额不一致
- **逻辑分析**：后端verifyData方法校验每个发票号码下明细行金额(单价×数量)汇总是否等于主要信息总金额(allAmount)。若不一致则抛出"发票号码[X]，详情信息行汇总金额与主要总金额不一致"。通常由修改明细行单价/数量未同步更新头金额或精度丢失导致。
- **排查SQL**：
  ```sql
  SELECT I.INVOICE_NUMBER AS 发票号码,
         I.ALL_AMOUNT AS 主要总金额,
         NVL(SUM(D.UNIT_PRICE * D.MDF_ITEM_NUMBER), 0) AS 明细汇总金额,
         I.ALL_AMOUNT - NVL(SUM(D.UNIT_PRICE * D.MDF_ITEM_NUMBER), 0) AS 差额
  FROM EPM_VERIFER_INVOICE_INFO I
    LEFT JOIN EPM_VERIFER_INVOICE_DETAILS D
      ON D.INVOICE_VERIFER_ID = I.INVOICE_VERIFER_ID
     AND D.INVOICE_NUMBER = I.INVOICE_NUMBER
  WHERE I.INVOICE_VERIFER_ID = :invoiceVeriferId
  GROUP BY I.INVOICE_NUMBER, I.ALL_AMOUNT
  HAVING I.ALL_AMOUNT <> NVL(SUM(D.UNIT_PRICE * D.MDF_ITEM_NUMBER), 0);
  ```

#### 报错11：未查找到核销信息
- **触发条件**：详情页执行终止、撤回终止或取消操作时，根据invoiceVeriferId未查询到核销头表记录
- **逻辑分析**：后端handle方法根据invoiceVeriferId查询EPM_VERIFER_INVOICE_HEADERS，若集合为空则抛出"未查找到核销信息:X"。通常由记录被他人删除或会话过期使用了缓存的ID导致。
- **排查SQL**：
  ```sql
  SELECT H.INVOICE_VERIFER_ID AS 核销ID, H.INVOICE_VERIFER_NO AS 核销单号,
         H.HZ_APPROVE_STATUS AS 审核状态
  FROM EPM_VERIFER_INVOICE_HEADERS H
  WHERE H.INVOICE_VERIFER_ID = :invoiceVeriferId;
  ```

#### 报错12：请求失败
- **触发条件**：详情页删除发票影像附件时，附件删除接口调用异常
- **逻辑分析**：前端handleDel调用deleteFile接口删除附件，若接口抛出异常则catch块提示"请求失败"。通常由网络异常、附件存储服务（ARROW_OSS）不可用或附件已被删除导致。
- **排查SQL**：
  ```sql
  SELECT V.NOUCHER_NUMBER AS 凭证号码, V.DOCNAME AS 附件名称,
         V.DOCNAME_URL AS 附件URL
  FROM EPM_VERIFER_INVOICE V
  WHERE V.INVOICE_VERIFER_ID = :invoiceVeriferId
    AND V.DOCNAME IS NOT NULL;
  ```

#### 报错13：暂无数据
- **触发条件**：列表页查询时，查询条件无匹配的核销发票记录
- **逻辑分析**：前端列表DataSet查询返回空集合时框架提示"暂无数据"。通常由查询条件过严、数据未生成或权限不足导致。
- **排查SQL**：
  ```sql
  SELECT COUNT(*) AS 记录数
  FROM EPM_VERIFER_INVOICE_HEADERS H
  WHERE H.HZ_APPROVE_STATUS = NVL(:status, H.HZ_APPROVE_STATUS)
    AND H.PROJECT_CODE LIKE NVL(:projectCode, '%')
    AND H.CREATION_DATE BETWEEN NVL(:dateFrom, H.CREATION_DATE) AND NVL(:dateTo, H.CREATION_DATE);
  ```

#### 报错14：会话过期
- **触发条件**：任意操作时，用户登录态失效（token过期或被踢出）
- **逻辑分析**：前端请求拦截器检测到响应401状态码时提示"会话过期"并跳转登录页。通常由长时间未操作、多端登录或服务端session过期导致。
- **排查SQL**：
  ```sql
  -- 会话过期为前端拦截，无对应数据查询
  -- 可检查用户最近登录时间
  SELECT U.USER_ID AS 用户ID, U.LOGIN_NAME AS 登录名,
         U.LAST_LOGIN_DATE AS 最近登录时间
  FROM HPFM_USER U
  WHERE U.USER_ID = :userId;
  ```
