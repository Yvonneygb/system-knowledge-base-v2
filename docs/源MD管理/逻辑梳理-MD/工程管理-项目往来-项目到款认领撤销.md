# 工程管理-项目往来-项目到款认领撤销

## 业务流程

### 业务流程图

```text
已审核认领单        选取撤销明细      保存认领撤销单      提交审批          ERP冲销
(已认领数据)  →   指定撤销原因  →   生成撤销单号  →   校验明细未重复  →   推送ERP负数冲销
                   按报销分组校验     状态=新建         发起工作流         审批通过回加可认领金额
                                                          ↓
                                                   审批通过→认领明细撤销标识=Y
                                                           →到款单可认领金额回加
```

### 上游依赖

| 上游模块 | 依赖类型 | 依赖说明 | 依赖成立条件 |
|---------|---------|---------|------------|
| 项目到款认领 | 数据依赖 | 提供已审核的认领明细、认领金额、工程服务费金额 | 认领单已审批通过（APPROVED） |
| 工程服务费报销 | 数据依赖 | 提供报销单信息、已申请兑现金额，用于校验撤销后可结算金额 | 认领明细关联了报销单 |
| ERP系统 | 数据依赖 | 推送负数冲销核销数据 | ERP接口可用 |
| 编码规则配置 | 配置依赖 | 生成撤销单号，规则编码AE.EPM_PAYMENT_ALLOT_CANCEL_NO | 编码规则已配置 |
| 工作流引擎 | 配置依赖 | 发起撤销审批流程EPM_PAYMENT_ALLOT_CANCEL | 工作流已部署 |

### 下游影响

- 影响1：认领明细撤销标识更新
  - 审批通过后，将对应认领明细的cancelFlag置为Y，表示已撤销

- 影响2：到款引入单可认领金额回加
  - 审批通过后，将撤销的认领金额回加到到款引入单的unallotAmt字段

- 影响3：ERP负数冲销
  - 推送ERP负数核销数据（所有金额取负），actionStatus=APPROVE，sourceType=REVOKE_CLAIM

- 影响4：工程服务费可结算金额
  - 撤销后减少已认领工程服务费，影响后续服务费兑现申请

## 重点逻辑

### 重点逻辑1：撤销后可结算工程服务费校验 {核心校验}

- **业务意义**：防止撤销后已认领工程服务费不足以覆盖已申请兑现金额

- **具体逻辑描述**

  - 第1点：按报销单分组，计算每组撤销的工程服务费金额合计

  - 第2点：可结算兑现金额=已认领工程服务费-本次撤销工程服务费-已退货工程服务费-已申请兑现金额

  - 第3点：可结算兑现金额小于0时不允许撤销，报错提示报销单号

### 重点逻辑2：撤销明细重复校验 {防重复撤销}

- **业务意义**：防止同一认领明细被重复撤销

- **具体逻辑描述**

  - 第1点：提交时查询所有撤销明细对应的认领明细，检查cancelFlag是否已为Y

  - 第2点：已撤销的明细列出认领单号、出库单号、产品编码，提示用户剔除后再提交

### 重点逻辑3：ERP负数冲销推送 {ERP集成}

- **业务意义**：通过推送负数数据实现ERP侧的冲销核销

- **具体逻辑描述**

  - 第1点：按认领单分组，每组组装AR_APPLY、OM_CLAIM、OM_APPLY三组数据

  - 第2点：所有金额取负数（negate），实现冲销效果

  - 第3点：actionStatus设为APPROVE，sourceType设为REVOKE_CLAIM，revokeSourceId指向原认领单

  - 第4点：虚拟到款单额外传creditMemoId

### 重点逻辑4：审批通过回加可认领金额 {金额回写}

- **业务意义**：撤销审批通过后，将撤销的金额退回到款单的可认领金额池

- **具体逻辑描述**

  - 第1点：查询撤销单关联的所有认领明细及其认领金额

  - 第2点：按到款引入单分组，将认领金额累加回unallotAmt

  - 第3点：同时更新认领明细的cancelFlag=Y和撤销单的撤销时间

### 重点逻辑5：撤销单号生成规则 {编码规则}

- **业务意义**：撤销单号由事业部编码+规则编号组成，确保唯一性

- **具体逻辑描述**

  - 第1点：调用编码规则AE.EPM_PAYMENT_ALLOT_CANCEL_NO生成规则编号

  - 第2点：撤销单号=事业部编码（deptCode）+规则编号

```sql
SELECT d.payment_allot_detail_id, d.payment_allot_line_id, d.claim_amt,
```

#### 按钮1：保存（详情页）

- **触发条件**：常显
- **执行逻辑**：
  - 第1点：新建时生成撤销单号（事业部编码+规则编号），设置状态为1
  - 第2点：调用verifyBeforeInsert校验撤销后可结算工程服务费是否>=0
  - 第3点：插入撤销头和撤销明细行（EPM_PAD_CANCEL）
  - 第4点：编辑时先删除旧明细再插入新明细
- **接口调用**：POST /v1/{organizationId}/epm-payment-allot-cancels/save
- **排查SQL**：

```sql
SELECT * FROM epm_payment_allot_cancel WHERE id = {cancelId};
SELECT * FROM epm_pad_cancel WHERE cancel_id = {cancelId};
```

#### 按钮2：提交（详情页）

- **触发条件**：审批状态为NEW
- **执行逻辑**：
  - 第1点：查询撤销明细对应的认领明细，检查是否有cancelFlag=Y的
  - 第2点：已撤销的明细报错，列出认领单号、出库单号、产品编码
  - 第3点：校验通过后发起工作流EPM_PAYMENT_ALLOT_CANCEL
  - 第4点：更新审批状态为RUN，记录工作流实例ID
- **接口调用**：POST /v1/{organizationId}/epm-payment-allot-cancels/wfProcSubmit
- **排查SQL**：

```sql
SELECT d.cancel_flag, pa.payment_allot_code, d.inv_bill_no, d.item_code
FROM epm_payment_allot_detail d
JOIN epm_pad_cancel pc ON d.payment_allot_detail_id = pc.payment_allot_detail_id
JOIN epm_payment_allot_line l ON d.payment_allot_line_id = l.payment_allot_line_id
JOIN epm_payment_allot pa ON l.payment_allot_id = pa.payment_allot_id
WHERE pc.cancel_id = {cancelId} AND d.cancel_flag = 'Y';
```

### 保存校验

- 校验1：撤销后可结算工程服务费校验 —— 确保撤销后已认领工程服务费足以覆盖已申请兑现金额

  - 详细逻辑

    - 第1点：按报销单（svcExpAccId）分组，计算每组撤销的工程服务费金额合计

    - 第2点：可结算兑现金额=已认领工程服务费-本次撤销工程服务费-已退货工程服务费-已申请兑现金额

    - 第3点：可结算兑现金额<0时报错，提示报销单号

  - 系统体现：阻断性报错

  - 排查SQL：

    ```sql
    -- 查询报销关联的认领信息
    SELECT total_claim_amt, total_claim_service_amt, return_service_amt
    FROM epm_pad_cancel_query WHERE svc_exp_acc_id = {svcExpAccId};
    -- 查询已申请兑现金额
    SELECT applied_amt FROM epm_applied_amt WHERE svc_exp_acc_id = {svcExpAccId};
    ```

### 提交校验

- 校验1：撤销明细重复校验 —— 确保选中的认领明细未被其他撤销单撤销

  - 详细逻辑

    - 第1点：查询撤销明细对应的认领明细，过滤cancelFlag=Y的

    - 第2点：存在已撤销明细时报错，列出认领单号、出库单号、产品编码

  - 系统体现：阻断性报错

  - 排查SQL：

    ```sql
    SELECT pa.payment_allot_code, d.inv_bill_no, d.item_code
    FROM epm_payment_allot_detail d
    JOIN epm_pad_cancel pc ON d.payment_allot_detail_id = pc.payment_allot_detail_id
    JOIN epm_payment_allot_line l ON d.payment_allot_line_id = l.payment_allot_line_id
    JOIN epm_payment_allot pa ON l.payment_allot_id = pa.payment_allot_id
    WHERE pc.cancel_id = {cancelId} AND d.cancel_flag = 'Y';
    ```

- 校验2：撤销明细非空校验 —— 确保撤销单有明细行

  - 详细逻辑

    - 第1点：查询EPM_PAD_CANCEL表中cancelId对应的明细

    - 第2点：明细为空时报错"流程启动异常，撤销明细不存在"

  - 系统体现：阻断性报错

  - 排查SQL：

    ```sql
    SELECT COUNT(*) FROM epm_pad_cancel WHERE cancel_id = {cancelId};
    ```

- 校验3：ERP冲销推送校验 —— 推送ERP负数冲销并校验返回

  - 详细逻辑

    - 第1点：按认领单分组组装冲销数据，所有金额取负

    - 第2点：推送ERP，actionStatus=APPROVE，sourceType=REVOKE_CLAIM

    - 第3点：ERP返回状态非S时报错

  - 系统体现：阻断性报错

  - 排查SQL：

    ```sql
    SELECT * FROM sys_exception_msg WHERE objid = {cancelId} AND objtypename = '到款认领撤销';
    ```

### 状态机

#### 状态机流转图

```text
NEW(新建) ──提交──→ RUN(审批中) ──审批通过──→ APPROVED(已审核)
                        │
                        │审批驳回
                        ↓
                     回到NEW
```

#### 状态机列表

| 状态机名称 | 状态释义 | 可执行的操作 |
|-----------|---------|------------|
| NEW | 新建，未提交 | 编辑、保存、提交 |
| RUN | 审批中，工作流运行中 | 无（等待审批结果） |
| APPROVED | 已审核，审批通过 | 无（已完成撤销，金额已回加） |

#### 报错1：撤销明细中，含有已经报销的认领明细，且撤销后可结算工程服务费小于零，不允许撤销
- **触发条件**：保存撤销单时，撤销明细中含已报销的认领明细，且撤销后可结算工程服务费(total_claim_service_amt - cancelServiceChargeAmt - return_service_amt - applied_amt) < 0
- **逻辑分析**：保存校验中查询epm_pad_cancel_query按svcExpAccId获取已认领工程服务费总额，减去本次撤销金额、已退回金额、已申请兑现金额后若<0则抛出阻断性报错。需减少撤销明细中工程服务费金额
- **排查SQL**：
  ```sql
  SELECT epcq.SVC_EXP_ACC_ID, epcq.TOTAL_CLAIM_SERVICE_AMT, epcq.RETURN_SERVICE_AMT, epcq.APPLIED_AMT,
         epcq.TOTAL_CLAIM_SERVICE_AMT - :cancelServiceChargeAmt - epcq.RETURN_SERVICE_AMT - epcq.APPLIED_AMT AS 撤销后可结算金额
  FROM EPM_PAD_CANCEL_QUERY epcq
  WHERE epcq.SVC_EXP_ACC_ID = :svcExpAccId
  -- 若撤销后可结算金额 < 0，则触发该报错
  ```

- **逻辑分析**：提交校验中按CANCEL_ID关联EPM_PAD_CANCEL和EPM_PAYMENT_ALLOT_DETAIL，若CANCEL_FLAG=Y则收集到已撤销明细列表并抛出阻断性报错。需剔除已撤销明细后重新提交

  ```sql

  JOIN EPM_PAD_CANCEL epc ON epad.PAYMENT_ALLOT_DETAIL_ID = epc.PAYMENT_ALLOT_DETAIL_ID
  ```


### 常见问题

- 问题1：撤销后可结算工程服务费小于0
  - 原因：撤销的工程服务费过大，导致已认领工程服务费无法覆盖已申请兑现金额
  - 解决思路：减少撤销明细中工程服务费金额，确保撤销后可结算金额>=0

```sql
SELECT total_claim_service_amt - #{cancelServiceChargeAmt} - return_service_amt - applied_amt AS settleable_amt
FROM epm_pad_cancel_query WHERE svc_exp_acc_id = {svcExpAccId};
```

- 问题2：ERP撤销推送失败
  - 原因：ERP接口不可用或推送数据异常
  - 解决思路：检查ERP接口状态和推送数据，修复后重新提交

```sql
SELECT * FROM sys_exception_msg WHERE objid = {cancelId} AND objtypename = '到款认领撤销';
```

- 问题3：提交时提示明细已被撤销
  - 原因：选中的认领明细已被其他撤销单撤销（cancelFlag=Y）
  - 解决思路：剔除已撤销的明细后重新提交

```sql
SELECT d.cancel_flag, pa.payment_allot_code, d.inv_bill_no, d.item_code
FROM epm_payment_allot_detail d
JOIN epm_pad_cancel pc ON d.payment_allot_detail_id = pc.payment_allot_detail_id
WHERE pc.cancel_id = {cancelId} AND d.cancel_flag = 'Y';
```
