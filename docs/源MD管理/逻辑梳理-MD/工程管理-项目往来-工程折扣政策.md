# 工程管理-项目往来-工程折扣政策

> 本页面为低代码页面(hlod)，无独立前端源码，基于后端API与Entity梳理。工程折扣政策定义客户/区域/省份/客户分类维度下产品折扣规则，支持通用(normal)和专项(special)两种适用类型，折扣和特价两种优惠方式，坎级(阶梯)定价。经审批通过后生效，可供要货订单、折扣申请单等下游单据引用。

## 业务流程

### 折扣政策如何流转

创建折扣政策 → 选择客户/产品 → 配置坎级定价 → 保存校验 → 提交审批 → 审批通过生效 → 可发起失效申请。

```
用户进入工程折扣政策页面
  → 填写查询条件，调用折扣政策列表接口
  → 新增折扣政策：选择适用3选择客户/区域/省份/客户分类)
  → CRM产品弹窗查询产品（GET /get-crm-item）
  → 配置产品明细行和坎级(阶梯)定价
  → 保存校验（POST /epm-discount-policy）
  → 保存并提交（POST /save-and-submit）
  → 提交校验（submitCheck）
  → 触发工作流审批
  → 审批通过后：
    → 通用类型(normal)：直接设valid=2生效
    → 专项类型(special)：同步CRM创建/完成折扣政策后生效
  → 可发起折扣政策失效申请
```

### 全链路流程图

```
开始 → ★新建折扣政策★ → 选择客户/产品 → 配置坎级定价 → 保存校验 → 提交校验
     → 提交工作流 · ⚖审批通过？ → 通用直接生效/专项CRM同步 → 结束（拒绝则修改重提）

失效申请 → 审批通过 → 产品行validStat=3 → 政策头valid=3 → 结束

上游支撑：CRM系统、EBS系统、客户组织、销售区域、省份、价目表、工作流引擎、OA审批系统
下游影响：要货订单、折扣申请单、折扣变更、CRM系统、OA审批系统
```

### 政策匹配规则(4种方式)

- **policyType=1(客户)** → 直接匹配customerId
- **policyType=2(区域)** → 匹配saleAreaId
- **policyType=3(客户分类)** → 匹配customerClass
- **policyType=4(省份)** → 匹配provinceId

## 重点逻辑

### 重点逻辑1：坎级定价与优惠方式

- **业务意义**：支持按数量阶梯定价，折扣和特价两种优惠方式灵活配置
- **具体逻辑描述**：
  - 折扣方式(preferentialType=1)：坎级行定义不同数量段的折扣率，折后单价=标准单价×折扣率
  - 特价方式(preferentialType=2)：坎级行定义不同数量段的特价金额，特价反算折扣率=特价/(标准单价×出厂折扣率)
  - 坎级行匹配规则：根据下单数量匹配minimumQty ≤ 数量 ≤ cappingQty的坎级段

### 重点逻辑2：通用与专项审批差异

- **业务意义**：通用类型直接生效，专项类型需同步CRM，处理逻辑不同
- **具体逻辑描述**：
  - 通用类型(normal)审批通过后直接设valid=2生效，不推送CRM
  - 专项类型(special)审批通过后调用crmPolicySyncService同步CRM：不存在CRMID时doCreatePolicy创建，已存在时doComplete完成
  - 通用类型优惠方式必须为折扣(1)，不支持特价

### 重点逻辑3：时间重叠校验

- **业务意义**：通用类型同一产品/型号在重叠时间段不能存在多个已审批/有效政策
- **具体逻辑描述**：
  - 保存时校验通用类型(suitableType=normal)同一产品/型号的有效日期区间与其他已审批/有效政策不重叠
  - 重叠时抛出"时间重叠冲突"

### 重点逻辑4：封顶量校验

- **业务意义**：控制折扣政策使用数量上限，防止超量使用
- **具体逻辑描述**：
  - 坎级行封顶量(cappingQty)：单次下单数量上限
  - 经销商封顶量(customerCapsNumber)：单个经销商累计使用上限
  - 提交校验：max(坎级封顶量) ≤ 单个经销商封顶数量 ≤ 政策行总数量

### 重点逻辑5：失效管理

- **业务意义**：已生效的折扣政策可发起失效申请，审批通过后政策失效
- **具体逻辑描述**：
  - 创建失效记录(EpmDiscountPolicyDisabled) → 生成编码 → 更新产品行disabledId
  - 保存并提交 → 开启工作流
  - 审批通过 → 产品行validStat=3 → 所有行失效则政策头valid=3 → 专项类型推送CRM失效

### 保存校验

- 校验1：必填字段非空 —— 专项时订单类型+业务类型必填；通用必填政策类型/名称/有效日期/币种
  - **详细逻辑**：preCheckData中校验必填字段，为空抛出"必填字段不能为空"
  - **系统体现**：后端saveData方法校验
  - **排查SQL**：`SELECT * FROM EPM_DISCOUNT_POLICY WHERE POLICY_NAME IS NULL OR POLICY_TYPE IS NULL;`

- 校验2：产品行非空 —— 至少添加一条产品明细行
  - **详细逻辑**：preCheckData中校验产品行列表非空，为空抛出"产品行不能为空"
  - **系统体现**：后端saveData方法校验
 C排查SQL**：`SELECT DP.DISCOUNT_POLICY_ID FROM EPM_DISCOUNT_POLICY DP LEFT JOIN EPM_DISCOUNT_POLICY_ITEM DPI ON DP.DISCOUNT_POLICY_ID = DPI.DISCOUNT_POLICY_ID WHERE DPI.DISCOUNT_POLICY_ITEM_ID IS NULL;`

- 校验3：申请类型互斥 —— 全产品(3)与型号(2)/产品(1)不能同时存在
  - **详细逻辑**：preCheckData中校验申请类型不冲突，冲突抛出"申请类型冲突"
  - **系统体现**：后端saveData方法校验
  - **排查SQL**：`SELECT DISTINCT APPLICATION_TYPE FROM EPM_DISCOUNT_POLICY_ITEM WHERE DISCOUNT_POLICY_ID = #{policyId};`

- 校验4：政策名称长度 —— 非空且长度≤30个字符
  - **/详细逻辑**：preCheckData中校验policyName长度，超限抛出"折扣政策名称最大输入30个字符"
  - **系统体现**：后端saveData方法校验
  - **排查SQL**：`SELECT DISCOUNT_POLICY_ID, POLICY_NAME, LENGTH(POLICY_NAME) AS NAME_LEN FROM EPM_DISCOUNT_POLICY WHERE LENGTH(POLICY_NAME) > 30;`

- 校验5：时间重叠校验 —— 通用类型同一产品/型号在重叠时间段不能存在其他已审批/有效政策
  - **详细逻辑**：preCheckData中校验通用类型有效日期区间不与其他政策重叠，重叠抛出"时间重叠冲突"
  - **系统体现**：后端saveData方法校验
  - **排查SQL**：`SELECT DP.DISCOUNT_POLICY_ID, DP.DISCOUNT_POLICY_CODE FROM EPM_DISCOUNT_POLICY DP JOIN EPM_DISCOUNT_POLICY_ITEM DPI ON DP.DISCOUNT_POLICY_ID = DPI.DISCOUNT_POLICY_ID WHERE DPI.ITEM_CODE = #{itemCode} AND DP.SUITABLE_TYPE = 'normal' AND DP.3VALID IN!IN(1,2) AND DP.EFFECTIVE_DATE_END >= #{startDate} AND DP.EFFECTIVE_DATE_START <= #{endDate};`

### 提交校验

- 校验1：一口价折扣率校验 —— 产品定位为"一口价"时折扣率必须≥1
  - **详细逻辑**：submitCheck中校验产品定位为"一口价"时坎级行折扣率≥1，否则抛出"一口价折扣率<1"
  - **系统体现**：后端submitCheck方法校验
  - **排查SQL**：`SELECT DPI.ITEM_CODE, DPIE.PROD_POSITIONING, EPIL.DISCOUNT_RATE FROM EPM_DISCOUNT_POLICY_ITEM DPI JOIN EPM_DISCOUNT_POLICY_ITEM_EXT DPIE ON DPI.DISCOUNT/ITEM_ID = DPIE.DISCOUNT_POLICY_ITEM_ID JOIN EPM_DISCOUNT_POLICY_ITEM_LINE EPIL ON DPI.DISCOUNT_POLICY_ITEM_ID = EPIL.DISCOUNT_POLICY_ITEM_ID WHERE DPI.DISCOUNT_POLICY_ID = #{policyId} AND DPIE.PROD_POSITIONING = '一口价' AND EPIL.DISCOUNT_RATE < 1;`

- 校验2：坎级数量校验 —— max(坎级封顶量) ≤ 单个经销商封顶数量 ≤ 政策行总数量
  - **详细逻辑**：submitCheck中校验封顶量层级关系
  - **系统体现**：后端submitCheck方法校验
  - **&排查SQL**：`SELECT MAX(EPIL.CAPPING_QTY) AS MAX_CAPPING, DPI.CUSTOMER_CAPS_NUMBER FROM EPM_DISCOUNT_POLICY_ITEM_LINE EPIL JOIN EPM_DISCOUNT_POLICY_ITEM DPI ON EPIL.DISCOUNT_POLICY_ITEM_ID = DPI.DISCOUNT_POLICY_ITEM_ID WHERE DPI.DISCOUNT_POLICY_ID = #{policyId} GROUP BY DPI.DISCOUNT_POLICY_ITEM_ID;`

- 校验3：折扣管控CRM校验 —— 非样品/长库龄业务类型时推送CRM校验
  - **详细逻辑**：wfProcSubmit中推送CRM折扣信息同步和折扣管控校验
  - **系统体现**：工作流提交回调wfProcSubmit
  - **排查SQL**：`SELECT DISCOUNT_POLICY_ID, IS_MAKT, SOURCE_TYPE FROM EPM_DISCOUNT_POLICY WHERE DISCOUNT_POLICY_ID = #{policyId};`

### 状态机

```text
┌──────────┐  提交   ┌──────────┐  审批通过  ┌──────────┐
│  新建    │ ──────→ │ 审批中    │ ────────→ │ 已生效   │
│ (valid=1)│         │ (RUN)   │           │ (valid=2)│
└──────────┘         └────┬─────┘           └────┬─────┘
      ↑                   │                      │
      │              审批拒绝                 失效申请
      │                   │                      │
      └───────────────────┘                      ▼
                                       ┌──────────┐  失效审批通过  ┌──────────┐
                                       │ 失效申请  │ ──────────→ │ 已失效   │
                                       │ (RUN)   │            │ (valid=3)│
                                       └──────────┘           <──────────┘
```

**审批通过后动作**：
- 通用类型(normal)：直接设valid=2生效
- 专项类型(special)：crmPolicySyncService同步CRM后设valid=2

#### 报错1：折扣政策名称最大输入30个字符
- **触发条件**：保存折扣政策时，DISCOUNT_POLICY_NAME长度超过30字符
- **逻辑分析**：preCheckData方法中校验政策名称长度，EPM_DISCOUNT_POLICY.DISCOUNT_POLICY_NAME字段定义为VARCHAR(30)。超长则抛出阻断性报错，需缩短至30字符以内
- **排查SQL**：
  ```sql
  SELECT edp.DISCOUNT_POLICY_ID, edp.DISCOUNT_POLICY_CODE, edp.DISCOUNT_POLICY_NAME,
         LENGTH(edp.DISCOUNT_POLICY_NAME) AS 名称长度
  FROM EPM_DISCOUNT_POLICY edp
  WHERE LENGTH(edp.DISCOUNT_POLICY_NAME) > 30
  -- 查出名称超长的异常数据
  ```

#### 报错2：产品行不能为空
- **触发条件**：保存折扣政策时，未添加产品明细行(EPM_DISCOUNT_POLICY_ITEM为空)
- **逻辑分析**：preCheckData方法中校验产品行列表非空，因折扣政策必须包含至少一条产品明细。该报错为阻断性报错
- **排查SQL**：
  ```sql
  SELECT edp.DISCOUNT_POLICY_ID, edp.DISCOUNT_POLICY_CODE, edp.DISCOUNT_POLICY_NAME,
         (SELECT COUNT(*) FROM EPM_DISCOUNT_POLICY_ITEM edpi
          WHERE edpi.DISCOUNT_POLICY_ID = edp.DISCOUNT_POLICY_ID) AS 产品行数
  FROM EPM_DISCOUNT_POLICY edp
  WHERE edp.DISCOUNT_POLICY_ID = :discountPolicyId
  -- 若产品行数为0，则触发该报错
  ```

#### 报错3：物料明细不能为空
- **触发条件**：保存折扣政策时，产品行下未配置物料明细(EPM_DISCOUNT_POLICY_ITEM_LINE为空)
- **逻辑分析**：preCheckData方法中遍历产品行，校验每个产品行下至少有一条物料明细。该报错为阻断性报错
- **排查SQL**：
  ```sql
  SELECT edpi.DISCOUNT_POLICY_ITEM_ID, edpi.ITEM_CODE, edpi.ITEM_NAME,
         (SELECT COUNT(*) FROM EPM_DISCOUNT_POLICY_ITEM_LINE edpil
          WHERE edpil.DISCOUNT_POLICY_ITEM_ID = edpi.DISCOUNT_POLICY_ITEM_ID) AS 物料行数
  FROM EPM_DISCOUNT_POLICY_ITEM edpi
  WHERE edpi.DISCOUNT_POLICY_ID = :discountPolicyId
  -- 查出物料行数为0的产品行
  ```

#### 报错4：申请类型冲突
- **触发条件**：保存折扣政策时，全产品与型号/产品同时存在
- **逻辑分析**：preCheckData方法中校验申请类型互斥，全产品类型(包含所有产品)与按型号/产品指定类型不能同时存在。需调整申请类型
- **排查SQL**：
  ```sql
  SELECT edpi.DISCOUNT_POLICY_ITEM_ID, edpi.ITEM_CODE, edpi.ITEM_NAME, edpi.APPLY_TYPE,
         edpi.IS_ALL_PRODUCT
  FROM EPM_DISCOUNT_POLICY_ITEM edpi
  WHERE edpi.DISCOUNT_POLICY_ID = :discountPolicyId
  -- 检查是否存在IS_ALL_PRODUCT=1与具体ITEM_CODE同时存在的情况
  ```

#### 报错5：时间重叠冲突
- **触发条件**：保存折扣政策时，通用类型(suitableType=normal)同一产品在重叠时间段已有其他政策
- **逻辑分析**：preCheckData方法中按ITEM_CODE和有效日期区间查询EPM_DISCOUNT_POLICY，若通用类型政策在重叠时间段已存在则抛出阻断性报错。需调整有效日期避免重叠
- **排查SQL**：
  ```sql
  SELECT edp.DISCOUNT_POLICY_ID, edp.DISCOUNT_POLICY_CODE, edp.DISCOUNT_POLICY_NAME,
         edp.SUITABLE_TYPE, edp.VALID, edp.EFFECTIVE_DATE_START, edp.EFFECTIVE_DATE_END,
         edpi.ITEM_CODE
  FROM EPM_DISCOUNT_POLICY edp
  JOIN EPM_DISCOUNT_POLICY_ITEM edpi ON edp.DISCOUNT_POLICY_ID = edpi.DISCOUNT_POLICY_ID
  WHERE edpi.ITEM_CODE = :itemCode
    AND edp.SUITABLE_TYPE = 'normal'
    AND edp.VALID IN (1, 2)
    AND edp.EFFECTIVE_DATE_END >= :newStartDate
    AND edp.EFFECTIVE_DATE_START <= :newEndDate
  -- 查出时间重叠的通用政策
  ```

#### 报错6：新品型号不允许
- **触发条件**：保存折扣政策时，家装专项(suitableType=special)且型号涉及新品
- **逻辑分析**：preCheckData方法中校验家装专项折扣政策的型号不能涉及新品，新品必须通过产品定义。该报错为中等优先级
- **排查SQL**：
  ```sql
  SELECT edpi.DISCOUNT_POLICY_ITEM_ID, edpi.ITEM_CODE, edpi.ITEM_NAME, edpi.MODEL,
         edpi.IS_NEW_PRODUCT
  FROM EPM_DISCOUNT_POLICY_ITEM edpi
  JOIN EPM_DISCOUNT_POLICY edp ON edpi.DISCOUNT_POLICY_ID = edp.DISCOUNT_POLICY_ID
  WHERE edp.SUITABLE_TYPE = 'special'
    AND edpi.IS_NEW_PRODUCT = 1
  -- 查出家装专项中涉及新品的型号
  ```

#### 报错7：一口价折扣率<1
- **触发条件**：提交折扣政策时，产品定位为"一口价"但折扣率(DISCOUNT_RATE)<1
- **逻辑分析**：submitCheck方法中校验一口价产品的折扣率必须>=1(一口价即折扣率>=1的特殊定价)。若<1则抛出阻断性报错，需修正折扣率
- **排查SQL**：
  ```sql
  SELECT edpi.DISCOUNT_POLICY_ITEM_ID, edpi.ITEM_CODE, edpi.ITEM_NAME,
         edpi.PRICE_POSITIONING, edpi.DISCOUNT_RATE
  FROM EPM_DISCOUNT_POLICY_ITEM edpi
  WHERE edpi.DISCOUNT_POLICY_ID = :discountPolicyId
    AND edpi.PRICE_POSITIONING = '一口价'
    AND edpi.DISCOUNT_RATE < 1
  -- 查出一口价但折扣率<1的异常数据
  ```

#### 报错8：折扣政策id不能为空
- **触发条件**：导入产品时，discountPolicyId参数为空
- **逻辑分析**：importProduct方法中校验discountPolicyId非空，因导入产品需关联到已保存的折扣政策。需先保存政策后再导入产品
- **排查SQL**：
  ```sql
  SELECT edp.DISCOUNT_POLICY_ID, edp.DISCOUNT_POLICY_CODE, edp.DISCOUNT_POLICY_NAME, edp.VALID
  FROM EPM_DISCOUNT_POLICY edp
  WHERE edp.DISCOUNT_POLICY_ID = :discountPolicyId
  -- 校验折扣政策ID是否存在
  ```

#### 报错9：适用类型为"通用"时，产品优惠方式只能为 "折扣"
- **触发条件**：保存折扣政策时，适用类型为通用(normal)但产品行优惠方式选择了特价(2)
- **逻辑分析**：preCheckData方法中校验通用类型政策的优惠方式必须为折扣(1)，不支持特价。因通用政策面向所有客户，特价会导致不同客户价格不一致。需将产品行优惠方式改为折扣
- **排查SQL**：
  ```sql
  SELECT edpi.DISCOUNT_POLICY_ITEM_ID, edpi.ITEM_CODE, edpi.ITEM_NAME,
         edpi.PREFERENTIAL_TYPE, edp.SUITABLE_TYPE
  FROM EPM_DISCOUNT_POLICY_ITEM edpi
  JOIN EPM_DISCOUNT_POLICY edp ON edpi.DISCOUNT_POLICY_ID = edp.DISCOUNT_POLICY_ID
  WHERE edp.SUITABLE_TYPE = 'normal'
    AND edpi.PREFERENTIAL_TYPE = 2
  -- 查出通用类型但优惠方式为特价的异常数据
  ```

#### 报错10：产品编码:xxx 单个经销商封顶数量为正整数
- **触发条件**：保存折扣政策时，capping=2(需校验封顶量)但customerCapsNumber非正整数
- **逻辑分析**：preCheckData方法中校验当产品行启用封顶量校验(capping=2)时，单个经销商封顶数量必须为正整数。需修正封顶数量
- **排查SQL**：
  ```sql
  SELECT edpi.DISCOUNT_POLICY_ITEM_ID, edpi.ITEM_CODE, edpi.CAPPING,
         edpi.CUSTOMER_CAPS_NUMBER
  FROM EPM_DISCOUNT_POLICY_ITEM edpi
  WHERE edpi.CAPPING = 2
    AND (edpi.CUSTOMER_CAPS_NUMBER IS NULL
         OR edpi.CUSTOMER_CAPS_NUMBER <= 0
         OR edpi.CUSTOMER_CAPS_NUMBER != FLOOR(edpi.CUSTOMER_CAPS_NUMBER))
  -- 查出封顶量异常的产品行
  ```

#### 报错11：产品【xxx】本次下单数量【xxx】，超过政策该经销商剩余可下单数量【xxx】，请检查！
- **触发条件**：要货订单下单时，下单数量+已下单数量超过折扣政策该经销商的封顶量
- **逻辑分析**：checkPolicyItem方法中当capping=2时，统计当前经销商已下单数量(currentApplyNum)，若currentApplyNum+本次下单数量>经销商封顶量(customerCapsNumber)则抛出阻断性报错。需调整下单数量或联系管理员调整封顶量
- **排查SQL**：
  ```sql
  SELECT edpi.DISCOUNT_POLICY_ITEM_ID, edpi.ITEM_CODE, edpi.CUSTOMER_CAPS_NUMBER,
         edpi.TOTAL_CAP_NUMBER
  FROM EPM_DISCOUNT_POLICY_ITEM edpi
  WHERE edpi.CAPPING = 2
    AND edpi.DISCOUNT_POLICY_ID = :discountPolicyId
  -- 对比经销商已下单数量与封顶量
  ```

## 常见问题FAQ

### Q1: 折扣政策与折扣单的关系？

折扣政策是折扣单的政策来源，合同可引用折扣政策中的产品和折扣率来生成折扣单。

### Q2: 折扣政策中的产品数据从哪里来@来？

从CRM系统查询，通过GET /get-crm-item接口获取产品数据。

### Q3: 要货订单?货订单封顶量校验失败？

下单数量超过折扣政策坎级行封顶量或经销商封顶量。

**排查SQL:**
```sql
SELECT EPIL.CAPPING_QTY, EPIC.CAPPING_QTY AS CUSTOMER_CAP, EPIL.MINIMUM_QTY
FROM EPM_DISCOUNT_POLICY_ITEM_LINE EPIL
LEFT JOIN EPM_DISCOUNT_POLICY_ITEM_CUSTOMER EPIC
  ON EPIL.DISCOUNT_POLICY_ITEM_ID = EPIC.DISCOUNT_POLICY_ITEM_ID
  AND EPIC.CUSTOMER_ID = #{customerId}
WHERE EPIL.DISCOUNT_POLICY_ITEM_ID = #{policyItemId};
```

### Q4: 通用政策时间重叠校验失败？

通用类型折扣政策不允许同一产品在重叠时间段存在多个已审批/有效政策。

**排查SQL:**
```sql
SELECT DP.DISCOUNT_POLICY_ID, DP.DISCOUNT_POLICY_CODE, DP.VALID,
       DP.EFFECTIVE_DATE_START, DP.EFFECTIVE_DATE_END
FROM EPM_DISCOUNT_POLICY DP
JOIN EPM&DISCOUNT_POLICY_ITEM DPI ON DP.DISCOUNT_POLICY_ID = DPI.DISCOUNT_POLICY_ID
WHERE DPI.ITEM_CODE = #{itemCode}
  AND DP.SUITABLE_TYPE = 'normal'
  AND DP.VALID IN (1, 2)
  AND DP.EFFECTIVE_DATE_END >= #{startDate}
  AND DP.EFFECTIVE_DATE_START <= #{endDate};
```

### Q5: 专项政策审批通过后CRM同步失败？

检查EPM_DISCOUNT_POLICY_GENERATE是否有记录，CRMIC是否为空。crmPolicySyncService.doCreatePolicy或doComplete调用失败时CRM未同步。

**排查SQL:**
```sql
SELECT DISCOUNT_POLICY_ID, CRMID, CRMIC
FROM EPM_DISCOUNT_POLICY_GENERATE
WHERE DISCOUNT_POLICY_ID = #{policyId};
```

### Q6: 折扣政策失效后要货订单仍可下单？

政策行validStat未全部更新为3，或政策LOV查询条件未过滤valid状态。

**排查SQL:**
```sql
SELECT DISCOUNT_POLICY_ITEM_ID, VALID_STAT
FROM EPM_DISCOUNT_POLICY_ITEM
WHERE DISCOUNT_POLICY_ID = #{policyId} AND VALID_STAT != 3;
```
