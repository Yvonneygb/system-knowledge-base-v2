# 工程管理-项目往来-项目到款认领

## 业务流程

### 业务流程图

```text
到款引入数据        选取项目/合同/出库明细      保存认领单         提交审批           ERP核销
(未认领到款)   →   指定认款金额      →   生成认领单号  →   校验+推送ERP  →   审批通过推送ERP
                     计算还款金额         状态=申请中       发起工作流         状态=已审核
                                                                ↓
                                                        审批驳回→推送ERP取消核销
```

### 上游依赖

| 上游模块 | 依赖类型 | 依赖类型 | 依赖成立条件 |
|---------|---------|---------|------------|
| 项目到款引入 | 数据依赖 | 提供未认领的到款记录、可认领金额、到款单状态 | 到款引入单已存在且状态允许认领 |
| 项目合同 | 数据依赖 | 提供可认领的合同信息、合同金额、已回款金额 | 合同已审批通过且属于同一客户/交易公司/收款公司 |
| 出库签收明细 | 数据依赖 | 提供可认领的出库单明细、工程方金额、经销商金额 | 出库单已签收且存在未认领金额 |
| ERP系统 | 数据依赖 | 真实到款单实时查询剩余可认领金额、推送核销数据 | ERP接口可用 |
| 编码规则配置 | 配置依赖 | 生成认领单号，规则编码AE.EPM_PAYMENT_ALLOT | 编码规则已配置 |
| 工作流引擎 | 配置依赖 | 发起审批流程，按区域分区(SOUTH/NORTH/WEST/EAST) | 工作流已部署 |

### 下游影响

- 影响1：到款引入单可认领金额回写
  - 保存认领单后，更新到款引入单的剩余可认领金额；若可认领金额为0则认领状态改为CLEAR

- 影响2：ERP核销
  - 提交审批时推送ERP SUBMIT核销数据；审批通过推送APPROVE；驳回/终止推送CANCEL

- 影响3：合同已回款金额更新
  - 认领后更新合同的已回款金额，影响后续认领的可认领金额计算

- 影响4：经销商回款金额计算
  - 根据工程方金额与经销商金额比例，自动计算还款金额（经销商金额/工程方金额×本次认领金额）

- 影响5：项目到款认领撤销
  - 已审核的认领单可被撤销，撤销后回加可认领金额并推送ERP负数冲销

## 重点逻辑

### 重点逻辑1：认领金额校验 {核心校验}

- **业务意义**：确保认领金额不超过到款单剩余可认领金额，防止超认领

- **具体逻辑描述**

  - 第1点：虚拟到款单（VIRTUAL_RECEIPT）查数据库计算剩余可认领金额，认领金额合计不能超过该值

  - 第2点：真实到款单实时调用ERP接口查询最新剩余可认领金额，认领金额合计不能超过ERP返回值

  - 第3点：每行出库明细的已认领金额+本次认领金额不能超过工程方金额

### 重点逻辑2：工作流按区域分区 {多工作流}

- **业务意义**：不同区域的到款认领走不同的审批流程

- **具体逻辑描述**

  - 第1点：根据项目所在区域选择对应工作流（EPM_PAYMENT_ALLOT_SOUTH/NORTH/WEST/EAST）

  - 第2点：提交时先校验到款单状态和可认领金额，推送ERP SUBMIT，再发起工作流

  - 第3点：审批通过推送ERP APPROVE，状态改为APPROVED；驳回推送ERP CANCEL

### 重点逻辑3：手工发票认领与自动认领区分 {认领方式}

- **业务意义**：支持手工发票认领和出库单认领两种模式，数据查询和推送逻辑不同

- **具体逻辑描述**

  - 第1点：手工发票认领（manualInvoiceClaim=Y）走selectDetailsByProject查询出库明细，推送ERP走queryManualAllotDetailDataToErp

  - 第2点：非手工发票认领走selectDetailsByProjectTwo查询，推送ERP走queryNotManualAllotDetailDataToErp

  - 第3点：认领方式字段claimType区分auto（自动认领）和manual（手动认领）

### 重点逻辑4：还款金额自动计算 {金额计算}

- **业务意义**：根据工程方与经销商金额比例自动计算经销商回款金额

- **具体逻辑描述**

  - 第1点：若本次认款金额等于剩余认款金额，则还款金额=经销商金额-已还款金额

  - 第2点：否则还款金额=（经销商金额/工程方金额）×本次认领金额，保留2位小数

  - 第3点：商票/银票类型且未兑付的到款单，标记为不可兑现（allowCashFlag=false）

### 重点逻辑5：删除限制 {状态控制}

- **业务意义**：仅新建和驳回状态的认领单可删除，防止已审批数据被误删

- **具体逻辑描述**

  - 第1点：仅审批状态为NEW或INTERRUPT的认领单可删除

  - 第2点：删除时级联删除合同行和出库明细行

  - 第3点：删除后更新到款引入单的可认领金额（虚拟单查DB，真实单查ERP）

  - 第3点：推送ERP核销数据，状态为SUBMIT
  - 第4点：发起工作流，按区域选择对应流程Key
  - 第5点：更新审批状态为RUN，记录工作流实例ID

  - 第4点：更新到款引入单可认领金额（虚拟单查DB计算，真实单查ERP实时数据）


### 保存校验

- 校验1：到款单状态校验 —— 确保到款单处于可认领状态

  - 详细逻辑

    - 第1点：调用verifyImportStat校验到款引入单状态

    - 第2点：到款单不存在时报错"未找到该到款单"

  - 系统体现：阻断性报错

  - 排查SQL：

    ```sql
    SELECT payment_import_id, payment_import_code, bill_type, unallot_amt, allot_status
    FROM epm_payment_import WHERE payment_import_id = {paymentImportId};
    ```

- 校验2：可认领金额校验 —— 确保认领金额不超过剩余可认领金额

  - 详细逻辑

    - 第1点：虚拟到款单（VIRTUAL_RECEIPT）查数据库计算剩余可认领金额

    - 第2点：真实到款单实时调ERP接口查询最新剩余可认领金额

    - 第3点：本次认款金额合计>剩余可认领金额时报错

  - 系统体现：阻断性报错

  - 排查SQL：

    ```sql
    -- 虚拟单查DB
    SELECT unallot_amt FROM epm_payment_import WHERE payment_import_id = {id};
    -- 真实单查ERP（通过ERP接口，无直接SQL）
    ```

- 校验3：出库明细金额校验 —— 确保不超工程金额

  - 详细逻辑

    - 第1点：每行出库明细的已认领金额+本次认领金额不能超过工程方金额

    - 第2点：超出时报错"已认领金额+本次认领金额已超工程金额"

  - 系统体现：阻断性报错

  - 排查SQL：

    ```sql
    SELECT d.claim_amt, d.contract_amount,
           (SELECT SUM(claim_amt) FROM epm_payment_allot_detail WHERE source_id = d.source_id AND cancel_flag = 'N') AS total_claim_amt
    FROM epm_payment_allot_detail d WHERE payment_allot_line_id IN (
      SELECT payment_allot_line_id FROM epm_payment_allot_line WHERE payment_allot_id = {id}
    );
    ```

- 校验4：事业部信息校验 —— 确保用户有事业部信息

  - 详细逻辑

    - 第1点：从用户附加信息中获取DEPT（事业部）

    - 第2点：事业部为空时报错"事业部信息为空"

  - 系统体现：阻断性报错

  - 排查SQL：无（从用户上下文获取）

### 提交校验

- 校验1：到款单状态校验 —— 提交前再次校验到款单状态

  - 详细逻辑

    - 第1点：调用paymentImportService.verifyImportStat校验

    - 第2点：到款单不存在时报错"流程发起异常，到款单不存在！"

  - 系统体现：阻断性报错

  - 排查SQL：

    ```sql
    SELECT payment_import_id, allot_status FROM epm_payment_import WHERE payment_import_id = {id};
    ```

- 校验2：可认领金额校验 —— 提交前再次校验金额

  - 详细逻辑

    - 第1点：与保存校验2相同的validPaymentImportCanAllotAmt逻辑

    - 第2点：确保提交时金额仍可用（防止并发认领）

  - 系统体现：阻断性报错

  - 排查SQL：

    ```sql
    SELECT unallot_amt FROM epm_payment_import WHERE payment_import_id = {id};
    ```

- 校验3：ERP推送校验 —— 推送ERP核销数据并校验返回

  - 详细逻辑

    - 第1点：组装AR_APPLY、OM_CLAIM、OM_APPLY三组数据推送ERP

    - 第2点：ERP返回状态非S时报错"认领推送erp异常"

    - 第3点：ERP返回数据为空时报错"erp返回认领结果为空"

  - 系统体现：阻断性报错

  - 排查SQL：

    ```sql
    SELECT * FROM sys_exception_msg WHERE objid = {paymentAllotId} AND objtypename = '到款认领';
    ```

### 状态机

#### 状态机流转图

```text
NEW(新建) ──提交──→ RUN(审批中) ──审批通过──→ APPROVED(已审核)
    ↑                    │                        │
    │驳回                 │终止                    │推送ERP
    │                    ↓                        ↓
    └── INTERRUPT(驳回) ──→ 推送ERP CANCEL    TRANSFER(已推送)
                                                    │
                                                    ↓
                                              ACCOUNTED(已认领)

APPROVED ──撤销──→ CANCEL(已撤销)
```

#### 状态机列表

| 状态机名称 | 状态释义 | 可执行的操作 |
|-----------|---------|------------|
| NEW | 新建，未提交 | 编辑、保存、提交、删除 |
| RUN | 审批中，工作流运行中 | 无（等待审批结果） |
| APPROVED | 已审核，审批通过 | 撤销 |
| INTERRUPT | 驳回/中断 | 编辑、保存、重新提交、删除 |
| TRANSFER | 已推送ERP | 无 |
| ACCOUNTED | 已认领，ERP核销完成 | 无 |
| CANCEL | 已撤销 | 无 |

#### 报错1：事业部信息为空
- **触发条件**：保存认领单时，当前用户上下文缺少事业部(ORGANIZATION_ID)信息
- **逻辑分析**：保存方法中通过DetailsHelper.getUserDetail()获取用户事业部信息，若为空则抛出阻断性报错。需联系管理员补充事业部配置
- **排查SQL**：
  ```sql
  SELECT iu.USER_ID, iu.LOGIN_NAME, iu.REAL_NAME, iu.ORGANIZATION_ID, iu.DEPT_ID
  FROM IAM_USER iu
  WHERE iu.USER_ID = :currentUserId
  -- 若ORGANIZATION_ID为空，则需补充用户事业部配置
  ```

#### 报错2：未找到该到款单
- **触发条件**：保存或提交认领单时，到款引入单(PAYMENT_IMPORT_ID)不存在或已删除
- **逻辑分析**：保存/提交方法中按PAYMENT_IMPORT_ID查询EPM_PAYMENT_IMPORT，若返回null则抛出阻断性报错。需检查paymentImportId有效性
- **排查SQL**：
  ```sql
  SELECT epi.PAYMENT_IMPORT_ID, epi.PAYMENT_IMPORT_CODE, epi.PAYMENT_STATUS, epi.IS_CASHOUT, epi.VALID
  FROM EPM_PAYMENT_IMPORT epi
  WHERE epi.PAYMENT_IMPORT_ID = :paymentImportId
  -- 若返回空，说明到款单不存在
  ```

#### 报错3：本次认款金额合计大于到款接口剩余认款金额
- **触发条件**：保存或提交认领单时，本次认款金额合计超过到款单剩余可认领金额
- **逻辑分析**：保存/提交校验中查询到款单剩余可认领金额(虚拟单查DB/实际单实时查ERP)，若本次认领金额合计>剩余金额则抛出阻断性报错。可能原因：并发认领占用金额、金额超限。需刷新后重新认领
- **排查SQL**：
  ```sql
  SELECT epi.PAYMENT_IMPORT_ID, epi.PAYMENT_IMPORT_CODE, epi.RECEIVE_AMT, epi.ALLOTED_AMT,
         epi.UNALLOT_AMT, epi.RECEIVE_AMT - epi.ALLOTED_AMT AS 剩余可认领金额
  FROM EPM_PAYMENT_IMPORT epi
  WHERE epi.PAYMENT_IMPORT_ID = :paymentImportId
  -- 对比本次认领金额合计与剩余可认领金额
  ```

#### 报错4：已认领金额+本次认领金额已超工程金额
- **触发条件**：保存认领单时，出库明细的已认领金额+本次认领金额超过工程金额
- **逻辑分析**：保存校验中按出库明细查询已认领金额，加上本次认领金额若超过工程金额则抛出阻断性报错。需减少本次认领金额
- **排查SQL**：
  ```sql
  SELECT epad.PAYMENT_ALLOT_DETAIL_ID, epad.INV_BILL_NO, epad.ITEM_CODE,
         epad.CONTRACT_AMT, epad.ALLOTTED_AMT, epad.THIS_ALLOT_AMT,
         epad.ALLOTTED_AMT + epad.THIS_ALLOT_AMT AS 认领后金额
  FROM EPM_PAYMENT_ALLOT_DETAIL epad
  WHERE epad.PAYMENT_ALLOT_ID = :paymentAllotId
    AND epad.ALLOTTED_AMT + epad.THIS_ALLOT_AMT > epad.CONTRACT_AMT
  -- 查出认领金额超工程金额的明细
  ```

#### 报错5：删除异常：新建状态下的认领才可删除
- **触发条件**：删除认领单时，认领单状态(HZ_APPROVE_STATUS)非NEW(新建)或INTERRUPT(驳回)
- **逻辑分析**：delete方法中校验认领单状态为NEW或INTERRUPT，其他状态(审批中/已通过)不允许删除。已审批通过的认领单需走撤销流程
- **排查SQL**：
  ```sql
  SELECT epa.PAYMENT_ALLOT_ID, epa.PAYMENT_ALLOT_CODE, epa.HZ_APPROVE_STATUS, epa.VALID
  FROM EPM_PAYMENT_ALLOT epa
  WHERE epa.PAYMENT_ALLOT_ID = :paymentAllotId
  -- 期望 HZ_APPROVE_STATUS IN ('NEW', 'INTERRUPT')，否则不允许删除
  ```

### 常见问题

- 问题1：认领金额与到款单可认领金额不一致
  - 原因：并发认领导致可认领金额被其他认领单占用，真实到款单以ERP实时数据为准
  - 解决思路：1.刷新页面重新获取最新可认领金额；2.减少本次认领金额；3.真实到款单会自动查ERP最新数据

- 问题2：ERP推送失败
  - 原因：ERP接口不可用或推送数据异常
  - 解决思路：1.检查ERP接口状态；2.检查推送数据是否完整；3.修复后重新提交

```sql
SELECT * FROM sys_exception_msg WHERE objid = {paymentAllotId} AND objtypename = '到款认领';
```

- 问题3：可认领项目/合同/明细查询为空
  - 原因：合同未审批通过、客户/交易公司/收款公司不匹配、合同金额已全部认领
  - 解决思路：1.检查合同是否审批通过；2.检查到款单客户与合同客户是否一致；3.检查合同是否还有剩余可认领金额

- 问题4：删除认领单失败
  - 原因：仅NEW和INTERRUPT状态的认领单可删除
  - 解决思路：确认认领单状态为新建或驳回后再删除；若已审批通过需走撤销流程
