# 门店管理-门店档案-门店变更申请

> 本页面为低代码页面(hlod)，无独立前端源码，基于后端API梳理。

## 业务流程

门店变更申请用于对已建立的门店档案进行信息变更，如门店名称、面积、经营属性、装修风格、店长信息等。采用"变更前(H后缀)/变更后"双字段设计，便于审批时对比展示差异。提交审批后经OA审批通过，系统自动将变更后字段写回门店档案表（MKT_TERMINAL）。工作流编码为SUB_STORE_UPDATE_APPLY（"门店变更申请"），编码规则为AE.TERMINAL_MODIFY_CODE。当变更类型为撤店（terminalStat=2）时，系统强制校验该门店下所有装修申请单和验收报销单必须已审批通过或作废。

**核心流程：**
1. 用户选择需变更的门店，系统自动带出变更前信息（H后缀字段）
2. 用户修改变更后字段，保存草稿（stat=SAVE）
3. 提交审批，调用wfProcSubmit发起工作流（SUB_STORE_UPDATE_APPLY），状态变为RUN
4. 撤店时校验装修申请单和验收报销单状态（validTerminalStat）
5. OA审批通过后回调onWfComplete，将变更后字段写回MKT_TERMINAL，状态变为APPROVED
6. 审批驳回回调onWfBreak，状态变为REJECTED

```
开始 → 选择门店 → 带出变更前信息(H字段) → 修改变更后字段 → 保存草稿(SAVE) → 撤店校验 → 提交审批(RUN) → OA审批 → 通过？ → 是：写回门店档案(APPROVED) / 否：驳回(REJECTED) → 结束
```

- 上游支撑：门店档案（MKT_TERMINAL）、经销商主数据、事业部基础设置（DIVISION_BASE_SET）、门店装修申请单（FIN_FEE_APPLY_FINISHED_HEADER）、门店验收与报销单（FIN_FEE_CHECK_BX_HEADER）、工作流引擎、OA审批系统
- 下游影响：门店档案更新（MKT_TERMINAL）、门店装修申请、门店验收与报销

## 重点逻辑

### 重点逻辑1：双字段变更前/后设计

- **业务意义**：同时保存变更前和变更后数据，便于审批对比和回溯
- **具体逻辑描述**：
  - 变更后字段：无后缀，如custId、custCode、custName、addr、brand、terminalArea等
  - 变更前字段：H后缀，如custIdH、custCodeH、custNameH、addrH、brandH、terminalAreaH等
  - 审批通过后将变更后字段写回门店档案表

### 重点逻辑2：工作流审批驱动

- **业务意义**：门店变更需经OA审批通过后才能更新门店档案
- **具体逻辑描述**：
  - 工作流编码：SUB_STORE_UPDATE_APPLY（"门店变更申请"）
  - 提交审批：wfProcSubmit方法组装流程参数，调用workflowClient.startInstanceByFlowKey发起流程
  - 流程参数包含：terminalModifyId、operatCenterOrgId、salezoneOrgId、terminalStat、terminalType、tradeYear、startRealName、customerId
  - 审批状态：SAVE(保存) → RUN(审批中) → APPROVED(已审批) / REJECTED(已驳回)

### 重点逻辑3：撤店前置校验

- **业务意义**：撤店前确保该门店下所有关联单据已处理完毕，避免遗留未审完单据
- **具体逻辑描述**：
  - 当变更后terminalStat==2（撤店）时，validTerminalStat方法执行校验：
    1. 校验FinFeeApplyFinishedHeader（门店装修申请与进度更新单）必须全部为APPROVED或INTERRUPT状态
    2. 校验FinFeeCheckBxHeader（门店验收与报销单）必须全部为APPROVED或INTERRUPT状态
  - 校验不通过抛异常："请先审批通过/作废未审完的门店装修申请与进度更新单"

### 重点逻辑4：编码规则

- **业务意义**：自动生成门店变更单号，确保编码规范统一
- **具体逻辑描述**：
  - 编码规则：AE.TERMINAL_MODIFY_CODE
  - 通过codeRuleBuilder.generateCode生成，参数含divisionCode
  - 新增时自动生成，更新时不重新生成

### 重点逻辑5：审批通过写回门店档案

- **业务意义**：审批通过后将变更后数据同步到门店档案表
- **具体逻辑描述**：
  - onWfComplete方法：
    1. 查询变更申请单
    2. 查询门店档案MktTerminal
    3. 通过MktTerminalConvert.INSTANCE.toMktTerminalByModify将变更后字段映射到门店
    4. 回写terminalId、审计字段、checkTime、checkor
    5. 更新门店档案
    6. 单据状态置为APPROVED

#### 报错1：请先审批通过/作废未审完的门店装修申请与进度更新单
- **触发条件**：点击"提交"按钮，变更后terminalStat=2（撤店）时，validTerminalStat校验FinFeeApplyFinishedHeader存在状态非APPROVED/INTERRUPT的记录
- **逻辑分析**：撤店意味着门店退出运营，需确保该门店下所有装修申请与进度更新单已闭环（APPROVED=已审批或INTERRUPT=作废），避免撤店后遗留未审单据造成流程悬挂。校验逻辑按terminalId查询FIN_FEE_APPLY_FINISHED_HEADER，若存在hzApproveStatus不在(APPROVED,INTERRUPT)集合的记录即抛异常阻断提交。常见根因：门店下有草稿/审批中的装修单未处理。
- **排查SQL**：
  ```sql
  SELECT m.terminal_modify_id    AS 变更单ID,
         m.terminal_modify_code  AS 变更单号,
         m.terminal_id           AS 门店ID,
         m.terminal_code         AS 门店编码,
         f.fee_apply_id          AS 装修申请ID,
         f.fee_apply_no          AS 装修申请号,
         f.hz_approve_status     AS 装修单审批状态
  FROM   mkt_terminal_modify m
  JOIN   fin_fee_apply_finished_header f ON f.terminal_id = m.terminal_id
  WHERE  m.terminal_stat = 2
  AND    m.stat IN ('SAVE','RUN')
  AND    f.hz_approve_status NOT IN ('APPROVED','INTERRUPT')
  ORDER  BY m.create_time DESC;
  ```

#### 报错2：请先审批通过/作废未审完的门店验收与报销单
- **触发条件**：点击"提交"按钮，变更后terminalStat=2（撤店）时，validTerminalStat校验FinFeeCheckBxHeader存在状态非APPROVED/INTERRUPT的记录
- **逻辑分析**：与装修单校验同理，撤店前需确保该门店下所有验收与报销单已闭环。校验逻辑按terminalId查询FIN_FEE_CHECK_BX_HEADER，若存在hzApproveStatus不在(APPROVED,INTERRUPT)集合的记录即抛异常。常见根因：门店下有未审完的验收报销单（草稿/审批中/被驳回待处理），需先审批通过或作废后再提交撤店。
- **排查SQL**：
  ```sql
  SELECT m.terminal_modify_id    AS 变更单ID,
         m.terminal_modify_code  AS 变更单号,
         m.terminal_id           AS 门店ID,
         m.terminal_code         AS 门店编码,
         c.check_bx_id           AS 验收报销ID,
         c.check_bx_no           AS 验收报销号,
         c.hz_approve_status     AS 验收报销审批状态
  FROM   mkt_terminal_modify m
  JOIN   fin_fee_check_bx_header c ON c.terminal_id = m.terminal_id
  WHERE  m.terminal_stat = 2
  AND    m.stat IN ('SAVE','RUN')
  AND    c.hz_approve_status NOT IN ('APPROVED','INTERRUPT')
  ORDER  BY m.create_time DESC;
  ```

## 常见问题FAQ

**Q1：变更前和变更后数据如何保存？**
A：采用双字段设计，变更后字段无后缀（如addr），变更前字段以H结尾（如addrH）。选择门店时自动带出变更前数据，用户修改变更后数据。

**Q2：撤店有什么特殊校验？**
A：当变更后terminalStat=2（撤店）时，系统校验该门店下所有装修申请单（FinFeeApplyFinishedHeader）和验收报销单（FinFeeCheckBxHeader）必须全部为APPROVED或INTERRUPT状态，否则不允许提交。

**Q3：审批通过后会做什么？**
A：通过MktTerminalConvert.INSTANCE.toMktTerminalByModify将变更后字段映射到MktTerminal实体，更新门店档案表。

**Q4：编码规则是什么？**
A：AE.TERMINAL_MODIFY_CODE，通过codeRuleBuilder生成，参数含divisionCode。

**Q5：工作流编码是什么？**
A：SUB_STORE_UPDATE_APPLY（"门店变更申请"）。
