# 财务管理-调整单-广告费调整申请单

## 业务流程

### 业务流程图

```text
广告费调整申请单页面
        │
        ├── 查询列表 ──→ 查询ADS_FEE_ADJUST_IN_QUOTA表
        │
        ├── 新建/编辑 ──→ POST /ads-quotas/save
        │              └── 保存调整头信息和明细行
        │
        ├── 提交 ──→ 发起OA审批流程(SUB_ADJ_FEES_QUOTA)
        │              │
        │              ├── 审批通过 ──→ 更新HZ_APPROVE_STATUS为APPROVED
        │              └── 审批拒绝 ──→ 更新HZ_APPROVE_STATUS为REJECTED
        │
        └── 删除 ──→ POST /ads-quotas/batchDelete
```

### 上游依赖

| 上游模块 | 依赖类型 | 依赖说明 | 依赖成立条件 |
|---------|---------|---------|------------|
| 广告费余额查询 | 数据依赖 | 调整关联额度内广告费余额 | 余额数据已生成 |
| 交易公司配置 | 配置依赖 | 调整关联交易公司 | 交易公司已配置 |
| OA审批系统 | 服务依赖 | 提交后发起OA审批 | OA系统可用 |

### 下游影响

- 影响1：广告费余额
  - 审批通过后调整广告费余额，影响可用余额计算

- 影响2：额度外预算总额
  - 调整金额同步到额度外预算表的预算调整字段(OUTLIMIT_BUD_ADJ)

## 重点逻辑

### 重点逻辑1：OA审批流程 {审批流转}

- **业务意义**：广告费调整需经OA审批，确保调整合规

- **具体逻辑描述**

  - 第1点：提交时通过WorkflowCodeEnum.SUB_ADJ_FEES_QUOTA发起OA审批流程

  - 第2点：单据名称为"广告费调整申请"，通过oaBillRefRepository.selectByBillName推送OA

  - 第3点：审批通过后更新HZ_APPROVE_STATUS为APPROVED，审批拒绝更新为REJECTED

### 重点逻辑2：调整类型与扣减比例 {调整计算}

- **业务意义**：不同调整类型对应不同调整逻辑，扣减比例控制调整力度

- **具体逻辑描述**

  - 第1点：调整类型来源于词汇adjust_type，区分不同调整场景

  - 第2点：扣减比例控制调整金额占原余额的比例

  - 第3点：调整年度限定调整作用的预算年度

#### 按钮1：新增（列表页）

- **触发条件**：始终可用
- **执行逻辑**：打开新建页面，自动带出申请人和申请时间
- **接口调用**：无，仅前端操作

#### 按钮2：保存（编辑页）

- **触发条件**：编辑状态
- **执行逻辑**：保存调整头信息和明细行到ADS_FEE_ADJUST_IN_QUOTA
- **接口调用**：POST `/v1/{organizationId}/ads-quotas/save`
- **排查SQL**：

```sql
SELECT * FROM ADS_FEE_ADJUST_IN_QUOTA WHERE ADJUST_HEADER_ID = #{id};
```

#### 按钮3：删除（列表页）

- **触发条件**：选中未提交记录
- **执行逻辑**：批量删除选中的调整申请单
- **接口调用**：POST `/v1/{organizationId}/ads-quotas/batchDelete`
- **排查SQL**：

```sql
SELECT * FROM ADS_FEE_ADJUST_IN_QUOTA WHERE ADJUST_HEADER_ID IN (#{ids}) AND HZ_APPROVE_STATUS NOT IN ('RUN','APPROVED');
```

#### 状态机流转图


#### 报错1：交易公司不能为空
- **触发条件**：用户在新建/编辑页未选择交易公司直接点击保存
- **逻辑分析**：保存接口ads-quotas/save在写入ADS_FEE_ADJUST_IN_QUOTA前校验TRADING_COMPANY_ID非空。交易公司是广告费调整关联额度内余额和法人的前置条件，未选择交易公司将导致调整无法定位到具体余额账户，后续审批通过后也无法回写余额。校验在Controller层前置拦截，toast提示后阻断保存
- **排查SQL**：
  ```sql
  SELECT ADJUST_HEADER_ID, ADJUST_HEADER_NO, APPLICANT, TRADING_COMPANY_ID, TRADING_COMPANY_NAME,
         ADJUST_TYPE, HZ_APPROVE_STATUS
  FROM ADS_FEE_ADJUST_IN_QUOTA
  WHERE TRADING_COMPANY_ID IS NULL OR TRADING_COMPANY_NAME IS NULL;
  ```

#### 报错2：调整类型不能为空
- **触发条件**：用户未选择调整类型（来源词汇adjust_type）直接点击保存
- **逻辑分析**：调整类型决定调整的业务场景和扣减逻辑，不同ADJUST_TYPE对应不同处理分支。未选择调整类型将导致后续扣减比例（DEDUCTION_RATIO）应用逻辑无法确定，审批通过后余额调整方向和金额计算无依据。校验ADJUST_TYPE非空，toast提示后阻断保存
- **排查SQL**：
  ```sql
  SELECT ADJUST_HEADER_ID, ADJUST_HEADER_NO, TRADING_COMPANY_NAME, ADJUST_TYPE,
         ADJUST_YEAR, DEDUCTION_RATIO, HZ_APPROVE_STATUS
  FROM ADS_FEE_ADJUST_IN_QUOTA
  WHERE ADJUST_TYPE IS NULL;
  ```

#### 报错3：推送OA失败：广告费调整申请不存在
- **触发条件**：用户提交调整单后，doOaAudit方法中adsFeeAdjustInQuotaMapper.selectList查询返回空集合
- **逻辑分析**：提交后系统调用AdsFeeAdjustInQuotaServiceImpl.doOaAudit推送OA，先通过adsFeeAdjustInQuotaMapper.selectList按adjustHeaderId查询调整单数据。返回空集合（CollectionUtils.isEmpty(quotaList)）时抛出CommonException("推送OA失败：广告费调整申请不存在")。根因有三类：(1)调整单在提交后被其他用户删除；(2)adjustHeaderId传参错误；(3)数据权限过滤导致查询不到。需刷新列表确认调整单存在后重试
- **排查SQL**：
  ```sql
  SELECT ADJUST_HEADER_ID, ADJUST_HEADER_NO, APPLICANT, TRADING_COMPANY_NAME,
         ADJUST_TYPE, HZ_APPROVE_STATUS, WFID, HZ_INSTANCE_ID
  FROM ADS_FEE_ADJUST_IN_QUOTA
  WHERE ADJUST_HEADER_ID = #{adjustHeaderId};
  ```

#### 报错4：OA回传单号为空，请检查！
- **触发条件**：OA审批完成后回调doProcessOA方法，回传报文中adjustHeaderNo字段为空
- **逻辑分析**：doProcessOA方法接收OABillCallbackDTO，从中获取adjustHeaderNo（OA回传单号）。若StringUtils.isBlank(adjustHeaderNo)为true则抛出CommonException("OA回传单号为空，请检查！")。根因有二：(1)OA流程表单配置缺少"调整单号"字段映射；(2)OA回传报文格式异常。需检查OA流程SUB_ADJ_FEES_QUOTA的表单字段配置及单据映射关系
- **排查SQL**：
  ```sql
  -- 核查OA单据映射配置
  SELECT OABILL_ID, BILL_NAME, ENABLED
  FROM OA_BILL_REF
  WHERE BILL_NAME = '广告费调整申请';
  ```

#### 报错5：OA回传单号不存在，请检查！
- **触发条件**：OA审批回调时，按adjustHeaderNo查询ADS_FEE_ADJUST_IN_QUOTA表返回null
- **逻辑分析**：doProcessOA方法中通过adsFeeAdjustInQuotaMapper.selectByCondition按ADJUST_HEADER_NO查询调整单。若结果为空（adsFeeAdjustInQuota == null）则抛出CommonException("OA回传单号不存在，请检查！")。根因有三类：(1)OA回传的单号在系统中不存在（如测试环境OA回调到生产）；(2)调整单已被物理删除；(3)单号格式不匹配（如OA传带前缀的单号，系统中存储无前缀）。需核对OA回传单号与系统ADJUST_HEADER_NO字段
- **排查SQL**：
  ```sql
  SELECT ADJUST_HEADER_ID, ADJUST_HEADER_NO, HZ_APPROVE_STATUS, AUDIT_STAT,
         CALLBACK_SOURCE, HZ_INSTANCE_ID
  FROM ADS_FEE_ADJUST_IN_QUOTA
  WHERE ADJUST_HEADER_NO = #{adjustHeaderNo};
  ```

#### 报错6：请选择要删除的记录！
- **触发条件**：用户未选中任何调整单直接点击"删除"按钮
- **逻辑分析**：batchDelete方法接收adjustHeaderIds列表，若CollectionUtils.isEmpty(adjustHeaderIds)为true则抛出CommonException("请选择要删除的记录！")。前端列表页需选中至少一条记录才可触发删除操作。需在列表中勾选目标记录后重试
- **排查SQL**：
  ```sql
  -- 核查可删除的调整单（未提交或已拒绝状态）
  SELECT ADJUST_HEADER_ID, ADJUST_HEADER_NO, APPLICANT, HZ_APPROVE_STATUS
  FROM ADS_FEE_ADJUST_IN_QUOTA
  WHERE HZ_APPROVE_STATUS NOT IN ('RUN', 'APPROVED')
  ORDER BY APPLICANT_TIME DESC;
  ```

#### 报错7：网络请求失败
- **触发条件**：用户点击保存/提交/删除按钮，前端调用对应接口返回非2xx状态码或超时
- **逻辑分析**：本页面通过AdsFeeAdjustInQuotaController提供save/batchDelete接口，提交时通过oaSdkService.toDataOA推送OA系统。网络请求失败根因有四类：(1)ae-business服务未启动或宕机；(2)OA系统不可达，toDataOA调用超时或失败；(3)数据库连接异常；(4)网关或网络层故障。需先确认ae-business服务和OA系统连通性
- **排查SQL**：
  ```sql
  -- 核查调整单数据量
  SELECT HZ_APPROVE_STATUS, COUNT(*) AS 记录数
  FROM ADS_FEE_ADJUST_IN_QUOTA
  GROUP BY HZ_APPROVE_STATUS;
  ```

#### 报错8：权限不足
- **触发条件**：用户登录后进入广告费调整申请单页面，当前用户无对应交易公司的数据权限
- **逻辑分析**：本页面按交易公司维度查询，数据权限通过用户上下文控制可见交易公司范围。权限不足根因有二：(1)用户未分配对应交易公司的数据权限，查询时自动过滤导致空结果；(2)用户未分配菜单访问权限，页面入口不可见。需联系管理员在权限系统中分配对应交易公司数据权限
- **排查SQL**：
  ```sql
  -- 核查用户可访问的交易公司
  SELECT USER_ID, TRADING_COMPANY_ID, TRADING_COMPANY_NAME, ENABLED
  FROM USER_TRADING_COMPANY_AUTH
  WHERE USER_ID = #{userId};
  ```
