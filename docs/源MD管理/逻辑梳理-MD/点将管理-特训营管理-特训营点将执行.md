# 点将管理-特训营管理-特训营点将执行

> 后端代码位于 mbo-business 微服务（源码未包含在当前源码目录下），前端 API 路径前缀 `mlt/trainCampApply/*`。本菜单为特训营点将的执行跟踪页面，固定参数 `pageType=camp`。

## 业务流程

### 业务流程图

```
特训营点将审批通过
        |
        v
特训营点将执行列表(本页面) ──autoQuery──→ 加载执行中数据(pageType=camp)
        |
        ├──→ 查看申请 ──→ 跳转特训营详情页(/camp/detail/{specialTrainCampId}/view)
        ├──→ 查看确认书 ──→ queryPDF接口 ──→ window.open打开PDF
        ├──→ 特殊取消 ──→ 校验7天内且已生效 ──→ specialCancel接口
        ├──→ 结束执行 ──→ 弹窗填写实际时间+备注 ──→ endExecute接口
        ├──→ 同步OA ──→ pushOa接口
        ├──→ 同步FDD ──→ pushFdd接口
        └──→ 同步CRM ──→ pushCrm接口
```

### 全链路流程图

```
开始 → 查看已生效点将 → ★执行跟踪★ → 执行完成·更新状态 → 回写执行记录·CRM状态 → 结束
```

**执行原则**：执行环节只更新交付结果，不修改申请内容；名额、讲师或时间需调整时应回到点将管理处理。

### 上游依赖

| 上游模块 | 依赖类型 | 依赖说明 | 依赖成立条件 |
|---------|---------|---------|-------------|
| 特训营点将管理 | 数据库状态流转 | 审批通过后进入执行 | APPLY_APPROVAL_STATE=approved |
| 特训营管理 | 数据库关联 | 提供特训营基础数据 | CAMP_CODE 匹配 TRAIN_CAMP |
| HZERO权限服务 | permissionList权限编码 | 提供按钮权限校验 | 用户已分配对应权限编码 |
| HZERO值集服务 | lookupCode值集编码 | 提供特训营类型、状态值集 | 值集已发布且有效 |
| 讲师档案 | 关联查询 | 讲师信息 | LECTURER 匹配档案 |
| 经销商主档 | 关联查询 | 经销商信息 | DISTRIBUTOR_ID 匹配主档 |
| CRM系统 | REST API | CRM订单 | 经销商CRM映射存在 |

### 下游影响

- **特训营详情页**：查看申请跳转，openTab 新标签页打开。
- **特训营执行记录**：执行结果同步，数据库回写 TRAIN_CAMP_APPLY 表。
- **CRM订单状态**：订单完成联动，调用 pushCrm 接口同步。
- **讲师排期(占用)**：占用排期，数据库状态共享。
- **OA审批系统**：流程同步，调用 pushOa 接口推送。
- **法大大电子签约**：签约同步，调用 pushFdd 接口推送。

## 重点逻辑

### 重点逻辑1：只读跟踪

- **业务意义**：执行跟踪页面不修改点将申请原始内容，仅记录执行结果与状态推进，保证申请数据与执行结果分离。
- **具体逻辑描述**：
  - 本菜单仅提供查询、查看和执行结果回写功能。
  - 如需调整名额、讲师或时间，应回到特训营点将管理处理。
  - 列表查询固定传入 `pageType=camp`，`autoQuery=true` 自动加载。

### 重点逻辑2：数据来源

- **业务意义**：复用特训营点将申请实体，筛选已审批通过且进入执行阶段的申请，避免重复建模。
- **具体逻辑描述**：
  - 复用 TRAIN_CAMP_APPLY 表和 `mlt/trainCampApply/*` 接口。
  - 列表查询调用 `campApi.pageByLecturerCode` 接口，按讲师编码查询特训营执行数据。
  - 筛选条件 `APPLY_APPROVAL_STATE=approved` 且进入执行阶段。

### 重点逻辑3：查看申请跳转

- **业务意义**：跳转特训营管理详情页查看特训营基础信息，而非点将申请详情页。
- **具体逻辑描述**：
  - 点击"查看申请"按钮，跳转特训营详情页。
  - 路由：`/general/specialTrainingCamp/camp/detail/{specialTrainCampId}/view`。
  - 注意：跳转的是特训营管理详情页，而非点将申请详情页。

### 重点逻辑4：特训营时间展示

- **业务意义**：直观展示特训营计划时间范围，便于掌握执行周期。
- **具体逻辑描述**：
  - 列表"特训营时间"列通过 renderer 渲染。
  - 展示 `planStartTime` 至 `planEndTime` 的时间范围。

### 重点逻辑5：状态联动

- **业务意义**：执行状态与CRM订单状态联动，确保状态机自动推进。
- **具体逻辑描述**：
  - 执行状态与CRM订单状态联动。
  - 订单完成后自动更新执行状态为已完成。
  - 结束执行后点将状态推进为已执行，作为该期特训营交付的最终留痕。

### 重点逻辑6：同步外部系统

- **业务意义**：将执行结果同步至外部系统，保证多方数据一致。
- **具体逻辑描述**：
  - **同步OA**：调用 `POST mlt/trainCampApply/pushOa/{applyCode}` 推送OA审批流程。
  - **同步FDD**：调用 `POST mlt/trainCampApply/pushFdd/{applyCode}` 推送法大大签约。
  - **同步CRM**：调用 `POST mlt/trainCampApply/pushCrm/{applyCode}` 推送CRM订单。

### 保存校验

- 校验1：结束执行实际时间必填 —— 确保执行结果可留痕
  - **详细逻辑**：`realStartDate`、`realEndDate`、`endExecuteRemark` 必填，任一为空提示对应报错信息。
  - **系统体现**：前端 `endExecuteFormDS.validate()` 校验，后端二次校验。
  - **排查SQL**：
    ```sql
    SELECT tca.APPLY_CODE AS 申请编码, tca.REAL_START_DATE AS 实际开始时间,
           tca.REAL_END_DATE AS 实际结束时间, tca.END_EXECUTE_REMARK AS 结束备注
    FROM TRAIN_CAMP_APPLY tca
    WHERE tca.ORDER_LECTURE_STATE = 'executed'
      AND (tca.REAL_START_DATE IS NULL OR tca.REAL_END_DATE IS NULL
           OR tca.END_EXECUTE_REMARK IS NULL);
    ```

### 提交校验

- 校验1：特殊取消时机校验 —— 防止临近开课取消造成资源浪费
  - **详细逻辑**：校验 `1 <= timeDiff <= 7` 且 `approvalState === 'fdd_sign'` 且未重复发起取消。
  - **系统体现**：前端时间差值计算与状态校验，后端二次校验。
  - **排查SQL**：
    ```sql
    SELECT tca.APPLY_CODE AS 申请编码, tca.CAMP_NAME AS 特训营名称,
           TO_CHAR(tca.PLAN_START_TIME, 'YYYY-MM-DD') AS 开始时间,
           tca.APPROVAL_STATE AS 审核状态,
           ROUND(tca.PLAN_START_TIME - SYSDATE) AS 距开始天数
    FROM TRAIN_CAMP_APPLY tca
    WHERE tca.APPROVAL_STATE = 'fdd_sign'
      AND tca.PLAN_START_TIME > SYSDATE
      AND tca.PLAN_START_TIME <= SYSDATE + 7;
    ```

### 状态机

```
待执行 ──开始执行──→ 执行中 ──结束执行──→ 已执行
                        |
                        └──特殊取消──→ 已取消
```

| 当前状态 | 触发动作 | 目标状态 |
|---------|---------|---------|
| 待执行 | 开始执行 | 执行中 |
| 执行中 | 结束执行 | 已执行 |
| 执行中 | 特殊取消 | 已取消 |

### 排查SQL

```sql
-- 查询特训营点将执行列表
SELECT
  tca.APPLY_CODE    AS 申请编码,
  tca.DISTRIBUTOR_NAME AS 申请人,
  tca.CAMP_NAME     AS 特训营名称,
  tca.LECTURER      AS 培训师,
  tca.ORDER_LECTURE_STATE AS 点将状态,
  tca.APPROVAL_STATE AS 审核状态,
  TO_CHAR(tca.PLAN_START_TIME, 'YYYY-MM-DD') AS 开始时间,
  TO_CHAR(tca.PLAN_END_TIME, 'YYYY-MM-DD') AS 结束时间,
  tca.CRM_ORDER_CODE AS CRM单号,
  tca.CRM_ORDER_STATUS AS CRM订单状态
FROM TRAIN_CAMP_APPLY tca
WHERE tca.APPROVAL_STATE = 'approved'
ORDER BY tca.UPDATE_DATE DESC;

-- 查询执行中的特训营点将
SELECT
  tca.APPLY_CODE    AS 申请编码,
  tca.CAMP_NAME     AS 特训营名称,
  tca.LECTURER      AS 培训师,
  tca.ORDER_LECTURE_STATE AS 点将状态
FROM TRAIN_CAMP_APPLY tca
WHERE tca.ORDER_LECTURE_STATE = 'executing'
ORDER BY tca.PLAN_START_TIME DESC;

-- 查询可发起特殊取消的申请（7天内且已法大大签约）
SELECT
  tca.APPLY_CODE    AS 申请编码,
  tca.CAMP_NAME     AS 特训营名称,
  TO_CHAR(tca.PLAN_START_TIME, 'YYYY-MM-DD') AS 开始时间,
  tca.APPROVAL_STATE AS 审核状态,
  tca.CANCEL_APPROVAL_STATE AS 取消审核状态,
  ROUND(tca.PLAN_START_TIME - SYSDATE) AS 距开始天数
FROM TRAIN_CAMP_APPLY tca
WHERE tca.APPROVAL_STATE = 'fdd_sign'
  AND tca.PLAN_START_TIME > SYSDATE
  AND tca.PLAN_START_TIME <= SYSDATE + 7
  AND (tca.CANCEL_APPROVAL_STATE IS NULL
       OR tca.CANCEL_APPROVAL_STATE IN ('reject', 'oa_reject'));
```

#### 报错1：请选择一条数据
- **触发条件**：点击查看申请、查看确认书、特殊取消、结束执行、同步OA、同步FDD、同步CRM等行操作按钮时，未选择数据或选择了多行
- **逻辑分析**：前端在执行单选操作前校验选中行数量，若 selectedRows.length ≠ 1 则阻止操作并提示"请选择一条数据"。单选操作需要明确的目标申请，未选择时无法确定操作对象，多选时操作对象不唯一
- **排查SQL**：
  ```sql
  SELECT APPLY_CODE AS 申请编码,
         DISTRIBUTOR_NAME AS 申请人,
         CAMP_NAME AS 特训营名称,
         ORDER_LECTURE_STATE AS 点将状态,
         APPROVAL_STATE AS 审核状态
  FROM TRAIN_CAMP_APPLY
  WHERE APPROVAL_STATE = 'approved'
  ORDER BY UPDATE_DATE DESC;
  ```

#### 报错2：只有在培训开始前七天内且已生效的单据才可以发起取消申请！
- **触发条件**：点击特殊取消按钮时，不满足"培训开始前1-7天内且已法大大签约"条件
- **逻辑分析**：前端执行多重校验：①计算时间差值 timeDiff = (PLAN_START_TIME - nowTime) / (24*60*60*1000)，校验 1 <= timeDiff <= 7（特训营开始前1-7天内）；②校验 APPROVAL_STATE = 'fdd_sign'（已法大大签约生效）。任一校验不通过则提示"只有在培训开始前七天内且已生效的单据才可以发起取消申请！"。此校验限制取消时机，避免临近开课取消造成资源浪费，同时要求单据已生效具备业务合法性
- **排查SQL**：
  ```sql
  SELECT APPLY_CODE AS 申请编码,
         CAMP_NAME AS 特训营名称,
         TO_CHAR(PLAN_START_TIME,'YYYY-MM-DD') AS 特训营开始时间,
         APPROVAL_STATE AS 审核状态,
         ROUND(PLAN_START_TIME - SYSDATE) AS 距开始天数
  FROM TRAIN_CAMP_APPLY
  WHERE APPROVAL_STATE = 'approved'
    AND (PLAN_START_TIME <= SYSDATE
         OR PLAN_START_TIME > SYSDATE + 7
         OR APPROVAL_STATE <> 'fdd_sign');
  ```

#### 报错3：该单据已发起取消申请，不可重复发起！

#### 报错9：权限不足
- **触发条件**：点击查看申请、特殊取消、结束执行、同步OA/FDD/CRM等按钮时，当前用户无对应 permissionList 权限码
- **逻辑分析**：前端 Button 组件通过 permissionList 配置权限码，HZERO 框架校验当前用户角色是否包含该权限码，未包含则按钮不可见或禁用。若强制调用接口，后端也会校验权限返回403。需联系管理员配置对应角色权限
- **排查SQL**：
  ```sql
  SELECT U.USER_NAME AS 用户名, R.ROLE_NAME AS 角色名, P.PERMISSION_CODE AS 权限码
  FROM SYS_USER U
  LEFT JOIN SYS_USER_ROLE UR ON U.USER_ID = UR.USER_ID
  LEFT JOIN SYS_ROLE R ON UR.ROLE_ID = R.ROLE_ID
  LEFT JOIN SYS_ROLE_PERMISSION RP ON R.ROLE_ID = RP.ROLE_ID
  LEFT JOIN SYS_PERMISSION P ON RP.PERMISSION_ID = P.PERMISSION_ID
  WHERE P.PERMISSION_CODE LIKE '%camp_general_execute%' ORDER BY U.USER_NAME;
  ```

### 常见问题

**Q1：执行跟踪页面能否修改数据？**
A：不能，本页面为只读跟踪页面，仅提供查询查看和执行结果回写功能。

**Q2：执行列表与点将管理列表有什么区别？**
A：点将管理列表展示所有状态的申请，执行列表仅展示已审批通过进入执行阶段的申请（`pageType=camp`）。

**Q3：查看申请跳转的是哪个页面？**
A：跳转特训营管理详情页 `/camp/detail/{specialTrainCampId}/view`，而非点将申请详情页。

| 问题 | 排查方式 |
|------|---------|
| 列表无数据 | 检查 pageByLecturerCode 接口，确认有执行中的特训营数据 |
| 查看申请跳转失败 | 检查 specialTrainCampId 是否存在，特训营详情页路由配置 |
| 特训营时间显示异常 | 检查 planStartTime 和 planEndTime 字段是否正确返回 |
| 特殊取消按钮校验不通过 | 检查 PLAN_START_TIME 与当前时间差值是否在1-7天，APPROVAL_STATE 是否为 fdd_sign |
