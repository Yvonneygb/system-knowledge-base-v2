# 门店管理-门店报表-店面额度内兑现余额表

> 本页面为低代码页面(hlod)，无独立前端源码，基于后端API梳理。

## 业务流程

店面额度内兑现余额表用于查询门店装修额度内兑现的余额情况，包括期初可兑现金额、本期兑现金额、期末未兑现金额等。报表按经销商、交易公司、事业部、支付方式等维度汇总额度内兑现余额数据，数据来源于兑现表（FIN_FEE_TERMINAL_CASHOUT）和验收报销单头表（FIN_FEE_CHECK_BX_HEADER）的关联查询。本页面为纯查询报表，仅支持查看和导出，不支持新增、修改、删除等写操作。

**核心流程：**
1. 用户进入店面额度内兑现余额表页面
2. 填写查询条件（事业部、交易公司、经销商、开票单位、支付方式、时间范围等）
3. 点击查询，调用后端接口分页返回额度内兑现余额数据
4. 用户查看报表数据，可导出Excel归档

```
开始 → 设定查询条件 → 点击查询 → 后端查询FIN_FEE_TERMINAL_CASHOUT+FIN_FEE_CHECK_BX_HEADER关联 → 计算期初/本期/期末金额 → 返回余额数据 → 查看报表/导出Excel → 结束
```

- 上游支撑：额度内兑现单（FIN_FEE_TERMINAL_CASHOUT）、门店验收与报销单（FIN_FEE_CHECK_BX_HEADER）、客户（CUSTOMER）、事业部基础设置（DIVISION_BASE_SET）、hlod报表引擎
- 下游影响：额度内兑现余额分析、期初/期末金额核对、Excel导出归档、内部管理决策参考

## 重点逻辑

### 重点逻辑1：纯报表查询页面【只读查询】

- **业务意义**：供内部人员查询门店额度内兑现的余额情况，了解额度内兑现的资金使用分布
- **具体逻辑描述**：
  - 本页面为hlod低代码报表页面，无独立前端源码
  - 仅提供查询和导出功能，不支持新增、修改、删除操作
  - 数据来源于兑现表和验收报销单头表的关联查询

### 重点逻辑2：期初/期末金额计算逻辑

- **业务意义**：通过期初可兑现金额、本期兑现金额计算期末未兑现金额，反映额度内兑现余额变化
- **具体逻辑描述**：
  - 期初可兑现金额（begin_Cashout_Amt）= 可报销金额(不含税) - 期初已兑现金额 = IN_CAN_NOT_TAX_BX_AMT - COALESCE(ttt.cashout_amt, 0)
  - 期初已兑现金额（ttt.cashout_amt）：统计ledger_date < startTime的已兑现金额
  - 本期兑现金额（in_This_Cashout_Amt）：统计startTime <= ledger_date <= endTime的已兑现金额
  - 期末未兑现金额（end_Cashout_Amt）= 期初可兑现金额 - 本期兑现金额 = begin_Cashout_Amt - in_This_Cashout_Amt

### 重点逻辑3：三段子查询统计

- **业务意义**：通过三段子查询分别统计期初、本期和历史兑现金额
- **具体逻辑描述**：
  - 子查询t：统计ledger_date <= endTime的验收报销单汇总数据（申请补贴总额、验收补贴总额、可报销金额）
  - 子查询tt：统计startTime <= ledger_date <= endTime的本期兑现金额
  - 子查询ttt：统计ledger_date < startTime的期初已兑现金额
  - 通过organization_id、trading_company_name、billing_unit_code、pay_type、cust_id、check_bx_code关联

### 重点逻辑4：时间格式校验

- **业务意义**：确保查询时间格式正确
- **具体逻辑描述**：
  - 开始/结束时间使用正则校验 `^\d{4}-\d{2}-\d{2}$`，必须为YYYY-MM-DD格式
  - SQL中使用TO_DATE转换：`TO_DATE(#{params.startTime}, 'yyyy-MM-dd')`、`TO_DATE(#{params.endTime}, 'yyyy-MM-dd')`

#### 报错1：开始时间格式必须为YYYY-MM-DD
- **触发条件**：点击"查询"按钮，调用余额表查询接口时，DTO中startTime字段值不符合正则 `^\d{4}-\d{2}-\d{2}$`
- **逻辑分析**：报表通过三段子查询统计期初已兑现金额（ledger_date < startTime）、本期兑现金额（startTime <= ledger_date <= endTime），需用TO_DATE转换字符串为日期。若前端日期选择器异常返回非标准格式（如YYYY/MM/DD或带时分秒）、或手工拼接参数格式错误，@Pattern注解校验失败抛出异常，查询无法执行。startTime用于界定期初统计的上界，格式错误会导致期初/本期金额计算错误或Oracle抛出ORA-01861。
- **排查SQL**：
  ```sql
  SELECT check_bx_code        AS 验收报销单号,
         cust_code             AS 经销商编码,
         pay_type              AS 支付方式,
         ledger_date           AS 台账日期,
         in_this_cashout_amt   AS 额度内本次兑现金额
  FROM   fin_fee_terminal_cashout
  WHERE  ledger_date IS NOT NULL
  ORDER  BY ledger_date DESC;
  ```

#### 报错2：结束时间格式必须为YYYY-MM-DD
- **触发条件**：点击"查询"按钮，调用余额表查询接口时，DTO中endTime字段值不符合正则 `^\d{4}-\d{2}-\d{2}$`
- **逻辑分析**：endTime用于限定本期兑现统计的下界（startTime <= ledger_date <= endTime）及期初统计的下界（ledger_date < startTime的补集）。SQL中通过 `TO_DATE(#{params.endTime}, 'yyyy-MM-dd')` 转换。若endTime格式错误，@Pattern注解校验失败抛出异常。若绕过校验传入非法字符串，TO_DATE转换会抛出Oracle格式错误，故前置正则校验提前拦截。
- **排查SQL**：
  ```sql
  SELECT check_bx_code        AS 验收报销单号,
         cust_code             AS 经销商编码,
         pay_type              AS 支付方式,
         ledger_date           AS 台账日期,
         in_this_cashout_amt   AS 额度内本次兑现金额
  FROM   fin_fee_terminal_cashout
  WHERE  ledger_date >= SYSDATE - 30
  ORDER  BY ledger_date DESC;
  ```

#### 报错3：网络请求失败/接口调用异常
- **触发条件**：点击"查询"或"导出"按钮，调用POST /v1/{organizationId}/terminalReport/mkt-terminal-face-cashIn-list/search接口时，前端未收到响应或收到非2xx状态码（如500、502、504）
- **逻辑分析**：本页面为hlod低代码报表页面，查询依赖后端TerminalReportController.mktTerminalFaceCashInListSearch接口分页查询FIN_FEE_TERMINAL_CASHOUT关联FIN_FEE_CHECK_BX_HEADER，通过三段子查询统计期初/本期/期末金额。若后端ae-report服务未启动、Oracle数据库连接异常、三段子查询关联条件不匹配导致慢SQL、TO_DATE转换失败抛出ORA-01861、网络中断、或网关转发失败，均会导致接口调用异常。需检查后端服务健康状态、数据库连接、网络连通性。
- **排查SQL**：
  ```sql
  SELECT COUNT(*)            AS 兑现单总数,
         MIN(ledger_date)    AS 最早台账日期,
         MAX(ledger_date)    AS 最晚台账日期
  FROM   fin_fee_terminal_cashout
  WHERE  ledger_date IS NOT NULL;
  ```

#### 报错4：权限不足/未登录
- **触发条件**：页面加载或点击"查询"/"导出"按钮时，接口返回401未授权或403禁止访问，或前端路由守卫拦截
- **逻辑分析**：本报表接口声明@Permission(level = ResourceLevel.ORGANIZATION)，要求用户具备组织级权限。若用户未登录（token过期/丢失）、或当前角色未分配该报表菜单权限、或organizationId路径参数与用户所属组织不匹配，均会触发权限校验失败。hlod低代码页面通过路由配置和接口权限双重校验，任一环节失败均阻断访问。需重新登录或联系管理员分配报表查看权限。
- **排查SQL**：
  ```sql

  FROM   dual;
  ```

#### 报错5：导出失败：网络异常
- **触发条件**：点击"导出"按钮，导出Excel过程中网络中断、后端响应超时或Excel文件流传输中断
- **逻辑分析**：导出接口将当前查询条件下的额度内兑现余额数据全量查询后生成Excel文件流返回。若查询数据量较大导致响应超时、或生成Excel过程中内存溢出、或网络不稳定导致文件流中断、或浏览器下载被拦截，均会触发导出失败。需重试导出或缩小查询条件（如限定台账日期范围、事业部）减少数据量。
- **排查SQL**：
  ```sql
  SELECT TO_CHAR(ledger_date, 'YYYY') AS 年度,
         COUNT(*)                     AS 兑现单数量
  FROM   fin_fee_terminal_cashout
  WHERE  ledger_date IS NOT NULL
  GROUP  BY TO_CHAR(ledger_date, 'YYYY')
  ORDER  BY 年度 DESC;
  ```

## 常见问题FAQ

**Q1：期初可兑现金额如何计算？**
A：期初可兑现金额 = 可报销金额(不含税) - 期初已兑现金额。期初已兑现金额统计ledger_date < startTime的兑现金额合计。

**Q2：期末未兑现金额如何计算？**
A：期末未兑现金额 = 期初可兑现金额 - 本期兑现金额。本期兑现金额统计startTime <= ledger_date <= endTime的兑现金额合计。

**Q3：报表是否支持导出？**
A：是，支持导出Excel。

**Q4：报表是否支持新增/修改/删除？**
A：不支持，本页面为纯查询报表，仅支持查看和导出。
