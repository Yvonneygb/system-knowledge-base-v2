### 流程说明

1. **列表查询**：查看紧急要货单列表，支持按单号、要货单号、审批状态筛选
2. **详情查看**：查询头信息+明细行+库存保留记录+提货时间变更历史+插单记录+被插单记录
3. **流程发起前校验**：校验对应要货单状态不能为制单（`ORDER_STAT in (1, 11)`）或`HZ_APPROVE_STATUS='NE'`
4. **审批流程**：触发工作流`EPM_URGENT_ORDER`，审批通过后回调`wfComplete`
5. **库存占用**：审批通过后向ERP发送库存占用申请（`StockReserveApply`），ERP返回后更新各行接口状态和库存保留记录

## 重点逻辑

### 重点逻辑1：流程发起前校验

- **业务意义**：确保要货单状态正常后才允许发起紧急要货审批流程
- **具体逻辑描述**：
  1. 查询对应要货单的`ORDER_STAT`和`HZ_APPROVE_STATUS`
  2. 若`ORDER_STAT IN (1, 11)`（制单或EBS退回）或`HZ_APPROVE_STATUS = 'NE'`，则流程失败
  3. 抛出异常"紧急要货订单对应的要货单状态为EBS退回或者制单状态，流程失败!"

### 重点逻辑2：审批通过后库存占用

- **业务意义**：审批通过后向ERP发送库存占用申请，优先锁定可用库存
- **具体逻辑描述**：
  1. 更新审批日期`DATE_APPROVAL`为当前时间
  2. 获取库存保留有效期系统参数`VALIDITY_OF_STOCK_RETENTION`
  3. 更新所有明细行的有效期`VALIDITY_TERM`
  4. 调用`doReserveApply`向ERP发送库存占用申请，传入CRM订单头ID、行ID、要货数量、发货基地、提货时间等

### 重点逻辑3：ERP响应处理

- **业务意义**：解析ERP返回的库存占用结果，更新本地数据
- **具体逻辑描述**：
  1. 解析ERP返回的`X_RESERVE_OUT_TBL_ITEM`中的`CRM_LINE_ID`、`RESERVED_QUANTITY`、`PRE_RESERVED_QUANTITY`、`RESERVED_DATE`、`EFFECTIVE_DATE_TO`
  2. 插入`EPM_URGENT_ORDER_LINE_STOCK`库存保留记录
  3. 更新`EPM_URGENT_ORDER_LINE`的已占用数量、预占数量、有效期至、接口状态和信息

### 重点逻辑4：取消判断与接口重推

- **业务意义**：处理已取消的行和支持接口重推
- **具体逻辑描述**：
  1. 若对应要货单行已被取消（`IS_CANCEL=2`），则不发送ERP请求，直接标记接口状态为E，信息为"该要货信息已取消"
  2. 已失败的行（`INTF_RESULT != 'S'`）可重新调用`doReserveApply`进行重推
  3. 已成功的行（`INTF_RESULT = 'S'`）跳过，不重复处理

### 重点逻辑5：详情多维度数据展示

- **业务意义**：在详情页展示紧急要货单的全生命周期数据
- **具体逻辑描述**：
  1. 紧急要货单头信息
  2. 明细行（`EPM_URGENT_ORDER_LINE`）
  3. 库存保留记录（`EPM_URGENT_ORDER_LINE_STOCK`）
  4. 提货时间变更历史（`PICKUP_DATE_CHANGE_LIST`）
  5. 插单记录（`EPM_URGENT_ADJUST`，`ADJUST_TYPE='+'`，作为申请方）
  6. 被插单记录（`EPM_URGENT_ADJUST`，`ADJUST_TYPE='-'`，作为调整方）

### 提交校验

- 校验1：要货单状态校验 —— 确保要货单状态正常后才允许发起流程
  - **详细逻辑**：查询对应要货单的`ORDER_STAT`和`HZ_APPROVE_STATUS`，若`ORDER_STAT IN (1, 11)`或`HZ_APPROVE_STATUS = 'NE'`则阻断
  - **系统体现**：`EpmUrgentOrderServiceImpl.workFlowStartVolidate`，抛出`CommonException("紧急要货订单对应的要货单状态为EBS退回或者制单状态，流程失败!")`
  - **排查SQL**：
    ```sql
    SELECT h.ORDER_STAT, h.HZ_APPROVE_STATUS
    FROM EPM_URGENT_ORDER eo
    LEFT JOIN SA_OUT_BILL_HEAD h ON eo.SA_OUT_BILL_HEAD_ID = h.SA_OUT_BILL_HEAD_ID
    WHERE eo.URGENT_ORDER_ID = :urgentOrderId;
    ```

- 校验2：要货单行取消校验 —— 确保未取消的行才发送ERP请求
  - **详细逻辑**：若对应要货单行`IS_CANCEL=2`，不发送ERP请求，标记`INTF_RESULT='E'`，`INTF_INFO="该要货信息已取消"`
  - **系统体现**：`EpmUrgentOrderServiceImpl.doReserveApply`中的逐行处理逻辑
  - **排查SQL**：
    ```sql
    SELECT SA_OUT_BILL_LINE_ID, IS_CANCEL
    FROM SA_OUT_BILL_LINE
    WHERE SA_OUT_BILL_LINE_ID = :saOutBillLineId;
    ```

#### 报错1：紧急要货订单对应的要货单状态为EBS退回或者制单状态，流程失败!
- **触发条件**：提交紧急要货流程时，要货单ORDER_STAT为1(制单)或11(EBS退回)或HZ_APPROVE_STATUS='NE'
- **逻辑分析**：workFlowStartVolidate方法中校验要货单状态，若ORDER_STAT IN (1, 11)或HZ_APPROVE_STATUS='NE'则抛出阻断性报错。需先确认要货单状态正常后再发起流程
- **排查SQL**：
  ```sql
  SELECT obh.SA_OUT_BILL_HEAD_ID, obh.SA_SALEBILLNO, obh.ORDER_STAT, obh.HZ_APPROVE_STATUS,
         euoh.URGENT_ORDER_HEAD_ID, euoh.URGENT_ORDER_CODE
  FROM EPM_URGENT_ORDER_HEAD euoh
  JOIN SA_OUT_BILL_HEAD obh ON euoh.SA_OUT_BILL_HEAD_ID = obh.SA_OUT_BILL_HEAD_ID
  WHERE euoh.URGENT_ORDER_HEAD_ID = :urgentOrderHeadId
    AND (obh.ORDER_STAT IN (1, 11) OR obh.HZ_APPROVE_STATUS = 'NE')
  -- 查出要货单状态异常的紧急要货单
  ```

#### 报错2：该要货信息已取消
- **触发条件**：提交紧急要货流程时，要货单行IS_CANCEL=2(已取消)
- **逻辑分析**：提交校验中按SA_OUT_BILL_LINE_ID查询要货单行，若IS_CANCEL=2则系统自动将此申请记录置为失效，不发送ERP请求
- **排查SQL**：
  ```sql
  SELECT obl.SA_OUT_BILL_LINE_ID, obl.SA_OUT_BILL_HEAD_ID, obl.ITEM_CODE, obl.IS_CANCEL,
         euol.URGENT_ORDER_LINE_ID, euol.IS_CANCEL AS 紧急要货行取消状态
  FROM EPM_URGENT_ORDER_LINE euol
  JOIN SA_OUT_BILL_LINE obl ON euol.SA_OUT_BILL_LINE_ID = obl.SA_OUT_BILL_LINE_ID
  WHERE euol.URGENT_ORDER_HEAD_ID = :urgentOrderHeadId
    AND obl.IS_CANCEL = 2
  -- 查出已取消的要货单行
  ```

#### 报错3：库存占用接口返回失败
- **触发条件**：提交紧急要货后调用ERP库存占用接口失败
- **逻辑分析**：doReserveApply方法中调用ERP接口，若返回失败则更新INTF_RESULT='E'和INTF_INFO记录错误信息。可通过接口重推按钮重新触发，已成功的行不会重复处理
- **排查SQL**：

  ```sql
  SELECT euol.URGENT_ORDER_LINE_ID, euol.URGENT_ORDER_HEAD_ID, euol.ITEM_CODE,
         euol.INTF_RESULT, euol.INTF_INFO, euol.RESERVED_QTY, euol.PRE_RESERVED_QTY
  FROM EPM_URGENT_ORDER_LINE euol
  WHERE euol.URGENT_ORDER_HEAD_ID = :urgentOrderHeadId
    AND euol.INTF_RESULT = 'E'
  -- 查出ERP接口失败的行及错误信息
  ```

#### 报错4：请至少使用一种参数传递方式
- **触发条件**：调用doReserveApply方法时，urgentOrderId、idList、epmUrgentOrderLines三个参数均为空
- **逻辑分析**：doReserveApply方法开头校验参数传递方式唯一性，统计三个参数是否非空的数量count，若count=0则抛出RuntimeException("请至少使用一种参数传递方式")。该报错通常由接口重推时未正确传参导致。需检查调用doReserveApply时是否传入了urgentOrderId或idList或epmUrgentOrderLines中的至少一个
- **排查SQL**：
  ```sql
  SELECT euoh.URGENT_ORDER_HEAD_ID, euoh.URGENT_ORDER_CODE, euoh.HZ_APPROVE_STATUS
  FROM EPM_URGENT_ORDER_HEAD euoh
  WHERE euoh.URGENT_ORDER_HEAD_ID = :urgentOrderId
  -- 确认紧急要货单存在，检查调用参数是否正确传递
  ```

#### 报错5：请勿同时使用多种参数传递方式
- **触发条件**：调用doReserveApply方法时，urgentOrderId、idList、epmUrgentOrderLines三个参数中同时有多个非空
- **逻辑分析**：doReserveApply方法校验参数传递方式唯一性，若count>1则抛出RuntimeException("请勿同时使用多种参数传递方式")。该报错通常由接口重推逻辑错误导致同时传入多种参数。需确保仅使用一种参数传递方式：单头ID重推用urgentOrderId，多头ID重推用idList，指定行重推用epmUrgentOrderLines
- **排查SQL**：
  ```sql
  SELECT euoh.URGENT_ORDER_HEAD_ID, euoh.URGENT_ORDER_CODE, euoh.HZ_APPROVE_STATUS
  FROM EPM_URGENT_ORDER_HEAD euoh
  WHERE euoh.URGENT_ORDER_HEAD_ID = :urgentOrderId
  -- 确认仅使用一种参数传递方式
  ```

#### 报错6：未知错误
- **触发条件**：doReserveApply方法中，headIds和lineIds均为空集合时触发
- **逻辑分析**：doReserveApply方法在初始化headIds或lineIds后，校验若headIds和lineIds均为空则抛出CommonException("未知错误")。该报错通常由参数传递逻辑异常导致，正常流程不会触发。需检查调用参数传递逻辑
- **排查SQL**：
  ```sql
  SELECT euoh.URGENT_ORDER_HEAD_ID, euoh.URGENT_ORDER_CODE
  FROM EPM_URGENT_ORDER_HEAD euoh
  WHERE euoh.URGENT_ORDER_HEAD_ID = :urgentOrderId
     OR euoh.URGENT_ORDER_HEAD_ID IN (:idList)
  -- 确认参数对应的紧急要货单存在
  ```

#### 报错7：库存占用ERP返回数据校验失败
- **触发条件**：审批通过后调用ERP库存占用接口成功(L_RET_STATUS=S)，但X_RESERVE_OUT_TBL_ITEM数据校验失败
- **逻辑分析**：doReserveApply方法中ERP返回成功后，reserveFeedbackProcess方法逐行校验ERP返回数据，任一校验失败则收集错误信息并抛出CommonException(Joiner.on("；").join(errors))。具体校验项包括：(1)CRM_LINE_ID为空→"第N行未传递订单行ID"；(2)CRM_LINE_ID在紧急要货行中不存在→"订单行[xxx]未申请紧急要货"；(3)RESERVED_QUANTITY为空→"未传递[占用数量: RESERVED_QUANTITY]"；(4)PRE_RESERVED_QUANTITY为空→"未传递[预占用数量: PRE_RESERVED_QUANTITY]"；(5)RESERVED_DATE无法解析→"[占用时间: RESERVED_TIME]不是有效时间"；(6)EFFECTIVE_DATE_TO为空或无法解析→"未传递[有效期至: EFFECTIVE_DATE_TO]"。该报错为阻断性，会中断库存保留记录写入
- **排查SQL**：
  ```sql
  SELECT euol.URGENT_ORDER_LINE_ID, euol.URGENT_ORDER_HEAD_ID, euol.ITEM_CODE,
         euol.EXT_SA_OUT_BILL_LINE_ID, euol.INTF_RESULT, euol.INTF_INFO
  FROM EPM_URGENT_ORDER_LINE euol
  WHERE euol.URGENT_ORDER_HEAD_ID = :urgentOrderHeadId
    AND euol.INTF_RESULT = 'E'
    AND euol.INTF_INFO LIKE '%未传递%'
  -- 查出ERP返回数据校验失败的行及具体错误信息
  ```

**Q1：为什么流程发起失败，提示"紧急要货订单对应的要货单状态为EBS退回或者制单状态"？**
A：对应要货单的`ORDER_STAT`为1（制单）或11（EBS退回），或`HZ_APPROVE_STATUS='NE'`，需先确认要货单状态正常后再发起流程。

**Q2：库存占用接口返回失败怎么处理？**
A：明细行的`INTF_RESULT`会被标记为'E'，`INTF_INFO`记录错误信息。可通过重新触发`doReserveApply`进行接口重推，已成功的行不会重复处理。

**Q3：某行提示"该要货信息已取消"是什么原因？**
A：对应的要货单行（`SA_OUT_BILL_LINE`）的`IS_CANCEL=2`，表示该行已被取消，系统自动将此申请记录置为失效，不发送请求至ERP。

**Q4：详情页面展示哪些关联数据？**
A：五类关联数据：(1) 紧急要货明细行；(2) 库存保留记录；(3) 提货时间变更历史；(4) 插单记录（作为申请方）；(5) 被插单记录（作为调整方）。
