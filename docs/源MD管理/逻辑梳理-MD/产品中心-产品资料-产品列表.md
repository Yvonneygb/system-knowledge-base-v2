## 业务流程

### 业务流程图

```text
产品数据来源（EBS/旧CRM同步）
        │
        ▼
   LNK_PROD表（产品主数据）
        │
        ├─── 内部用户（userType=E）──→ 按事业部+价目表过滤 ──→ 商品检索Tab / 配件&其它Tab
        │                                                    │
        │                                                    ├─── 查询产品列表
        │                                                    ├─── 导出（内部用户VO）
        │                                                    ├─── 产品图册-导入
        │                                                    ├─── 产品附件-导入
        │                                                    └─── 点击产品编码 → 跳转产品详情
        │
        └─── 外部用户（userType=D）─→ 按经销商渠道+价目表+生命状态过滤 ──→ 商品检索Tab / 其它Tab
                                                         │
                                                         ├─── 查询产品列表（隐藏部分字段）
                                                         ├─── 导出（外部用户VO）
                                                         └─── 点击产品编码 → 跳转产品详情
```

### 上游依赖

| 上游模块 | 依赖类型 | 依赖说明 | 依赖成立条件 |
|---------|---------|---------|------------|
| LNK_PROD（产品主数据表） | 数据依赖 | 产品列表的核心数据源，存储产品编码、名称、型号、状态等所有产品信息 | 产品数据已同步入库 |
| LNK_PRICE_LIST + LNK_PRICE_LIST_ITEM（价目表） | 数据依赖 | 关联查询产品在当前用户所属事业部价目表中的有效价格，决定产品是否展示及标准单价 | 价目表存在且价格状态为生效（PRICE_STATUS=Y，且在有效期内） |
| LNK_ORG_EXT（事业部扩展表） | 数据依赖 | 关联查询品牌事业部名称（ORG_NAME） | 产品dept_id有值时关联 |
| LNK_CONTRACT（合同表） | 数据依赖 | 外部用户查询时，获取经销商有效合同渠道列表，用于过滤产品渠道 | 外部用户（userType=D）查询时 |
| 经销商账户信息（Account） | 数据依赖 | 获取经销商币种和出口客户标识，决定按哪种币种匹配价目表价格 | 外部用户查询时 |
| EBS产品政策接口 | 数据依赖 | 上架校验时查询关联老款产品的可售月份 | 产品上架校验场景 |
| 值集（LOV） | 配置依赖 | 渠道、上/下架状态、物料类型、产品线、生命状态、品牌事业部等字段依赖值集翻译 | 值集数据已配置 |

### 下游影响

- 影响1：产品详情页
  - 点击产品编码跳转至产品详情页（/product/detail/{id}），查看产品完整信息

- 影响2：产品上下架
  - 产品列表中的上/下架状态（PROD_STATUS）可被其他菜单调用上下架接口修改，本菜单提供状态展示

- 影响3：下单等业务
  - 通过selectType=all的查询接口为下单等业务提供产品选择数据源

- 影响4：产品图册/附件导入
  - 导入产品图册（CRM.PROD_PHOTO）和产品附件（CRM.PROD_FILES），更新产品的图片和附件信息

## 重点逻辑

### 重点逻辑1：内外部用户数据隔离 `权限控制`

- **业务意义**：内部员工和外部经销商看到的产品范围不同，确保经销商只能看到有价格且渠道匹配的产品，内部员工可按事业部查看更多产品

- **具体逻辑描述**

  - 第1点：内部用户（userType=E）——"商品检索"Tab展示产品事业部不为空且物料类型不为"配件"的产品，且需满足产品事业部等于用户所属事业部、或虽不等于但在用户所属事业部价目表中有有效价格

  - 第2点：内部用户——"配件&其它"Tab展示产品事业部为空、或物料类型为"配件"的产品

  - 第3点：内部管理员（拥有hzero.product_data.product_info.product_list.ps.admin_search权限且range=ALL）——"商品检索"Tab展示所有产品事业部不为空且非配件的产品，"配件&其它"Tab展示所有事业部为空或配件的产品，不受价目表价格限制

  - 第4点：外部用户（userType=D）——"商品检索"Tab展示产品事业部不为空、在经销商有效合同渠道内、价目表有价格、生命状态不为Z1/Z3、且非配件的产品

  - 第5点：外部用户——"其它"Tab展示产品事业部为空、在经销商有效合同渠道内、价目表有价格、生命状态不为Z1/Z3、且非配件的产品

  - 第6点：外部用户不可使用管理员全量查询权限，若分配了ALL权限会报错"分配了管理员权限，不可查询，请联系管理员处理！"

### 重点逻辑2：外部用户字段隐藏 `界面差异`

- **业务意义**：外部经销商不需要看到品牌事业部、品牌、上市/淘汰日期、产品推广等级、制造或采购等内部管理字段

- **具体逻辑描述**

  - 第1点：当用户userType为'D'（外部用户）时，隐藏以下字段：品牌事业部（deptId）、品牌（brand）、上市日期（launchDate）、淘汰日期（obsolescenceDate）、产品推广等级（prodPromoteGrade）、制造或采购（planningMakeBuyCodeMir）

  - 第2点：外部用户的"配件&其它"Tab名称显示为"其它"（去掉"配件&"前缀）

  - 第3点：外部用户隐藏"产品图册-导入"和"产品附件-导入"按钮，仅保留"导出"按钮

  - 第4点：外部用户的生命状态值集使用CRM.PRODUCT_Z_STATE_NAME（含名称），内部用户使用CRM.PRODUCT_Z_STATE（含编码+名称）

### 重点逻辑3：默认查询条件与智能清空 `查询优化`

- **业务意义**：避免全表扫描，默认只查近一个月创建的产品；当用户输入精确查询条件时自动清空时间范围，提升查询效率

- **具体逻辑描述**

  - 第1点：页面加载时默认设置创建时间范围为近一个月（开始=当前日期-1月，结束=当前日期）

  - 第2点：当用户在"产品编码""产品名称""型号"任一字段输入值时，自动清空创建时间默认范围，改为按精确条件查询

  - 第3点：首次查询时若无任何查询参数（除organizationId和selectType外），自动补充默认创建时间范围并触发查询

  - 第4点：管理员权限检查通过后（hzero.product_data.product_info.product_list.ps.admin_search），查询时传入range=ALL参数，后端据此跳过价目表价格过滤

### 重点逻辑4：价目表价格关联与海外事业部特殊处理 `价格逻辑`

- **业务意义**：产品展示需关联价目表获取标准单价，海外事业部人民币场景存在多个价目表，需按出口客户标识精确匹配

- **具体逻辑描述**

  - 第1点：通过LNK_PRICE_LIST和LNK_PRICE_LIST_ITEM关联查询产品价格，条件为价目表币种=经销商币种（内部用户默认CNY）、价目表事业部=用户所属事业部、价格状态为Y且在有效期内

  - 第2点：海外事业部+人民币场景下，根据经销商账户的出口客户标识（outAccount）匹配专属价目表名称：出口客户匹配"海外事业部价目表_CNY（出口）"，非出口匹配"海外事业部价目表"

  - 第3点：内部用户无出口标识，海外事业部场景默认取"海外事业部价目表"

  - 第4点：价格取MAX(CASE WHEN PRICE_STATUS=Y AND EFF_START_DATE<=TRUNC(sysdate) AND EFF_END_DATE>=TRUNC(sysdate) THEN price END)，即生效价格中的最大值

### 重点逻辑5：多值查询拆分 `查询增强`

- **业务意义**：支持物料类型和产品编码多值查询，提升批量查询效率

- **具体逻辑描述**

  - 第1点：物料类型（lhProdSign）含分隔符时，拆分为列表使用IN查询，避免正则CONNECT BY性能问题

  - 第2点：产品编码（prodCode）含分隔符时，拆分为列表使用IN查询

#### 按钮1：导出（列表页）

- **触发条件**：常显，需拥有hzero.product_data.product_info.product_list.ps.export权限
- **执行逻辑**：
  - 第1点：内部用户（userType≠D）调用接口GET /v1/{organizationId}/prod/internal/export?selectType=general或other
  - 第2点：外部用户（userType=D）调用接口GET /v1/{organizationId}/prod/external/export?selectType=general或other
  - 第3点：导出参数取当前查询条件栏的值，包括管理员range=ALL参数
  - 第4点：异步导出，导出文件名"产品明细导出"
  - 第5点：内部用户导出VO为LnkProdInternalExport，外部用户导出VO为LnkProdExternalExport（字段不同）
- **接口调用**：GET /v1/{organizationId}/prod/{internal|external}/export
- **排查SQL**：

```sql
-- 内部用户-商品检索Tab导出查询
SELECT T1.ROW_ID, T1.PROD_CODE, T1.PROD_NAME, T1.LH_PROD_MODEL, T1.PROD_SERIES,
       T1.LH_PROD_CHANNEL, T1.PROD_STATUS, T1.LH_PROD_SIGN, T1.SM_STATE,
       T1.DEPT_ID, T2.ORG_NAME, T1.BRAND, T1.PROD_STANDARD, T1.LH_PROD_LINE,
       T1.LAUNCH_DATE, T1.OBSOLESCENCE_DATE, T1.PROD_PROMOTE_GRADE,
       T1.PLANNING_MAKE_BUY_CODE_MIR, T1.PROD_POSITIONING, T1.PROD_ATTRIBUTION_CHANNEL,
       T1.PACKAGE_NUMBER, T1.PROD_NAME_ABBR, T1.LH_PROD_COLOR, T1.IS_SECURITY,
       T1.LH_IS_DEDICATED, T1.LH_IS_DEPOSIT_OR_NOT, T1.SECONDARY_MATERIAL_TYPE,
       T1.CONVERSION_RATE, T1.PRICE, T1.CREATED, T1.LAST_UPD
FROM LNK_PROD T1
  LEFT JOIN LNK_ORG_EXT T2 ON T1.DEPT_ID = T2.ROW_ID
  LEFT JOIN (
    SELECT PLI.PROD_ID, 1 AS HAS_PRICE,
           MAX(CASE WHEN PLI.PRICE_STATUS = 'Y'
                     AND PLI.EFF_START_DATE <= TRUNC(SYSDATE)
                     AND PLI.EFF_END_DATE   >= TRUNC(SYSDATE)
                    THEN PLI.PRICE END) AS PRICE
    FROM LNK_PRICE_LIST PL
      JOIN LNK_PRICE_LIST_ITEM PLI ON PL.ROW_ID = PLI.HEAD_ID
    WHERE PL.CURRENCY = 'CNY'  -- 经销商币种
      AND PL.DEPT_ID = :userDeptId  -- 用户所属事业部
    GROUP BY PLI.PROD_ID
  ) PLI ON PLI.PROD_ID = T1.ROW_ID
WHERE T1.DEPT_ID IS NOT NULL
  AND T1.LH_PROD_SIGN <> '配件'
  AND (T1.DEPT_ID = :userDeptId OR (T1.DEPT_ID <> :userDeptId AND PLI.HAS_PRICE = 1))
ORDER BY T1.CREATED DESC, T1.ROW_ID DESC;
```

#### 报错1：分配了管理员权限，不可查询，请联系管理员处理！
- **触发条件**：外部用户（userType=D）查询产品列表时，range参数为"ALL"（管理员全量查询）
- **逻辑分析**：后端LnkProdServiceImpl.selectList方法中，外部用户查询时若检测到range参数为"ALL"，则抛出CommonException。外部用户（经销商）不应拥有管理员全量查询权限，该权限仅限内部用户使用。需联系管理员取消外部用户的hzero.product_data.product_info.product_list.ps.admin_search权限分配。
- **排查SQL**：
  ```sql
  SELECT U.LOGIN_NAME AS 登录名, U.REAL_NAME AS 姓名, U.USER_TYPE AS 用户类型,
         R.CODE AS 角色编码, R.NAME AS 角色名称, P.CODE AS 权限编码
  FROM HZERO.IAM_USER U
    JOIN HZERO.IAM_MEMBER_ROLE MR ON U.ID = MR.USER_ID
    JOIN HZERO.IAM_ROLE R ON MR.ROLE_ID = R.ID
    JOIN HZERO.IAM_ROLE_PERMISSION RP ON R.ID = RP.ROLE_ID
    JOIN HZERO.IAM_PERMISSION P ON RP.PERMISSION_ID = P.ID
  WHERE P.CODE = 'hzero.product_data.product_info.product_list.ps.admin_search'
    AND U.USER_TYPE = 'D';
  ```

#### 报错2：无有效合同渠道，不可查询
- **触发条件**：外部用户（userType=D）查询产品列表时，经销商无有效合同渠道
- **逻辑分析**：后端LnkProdServiceImpl.selectList方法中，外部用户查询时通过经销商编码查询LNK_CONTRACT获取有效合同渠道列表。若合同状态非"生效"或当前日期不在合同有效期内，则渠道列表为空，抛出CommonException。经销商无有效合同渠道时无法过滤产品范围，需检查经销商合同是否生效且包含渠道配置。
- **排查SQL**：
  ```sql
  SELECT C.CONTRACT_CODE AS 合同编码, C.CONTRACT_STATUS AS 合同状态,
         C.LH_PROD_CHANNEL AS 产品渠道, C.EFF_START_DATE AS 生效开始日期,
         C.EFF_END_DATE AS 生效结束日期,
         CASE WHEN TRUNC(SYSDATE) BETWEEN C.EFF_START_DATE AND C.EFF_END_DATE
              THEN '在有效期内' ELSE '不在有效期内' END AS 有效期检查
  FROM LNK_CONTRACT C
  WHERE C.DEALER_CODE = :dealerCode
    AND C.CONTRACT_STATUS = '生效'
    AND TRUNC(SYSDATE) BETWEEN C.EFF_START_DATE AND C.EFF_END_DATE;
  ```

#### 报错3：查询类型错误！
- **触发条件**：查询产品列表时，前端传入的selectType参数非general/other/all
- **逻辑分析**：后端按selectType分流查询逻辑：general=商品检索Tab、other=配件&其它Tab、all=全量查询（下单等场景）。若传入其他值则无法匹配查询分支，抛出CommonException。属于程序异常，通常由前端传参错误导致。
- **排查SQL**：
  ```sql
  -- 无对应表查询，检查前端调用日志
  -- 接口: GET /v1/{organizationId}/prod?selectType={selectType}
  -- 合法值: general / other / all
  SELECT '检查前端传入selectType参数是否为general/other/all' AS 提示 FROM DUAL;
  ```

#### 报错4：用户类型错误
- **触发条件**：查询产品列表时，当前用户userType既非E（内部用户）也非D（外部用户）
- **逻辑分析**：后端根据userType区分内部/外部用户查询逻辑。userType为空或非E/D时无法确定查询范围，抛出CommonException。常见于用户主档配置异常或登录态丢失。
- **排查SQL**：
  ```sql
  SELECT U.ID AS 用户ID, U.LOGIN_NAME AS 登录名, U.REAL_NAME AS 姓名,
         U.USER_TYPE AS 用户类型
  FROM HZERO.IAM_USER U
  WHERE U.ID = :currentUserId;
  ```

#### 报错5：请至少输入一个查询条件！
- **触发条件**：跨事业部产品选择弹窗查询时，未输入任何查询条件（不含excludeDeptId）就点击查询
- **逻辑分析**：跨事业部产品选择接口/v1/{orgId}/prod/cross-bu-prod要求至少传入prodCode、prodName、lhProdModel中的一个，防止全表扫描。前端校验未通过则提示。


#### 报错6：请传入需要上下架的产品！

- **逻辑分析**：后端LnkProdServiceImpl.checkProdStatusChange方法中，若prodCodeList为空集合则抛出CommonException。上下架操作需至少选择一个产品，前端未勾选产品就点击上下架按钮时触发。需先在产品列表中勾选产品再操作。

#### 报错7：产品编码【xxx】不存在！
- **触发条件**：上下架校验时，传入的产品编码在LNK_PROD表不存在
- **逻辑分析**：后端LnkProdServiceImpl.checkProdStatusChange方法中，根据prodCodeList查询LNK_PROD表（selectListEAll），找出在prodCodeList中但不在数据库查询结果中的产品编码（missingProdCodes）。若missingProdCodes不为空，则拼接错误信息"产品编码【xxx】不存在！"并抛出CommonException。常见于产品编码被删除、前端传入错误的产品编码。
- **排查SQL**：
  ```sql
  SELECT LP.PROD_CODE AS 产品编码, LP.PROD_NAME AS 产品名称, LP.SM_STATE AS 生命状态
  FROM LNK_PROD LP
  WHERE LP.PROD_CODE IN (:prodCodeList);
  -- 对比传入的产品编码列表，找出不存在的编码
  SELECT CODE AS 不存在的产品编码
  FROM (SELECT :prodCode1 AS CODE FROM DUAL UNION ALL SELECT :prodCode2 FROM DUAL) T
  WHERE NOT EXISTS (SELECT 1 FROM LNK_PROD LP WHERE LP.PROD_CODE = T.CODE);
  ```

#### 报错8：产品xxx的生命状态为xxx不允许上架!
- **触发条件**：上架校验时，产品SM状态为Z1或Z8
- **逻辑分析**：后端LnkProdServiceImpl.checkProdStatusChange方法中，当prodChangeStatus为上架（UPPERSHELF）时，检查每个产品的SM状态。若SM状态为Z1或Z8，则拼接错误信息"产品xxx的生命状态为xxx不允许上架!"并抛出CommonException。Z1/Z8状态的产品不允许上架，需先通过产品SM状态变更申请将SM状态变更为可上架状态。
- **排查SQL**：
  ```sql
  SELECT LP.PROD_CODE AS 产品编码, LP.PROD_NAME AS 产品名称,
         LP.SM_STATE AS 生命状态, '不允许上架' AS 校验结果
  FROM LNK_PROD LP
  WHERE LP.PROD_CODE IN (:prodCodeList)
    AND LP.SM_STATE IN ('Z1', 'Z8');
  ```

#### 报错9：产品xxx的生命状态为xxx是否确认上架!
- **触发条件**：上架校验时，产品SM状态为Z3/Z6/Z7/S6，且用户未确认（confirmShelf为null或false）
- **逻辑分析**：后端LnkProdServiceImpl.checkProdStatusChange方法中，当prodChangeStatus为上架且产品SM状态为Z3/Z6/Z7/S6时，拼接确认信息"产品xxx的生命状态为xxx是否确认上架!"并抛出带CONFIRM_REQUIRED错误码的CommonException。前端捕获该错误码后弹出确认弹窗，用户确认后携带confirmShelf=true重新请求。此为确认弹窗类报错，非阻断性。
- **排查SQL**：
  ```sql
  SELECT LP.PROD_CODE AS 产品编码, LP.PROD_NAME AS 产品名称,
         LP.SM_STATE AS 生命状态, '需确认上架' AS 校验结果
  FROM LNK_PROD LP
  WHERE LP.PROD_CODE IN (:prodCodeList)
    AND LP.SM_STATE IN ('Z3', 'Z6', 'Z7', 'S6');
  ```

#### 报错10：申请产品上架数量不能超过1千！
- **触发条件**：上架校验时，一次上架产品数量超过1000条
- **逻辑分析**：后端LnkProdServiceImpl.prodUpperProdCheck方法中，若prodCodeList.size()>=1000则抛出CommonException。限制单次上架产品数量不超过1000条，避免批量操作性能问题和ERP接口超时。需分批上架，每批不超过1000条产品。
- **排查SQL**：
  ```sql
  SELECT COUNT(1) AS 待上架产品数量
  FROM LNK_PROD LP
  WHERE LP.PROD_CODE IN (:prodCodeList);
  ```

#### 报错11：物料编码xxx关联老款产品xxx没有找到当前有效的折扣政策，不允许产品上架！
- **触发条件**：上架校验时，关联老款产品无有效折扣政策且可售月份大于1个月
- **逻辑分析**：后端LnkProdServiceImpl.prodUpperProdCheck方法中，根据产品查询事业部开启了"关联老品管控"、最新审批通过的、关联了"老款产品"的价目表申请单行。对每个关联老款产品查询有效折扣政策（queryProdNotEffectPxy），若无有效政策则调用EBS接口查询可售月份（fetchProductPolicyReferenceFromEbs）。若可售月份大于1个月，则拼接错误信息并抛出CommonException。需先为关联老款产品配置有效的折扣政策。
- **排查SQL**：
  ```sql
  SELECT LP.PROD_CODE AS 产品编码, LP.PROD_NAME AS 产品名称,
         LPAF.PRICE_APP_FORM_NO AS 价目表申请单号, LPAFO.OLD_PROD_CODE AS 老款产品编码
  FROM LNK_PROD LP
    JOIN LNK_PRICE_APP_FORM_ITEM LPAFI ON LPAFI.PROD_ID = LP.ROW_ID
    JOIN LNK_PRICE_APP_FORM LPAF ON LPAF.ROW_ID = LPAFI.HEAD_ID
    LEFT JOIN LNK_PRICE_APP_FORM_OLDPROD LPAFO ON LPAFO.PRICE_APP_FORM_ITEM_ID = LPAFI.ROW_ID
  WHERE LP.PROD_CODE IN (:prodCodeList)
    AND LPAF.RELATE_OLD_PROD_CONTROL = 'Y'
    AND LPAF.AUDIT_STATUS = '审批通过';
  ```

#### 报错12：未找到事业部编码[xxx]对应的CRM事业部！
- **触发条件**：跨事业部产品选择查询时，AE事业部编码在REL_CRM_AE_ORG表未映射到CRM事业部ID

  ```sql
  WHERE R.AE_OR_CODE = :excludeDeptCode;
  ```

### 常见问题

- 问题1：外部用户看不到品牌事业部、品牌等字段
  - 原因：外部用户（userType=D）前端通过getHideField()函数隐藏了deptId、brand、launchDate、obsolescenceDate、prodPromoteGrade、planningMakeBuyCodeMir字段
  - 解决思路：这是正常的业务设计，外部经销商不需要看到内部管理字段

- 问题2：查询结果为空，但产品确实存在
  - 原因：可能原因有：1）产品在当前用户所属事业部价目表中无有效价格（pli.has_price≠1）；2）外部用户产品渠道不在经销商有效合同渠道内；3）外部用户产品生命状态为Z1或Z3被过滤；4）产品在"商品检索"Tab但物料类型为"配件"被过滤
  - 解决思路：
    ```sql
    -- 检查产品是否有有效价格
    SELECT PL.DEPT_ID, PL.CURRENCY, PLI.PRICE, PLI.PRICE_STATUS, PLI.EFF_START_DATE, PLI.EFF_END_DATE
    FROM LNK_PRICE_LIST PL
      JOIN LNK_PRICE_LIST_ITEM PLI ON PL.ROW_ID = PLI.HEAD_ID
    WHERE PLI.PROD_ID = (SELECT ROW_ID FROM LNK_PROD WHERE PROD_CODE = :prodCode)
      AND PL.DEPT_ID = :userDeptId
      AND PL.CURRENCY = :currency;
    ```

- 问题3：内部管理员查询看不到所有产品
  - 原因：管理员权限未正确配置，前端checkPermissions检查hzero.product_data.product_info.product_list.ps.admin_search权限未通过，range参数未设置为ALL
  - 解决思路：检查用户角色是否分配了hzero.product_data.product_info.product_list.ps.admin_search权限

- 问题4：默认查询时间范围不符合预期
  - 原因：页面加载时默认创建时间为近1月，但如果用户先输入了产品编码/名称/型号，会自动清空默认时间范围
  - 解决思路：这是正常的查询优化设计，输入精确条件后按精确条件查询，不再限制时间范围
