# 门店管理-门店设置-门店装修标准

## 业务流程

### 业务流程图

```text
门店装修标准设置页面(hlod低代码页面)
        │
        ├── 查询 ──→ 按事业部、装修等级筛选装修标准配置
        │
        ├── 新增/编辑 ──→ 配置门店等级对应的装修标准
        │              (装修项目、面积范围、额度内/外单价、有效期等)
        │                    │
        │                    ▼
        │              保存 ──→ 批量插入/更新TERMINAL_DECORATE_STANDARD和TERMINAL_DECORATE_LINE
        │
        └── 被其他单据引用：
              ├── 门店装修申请与进度更新（do-search-decorate接口）
              ├── 门店验收与报销单（doSearchDecorate/searchDecorate接口）
              └── 面积分配标准比（get-com-data接口）
```

### 上游依赖

| 上游模块 | 依赖类型 | 依赖说明 | 依赖成立条件 |
|---------|---------|---------|------------|
| 事业部配置 | 配置依赖 | 装修标准按事业部隔离，需先存在事业部数据 | 事业部已创建 |
| 装修项目值集 | 配置依赖 | 明细行装修项目来源于词汇编码mkt.decorate_project | 值集已配置 |
| 装修等级值集 | 配置依赖 | 门店装修等级来源于词汇编码fixup_grade | 值集已配置 |
| 补贴方式值集 | 配置依赖 | 补贴方式来源于值集scpdict的decorate_subsidy_mode | 值集已配置 |

### 下游影响

- 影响1：门店装修申请与进度更新
  - 装修申请时通过do-search-decorate接口按门店等级查询装修标准，作为补贴预估与申请依据

- 影响2：门店验收与报销单
  - 验收报销时通过doSearchDecorate/searchDecorate接口匹配当期有效标准行，用于计算实际报销金额

- 影响3：面积分配标准比
  - 通过get-com-data接口返回面积分配标准比配置，供装修申请计算各项目面积分配

## 重点逻辑

### 重点逻辑1：多维标准匹配 {配置匹配}

- **业务意义**：不同门店装修等级、不同装修项目、不同面积范围对应不同的补贴单价，需要精确匹配才能保证补贴金额准确

- **具体逻辑描述**

  - 第1点：每个标准头下配置多行明细，按装修项目+门店装修等级+面积范围进行匹配

  - 第2点：面积范围通过"面积范围大于"和"面积范围小于等于"定义区间（左开右闭），即门店面积A匹配条件为：面积范围大于 < A <= 面积范围小于等于

  - 第3点：额度内标准（元/m²）和额度外标准（元/m²）分别设定单价，控制额度内外不同补贴口径

  - 第4点：额度外面积上限限制超出额度的最大可报销面积

### 重点逻辑2：有效期控制 {时效管理}

- **业务意义**：装修标准会随政策调整而变化，通过有效期控制确保仅当前有效标准被引用，避免使用过期标准导致补贴错误

- **具体逻辑描述**

  - 第1点：每行明细有独立的生效起止日期，控制该行标准何时可用

  - 第2点：下游单据引用时仅匹配当前日期在有效期范围内的行

  - 第3点：不同行可设置不同有效期，实现标准更替的平滑过渡

### 重点逻辑3：事业部隔离 {数据隔离}

- **业务意义**：不同事业部的装修政策和补贴标准不同，需按事业部隔离维护，互不影响

- **具体逻辑描述**

  - 第1点：数据按事业部隔离，不同事业部维护各自的装修标准

  - 第2点：查询时通过selectFixupGradeList按事业部ID和装修等级筛选

### 重点逻辑4：批量保存 {数据保存}

- **业务意义**：装修标准以头行结构维护，支持批量新增和修改，提升配置效率

- **具体逻辑描述**

  - 第1点：保存时按主键ID是否为空区分新增和更新列表

  - 第2点：新增列表批量插入（batchInsertSelective），更新列表批量更新（batchUpdateByPrimaryKeySelective）

### 保存校验

- 校验1：事业部不能为空 —— 确保装修标准归属明确事业部

  - 详细逻辑

    - 第1点：保存时校验头信息中事业部ID不为空

  - 系统体现：toast提醒

  - 排查SQL：

    ```sql
    SELECT * FROM TERMINAL_DECORATE_STANDARD WHERE ENTID IS NULL;
    ```

- 校验2：行信息不能为空 —— 确保至少配置一行明细

  - 详细逻辑

    - 第1点：保存时校明明细行列表不为空且至少一行

  - 系统体现：toast提醒

  - 排查SQL：

    ```sql
    SELECT TDS.DECORATE_STANDARD_ID FROM TERMINAL_DECORATE_STANDARD TDS
    WHERE NOT EXISTS (SELECT 1 FROM TERMINAL_DECORATE_LINE TDL WHERE TDL.DECORATE_STANDARD_ID = TDS.DECORATE_STANDARD_ID);
    ```

- 校验3：面积范围合法性 —— 确保面积区间下限小于上限

  - 详细逻辑

    - 第1点：校验每行面积范围小于等于(LOWER_AREA)需大于面积范围大于(UPER_AREA)

  - 系统体现：toast提醒

  - 排查SQL：

    ```sql
    SELECT * FROM TERMINAL_DECORATE_LINE WHERE LOWER_AREA <= UPER_AREA;
    ```

- 校验4：有效日期合法性 —— 确保结束日期不早于开始日期

  - 详细逻辑

    - 第1点：校验每行有效结束日期(END_DATE)需大于等于有效开始日期(START_DATE)

  - 系统体现：toast提醒

  - 排查SQL：

    ```sql
    SELECT * FROM TERMINAL_DECORATE_LINE WHERE END_DATE < START_DATE;
    ```

- 校验5：金额标准必须大于0 —— 确保补贴单价有效

  - 详细逻辑

    - 第1点：校验每行额度内标准(IN_STANDARD)和额度外标准(OUT_STANDARD)均大于0

  - 系统体现：toast提醒

  - 排查SQL：

    ```sql
    SELECT * FROM TERMINAL_DECORATE_LINE WHERE IN_STANDARD <= 0 OR OUT_STANDARD <= 0;
    ```

### 提交校验

- 校验1：保存校验全部通过 —— 确保提交前数据完整有效

  - 详细逻辑

    - 第1点：提交前先执行保存校验全部规则

    - 第2点：校验头信息和所有行信息完整无空值

  - 系统体现：阻断性报错

  - 排查SQL：

    ```sql
    SELECT * FROM TERMINAL_DECORATE_LINE 
    WHERE DECORATE_STANDARD_ID = #{id}
      AND (DECORATE_PROJECT IS NULL OR FIXUP_GRADE IS NULL OR IN_STANDARD IS NULL OR OUT_STANDARD IS NULL);
    ```

### 相关查询SQL

**按事业部和装修等级查询装修标准（selectFixupGradeList）：**

```sql
SELECT TDL.*
FROM TERMINAL_DECORATE_LINE TDL
JOIN TERMINAL_DECORATE_STANDARD TDS ON TDL.DECORATE_STANDARD_ID = TDS.DECORATE_STANDARD_ID
WHERE TDS.ENTID = #{entid}
  AND TDL.FIXUP_GRADE = #{fixupGrade}
  AND SYSDATE BETWEEN TDL.START_DATE AND TDL.END_DATE
ORDER BY TDL.DECORATE_PROJECT
```

| 金额标准必须大于0 | 保存时 | 额度内/外标准填写了0或负数，输入正确单价 | toast提醒 | [查看](#报错5金额标准必须大于0) |

#### 报错1：事业部不能为空
- **触发条件**：点击"保存"按钮时，校验头信息中TERMINAL_DECORATE_STANDARD.ENTID(事业部ID)为null
- **逻辑分析**：装修标准按事业部隔离维护，不同事业部装修政策和补贴标准不同，事业部ID是数据隔离和下游匹配的关键字段。若用户新建装修标准时未选择事业部即点击保存，或事业部LOV选择后未正确回传ENTID，后端校验ENTID为空即抛出toast提醒"事业部不能为空"，保存被拦截。该异常为非阻断性提示，用户选择事业部后可重新保存。
- **排查SQL**：
  ```sql
  SELECT s.decorate_standard_id   AS 装修标准ID,
         s.decorate_standard_no   AS 装修标准单号,
         s.entid                   AS 事业部ID,
         s.entname                 AS 事业部名称,
         s.hz_approve_status       AS 审批状态
  FROM   terminal_decorate_standard s
  WHERE  s.entid IS NULL
  ORDER  BY s.create_time DESC;
  ```

#### 报错2：行信息不能为空
- **触发条件**：点击"保存"按钮时，校验明细行列表为空或行数为0
- **逻辑分析**：装修标准以头行结构维护，头表记录归属事业部，明细行记录具体装修项目+装修等级+面积范围+补贴单价。若无任何明细行，头表记录无实际补贴配置，下游装修申请/验收报销查询时匹配不到任何标准行，无法计算补贴金额。后端校验明细行列表非空且至少一行，若为空即抛出toast提醒"行信息不能为空"，保存被拦截。
- **排查SQL**：
  ```sql
  SELECT s.decorate_standard_id   AS 装修标准ID,
         s.decorate_standard_no   AS 装修标准单号,
         s.entname                 AS 事业部名称,
         s.hz_approve_status       AS 审批状态
  FROM   terminal_decorate_standard s
  WHERE  NOT EXISTS (
    SELECT 1
    FROM   terminal_decorate_line l
    WHERE  l.decorate_standard_id = s.decorate_standard_id
  )
  ORDER  BY s.create_time DESC;
  ```

#### 报错3：面积范围不合法
- **触发条件**：点击"保存"按钮时，校验某行明细的LOWER_AREA(面积范围小于等于)不大于UPER_AREA(面积范围大于)
- **逻辑分析**：面积范围通过UPER_AREA(下限，不含)和LOWER_AREA(上限，含)定义左开右闭区间，门店面积A匹配条件为UPER_AREA < A <= LOWER_AREA，要求LOWER_AREA > UPER_AREA。若用户配置时误将下限填大于上限（如UPER_AREA=100、LOWER_AREA=50），区间为空集，任何门店面积都无法匹配该行，导致下游装修申请/验收报销匹配不到对应面积区间的补贴单价。后端校验LOWER_AREA <= UPER_AREA即抛出toast提醒"面积范围不合法"。
- **排查SQL**：
  ```sql
  SELECT l.decorate_line_id      AS 明细行ID,
         l.decorate_standard_id  AS 装修标准ID,
         l.decorate_project      AS 装修项目,
         l.fixup_grade           AS 装修等级,
         l.uper_area             AS 面积范围大于,
         l.lower_area            AS 面积范围小于等于
  FROM   terminal_decorate_line l
  WHERE  l.lower_area <= l.uper_area
  ORDER  BY l.decorate_standard_id, l.decorate_project;
  ```

#### 报错4：有效日期不合法
- **触发条件**：点击"保存"按钮时，校验某行明细的END_DATE(有效结束日期)早于START_DATE(有效开始日期)
- **逻辑分析**：每行明细有独立的有效期，下游单据引用时仅匹配当前日期在START_DATE至END_DATE之间的行。要求END_DATE >= START_DATE，确保有效期内有可被引用的时间段。若用户选择日期时误将结束日期早于开始日期（如跨年配置时年份选错），该行有效期为空区间，任何日期都无法匹配，下游装修申请/验收报销查询时该行永不生效。后端校验END_DATE < START_DATE即抛出toast提醒"有效日期不合法"。
- **排查SQL**：
  ```sql
  SELECT l.decorate_line_id      AS 明细行ID,
         l.decorate_standard_id  AS 装修标准ID,
         l.decorate_project      AS 装修项目,
         l.fixup_grade           AS 装修等级,
         l.start_date            AS 有效开始日期,
         l.end_date              AS 有效结束日期
  FROM   terminal_decorate_line l
  WHERE  l.end_date < l.start_date
  ORDER  BY l.decorate_standard_id, l.decorate_project;
  ```

#### 报错5：金额标准必须大于0
- **触发条件**：点击"保存"按钮时，校验某行明细的IN_STANDARD(额度内标准)或OUT_STANDARD(额度外标准)小于等于0
- **逻辑分析**：IN_STANDARD和OUT_STANDARD分别为额度内和额度外的补贴单价(元/m²)，下游装修申请预估补贴和验收报销计算实际报销金额时按"面积×单价"计算，要求单价大于0才有业务意义。若用户误填0或负数（如未输入默认0、或误填负值），会导致补贴金额计算为0或负数，造成经销商利益受损或财务数据异常。后端校验IN_STANDARD <= 0或OUT_STANDARD <= 0即抛出toast提醒"金额标准必须大于0"。
- **排查SQL**：
  ```sql
  SELECT l.decorate_line_id      AS 明细行ID,
         l.decorate_standard_id  AS 装修标准ID,
         l.decorate_project      AS 装修项目,
         l.fixup_grade           AS 装修等级,
         l.in_standard           AS 额度内标准,
         l.out_standard          AS 额度外标准
  FROM   terminal_decorate_line l
  WHERE  l.in_standard <= 0
  OR     l.out_standard <= 0
  ORDER  BY l.decorate_standard_id, l.decorate_project;
  ```

### 常见问题

- 问题1：装修标准查询无数据
  - 原因：TERMINAL_DECORATE_LINE中该装修等级(FIXUP_GRADE)无配置，或当前日期不在有效期内
  - 解决思路：检查SQL `SELECT * FROM TERMINAL_DECORATE_LINE WHERE FIXUP_GRADE = #{grade} AND SYSDATE BETWEEN START_DATE AND END_DATE`

- 问题2：装修申请中标准金额不正确
  - 原因：TERMINAL_DECORATE_LINE的IN_STANDARD/OUT_STANDARD配置错误
  - 解决思路：核对装修标准明细表中对应装修项目和等级的单价配置

- 问题3：面积范围匹配不上
  - 原因：门店面积不在任何配置行的面积区间内（UPER_AREA, LOWER_AREA）
  - 解决思路：检查面积区间配置是否覆盖该门店面积范围

- 问题4：该页面无独立Controller
  - 原因：本页面为hlod低代码页面，通过TerminalDecorateStandardRepository直接访问数据，查询接口嵌入在FinFeeCheckBxHeaderController和FinFeeApplyFinishedHeaderController中
  - 解决思路：通过doSearchDecorate/searchDecorate/do-search-decorate接口间接查询
