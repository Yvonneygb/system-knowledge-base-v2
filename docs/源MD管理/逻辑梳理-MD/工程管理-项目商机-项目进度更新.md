# 工程管理-项目商机-项目进度更新

> 本页面为低代码页面(hlod)，无独立前端源码，基于后端API与Entity梳理。贯穿工程全生命周期的进度推进机制，记录项目从报备到结案的各阶段历程。本功能为直接更新项目进度，无审批流程。

## 业务流程

### 进度如何流转

选择项目 → 加载当前阶段 → 选择目标阶段 → 填写阶段描述 → 提交更新 → 校验阶段前进规则 → 更新项目档案和历程。

```
用户进入项目进度更新页面
  → 选择项目（传入projectId）
  → 加载项目当前阶段、阶段描述（EPM_PROJECT.STAGE_ID/STAGE_DESC）
  → 选择目标阶段（STAGE_ID，来源于EPM_STAGE_DEF，序号需大于当前阶段）
  → 填写阶段描述（STAGE_DESC）
  → 提交更新（POST /do-update）
  → 后端校验：
    → 阶段前进规则（新阶段序号 >= 旧阶段序号）
    → 进度一致性（stageValueBefore <= 项目当前stageId）
  → 更新项目档案EPM_PROJECT的STAGE_ID/STAGE_NAME/STAGE_NOTE/STAGE_DESC
  → 插入历程记录到EPM_PROJECT_STAGE
  → 返回成功
```

### 全链路流程图

```
开始 → ★更新项目进度★ → 校验阶段前进 → 校验进度一致性 → 更新项目档案 → 插入历程记录 → 结束

上游支撑：项目档案(EPM_PROJECT)、阶段定义(EPM_STAGE_DEF)、项目报备、项目解冻申请、合同结案
下游影响：项目档案阶段字段、项目进度历程、项目透视、冻结预警、出库单、项目合同
```

### 进度推进方式

- **手动更新**：用户在页面选择目标阶段并填写描述，调用POST /do-update接口
- **自动更新**：系统内部调用doMotionUpdate，如解冻审批通过、合同结案等场景自动推进阶段
- **超时冻结**：超过阶段定义中UPDATE_CYCLE天数未更新进度，系统自动冻结项目(FREEZE_TYPE=2)

## 重点逻辑

### 重点逻辑1：阶段前进校验

- **业务意义**：项目阶段代表项目推进的里程碑，只能前进不能后退，保证业务连续性
- **具体逻辑描述**：
  - 更新阶段时通过EpmStageDef.seq比较新旧阶段顺序
  - 若stageChanged且newStage.seq < oldStage.seq，抛出"阶段更新，只能前进，不能后退"
  - 强制更新(forceUpdate=2)时仍需通过前进校验

### 重点逻辑2：进度一致性校验

- **业务意义**：防止并发更新时多个单据同时修改项目进度，避免覆盖
- **具体逻辑描述**：
  - 当单据中记录的进度stageValueBefore大于项目档案当前STAGE_ID时
  - 说明项目进度已被其他单据变更，抛出"项目进度已变更，请驳回重审!"
  - 仅在阶段改变、描述改变或强制更新时执行此校验

### 重点逻辑3：历程记录沿用

- **业务意义**：仅描述改变时保持历程连续性，不产生重复的阶段切换记录
- **具体逻辑描述**：
  - 若仅阶段描述改变而阶段未变(stageChanged=false)
  - 查询该阶段最新一条历程记录，沿用其创建人和创建时间
  - 仅追加新的描述记录到EPM_PROJECT_STAGE

### 重点逻辑4：强制更新

- **业务意义**：系统自动场景(如解冻审批通过)需跳过阶段改变判断直接更新
- **具体逻辑描述**：
  - forceUpdate=2时，即使阶段和描述都没有变化，也会执行更新操作
  - 用于进度超时解冻、报备审批等系统自动场景

### 重点逻辑5：doMotionUpdate自动更新

- **业务意义**：系统内部自动推进项目阶段，避免重复插入
- **具体逻辑描述**：
  - 先查询项目是否已存在目标阶段记录(EPM_PROJECT_STAGE中PROJECT_ID+STAGE_ID)
  - 未存在时：查询阶段定义，更新项目表STAGE_ID/STAGE_NAME/STAGE_NOTE/STAGE_DESC，插入阶段历程
  - 已存在时不重复更新

### doUpdate更新逻辑

```
入参：EpmProjectStageDTO (projectId, stageId, stageDesc, forceUpdate, stageValueBefore)
1. 查询项目当前状态 projBeforeUpdate = selectByPrimaryKey(projectId)
2. trim处理stageDesc
3. 判断阶段是否改变 stageChanged = (stageId != projBeforeUpdate.stageId)
4. 判断描述是否改变 stageDescChanged = (stageDesc != projBeforeUpdate.stageDesc)
5. 若阶段改变或描述改变或强制更新(forceUpdate=2)：
   → 校验进度一致性：stageValueBefore > projBeforeUpdate.stageId时抛"项目进度已变更，请驳回重审!"
   → 查询旧阶段定义 oldStage
   → 查询新阶段定义 newStage(stageChanged时查询，否则同oldStage)
   → 校验阶段前进：stageChanged且newStage.seq < oldStage.seq时抛"阶段更新，只能前进，不能后退"
   → 更新项目档案：STAGE_DESC/STAGE_ID/STAGE_NAME/STAGE_NOTE
   → 插入历程记录EPM_PROJECT_STAGE：
     → 若阶段未改变，查询该阶段最新记录沿用创建人和创建时间
     → insert(insertEpmProjectStage)
```

### doMotionUpdate自动更新逻辑

```
入参：projectId, stageId, stageDesc
1. 查询项目是否已存在当前阶段(EPM_PROJECT_STAGE中PROJECT_ID+STAGE_ID)
2. 不存在时：
   → 查询阶段定义 newStage = selectByPrimaryKey(stageId)
   → 更新项目表STAGE_ID/STAGE_NAME/STAGE_NOTE/STAGE_DESC
   → 插入项目阶段历程记录
3. 已存在时不重复更新
```

### 保存校验

- 校验1：项目ID非空 —— 必须选择有效的项目
  - **详细逻辑**：projectId字段标注@NotNull(message="项目ID不能为空")，框架自动校验
  - **系统体现**：DTO注解校验
  - **排查SQL**：`SELECT * FROM EPM_PROJECT WHERE PROJECT_ID = #{projectId};`

- 校验2：阶段ID非空 —— 必须选择目标阶段
  - **详细逻辑**：stageId字段标注@NotNull(message="阶段ID不能为空")，框架自动校验
  - **系统体现**：DTO注解校验
  - **排查SQL**：`SELECT * FROM EPM_STAGE_DEF WHERE STAGE_ID = #{stageId};`

- 校验3：进度描述非空 —— 必须填写阶段描述
  - **详细逻辑**：stageDesc字段标注@NotEmpty(message="项目进度描述不能为空")，框架自动校验
  - **系统体现**：DTO注解校验
  - **排查SQL**：无（前端校验）

### 提交校验

- 校验1：阶段前进校验 —— 新阶段序号不小于旧阶段序号，防止进度回退
  - **详细逻辑**：doUpdate中stageChanged且newStage.seq < oldStage.seq时抛出"阶段更新，只能前进，不能后退"
  - **系统体现**：后端doUpdate方法校验
  - **排查SQL**：`SELECT OLD.STAGE_ID, OLD.SEQ AS OLD_SEQ, NEW.STAGE_ID, NEW.SEQ AS NEW_SEQ FROM EPM_STAGE_DEF OLD, EPM_STAGE_DEF NEW WHERE OLD.STAGE_ID = #{当前阶段ID} AND NEW.STAGE_ID = #{目标阶段ID} AND NEW.SEQ < OLD.SEQ;`

- 校验2：进度一致性 —— 单据进度与项目档案进度一致，防止并发覆盖
  - **详细逻辑**：doUpdate中stageValueBefore > projBeforeUpdate.stageId时抛出"项目进度已变更，请驳回重审!"
  - **系统体现**：后端doUpdate方法校验
  - **排查SQL**：`SELECT EP.STAGE_ID AS 当前阶段, #{stageValueBefore} AS 单据进度 FROM EPM_PROJECT EP WHERE EP.PROJECT_ID = #{projectId};`

### 状态机

```text
项目进度阶段流转（只能前进不能后退）：

[初始阶段] → [折扣通过] → [已下首单] → [项目供货中] → [供货按期完成] → [项目结案]

项目有效状态流转（与进度更新相关）：

已生效(2) ──进度超时未更新──→ 已冻结(4) [FREEZE_TYPE=2]
已冻结(4) ──解冻审批通过──→ 已生效(2)
```

> 本功能为直接更新项目进度，无审批流程。

### 查询SQL

```sql
-- 查询项目进度历程
SELECT PS.PK_ID, PS.PROJECT_ID, PS.STAGE_ID, SD.STAGE_NAME,
       PS.STAGE_DESC, PS.CREATED_BY, PS.CREATION_DATE
FROM EPM_PROJECT_STAGE PS
LEFT JOIN EPM_STAGE_DEF SD ON SD.STAGE_ID = PS.STAGE_ID
WHERE PS.PROJECT_ID = #{projectId}
ORDER BY PS.CREATION_DATE DESC;

-- 查询阶段定义顺序
SELECT STAGE_ID, STAGE_NAME, SEQ, UPDATE_CYCLE
FROM EPM_STAGE_DEF
WHERE ORGANIZATION_ID = #{organizationId}
ORDER BY SEQ;

-- 更新项目档案阶段
UPDATE EPM_PROJECT
SET STAGE_ID = #{stageId},
    STAGE_NAME = #{stageName},
    STAGE_NOTE = #{stageNote},
    STAGE_DESC = #{stageDesc}
WHERE PROJECT_ID = #{projectId};
```

#### 报错1：阶段更新，只能前进，不能后退
- **触发条件**：更新项目进度时，目标阶段序号(newStage.seq)小于当前阶段序号(oldStage.seq)
- **逻辑分析**：doUpdate方法中查询EPM_STAGE_DEF获取目标阶段和当前阶段的SEQ，若newStage.seq < oldStage.seq则抛出阻断性报错。项目阶段代表里程碑(报备→合同→结案)，回退会破坏业务连续性和下游数据一致性
- **排查SQL**：
  ```sql
  SELECT esd.STAGE_ID, esd.STAGE_NAME, esd.SEQ, esd.UPDATE_CYCLE, esd.ORGANIZATION_ID
  FROM EPM_STAGE_DEF esd
  WHERE esd.ORGANIZATION_ID = :organizationId
  ORDER BY esd.SEQ
  -- 对比目标阶段与当前阶段的SEQ
  ```

#### 报错2：项目进度已变更，请驳回重审!
- **触发条件**：更新项目进度时，单据进度stageValueBefore与项目档案当前STAGE_ID不一致
- **逻辑分析**：doUpdate方法中查询项目档案EPM_PROJECT获取projBeforeUpdate.stageId，若stageValueBefore > projBeforeUpdate.stageId说明项目进度已被其他单据变更，当前单据基于旧进度提交，需驳回重审
- **排查SQL**：
  ```sql
  SELECT ep.PROJECT_ID, ep.PROJECT_CODE, ep.STAGE_ID AS 当前阶段ID, ep.PROJECT_VALID,
         eps.STAGE_ID AS 历程阶段ID, eps.CREATION_DATE, eps.CREATED_BY
  FROM EPM_PROJECT ep
  LEFT JOIN EPM_PROJECT_STAGE eps ON ep.PROJECT_ID = eps.PROJECT_ID
  WHERE ep.PROJECT_ID = :projectId
  ORDER BY eps.CREATION_DATE DESC
  -- 对比单据的stageValueBefore与项目当前STAGE_ID
  ```

#### 报错3：项目ID不能为空
- **触发条件**：更新项目进度时，projectId参数为空
- **逻辑分析**：updateStage方法projectId参数标注@NotNull，Spring校验框架自动校验。该报错为阻断性报错，需选择项目后重新提交
- **排查SQL**：

  ```sql
  SELECT ep.PROJECT_ID, ep.PROJECT_CODE, ep.PROJECT_NAME, ep.STAGE_ID, ep.PROJECT_VALID
  FROM EPM_PROJECT ep
  WHERE ep.PROJECT_ID = :projectId
  -- 校验项目ID是否存在
  ```

#### 报错4：阶段ID不能为空
- **触发条件**：更新项目进度时，stageId参数为空
- **逻辑分析**：updateStage方法stageId参数标注@NotNull，Spring校验框架自动校验。需选择目标阶段后重新提交
- **排查SQL**：
  ```sql
  SELECT esd.STAGE_ID, esd.STAGE_NAME, esd.SEQ, esd.ORGANIZATION_ID
  FROM EPM_STAGE_DEF esd
  WHERE esd.STAGE_ID = :stageId
  -- 校验阶段ID是否存在
  ```

#### 报错5：项目进度描述不能为空
- **触发条件**：更新项目进度时，stageDesc参数为空

## 常见问题FAQ

### Q1: 为什么阶段只能前进不能后退？

项目阶段代表项目推进的里程碑(如报备→合同→结案)，回退会破坏业务连续性和下游数据一致性。

**排查SQL:**
```sql
SELECT STAGE_ID, STAGE_NAME, SEQ FROM EPM_STAGE_DEF ORDER BY SEQ;
```

### Q2: 阶段未改变但描述改变时会记录历程吗？

会记录。只要阶段或描述任一改变，或启用强制更新，都会插入新的历程记录，但会沿用上次该阶段的创建人和创建时间。

### Q3: doMotionUpdate与doUpdate的区别？

doMotionUpdate为系统内部调用(如解冻审批通过后自动推进)，先查询项目是否已存在目标阶段记录，未存在才更新；doUpdate为页面手动触发，含完整的阶段前进和一致性校验。

### Q4: 项目被冻结，冻结类型为"进度超时更新"是什么原因？

项目在当前阶段的进度更新期限(由阶段定义中UPDATE_CYCLE字段控制)内未更新进度，系统自动冻结。

**排查SQL:**
```sql
SELECT EP.PROJECT_ID, EP.PROJECT_CODE, EP.STAGE_ID, EP.PROJECT_VALID, EP.FREEZE_TYPE,
       SD.STAGE_NAME, SD.UPDATE_CYCLE
FROM EPM_PROJECT EP
LEFT JOIN EPM_STAGE_DEF SD ON SD.STAGE_ID = EP.STAGE_ID
WHERE EP.FREEZE_TYPE = 2;
```

### Q5: 强制更新是什么意思？

强制更新(forceUpdate=2)时，即使阶段和描述都没有变化，也会执行更新操作并写入历程记录。主要用于报备审批和解冻场景。

### Q6: 进度更新期限如何计算？

进度更新期限 = 当前阶段最近一次更新时间 + 阶段定义中的UPDATE_CYCLE天数。

**排查SQL:**
```sql
SELECT PS.PROJECT_ID, PS.STAGE_ID, PS.CREATION_DATE,
       SD.UPDATE_CYCLE,
       PS.CREATION_DATE + INTERVAL TO_NUMBER(SD.UPDATE_CYCLE) DAY AS 期限
FROM EPM_PROJECT_STAGE PS
JOIN EPM_STAGE_DEF SD ON SD.STAGE_ID = PS.STAGE_ID
WHERE PS.PROJECT_ID = #{projectId}
ORDER BY PS.CREATION_DATE DESC
FETCH FIRST 1 ROWS ONLY;
```

### Q7: 历程记录如何查询？

**排查SQL:**
```sql
SELECT * FROM EPM_PROJECT_STAGE
WHERE PROJECT_ID = #{projectId}
ORDER BY CREATION_DATE DESC;
```
