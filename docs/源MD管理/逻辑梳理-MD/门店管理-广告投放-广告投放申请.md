# 门店管理-广告投放-广告投放申请

## 业务流程

### 业务流程图

```text
经销商/门店        新建广告投放申请      保存申请单         提交审批          OA审批
选择广告项目  →   填写广告信息    →   applyType=2   →   校验金额>0  →   推送OA审批
填写投放信息       选择额度内/外        生成申请单号       推送OA数据       ↓
                                                              ↓        审批通过/驳回
                                                    额度外扣减预算    OA回调处理
                                                    额度内占用额度    更新审批状态
```

### 上游依赖

| 上游模块 | 依赖类型 | 依赖说明 | 依赖成立条件 |
|---------|---------|---------|------------|
| 门店档案 | 数据依赖 | 提供门店信息、经销商信息、销售区域、运营中心 | 门店已建档 |
| 年度资源额度 | 数据依赖 | 提供可用金额（额度内）或额度外可用余额 | 年度预算已配置 |
| 预算超额配置 | 数据依赖 | 额度外申请时扣减/回加预算金额 | 额度外(bxType=2)时依赖 |
| OA审批系统 | 配置依赖 | 推送OA审批表单，接收OA回调结果 | OA单据配置"YXZT广告投放申请"已配置 |
| 值集配置 | 配置依赖 | 广告媒介类型、媒介项目等值集 | AE_ADVERT_MEDIUM_TYPE/AE_ADVERT_MEDIUM_ITEM值集已配置 |
| 工作流引擎 | 配置依赖 | 发起审批流程SUB_ADJ_PLACEMENT_APPLY | 工作流已部署 |

### 下游影响

- 影响1：广告费报销
  - 审批通过后可发起广告费报销申请，报销金额不超过审批金额

- 影响2：额度外预算扣减
  - 额度外(bxType=2)审批通过时扣减BUD_OVER_BUDGET表的TAX_TOTAL_AMT；驳回时加回

- 影响3：额度内资源占用
  - 额度内(bxType=1)审批通过后占用年度资源额度，影响后续申请的可用金额

- 影响4：完工验收
  - 审批通过后可发起完工验收申请（storeCheck模块）

## 重点逻辑

### 重点逻辑1：额度内与额度外区分 {费用类型}

- **业务意义**：广告投放申请分为额度内和额度外两种，预算控制逻辑不同

- **具体逻辑描述**

  - 第1点：bxType=1为额度内，使用年度资源额度内的可用金额

  - 第2点：bxType=2为额度外，审批通过时扣减BUD_OVER_BUDGET预算表，驳回时加回

  - 第3点：额度外可用余额=可用金额-占用金额

### 重点逻辑2：OA审批集成 {OA集成}

- **业务意义**：广告投放申请走OA审批流程，需推送数据到OA并处理回调

- **具体逻辑描述**

  - 第1点：提交时组装广告投放数据（申请单号、广告项目、媒介类型等）推送到OA系统

  - 第2点：OA审批通过回调时，更新可用金额、申请总金额、审批总金额、使用占比等字段

  - 第3点：OA审批驳回回调时，额度外需加回已扣减的预算金额

  - 第4点：通过callbackSource变量(1=通过/2=驳回)驱动工作流分支

### 重点逻辑3：申请使用占比计算 {金额计算}

- **业务意义**：自动计算申请使用占比和批准使用占比

- **具体逻辑描述**

  - 第1点：申请使用占比=申请总金额/可用金额（保留6位小数）

  - 第2点：批准使用占比=审批总金额/可用金额×100（保留6位小数）

  - 第3点：可用金额为0时占比为0，避免除零异常

### 重点逻辑4：申请金额校验 {核心校验}

- **业务意义**：确保申请总金额大于0，防止空单提交

- **具体逻辑描述**

  - 第1点：OA提交前校验申请总金额(totalApplyAmtBx)必须>0

  - 第2点：申请总金额<=0时报错"申请总金额必须大于0！"

#### 按钮1：提交（详情页）

- **触发条件**：审批状态为NEW
- **执行逻辑**：
  - 第1点：校验申请总金额(totalApplyAmtBx)>0
  - 第2点：组装广告投放数据（申请单号、广告项目、媒介类型、经销商等）推送OA
  - 第3点：额度外(bxType=2)审批通过时扣减BUD_OVER_BUDGET预算表TAX_TOTAL_AMT
  - 第4点：发起工作流SUB_ADJ_PLACEMENT_APPLY
- **接口调用**：OA推送接口 + 工作流发起接口
- **排查SQL**：

```sql
SELECT fee_apply_id, fee_apply_no, apply_type, bx_type, total_apply_amt_bx, hz_approve_status
FROM fin_fee_apply_header WHERE fee_apply_id = {id};
```

#### 按钮2：查询可用余额（详情页）

- **触发条件**：费用类型为额度外(bxType=2)
- **执行逻辑**：
  - 第1点：传入预算年度、部门ID、费用类型ID
  - 第2点：可用余额=可用金额-占用金额
- **接口调用**：POST /v1/{organizationId}/fin-fee-apply-headers/query-amt
- **排查SQL**：

```sql
SELECT available_amt, occupy_amt FROM bud_over_budget
WHERE bud_year = #{budYear} AND entid = #{divisionId} AND fee_type_id = #{feeTypeId};
```

    - 第2点：金额<=0时报错"申请总金额必须大于0！"

  - 系统体现：阻断性报错

  - 详细逻辑

    - 第2点：objid为0时报错"流程中objid为0，流程失败！"

  - 系统体现：阻断性报错

  - 排查SQL：

    ```sql

    ```

### 状态机

#### 状态机流转图

```text
NEW(新建) ──提交──→ RUN(审批中) ──OA审批通过──→ APPROVED(已审核)
                        │                        │
                        │OA审批驳回               │
                        ↓                        ↓
                   REJECTED(已驳回)          可发起报销/完工验收
```

#### 状态机列表

| 状态机名称 | 状态释义 | 可执行的操作 |
|-----------|---------|------------|
| NEW | 新建，未提交 | 编辑、保存、提交、作废 |
| RUN | 审批中，OA审批中 | 无（等待OA审批结果） |
| APPROVED | 已审核，OA审批通过 | 发起报销、完工验收 |
| REJECTED | 已驳回，OA审批驳回 | 编辑、重新提交 |

#### 报错1：申请总金额必须大于0！
- **触发条件**：点击"提交"按钮，OA推送前调用doCheckAdvertiseAmt校验时，totalApplyAmtBx<=0
- **逻辑分析**：提交审批前需确保申请总金额有效。校验逻辑读取FIN_FEE_APPLY_HEADER.TOTAL_APPLY_AMT_BX，若该值<=0则抛出阻断性异常，阻止OA推送和工作流发起。常见根因：用户未填写金额、金额被错误置0、或前端未做必填校验直接提交空单。
- **排查SQL**：
  ```sql
  SELECT fee_apply_id        AS 申请单ID,
         fee_apply_no        AS 申请单号,
         total_apply_amt_bx  AS 申请总金额,
         hz_approve_status   AS 审批状态
  FROM   fin_fee_apply_header
  WHERE  apply_type = 2
  AND    total_apply_amt_bx <= 0
  ORDER  BY create_time DESC;
  ```

#### 报错2：流程中objid为0，流程失败！
- **触发条件**：点击"提交"按钮，发起工作流SUB_ADJ_PLACEMENT_APPLY时，传入的objid（单据主键FEE_APPLY_ID）为0或null
- **逻辑分析**：工作流引擎需用objid关联业务单据。若保存时未正确回写FEE_APPLY_ID（如自增序列未取回、事务未提交即发起流程），或前端未传id字段，会导致objid=0。工作流无法定位单据，流程发起失败。
- **排查SQL**：
  ```sql
  SELECT fee_apply_id        AS 申请单ID,
         fee_apply_no        AS 申请单号,
         hz_instance_id      AS 工作流实例ID,
         hz_approve_status   AS 审批状态
  FROM   fin_fee_apply_header
  WHERE  apply_type = 2
  AND    (fee_apply_id = 0 OR fee_apply_id IS NULL)
  ORDER  BY create_time DESC;
  ```

#### 报错3：推送OA失败：广告投放申请不存在
- **触发条件**：点击"提交"按钮推送OA时，按feeApplyId查询FIN_FEE_APPLY_HEADER返回null
- **逻辑分析**：OA推送前需查询申请单组装数据。若单据在推送前被其他用户删除（物理删除），或feeApplyId传值错误，查询返回空，无法组装OA数据导致推送失败。
- **排查SQL**：

  ```sql
         hz_approve_status   AS 审批状态
  FROM   fin_fee_apply_header
  WHERE  apply_type = 2
  AND    fee_apply_id = #{传入的feeApplyId};
  ```

#### 报错4：OA回调失败：广告投放申请不存在！

- **逻辑分析**：OA回调处理需更新申请单审批状态、可用金额、审批总金额等。若回调期间单据被删除，或OA回调报文的单据ID与DMS不一致（如OA配置错误、ID映射异常），查询返回空，回调处理失败，审批状态无法更新。
