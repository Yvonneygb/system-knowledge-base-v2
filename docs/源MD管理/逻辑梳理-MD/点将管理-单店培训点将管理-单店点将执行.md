# 点将管理-单店培训点将管理-单店点将执行

> 后端代码位于mbo-business微服务（源码未包含在当前源码目录下），以下逻辑基于前端API定义和页面组件代码梳理。

## 业务流程

### 业务流程图

```text
单店点将审批通过
        |
        v
单店点将执行列表(本页面) ──autoQuery──→ 加载执行中数据
        |
        ├──→ 查看申请 ──→ 跳转经销商单店点将详情页(isExecute=true)
        ├──→ 查看确认书 ──→ 调用queryPDF接口 ──→ 新窗口打开PDF
        ├──→ 特殊取消 ──→ 填写取消原因 ──→ 提交specialCancel接口
        ├──→ 结束执行 ──→ 填写实际开始/结束时间+备注 ──→ 提交endExecute接口
        ├──→ 同步OA ──→ 调用pushOa接口 ──→ 刷新列表
        ├──→ 同步FDD ──→ 调用pushFdd接口 ──→ 刷新列表
        └──→ 同步CRM ──→ 调用pushCrm接口 ──→ 刷新列表
```

### 上游依赖

| 上游模块 | 依赖类型 | 依赖说明 | 依赖成立条件 |
|---------|---------|---------|------------|
| 单店点将管理 | 数据依赖 | 审批通过后申请进入执行环节 | 申请审批状态为approved |
| HZERO权限服务 | 配置依赖 | 提供按钮权限校验 | 用户已登录且分配了对应角色 |
| HZERO值集服务 | 配置依赖 | 提供点将状态、审核状态等值集 | 值集已配置 |
| 讲师档案 | 数据依赖 | 提供讲师信息 | 讲师档案已创建 |
| 讲师排期 | 数据依赖 | 提供讲师档期数据 | 排期已占用 |
| 经销商主档 | 数据依赖 | 提供经销商信息 | 经销商已存在 |
| 门店主档 | 数据依赖 | 提供门店信息 | 门店已存在 |

### 下游影响

- 影响1：经销商单店点将详情页
  - 查看申请跳转，传入isExecute=true参数

- 影响2：OA审批系统
  - 同步OA推送流程，记录推送结果

- 影响3：法大大电子签约
  - 同步FDD推送签约，生成结算确认书

- 影响4：CRM订单系统
  - 同步CRM推送订单，回写CRM单号

- 影响5：讲师排期
  - 完成执行后释放讲师档期，讲师可承接新点将

- 影响6：讲师饱和度统计
  - 完成执行后刷新饱和度数据

## 重点逻辑

### 重点逻辑1：执行状态跟踪

- **业务意义**：确保培训从审批通过到实际完成的全过程可追溯

- **具体逻辑描述**

  - 第1点：点将生效后进入执行阶段，需跟踪实际培训执行情况

  - 第2点：状态流转为待执行→执行中→已完成，状态变更需记录操作人和时间

  - 第3点：执行完成后自动释放讲师排期，更新讲师可用时间

  - 第4点：展示当前用户有权限查看的所有已生效点将记录

### 重点逻辑2：结束执行逻辑

- **业务意义**：记录培训实际执行情况，作为讲师费用结算和档期释放的依据

- **具体逻辑描述**

  - 第1点：结束执行通过Modal弹窗实现，需填写实际开始时间、实际结束时间、结束备注

  - 第2点：结束执行人自动填充当前登录用户，不可编辑

  - 第3点：提交时将日期格式化为YYYY-MM-DD

  - 第4点：调用POST /mlt/trainApply/endExecute接口，成功后刷新当前页列表

### 重点逻辑3：特殊取消逻辑

- **业务意义**：允许对已生效的点将进行特殊取消，处理异常情况

- **具体逻辑描述**

  - 第1点：特殊取消通过Modal弹窗实现，需填写取消原因（必填）

  - 第2点：弹窗同时展示申请详情（type=view）

  - 第3点：提交调用POST /mlt/trainApply/specialCancel接口，传入cancelReason和applyCode

### 重点逻辑4：同步外部系统

- **业务意义**：将点将执行数据同步到OA、法大大、CRM等外部系统

- **具体逻辑描述**

  - 第1点：同步OA调用POST /mlt/trainApply/pushOa接口

  - 第2点：同步FDD调用POST /mlt/trainApply/pushFdd接口

  - 第3点：同步CRM调用POST /mlt/trainApply/sendCrmOrder接口

  - 第4点：同步成功后刷新当前页列表

### 保存校验

- 校验1：结束执行必填项校验 —— 确保结束执行记录完整

  - 详细逻辑

    - 第1点：实际开始时间realStartDate必填

    - 第2点：实际结束时间realEndDate必填

    - 第3点：结束备注endExecuteRemark必填

  - 系统体现：toast提醒对应字段不能为空

  - 排查SQL：

    ```sql
    SELECT APPLY_CODE
    FROM TRAIN_APPLY
    WHERE APPLY_CODE = :applyCode
      AND (REAL_START_DATE IS NULL OR REAL_END_DATE IS NULL OR END_REMARK IS NULL);
    ```

- 校验2：特殊取消原因必填 —— 确保取消操作有明确原因记录

  - 详细逻辑

    - 第1点：取消原因cancelReason必填

  - 系统体现：toast提醒"取消原因不能为空"

  - 排查SQL：

    ```sql
    SELECT APPLY_CODE
    FROM TRAIN_APPLY
    WHERE APPLY_CODE = :applyCode
      AND CANCEL_REASON IS NULL;
    ```

### 提交校验

无审批按钮，通过同步OA/FDD/CRM推送外部系统。无工作流编码。

### 状态机

#### 状态机流转图

```text
待执行(PENDING) → 执行中(EXECUTING) → 已完成(COMPLETED)
                      |
                      └→ 特殊取消(CANCELLED)
```

#### 状态机列表

| 状态机名称 | 状态释义 | 可执行的操作 |
|-----------|---------|------------|
| PENDING | 待执行 | 查看申请、特殊取消 |
| EXECUTING | 执行中 | 查看申请、查看确认书、结束执行、特殊取消、同步OA/FDD/CRM |
| COMPLETED | 已完成 | 查看申请、查看确认书 |
| CANCELLED | 已取消 | 查看申请 |

#### 报错1：请选择一条数据
- **触发条件**：单选行操作（查看申请/查看确认书/特殊取消/结束执行/同步OA/同步FDD/同步CRM）前未选择列表行，或选择了多行
- **逻辑分析**：前端校验选中行数量=1，不满足时toast提示
- **排查SQL**：
  ```sql
  -- 本校验为前端选中行校验，无对应SQL；如需确认列表数据可执行：
  SELECT ta.APPLY_CODE AS 申请编码, ta.TRAIN_NAME AS 培训名称, ta.ORDER_LECTURE_STATE AS 点将状态
  FROM TRAIN_APPLY ta
  WHERE ta.APPLY_TYPE_ONE = 'train' AND ta.APPROVAL_STATE = 'approved'
  ORDER BY ta.UPDATE_DATE DESC;
  ```

#### 报错2：请求失败
- **触发条件**：调用 page/queryPDF/specialCancel/endExecute/pushOa/pushFdd/sendCrmOrder 等接口时
- **逻辑分析**：后端 mbo-business 微服务异常、网络中断或接口返回非2xx状态码
- **排查SQL**：
  ```sql
  SELECT ta.APPLY_CODE AS 申请编码, ta.ERROR_INFO AS 异常信息,
         ta.CRM_ORDER_STATUS AS CRM状态, ta.UPDATE_DATE AS 更新时间
  FROM TRAIN_APPLY ta
  WHERE ta.ERROR_INFO IS NOT NULL
  ORDER BY ta.UPDATE_DATE DESC;
  ```

#### 报错3：实际开始时间不能为空

- **逻辑分析**：结束执行弹窗 realStartDate 字段必填，前端 endExecuteFormDS.validate() 校验不通过时提示
- **排查SQL**：

  ```sql
  SELECT ta.APPLY_CODE AS 申请编码, ta.REAL_START_DATE AS 实际开始时间
  FROM TRAIN_APPLY ta
  WHERE ta.ORDER_LECTURE_STATE = 'completed'
    AND ta.REAL_START_DATE IS NULL;
  ```

#### 报错4：实际结束时间不能为空

- **逻辑分析**：结束执行弹窗 realEndDate 字段必填，前端校验不通过时提示
- **排查SQL**：
  ```sql
  SELECT ta.APPLY_CODE AS 申请编码, ta.REAL_END_DATE AS 实际结束时间
  FROM TRAIN_APPLY ta
  WHERE ta.ORDER_LECTURE_STATE = 'completed'
    AND ta.REAL_END_DATE IS NULL;
  ```

#### 报错5：结束备注不能为空
- **触发条件**：点击"结束执行"提交时，结束备注 endExecuteRemark 为空
- **逻辑分析**：结束执行弹窗 endExecuteRemark 字段必填（TextArea），前端校验不通过时提示
- **排查SQL**：
  ```sql
  SELECT ta.APPLY_CODE AS 申请编码, ta.END_REMARK AS 结束备注
  FROM TRAIN_APPLY ta
  WHERE ta.ORDER_LECTURE_STATE = 'completed'
    AND (ta.END_REMARK IS NULL OR ta.END_REMARK = '');
  ```

#### 报错6：取消原因不能为空
- **触发条件**：点击"特殊取消"提交时，取消原因 cancelReason 为空
- **逻辑分析**：特殊取消弹窗 cancelReason 字段必填（TextArea），前端校验不通过时提示

  ```sql
  SELECT ta.APPLY_CODE AS 申请编码, ta.CANCEL_REASON AS 取消原因
  FROM TRAIN_APPLY ta
  WHERE ta.ORDER_LECTURE_STATE = 'cancelled'
    AND (ta.CANCEL_REASON IS NULL OR ta.CANCEL_REASON = '');
  ```

#### 报错7：未查询到对应的确认书
- **触发条件**：点击"查看确认书"时，queryPDF 接口返回的 PDF URL 为空
- **逻辑分析**：调用 GET queryPDF 接口（参数 applyCode、applyTypeOne=train、applyTypeTwo=apply）未返回 PDF URL，可能因 FDD 推送未完成或失败
- **排查SQL**：
  ```sql
  SELECT ta.APPLY_CODE AS 申请编码, ta.FDD_PDF_URL AS 确认书URL,
         ta.FDD_PUSH_STATUS AS FDD推送状态, ta.ERROR_INFO AS 异常信息
  FROM TRAIN_APPLY ta
  WHERE ta.APPLY_CODE = :applyCode
    AND (ta.FDD_PDF_URL IS NULL OR ta.FDD_PDF_URL = '');
  ```

#### 报错8：网络异常/接口超时
- **触发条件**：任意接口调用时，网络中断或接口响应超过 axios timeout 配置
- **逻辑分析**：前端 axios 请求未收到响应或响应超时，触发 catch 回调统一提示"请求失败"。常见根因：网络中断、mbo-business 服务假死、数据库慢查询、外部系统响应慢等。需检查网络连通性、后端服务负载、数据库性能
- **排查SQL**：
  ```sql
  SELECT APPLY_CODE AS 申请编码, TRAIN_NAME AS 培训名称,
         ORDER_LECTURE_STATE AS 点将状态,
         TO_CHAR(LAST_UPDATE_DATE,'YYYY-MM-DD HH24:MI:SS') AS 最后更新时间
  FROM TRAIN_APPLY
  WHERE APPLY_TYPE_ONE = 'train' AND APPLY_TYPE_TWO = 'apply'
    AND LAST_UPDATE_DATE >= SYSDATE - 1
  ORDER BY LAST_UPDATE_DATE DESC;
  ```

#### 报错9：权限不足
- **触发条件**：点击查看申请、特殊取消、结束执行、同步OA/FDD/CRM等按钮时，当前用户无对应 permissionList 权限码
- **逻辑分析**：前端 Button 组件通过 permissionList 配置权限码，HZERO 框架校验当前用户角色是否包含该权限码，未包含则按钮不可见或禁用。若强制调用接口，后端也会校验权限返回403。需联系管理员配置对应角色权限
- **排查SQL**：
  ```sql
  SELECT U.USER_NAME AS 用户名, R.ROLE_NAME AS 角色名, P.PERMISSION_CODE AS 权限码
  FROM SYS_USER U
  LEFT JOIN SYS_USER_ROLE UR ON U.USER_ID = UR.USER_ID
  LEFT JOIN SYS_ROLE R ON UR.ROLE_ID = R.ROLE_ID
  LEFT JOIN SYS_ROLE_PERMISSION RP ON R.ROLE_ID = RP.ROLE_ID
  LEFT JOIN SYS_PERMISSION P ON RP.PERMISSION_ID = P.PERMISSION_ID
  WHERE P.PERMISSION_CODE LIKE '%single_store_general_execute%' ORDER BY U.USER_NAME;
  ```

#### 报错10：数据不存在
- **触发条件**：查看申请、结束执行等操作时，接口返回数据为空或申请编码不存在
- **逻辑分析**：前端通过 applyCode 调用详情接口，后端查询 TRAIN_APPLY 表无对应记录或记录已逻辑删除，返回空数据。常见根因：申请编码错误、申请已被删除、跨租户查询、数据权限隔离等。需检查 APPLY_CODE 有效性及数据权限
- **排查SQL**：
  ```sql
  SELECT APPLY_CODE AS 申请编码, TRAIN_NAME AS 培训名称,
         ORDER_LECTURE_STATE AS 点将状态, DELETE_FLAG AS 删除标记
  FROM TRAIN_APPLY
  WHERE APPLY_TYPE_ONE = 'train' AND APPLY_TYPE_TWO = 'apply'
    AND (DELETE_FLAG = 'Y' OR APPLY_CODE IS NULL);
  ```

#### 报错11：状态不允许操作
- **触发条件**：点击结束执行、特殊取消等按钮时，申请状态不在允许操作的状态范围内
- **逻辑分析**：后端校验申请状态机，如结束执行要求状态为执行中、特殊取消要求审批通过且培训开始前7天内等。状态不匹配时后端返回业务异常，前端提示后端返回的 message。需检查申请当前状态及操作流程
- **排查SQL**：
  ```sql
  SELECT APPLY_CODE AS 申请编码, TRAIN_NAME AS 培训名称,
         ORDER_LECTURE_STATE AS 点将状态, APPROVAL_STATE AS 审核状态,
         CANCEL_APPROVAL_STATE AS 取消审核状态, ERROR_INFO AS 异常问题
  FROM TRAIN_APPLY
  WHERE APPLY_TYPE_ONE = 'train' AND APPLY_TYPE_TWO = 'apply'
    AND ORDER_LECTURE_STATE NOT IN ('valid','executing','finished')
  ORDER BY CREATE_DATE DESC;
  ```

#### 报错12：同步外部系统失败
- **触发条件**：点击同步CRM/同步OA/同步FDD按钮，对应推送接口返回失败
- **逻辑分析**：前端通过 PRequest 调用 pushCrm/pushOa/pushFdd 接口，接口返回 success=false 或非2xx状态码时触发错误回调。常见根因：CRM/OA/FDD 外部系统不可用、数据不符合外部接口要求、申请状态不允许同步、网络中断等。后端会将异常写入 ERROR_INFO 字段
- **排查SQL**：
  ```sql
  SELECT APPLY_CODE AS 申请编码, TRAIN_NAME AS 培训名称,
         CRM_ORDER_CODE AS CRM单号, CRM_ORDER_STATUS AS CRM订单状态,
         ERROR_INFO AS 异常问题,
         TO_CHAR(LAST_UPDATE_DATE,'YYYY-MM-DD HH24:MI:SS') AS 最后更新时间
  FROM TRAIN_APPLY
  WHERE APPLY_TYPE_ONE = 'train' AND APPLY_TYPE_TWO = 'apply'
    AND (ERROR_INFO IS NOT NULL OR CRM_ORDER_STATUS = 'FAIL')
    AND LAST_UPDATE_DATE >= SYSDATE - 7
  ORDER BY LAST_UPDATE_DATE DESC;
  ```

#### 报错13：值集数据不显示
- **触发条件**：查询条件或列表中点将状态、审核状态等下拉选项为空
- **逻辑分析**：前端通过 lookupCode 查询值集 MBO.ORDER_LECTURE_STATE、MBO.APPLY_APPROVAL_STATE 等，值集未配置或未启用则下拉选项为空。需在值集管理页面配置对应值集
- **排查SQL**：
  ```sql
  SELECT LOOKUP_CODE AS 值集编码, LOOKUP_VALUE_CODE AS 值编码,
         LOOKUP_VALUE_NAME AS 值名称, ENABLE_FLAG AS 启用标记
  FROM SYS_LOOKUP_VALUE
  WHERE LOOKUP_CODE IN ('MBO.ORDER_LECTURE_STATE','MBO.APPLY_APPROVAL_STATE','MBO.CANCEL_APPROVAL_STATE')
    AND ENABLE_FLAG = 'N' ORDER BY LOOKUP_CODE;
  ```

### 常见问题

- 问题1：结束执行后讲师排期未释放
  - 原因：排期释放逻辑未执行或异常，排查SQL：SELECT * FROM MA_LECTURER_SCHEDULE WHERE APPLY_CODE = :applyCode AND STATUS = 'occupied';
  - 解决思路：检查结束执行接口返回状态，手动触发排期释放

- 问题2：CRM推送失败
  - 原因：CRM系统不可用或数据校验失败，排查SQL：SELECT APPLY_CODE, CRM_ORDER_CODE, CRM_ORDER_STATUS, ERROR_INFO FROM TRAIN_APPLY WHERE APPLY_CODE = :applyCode AND CRM_ORDER_STATUS IS NULL;
  - 解决思路：查看ERROR_INFO异常信息，修复后点击同步CRM重新推送
