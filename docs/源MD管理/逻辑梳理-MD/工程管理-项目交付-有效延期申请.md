### 流程说明

1. **查询阶段**：选择紧急要货单后查询明细，校验不存在未审核完毕的延期申请，展示可延期行项和最大有效期
2. **保存阶段**：填写延期至日期后保存，校验延期日期必须大于最大有效期，生成单据号（编码规则`AE.URGENT_EXTEND_BILLNO`）
3. **审批阶段**：提交后触发H0工作流（`VALIDITY_POST_PONE`），审批通过后回调`wfComplete`
4. **处理阶段**：审批通过后按行项分情况处理：延期日期过期则全部失效；否则逐行校验有效性，有效行推送ERP延期，无效行标记失效

## 重点逻辑

### 重点逻辑1：同一紧急要货单不允许存在多条未审核完毕的延期申请

- **业务意义**：防止同一紧急要货单同时存在多条延期申请导致有效期冲突
- **具体逻辑描述**：
  1. 查询详情时，若该紧急要货单存在状态非"审核通过(5)"的延期申请，则阻断并提示"该紧急要货单存在有未审核完毕的延期申请单"
  2. 新建保存时，同样校验是否存在未审核完毕的延期申请，存在则阻断
  3. 更新保存时，允许当前延期单自身存在，但不允许其他未审核完毕的延期单存在

### 重点逻辑2：延期日期必须大于已延期最大有效期

- **业务意义**：确保延期是向后延伸，不允许缩短有效期或重复延期
- **具体逻辑描述**：
  1. 最大有效期=该紧急要货单所有可延期行项中`VALID_DATE`的最大值
  2. 可延期行项条件：接口成功(`INTF_RESULT='S'`)、未过期(`IS_OVERDUE!=2`)、未取消(`IS_CANCEL!=2`)、有效期在未来(`Trunc(VALID_DATE)>Trunc(sysdate)`)、有预留数量(`RESERVED_QTY+PRE_RESERVED_QTY+RELEASED_QTY!=0`)
  3. 保存时校验延期日期必须严格大于最大有效期，否则阻断提示"延期时间不能小于等于已延期的最大时间"

### 重点逻辑3：审批通过后分情况处理行项

- **业务意义**：根据延期日期和行项状态，区分可推送EBS和不可推送的行项
- **具体逻辑描述**：
  1. 若延期日期已早于当前日期（`extendValidDate.isBefore(LocalDate.now())`），则全部行项标记为失效（`CANNOT_EXTEND=2`），不调用EBS
  2. 若延期日期≥当前日期，则逐行判断行项是否仍有效（`valid()`方法）
  3. 已失效的行项标记`CANNOT_EXTEND=2`，仍有效的行项调用EBS接口推送延期
  4. EBS接口返回S则更新紧急要货行有效期；返回E则仅记录接口失败信息，不影响其他行项

### 重点逻辑4：可延期行项筛选条件

- **业务意义**：只有满足条件的紧急要货行项才能参与延期
- **具体逻辑描述**：
  1. 接口调用状态`INTF_RESULT='S'`（成功）
  2. 未过期：`IS_OVERDUE != 2`
  3. 未取消：`IS_CANCEL != 2`
  4. 有效期在未来：`Trunc(VALID_DATE) > Trunc(sysdate)`
  5. 有预留数量：`(RESERVED_QTY + PRE_RESERVED_QTY + RELEASED_QTY) != 0`

### 重点逻辑5：ERP延期调用与结果处理

- **业务意义**：对有效行通过ERP接口执行延期，更新本地数据
- **具体逻辑描述**：
  1. 查询CRM订单行信息（`crmSaleOrderItemV`），获取CRM头ID和行ID
  2. 调用`ValidityPostponeInft.pushData`传入CRM头ID、行ID和延期日期
  3. 调用`interfaceInvoke`发送ERP请求，返回`status`（S/E）和`msg`
  4. 更新`EPM_URGENT_EXTEND_LINE`的`INTF_RESULT`和`INTF_INFO`
  5. ERP成功时更新`EPM_URGENT_ORDER_LINE.VALID_DATE`为延期日期

### 保存校验

- 校验1：延期日期必须大于已延期的最大有效期 —— 确保延期是向后延伸
  - **详细逻辑**：查询该紧急要货单所有可延期行项中`VALID_DATE`的最大值（`maxValidDate`），比较用户输入的`extendValidDate`与`maxValidDate`，若`extendValidDate <= maxValidDate`则阻断
  - **系统体现**：`EpmUrgentExtendServiceImpl.saveOrUpdate`第88-90行，抛出`CommonException("延期时间不能小于等于已延期的最大时间")`
  - **排查SQL**：
    ```sql
    SELECT MAX(el.VALID_DATE) AS max_valid_date
    FROM EPM_URGENT_ORDER_LINE el
    WHERE el.URGENT_ORDER_ID = :urgentOrderId
      AND el.INTF_RESULT = 'S'
      AND el.IS_OVERDUE != 2
      AND el.IS_CANCEL != 2
      AND TRUNC(el.VALID_DATE) > TRUNC(SYSDATE)
      AND (el.RESERVED_QTY + el.PRE_RESERVED_QTY + el.RELEASED_QTY) != 0;
    ```

- 校验2：同一紧急要货单不允许存在未审核完毕的延期申请 —— 防止有效期冲突
  - **详细逻辑**：查询`EPM_URGENT_EXTEND`表中同一`urgentOrderId`且`STAT != 5`的记录，若存在（新建时任何记录；更新时排除自身的其他记录）则阻断
  - **系统体现**：`EpmUrgentExtendServiceImpl.saveOrUpdate`第91-98行（新建）和第105-107行（更新），抛出`CommonException("该紧急要货单存在有未审核完毕的延期申请单")`
  - **排查SQL**：
    ```sql
    SELECT * FROM EPM_URGENT_EXTEND
    WHERE URGENT_ORDER_ID = :urgentOrderId
      AND STAT != 5;
    ```

- 校验3：延期申请基础数据必须存在 —— 确保紧急要货单有效
  - **详细逻辑**：根据`urgentOrderId`查询延期基础数据，若返回空则阻断
  - **系统体现**：`EpmUrgentExtendServiceImpl.saveOrUpdate`第83-86行，抛出`CommonException("紧急要货延期申请单不存在")`
  - **排查SQL**：
    ```sql
    SELECT * FROM EPM_URGENT_ORDER eo
    WHERE eo.URGENT_ORDER_ID = :urgentOrderId
      AND eo.HZ_APPROVE_STATUS = 'APPROVED';
    ```

### 提交校验

- 校验1：延期申请单必须存在 —— 确保数据完整性
  - **详细逻辑**：根据`objId`查询`EPM_URGENT_EXTEND`记录，若不存在则阻断
  - **系统体现**：`EpmUrgentExtendServiceImpl.wfProcSubmit`第242-245行，抛出`CommonException("紧急要货延期申请单不存在")`
  - **排查SQL**：
    ```sql
    SELECT * FROM EPM_URGENT_EXTEND WHERE URGENT_EXTEND_ID = :urgentExtendId;
    ```

- 校验2：删除时已审核通过的延期申请单不能删除 —— 确保审批后数据不可删
  - **详细逻辑**：查询延期申请单，若`STAT = APPROVED`则阻断
  - **系统体现**：`EpmUrgentExtendServiceImpl.delete`第134-136行，抛出`CommonException("已审核通过的紧急要货延期申请单不能删除")`
  - **排查SQL**：
    ```sql
    SELECT STAT FROM EPM_URGENT_EXTEND WHERE URGENT_EXTEND_ID = :urgentExtendId;
    ```

### 状态机

#### 状态机流转图

```text
新建 → 制单(1) → 已提交(-1) → 审核通过(5)
                ↑                ↓
                └──── 可删除 ←───┘(审批拒绝/撤回后)
```

#### 状态机列表

| 状态值 | 状态释义 | 可执行的操作 |
|--------|---------|------------|
| 1 | 制单 | 保存、删除、提交 |
| -1 | 已提交 | 等待审批（由工作流控制） |
| 5 | 审核通过 | 不可编辑、不可删除 |
| 99 | 已作废 | 不可操作 |

#### 报错1：延期时间不能小于等于已延期的最大时间
- **触发条件**：保存延期申请时，延期日期≤当前所有有效行中最大的VALID_DATE
- **逻辑分析**：保存校验中查询紧急要货行的最大VALID_DATE，若延期日期≤最大值则抛出阻断性报错。延期是向后延伸，不允许缩短有效期
- **排查SQL**：
  ```sql
  SELECT euol.URGENT_ORDER_LINE_ID, euol.VALID_DATE, MAX(euol.VALID_DATE) OVER() AS 已延期最大有效期
  FROM EPM_URGENT_ORDER_LINE euol
  WHERE euol.URGENT_ORDER_HEAD_ID = :urgentOrderHeadId
    AND euol.INTF_RESULT = 'S'
    AND euol.IS_OVERDUE <> 2
    AND euol.IS_CANCEL <> 2
  -- 对比延期日期与已延期最大有效期
  ```

#### 报错2：该紧急要货单存在有未审核完毕的延期申请单
- **触发条件**：保存延期申请时，同一紧急要货单已有审批中(STAT<>5)的延期申请
- **逻辑分析**：保存校验中按URGENT_ORDER_HEAD_ID查询EPM_URGENT_EXTEND_HEAD筛选STAT<>5，若存在(排除当前单据)则抛出阻断性报错。需等原单审批完成或删除后新建
- **排查SQL**：
  ```sql
  SELECT eueh.URGENT_EXTEND_HEAD_ID, eueh.URGENT_EXTEND_CODE, eueh.URGENT_ORDER_HEAD_ID,
         eueh.STAT, eueh.HZ_APPROVE_STATUS
  FROM EPM_URGENT_EXTEND_HEAD eueh
  WHERE eueh.URGENT_ORDER_HEAD_ID = :urgentOrderHeadId
    AND eueh.STAT <> 5
    AND eueh.URGENT_EXTEND_HEAD_ID <> :currentExtendHeadId
  -- 查出未审核完毕的延期申请
  ```

#### 报错3：延期申请基础数据必须存在
- **触发条件**：保存延期申请时，紧急要货单无效或查询EPM_URGENT_ORDER_LINE为空
- **逻辑分析**：保存校验中按URGENT_ORDER_HEAD_ID查询紧急要货行，若为空则抛出阻断性报错。需检查紧急要货单有效性
- **排查SQL**：
  ```sql
  SELECT euoh.URGENT_ORDER_HEAD_ID, euoh.URGENT_ORDER_CODE, euoh.HZ_APPROVE_STATUS,
         (SELECT COUNT(*) FROM EPM_URGENT_ORDER_LINE euol
          WHERE euol.URGENT_ORDER_HEAD_ID = euoh.URGENT_ORDER_HEAD_ID) AS 要货行数
  FROM EPM_URGENT_ORDER_HEAD euoh
  WHERE euoh.URGENT_ORDER_HEAD_ID = :urgentOrderHeadId
  -- 若要货行数为0，则触发该报错
  ```

#### 报错4：延期申请单必须存在
- **触发条件**：提交延期申请时，按ID查询EPM_URGENT_EXTEND_HEAD为空
- **逻辑分析**：提交方法中按URGENT_EXTEND_HEAD_ID查询延期申请单，若返回null则抛出阻断性报错。需检查单据是否存在
- **排查SQL**：
  ```sql
  SELECT eueh.URGENT_EXTEND_HEAD_ID, eueh.URGENT_EXTEND_CODE, eueh.STAT, eueh.HZ_APPROVE_STATUS
  FROM EPM_URGENT_EXTEND_HEAD eueh
  WHERE eueh.URGENT_EXTEND_HEAD_ID = :urgentExtendHeadId
  -- 若返回空，说明延期申请单不存在
  ```

#### 报错5：已审核通过的延期申请单不能删除
- **触发条件**：删除延期申请单时，单据STAT=5(已审核通过)
- **逻辑分析**：删除方法中校验STAT<>5，已审核通过的单据不允许删除。需通过其他方式处理
- **排查SQL**：
  ```sql
  SELECT eueh.URGENT_EXTEND_HEAD_ID, eueh.URGENT_EXTEND_CODE, eueh.STAT, eueh.HZ_APPROVE_STATUS
  FROM EPM_URGENT_EXTEND_HEAD eueh
  WHERE eueh.URGENT_EXTEND_HEAD_ID = :urgentExtendHeadId
  -- 期望 STAT <> 5
  ```

#### 报错6：EBS接口调用失败
- **触发条件**：审批通过后调用EBS接口，EBS返回错误状态(E)
- **逻辑分析**：审批通过后逐行调用EBS接口延期库存预留，若返回E则更新INTF_RESULT='E'和INTF_INFO。可能原因：EBS侧库存预留已释放、数据异常。不影响其他行项
- **排查SQL**：
  ```sql
  SELECT euel.URGENT_EXTEND_LINE_ID, euel.URGENT_EXTEND_HEAD_ID, euel.ITEM_CODE,
         euel.INTF_RESULT, euel.INTF_INFO, euel.CANNOT_EXTEND
  FROM EPM_URGENT_EXTEND_LINE euel
  WHERE euel.URGENT_EXTEND_HEAD_ID = :urgentExtendHeadId
    AND euel.INTF_RESULT = 'E'
  -- 查出EBS接口失败的行及错误信息
  ```

#### 报错7：查询详情时存在未审核完毕的延期申请单
- **触发条件**：查询延期申请明细时（selectDetailByOrderId），同一紧急要货单存在STAT<>5（非审核通过）的延期申请记录
- **逻辑分析**：selectDetailByOrderId方法中按urgentOrderId查询EPM_URGENT_EXTEND筛选STAT<>AuditStatEnum.APPROVED.getCode()，若存在记录则抛出阻断性报错"该紧急要货单存在有未审核完毕的延期申请单【延期单号】"。该报错在页面加载查询明细时触发，先于保存校验。需先等原延期申请审批完成或删除后再进入
- **排查SQL**：
  ```sql
  SELECT eue.URGENT_EXTEND_ID, eue.URGENT_EXTEND_BILLNO, eue.URGENT_ORDER_ID,
         eue.STAT, eue.HZ_APPROVE_STATUS
  FROM EPM_URGENT_EXTEND eue
  WHERE eue.URGENT_ORDER_ID = :urgentOrderId
    AND eue.STAT <> 5
  -- 查出未审核完毕的延期申请，若存在则查询详情被阻断
  ```

#### 报错8：删除时延期申请单不存在
- **触发条件**：删除延期申请单时，按urgentExtendId查询EPM_URGENT_EXTEND返回null
- **逻辑分析**：delete方法中先按主键查询延期申请单，若返回null则抛出阻断性报错"紧急要货延期申请单不存在"。常见原因：单据已被其他用户删除、传入ID错误。需确认单据ID有效性
- **排查SQL**：
  ```sql
  SELECT eue.URGENT_EXTEND_ID, eue.URGENT_EXTEND_BILLNO, eue.STAT
  FROM EPM_URGENT_EXTEND eue
  WHERE eue.URGENT_EXTEND_ID = :urgentExtendId
  -- 若返回空，说明延期申请单已被删除或ID错误
  ```

#### 报错9：审批回调时延期申请单不存在
- **触发条件**：H0工作流审批通过回调wfComplete时，按dto.objId查询EPM_URGENT_EXTEND返回null
- **逻辑分析**：wfComplete方法中按objId查询延期申请单，若返回null则抛出阻断性报错"紧急要货延期申请单不存在"。常见原因：工作流回调参数objId与延期申请单ID不一致、单据在审批期间被删除。需检查流程回调参数与单据一致性
- **排查SQL**：
  ```sql
  SELECT eue.URGENT_EXTEND_ID, eue.URGENT_EXTEND_BILLNO, eue.STAT,
         eue.HZ_INSTANCE_ID, eue.HZ_APPROVE_STATUS
  FROM EPM_URGENT_EXTEND eue
  WHERE eue.URGENT_EXTEND_ID = :objId
  -- 若返回空，说明回调时单据不存在
  ```

**Q1：为什么提示"该紧急要货单存在有未审核完毕的延期申请单"？**
A：该紧急要货单已有一张延期申请单处于审批中（`STAT != 5`），需等该单据审批完成或删除后才能新建。

**Q2：为什么提示"延期时间不能小于等于已延期的最大时间"？**
A：输入的延期至日期必须大于当前所有有效行中最大的`VALID_DATE`，否则无法提交。

**Q3：审批通过后为什么某些行标记为"不可延期"？**
A：这些行不满足延期条件：接口状态非'S'、已超期（`IS_OVERDUE=2`）、已失效（`IS_CANCEL=2`）、有效期已过（`VALID_DATE ≤ 当前时间`）、或数量已全部释放。

**Q4：延期申请单删除条件？**
A：仅未审核通过（`STAT != 5`）的延期申请单可以删除。

**Q5：审批通过后部分行项EBS接口调用失败怎么办？**
A：EBS接口返回错误状态(E)，可能是EBS侧库存预留已释放或数据异常。查看`INTF_INFO`字段中的EBS返回信息，确认EBS侧数据状态后重新提交延期申请。

**Q6：审批通过后行项全部标记为不满足延期条件怎么办？**
A：延期日期在审批通过时已早于当前日期（审批流程耗时过长导致延期日期过期），或所有行项已过期/已取消。重新创建延期申请，设置更远的延期日期；或确认紧急要货行项的有效性状态。
