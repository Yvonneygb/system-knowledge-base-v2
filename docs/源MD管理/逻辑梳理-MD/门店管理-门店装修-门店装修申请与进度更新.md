# 门店管理-门店装修-门店装修申请与进度更新

## 业务流程

```
门店装修申请与进度更新列表页
        │
        ├── 新增 ──→ 选择门店(LOV,排除已有未审完申请的门店)
        │              ──→ 查询门店等级对应装修标准 ──→ 填写装修申请信息
        │                                                    │
        │                                                    ▼
        │                                              保存 ──→ HZ_APPROVE_STATUS=NEW
        │                                                    │
        │                                                    ▼
        │                                              提交审批 ──→ 启动OA工作流(SUB_STORE_MDZXBZSQYJDG)
        │                                                    │
        │                                                    ▼
        │                                              OA审批流程中(多节点:经销商上传照片/设计师提交方案/设计经理审批/展示总监等)
        │                                                    │
        │                                         ├──审批通过──→ HZ_APPROVE_STATUS=APPROVED
        │                                         │              ├─ 计算装修间隔期/超期天数/扣减比例
        │                                         │              ├─ 更新门店状态terminalStat=1
        │                                         │              └─ 超期天数>Over_Date_Limit时自动发起关闭申请(FIN_FEE_APPLY_CLOSE)
        │                                         │
        │                                         ├──审批驳回──→ HZ_APPROVE_STATUS=REJECTED
        │                                         │              └─ 恢复门店原始状态
        │                                         │
        │                                         └──退回──→ HZ_APPROVE_STATUS=NEW
        │                                                       └─ 恢复门店原始状态
        │
        ├── 作废 ──→ 仅NEW/REJECTED状态可作废 ──→ HZ_APPROVE_STATUS=INTERRUPT ──→ 解绑CRM软装订单
        │
        ├── 重新生成 ──→ 校验同门店无其他非INTERRUPT单 ──→ 校验超期天数≤Over_Date_Limit ──→ 重置为NEW
        │
        ├── 发起签呈 ──→ 查询签呈列表 ──→ 二次变更(isSecondChange=2)
        │
        └── 打印 ──→ 获取打印数据(含审批历史)
```

## 重点逻辑

### 重点逻辑1：装修标准自动计算

- **业务意义**：根据门店装修等级和类型自动匹配政策补贴标准，确保申请金额有据可依
- **具体逻辑描述**：
  - 选择门店后根据fixupGrade(装修等级)+terminalType(门店类型)+thisTerminalArea(装修面积)调用do-search-decorate接口查询装修标准
  - 返回额度内/额度外/店面/门头四类政策补贴标准(元/㎡)
  - 政策补贴金额 = 政策补贴标准 × 装修面积
  - 申请补贴金额 = 申请补贴标准 × 装修面积
  - 差异金额 = 政策补贴金额 - 申请补贴金额

### 重点逻辑2：超期扣减计算

- **业务意义**：装修超期完成时按比例扣减补贴金额，控制装修时效
- **具体逻辑描述**：
  - 超期天数 = (装修完成时间 - 交付设计时间) - 装修周期
  - 扣减比例 = 超期天数 × 公司参数Deduct_Pro / 100（封顶100%）
  - 申请标准金额 = 申请标准 × 装修面积 × (1 - 扣减比例)
  - 差异标准金额 = 政策标准金额 - 申请标准金额

### 重点逻辑3：审批通过自动发起关闭

- **业务意义**：装修严重超期时系统自动发起关闭申请，扣减经销商额度
- **具体逻辑描述**：
  - 审批通过后若超期天数 > 公司参数Over_Date_Limit
  - 系统自动创建FinFeeApplyClose记录(关闭原因:申请单超过最大装修超期天数，系统自动发起装修申请关闭)
  - 调用doCalDeductionAmt计算扣减金额
  - 自动启动FIN_FEE_APPLY_CLOSE工作流

### 重点逻辑4：门店状态联动

- **业务意义**：装修申请流程中锁定门店状态，防止并发操作
- **具体逻辑描述**：
  - 提交审批时：保存门店原始状态到originalStat，设置terminalStat=4(装修中)
  - 审批通过时：设置terminalStat=1(正常)
  - 驳回/退回时：恢复terminalStat=originalStat

### 重点逻辑5：作废解绑软装订单

- **业务意义**：作废装修申请时解除已绑定的CRM软装采购订单关联
- **具体逻辑描述**：
  - 作废后查询已绑定的CRM销售订单(queryCrmSaleOrderV)
  - 调用unbindSoftOrder解绑软装订单

#### 按钮1：作废（列表页行操作）

- **触发条件**：HZ_APPROVE_STATUS为NEW或REJECTED
- **执行逻辑**：
  1. 弹窗输入作废原因(applyCause)
  2. 调用operate接口，设置HZ_APPROveStatus=INTERRUPT
  3. 解绑已绑定的CRM软装采购订单(queryCrmSaleOrderV + unbindSoftOrder)
  4. 刷新列表

#### 按钮2：重新生成（列表页行操作）

- **触发条件**：HZ_APPROVE_STATUS为APPROVED
- **执行逻辑**：
  1. 调用valid-regenerate接口校验
  2. 校验同一门店无其他非INTERRUPT状态的申请单
  3. 校验超期天数≤公司参数Over_Date_Limit且扣减比例<1
  4. 清空terminalApplyId/terminalApplyNo/hzInstanceId，重置hzApproveStatus=NEW
  5. 返回重置后的数据用于新增

#### 按钮3：发起签呈（列表页行操作）

- **触发条件**：HZ_APPROVE_STATUS为APPROVED
- **执行逻辑**：
  1. 调用do-search-modify查询可发起签呈的申请单列表(isModify=1)
  2. 选择目标申请单
  3. 调用do-update-second-change批量设置isSecondChange=2

#### 按钮4：删除（列表页行操作）

- **触发条件**：HZ_APPROVE_STATUS为NEW

  2. 调用do-delete删除主表记录及关联照片明细

#### 按钮5：打印（详情页）

  3. 翻译值集含义(terminalType/fixupGrade/propertyType/locationType)

### 保存校验

- 校验1：门店编码/门店名称/经销商名称/简称必填 —— 确保关联门店信息完整
  - **详细逻辑**：前端DataSet字段required=true，C7N内置校验
  - **系统体现**：保存时后端校验terminalId和custId非空
  - **排查SQL**：`SELECT TERMINAL_APPLY_ID, TERMINAL_CODE, CUST_CODE FROM FIN_FEE_APPLY_FINISHED_HEADER WHERE TERMINAL_ID IS NULL OR CUST_ID IS NULL`

- 校验2：装修周期≤公司参数Decoration_Days —— 控制装修时效上限
  - **详细逻辑**：doInsert/doUpdate时读取系统参数Decoration_Days，若decorationDays>参数值抛异常
  - **系统体现**：后端validSystemParam("Decoration_Days")校验
  - **排查SQL**：`SELECT PARAM_VALUE FROM SYS_PARAM WHERE PARAM_CODE='Decoration_Days'`

- 校验3：本次装修面积≤门店面积 —— 防止面积超限
  - **详细逻辑**：前端validateArea方法校验thistimeTerminalArea≤terminalArea
  - **系统体现**：前端message.info提示并回填为门店面积
  - **排查SQL**：`SELECT TERMINAL_APPLY_ID, TERMINAL_AREA, THIS_TERMINAL_AREA FROM FIN_FEE_APPLY_FINISHED_HEADER WHERE THIS_TERMINAL_AREA > TERMINAL_AREA`

- 校验4：旧店上次装修时间(decorationType=2时必填) —— 旧店重装需记录上次装修时间
  - **详细逻辑**：前端dynamicProps.required根据decorationType=2动态校验
  - **系统体现**：前端DataSet字段dynamicProps配置
  - **排查SQL**：`SELECT TERMINAL_APPLY_ID FROM FIN_FEE_APPLY_FINISHED_HEADER WHERE DECORATION_TYPE=2 AND LAST_DECORATION_DATE IS NULL`

- 校验5：单据不在变更中 —— 防止变更和提交冲突
  - **详细逻辑**：onUserSubmit时校验isModify≠2
  - **系统体现**：后端抛异常"单据正在申请变更中，不可提交！"
  - **排查SQL**：`SELECT TERMINAL_APPLY_ID, IS_MODIFY FROM FIN_FEE_APPLY_FINISHED_HEADER WHERE IS_MODIFY=2`

### 提交校验

- 校验1：预算年度≤当前年份 —— 防止提前发起未来年度申请
  - **详细逻辑**：onUserSubmit时校验budYear-LocalDate.now().getYear()≤0
  - **系统体现**：后端抛异常"申请单的预算年度不可晚于当前年份，不可提前发起申请"
  - **排查SQL**：`SELECT TERMINAL_APPLY_ID, BUD_YEAR FROM FIN_FEE_APPLY_FINISHED_HEADER WHERE BUD_YEAR > EXTRACT(YEAR FROM SYSDATE)`

- 校验2：预算额度充足 —— 确保额度外预算有剩余
  - **详细逻辑**：onUserSubmit时若额度内申请金额>0，查询viewOverBudgetAmt(feeTypeId=66014601)校验剩余额度≥0
  - **系统体现**：后端抛异常"{budYear}的预算剩余可用额度不足"
  - **排查SQL**：`SELECT * FROM FIN_FEE_CHECK_BX_HEADER WHERE BUD_YEAR={year} AND FEE_TYPE_ID='66014601'`

- 校验3：有政策标准 —— 确保装修等级有对应政策
  - **详细逻辑**：onUserSubmit时校验fixupGrade非空非0，查询terminalDecorateStandardRepository.selectFixupGradeList非空
  - **系统体现**：后端抛异常"无政策标准不能提交"/"店面装修等级没有对应的政策标准"
  - **排查SQL**：`SELECT * FROM TERMINAL_DECORATE_LINE WHERE FIXUP_GRADE={grade} AND ORGANIZATION_ID={orgId}`

- 校验4：有有效期内政策标准 —— 确保政策在当前时间有效
  - **详细逻辑**：onUserSubmit时调用doSearchDecorate查询有效期内的装修标准，非空校验
  - **系统体现**：后端抛异常"店面装修等级没有有效期内的政策标准"
  - **排查SQL**：`SELECT * FROM TERMINAL_DECORATE_LINE WHERE FIXUP_GRADE={grade} AND START_DATE<=SYSDATE AND END_DATE>=SYSDATE`

- 校验5：单据不在变更中 —— 防止变更和提交冲突
  - **详细逻辑**：onUserSubmit时校验isModify≠2
  - **系统体现**：后端抛异常"单据正在申请变更中，不可提交！"
  - **排查SQL**：`SELECT TERMINAL_APPLY_ID, IS_MODIFY FROM FIN_FEE_APPLY_FINISHED_HEADER WHERE IS_MODIFY=2`

### 状态机

```text
NEW(新建) ──提交审批──→ RUN(审批中) ──┬──审批通过──→ APPROVED(已审批)
                                       │              ├─ 计算超期/扣减
                                       │              ├─ 门店状态→1(正常)
                                       │              └─ 超期>限制时自动发起关闭申请
                                       │
                                       ├──审批驳回──→ REJECTED(已驳回)
                                       │              └─ 恢复门店原始状态
                                       │
                                       └──退回──→ NEW(新建)
                                                   └─ 恢复门店原始状态

NEW/REJECTED ──作废──→ INTERRUPT(已作废) ──→ 解绑CRM软装订单
APPROVED ──重新生成──→ NEW(新建)
APPROVED ──发起签呈──→ isSecondChange=2
```

### 工作流

- **工作流编码**：`SUB_STORE_MDZXBZSQYJDG`（门店装修申请与进度更新）
- **编码规则**：`AE.TERMINAL_APPLY_NO`（装修申请单号，参数divisionCode）
- **审批节点**：经销商上传装修后照片 → 门店设计师提交方案 → 软装设计师提交方案 → 设计经理审批 → 展示总监审批
- **OA回传**：doProcessOA处理OA审批结果回传，更新装修面积/等级/计划开业时间/装修周期/设计师等信息

## 常见问题FAQ

### Q1：装修申请提交时报"预算剩余可用额度不足"

**根因**：该预算年度的额度外预算(feeTypeId=66014601)剩余可用额度<0
**解决方案**：联系财务确认预算额度是否已用完，或调整申请金额

### Q2：装修申请提交时报"店面装修等级没有有效期内的政策标准"

**根因**：该装修等级在当前时间范围内没有有效的装修标准政策(START_DATE~END_DATE未覆盖当前日期)
**解决方案**：在门店装修标准设置中新增或延长该等级的政策有效期

### Q3：作废时报"新建、审核拒绝的单据才能作废"

**根因**：单据状态非NEW或REJECTED，可能已在审批中(RUN)或已审批(APPROVED)
**解决方案**：已审批单据不可作废，如需关闭请走关闭申请流程

### Q4：重新生成时报"该门店已有其它装修申请单"

**根因**：同一门店存在其他非INTERRUPT状态的装修申请单
**解决方案**：先作废其他申请单，再重新生成

### Q5：重新生成时报"超期天数大于限制或补贴金额为0"

**根因**：超期天数>公司参数Over_Date_Limit，或扣减比例≥1(补贴金额已全部扣减)
**解决方案**：超期严重的申请单不可重新生成，需新建申请

### Q6：审批通过后自动发起了关闭申请

**根因**：装修超期天数>公司参数Over_Date_Limit，系统自动创建FinFeeApplyClose并启动FIN_FEE_APPLY_CLOSE工作流
**解决方案**：这是系统正常逻辑，需在关闭申请流程中处理扣减额度

### Q7：提交时报"单据正在申请变更中，不可提交"

**根因**：isModify=2，单据已发起变更申请
**解决方案**：先完成或撤销变更申请，再提交

#### 报错1：门店装修申请及完成信息不存在
- **触发条件**：doSelect/doInsert/doUpdate/doDelete/operate/validRegenerate/onWfComplete/onUserSubmit等操作，finFeeApplyFinishedHeaderMapper.selectByPrimaryKey按TERMINAL_APPLY_ID查询返回null
- **逻辑分析**：装修申请单是各操作的主数据源，需先校验存在。若申请单在操作期间被其他用户删除、TERMINAL_APPLY_ID传值错误（如前端缓存失效ID）、或并发场景下被清理，查询返回空抛异常。需核查申请单数据是否仍存在。
- **排查SQL**：
  ```sql
  SELECT f.terminal_apply_id   AS 装修申请ID,
         f.terminal_apply_no   AS 申请单号,
         f.terminal_code       AS 门店编码,
         f.hz_approve_status   AS 审批状态,
         f.update_time         AS 最后更新时间
  FROM   fin_fee_apply_finished_header f
  WHERE  f.terminal_apply_id = #{传入的terminalApplyId};
  ```

#### 报错2：门店信息不存在
- **触发条件**：onWfBreak/breakWF/onUserSubmit操作，mktTerminalRepository.selectByPrimaryKey按terminalId查询MKT_TERMINAL返回null或originalStat为空
- **逻辑分析**：装修申请需联动更新门店状态(提交时置4-装修中、通过时置1-正常、驳回时恢复originalStat)。若门店档案被删除、terminalId传值错误、或originalStat未在提交时正确保存（导致驳回时无法恢复），查询返回空抛异常。需核查门店档案与申请单关联一致性。
- **排查SQL**：
  ```sql
  SELECT f.terminal_apply_id AS 装修申请ID,
         f.terminal_apply_no AS 申请单号,
         f.terminal_id       AS 门店ID,
         f.terminal_code     AS 门店编码,
         f.original_stat     AS 门店原始状态,
         m.terminal_stat     AS 门店当前状态,
         m.usable            AS 有效状态
  FROM   fin_fee_apply_finished_header f
  LEFT   JOIN mkt_terminal m ON m.terminal_id = f.terminal_id
  WHERE  f.hz_approve_status IN ('RUN','REJECTED')
  AND    (m.terminal_id IS NULL OR f.original_stat IS NULL)
  ORDER  BY f.update_time DESC;
  ```

#### 报错3：装修周期只能小于等于:{v},请检查
- **触发条件**：doInsert/doUpdate保存时，validSystemParam("Decoration_Days")校验decorationDays>公司参数Decoration_Days的值
- **逻辑分析**：装修周期受公司参数Decoration_Days上限约束，确保装修时效可控。若用户填写的decorationDays超过公司参数配置值（如参数30但填了45），校验不通过抛异常。需修改装修周期至≤Decoration_Days。
- **排查SQL**：
  ```sql
  SELECT f.terminal_apply_id   AS 装修申请ID,
         f.terminal_apply_no   AS 申请单号,
         f.decoration_days     AS 装修周期,
         p.param_value         AS 公司参数值
  FROM   fin_fee_apply_finished_header f
  ```

- **逻辑分析**：软装设计师提交方案节点需维护灯具补贴标准，用于计算灯具补贴金额。若该节点未选择lanternStandard（值集AE.LANTERN_PURCHASE_STANDARD），前端notification.error提示并阻断保存/提交。需在软装设计师提交方案节点选择灯具补贴标准。
- **排查SQL**：
  ```sql
  SELECT f.terminal_apply_id AS 装修申请ID,
         f.terminal_apply_no AS 申请单号,
         f.lantern_standard  AS 灯具补贴标准,
         f.hz_approve_status AS 审批状态
  FROM   fin_fee_apply_finished_header f
  WHERE  f.lantern_standard IS NULL
  AND    f.hz_approve_status IN ('NEW','RUN');
  ```

#### 报错25：店面产权归属不允许为空

- **逻辑分析**：产权归属影响装修补贴的政策适用和财务处理，需必填。若门店档案未维护propertyType、或选择门店时未带入，前端notification.error提示并阻断保存/提交。需在门店档案中维护产权归属后重新发起申请。

#### 报错26：备注不能超过80个字
- **触发条件**：详情页保存时，前端校验note(备注)字段长度>80
- **逻辑分析**：备注字段限制80字符，防止过长文本影响数据库存储和界面展示。若用户输入超长备注，前端notification.error提示并阻断保存。需精简备注内容至≤80字符。


#### 报错27：请先选择门店编码
- **触发条件**：详情页计算扣除金额或保存时，前端校验headDS中terminalCode(门店编码)为空
- **逻辑分析**：装修申请依赖门店关联的装修信息，需先选择有效门店联动带出门店等级、面积、地址等。若用户未选择门店即操作、或LOV选择失败未回填terminalCode，前端message.info提示并阻断操作。需先选择门店再操作。


#### 报错28：本次店面装修面积不能大于门店面积
- **触发条件**：详情页编辑面积字段时，前端校验thistimeTerminalArea(本次店面装修面积)>terminalArea(门店面积)
- **逻辑分析**：本次店面装修面积不应超过门店总面积，防止面积超限导致补贴金额计算异常。政策补贴金额=政策补贴标准×装修面积，若本次装修面积>门店面积，金额计算将超出实际范围。前端message.info提示并回填为门店面积，需修改本次装修面积至≤门店面积。
- **排查SQL**：
  ```sql
  SELECT f.terminal_apply_id     AS 装修申请ID,
         f.terminal_apply_no     AS 申请单号,
         f.terminal_area         AS 门店面积,
         f.thistime_terminal_area AS 本次店面装修面积
  FROM   fin_fee_apply_finished_header f
  WHERE  f.thistime_terminal_area > f.terminal_area;
  ```

#### 报错29：店面实际装修面积不能大于本次店面装修面积
- **触发条件**：详情页编辑面积字段时，前端校验thisTerminalArea(店面实际装修面积)>thistimeTerminalArea(本次店面装修面积)
- **逻辑分析**：店面实际装修面积应≤本次店面装修面积，防止面积数据逻辑矛盾。本次店面装修面积是本次装修的面积上限，实际装修面积是其中实际完成的部分。前端message.info提示并阻断保存，需修改店面实际装修面积至≤本次店面装修面积。
- **排查SQL**：
  ```sql
  SELECT f.terminal_apply_id     AS 装修申请ID,
         f.terminal_apply_no     AS 申请单号,
         f.this_terminal_area    AS 店面实际装修面积,
         f.thistime_terminal_area AS 本次店面装修面积
  FROM   fin_fee_apply_finished_header f
  WHERE  f.this_terminal_area > f.thistime_terminal_area;
  ```
