<KbCard num="1" title="重点逻辑1：纯查询页面，无增删改操作">
<ul><li><strong>业务意义</strong>：供内部人员查询折扣政策的产品明细信息，了解各产品的折扣率、特价、封顶数量等详细配置</li></ul>
<ul><li><strong>具体逻辑描述</strong></li></ul>
<ul><li>第1点：本页面为hlod低代码报表页面，无独立前端源码，仅提供查询和导出功能</li></ul>
<ul><li>第2点：不支持新增、修改、删除操作</li></ul>
<ul><li>第3点：查询结果关联产品拓展表，展示月平均动销数量、库存消化月数、现有量、库龄等扩展信息</li></ul>
</KbCard>

<KbCard num="2" title="重点逻辑2：产品明细行关联二级明细">
<ul><li><strong>业务意义</strong>：折扣政策产品明细行下可挂载二级明细行，定义不同折扣率/特价阶梯</li></ul>
<ul><li><strong>具体逻辑描述</strong></li></ul>
<ul><li>第1点：每个产品明细行(applicationType=1产品/2型号)下可有多条二级明细行，定义不同折扣率/特价</li></ul>
<ul><li>第2点：申请类型=3(全产品)时，无二级明细行，折扣率/特价直接在产品行上</li></ul>
</KbCard>

<KbCard num="3" title="重点逻辑3：多表关联查询">
<ul><li><strong>业务意义</strong>：通过多表关联获取完整的政策明细信息</li></ul>
<ul><li><strong>具体逻辑描述</strong></li></ul>
<ul><li>第1点：头表(EPM_DISCOUNT_POLICY) INNER JOIN 行表(ITEM) INNER JOIN 行明细(ITEM_LINE)</li></ul>
<ul><li>第2点：LEFT JOIN 扩展表(ITEM_EXT) LEFT JOIN 行扩展(DPIL_EXT)</li></ul>
</KbCard>

<KbCard num="4" title="重点逻辑4：适用客户编码聚合">
<ul><li><strong>业务意义</strong>：将政策关联的多个客户编码聚合为一个字符串展示</li></ul>
<ul><li><strong>具体逻辑描述</strong></li></ul>
<ul><li>第1点：通过LISTAGG函数将EPM_DISCOUNT_POLICY_CUSTOMER中的customer_code逗号拼接</li></ul>
</KbCard>

<KbCard num="5" title="重点逻辑5：有效日期区间查询">
<ul><li><strong>业务意义</strong>：查询某日期区间内有交集的政策</li></ul>
<ul><li><strong>具体逻辑描述</strong></li></ul>
<ul><li>第1点：传入effectiveDateStart时，要求政策effective_date_start ≤ 查询日期 AND effective_date_end ≥ 查询日期</li></ul>
<ul><li>第2点：即查询日期落在政策有效期内</li></ul>
</KbCard>

<KbCard num="6" title="重点逻辑6：业务类型动态翻译">
<ul><li><strong>业务意义</strong>：根据销售渠道选择不同值集翻译业务类型</li></ul>
<ul><li><strong>具体逻辑描述</strong></li></ul>
<ul><li>第1点：channel=1(家装)用epm.home.business_type1</li></ul>
<ul><li>第2点：channel=3(样品)用epm.home.business_type2</li></ul>
<ul><li>第3点：其他(工程)用epm.engineer.business_type</li></ul>
</KbCard>

<h4>报错1：查询条件不能为空</h4>
<ul><li><strong>触发条件</strong>：用户点击"查询"按钮时，所有查询条件(折扣政策编码/名称/客户/项目/有效日期等)均为空</li><li><strong>逻辑分析</strong>：前端校验至少需输入一个查询条件，因折扣政策明细数据量大，强制要求至少一个过滤条件以避免全表扫描。该报错为toast提醒级别，不发起后端请求</li><li><strong>排查SQL</strong>：</li></ul>
<pre class="detail-sql" v-pre><code>-- 前端校验为主，后端可结合如下SQL确认条件下的数据量
  SELECT COUNT(*) AS 满足条件数据量
  FROM EPM_DISCOUNT_POLICY edp
  WHERE (:discountPolicyCode IS NULL OR edp.DISCOUNT_POLICY_CODE LIKE '%' || :discountPolicyCode || '%')
    AND (:discountPolicyName IS NULL OR edp.DISCOUNT_POLICY_NAME LIKE '%' || :discountPolicyName || '%')
    AND (:customerCode IS NULL OR EXISTS (
        SELECT 1 FROM EPM_DISCOUNT_POLICY_CUSTOMER edpc
        WHERE edpc.DISCOUNT_POLICY_ID = edp.DISCOUNT_POLICY_ID AND edpc.CUSTOMER_CODE = :customerCode))</code></pre>
<h4>报错2：无权限访问</h4>
<ul><li><strong>触发条件</strong>：非内部用户(userType≠I)访问折扣政策明细查询(内部)接口时</li><li><strong>逻辑分析</strong>：该接口为内部用户专用，后端通过当前登录用户类型(userType)校验，仅内部用户(userType=I)允许访问。经销商(userType=D)或外部用户访问时返回无权限错误。该报错为阻断性报错</li><li><strong>排查SQL</strong>：</li></ul>
<pre class="detail-sql" v-pre><code>-- 校验当前用户类型
  SELECT iu.USER_ID, iu.USER_NAME, iu.USER_TYPE, iu.REAL_NAME
  FROM IAM_USER iu
  WHERE iu.USER_ID = :currentUserId
  -- 期望 USER_TYPE = 'I'，否则无权限</code></pre>
<h4>报错3：政策失效id不允许为空</h4>
<ul><li><strong>触发条件</strong>：查询折扣政策失效行明细时，未传入discountPolicyDisabledId参数或参数为空</li><li><strong>逻辑分析</strong>：调用getDisabledLineList接口查询EPM_DISCOUNT_POLICY_DISABLE_LINE(政策失效行表)时，必须传入discountPolicyDisabledId作为关联EPM_DISCOUNT_POLICY_DISABLE头表的外键。若为空则无法定位失效行数据，抛出阻断性报错</li><li><strong>排查SQL</strong>：</li></ul>
<pre class="detail-sql" v-pre><code>-- 校验传入的政策失效ID是否存在
  SELECT edpd.DISABLE_ID, edpd.DISCOUNT_POLICY_ID, edpd.DISABLE_DATE, edpd.HZ_APPROVE_STATUS
  FROM EPM_DISCOUNT_POLICY_DISABLE edpd
  WHERE edpd.DISABLE_ID = :discountPolicyDisabledId
  -- 若返回空，说明传入的失效ID不存在</code></pre>
<h4>报错4：查询无数据</h4>
<ul><li><strong>触发条件</strong>：用户点击"查询"按钮时，查询条件无匹配数据</li><li><strong>逻辑分析</strong>：后端search方法按查询条件关联EPM_DISCOUNT_POLICY、EPM_DISCOUNT_POLICY_ITEM、EPM_DISCOUNT_POLICY_ITEM_LINE多表查询，若结果集为空则前端展示"无数据"。需调整查询条件</li><li><strong>排查SQL</strong>：</li></ul>

  FROM EPM_DISCOUNT_POLICY edp

    AND (:discountPolicyName IS NULL OR edp.DISCOUNT_POLICY_NAME LIKE '%' || :discountPolicyName || '%')</code></pre>
<h4>报错6：报表查询超时</h4>
<ul><li><strong>触发条件</strong>：查询时，查询数据量过大导致数据库查询超时</li><li><strong>逻辑分析</strong>：后端search方法关联EPM_DISCOUNT_POLICY、EPM_DISCOUNT_POLICY_ITEM、EPM_DISCOUNT_POLICY_ITEM_LINE、EPM_DISCOUNT_POLICY_ITEM_EXT多表查询，若查询条件过宽导致数据量过大则可能超时。需缩小查询范围</li><li><strong>排查SQL</strong>：</li></ul>
<pre class="detail-sql" v-pre><code>SELECT COUNT(*) AS 预估数据量
  FROM EPM_DISCOUNT_POLICY edp
  INNER JOIN EPM_DISCOUNT_POLICY_ITEM edpi ON edpi.DISCOUNT_POLICY_ID = edp.DISCOUNT_POLICY_ID
  -- 若数据量过大(超过10万)，建议缩小查询范围</code></pre>
<h4>报错7：导出失败，请稍后重试</h4>
<ul><li><strong>触发条件</strong>：导出时，导出处理异常(如内存不足、IO异常等)</li><li><strong>逻辑分析</strong>：导出方法中try-catch捕获异常，若处理失败则提示稍后重试。需稍后重试或联系管理员查看后端日志</li><li><strong>排查SQL</strong>：</li></ul>
<pre class="detail-sql" v-pre><code>SELECT sem.OBJID, sem.OBJTYPENAME, sem.ERROR_MSG, sem.CREATION_DATE
  FROM SYS_EXCEPTION_MSG sem
  WHERE sem.OBJTYPENAME = '折扣政策明细查询'
  ORDER BY sem.CREATION_DATE DESC</code></pre>
<h4>报错8：政策明细数据不完整</h4>
<ul><li><strong>触发条件</strong>：查询时，政策关联数据缺失(如产品明细行、阶梯明细行、扩展信息等缺失)</li><li><strong>逻辑分析</strong>：后端search方法关联查询EPM_DISCOUNT_POLICY_ITEM_EXT扩展表，若关联数据缺失则部分字段(如SM_STATE、月平均动销数量等)为空。需检查政策数据完整性</li><li><strong>排查SQL</strong>：</li></ul>
<pre class="detail-sql" v-pre><code>SELECT edpi.DISCOUNT_POLICY_ITEM_ID, edpi.ITEM_CODE, edpi.ITEM_NAME,
         edpie.SM_STATE, edpie.AVG_MONTH_DYNAMIC_SALE_NUM, edpie.INVENTORY_DIGESTION_MONTHS
  FROM EPM_DISCOUNT_POLICY_ITEM edpi
  LEFT JOIN EPM_DISCOUNT_POLICY_ITEM_EXT edpie ON edpi.DISCOUNT_POLICY_ITEM_ID = edpie.DISCOUNT_POLICY_ITEM_ID
  WHERE edpie.ID IS NULL
  -- 查出扩展信息缺失的产品明细行</code></pre>

<KbCard title="常见问题">
<ul><li>问题1：查询结果中部分产品明细行的拓展信息为空</li><li>原因：EPM_DISCOUNT_POLICY_ITEM_EXT表中无对应记录，可能为历史数据</li><li>解决思路：确认该产品明细行是否需要拓展信息，如需要可重新生成</li></ul>
<ul><li>问题2：生效状态含义不明确？</li><li>原因：VALID_STAT字段使用数值编码，0=未生效/1=生效/3=已失效</li><li>解决思路：通过值集翻译显示</li></ul>
<ul><li>问题3：有效日期查询的逻辑是什么？</li><li>原因：使用区间重叠判断：政策effective_date_start ≤ 查询日期 AND effective_date_end ≥ 查询日期</li><li>解决思路：即查询日期落在政策有效期内</li></ul>
<ul><li>问题4：业务类型为什么有不同的翻译？</li><li>原因：根据销售渠道(channel)动态选择值集：channel=1用epm.home.business_type1，channel=3用epm.home.business_type2，其他用epm.engineer.business_type</li><li>解决思路：这是预期行为，不同渠道使用不同业务类型值集</li></ul>
<ul><li>问题5：适用客户编码列表怎么展示？</li><li>原因：通过LISTAGG函数将EPM_DISCOUNT_POLICY_CUSTOMER表中该政策关联的所有customer_code用逗号拼接</li><li>解决思路：这是SQL聚合展示</li></ul>
<ul><li>问题6：导出时asyncThreshold=10000是什么意思？</li><li>原因：当数据量超过10000条时，导出切换为异步模式，避免超时</li><li>解决思路：缩小查询范围或等待异步导出完成</li></ul>
