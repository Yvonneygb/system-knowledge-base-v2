<KbCard num="1" title="重点逻辑1：纯报表查询页面">
<ul><li><strong>业务意义</strong>：供内部人员查询工程要货订单的汇总报表信息，了解工程要货订单整体情况</li></ul>
<ul><li><strong>具体逻辑描述</strong></li></ul>
<ul><li>第1点：本页面为hlod低代码报表页面，无独立前端源码，仅提供查询和导出功能</li></ul>
<ul><li>第2点：不支持新增、修改、删除操作</li></ul>
<ul><li>第3点：数据来源于要货订单头表和行表，通过searchFlag/billType区分工程要货</li></ul>
</KbCard>

<KbCard num="2" title="重点逻辑2：经销商数据隔离">
<ul><li><strong>业务意义</strong>：经销商登录时仅查看自己的订单数据</li></ul>
<ul><li><strong>具体逻辑描述</strong></li></ul>
<ul><li>第1点：经销商登录(userType=D)时自动将客户编码设置为经销商编码(DC)</li></ul>
<ul><li>第2点：仅查询该经销商的订单数据</li></ul>
</KbCard>

<KbCard num="3" title="重点逻辑3：工程家装区分">
<ul><li><strong>业务意义</strong>：通过isHome参数区分工程和家装要货订单报表</li></ul>
<ul><li><strong>具体逻辑描述</strong></li></ul>
<ul><li>第1点：isHome=0为工程要货订单报表，isHome=2为家装要货订单报表</li></ul>
<ul><li>第2点：工程时关联项目合同表查contract_unit</li></ul>
</KbCard>

<KbCard num="4" title="重点逻辑4：紧急要货筛选">
<ul><li><strong>业务意义</strong>：支持筛选紧急要货订单，查看紧急订单执行情况</li></ul>
<ul><li><strong>具体逻辑描述</strong></li></ul>
<ul><li>第1点：isUrgentOrder&gt;0时筛选orderStat in (3,6,12)且bill_type=1的订单</li></ul>
<ul><li>第2点：即常规订单中状态为已提交/部分发货/发货完成</li></ul>
</KbCard>

<KbCard num="5" title="重点逻辑5：产品条件模式">
<ul><li><strong>业务意义</strong>：支持按产品编码或产品型号查询，两种模式性能不同</li></ul>
<ul><li><strong>具体逻辑描述</strong></li></ul>
<ul><li>第1点：conditionFlag=1时直接关联行表like查询产品编码</li></ul>
<ul><li>第2点：conditionFlag≠1时用sa_out_bill_head_id in (子查询)方式查询产品型号</li></ul>
</KbCard>

<KbCard num="6" title="重点逻辑6：折扣率格式化">
<ul><li><strong>业务意义</strong>：折扣率以百分比格式展示，便于阅读</li></ul>
<ul><li><strong>具体逻辑描述</strong></li></ul>
<ul><li>第1点：discount_rate和base_discount_rate格式化为百分比</li></ul>
<ul><li>第2点：计算公式：ROUND(折扣率*100, 2)%，保留2位小数</li></ul>
</KbCard>

<h4>报错1：查询条件时间范围不能为空</h4>
<ul><li><strong>触发条件</strong>：用户点击"查询"或"导出"按钮时，订单日期起止范围(dateInvbillStart/dateInvbillEnd)未选择或为空</li><li><strong>逻辑分析</strong>：前端在调用查询接口前校验时间范围必填，因报表数据量大，强制要求按订单日期(DATE_INVBILL)区间过滤以避免全表扫描。后端search方法接收conditionDTO后，若dateInvbillStart或dateInvbillEnd为空亦会阻断查询。该报错为阻断性报错，不发起后端请求</li><li><strong>排查SQL</strong>：</li></ul>
<pre class="detail-sql" v-pre><code>-- 前端校验为主，后端可结合如下SQL确认时间范围内是否有数据
  SELECT COUNT(*) AS 期间数据量

<ul><li>问题2：经销商登录为什么只能看到自己的订单？</li><li>原因：经销商登录(userType=D)时系统自动将客户编码设置为经销商编码(DC)，实现数据隔离</li><li>解决思路：这是预期行为，经销商仅查看自己的订单</li></ul>
<ul><li>问题3：产品编码和产品型号查询有什么区别？</li><li>原因：产品编码(conditionFlag=1)直接在主查询关联行表like匹配；产品型号(conditionFlag≠1)用子查询方式匹配，性能不同</li><li>解决思路：优先使用产品编码查询以获得更好性能</li></ul>
<ul><li>问题4：紧急要货筛选条件是什么？</li><li>原因：isUrgentOrder&gt;0时筛选orderStat in (3,6,12)且bill_type=1的订单</li><li>解决思路：即常规订单中状态为已提交/部分发货/发货完成</li></ul>
<ul><li>问题5：导出时为什么organizationId=0要设为null？</li><li>原因：organizationId=0表示租户级查询（全事业部），设为null使SQL中该条件不生效</li><li>解决思路：这是预期行为，用于导出所有事业部的数据</li></ul>
<ul><li>问题6：申请人名称为什么有时显示客户简称？</li><li>原因：查询结果中createdName(iam_user.real_name)为空时，通过created_by_bak关联Customer表取short_name补充显示</li><li>解决思路：这是数据兼容处理，旧数据可能没有iam_user记录</li></ul>
