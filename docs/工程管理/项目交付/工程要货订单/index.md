<KbCard num="1" title="重点逻辑1：期望到达日期自动赋值订单类型">
<ul><li><strong>业务意义</strong>：根据当前日期和期望到达日期自动判断订单类型，控制常规订单和计划订单的下单规则</li></ul>
<ul><li><strong>具体逻辑描述</strong></li></ul>
<ul><li>第1点：当日≤25号时，期望日期为本月→常规订单(billType=1)，非本月→计划订单(billType=2)</li></ul>
<ul><li>第2点：当日&gt;25号时，仅瓷砖产品线(orderPdtLine=2)可下常规订单，非瓷砖产品线期望日期为次月→常规订单，超过次月→计划订单</li></ul>
<ul><li>第3点：海外事业部(organizationId=111)且二级类目为"境外注册出口经销商"时，常规订单=13，计划订单=14，业务类型=17</li></ul>
<ul><li>第4点：电商渠道(channel=2)计划订单期望日期限当月往后6个月内，常规订单限7个月内；非电商渠道计划订单限3个月内，常规订单限4个月内</li></ul>
</KbCard>

<KbCard num="2" title="重点逻辑2：可下单数量扣减/返还">
<ul><li><strong>业务意义</strong>：保存订单时扣减折扣单/合同的可下单数量，防止超量下单；修改/删除时返还</li></ul>
<ul><li><strong>具体逻辑描述</strong></li></ul>
<ul><li>第1点：保存前若为已有订单，先返还可下单数量(updateActiveQty, false)</li></ul>
<ul><li>第2点：保存后扣减可下单数量(updateActiveQty, true)</li></ul>
<ul><li>第3点：例外：家装订单且合同类型=1且orderQtyCtrlType=2且priceType=1时跳过扣减</li></ul>
</KbCard>

<KbCard num="3" title="重点逻辑3：折扣率回写">
<ul><li><strong>业务意义</strong>：保存后取订单行最低审批折扣回写到订单头，确保头表折扣率为最优惠值</li></ul>
<ul><li><strong>具体逻辑描述</strong></li></ul>
<ul><li>第1点：保存后取所有订单行中最低的EXTRA_DISCOUNT_RATE(审批折扣)</li></ul>
<ul><li>第2点：回写到订单头DISCOUNT_RATE字段</li></ul>
</KbCard>

<KbCard num="4" title="重点逻辑4：SM状态校验">
<ul><li><strong>业务意义</strong>：生成CRM订单前校验产品SM生命状态，防止已停产产品下单</li></ul>
<ul><li><strong>具体逻辑描述</strong></li></ul>
<ul><li>第1点：Z8状态产品禁止下单，阻断报错</li></ul>
<ul><li>第2点：Z6状态产品计划淘汰中，提示关注，确认后可继续</li></ul>
<ul><li>第3点：S6状态产品进入售后阶段，提示关注，确认后可继续</li></ul>
<ul><li>第4点：Z7状态产品有库存数量，发完即止，提示关注，确认后可继续</li></ul>
</KbCard>

<KbCard num="5" title="重点逻辑5：紧急行数限制">
<ul><li><strong>业务意义</strong>：控制紧急订单数量，防止滥用紧急通道</li></ul>
<ul><li><strong>具体逻辑描述</strong></li></ul>
<ul><li>第1点：仅计划订单(billType=2/14)可加紧急，常规订单(billType=1/13)有紧急行则报错</li></ul>
<ul><li>第2点：紧急行数≤CEIL(产品行数/5)，即每5行产品最多1行紧急</li></ul>
</KbCard>

<KbCard num="6" title="重点逻辑6：生成CRM订单校验链">
<ul><li><strong>业务意义</strong>：生成CRM订单前执行完整校验链，确保数据完整性和业务合规性</li></ul>
<ul><li><strong>具体逻辑描述</strong></li></ul>
<ul><li>第1点：校验地址信息完整性（省/市/县非空）</li></ul>
<ul><li>第2点：校验折扣单未过期（discountValidDate+1天 &gt; 当前时间）</li></ul>
<ul><li>第3点：校验开票单位有效性(checkBill)</li></ul>
<ul><li>第4点：校验合同非变更中、非已审批</li></ul>
<ul><li>第5点：校验产品下单数量未超过合同(doCheckBillQty)</li></ul>
<ul><li>第6点：校验SM状态</li></ul>
</KbCard>

<KbCard num="7" title="重点逻辑7：不扣订金OA审批">
<ul><li><strong>业务意义</strong>：特殊情形可走OA申请免扣定金，审批后标记生效</li></ul>
<ul><li><strong>具体逻辑描述</strong></li></ul>
<ul><li>第1点：仅常规订单(billType=1/13)且无要货单号时可申请</li></ul>
<ul><li>第2点：填写申请原因后送签OA审批</li></ul>
<ul><li>第3点：OA审批通过后更新nodepositOaAuditStat</li></ul>
</KbCard>

<KbCard num="8" title="重点逻辑8：经销商登录自动带出客户">
<ul><li><strong>业务意义</strong>：经销商登录时自动带出客户信息，简化操作</li></ul>
<ul><li><strong>具体逻辑描述</strong></li></ul>
<ul><li>第1点：用户类型为D（经销商）时自动查询并带出客户信息、收货地址</li></ul>
<ul><li>第2点：经销商登录时客户字段不可编辑</li></ul>
</KbCard>

<KbCard num="9" title="重点逻辑9：工程意向单模式">
<ul><li><strong>业务意义</strong>：意向单模式支持先关联合同再生成CRM订单，适用于无折扣单的场景</li></ul>
<ul><li><strong>具体逻辑描述</strong></li></ul>
<ul><li>第1点：projectIntention=2时走意向单流程，价格类型=3(价目表)，需关联合同</li></ul>
<ul><li>第2点：非意向单时价格类型=1(折扣单)</li></ul>
<ul><li>第3点：意向单有关联合同时校验产品数量未超合同，无关联合同时直接生成CRM</li></ul>

<ul><li>系统体现：阻断性报错</li></ul>
<ul><li>排查SQL：</li></ul>

<ul><li>详细逻辑</li></ul>

<h4>报错1：期望到达日期不能为空</h4>
<ul><li><strong>触发条件</strong>：保存要货订单时，期望到达日期(IN_DATE)未填写</li><li><strong>逻辑分析</strong>：保存校验中检查IN_DATE非空，因期望到达日期为要货订单必填项，用于物流安排。该报错为阻断性报错</li><li><strong>排查SQL</strong>：</li></ul>
<pre class="detail-sql" v-pre><code>SELECT obh.SA_OUT_BILL_HEAD_ID, obh.SA_SALEBILLNO, obh.IN_DATE, obh.BILL_TYPE, obh.ORDER_STAT
  FROM SA_OUT_BILL_HEAD obh

<h4>报错2：期望到达日期超过限制范围</h4>
<ul><li><strong>触发条件</strong>：保存要货订单时，期望到达日期超出允许范围(超过一年；电商渠道计划订单超6个月/常规订单超7个月；非电商渠道计划订单超3个月/常规订单超4个月)</li><li><strong>逻辑分析</strong>：保存校验中按BILL_TYPE和CHANNEL计算日期上限，若IN_DATE超过上限则抛出阻断性报错。需参考日期限制规则调整日期</li><li><strong>排查SQL</strong>：</li></ul>
<pre class="detail-sql" v-pre><code>SELECT obh.SA_OUT_BILL_HEAD_ID, obh.SA_SALEBILLNO, obh.IN_DATE, obh.BILL_TYPE, obh.CHANNEL,
         SYSDATE AS 当前日期,
         CASE WHEN obh.CHANNEL = 1 AND obh.BILL_TYPE = 2 THEN ADD_MONTHS(SYSDATE, 6)
              WHEN obh.CHANNEL = 1 AND obh.BILL_TYPE = 1 THEN ADD_MONTHS(SYSDATE, 7)
              WHEN obh.CHANNEL &lt;&gt; 1 AND obh.BILL_TYPE = 2 THEN ADD_MONTHS(SYSDATE, 3)
              WHEN obh.CHANNEL &lt;&gt; 1 AND obh.BILL_TYPE = 1 THEN ADD_MONTHS(SYSDATE, 4)
              ELSE ADD_MONTHS(SYSDATE, 12) END AS 日期上限
  FROM SA_OUT_BILL_HEAD obh
  WHERE obh.SA_OUT_BILL_HEAD_ID = :saOutBillHeadId
  -- 对比IN_DATE与日期上限</code></pre>

<h4>报错6：紧急行数超过限制</h4>
<ul><li><strong>触发条件</strong>：保存要货订单时，紧急行数 &gt; CEIL(产品行数/5)</li><li><strong>逻辑分析</strong>：保存校验中统计紧急行数(URGENCY=2)和产品行数，若紧急行数&gt;CEIL(产品行数/5)则抛出阻断性报错。需减少紧急行数</li><li><strong>排查SQL</strong>：</li></ul>
<pre class="detail-sql" v-pre><code>SELECT obh.SA_OUT_BILL_HEAD_ID, obh.SA_SALEBILLNO,
         COUNT(*) AS 产品行数,
         SUM(CASE WHEN obl.URGENCY = 2 THEN 1 ELSE 0 END) AS 紧急行数,
         CEIL(COUNT(*) / 5) AS 紧急行数上限
  FROM SA_OUT_BILL_HEAD obh
  JOIN SA_OUT_BILL_LINE obl ON obh.SA_OUT_BILL_HEAD_ID = obl.SA_OUT_BILL_HEAD_ID
  WHERE obh.SA_OUT_BILL_HEAD_ID = :saOutBillHeadId
  GROUP BY obh.SA_OUT_BILL_HEAD_ID, obh.SA_SALEBILLNO

<KbCard title="常见问题">
<ul><li>问题1：为什么折扣单号选择后没有带出产品明细？</li><li>原因：折扣单需满足折扣有效期未过期、可下单数量&gt;0、产品未下架且渠道适用、产品价格未失效。排查SQL：<code>SELECT VALID, EFFECTIVE_DATE_END, ACTIVE_QTY FROM EPM_DISCOUNT_APPLY WHERE DISCOUNT_APPLY_ID = :id</code></li><li>解决思路：检查折扣单状态和产品状态</li></ul>
<ul><li>问题2：期望到达日期为什么被清空？</li><li>原因：期望到达日期有严格限制：不能超过一年；当日≤25号时非电商渠道计划订单限3个月内；当日&gt;25号时非瓷砖产品线不能下常规订单</li><li>解决思路：参考提示信息调整日期</li></ul>
<ul><li>问题3：生成CRM订单时报"关联合同变更中"怎么办？</li><li>原因：该订单关联合同存在正在审批的变更单(ECN)。排查SQL：<code>SELECT * FROM EPM_PROJECT_CONTRACT_ECN WHERE CONTRACT_ID = :contractId AND HZ_APPROVE_STATUS = 'RUN'</code></li><li>解决思路：等合同变更审批完成后再生成CRM订单</li></ul>
<ul><li>问题4：紧急行数提示过多怎么办？</li><li>原因：紧急行数规则：仅计划订单可加紧急，且紧急行数≤CEIL(产品行数/5)</li><li>解决思路：减少紧急行数或将订单改为计划订单</li></ul>
<ul><li>问题5：产品SM状态为Z8无法下单怎么办？</li><li>原因：Z8表示产品生命状态不允许下单。排查SQL：<code>SELECT SM_STATE FROM SA_OUT_BILL_LINE WHERE SA_OUT_BILL_HEAD_ID = :id AND SM_STATE = 'Z8'</code></li><li>解决思路：联系产品部调整产品状态</li></ul>
<ul><li>问题6："申请不扣订金"按钮不显示？</li><li>原因：显示条件：订单可编辑 + billType=1/13 + 无要货单号或订单状态=4 + OA状态0/99/空 + 订单状态≠4</li><li>解决思路：检查订单状态是否满足</li></ul>
<ul><li>问题7：经销商登录时客户字段为什么不可选？</li><li>原因：经销商登录(userType=D)时自动带出其客户信息，不允许修改客户</li><li>解决思路：这是预期行为，经销商只能为自己下单</li></ul>
