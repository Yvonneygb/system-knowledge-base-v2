<KbCard num="1" title="重点逻辑1：阶段前进校验">
<ul><li><strong>业务意义</strong>：项目阶段代表项目推进的里程碑，只能前进不能后退，保证业务连续性</li><li><strong>具体逻辑描述</strong>：</li><li>更新阶段时通过EpmStageDef.seq比较新旧阶段顺序</li><li>若stageChanged且newStage.seq &lt; oldStage.seq，抛出"阶段更新，只能前进，不能后退"</li><li>强制更新(forceUpdate=2)时仍需通过前进校验</li></ul>
</KbCard>

<KbCard num="2" title="重点逻辑2：进度一致性校验">
<ul><li><strong>业务意义</strong>：防止并发更新时多个单据同时修改项目进度，避免覆盖</li><li><strong>具体逻辑描述</strong>：</li><li>当单据中记录的进度stageValueBefore大于项目档案当前STAGE_ID时</li><li>说明项目进度已被其他单据变更，抛出"项目进度已变更，请驳回重审!"</li><li>仅在阶段改变、描述改变或强制更新时执行此校验</li></ul>
</KbCard>

<KbCard num="3" title="重点逻辑3：历程记录沿用">
<ul><li><strong>业务意义</strong>：仅描述改变时保持历程连续性，不产生重复的阶段切换记录</li><li><strong>具体逻辑描述</strong>：</li><li>若仅阶段描述改变而阶段未变(stageChanged=false)</li><li>查询该阶段最新一条历程记录，沿用其创建人和创建时间</li><li>仅追加新的描述记录到EPM_PROJECT_STAGE</li></ul>
</KbCard>

<KbCard num="4" title="重点逻辑4：强制更新">
<ul><li><strong>业务意义</strong>：系统自动场景(如解冻审批通过)需跳过阶段改变判断直接更新</li><li><strong>具体逻辑描述</strong>：</li><li>forceUpdate=2时，即使阶段和描述都没有变化，也会执行更新操作</li><li>用于进度超时解冻、报备审批等系统自动场景</li></ul>
</KbCard>

<KbCard num="5" title="重点逻辑5：doMotionUpdate自动更新">
<ul><li><strong>业务意义</strong>：系统内部自动推进项目阶段，避免重复插入</li><li><strong>具体逻辑描述</strong>：</li><li>先查询项目是否已存在目标阶段记录(EPM_PROJECT_STAGE中PROJECT_ID+STAGE_ID)</li><li>未存在时：查询阶段定义，更新项目表STAGE_ID/STAGE_NAME/STAGE_NOTE/STAGE_DESC，插入阶段历程</li><li>已存在时不重复更新</li></ul>
</KbCard>

<KbCard title="doUpdate更新逻辑">
<pre class="detail-sql" v-pre><code>入参：EpmProjectStageDTO (projectId, stageId, stageDesc, forceUpdate, stageValueBefore)
1. 查询项目当前状态 projBeforeUpdate = selectByPrimaryKey(projectId)
2. trim处理stageDesc
3. 判断阶段是否改变 stageChanged = (stageId != projBeforeUpdate.stageId)
4. 判断描述是否改变 stageDescChanged = (stageDesc != projBeforeUpdate.stageDesc)
5. 若阶段改变或描述改变或强制更新(forceUpdate=2)：
   → 校验进度一致性：stageValueBefore &gt; projBeforeUpdate.stageId时抛"项目进度已变更，请驳回重审!"
   → 查询旧阶段定义 oldStage
   → 查询新阶段定义 newStage(stageChanged时查询，否则同oldStage)
   → 校验阶段前进：stageChanged且newStage.seq &lt; oldStage.seq时抛"阶段更新，只能前进，不能后退"
   → 更新项目档案：STAGE_DESC/STAGE_ID/STAGE_NAME/STAGE_NOTE
   → 插入历程记录EPM_PROJECT_STAGE：
     → 若阶段未改变，查询该阶段最新记录沿用创建人和创建时间
     → insert(insertEpmProjectStage)</code></pre>

<h4>报错1：阶段更新，只能前进，不能后退</h4>
<ul><li><strong>触发条件</strong>：更新项目进度时，目标阶段序号(newStage.seq)小于当前阶段序号(oldStage.seq)</li><li><strong>逻辑分析</strong>：doUpdate方法中查询EPM_STAGE_DEF获取目标阶段和当前阶段的SEQ，若newStage.seq &lt; oldStage.seq则抛出阻断性报错。项目阶段代表里程碑(报备→合同→结案)，回退会破坏业务连续性和下游数据一致性</li><li><strong>排查SQL</strong>：</li></ul>
<pre class="detail-sql" v-pre><code>SELECT esd.STAGE_ID, esd.STAGE_NAME, esd.SEQ, esd.UPDATE_CYCLE, esd.ORGANIZATION_ID
  FROM EPM_STAGE_DEF esd
  WHERE esd.ORGANIZATION_ID = :organizationId
  ORDER BY esd.SEQ
  -- 对比目标阶段与当前阶段的SEQ</code></pre>
<h4>报错2：项目进度已变更，请驳回重审!</h4>
<ul><li><strong>触发条件</strong>：更新项目进度时，单据进度stageValueBefore与项目档案当前STAGE_ID不一致</li><li><strong>逻辑分析</strong>：doUpdate方法中查询项目档案EPM_PROJECT获取projBeforeUpdate.stageId，若stageValueBefore &gt; projBeforeUpdate.stageId说明项目进度已被其他单据变更，当前单据基于旧进度提交，需驳回重审</li><li><strong>排查SQL</strong>：</li></ul>
<pre class="detail-sql" v-pre><code>SELECT ep.PROJECT_ID, ep.PROJECT_CODE, ep.STAGE_ID AS 当前阶段ID, ep.PROJECT_VALID,
         eps.STAGE_ID AS 历程阶段ID, eps.CREATION_DATE, eps.CREATED_BY
  FROM EPM_PROJECT ep
  LEFT JOIN EPM_PROJECT_STAGE eps ON ep.PROJECT_ID = eps.PROJECT_ID
  WHERE ep.PROJECT_ID = :projectId
  ORDER BY eps.CREATION_DATE DESC
  -- 对比单据的stageValueBefore与项目当前STAGE_ID</code></pre>
<h4>报错3：项目ID不能为空</h4>
<ul><li><strong>触发条件</strong>：更新项目进度时，projectId参数为空</li><li><strong>逻辑分析</strong>：updateStage方法projectId参数标注@NotNull，Spring校验框架自动校验。该报错为阻断性报错，需选择项目后重新提交</li><li><strong>排查SQL</strong>：</li></ul>
<pre class="detail-sql" v-pre><code>SELECT ep.PROJECT_ID, ep.PROJECT_CODE, ep.PROJECT_NAME, ep.STAGE_ID, ep.PROJECT_VALID
  FROM EPM_PROJECT ep
  WHERE ep.PROJECT_ID = :projectId
  -- 校验项目ID是否存在</code></pre>
<h4>报错4：阶段ID不能为空</h4>
<ul><li><strong>触发条件</strong>：更新项目进度时，stageId参数为空</li><li><strong>逻辑分析</strong>：updateStage方法stageId参数标注@NotNull，Spring校验框架自动校验。需选择目标阶段后重新提交</li><li><strong>排查SQL</strong>：</li></ul>
<pre class="detail-sql" v-pre><code>SELECT esd.STAGE_ID, esd.STAGE_NAME, esd.SEQ, esd.ORGANIZATION_ID
  FROM EPM_STAGE_DEF esd
  WHERE esd.STAGE_ID = :stageId
  -- 校验阶段ID是否存在</code></pre>
<h4>报错5：项目进度描述不能为空</h4>
<ul><li><strong>触发条件</strong>：更新项目进度时，stageDesc参数为空</li><li><strong>逻辑分析</strong>：updateStage方法stageDesc参数标注@NotEmpty，Spring校验框架自动校验。进度描述用于记录阶段变更说明，需填写后重新提交</li><li><strong>排查SQL</strong>：</li></ul>
<pre class="detail-sql" v-pre><code>SELECT eps.PROJECT_STAGE_ID, eps.PROJECT_ID, eps.STAGE_ID, eps.STAGE_DESC,
         eps.CREATION_DATE, eps.CREATED_BY
  FROM EPM_PROJECT_STAGE eps
  WHERE eps.PROJECT_ID = :projectId
    AND (eps.STAGE_DESC IS NULL OR TRIM(eps.STAGE_DESC) = '')
  -- 查出进度描述为空的历程记录</code></pre>

<div id="faq" style="display:none;">
<div class="tab-pad">
<div class="kl-wrap">
<KbCard title="Q1: 为什么阶段只能前进不能后退？">
<p>项目阶段代表项目推进的里程碑(如报备→合同→结案)，回退会破坏业务连续性和下游数据一致性。</p>
<p><strong>排查SQL:</strong></p>
<pre class="detail-sql" v-pre><code>SELECT STAGE_ID, STAGE_NAME, SEQ FROM EPM_STAGE_DEF ORDER BY SEQ;</code></pre>
</KbCard>

<KbCard title="Q2: 阶段未改变但描述改变时会记录历程吗？">
<p>会记录。只要阶段或描述任一改变，或启用强制更新，都会插入新的历程记录，但会沿用上次该阶段的创建人和创建时间。</p>
</KbCard>

<KbCard title="Q3: doMotionUpdate与doUpdate的区别？">
<p>doMotionUpdate为系统内部调用(如解冻审批通过后自动推进)，先查询项目是否已存在目标阶段记录，未存在才更新；doUpdate为页面手动触发，含完整的阶段前进和一致性校验。</p>
</KbCard>

<KbCard title="Q4: 项目被冻结，冻结类型为"进度超时更新"是什么原因？">
<p>项目在当前阶段的进度更新期限(由阶段定义中UPDATE_CYCLE字段控制)内未更新进度，系统自动冻结。</p>
<p><strong>排查SQL:</strong></p>
<pre class="detail-sql" v-pre><code>SELECT EP.PROJECT_ID, EP.PROJECT_CODE, EP.STAGE_ID, EP.PROJECT_VALID, EP.FREEZE_TYPE,
       SD.STAGE_NAME, SD.UPDATE_CYCLE
FROM EPM_PROJECT EP
LEFT JOIN EPM_STAGE_DEF SD ON SD.STAGE_ID = EP.STAGE_ID
WHERE EP.FREEZE_TYPE = 2;</code></pre>
</KbCard>

<KbCard title="Q5: 强制更新是什么意思？">
<p>强制更新(forceUpdate=2)时，即使阶段和描述都没有变化，也会执行更新操作并写入历程记录。主要用于报备审批和解冻场景。</p>
</KbCard>

<KbCard title="Q6: 进度更新期限如何计算？">
<p>进度更新期限 = 当前阶段最近一次更新时间 + 阶段定义中的UPDATE_CYCLE天数。</p>
<p><strong>排查SQL:</strong></p>
<pre class="detail-sql" v-pre><code>SELECT PS.PROJECT_ID, PS.STAGE_ID, PS.CREATION_DATE,
       SD.UPDATE_CYCLE,
       PS.CREATION_DATE + INTERVAL TO_NUMBER(SD.UPDATE_CYCLE) DAY AS 期限
FROM EPM_PROJECT_STAGE PS
JOIN EPM_STAGE_DEF SD ON SD.STAGE_ID = PS.STAGE_ID
WHERE PS.PROJECT_ID = #{projectId}
ORDER BY PS.CREATION_DATE DESC
FETCH FIRST 1 ROWS ONLY;</code></pre>
</KbCard>

<KbCard title="Q7: 历程记录如何查询？">
<p><strong>排查SQL:</strong></p>
<pre class="detail-sql" v-pre><code>SELECT * FROM EPM_PROJECT_STAGE
WHERE PROJECT_ID = #{projectId}
ORDER BY CREATION_DATE DESC;</code></pre>
</KbCard>
