<KbCard num="1" title="重点逻辑1：OCR发票识别">
<ul><li><strong>业务意义</strong>：上传发票影像文件后自动识别发票信息，减少人工录入工作量</li><li><strong>具体逻辑描述</strong>：</li><li>通过附件UUID获取文件URL，调用sysFileService.getSignedUrl获取签名URL</li><li>调用OcrSdkService.ocrCheckInvoice进行OCR识别</li><li>OCR返回结果包含发票代码、发票号码、开票日期、金额、校验码、购销方信息、明细行等</li><li>识别结果自动回填到发票主要信息和详细信息字段，operationFlag=2标记为OCR识别</li><li>跳过货物名称为"(详见销货清单)"的明细行</li><li>通过规格型号自动匹配基本单位(selectUomByModel)</li><li>OCR识别失败时抛出异常，不阻断保存(try-catch包裹)</li></ul>
</KbCard>

<KbCard num="2" title="重点逻辑2：发票重复校验">
<ul><li><strong>业务意义</strong>：防止同一张发票被重复上传核销，确保发票唯一性</li><li><strong>具体逻辑描述</strong>：</li><li>beforeSave方法中遍历发票主要信息，校验发票代码+发票号码非空且不重复</li><li>调用checkInvoices方法，通过selectCountOfInvoiceCode查询该发票是否已被其它核销单核销</li><li>发票详细信息校验：每条明细的发票代码+号码必须在主要信息中存在</li><li>校验失败时抛出CommonException，包含所有错误信息</li></ul>
</KbCard>

<KbCard num="3" title="重点逻辑3：保存逻辑">
<ul><li><strong>业务意义</strong>：保存核销发票上传单，包含影像、主要信息、详细信息、附件四部分数据</li><li><strong>具体逻辑描述</strong>：</li><li>新增(doInsert)：自动生成核销单号(编码规则AE.INVOICE_VERIFER_NO/AE.JZ_INVOICE_VERIFER_NO)，auditStat="新建"，保存四部分数据</li><li>修改(doUpdate)：保留原auditStat/hzInstanceId/hzApproveStatus/wfflag/organizationId，更新四部分数据</li><li>保存前调用beforeSave校验发票唯一性和完整性</li><li>附件通过objAttachRelService.saveData保存关联关系</li></ul>
</KbCard>

<KbCard num="4" title="重点逻辑4：导入发票明细">
<ul><li><strong>业务意义</strong>：支持通过Excel导入发票详细信息，提高录入效率</li><li><strong>具体逻辑描述</strong>：</li><li>导入时逐行校验：凭证号码非空且存在、发票号码非空、发票代码非空、发票数量非空且&gt;0、单价非空、转换率非空、规格型号非空</li><li>税率校验：0-100范围内</li><li>导入数据匹配已有明细(seq+凭证号码匹配)，匹配到则更新(OCR识别的改为手工修改flag=1)，未匹配则新增(flag=0)</li><li>错误信息按行号收集，返回所有错误</li></ul>
</KbCard>

<KbCard num="5" title="重点逻辑5：终止与撤回终止">
<ul><li><strong>业务意义</strong>：对核销发票上传单进行终止操作，支持撤回终止恢复</li><li><strong>具体逻辑描述</strong>：</li><li>终止(terminate)：调用invoiceCancelHandle(handleType="disable")，记录终止历史</li><li>撤回终止(undoTerminate)：调用invoiceCancelHandle(handleType="enable")，恢复正常状态</li><li>bizType区分：isHome=2为211116(家装)，否则210906(工程)</li><li>终止/撤回终止通过invoiceCancelService.handle处理，记录操作原因和操作人</li></ul>
</KbCard>

<KbCard num="6" title="重点逻辑6：审批完成回调">
<ul><li><strong>业务意义</strong>：审批通过后更新发票有效状态，确保核销数据生效可用于真实性核销</li><li><strong>具体逻辑描述</strong>：</li><li>wfComplete：审批非驳回时，更新发票主要信息和详细信息的effectStatus="valid"</li><li>onProcComplete：校验发票详细信息非空，更新主要信息和详细信息的effectStatus="valid"</li><li>wfProcSubmit：提交工作流前校验主要信息和详细信息非空，调用beforeSave和verifyData校验，按isHome选择工作流编码</li></ul>
</KbCard>

<KbCard num="7" title="重点逻辑7：金额校验">
<ul><li><strong>业务意义</strong>：确保发票明细金额计算正确，明细汇总与发票总金额一致</li><li><strong>具体逻辑描述</strong>：</li><li>verifyData方法：查询发票主要信息和详细信息</li><li>行级校验：单价×数量=金额(允许0.01差异)</li><li>汇总校验：同一发票号码的明细行金额汇总=发票主要信息总金额(allAmount)</li><li>校验失败时收集所有错误信息一次性抛出</li></ul>

<KbCard title="保存校验">
<h4>校验1：发票号码和发票代码不可重复 —— 防止同一张发票重复上传</h4>
<ul><li><strong>详细逻辑</strong>：beforeSave方法中遍历发票主要信息，校验发票代码+发票号码非空且在同一条上传单内不重复，同时调用checkInvoices校验该发票是否已被其它单核销</li><li><strong>系统体现</strong>：beforeSave方法中invoiceSet去重校验+selectCountOfInvoiceCode跨单校验</li><li><strong>排查SQL</strong>：</li></ul>
<pre class="detail-sql" v-pre><code>SELECT INVOICE_CODE, INVOICE_NUMBER, COUNT(*)
FROM EPM_UPLOAD_INVOICE_INFO
WHERE INVOICE_VERIFER_ID = #{invoiceVeriferId}
GROUP BY INVOICE_CODE, INVOICE_NUMBER
HAVING COUNT(*) &gt; 1;</code></pre>
<h4>校验2：发票详细信息关联主要信息 —— 确保明细行发票号码在主要信息中存在</h4>
<ul><li><strong>详细逻辑</strong>：遍历发票详细信息，校验每条明细的发票代码+号码在主要信息集合中存在</li><li><strong>系统体现</strong>：beforeSave方法中detail校验invoiceSet.contains</li><li><strong>排查SQL</strong>：</li></ul>
<pre class="detail-sql" v-pre><code>SELECT d.INVOICE_CODE, d.INVOICE_NUMBER
FROM EPM_UPLOAD_INVOICE_DETAILS d
WHERE d.INVOICE_VERIFER_ID = #{invoiceVeriferId}
  AND NOT EXISTS (
    SELECT 1 FROM EPM_UPLOAD_INVOICE_INFO i
    WHERE i.INVOICE_VERIFER_ID = d.INVOICE_VERIFER_ID
      AND i.INVOICE_CODE = d.INVOICE_CODE
      AND i.INVOICE_NUMBER = d.INVOICE_NUMBER
  );</code></pre>
</KbCard>

<KbCard title="提交校验">
<h4>校验1：发票主要信息不能为空 —— 确保上传单有发票主信息</h4>
<ul><li><strong>详细逻辑</strong>：提交工作流前查询发票主要信息，为空则报错</li><li><strong>系统体现</strong>：wfProcSubmit方法中epmUploadInvoiceInfoService.select结果为空时抛CommonException</li><li><strong>排查SQL</strong>：</li></ul>
<pre class="detail-sql" v-pre><code>SELECT COUNT(*) FROM EPM_UPLOAD_INVOICE_INFO WHERE INVOICE_VERIFER_ID = #{invoiceVeriferId};</code></pre>
<h4>校验2：发票详细信息不能为空 —— 确保上传单有发票明细</h4>
<ul><li><strong>详细逻辑</strong>：提交工作流前和流程节点完成时查询发票详细信息，为空则报错</li><li><strong>系统体现</strong>：wfProcSubmit和onProcComplete方法中selectByInvoiceVeriferId结果为空时抛CommonException</li><li><strong>排查SQL</strong>：</li></ul>
<pre class="detail-sql" v-pre><code>SELECT COUNT(*) FROM EPM_UPLOAD_INVOICE_DETAILS WHERE INVOICE_VERIFER_ID = #{invoiceVeriferId};</code></pre>
<h4>校验3：行金额校验 —— 确保明细金额计算正确且汇总一致</h4>
<ul><li><strong>详细逻辑</strong>：verifyData方法校验：单价×数量=金额(允许0.01差异)，同一发票号码的明细行金额汇总=发票主要信息总金额(allAmount)</li><li><strong>系统体现</strong>：verifyData方法中逐行计算并汇总比对，错误收集后一次性抛出</li><li><strong>排查SQL</strong>：</li></ul>
<pre class="detail-sql" v-pre><code>SELECT i.INVOICE_NUMBER, i.ALL_AMOUNT, NVL(SUM(d.AMOUNT), 0) AS detail_sum
FROM EPM_UPLOAD_INVOICE_INFO i
LEFT JOIN EPM_UPLOAD_INVOICE_DETAILS d
  ON d.INVOICE_VERIFER_ID = i.INVOICE_VERIFER_ID
 AND d.INVOICE_NUMBER = i.INVOICE_NUMBER
WHERE i.INVOICE_VERIFER_ID = #{invoiceVeriferId}
GROUP BY i.INVOICE_NUMBER, i.ALL_AMOUNT;</code></pre>
</KbCard>

<KbCard title="常见问题">
<p><strong>Q1: OCR识别后发票信息不完整怎么办？</strong></p>
<p>A: 可能是发票影像模糊、格式不规范或OCR服务识别精度限制。处理方式：手工补充修正识别结果，或重新上传清晰影像。</p>
<p><strong>Q2: 导入发票明细后金额校验失败怎么办？</strong></p>
<p>A: 导入数据中金额字段格式错误或与发票总金额不一致。检查导入Excel中金额列格式，确保明细金额合计=发票总金额，且单价×数量=金额。</p>
<p><strong>Q3: 核销发票上传的编号如何生成？</strong></p>
<p>A: 工程使用编码规则AE.INVOICE_VERIFER_NO，家装使用AE.JZ_INVOICE_VERIFER_NO。凭证号码通过AE.INVOICE_CANCELLATION_UPLOAD生成。</p>
<p><strong>Q4: 家装和工程场景的区别？</strong></p>
<p>A: 家装(isHome=2)使用AE.JZ_INVOICE_VERIFER_NO编码规则+INVOICE_JZHXFPSC_AW工作流+homeExport导出接口，工程(isHome=1)使用AE.INVOICE_VERIFER_NO编码规则+INVOICE_WF_UPLOAD_AW工作流+export导出接口。</p>
<p><strong>Q5: 终止和撤回终止的作用？</strong></p>
<p>A: 终止(terminate)用于中止核销发票流程，handleType="disable"，终止后发票不可用。撤回终止(undoTerminate)用于恢复被误终止的发票，handleType="enable"。bizType区分：isHome=2为211116(家装)，否则210906(工程)。</p>
<p><strong>Q6: 审批通过后发票数据如何生效？</strong></p>
<p>A: wfComplete和onProcComplete中，审批非驳回时更新EPM_UPLOAD_INVOICE_INFO和EPM_UPLOAD_INVOICE_DETAILS的effectStatus="valid"，使发票可用于真实性核销关联。</p>
