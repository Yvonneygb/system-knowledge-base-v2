<KbCard num="1" title="重点逻辑1：坎级定价与优惠方式">
<ul><li><strong>业务意义</strong>：支持按数量阶梯定价，折扣和特价两种优惠方式灵活配置</li><li><strong>具体逻辑描述</strong>：</li><li>折扣方式(preferentialType=1)：坎级行定义不同数量段的折扣率，折后单价=标准单价×折扣率</li><li>特价方式(preferentialType=2)：坎级行定义不同数量段的特价金额，特价反算折扣率=特价/(标准单价×出厂折扣率)</li><li>坎级行匹配规则：根据下单数量匹配minimumQty ≤ 数量 ≤ cappingQty的坎级段</li></ul>
</KbCard>

<KbCard num="2" title="重点逻辑2：通用与专项审批差异">
<ul><li><strong>业务意义</strong>：通用类型直接生效，专项类型需同步CRM，处理逻辑不同</li><li><strong>具体逻辑描述</strong>：</li><li>通用类型(normal)审批通过后直接设valid=2生效，不推送CRM</li><li>专项类型(special)审批通过后调用crmPolicySyncService同步CRM：不存在CRMID时doCreatePolicy创建，已存在时doComplete完成</li><li>通用类型优惠方式必须为折扣(1)，不支持特价</li></ul>
</KbCard>

<KbCard num="3" title="重点逻辑3：时间重叠校验">
<ul><li><strong>业务意义</strong>：通用类型同一产品/型号在重叠时间段不能存在多个已审批/有效政策</li><li><strong>具体逻辑描述</strong>：</li><li>保存时校验通用类型(suitableType=normal)同一产品/型号的有效日期区间与其他已审批/有效政策不重叠</li><li>重叠时抛出"时间重叠冲突"</li></ul>
</KbCard>

<KbCard num="4" title="重点逻辑4：封顶量校验">
<ul><li><strong>业务意义</strong>：控制折扣政策使用数量上限，防止超量使用</li><li><strong>具体逻辑描述</strong>：</li><li>坎级行封顶量(cappingQty)：单次下单数量上限</li><li>经销商封顶量(customerCapsNumber)：单个经销商累计使用上限</li><li>提交校验：max(坎级封顶量) ≤ 单个经销商封顶数量 ≤ 政策行总数量</li></ul>
</KbCard>

<KbCard num="5" title="重点逻辑5：失效管理">
<ul><li><strong>业务意义</strong>：已生效的折扣政策可发起失效申请，审批通过后政策失效</li><li><strong>具体逻辑描述</strong>：</li><li>创建失效记录(EpmDiscountPolicyDisabled) → 生成编码 → 更新产品行disabledId</li><li>保存并提交 → 开启工作流</li><li>审批通过 → 产品行validStat=3 → 所有行失效则政策头valid=3 → 专项类型推送CRM失效</li></ul>
</KbCard>

<ul><li><strong>业务意义</strong>：批量导入产品明细和阶梯政策</li><li><strong>具体逻辑描述</strong>：调用POST /importProduct接口，上传Excel文件批量导入</li></ul>

<KbCard title="保存校验">
<ul><li>校验1：必填字段非空 —— 专项时订单类型+业务类型必填；通用必填政策类型/名称/有效日期/币种</li><li><strong>详细逻辑</strong>：preCheckData中校验必填字段，为空抛出"必填字段不能为空"</li><li><strong>系统体现</strong>：后端saveData方法校验</li><li><strong>排查SQL</strong>：<code>SELECT * FROM EPM_DISCOUNT_POLICY WHERE POLICY_NAME IS NULL OR POLICY_TYPE IS NULL;</code></li></ul>
<ul><li>校验2：产品行非空 —— 至少添加一条产品明细行</li><li><strong>详细逻辑</strong>：preCheckData中校验产品行列表非空，为空抛出"产品行不能为空"</li><li><strong>系统体现</strong>：后端saveData方法校验</li></ul>
<p>C排查SQL**：<code>SELECT DP.DISCOUNT_POLICY_ID FROM EPM_DISCOUNT_POLICY DP LEFT JOIN EPM_DISCOUNT_POLICY_ITEM DPI ON DP.DISCOUNT_POLICY_ID = DPI.DISCOUNT_POLICY_ID WHERE DPI.DISCOUNT_POLICY_ITEM_ID IS NULL;</code></p>
<ul><li>校验3：申请类型互斥 —— 全产品(3)与型号(2)/产品(1)不能同时存在</li><li><strong>详细逻辑</strong>：preCheckData中校验申请类型不冲突，冲突抛出"申请类型冲突"</li><li><strong>系统体现</strong>：后端saveData方法校验</li><li><strong>排查SQL</strong>：<code>SELECT DISTINCT APPLICATION_TYPE FROM EPM_DISCOUNT_POLICY_ITEM WHERE DISCOUNT_POLICY_ID = #&#123;policyId&#125;;</code></li></ul>
<ul><li>校验4：政策名称长度 —— 非空且长度≤30个字符</li><li><strong>/详细逻辑</strong>：preCheckData中校验policyName长度，超限抛出"折扣政策名称最大输入30个字符"</li><li><strong>系统体现</strong>：后端saveData方法校验</li><li><strong>排查SQL</strong>：<code>SELECT DISCOUNT_POLICY_ID, POLICY_NAME, LENGTH(POLICY_NAME) AS NAME_LEN FROM EPM_DISCOUNT_POLICY WHERE LENGTH(POLICY_NAME) &gt; 30;</code></li></ul>
<ul><li>校验5：时间重叠校验 —— 通用类型同一产品/型号在重叠时间段不能存在其他已审批/有效政策</li><li><strong>详细逻辑</strong>：preCheckData中校验通用类型有效日期区间不与其他政策重叠，重叠抛出"时间重叠冲突"</li><li><strong>系统体现</strong>：后端saveData方法校验</li><li><strong>排查SQL</strong>：<code>SELECT DP.DISCOUNT_POLICY_ID, DP.DISCOUNT_POLICY_CODE FROM EPM_DISCOUNT_POLICY DP JOIN EPM_DISCOUNT_POLICY_ITEM DPI ON DP.DISCOUNT_POLICY_ID = DPI.DISCOUNT_POLICY_ID WHERE DPI.ITEM_CODE = #&#123;itemCode&#125; AND DP.SUITABLE_TYPE = 'normal' AND DP.3VALID IN!IN(1,2) AND DP.EFFECTIVE_DATE_END &gt;= #&#123;startDate&#125; AND DP.EFFECTIVE_DATE_START &lt;= #&#123;endDate&#125;;</code></li></ul>
</KbCard>

<KbCard title="提交校验">
<ul><li>校验1：一口价折扣率校验 —— 产品定位为"一口价"时折扣率必须≥1</li><li><strong>详细逻辑</strong>：submitCheck中校验产品定位为"一口价"时坎级行折扣率≥1，否则抛出"一口价折扣率&lt;1"</li><li><strong>系统体现</strong>：后端submitCheck方法校验</li><li><strong>排查SQL</strong>：<code>SELECT DPI.ITEM_CODE, DPIE.PROD_POSITIONING, EPIL.DISCOUNT_RATE FROM EPM_DISCOUNT_POLICY_ITEM DPI JOIN EPM_DISCOUNT_POLICY_ITEM_EXT DPIE ON DPI.DISCOUNT/ITEM_ID = DPIE.DISCOUNT_POLICY_ITEM_ID JOIN EPM_DISCOUNT_POLICY_ITEM_LINE EPIL ON DPI.DISCOUNT_POLICY_ITEM_ID = EPIL.DISCOUNT_POLICY_ITEM_ID WHERE DPI.DISCOUNT_POLICY_ID = #&#123;policyId&#125; AND DPIE.PROD_POSITIONING = '一口价' AND EPIL.DISCOUNT_RATE &lt; 1;</code></li></ul>
<ul><li>校验2：坎级数量校验 —— max(坎级封顶量) ≤ 单个经销商封顶数量 ≤ 政策行总数量</li><li><strong>详细逻辑</strong>：submitCheck中校验封顶量层级关系</li><li><strong>系统体现</strong>：后端submitCheck方法校验</li><li><strong>&排查SQL</strong>：<code>SELECT MAX(EPIL.CAPPING_QTY) AS MAX_CAPPING, DPI.CUSTOMER_CAPS_NUMBER FROM EPM_DISCOUNT_POLICY_ITEM_LINE EPIL JOIN EPM_DISCOUNT_POLICY_ITEM DPI ON EPIL.DISCOUNT_POLICY_ITEM_ID = DPI.DISCOUNT_POLICY_ITEM_ID WHERE DPI.DISCOUNT_POLICY_ID = #&#123;policyId&#125; GROUP BY DPI.DISCOUNT_POLICY_ITEM_ID;</code></li></ul>
<ul><li>校验3：折扣管控CRM校验 —— 非样品/长库龄业务类型时推送CRM校验</li><li><strong>详细逻辑</strong>：wfProcSubmit中推送CRM折扣信息同步和折扣管控校验</li><li><strong>系统体现</strong>：工作流提交回调wfProcSubmit</li><li><strong>排查SQL</strong>：<code>SELECT DISCOUNT_POLICY_ID, IS_MAKT, SOURCE_TYPE FROM EPM_DISCOUNT_POLICY WHERE DISCOUNT_POLICY_ID = #&#123;policyId&#125;;</code></li></ul>

<h4>报错1：折扣政策名称最大输入30个字符</h4>

  -- 查出名称超长的异常数据</code></pre>
<h4>报错2：产品行不能为空</h4>

WHERE EPIL.DISCOUNT_POLICY_ITEM_ID = #{policyItemId};</code></pre>
</KbCard>

<KbCard title="Q4: 通用政策时间重叠校验失败？">
<p>通用类型折扣政策不允许同一产品在重叠时间段存在多个已审批/有效政策。</p>
<p><strong>排查SQL:</strong></p>
<pre class="detail-sql" v-pre><code>SELECT DP.DISCOUNT_POLICY_ID, DP.DISCOUNT_POLICY_CODE, DP.VALID,
       DP.EFFECTIVE_DATE_START, DP.EFFECTIVE_DATE_END
FROM EPM_DISCOUNT_POLICY DP
JOIN EPM&amp;DISCOUNT_POLICY_ITEM DPI ON DP.DISCOUNT_POLICY_ID = DPI.DISCOUNT_POLICY_ID
WHERE DPI.ITEM_CODE = #{itemCode}
  AND DP.SUITABLE_TYPE = 'normal'
  AND DP.VALID IN (1, 2)
  AND DP.EFFECTIVE_DATE_END &gt;= #{startDate}
  AND DP.EFFECTIVE_DATE_START &lt;= #{endDate};</code></pre>
</KbCard>

<KbCard title="Q5: 专项政策审批通过后CRM同步失败？">
<p>检查EPM_DISCOUNT_POLICY_GENERATE是否有记录，CRMIC是否为空。crmPolicySyncService.doCreatePolicy或doComplete调用失败时CRM未同步。</p>
<p><strong>排查SQL:</strong></p>
<pre class="detail-sql" v-pre><code>SELECT DISCOUNT_POLICY_ID, CRMID, CRMIC
FROM EPM_DISCOUNT_POLICY_GENERATE
WHERE DISCOUNT_POLICY_ID = #{policyId};</code></pre>
</KbCard>

<KbCard title="Q6: 折扣政策失效后要货订单仍可下单？">
<p>政策行validStat未全部更新为3，或政策LOV查询条件未过滤valid状态。</p>
<p><strong>排查SQL:</strong></p>
<pre class="detail-sql" v-pre><code>SELECT DISCOUNT_POLICY_ITEM_ID, VALID_STAT
FROM EPM_DISCOUNT_POLICY_ITEM
WHERE DISCOUNT_POLICY_ID = #{policyId} AND VALID_STAT != 3;</code></pre>
</KbCard>
