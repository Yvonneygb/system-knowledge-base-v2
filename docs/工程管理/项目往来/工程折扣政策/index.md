<KbCard title="2.1 坎级定价与优惠方式">
<KbQuote>支持按数量阶梯定价，折扣和特价两种优惠方式灵活配置</KbQuote>
<table class="kl-table"><thead><tr><th>优惠方式</th><th>preferentialType</th><th>定价逻辑</th></tr></thead><tbody><tr><td>折扣</td><td>1</td><td>坎级行定义不同数量段的折扣率，折后单价 = 标准单价 &times; 折扣率</td></tr><tr><td>特价</td><td>2</td><td>坎级行定义不同数量段的特价金额，特价反算折扣率 = 特价 / (标准单价 &times; 出厂折扣率)</td></tr></tbody></table>
<p><strong>坎级行匹配规则</strong>：根据下单数量匹配 minimumQty &le; 数量 &le; cappingQty 的坎级段</p>
<table class="kl-table"><thead><tr><th>计算项</th><th>公式</th></tr></thead><tbody><tr><td>应用折扣率(计开单折扣)</td><td>出厂折扣率 &times; 审批折扣率</td></tr><tr><td>应用折扣率(不计开单折扣)</td><td>出厂折扣率 &times; 经销商全年折扣率</td></tr><tr><td>价值链</td><td>(折后单价 - 成本单价) / 折后单价</td></tr><tr><td>整单价值链</td><td>(折后总价 - 成本总价) / 折后总价</td></tr></tbody></table>
</KbCard>
<KbCard title="2.2 通用与专项审批差异">
<KbQuote>通用类型直接生效，专项类型需同步CRM，处理逻辑不同</KbQuote>
<table class="kl-table"><thead><tr><th>类型</th><th>suitableType</th><th>审批通过后动作</th><th>优惠方式限制</th></tr></thead><tbody><tr><td>通用</td><td>normal</td><td>直接设valid=2生效，不推送CRM</td><td>必须为折扣(1)，不支持特价</td></tr><tr><td>专项</td><td>special</td><td>crmPolicySyncService同步CRM：不存在CRMID时doCreatePolicy创建，已存在时doComplete完成</td><td>支持折扣和特价</td></tr></tbody></table>
</KbCard>
<KbCard title="2.3 时间重叠校验">
<KbQuote>通用类型同一产品/型号在重叠时间段不能存在多个已审批/有效政策</KbQuote>
<ul><li>保存时校验通用类型(suitableType=normal)同一产品/型号的有效日期区间与其他已审批/有效政策不重叠</li><li>重叠时抛出"时间重叠冲突"</li><li>仅通用类型校验，专项类型允许多个政策并存</li></ul>
</KbCard>
<KbCard title="2.4 封顶量校验">
<KbQuote>控制折扣政策使用数量上限，防止超量使用</KbQuote>
<ul><li><strong>坎级行封顶量(cappingQty)</strong>：单次下单数量上限</li><li><strong>经销商封顶量(customerCapsNumber)</strong>：单个经销商累计使用上限</li><li><strong>提交校验</strong>：max(坎级封顶量) &le; 单个经销商封顶数量 &le; 政策行总数量</li><li><strong>要货订单校验</strong>：下单数量 + 已下单数量 &le; 经销商封顶量，否则抛出阻断性报错</li></ul>
</KbCard>
<KbCard title="2.5 失效管理">
<KbQuote>已生效的折扣政策可发起失效申请，审批通过后政策失效</KbQuote>
<ul><li>创建失效记录(EpmDiscountPolicyDisabled) &rarr; 生成编码 &rarr; 更新产品行disabledId</li><li>保存并提交 &rarr; 开启工作流</li><li>审批通过 &rarr; 产品行validStat=3 &rarr; 所有行失效则政策头valid=3 &rarr; 专项类型推送CRM失效</li><li><strong>删除限制</strong>：仅NEW状态可删除，级联删除所有子表</li></ul>
</KbCard>

<h4>报错1：折扣政策名称最大输入30个字符</h4>
<p><strong>触发条件</strong>：保存折扣政策时，DISCOUNT_POLICY_NAME长度超过30字符</p>
<p><strong>逻辑分析</strong>：preCheckData方法中校验政策名称长度，EPM_DISCOUNT_POLICY.DISCOUNT_POLICY_NAME字段定义为VARCHAR(30)。超长则抛出阻断性报错，需缩短至30字符以内</p>
<pre class="detail-sql" v-pre><code>SELECT edp.DISCOUNT_POLICY_ID, edp.DISCOUNT_POLICY_CODE, edp.DISCOUNT_POLICY_NAME,
       LENGTH(edp.DISCOUNT_POLICY_NAME) AS NAME_LEN
FROM EPM_DISCOUNT_POLICY edp
WHERE LENGTH(edp.DISCOUNT_POLICY_NAME) &gt; 30;</code></pre>

<h4>报错2：产品行不能为空</h4>
<p><strong>触发条件</strong>：保存折扣政策时，未添加产品明细行(EPM_DISCOUNT_POLICY_ITEM为空)</p>
<p><strong>逻辑分析</strong>：preCheckData方法中校验产品行列表非空，因折扣政策必须包含至少一条产品明细。该报错为阻断性报错</p>
<pre class="detail-sql" v-pre><code>SELECT edp.DISCOUNT_POLICY_ID, edp.DISCOUNT_POLICY_CODE, edp.DISCOUNT_POLICY_NAME,

        WHERE edpi.DISCOUNT_POLICY_ID = edp.DISCOUNT_POLICY_ID) AS ITEM_COUNT

<p><strong>触发条件</strong>：保存折扣政策时，通用类型(suitableType=normal)同一产品在重叠时间段已有其他政策</p>
<p><strong>逻辑分析</strong>：preCheckData方法中按ITEM_CODE和有效日期区间查询EPM_DISCOUNT_POLICY，若通用类型政策在重叠时间段已存在则抛出阻断性报错。需调整有效日期避免重叠</p>
<pre class="detail-sql" v-pre><code>SELECT edp.DISCOUNT_POLICY_ID, edp.DISCOUNT_POLICY_CODE, edp.DISCOUNT_POLICY_NAME,
       edp.SUITABLE_TYPE, edp.VALID, edp.EFFECTIVE_DATE_START, edp.EFFECTIVE_DATE_END,
       edpi.ITEM_CODE
FROM EPM_DISCOUNT_POLICY edp
JOIN EPM_DISCOUNT_POLICY_ITEM edpi ON edp.DISCOUNT_POLICY_ID = edpi.DISCOUNT_POLICY_ID
WHERE edpi.ITEM_CODE = :itemCode
  AND edp.SUITABLE_TYPE = 'normal'
  AND edp.VALID IN (1, 2)
  AND edp.EFFECTIVE_DATE_END &gt;= :newStartDate

<p><strong>触发条件</strong>：保存折扣政策时，适用类型为通用(normal)但产品行优惠方式选择了特价(2)</p>

JOIN EPM_DISCOUNT_POLICY edp ON edpi.DISCOUNT_POLICY_ID = edp.DISCOUNT_POLICY_ID

WHERE edpi.CAPPING = 2
  AND (edpi.CUSTOMER_CAPS_NUMBER IS NULL
       OR edpi.CUSTOMER_CAPS_NUMBER &lt;= 0

<KbCard title="操作手册 — 新建折扣政策">
<ol><li>进入工程折扣政策列表页，点击「新增」按钮</li><li>选择适用类型(通用normal/专项special)</li><li>填写政策名称(必填，&le;30字符)、有效日期起止(必填)</li><li>选择政策类型(1=客户, 2=区域, 3=客户分类, 4=省份)</li><li>根据政策类型选择对应的客户/区域/省份/客户分类</li><li>在产品明细行中点击「添加产品」，通过CRM产品弹窗(GET /get-crm-item)选择产品</li><li>配置每个产品行的申请类型(1=产品, 2=型号, 3=全产品)和优惠方式(1=折扣, 2=特价)</li><li>在坎级行中配置起订量、封顶量、折扣率或特价金额</li><li>如需封顶量校验，设置capping=2并填写经销商封顶量</li><li>点击「保存」或「保存并提交」</li></ol>
</KbCard>
<KbCard title="操作手册 — 提交审批">
<ol><li>在折扣政策详情页，确认所有信息填写完整</li><li>点击「保存并提交」按钮</li><li>系统执行preCheckData保存校验(必填字段、产品行、时间重叠、封顶量等)</li><li>通过后执行submitCheck提交校验(一口价折扣率、坎级数量、CRM校验等)</li><li>校验通过后触发工作流审批</li><li>审批通过后：通用类型直接设valid=2生效；专项类型同步CRM后生效</li></ol>
</KbCard>
<KbCard title="操作手册 — 导入产品">
<ol><li>在折扣政策详情页，点击「导入产品」按钮</li><li>下载导入模板，按模板格式填写产品明细和坎级行数据</li><li>上传Excel文件，系统调用POST /importProduct接口</li><li>导入时校验discountPolicyId非空(需先保存政策)</li><li>导入后系统自动校验产品编码是否在CRM中存在</li></ol>
</KbCard>
<KbCard title="操作手册 — 发起失效申请">
<ol><li>在折扣政策列表页，选中状态为「已生效」的政策</li><li>点击「失效」按钮，创建失效记录(EpmDiscountPolicyDisabled)</li><li>系统生成失效单号，更新产品行disabledId</li><li>保存并提交失效申请，开启工作流</li><li>审批通过后：产品行validStat=3，所有行失效则政策头valid=3，专项类型推送CRM失效</li></ol>
</KbCard>
<KbCard title="操作手册 — 删除折扣政策">
<ol><li>在折扣政策列表页，选中状态为「NEW(新建)」的政策</li><li>点击「删除」按钮</li><li>系统校验单据状态为NEW，非新建状态不允许删除</li><li>确认删除后，级联删除所有子表(产品行、坎级行、客户列表等)</li></ol>
</KbCard>
